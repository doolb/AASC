# project-pseudocode-sync

## 调用顺序（固定）

- 由 `ai-code-translation` 先接收用户需求
- 当检测到“需按当前项目实际修正伪代码”时，调用本技能
- 本技能完成 `.src` 伪代码对齐后，返回 `ai-code-translation`
- 最后由 `ai-code-translation` 继续执行确认门禁与目标代码生成

## 目标

把需求口径同步到当前项目真实实现路径，输出可直接用于后续 `ai-code-translation` 的伪代码版本。

该技能专门解决：
- 需求说法和项目现状不一致
- 伪代码抽象过高，缺少真实落点
- 需要先对齐“会改哪些文件”，再进入代码阶段

## 触发场景

当用户表达以下意图时使用：
- “按当前项目结构改伪代码”
- “不要新定义，直接用现有数据/现有 pb”
- “列出会改哪些文件并写回伪代码”
- “先只调伪代码，不生成代码”

## 硬性约束

1. 只修改 `.src/**/*.md` 伪代码文件
2. 不新增目标代码文件，不修改 `Unity/` 真实业务代码
3. 不凭空新增结构，优先复用现有类/字段/协议
4. 路径与命名必须来自仓内真实文件与真实标识
5. 若用户要求“去缓存/用原 pb”，必须删除中间缓存描述

## 执行流程

### 1) 对齐输入口径

- 提取用户约束（例如：
  - 只做客户端
  - 推送协议：`P_SyncPowerChange`
  - 登录来源：`PetInfo.Power` / `PartnerItemInfo.Power` / `FormationData.Power`
  - 弹窗：`UIFightPowerChangeView`
  - 不显示标题，动画内部处理
  - 旧字段替换：`TotalScore -> Power`
  - `PlayerModel.Instance.BattlePower` 展示位改为当前阵容战力）

### 2) 以真实代码反查落点

- 在 `Unity/Assets/Scripts/HotProject` 内检索真实类、字段、消息、界面名
- 先找“入口层”（Push 注册、Model 写入），再找“展示层”（UI 读取）
- 最终形成“目标文件清单”

### 3) 回写伪代码

- 写入/更新 `.src` 文件（默认优先更新当前业务单文件）
- 伪代码结构推荐：
  - `目标文件清单`
  - `范围约束`
  - `已有声明`
  - `显示口径`
  - `新增定义`（若用户要求不新增，则写“无”）
  - `操作流程`

### 4) 输出给用户

- 明确本轮只改了伪代码
- 给出更新文件路径
- 简述改动点（不贴大段全文）

## 伪代码写法规范（本技能）

1. 使用中文命令式语句
2. 不写可运行代码
3. 不引入无来源的抽象对象
4. 每条流程语句尽量包含“动作 + 数据来源 + 原因”
5. 用户明确“不要新增定义”时，`新增定义`必须为 `无`

## 目标文件清单写法规范

每条使用：

`- <真实路径> // <该文件改动目的>`

示例：

`- Unity/Assets/Scripts/HotProject/Network/NetGlobalPush.cs // 注册 P_SyncPowerChange 推送入口`

## 常见修正规则

### 规则 A：PB 口径优先
- 出现 `TotalScore` 与 `Power` 并存时，按用户口径改为 `Power`
- 差值优先使用推送字段，缺失时再从当前 pb 对象回读

### 规则 B：展示口径去歧义
- 明确到具体控件/界面（如 `UIPartnerView.fight`）
- 对“是否显示标题/动画谁处理”给出单义描述

### 规则 C：全局字段替换策略
- 当用户要求“`BattlePower` 展示位改为当前阵容战力”，先列出全部使用点，再写入伪代码清单

### 规则 D：去缓存策略
- 用户说“去掉缓存”后，伪代码中不得再出现“本地缓存/索引/缓冲队列”等字样

## 输出模板

```markdown
已按当前项目真实结构同步伪代码，仅修改 .src 文件，未改目标代码。

更新文件：
- .src/app/xxx.md

本轮调整：
- <关键点1>
- <关键点2>
- <关键点3>
```

## 与 ai-code-translation 的配合

- `ai-code-translation` 是主调技能（编排者）
- 本技能是被调技能（伪代码对齐器）
- 固定顺序：
  1) `ai-code-translation` 接收需求并判定需要项目对齐
  2) 调用 `project-pseudocode-sync` 修正 `.src` 伪代码
  3) 回到 `ai-code-translation` 进入确认与后续代码生成

## 回传确认话术（返回主调技能后使用）

`project-pseudocode-sync` 执行完成后，返回 `ai-code-translation` 时应使用以下确认选项，保持交互一致：

```text
当前状态：待确认
我已按当前项目真实结构完成伪代码对齐，并仅修改了 .src 文件。
本轮已写入/更新伪代码文件：<逐条列出 `.src/*.md` 路径>
请选择下一步：
1) 生成目标代码（不含自测代码）
2) 生成目标代码 + 自测代码
3) 仅调整伪代码，暂不生成目标代码
4) 按当前项目结构继续对齐伪代码（再次调用 project-pseudocode-sync）
```
