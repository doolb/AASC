# 项目规则

## 文档规范
- doc/design.md: 项目设计文档
 - doc/design/*.md: 每个功能模块的设计文档
- doc/spec.md: 项目实现文档
 - doc/spec/*.md: 每每个功能模块的实现文档
- todo.md: 项目未完成任务列表文档
- usage.md: 项目使用说明文档
- rules.md: 项目规则文档，包含代码规范，文件结构，命名约定，消息格式等
- ref.md: 项目参考文档，外部资源，如 API 文档，库文档，设计模式等
- changlog.md: 项目变更日志文档，记录项目每次版本的变更内容 （工具生成）


## 注意事项
1. 一定要记得按照文档规范，更新文档
2. 不使用 var，使用 const/let
3. 异步操作使用 async/await
4. 错误处理使用 try-catch
5. 避免全局变量污染
6. DOM 操作尽量批量处理
7. 每次对话完一定要更新todo.md和相应的design文档，保持任务列表的最新状态，已完成的功能，从todo.md中删除，再在docs/design.md中记录
8. 更新代码前，首先把实现思路更新到docs/spec/*.md中对应的位置，如果没有文件，就新增一个文件
9. 如果有大的变动，需要更认新changlog.md文档

### 和用户对话时的注意事项
- 可以从docs/spec/*.md中查看项目实现文档
- 更新代码前，把实现思路更新到docs/spec/*.md中对应的位置
- 可以从design 和 spec 中和已完成任务以及和已完成任务以及和需求改动的文件名，资源命名规则等
- 把用户的问题更新到doc/design.md以及doc/spec/*.md中对应的功能模块的合适的位置，如果没有合适的位置，就新增一行，分析需求并记录
- 已完成design的任务，在最前面添加✅已完成标记，在下放记录和需求改动的文件名，资源命名规则等
- todo.md / docs/design.md 格式：
```
# 大模块
## 小模块
 - (✅已完成)[添加时间][完成时间] 任务描述
   - 改动的文件名，资源命名规则等
 - (✅已完成)[发现时间][修复时间] Bug 修复描述
```
