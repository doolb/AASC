## 每次开始与进入游戏

1. 检查 ADB 连接、当前屏幕和前台应用。若已在云幻塔中，观察当前页面后接续，避免重启已有会话。
2. 息屏时用唤醒键，例如 `adb -s <设备> shell input keyevent KEYCODE_WAKEUP`，随后截图检查是否锁屏。避免用切换亮灭状态的电源键。
3. 解锁、密码、短信验证码及实名验证由用户在手机上完成；认证结束后重新观察，不记录密码和令牌。
4. 需要启动时重新核对启动组件，可使用下列已核对入口；升级后若入口变化，先重新查询包管理器，不猜 Activity。

```sh
adb -s <设备> shell am start -n com.pwrd.cloud.huanta.laohu/com.pwrd.cloudgame.client_core.LaunchActivity
```

5. 云客户端的登录、开始/进入入口、服务器和角色选择以现场为准，沿用当前账号及已有角色。界面要求选服且无法确定时请用户指定，不创建新角色或换号。
6. 看到队列或加载时等待；看到角色及可操作 HUD 后才确认进入游戏。客户端首页、标题页、排队页及加载进度均不算进入角色场景。

## 排队、息屏与中断恢复

- 云游戏可能排队，保留当前队列，读取位置与预计时间；建议每20～30秒检查状态，长时间等待时告知用户进展。不要反复开始、取消或重启丢失队列。
- 等待时可能息屏，先唤醒，再截图确认所处页面；不为保活盲点游戏区域，不默认永久修改系统息屏设置。
- ADB断线后恢复原设备连接，重新观察队列/角色/菜单状态，再继续第一个未确认完成项。
- 点击后中断或结果不明时，先核对“已领取”、奖励弹窗或实际数值，不能重复执行旧坐标序列。
- 免费云时长不足、收费通道、协议变更或未知弹窗时读取内容并报告，不自动购买云时长、月卡或充值。

## 每日主流程

按现场截图确认后执行；菜单、任务顺序和可领取状态可能变化，不能盲点旧坐标。

### 1. 特别行动、签到和通行证

- 主界面右上礼物图标 → 特别行动，检查免费每日供给并领取。本次“执行供给”第1天领取成功。
- 底部“福利” → “签到”，领取当天奖励；本次第5天领取成功。
- 福利中检查“通行证”版本日常及已解锁奖励；本次功勋等级0，未有已解锁档位可领。按实际可领状态操作。

### 2. 必做与米娅私厨

- 回主界面 → 右上交叉武器图标 → 必做/每周；领取已完成的在线奖励等可领项目。
- 找到米娅私厨并进入，逐次“品尝”，每次等动画和奖励弹窗结束；页面显示每日 05:00、12:00、18:00 各增加1次，按当前可用次数执行。当天次数用完后返回周常，领取已完成的米娅任务。本次品尝3次，日任务3/3已领；每周累计9次任务显示3/9，尚未完成。
- 查看已达成的活跃度奖励，未达到门槛则记录，不强行做其他任务。

### 3. 次元历练代理作战

- 在必做/每周中滑动寻找“通关次元历练1次”，点“前往” → “参与” → 代理作战。
- 核对代理次数及消耗：本次默认12次，调整为1次，消耗30活力；确认完成一次即可，不沿用默认12次。
- 看到“作战成功”后关闭结果，返回周常；列表可能重排，重新寻找并领取已完成的次元历练任务。本次1/1奖励已领，周活跃达到60。
- 周常可能已有进度；例如本周1次任务已领后会显示3次任务，单次代理后未达3次就记录进度，不虚报领奖。次数不足、资源不足或按钮变化时记录，不购买资源或盲目重复。

### 4. 邮件附件

- 主界面左侧信封 → 邮件，查看附件，点击“一键领取”，核对到账；本次领取成功。
- 区分未读与未领附件；无可领取则记录。不删除邮件，不点击外部链接。

### 5. 用 ADB 关闭进程（必须）

奖励核验结束后关闭**云幻塔**，不要只按Home键：

```sh
adb -s <设备> shell am force-stop --user 0 com.pwrd.cloud.huanta.laohu
adb -s <设备> shell pidof com.pwrd.cloud.huanta.laohu
adb -s <设备> shell ps -A
adb -s <设备> shell dumpsys package com.pwrd.cloud.huanta.laohu
```

- 等待数秒复查：`pidof`无PID、进程列表无该包及子进程、`User 0`显示`stopped=true`，前台离开云幻塔。
- `pidof`无PID时的非零退出状态是正常现象；若进程又出现，重新核对是否被启动并有界复停，仍失败则报告，不无限重试。
- 关闭后不重新启动游戏。本地客户端已关闭不能等同于已向云平台查询确认服务器会话释放。

## 执行和结果记录

每一步采用“新截图 → 识别当前页面/按钮 → 一次动作 → 等待 → 新截图核验”。需要区分游戏UI与云客户端悬浮设置，打开菜单后等待动画结束；按钮重排后重新定位。遇其他人操作手机或未知页面先停止输入并确认现场。

每次重新读取当天状态，不把历史结果当成今天已完成。最终按以下项目汇报，状态使用“已完成、已领无需重复、无可领取、条件不足、未执行/中断未确认”。

| 检查项 | 判据 |
| --- | --- |
| 进入游戏 | 角色场景和可操作HUD出现 |
| 每日主流程 | 用户指定的当前每日入口与动作逐项核验 |
| 米娅 | 仅在当前流程已确认时执行，并核对次数/状态变化 |
| 签到及赠礼 | 奖励已领取标记或明确到账结果 |
| 邮件 | 附件已领取，或明确没有可领附件 |
| 结束关闭 | 无应用主/子进程，包stopped=true |

本次实机结果见各步骤；每次保留未达条件及未执行事项，不虚报完整日常完成。
