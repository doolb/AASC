# 2026-08-17 文件驱动多 Agent 工作组（Workgroup）

## 任务描述

实现一个开发流程工具：多个独立 Claude 进程通过纯文件系统组成 AI 开发团队。main（主 agent）收需求并分发任务，子 agent 自治轮询认领、干活、写回结果。

## design 需求

见 `workgroup/docs/design.md`：
- 目录结构：roles/（角色定义）、members/（成员状态）、tasks/pending+claimed/（任务流转）、results/（结果）
- 空闲判定：lock 文件（在线）+ busy 文件（忙碌）叠加
- 历史画像：members/<name>/history.md，任务完成后追加；main 按匹配度打分分发给同角色成员
- 原子认领：fs.rename 防重复
- 崩溃恢复：lock 内 PID 已死则覆盖

## spec 设计

见 `workgroup/docs/spec.md`：
- poll.js 主循环状态机：idle ──认领──▶ busy ──完成──▶ idle
- main 分发：读 roles + members 状态 → 拆解 → 打分 → 写 pending
- 认领失败（ENOENT）跳过

## 受影响的功能模块和代码

| 文件 | 动作 | 说明 |
|------|------|------|
| `workgroup/tools/poll.js` | 新增 | 子 agent 轮询脚本 |
| `workgroup/README.md` | 新增 | 工作组使用说明 |
| `workgroup/roles/main.md` 等 | 新增 | 角色定义模板（内容由用户确认） |
| `workgroup/.gitignore` | 新增 | 忽略 members 运行时信号、pending/ |

## 自测用例

1. poll.js 启动 → members/<name>/ 创建、lock 写入、role.md 写入
2. main 投递 role 匹配任务 → 原子认领 → busy 出现 → 完成后 busy 删除 → results/ 出现结果、history.md 更新（专长画像累加 + 最近记录追加）
3. 两个同名角色 agent 抢同一任务 → 只有一个认领成功
4. 崩溃残留 lock（PID 已死）→ 新 poll.js 能覆盖
5. 任务 role 不匹配 → 子 agent 跳过
6. **重启历史保留**：同名 agent 重启 → history.md 原样保留、仅追加新任务
7. **启动总结注入**：spawn claude 前 prompt 含专长画像 + 经验约定，不含最近记录
8. **防膨胀**：最近记录超 N 条删最旧、经验约定超 M 条删最旧
9. **无命令交互启动**：`node poll.js` → 菜单列出已有角色；输入新名 → 生成 roles/<name>.md 模板；成员名列出已有成员可选复用、也可输新名

## 兼容性测试

- 本项目使用 Claude Code CLI（`claude --print`），需确认 `--print` 非交互执行模式可用
- Node.js 版本：使用内置 fs 模块，无新增依赖

## 性能测试

- poll.js 扫描间隔 5s，文件操作全部为本地磁盘，开销可忽略
- 多 agent 并发认领由原子 rename 保证，无锁等待

## 风险评估

- `claude --print` 是非交互执行；若当前环境不支持或 token 消耗大，可能需要降级为提示用户手动运行
- lock/busy 是运行时状态，若误提交到 git 会污染仓库 → 用 .gitignore 兜底
- history 匹配度打分是启发式，初期可能分配不完美 → 可接受，后续迭代
