# 局域网五子棋设计

首版由 Android 房主在局域网运行 HTTP/WebSocket 服务，浏览器或其他 APK 通过房主地址加入；房主也使用同一网页界面参与。房间两人，黑棋先行，支持 9、11、13、15 路，五子连线获胜。房主配置尺寸并开始游戏；服务端校验座位、轮次、版本及空位，向玩家广播权威快照。客户端断线重连时携带本地身份恢复座位。房主应用关闭后服务停止，再开启时恢复持久化的棋局与座位，公网中转留待后续实现。

消息采用 AASC JSON 消息外壳（id、version、type、source、topic、payload 等），配置使用 WebSocket 命令并由服务端保存和广播，连接时补发。网页和 APK 使用同一客户端，APK 仅增加开启局域网服务及系统能力桥。房主显示含局域网房间地址的二维码，手机相机扫码可直接在浏览器打开；网页提供摄像头扫码入口，在浏览器允许摄像头的安全上下文下使用。普通 HTTP 局域网页面受浏览器限制时提供系统相机扫码和手动地址。地址只支持同一局域网且设备网络允许互访。

APK 房主服务还直接分发与 APK 内置版本相同的网页文件，使浏览器扫码打开地址即可获取客户端，无需单独部署网页。

代码热更新需求：参考现有 Offline APK 的签名清单、文件大小及 SHA-256 校验、候选版本健康确认和失败回退；用户已选择复用 Offline 更新源及签名体系、使用独立游戏制品，当前尚未实现热更新。Android 原生服务变更仍需更新 APK。

## 独立游戏更新方案（尚未实现）

网页可从公网服务器独立分发。APK 从现有 Offline 内外网更新服务读取独立游戏签名清单与游戏制品，复用已有 RSA 签名体系；游戏网页包与游戏 APK 使用独立版本和路径，不替换现有 Offline 服务清单。网页包核验、暂存后切换并设置健康确认，异常恢复上一健康版本；房主本地服务分发当前健康网页。APK 下载前后校验清单签名、包名、版本、文件大小、SHA-256 和 APK 签名，交由 Android 系统安装器确认安装；原生房主服务通过 APK 更新。无可用更新或下载失败时继续使用本机健康版本。现有调试 APK 的签名可能与正式 APK 不同，正式升级需要一致的安装包签名。

公网 HTTPS 网页连接局域网房主时，浏览器可能阻止不安全 WebSocket；首版将房间链接导航至房主分发的局域网网页，并由该网页连接房主。公网直连局域网、跨公网中转和可信 HTTPS 局域网部署属于后续工作。

## JavaScript 中转与浏览器房主（内网源码已实现）

Node.js 中转服务供浏览器和 APK 网页建立 AASC 消息通道。创建房间的网页在本地运行 JavaScript 游戏管理器并保存权威棋局，中转按房间转发玩家命令和房主快照；房主可在浏览器或 APK 网页中创建房间。房主离线时暂停房间，重连后按身份恢复。现有 Android 独立局域网房主模式继续保留。网页更新和 APK 更新沿用独立游戏制品方案。

2026-11-12 用户调整部署范围：Node.js 中转首版只在内网自行运行，不对公网开放。中转同时分发网页；网页和 APK 网页可作为房主，本地 JS 管理棋局并以 AASC 消息经中转转发。内网使用 HTTP/WS；将来部署 HTTPS 时使用 HTTPS/WSS。每个房间使用随机标识及独立房主凭据，房主凭据不进入邀请链接；按房间隔离并校验发件身份、消息类型和长度，房主掉线暂停。使用房主本地存储恢复棋盘及凭据，中转重启后由房主重建房间，玩家通过同一邀请链接重连。APK 自带原生局域网房主模式保留。

已实现 `server/relay.js`、`game-host.js` 与共享页面。自动化覆盖两个真实浏览器创建房间、落子、房主刷新和离线恢复，以及中转身份校验；尚未进行 Android 双设备验收或上线部署。

## 多游戏扩展（源码已实现）

用户后续希望支持多个游戏。平台提供游戏目录和稳定 gameId，每个游戏模块声明名称、玩家人数范围、版本、房间状态、操作校验和页面渲染；五子棋为首个模块。建房时选择游戏并将 gameId 和协议版本绑定房间，邀请链接、加入握手与重连快照携带游戏标识，不兼容时明确提示。中转只管理通用房间、成员、容量和带类型的 AASC 消息路由，具体规则由房主选中的游戏模块负责；不同游戏人数上限由受信注册表限制，而不是固定两个座位。网页和 APK 网页共享模块与目录；已有 APK 原生房主模式需保留现有五子棋协议和旧存档兼容，改造为可扩展接口，不能宣称尚未迁移的其他游戏已在该模式运行。

已实现共享静态游戏目录 `games/catalog.js`、网页模块注册 `games/modules.js`、五子棋的 `games/gomoku/host.js` 与 `view.js`；游戏选择、邀请、加入与快照携带 gameId 和版本。中转按游戏容量分配座位，分发游戏允许的操作；房主和玩家断线后按原座位恢复。旧五子棋邀请、旧握手和旧存档无标识时按 gomoku/1 兼容。APK 原生房主通过 `NativeRoom` 接口及 `RoomServer` 注册表选择实现，现有规则归入 `GomokuRoomServer`，目前只注册五子棋。

本次仅迁移现有五子棋；三人游戏只在自动化测试构建中注入，未作为正式游戏发布。网页包、APK 更新仍是独立待办，不能误标为已实现。新增游戏需编写并构建模块，当前不支持运行时直接安装第三方游戏。
