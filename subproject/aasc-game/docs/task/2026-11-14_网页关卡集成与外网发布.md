# 独立网页关卡集成与发布

- 任务：将已有完整通关证据且兼容当前网页引擎的关卡转换为独立静态网页关卡，并建立未兼容/未完成关卡的排除边界；第59关仅保留采集状态，不作为可玩关卡发布。
- Design：见 `docs/design/pig-game.md` 的“独立静态网页首批关卡集成”。
- Spec：见 `docs/spec/pig-game.md` 的“独立静态网页首批关卡集成”；先按证据筛选，再把 `level-reviewed.json` 与 `solution-order.json` 转为网页统一 JSON，由 `verifyPlan` 启动时独立重放。
- 首批范围：普通猪及现有网页引擎可表达的机制；鸭子、小象、动态铁笼和第59关阶段性采集不进入可玩列表。
- 受影响功能：网页关卡选择与加载、静态资源白名单、关卡 JSON、网页规则测试、动画/HTTP 测试、使用文档和变更记录。
- 不做项：不猜测待确认动作，不把 `stage_complete` 或 `interrupted` 记录当作通关，不直接复用未确认的外网 Offline/Node 发布目录，不构建 APK。
- 自测用例：每个新增关卡 JSON 加载、`verifyPlan` 完整重放、最终清空、动作篡改拒绝；现有第40、48关回归；浏览器访问每个新增 `?level=`、步骤提示、撤回、进度跳转和通关显示。
- 兼容性测试：本地静态服务器 GET/HEAD 资源；Chromium 页面黄金路径；移动端布局不回归。外网验证仅在静态根目录和 URL 明确后执行。
- 性能测试：首批最大猪数关卡加载和完整重放在页面初始化可接受；不引入服务端状态。
- 风险评估：采集步骤来自不同模型和阶段合并记录，必须逐关独立验证；动态铁笼等机制若未实现不可降级为普通猪；公网目标不明确时阻塞发布。
- 预计工时：本地筛选、转换、测试和页面接入约 4 小时；外网目标确认后的上传与 HTTP 校验另计。
