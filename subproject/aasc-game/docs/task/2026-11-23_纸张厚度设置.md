# 纸张厚度设置实现与验收

## 需求与设计

用户询问厚度设置位置后确认希望增加设置。原先厚度为全局固定 0.008，页面没有入口。本次在新建/添纸及工作台增加每纸厚度设置，工作台使用滑块和数值输入；按原纸边长百分比显示，范围 0.1%～1%，默认 0.4%。设计见 `../design/gami.md`，伪代码见 `../spec/gami.md`。

厚度同时影响绘制、点边可见性、层间距与碰撞。已折纸调整时按比例更新保存的层位移并验证接触，失败保留原状态；存档、导入导出、切纸和撤销保持一致。页面设置属于独立静态折纸材料数据，无跨端运行配置。

## 需求分析（analyze-requirement-level，enterprise）

- 结论：方案可开发，具体范围已由用户确认。主等级 L6，次等级 L5；邻层混合。
- 证据：厚度输入/材料字段/几何和接触契约为 L6 强证据两项；存档、撤销及失败保留为 L5 强证据一项。
- 置信度：6 / 9 × 0.90 = 0.60，中。评分：层级清晰度 23/25、证据充分度 16/20、实现完备度 17/20、风险暴露度 18/20、L4 可落地性 14/15，总分 88/100。
- 能力下放：必须下放到 L4，原因是同一值涉及多个几何入口及已保存层位移；按 spec 的输入校验、统一读取、候选校验和保存恢复数据流拆解。
- 直接开发风险：中。断点为已折纸增厚可能穿透及旧存档无厚度字段；行动为候选接触检查和缺省兼容，均已纳入实现设计。
- 不自动调用额外翻译或伪代码同步技能，直接使用本项目既有伪代码与实现流程。

## 涉及文件

- `web/gami/index.html`、`style.css`：厚度输入与布局。
- `web/gami/app.mjs`：新建/添纸输入、选纸同步、设置提交、存档及撤销。
- `web/gami/paper-topology.mjs`：默认值、范围、每纸厚度读取及导入校验。
- `web/gami/paper-contact.mjs`：厚度变更的候选接触检查，统一计算参数。
- `web/gami/scene.mjs`：表面、侧壁、层间距与点边拾取读取每纸参数。
- `tests/gami.test.js`：新增厚度契约与浏览器操作验证。
- 对应设计、伪代码、任务、待办、使用说明与变更日志同步。

## 自测和兼容性

1. 新建、添纸、切换多张纸，厚度互不影响；滑块和数值同步。
2. 最小值、默认值和最大值影响侧壁及层间距，接触使用相同厚度；异常值拒绝。
3. 已折纸调整后不会因设置产生穿透，拒绝时纸形与撤销历史不变。
4. 修改后撤销、刷新、导出导入保留厚度与层位移；旧存档缺省兼容。
5. 回归吸附、压平、折痕展开和交点操作。
6. 先运行 `env -u DISPLAY npm run test:gami`，再以 `DISPLAY=:0 npm run test:gami` 验证 SDDM 硬件浏览器。

## 性能、风险和预计工时

厚度变更只在确认数值时做一次完整候选校验，滑动预览需避免重复重建和高频接触计算。保留现有面片和接触预算；真实移动设备仍需实测。预计 0.5～1 个工作日，取决于已有复杂折形的接触回归。厚度范围及已折纸变更规则已由用户确认；已折纸需扫描过渡状态，最多 64 面和 16000 面对步。

## 实现记录

- 工作台厚度控件放在左上工具栏下方。初版放在底部时，浏览器回归发现面板升高会遮住刷新后待压平的纸角，因此调整位置，并增加纸角命中画布的断言。
- 每纸保存可选 `thickness`；`paperThickness` 为旧存档提供原默认值，导入拒绝非数值和越界厚度。
- `resizedPaper` 创建候选层位移并扫描厚度过渡，全部通过后才记录撤销和保存。待压平纸张校验重建形状，但不将显示条带层位移写入材料面存档。
- `scene.mjs` 的正背面、侧壁、折痕位置和可见点边拾取统一读取材料厚度，薄纸的遮挡容差按厚度缩小。
- 两面平折纸由 0.008 增厚到 0.02 的 30 次计算采样：中位 1.85 ms、95 分位 5.94 ms。这是 Node 计算模块测量，不代表整页或真实移动设备帧率。
- 该独立静态子项目未进入 Offline 服务包生产文件集合，不修改主工程 Offline 产物状态；保留工作区无关配置及其他游戏改动。
