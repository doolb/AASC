# 折纸游戏化操作界面

状态：实现、分组回归及公网资源校验已完成。

需求：操作 UI 更像游戏。按 analyze-requirement-level 的需求明确性检查，风格和布局尚待确认，暂不输出可开发判级。建议轻松折纸游戏 HUD：米白/青绿/暖橙，底部图标文字工具栏，模式分段按钮，稳定的上下文主动作与取消区，参数按需展开。

设计与伪代码：docs/design/gami.md 游戏化操作界面；docs/spec/gami.md 游戏化 HUD。

涉及文件：web/gami/index.html、style.css（布局/控件/响应式）；app.mjs（设置与工具状态、上下文反馈）；pair-controls.mjs（实际 HUD 避让）；tests/gami.test.js（新入口与布局回归）。折纸几何与保存契约沿用已有能力。

自测：DISPLAY=:0 npm run test:gami；桌面与 390px 窄屏、手机横屏截图检查；模式选择、设置开关、压平/留痕还原、取消、双角抓取、撤销、刷新。保留旧功能断言，不以修改预期掩盖遮挡。

兼容：旧存档、鼠标/触屏、键盘与可访问名称；无悬停依赖。性能：动画仅使用透明度/位移，布局测量不进入几何求解热循环，减少动态偏好生效；复杂纸形性能仍独立验收。

风险：工具栏遮住角点、设置层穿透触发纸张手势、把确认按钮换布局时破坏原事件、编号避让仍硬编码。对应措施：可点击位置断言、菜单事件隔离、复用原状态与动作、实际边界避让。

预计工时：实现与回归约半个工作日。已确认：采用上述轻松折纸游戏风格及布局。

实施补充：新增 hud.mjs 隔离 UI 状态及避让布局。需求为 L5 操作状态呈现与 L6 控件契约，按既有工具状态、当前动作、材料参数拆解为 spec 数据流；用户已明确授权实现，无需追加技能选择。

专项验证：游戏 HUD 浏览器测试通过，桌面 1000×760、竖屏 390×844、横屏 844×390，主要按钮至少 44px，编号直接点击不被 HUD 或设置遮挡；Escape 关闭后焦点回到设置按钮，纯 UI 切换不改变纸形存档。截图已检查。

回归修正：隔离工具容器 activeTool 与按钮 data-tool 属性；提示固定高度避免抓角时推动编号。CDP 视口切换后需等实际两帧重绘再采集角点坐标，独立双指验证两侧均转动通过；完整双模式用例复跑通过。

最终验证：26 项用例分组通过，包括 22 项几何/状态用例和 4 组浏览器用例；首轮完整进程异常退出未计为通过，两个失败点定位修复后各自重跑通过。DISPLAY=:0 / SDDM / Intel HD 610，未降低双侧实际旋转和可点击性断言。
