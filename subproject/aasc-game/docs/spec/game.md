# 局域网五子棋实现伪代码

```text
已有声明 := AASC 消息外壳、现有五子棋尺寸 9/11/13/15、四方向连续五子规则
新增定义 := Room { config, seats, board, turn, revision, result }; Client { token, name, connection }
房主启动 → Android Socket 服务提供网页和 WebSocket → 客户端连接并发送 game.join → 按身份恢复座位或占用空座 → 广播权威 room.snapshot
访问房主 HTTP 地址 → 读取 APK 内置网页资源 → 浏览器加载共享客户端 → 通过同一房主连接 WebSocket
房主配置 → game.config 命令 → 校验房主与尺寸 → 持久化规范配置 → 广播权威快照
房主开局 → 校验两席在线 → 清空棋盘、黑棋先行、递增版本 → 广播快照
玩家落子 → 校验座位、连接、游戏状态、版本、轮次与空位 → 落子 → 四方向计数判胜或判平 → 更新轮次与版本 → 广播快照
断线 → 标记座位离线并广播 → 重连凭身份恢复 → 返回当前快照
房主应用关闭 → 持久化的棋局、座位身份与尺寸保留 → 重新开启服务时恢复权威状态，玩家重连后重新标记在线；房主密钥每次启动重新生成
页面 → 展示房间地址、座位、棋盘和状态 → 客户端只提交命令，不自行决定棋局
房主房间地址 → 编码二维码供其他设备扫描 → 扫码结果校验为局域网 HTTP 地址 → 导航到房主页面并连接房间
网页扫码 → 安全上下文申请摄像头 → 持续解码二维码 → 成功或退出时停止摄像头；不支持摄像头时保留手动地址与系统扫码方式
待实现热更 := 复用 Offline 更新源及签名体系，使用独立游戏制品 → 校验签名清单、版本和兼容性 → 下载候选文件并核对大小/SHA-256 → 健康确认后切换 → 失败保留上一健康版本
待确认更新方案 := 既有 Offline 源 + 游戏独立清单/网页包/APK → 校验 RSA 签名及版本兼容 → 分别校验大小与 SHA-256 → 网页包安全解压至候选版本 → 页面健康确认后切换，失败回退 → 房主服务分发健康网页；APK 验证包名与签名后交系统安装器确认
公网 HTTPS 页面 → 扫码或输入房主地址 → 导航至房主 HTTP 页面 → 使用该页面连接同源局域网 WebSocket；不假设 HTTPS 页面能直接访问不安全 WebSocket
待确认浏览器房主 := 公网网页内 JavaScript 游戏管理器持有权威棋局 → 房主与玩家连接 Node.js WSS 中转 → 中转验证身份及房间并按 AASC 消息转发 → 房主校验落子并广播权威快照 → 房主离线暂停，身份验证后重连恢复；原 Android 局域网方式保留
内网中转 := Node HTTP/WS 在指定内网接口分发网页 → 房主网页生成房间标识与仅本地保存的房主密钥 → 建房并生成不含密钥的邀请链接 → 玩家凭房间号加入 → 中转绑定连接与座位并将命令转交房主 → 房主本地检查身份、版本、轮次及空位，持久化后广播权威快照 → 房主掉线暂停，重连时恢复与同步；中转启动默认只绑定 127.0.0.1，显式指定内网地址开放给同网设备
内网中转自测 := 自动化真实浏览器建房、双端落子、房主刷新和关闭重连 → 校验座位身份、伪造快照拒绝、房主离线通知与恢复 → 原 Android 权威棋局和二维码测试继续通过
独立游戏制品构建 := 网页固定文件集合与指定版本 → 生成版本化 ZIP → 从给定 APK 读取版本、包名与签名指纹 → 计算字节数和 SHA-256 → 使用 Offline 签名私钥签署游戏专用规范化 JSON 清单 → 校验签名及公钥匹配 → 生成独立清单、网页包与 APK，禁止覆盖既有 Offline 清单
多游戏 := 游戏注册表 { gameId, 协议版本, 名称, 玩家人数范围, 规则与渲染入口 } → 用户选择游戏 → 建房/邀请/加入/快照绑定 gameId 和版本 → 中转按注册表约束人数并隔离房间和通用操作 → 房主加载选定游戏模块处理状态和操作 → 客户端加载对应画面 → 不兼容或未知游戏拒绝 → 旧无 gameId 的五子棋会话与存档按显式兼容规则恢复
实施契约 := 共用目录按 gameId 查找 {version, minPlayers, maxPlayers, actions}；默认 gomoku/version 1 → 新建房间持久化 gameId、version；旧邀请和握手缺少二者仅按 gomoku/1 处理 → 其他游戏及不兼容版本明确拒绝 → 邀请 URL 带 game 与 version；缺省旧 URL 为 gomoku/1
中转 := 每间房保有受注册表约束的多席位身份 → 按座位路由操作和错误 → 只允许该游戏声明的操作 → 房主断线通知全部玩家 → 房主重连补发座位与状态；presence 保留旧 guestOnline/guestName 字段以兼容旧五子棋页面
客户端 := 目录生成选择器 → 游戏模块注册独立规则管理器与渲染器 → gomoku 使用现有状态和存档路径 → API 默认 gomoku/1，APK 原生旧模式仍仅允许五子棋但对新旧请求兼容
原生适配 := RoomServer 通过 NativeRoom 注册表选择版本化游戏房间实现 → 默认 gomoku/1 → GomokuRoomServer 保留原持久化、HTTP/WS、落子行为和旧身份 → 未注册游戏拒绝；其他原生游戏将来添加独立实现和注册，不复用五子棋规则
多游戏验证 := 五子棋原局域网/APK/中转回归 + 第二个测试专用模块验证不同游戏与不同人数的隔离、未知游戏拒绝、版本不匹配、断线恢复和旧数据兼容；不把测试模块伪装为正式游戏
浏览器测试注入 := 临时网页资源目录及测试专用游戏模块 → 仅测试服务注册三人测试游戏 → 真实浏览器从目录选择并建房 → 三个不同页面加入、发送游戏特有操作 → 检查座位、状态、房间隔离；生产目录仍只登记正式五子棋
平台断线 := 暂停游戏区域交互，不改写具体游戏状态 → 收到匹配游戏与版本的权威快照 → 解除暂停、按对应模块渲染
自测 := 使用实际 RoomServer 和两个 WebSocket 客户端验证 HTTP 页面分发、房主与玩家加入、棋盘配置、非法落子、获胜及重连恢复；二维码编码与解码使用真实库往返验证
```
