# HIE 子工程与游戏任务桥接伪代码

## 猪关卡目标导航伪代码（进行中）

高层未知机制处理 := 导航采集返回候选与截图 → 高层 AI 提交绑定首屏的完整布局，或提交棋盘内单步试探与原因 → 宿主校验当前关卡、窗口与棋盘边界并保存动作前画面 → 执行一次点击 → 保存动作后画面及结构化结果 → 重新采集，旧布局与路线不再复用 → AI 根据反馈修正假设并继续；禁止道具区域与任意命令。自动计划仍必须通过已支持机制的完整求解和独立重放；未知规则先通过试探验证，再接入对应求解器，不能将模型的猜测当成已验证事实。

```
加载 pig-game 导航包 → 校验目标与步骤 → 设置当前关卡目标及隔离的进度存储
采集步骤 → GameTaskBridge 仅观察当前 X11 窗口 → 保存原图及候选 → 记录采集完成
布局步骤 → 仅接受明确复核、绑定当前采集截图摘要、无未建模物件的布局 → 否则上报缺口并阻塞
求解步骤 → 固定命令调用 pig_locked_candidate.py --strategy auto → 独立重放完整计划 → 保存计划与布局摘要
执行步骤 → 验证计划摘要、关卡与原始截图一致 → 验证棋盘范围不会触及底部道具 → 既有 X11 执行器逐步匹配并确认 → 仅胜利截图确认后记录执行和完成
中断、错误、机制未建模或部分计划 → 保留证据并阻塞；不使用底部道具，不伪造胜利
目标 success 为完成条件，不是前置条件；condition/when 为前置条件，保留原条件判断
```

游戏宿主 → GameTaskBridge.run → 收集退出码及实际证据；脚本维护工具仅限 HIE scripts 现有 JavaScript 文件，原文件摘要一致后更新 → 语法检查和可运行的 HIE 自测（排除缺失数据集及导航资源的两组）→ 失败恢复原内容并返回错误。

GameTaskBridge.run(inspectOnly=true) → 向固定游戏脚本传入 --inspect-only → 只采集首屏及候选、记录零点击并停止；省略时保持既有调用兼容。

工程路径 := AASC/subproject 下 HIE、retop、remote-gamepad 实际目录
旧 HIE 路径 → HIE 实际目录；旧 retop 路径 → retop 实际目录
关卡证据目录 → 读取识别、计划、结果 → 组装观察与反馈 → 非通关结果映射 NavigationGap → 可选报告到队列
显式启用 → 验证关卡、窗口和显示参数 → 固定脚本与参数数组启动游戏任务 → 返回退出状态；默认不启动

统一仓库 := 将 HIE 与 retop 的嵌套 Git 元数据移出工作树 → 子工程文件由 AASC 主仓库管理 → 源代码和必要文档纳入主仓库；模型、运行日志、设备数据和构建产物按路径忽略并保留本地 → 不自动提交。旧提交历史不要求合入主仓库。

仓库 references 规则 := 各层 references 目录匹配 Git 忽略 → 已跟踪 references 文件仅从索引退出并保留本地文件 → 历史提交与远端现状不变；脚本依赖的模板及测试数据由本地提供。

中层优先调度伪代码:
    默认行为保持三层全部调用；显式启用中层优先时先运行本能与肌肉记忆
    两层没有可用计划，或存在明确需要 intelligence 的缺口 → 调用 intelligence
    否则跳过 intelligence，仍按优先级选择计划并保留安全层结果
猪关卡复核伪代码:
    捕获首屏与候选 → 固定中层适配器匹配同关历史胜利证据及完全一致的棋盘像素
    有可信历史复核布局 → 绑定当前截图摘要，固定求解并独立重放
    识别冲突、未知物件、未验证机制或搜索失败 → 保留证据并报告结构化缺口；不可将候选伪造为已复核
