已有声明 := ADB 设备列表、设备截图、原生 UI 层级、设备点击、AdbClient
已知环境 := 在线设备 192.168.1.6:5555、应用 com.pwrd.cloud.yh.laohu

只读复查截图 → 游戏内手机菜单 → 保持停止，不接管其他输入来源的界面变化

## 每日主流程（已实机验证，尚未实现无人值守程序）

已有声明 := ADB 设备检查、截图、唤醒、单步点击、返回、用户提供的每日路线
新增定义 := DailyStepResult {步骤、当天状态、现场证据、未完成原因}

设备与当前截图 → 确认屏幕状态及游戏会话 → 息屏则唤醒并重新观察；认证页则人工交接
云排队页面 → 保留队列 → 定期等待与截图 → 更新等待状态；不反复启动或取消
加载页面 → 等待并再次观察 → 确认角色场景后继续
游戏右上角按钮 → 展开手机面板 → 都市大亨 → 一咖舍 → 补货 → 原料库存选择24小时 → 核验高亮 → 点击补货
原料不足 → 核对缺料 → 送货上门 → 核对仅使用普通方斯 → 确认 → 补货成功且库存充足；已成功则不重复采购
同一店铺 → 提取收益 → 营收报告确定 → 获得物品 → 空白关闭 → 核验营收归零 → 关闭店铺及都市大亨返回面板
面板图标区左滑 → 中间圆点及探索指南图标确认第二页 → 探索指南 → 左侧第二个跑步图标 → 每日活跃页
已完成卡片的下方领取 → 一次领取所有已完成项 → 重新观察重排后的卡片和活跃度
上方已解锁礼物 → 一次领取所有可领档位 → 获得物品 → 空白关闭 → 核验对应礼物变粉色勾选
本轮结果 := 登录20 + 消费方斯20 + 收取店铺方斯30 → 活跃度70 → 已领20、40、60档；80、100档未达成
面板邮件 → 领取全部 → 获得物品 → 空白关闭 → 核验附件黄色勾和面板邮件红点消失；不删除邮件
面板活动 → 优先检查签到及明显可领取赠礼 → 环期赠礼可领取项 → 核验七天均已领取
集市分福 → 活动任务 → 领取已达成登录奖励 → 核验所得200硬币及200/300进度；不额外消费凑条件
活动一般按主流程处理 → 不逐页深入所有挑战或商店；用户要求结束时立即停止扩展检查
每次恢复 → 重新检查现场和已领取状态 → 从首个未确认完成项继续，不直接重放旧坐标
充值、付费货币、未知页面或其他输入来源改变现场 → 暂停并说明情况，不扩大执行范围
奖励状态核验结束或用户要求收尾 → ADB强制停止目标包及当前用户 → 等待数秒 → 读取进程列表及包停止状态
无目标包主/子进程 且 包stopped为true 且 前台离开游戏 → 记录本地进程已关闭；不得据此声明已查询云服务端会话释放
进程仍在或再次出现 → 重新核对现场 → 有界重试并复查 → 仍失败则报告原因；不可仅凭回到桌面判定关闭成功
全部步骤结果及关闭结果 → 逐项汇报完成、已领、无可领、条件不足或中断 → 不重新打开游戏

## 验证约束

每个动作只使用新鲜观察对应的节点或已验证图像区域；系统导航栏变化后重新计算坐标。
认证输入、完整账号及令牌 → 不进入持久化日志和导航数据。
未有实机角色场景证据 → 结果保持未完成；不自动标记每日任务进度。
