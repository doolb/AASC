# HIE 子工程与游戏任务桥接

## 猪关卡目标导航（进行中）

在 HIE 导航包声明猪关卡的采集、布局复核、auto 求解、路线执行和胜利核验目标。运行时以现有 GoalManager 记录目标进度，通过受限桥接调用 aasc-game；遇到未知物件时将截图和候选反馈给高层 AI，可在棋盘内单步试探并重新采集。完整路线必须由已支持机制的 auto 策略求解并独立重放，执行时再次匹配现场、逐步确认和验证胜利。

游戏宿主通过 PigNavigation 加载目标，GameTaskBridge 固定参数采集；模型可提交绑定截图的布局，并可在宿主校验后进行棋盘单步试探。试探后旧会话失效并重新采集；失败或中断时不盲目重放。炸弹猪完整求解与网页同步尚未完成。实时进度与成功状态以脚本实际证据为准。

HIE、retop 和 remote-gamepad 的实际目录分别位于 `subproject/aasc-hie`、`subproject/retop` 和 `subproject/remote-gamepad`。三个子工程及 aasc-game 使用 AASC 主仓库；原 HIE 与 retop 的本地 Git 元数据移出子工程工作树，旧历史不要求合并。模型、运行数据和重建产物按忽略规则留在本地。旧 HIE 和 retop 路径通过链接兼容。

HIE 提供游戏任务桥接，读取 aasc-game 关卡识别、计划、结果并可上报卡关；真实运行必须显式启用。脚本仍负责 X11 输入与逐步验证。当前需要调用方主动读取快照，不声称已经实现自动排障。详见子工程 `docs/design/game-task-bridge.md`。

自动测试依赖的固定截图与布局样本纳入仓库，其他关卡运行记录仍保存在本机；测试样本的例外不包含日志、模型、安装包或构建产物。

2026-11-13：按用户要求，所有 `references/` 目录改为 Git 忽略；已跟踪的游戏参考资源从索引移除、文件保留本机。已有远端提交仍包含历史文件；克隆后游戏提取脚本与部分测试需要单独提供本地模板和样本。

中层优先（进行中）：导航先尝试同关卡、棋盘像素完全一致且留有实机胜利证据的已复核布局，仍须完整求解和独立重放；其他画面明确上报缺口。中层调度可选跳过不必要的高层，默认兼容旧调用。未知朝向可以通过两帧稳定且一致的候选补充；新布局完整复核和炸弹机制仍需继续实现。
