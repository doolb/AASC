# 云异环 ADB 入口设计

## 需求与范围

用户要求逐步完成通过 ADB 执行云异环每日任务，最初入口阶段只做到进入游戏。入口验收以角色场景和游戏操作 HUD 出现为准，云客户端首页、排队、加载或登录界面均不算完成。入口阶段不执行每日任务及领奖。

## 每日路线与实机验证（2026-11-23）

用户随后提供每日操作顺序，并要求保存到可复用的 goal Markdown，见 [`goal/cloud-yihuan-daily.md`](../../../../goal/cloud-yihuan-daily.md)。依次打开最右上角游戏面板 → 都市大亨 → 一咖舍补货与提取收益 → 返回面板第二页 → 探索指南左侧第二项 → 下方领取 → 上方礼物每日奖励 → 邮件附件 → 活动中的免费每日赠礼。

随后用户授权实机跑一遍并明确补货选 24 小时。本轮已验证主流程：库存不足时通过送货上门花费普通游戏货币 1,104 方斯补货成功；提取收益 12,874 方斯；探索指南一次领取所有已完成卡片，达到 70 活跃度，再一次领取 20/40/60 三档礼物。80/100 档未满足，不能宣称满活跃。邮件使用“领取全部”并核对附件勾选、红点消失；环期赠礼一次补领第 5～7 天共 5 个红色骰子；集市分福领取已达成登录奖励 200 分福硬币。

用户收尾要求为一般完成每日主流程即可，不为活动逐页深入，结束后使用 ADB 关闭进程。采用 `am force-stop --user 0`，核验无该包名进程、包状态 `stopped=true`、前台离开游戏；首次关闭后曾出现进程，原因未确认，第二次带用户参数关闭后检查通过。关闭本地客户端不等于已经向云平台查询确认服务端会话释放。

后续仍按新截图执行；排队与息屏处理本轮未触发，不记作已经实测。补货授权包含正常方斯原料支出，充值、付费货币、扩建及升级不在其中。没有新增自动化代码，完整执行记录与临时截图摘要见 `../task/2026-11-23_云异环每日实机流程与关闭进程.md`。

## 拟实现方案（等待代码修改确认）

复用 `src/execution/adb-client.js`，在独立入口脚本中加载云异环导航数据，提供 npm 运行命令。按“观察 → 识别 → 单步动作 → 再观察”推进，原生页面优先按资源 ID 和节点边界识别；游戏流画面须使用经实机验证的图像特征，不把空 UI 树视为已进游戏。游戏专属数据与通用执行器分离，以状态表和处理器映射组织流程。

仅明确启用执行后允许启动应用和点击已确认入口。密码、短信验证码、实名验证、协议变更、付费提示及未知页面需要人工处理；不得保存或输出密码、验证码、登录令牌和完整账号。设定总超时和状态重试上限，超时保存原因并退出。角色场景验证成功后停止，不继续每日任务。
