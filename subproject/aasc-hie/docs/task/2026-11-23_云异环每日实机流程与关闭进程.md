## 任务、design需求与spec设计

用户要求按 [`goal/cloud-yihuan-daily.md`](../../../../goal/cloud-yihuan-daily.md) 跑一遍生成流程，过程中明确补货选24小时，收尾补充“一般过主线就行，完成后用adb关闭进程”。本任务将其落实为每日主流程：补货及收益 → 探索指南当前可领奖励 → 邮件 → 活动明显可领赠礼 → ADB关闭并复查。没有新增剧情推进、战斗、养成或付费任务。

设计见 [入口及每日设计](../design/cloud-yihuan-entry.md)，伪代码见 [入口与每日主流程](../spec/cloud-yihuan-entry.md)。Agent逐屏观察后发送一次ADB动作并核验，不实现无人值守脚本，不修改程序。

## 兼容性、性能、风险与预计工时

本轮只验证SM_N9500横屏2220×1080、已登录且已在云游戏中的分支；未触发排队、息屏和断线，不声称这些恢复分支已通过实测。菜单打开有动画，等待后重新截图；返回探索指南后面板可能重置第一页。侧栏滚动会改变坐标，点到滚动箭头不等于进入目标活动。

自测使用真实ADB截图和状态核验；没有代码变化，不新增程序测试或运行无关全量测试。性能观察为单步输入、串行截图及约1～2秒页面等待，不做战斗性能或长时保活测试。永久息屏设置未修改。未来流程仅走主流程，避免活动逐页展开造成额外耗时。

已知风险：普通方斯补货金额随库存变化；每日活跃可能不足100；本地客户端关闭不证明云服务器会话已即时释放；第一次关闭后进程再次出现的原因未查明。首次实机采集与整理原估30～60分钟，后续主流程耗时由排队、加载和奖励弹窗决定。
