# 网易云游戏广告时长目标

日期：2026-11-24。用户要求独立goal，期望中层全自动；三个游戏的流程依用户要求留到明天测试。

需求和设计见 [design](../design/netease-cloud-ad-time.md)，伪代码见 [spec](../spec/netease-cloud-ad-time.md)，入口和现场操作见 [goal](../../../../goal/netease-cloud-ad-time.md)。涉及HIE导航包、状态识别、ADB执行、等待及到账核验；仅文档与人工实机，本次未修改程序。

实机：SM_N9500、网易云游戏2.9.4；我的→看视频得时长。首次广告“跳过→坚持退出”出现未观看完成且余额不变；第二次进入三星应用商店广告详情，等待超过15秒后返回，显示奖励已领取；网易弹窗显示120s手游时长，刷新余额12→14分钟，端游45分钟未变。客户端force-stop后User 0 stopped=true、无主进程。

自测与兼容：已验证单次成功、提前退出和余额刷新；广告素材、界面位置、延迟、次数耗尽及不同设备未验证。性能：本次采用人工逐屏观察，不代表自动化耗时；广告15秒浏览和倒计时按服务实际规则。风险：不明广告跳转、误装、误购、余额延迟、重复观看和错误关闭；对未知状态暂停。预计程序实现和测试约数小时，取决于广告类型和现场证据。

后续需根据设计实现可恢复中层闭环，先补程序修改方案并按项目规则获得确认；另需验证三款游戏导航包及更多广告类型。奖励次数和单次秒数不固化。

用户补充可多次领取后，重新从“我的”入口完成第二次：结果180秒，刷新余额14→17分钟，端游仍45分钟；结果页显示“继续观看”和每日8次提示，但尚未验证该按钮及当日剩余次数。已补多轮停止和逐次核验要求；客户端关闭后User 0 stopped=true。

继续实测：通过“继续观看”完成第3至8次，依次60、120、240、60、120、60秒；第8次显示“今日次数已用完”，刷新手游余额28分钟、端游45分钟。广告插入可使结果弹窗移动；一条广告唤起安装确认，取消安装后获得奖励。该流程仍为人工操作，自动化、其他广告素材和设备兼容性待验证。

中层自动化方案待确认：新增 `src/runtime/netease-cloud-ad-time.js`、广告导航包和状态序列测试，接入 CLI 与公开导出，必要时补充 ADB 返回和前台包查询。设计和伪代码见对应文档；模拟验证完整状态序列，实机先验证 dry-run 和次数耗尽，次日可领取后验证真实到账。风险为广告素材变化、OCR 漏识别、意外安装及余额更新延迟；不确定即停止。预计数小时，视设备与 OCR 服务状态而定。

方案确认后实现状态控制器、节点优先/局部 OCR、CLI、导航包和模拟测试。实机 dry-run 识别“我的”和云游戏运行中；已有游戏运行，未强停或继续点击。OCR 请求超时，真实广告及次数耗尽分支未验证，待后续设备空闲且有次数时验证。

OCR 复测后将中层 `OcrClient` 默认单次请求超时由 30 秒调整至 60 秒，保留显式覆盖；单元测试覆盖默认值及覆盖，历史截图局部 OCR 以默认配置约 27.7 秒返回。真实广告及次数耗尽分支仍待验证。

2026-11-25 真实测试：冷启动因加载画面 unknown 停止；首页重试可自动进入我的、读取30分钟并打开广告，但“60S内必得奖励”广告页判 unknown。人工等待并点击广告右下关闭后得120秒，刷新余额32分钟；完整无人值守不通过，待修复启动等待与广告识别后复测。

同日修复启动有限等待、广告顶部与右下角优先 OCR、关闭二次确认、节点采集短暂失败重试和截图回退。修复迭代期间一条广告人工关闭获180秒，另一条中层关闭获60秒但节点采集失败后人工刷新；最终中层完整处理一条广告并获120秒，余额36→38分钟，返回 completed。模拟测试覆盖区域边界、重复确认、节点失败回退；冷启动与不同素材、多轮领取待后续实机验证。

同日继续由中层多轮领取：240、60、120、60秒，至平台提示今日次数已用完；中层自动刷新余额38→46分钟并返回 completed/daily-limit，安装提示均取消。其他广告素材及冷启动仍待实测。
