## 设计与已实施方案

依据 [设计](../design/retop-ai-squadgen.md) 和 [伪代码](../spec/retop-ai-squadgen.md)，使用官方预训练权重建立一次未微调基线。先低采样量冒烟，记录该配置不足以代表官方高分辨率上限。

用户已确认的代码方案：

1. 在 `/mnt/SQuadGen/.venv` 建立隔离依赖环境，复用可用 CPU PyTorch；权重放 `/mnt/SQuadGen/checkpoints`，避免占用内存文件系统 `/tmp`。
2. 新增 `/mnt/SQuadGen/local_cpu/run_shoulder.py`：CPU 分阶段编码/采样/解码、固定种子、内存与用时记录、生成文件完整性检查；保留官方权重与网络数学定义。
3. 按实际导入失败情况，对 `/mnt/SQuadGen/squadgen/network/utils.py` 的渲染依赖延迟导入；如 CPU FPS 扩展不能使用，在 `squadgen/util/util.py` 增加明确的 CPU 采样适配。保留补丁差异，不伪造 CUDA 依赖或模型输出。
4. 构建 `QuadTools` 的实际布局提取工具；缺少头文件时先准备本地依赖，避免改系统环境。输出实际四边 PLY/OBJ 后再检查保形和多视角。

用户在方案说明后回复“是”，已明确授权本次独立依赖安装、权重下载和 CPU 兼容代码修改。上述工作均已执行，在 Python 3.14 独立环境复用系统 CPU PyTorch。

## 结果与验收

- 实际输出 1282 顶点、1280 四边面（等价三角数 2560）；单闭合组件、Euler 2，没有检测出非流形或边定向冲突。
- **质量拒绝**：2 个退化面；索引 33、197、227、239、298、300、304、318、330、393、933、1045 的 12 个面无法严格三角化。穿插检查未完成，记为未知，不能记为零。
- 初次独立检查因上述几何问题中止；检查脚本现已将其记录为模型候选缺陷，并继续只读可视化和诊断距离。没有修改、修复或替换生成网格。
- 双向各 5000 个面积均匀样本：高→低 P95 = 9.2152 单位（原对角线 22.60%），低→高 P95 = 1.5340 单位（3.76%）。使用无效四边形的三角显示代理作诊断，非精确 Hausdorff，不能据此认证原多边形合法。
- 五视图目视检查：大块形体缺失、包边损失、局部四边面严重拉长/聚集。照片式着色、隐藏三角线或全四边统计均不能掩盖失败。
- 官方 QuadExtraction 曾警告中间提取存在 8 个非四边多边形；最终文件经独立回读为 1280 四边面。该最终统计不代表几何有效。QuadQuality 的环线交叉指标与三角表面的物理穿插不同，未混用。
- 校验：两份权重 SHA-256 与下载元数据一致，两份 YAML 与仓库字节一致；严格 state_dict 加载、缓存解码对照官方 decode_batch 均通过。源 OBJ/JSON 指纹保持不变。

## 自测、兼容、性能与风险

- 自测：源件指纹、OBJ 往返、实际四边面计数、非流形/翻面/穿插、原高模表面偏差、正侧顶背斜视对照。
- 兼容：官方 checkpoint/config 配套；CPU-only 环境无 CUDA 渲染调用；不将 CDF 着色预览 GLB 当成生成的四边低模，必须检查 `extracted_quad.ply`。
- 性能：记录模型加载、编码、扩散、解码、提取的耗时与内存；先低采样量，不能以较小 res 的效果直接代表官方默认效果。
- 风险：2 核 CPU 可能耗时很长，约 4.1GB 权重加模型构造副本/激活可能超过可用内存；尽量分阶段驻留，资源不满足时保留真实失败日志。
- 实测耗时见上表；原粗估保留为计划背景，实际任务以阶段日志为准。
- 未验证：官方默认 res 4096/Dopri5 配置、2080 Ti 16GiB 训练预算、人物泛化、动画、目标面数控制、UV/烘焙。后续先做默认配置和表示上限对照，再决定领域训练；本次失败不能归因为缺少 Qwen。
