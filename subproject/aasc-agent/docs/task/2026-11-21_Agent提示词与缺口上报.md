# Agent 提示词与缺口上报（已实现）

## 任务描述和设计需求

游戏宿主允许用户在启动时提供自然语言任务指示，由中层按现有权限执行；遇到无法解决的缺口时将指示、现场证据和明确的待分析问题交给高层，高层返回工具命令后仍先经宿主校验并交回中层。普通聊天入口与游戏宿主的授权边界保持明确。

区分缺口已上报、未解决、请求失败和会话状态不确定，不将请求记录等同于问题已修复。对于无确认进展的相同缺口保持去重，允许用户明确要求重试；请求或动作状态不确定时先报告并提供安全恢复路径，不自动重放或清除历史。

第 112 关 `nav-level-112-6HHPtA` 的缺口记录为 failed，关联模型会话仍有 pending，是否真正送达高层尚不能从本地状态确定。应先说明这种不确定状态，不能把当前缺口宣称为已处理。

## 伪代码方案

```text
启动参数 → 用户任务指示 → 中层推进 → 缺口与现场证据 → 判断会话状态
会话明确且首次缺口 → 高层分析并返回受限工具命令 → 宿主校验 → 中层复核
无进展的相同缺口 → 报告未解决与可选重试方式 → 等待明确操作
模型请求或工具状态不确定 → 停止并报告原因 → 人工核实后选择安全恢复
```

## 受影响模块

预计涉及 `subproject/aasc-agent/src/pig-cli.js`、`pig-loop.js`、必要时的 `pig-host.js` 和会话存储、对应测试与 `subproject/aasc-agent/readme.md`，以及本项目的设计、实现伪代码、待办和变更日志。实施前按实际接口再核对，不扩大既有工具权限。

实际修改了上述 CLI、循环、宿主、会话存储、测试及使用文档；用户提示词随高层缺口证据发送，不能替代中层的权限或操作约束。第 112 关未改变，旧会话需先核实后再恢复。

## 验证、兼容性、性能与风险

- 自测：用户指示能随缺口和证据送达高层；已解决、失败、无进展及不确定状态分别显示；模拟高层调用后返回中层。
- 兼容性：不提供指示时现有命令可用；保留 `--plan-only`、`--session`、`--retry-gap` 和现有授权边界。
- 性能：中层可解决的任务不增加模型调用；同一无进展缺口不循环请求高层。
- 风险：模型响应或点击中断时存在重复执行风险；不在状态不确定时自动重放动作，不假设高层已收到信息。
- 预计工时：约 2～4 小时，取决于不确定会话恢复所需的实际核验。
- 自测结果：`TMPDIR=/dev/shm npm test`，55 项通过；使用模拟覆盖提示词与证据、会话不确定前置停止、缺口状态及显式重试，未触发游戏操作或外部模型请求。
- 后续修复：第 112 关高层先调用脚本列表，旧去重逻辑在列表结果反馈前停止；现允许同一调查中有限次反馈不同工具结果，并优先交回中层复查。新增相同结果和调查轮数限制测试，`TMPDIR=/dev/shm npm test` 共 57 项通过。
