## 现场问题

- 第 81 关的中层返回复核缺口后，高层可能只给出建议；相同缺口已记录时，宿主直接结束。
- 高层可能误称工具次数用尽，或者返回服务错误文本；目前这两种情况都可能使进程结束，无法持续恢复。
- 试探可能在结果返回前中断，恢复时不能假设点击未发生。

## 拟修改

1. 先更新 `subproject/aasc-agent/docs/spec/aasc-agent.md` 中对应伪代码，再更新设计、待办与变更记录。
2. 修改 `subproject/aasc-agent/src/pig-loop.js` 和 `pig-cli.js`：持续运行到关卡完成或用户主动停止；中层优先，收到新证据后交由高层处理；高层只提出建议而没有调用工具时，结合状态要求执行或修复；可恢复错误采用退避等待后重试，避免空转。
3. 修改 `pig-host.js` 和 `pig-session-store.js`：保留模型会话和进度；区分缺口已请求、实际处理、处理失败，失败和无进展的缺口不能被永久去重；不确定的工具执行先重新采集，不重复旧点击。
4. 高层发现导航脚本或识别问题时，使用现有受限脚本维护工具分析并修复；规则变更需有证据与验证，实机动作仍由受限工具和中层校验。
5. 在 `subproject/aasc-agent/test/` 增加行为测试：覆盖纯建议、误称工具耗尽、服务错误、进程恢复、重复缺口和试探结果不确定；复用同一会话且已知路径不增加高层调用。

## 运行要求

- 持续运行不等于持续盲点或密集重复请求：现场、服务、设备不可用时保留进程、状态和退避重试，并明确记录错误。
- 不使用底部道具；未知炸弹规则不能当作已验证；任何不确定点击都先重新观察。
- 完成代码与测试后，从当前第 81 关证据恢复，监控真实工具动作、错误及胜利证据。
