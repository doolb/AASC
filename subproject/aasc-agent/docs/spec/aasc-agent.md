# 个人 Agent 实现伪代码

目标参考 → `goal/aasc-agent.md`；实际流程和限制以下列伪代码为准。

用户输入 --prompt → 保存本次任务指示 → 中层优先推进 → 需要高层时附带指示、缺口和现场证据；参数缺省时保持原有行为。
每轮中层执行前核验关联会话 → pending 或角色不确定 → 停止并报告原因与恢复方式，不执行旧动作；会话记录无效 → 停止并报告。
已有缺口指纹且未指定重试 → 读取缺口状态 → 报告未解决或上报状态不明，停止重复请求；显式 --retry-gap 且会话状态明确 → 再次请求高层。
高层有效回复但没有确认进展 → 标记未解决；调用异常 → 标记请求失败；模型会话状态不确定 → 保留证据并停止，不将其视为已修复。
高层工具批次返回 → 中层重新检查现场 → 同一缺口且存在尚未反馈的工具结果 → 限定轮数内将结果和新证据发送高层继续调查；重复相同结果或超过上限 → 标记未解决并停止。工具结果已反馈或进程重启后不得凭空恢复未持久化的工具结果。

## 游戏宿主伪代码（进行中）

导航宿主 → 加载 pig-game 目标及按关卡隔离的进度 → 模型调用 advance/status → 返回下一步骤、实际结果和证据 → 经复核与自动求解独立重放后才允许执行；阻塞状态保留会话并退避处理。
显式 --plan-only → 保留经过独立重放的完整计划并停在执行步骤，不向游戏发送点击。
本次续跑 → 停止会话状态不确定的旧进程 → 建立新导航和模型会话并注入禁用脚本维护的适配器 → 重新采集第 81 关 → 候选布局未复核时等待高层处理，不宣称通关。

跨进程历史试探仍未自动拦截，发现重复后停止实机续跑。

```
显式启用游戏宿主 → 读取本地模型配置 → 注册游戏角色与受限 hie 工具 → 模型根据能力说明返回结构化调用
hie(action=run) → PigNavigation.advance → 按导航包步骤采集；没有宿主预设的复核布局时返回复核阻塞，有布局时进行摘要与机制检查、auto 求解、独立重放和逐步执行；炸弹等未建模机制拒绝执行；中断后不能盲目重试
hie(action=snapshot) → 限定游戏证据根目录 → 读取快照 → 模型复盘
同一宿主内相同截图只上传一次；模型继续使用同一 Responses 链时可读取先前截图，图片变化则重新上传
hie(action=list/read/update) → 仅 HIE scripts 下普通 JavaScript 文件 → 更新须匹配 SHA-256 → 语法和可用 HIE 测试失败则恢复原文件；排除依赖本机缺失的王者荣耀数据集和导航资源的两组测试
限制模型循环次数；任何执行失败按实际状态报告，不模拟通关
游戏宿主模型决策 → 续接当前主角色 Responses 链并更新响应 ID → 执行工具后沿同一链反馈；失败标记会话状态不确定
```

已有声明：HIE 角色运行时绑定环境、识别与导航；SubAI 使用 CSV 字段。

新增定义：角色 = {名称, 人设, 允许能力集合}；任务 = {角色, 内容, 参数}；模型 = {decide}；能力 = {名称, execute}。

操作流程：
1. 内部命令输入 → 按配置检查完整方括号 → CSV 解码 → 校验角色与内容 → 任务；格式错误拒绝。
2. 模型提出的任务 → 主角色与模型 decide → 请求能力及参数 → 按主角色允许集合检查 → 能力执行 → 返回结果。
3. 委派请求 → 校验主角色具备 delegate 权限 → 选择已注册角色 → 调用该角色模型 → 按该角色允许集合检查能力 → 返回结果；不接受模型自行扩大权限。
4. HIE 能力通过注入的 execute 接口调用；未注入时明确报错。模拟能力和模型用于自测。

## 终端聊天与内部命令伪代码

```
Agent.chat(用户自然语言, 配置):
    校验可选聊天角色为宿主已注册角色；将角色名称与人设传入每次 model.respond
    将用户文本原样交给宿主 model.respond，不将用户文本作为本地命令解析
    模型返回文本，或 {text, commands}，commands 是模型明确提出的方括号指令或 {role, task, args} 对象数组；对象严格校验并按 CSV 转义后进入同一授权流程
    校验本轮全部 commands 的格式、数量和宿主授权的 commandRoles，任何一项不合法则本轮均不执行
    依序将模型指令传给 runCommand；保留角色权限检查；把本地结果交给 model.respond 继续处理
    模型不再提出命令则返回最终回复与本地结果；限制单次聊天的模型调用轮数
Agent.runCommand(模型指令, 配置):
    解析指令；将可选的 onEvent 观察器传入 run
Agent.run(角色, 任务, 参数, 深度, 观察器):
    发出开始、决策、委派、工具执行与结束事件；观察器异常不改变授权或任务结果
TUI(Agent, 输入流, 输出流):
    持续读取用户自然语言；/help 显示帮助；/exit 或 EOF 退出
    /role 列出注册角色与当前角色，/role 名称 选择角色，/role --default 清除选择
    不存在的角色给出错误并保留现有选择；角色选择不改变 commandRoles 或工具权限
    顺序调用 Agent.chat，展示 AI 文本、执行事件和本地结果；错误后继续
    不将用户输入直接交给 runCommand；npm start 启动自然语言界面
    原解析工具以 npm run parse 保留供开发调试
TUI 入口:
    --demo 使用标注为演示的本地回显模型；不连接真实模型或设备
    AASC_AGENT_MODULE 提供实现 chat 的宿主 Agent 或工厂；否则明确提示未配置
```

事件类型 := run:start、decision、delegate、tool:start、tool:complete、run:complete、run:error；每项包含 role、depth。显示输出过滤终端控制字符。模型命令的允许角色须由宿主显式配置，默认为空；现有工具权限仍由角色检查。真实 Responses 适配器、跨轮模型上下文和外部执行由宿主提供。

## Responses 模型与本地配置伪代码

猪游戏角色自动处理 := run 取得采集候选和图片 → AI 可通过 review 提交布局并立即触发导航求解，或通过 probe 提交棋盘内坐标、假设及预期结果 → 宿主保存并返回真实前后截图和新采集候选 → AI 比较结果，继续调查或求解；模型只回复下一步计划或没有工具进展时退避后继续处理，直到完成或用户停止。执行由宿主固定脚本处理，不允许模型指定窗口、显示器或 shell 命令。每轮试探次数有限；plan-only 禁止所有实机点击。

```
加载配置(路径):
    读取 JSON；校验 API 地址、模型、超时、角色、权限与默认角色
    密钥来自本地配置或指定环境变量；不将密钥写入日志或示例
创建正式 Agent(配置):
    注册主助手及游戏角色；默认仅聊天，无须 HIE
    本地能力由宿主按需注入；未注册能力明确报错，commandRoles 仅采用配置明确授予的角色
Responses.respond(消息, 选中角色, 本地结果):
    按角色查找上次 response_id；新会话发送角色人设和可调用角色说明，续接只发送新增输入，不重复发送 instructions
    只有模型整段回复由完整方括号 CSV 指令组成时，才转换为角色命令；普通文字、用户输入和无授权角色不执行；本地结果中明确提供的数据 URL 截图以 input_image 回传
    成功且响应 ID 有效时更新该角色续接点；失败不静默新建会话
Responses.decide(角色, 任务):
    通用角色仍可单独请求模型选择允许的能力；猪游戏角色直接将 [游戏,操作,参数...] 映射到固定工具，不额外调用选择器；非法参数和无授权能力拒绝
猪游戏续接存储:
    导航会话目录保存关联标识 → 同一调查涉及的新导航会话关联同一私有续接文件 → 按模型地址、模型名与密钥摘要核对身份 → 记录各角色最新 response_id
    发送请求或执行工具前先持久化未完成标志 → 成功接收反馈后更新 ID 并清除标志 → 进程重启时若未完成则拒绝盲目续接；禁止同时写入同一续接文件
    显式 --new-conversation → 为当前导航会话建立新模型续接点，不删除旧网页会话或旧证据

独立进程临时启动 := 使用 setsid 与独立日志启动猪游戏宿主 → 保持现有导航会话与模型续接点 → 不依赖当前工具会话；SIGTERM 来源仍需更多证据。

中层优先伪代码:
    宿主直接调用已授权游戏角色的 run → 中层采集、复核、求解与执行
    已完成或 plan-only 的计划就绪 → 返回中层结果，不调用模型
    产生需要分析的缺口 → 根据关卡、首屏摘要、阶段、原因计算指纹，持久化至关联模型会话
    持续运行直至完成或用户停止；plan-only 计划就绪时结束
    缺口指纹已请求但没有新的确认进展 → 保留记录并停止重复上报；现场变化或显式重试才重新请求
    向模型提供精简缺口、截图与保留全部候选信息的紧凑数据 → 指示必须输出下一条方括号命令或说明具体阻碍；动作与布局仍经中层验证
    模型只给建议、误称工具耗尽、返回服务错误文本或无进展 → 保留缺口和证据，不将其当作确认进展
    高层提交单个合法工具 → 执行后确认批次并交还中层；单批多个命令 → 整批拒绝
    请求或工具执行状态不确定 → 不重复执行旧命令，不静默切换会话；停止并保留证据
    模型服务明确返回已恢复续接点的通用失败码 → 保持相同会话，清除本地请求中标记，退避后重新观察并重试；其他超时或失败不得按确定失败处理
    同一宿主连续请求相同坐标的单步试探 → 返回拒绝和现有证据，不再次点击；其他坐标试探后可重新评估
终端入口:
    显式 --demo 使用演示；AASC_AGENT_MODULE 使用宿主注入；否则加载本地配置与正式角色
```

显式 /new := 仅清除当前角色的本地 Responses 续接点，下一条消息新建会话；不删除网页对话。若宿主不支持重置则明确报错。默认角色由配置指定，/role --default 恢复该角色。

中层优先接管伪代码:
    采集 → 中层复核与求解 → 安全阶段独立重放与执行 → 核对 → 中层继续
    中层存在不可解决的新增缺口 → 高层处理一次 → 收到工具结果 → 中层接管
    相同缺口无新证据 → 不重复请求；不确定的现场 → 停止并保留证据
    首次请求 → 附说明；可验证续接 → 附增量与上轮 ID；显式配置可兼容需要重复说明的服务

游戏宿主脚本权限伪代码:
    未显式注入写入授权 → 只允许列出和读取脚本 → 更新请求拒绝；可信宿主按用户确认显式注入维护能力时才允许更新

会话续接异常伪代码:
    请求或工具批次状态不确定 → 保留当前证据并停止循环 → 用户显式创建新会话后才可继续；不反复请求高层
