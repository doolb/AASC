# AASC Agent

第一阶段提供独立命令解析、角色授权、模型决策和专用角色委派接口。运行 `npm test` 自测，`npm start` 打开聊天界面；`npm run parse` 是内部命令的开发调试工具。内部命令默认格式为 `[游戏,"今天先完成日常任务"]`，使用 CSV 双引号转义；调用 `parseCommand(text, { requireBrackets: false })` 可显式允许省略方括号。

模型通过 `decide({role, task, args})` 返回能力请求；宿主注册角色及其权限、模型和能力。`createHieTool` 接受具有 `execute` 的适配器。现已支持 OpenAI Responses 兼容模型；本地能力由宿主按需注入，默认无需 HIE。当前没有真实 HIE、网页、Codex 或 Claude 工具接入，也没有操作系统级隔离或跨进程会话持久化。

## 终端界面与模型配置

使用 Node.js 18 或更高版本。在本目录运行 `npm start`，直接输入自然语言；`/role` 查看角色，`/role 游戏` 切换，`/role --default` 恢复主助手，`/new` 开始当前角色的新会话，`/help` 查看帮助，`/exit` 或 Ctrl+D 退出。角色各自保存进程内续接点。

默认读取本目录 `config.json`。若尚未配置，可复制 `config.example.json`，在 `api.baseUrl`、`api.apiKey` 和 `api.model` 中填写服务地址、密钥和模型名；也可用 `AASC_AGENT_CONFIG` 指定配置路径。示例指向 `http://127.0.0.1:5918/v1`，使用 OpenAI Responses 兼容接口。`config.json` 被 Git 忽略，切勿将真实密钥填入示例文件。配置中 `roles` 包含主助手和游戏专用角色的人设，`defaultRole` 指定默认角色；可按需调整。

默认 `commandRoles` 和角色 `permissions` 为空，只使用模型聊天，不依赖 HIE。确需本地操作时，由可信宿主注入工具并在配置中明确授权；未注入的能力不会被模拟执行。Responses 模型仅在整段回复由完整方括号 CSV 命令组成且角色已授权时触发本地调用，例如 `[游戏,run]`；人输入的方括号和说明文字中的方括号不会直接执行。本地工具结果反馈给模型继续处理。

`npm start -- --demo` 是无网络的本地回显演示。`AASC_AGENT_MODULE` 可覆盖默认配置入口，加载本地可信宿主模块，模块导出 `createAgent()` 或默认 Agent 实例；Agent 须实现 `chat(text, { role, onEvent })`，支持 `/role` 时还须提供 `listRoles()`，支持 `/new` 时须提供 `resetChat()`。旧的内部命令解析工具可通过 `npm run parse` 使用。

如果模型续接失败，界面会要求使用 `/new` 明确开始新会话，不会悄悄丢弃上下文或重发。长任务顺序执行，Ctrl+C 关闭界面输入，但不会强行取消已提交的外部任务。

## 猪关卡宿主

确认 `DISPLAY=:1` 下当前关卡与游戏窗口 ID 后运行：

```bash
npm run pig -- --level 81 --window 0x3c00015 --display :1
```

窗口 ID 和关卡号须按当前画面重新确认，不能照抄示例。宿主使用本地 `config.json` 的 Responses 服务及密钥，显式授权游戏角色；默认聊天入口不启用游戏能力。游戏宿主加载 HIE 的 `pig-game` 导航包，按采集、复核、求解、执行、胜利的目标顺序推进。高层 AI 可以调查未知物件：提供假设与预期后，在棋盘内单步试探并读取前后画面，然后重新采集；现场证据保存在会话目录下。

可在启动命令后加入 `--prompt '请复核特殊物件并寻找安全路线'` 提供本次任务指示。中层先执行已有流程，需要高层时才将该指示与现场证据一同发送；提示词不会增加工具权限，也不能替代现有执行校验。提示词不是供中层强制执行的通用规则；涉及权限或禁止操作的要求仍须由宿主保障。需要重新处理之前的同一缺口时，在会话状态明确的前提下同时指定 `--session` 和 `--retry-gap`。

复核布局须包含 `level`、`reviewed: true`、`mechanicsReviewed: true`、`source_sha256`、`mechanics`、`grid`、`board` 和 `pigs`。`source_sha256` 是这次采集的 `original.png` 的 SHA-256；完整路线支持已建模的 `ordinary`、`lock`、`duck`、`scissors`、`rope`、`cage`，炸弹只允许完整声明后的保守避碰规划，实机执行仍会拒绝。未复核物件不能标为普通猪。已确认布局后，通过以下命令恢复（路径与窗口 ID 应替换成实际值）：

```bash
npm run pig -- --level 81 --window 0x3c00015 --display :1 --session /实际导航会话目录 --layout /实际复核布局.json
```

如只需生成和核对计划，在上述命令后加 `--plan-only`；此模式不会执行游戏点击。

布局可以由高层模型提交，也可由宿主启动参数提供；模型不能指定窗口、显示器或 shell 命令。游戏命令使用 `[游戏,run]`、`[游戏,snapshot]` 和 `[游戏,probe,截图SHA256,x,y,"假设","预期"]`；较复杂的布局以 JSON 数据作为方括号命令的字段。求解器使用 `strategy='auto'` 并独立重放完整路线；执行前重核首屏和计划摘要、当前关卡 OCR、现场布局，逐步确认后才点击。未知机制可用单步试探调查，但未接入求解器的机制仍不能作为完整路线执行。试探后重新采集，`--plan-only` 禁止试探和执行。胜利截图确认后目标才完成；网页关卡同步和连续通关尚未自动接入。

同一导航会话的模型续接点保存在证据目录中，`--session` 可在进程重启后恢复；试探后产生的新导航会话仍关联同一模型会话。请求或工具执行中断时，续接状态不确定，宿主会拒绝盲目续接；如需明确开始新模型会话，可在命令后增加 `--new-conversation`，不会删除旧网页会话或旧证据。此功能启用前的会话如果没有保存续接点，无法自动恢复原模型会话。默认续接不重复发送 `instructions`；若 Responses 服务要求每次显式提供说明，可在本地配置的 `api` 中设置 `"instructionsEachRequest": true`。

入口先直接运行中层导航。已有实机胜利证据且棋盘像素一致的历史布局会进入本地求解、独立重放和现场核对；可确认的铁笼关卡也可由中层阶段求解器处理。铁笼与未知物件混合时，可提交 `stage_mode: "conservative_cage"` 的复核布局，明确 `cage_cells`、`cage_counters`、`cage_unknown` 和覆盖未知物件及其周边的 `blockers`；本地会校验截图绑定、特殊标记的阻挡范围、完整笼外候选和铁笼计数，独立重放后连续执行安全阶段。若已确认红色区域只是某个冻结棋子的提示，可在 `reviewed_red_hints` 声明该棋子的 ID；宿主仍核验红框与候选的唯一对应，冻结其占格和红色区域。阶段结束后重新采集；不确定时停止，不能将未知物件伪装成普通猪。

中层没有可安全执行的路线时才上报高层；高层执行一批工具后立即交回中层。同一缺口在关联模型会话中持久去重，不会因退避反复请求；用户确认需要重试时，可在恢复命令中加 `--retry-gap`。`probe` 的 `observed` 仅表示获取了图片，不能作为棋子离场的证明。

同一轮调查中，高层工具返回后若中层仍遇到同一缺口，宿主会把未反馈的工具结果和新证据发回高层；默认最多追加四轮，相同结果不会反复反馈。超过限制或没有新结果时保留未解决状态并停止，不将读取脚本等操作当作通关进展。工具结果仅保存在当前进程中，进程退出后不会伪造或重放旧结果。

游戏宿主每轮中层动作前检查模型会话：上次请求或工具执行仍未完成时，报告状态不确定并停止，不会因为 `--retry-gap` 而忽略该状态。此时先核实服务端请求及游戏现场；`--new-conversation` 会为导航会话建立新的模型续接点，不核实旧请求或撤销已发生的动作，只有确认现场安全后才考虑使用。缺口曾发送但没有确认进展时，报告未解决或上报状态不明，不宣称问题已处理。

游戏宿主默认只允许列出和读取 HIE `scripts/`，拒绝模型更新脚本；需要修改时须先获得用户确认，由可信宿主显式注入维护能力。真实模型输出和图像识别可能不稳定，报告应以执行状态及游戏证据为准。
