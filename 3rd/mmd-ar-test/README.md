# MMD AR 独立测试 APK / HTTPS 网页

此 APK 单独运行显示端现有图片基准图 AR 与默认 `miya-default` PMX，不连接或启动 AASC 服务。它保留灯光面板、默认 VMD、布料/刚体物理、模型拖动旋转和本地图片校准/跟踪。

## HTTPS 网页

打开 <https://c.aasc.us/mnt/mmd-ar/> 可在浏览器测试完整 MMD 页面，不需要安装 APK 或运行 AASC 服务。页面保留默认模型、灯光/AO、动作/物理、模型交互和定位面板；网页定位已改用 MindAR Basic 的 A-Frame 目标锚点。在“定位”中可选内置官方示例图，点“查看 MindAR 官方测试图”在另一屏幕显示或打印后平放并对准摄像头；也可拍照、选区并保存自定义基准图。网页识别目标后，蓝色矩形与中心十字贴在目标上，MMD 角色脚底站在图中心；相机姿态由目标锚点逆矩阵驱动，丢失目标时保留角色与最后相机视角，停止后恢复原展示相机。真实相机模式会在启动定位时请求浏览器摄像头权限。APK 与网页的本地存储互不相通，正式显示端仍保留原图片跟踪器；该相机改动已发布到外网测试页。

没有摄像头的电脑可在“定位图与校准”中把“视频输入”切换为“模拟摄像头”，再选择一张本地图片作为摄像头拍到的画面；“定位图”仍是独立的识别目标，可先选内置 MindAR 官方示例。预览上方滑条调缩放、左侧竖向滑条调经度透视、右侧竖向滑条调纬度透视、下方 0–360° 滑条先在图片平面内旋转，再应用经纬度透视，鼠标拖动图片只平移；“重置透视”恢复正面居中和 0° 旋转。模拟模式下“拍照校准”会预览当前透视画面，拍下那一帧后显示独立的蓝色矩形选区：拖动内部移动，拖动边或角调整尺寸，再保存新定位图。模拟视角与拍后矩形不是同一组操作。开始定位也使用模拟流，两者均不请求摄像头权限。图片只留在浏览器内存，刷新后需重新选择；已保存的定位图仍在浏览器 IndexedDB 中。切换输入源会结束当前定位；模拟成功不代表真实手机相机已经验收。

模拟定位运行中切到后台时会释放旧视频；回前台后若目标和输入模式未变，会自动重建流并继续定位。手动停止、切换输入或离开页面不会自动恢复；真实摄像头仍需手动启动。AR 只改变 PMX 相机，角色根节点位置和缩放不会被定位改写，以免扰动物理。

定位面板的“相机跟随”分类可调平移死区、旋转死区、缓动时间和相机距定位图中心的比例。默认分别为 0.5%、0.5°、120 ms、100%；前三项可调到 0 关闭防抖或缓动。距离可调 50%–100%，减小时沿相机到定位图中心的连线拉近，角色模型本身不移动。设置保存在当前浏览器，并在滑动时生效；此版本已发布到外网测试页。

测试网页的“灯光”和“定位”面板内设有可独立展开的分类：灯光为基础光照、AO、主光、补光、边缘光 1、边缘光 2、物理；定位为定位图与校准、跟踪操作、体感环绕、相机跟随。每个面板默认展开第一类。第一定位分类内的单个按钮会随状态切换“开始定位／结束定位”；拍照校准弹窗在短竖屏可滚动到关闭、拍摄和保存按钮。AO、补光、两盏边缘光和体感环绕的开关位于浅色分类标题左侧；仅点击复选框改变功能状态，点击分类文字或箭头展开/收起内容。此分类仅限 HTTPS 网页，不改变独立测试 APK 或正式显示端。

网页的主光阴影开关默认开启，位于主光分类标题前。补光开启后，可选“无阴影”（补光照亮全部区域）、“沿用主光阴影”（主光开启时补光不填亮主光遮挡区）或“自己的阴影”（另生成补光方向的第二张阴影图）；主光阴影关闭时，补光仍可用自己的阴影。手机上双阴影模式可能增加 GPU 开销。

A-Frame 真实相机定位使用摄像头原始帧；模拟模式以 960 像素为画面宽度，高度按所选原图比例计算，预览、纬度滑条、拍照校准和视频流使用同一比例；未选图时 960×540 仅为占位。不再显示旧 Controller 的输入分辨率选择。若真实相机预览正常但仍不能锁定，请先刷新网页，选中官方示例图，并在另一屏幕上让完整图片清晰、无反光地进入相机画面；持续失败时记录定位面板状态与手机型号，以便区分识别失败和相机帧异常。A-Frame 与 MindAR 组件目前与 MindAR Basic 一样从版本固定的 HTTPS CDN 加载。

网页加载模型时显示阶段、百分比和进度条；百分比是下载与初始化的分段进度，不是总字节比例，模型可显示后才到 100%。原测试 APK 不显示该进度条。

HTTPS 网页会随窗口、屏幕方向和舞台尺寸变化调整 MMD Canvas。它与正式显示端共用灯光面板中的当前实际渲染分辨率（Canvas 绘制缓冲像素宽×高）；渲染像素比沿用最多 2 倍的上限，因此不一定等于手机屏幕的物理像素数。独立测试 APK 后续不再维护。

在仓库根目录运行 `npm run build:web:mmd-ar-test`，输出 `3rd/mmd-ar-test/web-dist/`。可以直接通过内网的 `/mnt/AASC/3rd/mmd-ar-test/web-dist/` 打开，也可把该目录的**内容**放到 HTTPS 站点的 `/mnt/mmd-ar/` 路径；资源地址相对于当前页面目录，不依赖固定挂载前缀。模型与 MindAR 文件复用现有固定 SHA-256 清单，不需要 Gradle。网页构建产物已忽略，不提交 Git。

## 构建

在仓库根目录执行：

```sh
npm run build:apk:mmd-ar-test
```

构建脚本从显示端源代码生成轻量页面，按固定 SHA-256 清单获取 PMX、纹理和默认 VMD，最后输出：

```text
3rd/mmd-ar-test/output/aasc-mmd-ar-test.apk
```

模型缓存、Gradle 中间文件和 APK 输出均被本目录 `.gitignore` 排除，不提交到 Git。

## 本地页面和权限

APK 启动时仅在设备回环地址 `127.0.0.1:17836` 启动静态 HTTP 服务，固定端口让 IndexedDB 定位图和灯光设置可以跨启动保存。WebView 只接受本地 origin 和白名单静态路径。此服务用于加载 APK 内页面和资源，不绑定局域网、不提供 AASC API、不运行 Node 服务。用户点击图片定位并使用摄像头时，Android 才申请 CAMERA 权限；灯光和模型旋转不需要相机权限。

若 Activity 同步初始化失败，APK 会显示包含失败阶段与异常摘要的诊断页，可截图或选择文字反馈；详细堆栈写入 `MmdArTest` 日志。沉浸式全屏失败会降级继续运行。iQOO Z5x 的现场反馈指出 `window.insetsController` 为空，修正版增加了延后初始化和空值降级；仍需在该机型上复测。

沉浸式系统栏在页面视图挂载且窗口获得焦点后才初始化。若 `window.insetsController` 为空，测试页保留状态栏/导航栏并继续运行。

图片定位第一次使用时需要拍摄并保存一张基准图；位置图片保存在应用 WebView 的 IndexedDB 中。VMD 和 PMX 运行不依赖网络。

## 图片跟踪器 A/B 对比

定位面板中可选“当前 JS”或“MindAR 1.2.5”，默认仍是当前 JS。先保存一张定位图，再一次只运行一个算法；两轮会复用同一张参考图、四角选区和摄像头流程。测试面板统计参考图准备/目标编译、识别首锁耗时、识别器实际产出帧率、时间加权可见率、丢失次数和屏幕锚点 RMS 偏差。MindAR 每轮重新编译目标；首次首锁时间包含 APK 内模块加载，但不含相机授权。为测抖动请保持手机和定位图静止。MindAR 不提供置信度，所以页面不会显示虚假的置信度数值。

MindAR 运行时代码和许可证已随测试 APK 本地打包；只有选择 MindAR 时才加载，不访问 CDN。该 A/B 工具仅存在于此独立测试 APK，不改变正式显示端的默认 tracker。

选择 MindAR 后，共享摄像头就绪时状态会进入“MindAR 准备中”，并在目标编译/控制器启动后切换为寻找定位图，避免预览已出现但仍停留在摄像头权限提示。竖屏时顶部说明会在灯光按钮左侧换行，不遮挡右上角按钮。

MindAR 编译定位图时会显示百分比；若编译或控制器初始化失败，状态提示会显示错误原因，只有编译成功后才进入寻找定位图阶段。

## 设备要求

- Android 8.0/API 26 及以上，带摄像头和支持 WebGL 的 Android System WebView。
- 首次构建需能访问已发布的 MMD 静态资源源，构建机需安装 Android SDK/JDK 17、Node.js 和 `unzip`；通过 SHA-256 校验后的模型文件留在本机忽略缓存中。
