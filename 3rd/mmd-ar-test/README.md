## 布料物理频率（独立网页）

独立测试网页“动作 → 物理”新增“启用风”，默认关闭。开启后可调风力强度0–30（默认0.3）、风向经度−180至180°、纬度−90至90°（均默认0、步长1°），以及阵风幅度0–100%（默认0为恒风）。经纬度和灯光一致表示风从哪边吹来：0/0从角色前方（场景+Z）吹来，正90°经度从+X吹来，正纬度从上方吹来。风力强度是效果等级，调整强度有0.3秒缓动；偏好自动保存，刷新/切换模型或动作后保留，关闭风保留布料已有速度。黄色type2继续保持骨骼位置约束，仅受近似风矩影响；灰色无刚体骨骼及红色type0不直接受风。效果来自PMX刚体近似，手机布料手感和额外CPU开销仍需实测。

纠错基准默认45Hz，物理默认90Hz；已有合法保存值优先恢复，缺失/非法值回退新默认。纠错基准可在“动作 → 物理”调30–180Hz、步长5Hz，仅影响关节纠错强度；已有浏览器要应用新默认，可手动设45/90。灯光恢复默认将物理设90Hz，纠错独立保存。

右上角“动作 → 物理 → PMX 物理频率”可调30–180Hz，默认90Hz，步长5Hz。实时应用并保存，刷新、换模型、换动作或物理重载后保持选值；调整频率不重新加载模型或清零物理速度。

所有30–180Hz的物理子步预算覆盖当前最大0.1秒帧间隔并保留一个累计余量；90Hz为10步、65Hz为8步、180Hz为19步，实际按每帧需要执行。每个Ammo固定子步前对运动学锚点位置和旋转进行插值；有骨骼的type2刚体位置也按子步目标驱动，旋转保留物理求解，取消帧末位置回位。关节纠错率以默认45Hz归一时间，减小高Hz重复纠错扰动。PMX质量、弹簧和旋转阻尼保持，受控平移积分时跳过线性阻尼并在步进后恢复。时间余量跨画面帧保留；不足一步不强制推进。初始化、物理复位、步频变化和后台恢复时同步插值历史，正常子步保留动态速度。旧480Hz保存值恢复时限制为180Hz。180Hz是物理步进目标，渲染帧率由浏览器决定，高频增加CPU负担。本地网页已构建，当前外网以实际发布版本为准，手机布料观感与性能待现场验收，不保证不同步长的布料手感完全相同。

## 本地模型、贴图和动作（独立网页）

打开“动作”面板并展开“本地模型与动作”。电脑可点“选择模型目录”保留 PMX 与贴图的子目录关系；也可点“多选 PMX＋贴图”，一次选中 PMX 和所有配套贴图。选到多个 PMX 时，在下拉框选择要加载的模型。目录中缺少贴图会提示具体路径；多文件选择只能在名称唯一时回退匹配，请避免不同目录存在同名贴图。

模型加载后点“选择 VMD 动作”更换当前模型的动作；现有播放开关、动作进度、物理和重力/手动旋转继续可用。“恢复默认动作”只换动作，“恢复默认模型与动作”恢复内置米娅。动作开关开启且当前已有 VMD 时，新选 PMX 自动沿用该动作，从头播放（内置或本地 VMD 均可）；动作关闭或当前无 VMD 时，新模型保持无动作。选择取消、缺失贴图或损坏 VMD 时保留原先成功加载的角色或动作。

换模型、手动切换 VMD 或恢复默认动作都采用刷新时的顺序：文件准备成功后恢复模型绑定姿态（T Pose），初始化物理并清零速度，首个实际渲染帧只运行物理且隐藏初始化角色，下一帧才按动作开关播放。模型绑定姿态以其骨骼定义为准。原本关闭物理时保持关闭，原本暂停播放时不提前应用动作第 0 帧，保留绑定姿态与物理模拟。失败保留旧模型/动作；继承的本地 VMD 引用保留，后续物理重载仍可读取。

确认选择目录、PMX＋贴图或VMD后，底部会立即显示加载进度，本地资源区也显示当前阶段。读取文件/贴图时显示可确定的比例，解析和物理初始化时显示动态等待提示；资源提交成功后显示100%，约1.5秒后收起。失败保留错误原因和原模型/动作，多个PMX时先提示数量，选定模型后才加载。

新模型或动作的物理初始化后会清零刚体线速度、角速度并清除残留力，再开始正常物理模拟。自动循环重播沿用原有逻辑，不调用新增速度清理。

切换成功后会释放旧 Ammo 刚体、约束、物理世界和资源池；失败或过期结果会释放暂存物理并保留原内容，避免每次切换累积物理内存。若当前页面已经出现 `abort(OOM)`，先刷新恢复运行；外网以实际发布版本为准。

文件只在当前网页使用，不上传，刷新后需重新选择。手机的目录/多选能力以实际浏览器文件选择器为准；不支持目录选择时使用多文件入口。本功能通过 `npm run build:web:mmd-ar-test` 生成，仅独立网页包含这些入口，外网以实际发布版本为准。


## 2026-09-30 独立重力旋转与手动角度叠加（当前网页）

mmd-ar 原“独立体感环绕”改为“独立重力旋转（角色锚点）”。只读取设备姿态 beta/gamma 的倾斜分量来推导重力上方向，不读取 alpha 航向；无须摄像头、图片目标或 IMU 相机定位开启。首次有效倾斜样本作为中性重力参考，之后的重力倾斜驱动角色锚点的旋转。不设灵敏度倍率，使用完整倾斜角；保留“重力居中”；居中/关闭仅将重力层归零，手动旋转角度保持。

手动拖动目标角与重力四元数独立保存和缓动，不从最终合成的 Euler 角反推手动状态。每帧先更新实际相机，再把相机坐标中的重力倾斜旋转转换到世界坐标，最后左乘手动旋转四元数，更新现有角色中心枢轴。原位置、尺度和模型拖动不因重力模式改变；最终合成角速度沿用旋转物理保护，角色世界矩阵在动作/物理更新前提交。

屏幕旋转/后台切换清除旧重力参考，下一有效样本重新建立中性方向；启用权限有请求代号，关闭/退出会取消等待并移除监听，避免授权迟到重新开启。模型就绪前保存重力目标，模型重载后继续应用。IMU＋MindAR 相机定位和第二层相机缓动仍可同时使用。

打开右上角“定位 → 重力旋转”，分类左侧复选框为独立开关。重力死区默认 0.5°（0–3°），比较当前方向与上次接受目标；缓慢倾斜能累计越过阈值，接受后保持完整角度。重力缓动默认 20ms（0–500ms），只控制跟随速度。两个参数保存在当前浏览器，0 关闭对应过滤，与相机过滤分别生效。居中/关闭绕过死区将重力目标归零，再按缓动回到零点。

`npm run build:web:mmd-ar-test` 生成网页专用控制器/显示 API/runtime 和 `web-gravity-filter.mjs`。重力定向和真实网页回归见 `docs/self-test.md`；手机方向、噪声、布料与性能待现场验收。此次重力修改尚未发布外网。历史“体感只环绕相机”的网页描述以本节为准。

## HTTPS 网页

定位面板的“MindAR 抖动过滤”分类可调 One Euro Filter 的 `filterMinCF`（默认 0.001）和 `filterBeta`（默认 1000），设置保存在当前浏览器。滑动值在下一次启动定位时传给 MindAR；定位运行中更改后需先停止再重新开始。调低 `filterMinCF` 可减少静止抖动但会增加快速移动拖后；提高 `filterBeta` 可减少快速运动延迟，但可能更容易看到运动抖动。这与“相机跟随”里的死区和 120ms 相机缓动分开。

没有摄像头的电脑可在“定位图与校准”中把“视频输入”切换为“模拟摄像头”，再选择一张本地图片作为摄像头拍到的画面；“定位图”仍是独立的识别目标，可先选内置 MindAR 官方示例。预览上方滑条调缩放、左侧竖向滑条调经度透视、右侧竖向滑条调纬度透视、下方 0–360° 滑条先在图片平面内旋转，再应用经纬度透视，鼠标拖动图片只平移；“重置透视”恢复正面居中和 0° 旋转。模拟模式下“拍照校准”会预览当前透视画面，拍下那一帧后显示独立的蓝色矩形选区：拖动内部移动，拖动边或角调整尺寸，再保存新定位图。模拟视角与拍后矩形不是同一组操作。开始定位也使用模拟流，两者均不请求摄像头权限。图片只留在浏览器内存，刷新后需重新选择；已保存的定位图仍在浏览器 IndexedDB 中。切换输入源会结束当前定位；模拟成功不代表真实手机相机已经验收。

模拟定位运行中切到后台时会释放旧视频；回前台后若目标和输入模式未变，会自动重建流并继续定位。手动停止、切换输入或离开页面不会自动恢复；真实摄像头仍需手动启动。AR 只改变 PMX 相机，角色根节点位置和缩放不会被定位改写，以免扰动物理。

普通预览未进入AR时，后台自动清理保留角色拖动位置、相机方向和缩放距离，重复前后台/pagehide及resize也不自动居中。校准/定位流和未完成相机请求仍被释放或取消；手动停止定位、开始定位以及初次加载/换模型沿用原显式复位。2026-10-09本地web-dist已重建并通过真实模型/模拟轨道回归，外网以实际发布版本为准，手机系统后台恢复待现场验收。

定位面板的“相机跟随”分类可调平移死区、旋转死区、缓动时间和相机距定位图中心的比例。默认分别为 0.5%、0.5°、120 ms、100%；前三项可调到 0 关闭防抖或缓动。距离可调 50%–100%，减小时沿相机到定位图中心的连线拉近，角色模型本身不移动。设置保存在当前浏览器，并在滑动时生效；此版本已发布到外网测试页。

测试网页的“灯光”和“定位”面板内设有可独立展开的分类：灯光为基础光照、AO、主光、补光、边缘光 1、边缘光 2、物理；定位为定位图与校准、跟踪操作、体感环绕、相机跟随。每个面板默认展开第一类。第一定位分类内的单个按钮会随状态切换“开始定位／结束定位”；拍照校准弹窗在短竖屏可滚动到关闭、拍摄和保存按钮。AO、补光、两盏边缘光和体感环绕的开关位于浅色分类标题左侧；仅点击复选框改变功能状态，点击分类文字或箭头展开/收起内容。此分类仅限 HTTPS 网页，不改变独立测试 APK 或正式显示端。

网页的主光阴影开关默认开启，位于主光分类标题前。补光开启后，可选“无阴影”（补光照亮全部区域）、“沿用主光阴影”（主光开启时补光不填亮主光遮挡区）或“自己的阴影”（另生成补光方向的第二张阴影图）；主光阴影关闭时，补光仍可用自己的阴影。手机上双阴影模式可能增加 GPU 开销。

A-Frame 真实相机定位使用摄像头原始帧；模拟模式以 960 像素为画面宽度，高度按所选原图比例计算，预览、纬度滑条、拍照校准和视频流使用同一比例；未选图时 960×540 仅为占位。不再显示旧 Controller 的输入分辨率选择。若真实相机预览正常但仍不能锁定，请先刷新网页，选中官方示例图，并在另一屏幕上让完整图片清晰、无反光地进入相机画面；持续失败时记录定位面板状态与手机型号，以便区分识别失败和相机帧异常。A-Frame 与 MindAR 组件目前与 MindAR Basic 一样从版本固定的 HTTPS CDN 加载。

网页加载模型时显示阶段、百分比和进度条；百分比是下载与初始化的分段进度，不是总字节比例，模型可显示后才到 100%。原测试 APK 不显示该进度条。

HTTPS 网页会随窗口、屏幕方向和舞台尺寸变化调整 MMD Canvas。它与正式显示端共用灯光面板中的当前实际渲染分辨率（Canvas 绘制缓冲像素宽×高）；渲染像素比沿用最多 2 倍的上限，因此不一定等于手机屏幕的物理像素数。独立测试 APK 后续不再维护。

在仓库根目录运行 `npm run build:web:mmd-ar-test`，输出 `3rd/mmd-ar-test/web-dist/`。可以直接通过内网的 `/mnt/AASC/3rd/mmd-ar-test/web-dist/` 打开，也可把该目录的**内容**放到 HTTPS 站点的 `/mnt/mmd-ar/` 路径；资源地址相对于当前页面目录，不依赖固定挂载前缀。模型与 MindAR 文件复用现有固定 SHA-256 清单，不需要 Gradle。网页构建产物已忽略，不提交 Git。

Blender工程工作区仅在独立HTTPS网页启用。首次构建前在仓库根目录运行 `npm run prepare:mmd-ar-blender-engine`，再运行 `npm run build:web:mmd-ar-test`；Web构建会生成单独延迟加载的引擎模块、`assets/blender-engine/0.1.136/` Brotli运行资源、目录Service Worker和跨域隔离 `.htaccess`。点击网页“Blender工程”后选择工程目录，再选 `.blend` 打开；关闭时保存回所选目录。浏览器缓存后可复用引擎资源；APK不包含Blender引擎。需要支持 File System Access API 和 Service Worker 的HTTPS桌面Chromium。更多边界见根目录 `docs/design/mmd-ar-blender-workbench.md`。

## 构建

在仓库根目录执行：

```sh
npm run build:apk:mmd-ar-test
```

构建脚本从显示端源代码生成轻量页面，按固定 SHA-256 清单获取 PMX、纹理和默认 VMD，最后输出：

```text
3rd/mmd-ar-test/output/aasc-mmd-ar-test.apk
```

模型缓存、Gradle 中间文件和 APK 输出均被本目录 `.gitignore` 排除，不提交到 Git。

## 本地页面和权限

APK 启动时仅在设备回环地址 `127.0.0.1:17836` 启动静态 HTTP 服务，固定端口让 IndexedDB 定位图和灯光设置可以跨启动保存。WebView 只接受本地 origin 和白名单静态路径。此服务用于加载 APK 内页面和资源，不绑定局域网、不提供 AASC API、不运行 Node 服务。用户点击图片定位并使用摄像头时，Android 才申请 CAMERA 权限；灯光和模型旋转不需要相机权限。

若 Activity 同步初始化失败，APK 会显示包含失败阶段与异常摘要的诊断页，可截图或选择文字反馈；详细堆栈写入 `MmdArTest` 日志。沉浸式全屏失败会降级继续运行。iQOO Z5x 的现场反馈指出 `window.insetsController` 为空，修正版增加了延后初始化和空值降级；仍需在该机型上复测。

沉浸式系统栏在页面视图挂载且窗口获得焦点后才初始化。若 `window.insetsController` 为空，测试页保留状态栏/导航栏并继续运行。

图片定位第一次使用时需要拍摄并保存一张基准图；位置图片保存在应用 WebView 的 IndexedDB 中。VMD 和 PMX 运行不依赖网络。

## 图片定位

定位面板固定使用 MindAR 1.2.5。先保存一张定位图，再开始跟踪；MindAR 模块按需从 APK 本地资源加载，不访问 CDN。测试面板显示目标编译、首锁耗时、识别器实际产出帧率、时间加权可见率、丢失次数和屏幕锚点 RMS 偏差。MindAR 每次启动会重新编译目标，首锁时间包含 APK 内模块加载，但不含相机授权。为测抖动请保持手机和定位图静止。MindAR 不提供置信度，所以页面不会显示虚假的置信度数值。

独立测试 APK 和正式显示端均只使用 MindAR；HTTPS 测试网页使用 A-Frame MindAR。

选择 MindAR 后，共享摄像头就绪时状态会进入“MindAR 准备中”，并在目标编译/控制器启动后切换为寻找定位图，避免预览已出现但仍停留在摄像头权限提示。竖屏时顶部说明会在灯光按钮左侧换行，不遮挡右上角按钮。

MindAR 编译定位图时会显示百分比；若编译或控制器初始化失败，状态提示会显示错误原因，只有编译成功后才进入寻找定位图阶段。

### 当前顶点模式：骨骼跟随与自碰撞

“顶点布料（CPU）”和“顶点布料 GPU（WebGL2）”现在都保留原骨骼物理，顶点层只做形状跟随、附件连接、身体接触和布料自碰撞，不重复施加风和重力。无固定点的包体/装饰也先跟随原骨骼，近距离同链附件按相对偏移约束连接；关联组开关会同步，关闭组仍按骨骼运动并作为接触表面。

状态显示“骨骼驱动 · 自碰撞（点-面/边-边）· 附着数量”。仍使用现有每帧子步数，未新增调参项。GPU在纹理中重拟合BVH和计算接触，无逐帧全部粒子读回。初始重叠层不会强行撑开，自动附件映射需模型验收；不是完整连续碰撞，快速运动/深穿插仍可能有残余穿透，顶点接触不反向推动骨骼。自碰撞会增加开销，帧率须实机确认。此次已重建独立网页，尚未运行验收或发布。

### GPU 顶点布料 500ms 保护

顶点GPU任务采用至多4个pass/批、非阻塞栅栏等待和4行自碰撞切片。初始化/更新/复位超时或GPU错误时，停用顶点层并保存Ammo，不执行CPU自碰撞。刷新默认退出GPU顶点模式，`?safePhysics=1` 强制Ammo。500ms为墙钟预算而非硬中断或纯GPU执行时间；当前未真机验收。

## 接触阴影与间接光（独立测试页，本地构建）

灯光面板下方使用现有正式分类：“接触阴影”和“间接光”并列，SSGI位于“间接光 → SSGI”子类。接触阴影可调强度/距离及4–64步整数采样，首次默认12；旧设置按原低/中/高质量迁移12/20/32步，之后独立保存。SSGI可调强度/半径/质量及0–3轮双边滤波（默认1轮、每轮半径3个低分辨率效果像素）。SSGI质量低/中/高分别使用4/6/8条GI射线、每条12/20/32步，效果尺寸最多画布一半且长边上限384/512/640。两项效果首次均关闭，设置保存在浏览器的 `aasc.mmdArTest.screenLighting.v1` 中；灯光重置会关闭效果、接触采样恢复12步。

SSGI每帧将未合成GI的原始SceneColor/深度写入双缓冲历史；SceneColor经深度引导Reduction，深度建普通Z near/min 与 far/max HZB，重投影通过历史深度及当前可见性校验后才参与本帧新的SSGI计算。首次帧、相机/投影切断或动态表面不匹配时回退当前帧颜色，不对上一帧GI结果做无条件累积。SSGI保边滤波只处理RGB；接触保边模糊独立处理alpha，两种模式均保留另一通道。接触分类可调0–3轮，每轮1–5效果像素，默认1轮/3像素，0轮旁路；先GI后接触依次水平/垂直滤波。新增设置本地保存并随灯光重置恢复；关闭接触释放独立当前帧半深度目标，关闭GI释放历史。

该效果只限WebGL2独立测试网页/测试APK副本，正式显示端未修改。仅屏幕可见深度参与；屏外、透明头发/多层衣物可能有漏光或历史拒绝；没有镜面反射，属于漫反射近似。Reduction/HZB增加全屏pass，质量/滤波轮数提升也会增加GPU成本；需用用户模型和目标设备验收画面及性能。
