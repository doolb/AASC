# 声纹匹配分数和阈值

## 任务描述

在独立 Android ASR APK 中增加声纹匹配相似度分数和当前阈值的 HTTP 返回字段，用于观察命中与未命中的实际分数。保持现有声纹模型、匹配逻辑、单段/多段流程和默认阈值不变。

## Design 需求

- 使用现有 Sherpa `SpeakerEmbeddingManager.search` 决定命中结果。
- 使用注册 embedding 与测试 embedding 的余弦相似度生成诊断分数。
- 单段声纹结果返回顶层 `similarityScore`、`threshold`。
- 多段声纹结果返回顶层 `threshold`，每个 segment 返回 `similarityScore`。
- 声纹状态接口返回 `threshold`。
- 空声纹库或无可用 embedding 时分数返回 `null`。

## Spec 设计

```text
match(embedding):
    speaker = existingManager.search(embedding, threshold)
    score = cosineSimilarity against matched speaker, or highest registered embedding when unmatched
    return speaker, score, threshold

serialize result:
    preserve existing speaker fields
    add similarityScore and threshold
```

## 自测用例

1. 单段命中：返回 `matchedSpeaker`、数值 `similarityScore` 和 `threshold`。
2. 单段未命中：`matchedSpeaker` 为 `null`，仍返回最高相似度分数和阈值。
3. 多段结果：每个 segment 返回相似度分数，顶层返回阈值。
4. 空声纹库：分数为 `null`，JSON 合法。
5. 状态接口：返回当前默认阈值 `0.5`。
6. 原有字段值和模型文件名保持不变。

## 兼容性测试

- Android JVM 单元测试。
- HTTP JSON 序列化测试。

## 性能测试

- 分数计算仅遍历内存中的注册 embedding，不增加 ONNX 推理。
- 对单个注册说话人的额外计算为一次 512 维向量余弦相似度。
- 验证接口响应仍能在现有 60 秒音频限制内完成。

## 风险评估

- 当前 AAR 不直接返回 `SpeakerEmbeddingManager.search` 的分数，因此诊断分数由注册 embedding 计算；若底层版本改变相似度实现，需要重新校准解释方式。
- 分数只用于观测，不参与命中判定，避免改变现有识别行为。
- 注册 embedding 不可用时返回 `null`，不能伪造分数。
