# RapidOCR Android APK 大小核选择

## 任务描述

为已完成的 `android-rapidocr` 测试 APK 增加“自动 / 大核 / 小核”选择，使 HTTP OCR 的 ONNX Runtime 推理线程可以按设备 CPU 集群进行调度。

## Design 需求

- 原生控制页增加三档 CPU 模式，默认自动并通过 `SharedPreferences` 保存。
- 复用现有 Android affinity 方案：JNI 识别 `cpu_capacity` 或 `cpuinfo_max_freq`，调用 `sched_setaffinity` 绑定当前线程。
- 只绑定 RapidOCR 单线程推理执行器，不绑定 UI、HTTP 接收和模型加载线程。
- affinity 不可用、大小核无法识别或系统拒绝绑定时自动回退，不影响 OCR 结果。
- HTTP 接口和网页协议保持兼容。

## Spec 设计

- `CpuMode` 定义 `AUTO/BIG/LITTLE` 及持久化数值。
- `CpuAffinity` 提供 Kotlin 安全边界，native 失败只返回回退状态。
- `OcrHttpServer` 接收 CPU 模式 provider，在每个推理任务线程中应用当前模式。
- `MainActivity` 负责下拉框、持久化、状态显示和 provider 注入。

## 受影响的功能模块和代码

- `3rd/tts-server/android-rapidocr/app/build.gradle.kts`：接入 CMake/native affinity 库。
- `3rd/tts-server/android-rapidocr/app/src/main/cpp/`：新增 CPU 集群检测和线程 affinity。
- `3rd/tts-server/android-rapidocr/app/src/main/java/com/aasc/rapidocr/CpuMode.kt`、`CpuAffinity.kt`：新增模式和 JNI 边界。
- `MainActivity.kt`、`OcrHttpServer.kt`、`activity_main.xml`、`strings.xml`：增加选择、状态和推理线程应用。
- `app/src/test/`：增加模式映射、provider 接入和失败回退测试。
- RapidOCR design/spec/readme/changelog/todo：同步当前行为和验收结果。

## 自测用例

1. AUTO/BIG/LITTLE 的持久化值和未知值回退正确。
2. 推理线程读取当前模式，切换模式后下一次请求使用新模式。
3. affinity native 不可用或返回失败时，OCR 仍返回成功结果。
4. APK 构建成功，arm64 真机显示实际核心或回退状态。
5. HTTP `/health`、网页上传和 `/api/ocr` 行为不回归。

## 兼容性测试

- Android 8.0+、arm64-v8a；优先验证现有 Android 9 arm64 设备。
- 至少覆盖可识别大小核和无法读取 CPU 能力值的自动回退路径。

## 性能测试

- 比较自动、大核、小核模式下同一测试图片的 `elapsedMs`，只记录观测值，不把 affinity 成功率等同于 OCR 正确率。
- 验证模式切换不会创建额外 OCR session 或推理线程。

## 风险评估

- Android 厂商可能隐藏 CPU sysfs 文件或限制 affinity；必须保留系统调度回退。
- `sched_setaffinity` 仅对调用线程生效，若绑定位置错误会产生“界面显示已选择但 OCR 未绑定”的假象，因此测试要覆盖推理线程边界。
