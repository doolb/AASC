# 2026-09-10 ASR 文字与声纹双降噪开关

## 任务描述

将 Android ASR APK 当前共用的 GTCRN 降噪开关拆分为 ASR 文字降噪和声纹降噪，支持独立比较两条识别链路的效果。

## Design 需求

- 普通文字识别只使用 ASR 文字降噪设置。
- 声纹注册、分段、embedding 和匹配只使用声纹降噪设置。
- 声纹测试的分段时间轴来自声纹音频，ASR 使用文字音频的同一时间区间。
- 旧 `denoise` 参数继续兼容，并同时控制两条链路。

关联设计：`docs/design/android-asr-apk.md` 的“2026-09-10 ASR 文字与声纹双降噪开关”。

## Spec 设计

- 解析 `asrDenoise`、`voiceprintDenoise`，缺省时回退旧 `denoise`。
- 两个设置相同时只执行一次降噪并复用结果。
- 两个设置不同时分别准备文字音频和声纹音频。
- JSON 返回新旧降噪状态和耗时字段。

关联实现伪代码：`docs/spec/android-asr-apk.md` 的“2026-09-10 ASR 文字与声纹双降噪伪代码”。

## 自测用例

1. 两个开关都关闭，文字和声纹均使用原始音频。
2. 只开启 ASR 文字降噪，普通 ASR 使用降噪音频，声纹仍使用原始音频。
3. 只开启声纹降噪，注册、分段和匹配使用降噪音频，ASR 文字使用原始音频。
4. 两个开关都开启，降噪结果只生成一次并被两条链路复用。
5. 旧 `denoise=1/0` 请求仍同时控制两条链路。
6. 注册接口使用 `voiceprintDenoise`，测试时返回两类状态和耗时。

## 兼容性测试

- Android 9、arm64 设备 `SM-N9500`。
- `/api/asr`、`/api/voiceprint/register`、`/api/voiceprint/test`。
- 现有 `SHERPA_SINGLE`、`SHERPA_MULTI`、`SHERPA_MULTI_FAST` 和旧 `denoise` 参数。

## 性能测试

- 记录两个开关组合下的 `denoiseMs`、`asrDenoiseMs`、`voiceprintDenoiseMs`、`embeddingMs` 和总耗时。
- 验证两个开关同时打开时不会重复生成相同的降噪音频。

## 风险评估

- 注册与测试的声纹降噪设置不一致时，声纹分数可能下降；页面需要明确提示。
- 两个开关分别打开时会增加一次 GTCRN 推理，可能增加耗时和内存峰值。
- 不同处理链路必须保持时间轴一致，否则声纹分段对应的文字区间会错位。

## 执行结果

- 已完成 `asrDenoise` 与 `voiceprintDenoise` 两条独立链路；旧 `denoise` 参数继续同时控制两条链路。
- Android JVM 全量单元测试通过，共 52 个测试；`npm --prefix 3rd/tts-server run build:android-asr` 构建成功。
- APK 已安装到 `SM-N9500`（`192.168.1.6:5555`），HTTPS 服务和 `MainActivity` 正常运行。
- 真机使用 `res/models/sensevoice/zh.wav` 注册 `z`：单段独立开关测试命中 `z`，分数 `1.0`，阈值 `0.5`；`asrDenoise=1&voiceprintDenoise=0` 返回文字降噪耗时约 `955ms`、声纹降噪 `0ms`。
- 两个开关同时开启时两类降噪耗时均为约 `941ms`，验证降噪结果复用；`SHERPA_MULTI_FAST` 独立开关测试返回一个连续分段且分数 `0.9773119`。
