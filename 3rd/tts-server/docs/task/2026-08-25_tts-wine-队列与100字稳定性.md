# 任务：Wine TTS 队列与 100 字稳定性

## 任务描述

修复 `tts-wine.js` 中 worker 派发错误，使请求可以完成；参考 `tts.js` 补齐 FIFO 队列、断连清理和超时边界，并使用固定 100 字文本测试速度、队列恢复和 RSS 稳定性。

## Design 需求

- 固定 worker 并发，任务 FIFO 出队。
- 出队前跳过断连响应，排队任务支持超时和上限。
- 一个任务绑定一个明确的 Wine worker，不在处理函数中重新查找 worker。

## Spec 设计

见 `docs/spec/tts-wine-queue-stability.md`，包含任务字段、`drain()`、TTS 处理和状态伪代码。

## 受影响模块与代码

- `tts-wine.js`：HTTP 请求、队列和 Wine worker 调度。
- `tts-wine.test.js`：100 字请求、并发队列和断连恢复集成测试。
- `stress-test.js`、`tts-wine-benchmark.js`：速度与内存测试。

## 自测用例

1. `/api/voices` 返回 200 和语音列表。
2. 100 字 `/api/tts` 返回有效 WAV。
3. 两 worker 并发处理 6 个 100 字请求，全部成功且队列归零。
4. 排队/处理中断连后，后续正常请求成功。
5. 100 次 HTTP 常驻循环记录延迟和 RSS；另有此前 100 次直接 worker 循环作为 SDK 基线。

## 兼容性测试

- Node.js + Wine + 已有 worker 二进制。
- 保持原有 `/api/tts`、`/api/voices` 和 `/api/tts/status` 路径及 WAV 格式。

## 性能测试

- 并发 1、2、3。
- 固定 100 Unicode 字符，统计平均、P50、P95、P99、TPS。
- 记录 Node、worker、wineserver 进程树 RSS。

## 风险评估

- SDK 每次合成创建/释放 synthesizer，若长稳 RSS 持续增长，需另行评估 C++ 句柄复用。
- 队列上限会在过载时返回 503，调用方需要按错误结构处理。

## 实际结果

- 集成测试：3/3 通过；覆盖语音列表、100 字 WAV、2 worker FIFO 6 请求、断连恢复。
- 断连验证：`stress-test.js --mode verify` 5/5 通过，所有验证文本均为 100 字。
- HTTP 压测：100/100 成功，3 worker/并发 3，TPS 0.55，平均 5434ms，P50 5438ms，P95 6809ms，P99 8302ms。
- RSS：ready 269552KB、peak 521776KB、final 429924KB，增长 160372KB；暂不判定为内存稳定。
