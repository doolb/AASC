# 任务记录：TTS 生成失败返回结果

## 任务描述

- 修复 `tts.js` 在生成 TTS 失败时的返回行为，确保调用方能收到明确错误信息。

## Design 需求

- `/api/tts` 失败时必须返回统一 JSON。
- 成功时继续返回音频流，兼容现有前端播放逻辑。
- 前端需要优先展示后端返回的失败详情。

## Spec 设计

- 抽取统一错误返回函数，避免不同接口返回结构不一致。
- 前端对非成功响应先走 JSON 解析，再回退到通用错误提示。

## 受影响模块与代码

- `tts.js`
- `public/index.html`
- `docs/design/tts-error-return.md`
- `docs/spec/tts-error-return.md`

## 自测用例

- 提交空文本，确认返回 400 JSON。
- 模拟 `balcon.exe` 不可用，确认返回 500 JSON，包含失败详情。
- 正常生成语音，确认仍可播放音频。

## 兼容性测试

- 浏览器端继续使用 `fetch` 调用接口。
- 成功场景保持 `audio/wav` 不变。

## 性能测试

- 本次仅调整错误分支与响应解析逻辑，无额外性能开销。

## 风险评估

- 如果调用方硬编码按二进制解析所有响应，仍需自行判断 HTTP 状态码。
- 音频流开始发送后的流式错误无法再切换为 JSON，这是 HTTP 响应模型限制。

- 0.5 小时。
