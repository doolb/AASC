# 测试 OCR 与 YOLO 单核推理配置

## 任务描述

为测试 RapidOCR 和测试 YOLO11 Android APK 增加“单大核”和“单小核”模式。模式不仅要把推理执行线程绑定到一个具体 CPU，还要把 ONNX Runtime 的 intra-op 线程数设置为 1，便于通过 HTTP 图片接口进行单核心速度对比。

## Design 需求

- 保留现有“自动 / 大核 / 小核”模式和 SharedPreferences 数值兼容。
- 增加“单大核 / 单小核”两档；JNI 根据设备能力值选择对应集群中的第一个核心。
- 单核模式使用 ORT `intraOp=1`、`interOp=1`，其他模式保持原有 `intraOp=2`、`interOp=1`。
- RapidOCR 和 YOLO11 的 HTTP 推理及五模型测速都读取当前模式；切换线程模式时安全重建受影响的 ORT session。
- affinity 失败只产生回退状态，不影响 OCR 或目标检测结果。

## Spec 设计

```text
CpuMode:
    AUTO = 0, BIG = 1, LITTLE = 2
    SINGLE_BIG = 3, SINGLE_LITTLE = 4
    SINGLE_BIG/SINGLE_LITTLE.intraOpThreads = 1
    other modes.intraOpThreads = 2

NativeCpuAffinity.nativeApply(mode):
    restore AUTO to original CPU mask
    classify CPUs by cpu_capacity or cpuinfo_max_freq
    BIG/LITTLE select the complete matching cluster
    SINGLE_BIG/SINGLE_LITTLE select the first matching CPU only
    apply sched_setaffinity to the current inference thread

RapidOcrEngine.recognize(bitmap, mode):
    inside the synchronized engine state:
        if session is not yet bound to the inference thread or active mode differs:
            close and recreate the three sessions from the saved model directory
        run OCR with the selected session options

YoloDetector.load(model, mode):
    reuse session only when both active model and CPU mode match
    otherwise close active session and recreate it with mode.intraOpThreads
```

## 受影响的功能模块和代码

- `android-rapidocr`: `CpuMode`、`CpuAffinity`、RapidOCR ORT session、HTTP 推理 runner、JNI affinity、CPU 模式单元测试。
- `android-yolo`: `CpuMode`、`YoloDetector`、`YoloBenchmark`、JNI affinity、CPU 模式单元测试。

## 自测用例

- JVM 单元测试确认持久化数值 0..4 映射到五档模式。
- JVM 单元测试确认两档单核模式 `intraOpThreads == 1`，其余模式为 2。
- RapidOCR 和 YOLO11 模块单元测试通过。
- 两个 APK debug 构建成功，`arm64-v8a` JNI 库被打包。
- 真机通过 HTTP `/health`、图片接口和网页入口验证；CPU 状态返回单核模式及单个核心。

## 兼容性测试

- Android 9 arm64 设备，保留 API 26 及以上构建约束。
- 无法读取 CPU 能力值或系统拒绝 affinity 时，识别/检测仍返回结果并显示自动回退。
- 旧版 SharedPreferences 的 0/1/2 值继续对应自动/大核/小核。

## 性能测试

- 以 HTTP 单次检测及 YOLO11 五模型测速接口为入口，记录模式、模型、推理阶段耗时和检测结果。
- 单核模式的 session 线程数通过代码测试和真机线程/CPU 状态核验。

## 风险评估

- Android 厂商可能隐藏 `cpu_capacity`、`cpuinfo_max_freq` 或限制 `sched_setaffinity`；此时只能回退系统调度。
- ORT session 的线程数在创建时固定，模式切换必须重建 session，重建期间会增加一次加载延迟。
- 单核模式通常降低吞吐，结果准确度应与原有模式保持一致但需要真机图片回归确认。

## 预计工时

- 约 2 小时，包含实现、单元测试、APK 构建和真机 HTTP 验证。

## 执行结果

- 已完成 RapidOCR 与 YOLO11 的五档 CPU 模式：自动、大核、小核、单大核、单小核；旧版 0/1/2 持久化值保持兼容。
- 已完成单核 ORT session 配置：单核模式 `intraOp=1`、`interOp=1`，其他模式保持 `intraOp=2`、`interOp=1`；模式变化时重建 session。
- 已完成 JNI 单核心 affinity：根据设备 `cpuinfo_max_freq` 识别大小核，单大核/单小核分别绑定一个具体核心；RapidOCR HTTP 响应和网页显示 affinity 状态。
- JVM 单元测试通过：`android-rapidocr`、`android-yolo` 均执行 `:app:testDebugUnitTest` 成功。
- Debug APK 构建通过：`npm run build:android-rapidocr`、`npm run build:android-yolo`；两个 arm64 JNI 库均完成 CMake 编译并打包。
- Android 9 arm64 真机 `192.168.1.6:5555` 验证通过：RapidOCR `/health`、网页入口、PNG OCR；单小核推理线程及 ORT 线程为 CPU 0，单大核为 CPU 4。YOLO `/health`、`/api/models`、单大核 `/api/yolo` 通过，返回 `affinityStatus=单大核（核心 5）` 且推理线程仅允许 CPU 5。
- YOLO 设备检测使用 `screen.png`，返回成功但无目标框；本任务只验证单核调度和接口链路，未改变此前的准确度结论。
