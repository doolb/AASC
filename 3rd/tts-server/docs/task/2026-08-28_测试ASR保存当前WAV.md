# 测试 ASR APK 保存当前 WAV

## 任务描述

为独立测试 ASR APK 的内置网页和 Android 原生界面增加“保存当前 WAV”按钮，便于保存当前录音或已经选择的音频样本。

## Design 需求

- 网页在播放当前音频按钮旁显示保存按钮。
- Android 原生界面在已有音频后启用保存按钮。
- 保存内容统一为 16kHz、单声道、16-bit PCM WAV。
- Android 10 及以上保存到系统 Download；旧系统保存到 APK 专属外部音频目录。

## Spec 设计

- 网页下载 `selectedAudio`，文件名保持 `.wav` 后缀。
- Android 通过 `WavFileSaver` 编码并写入目标目录；写入失败时删除不完整文件并显示错误。

## 受影响功能模块和代码

- `AsrWebPage.kt`：内置网页按钮和浏览器下载逻辑。
- `activity_main.xml`、`MainActivity.kt`：Android 原生保存按钮和状态。
- `WavFileSaver.kt`：Android WAV 文件保存边界。
- `WavAudioTest.kt`、`AsrHttpServerTest.kt`、静态测试：保存契约。

## 自测用例

- 未选择音频时两个保存按钮不可用。
- 网页录音或选择 WAV 后可以触发 `.wav` 下载。
- Android 保存文件包含 RIFF/WAVE、PCM、16kHz、单声道、16-bit 头。
- Android 保存失败不遗留不完整目标文件。

## 兼容性测试

- Android 10+ 使用 MediaStore Downloads。
- Android 8/9 使用 APK 专属外部音频目录，不额外申请存储权限。
- 内置网页在 HTTPS 与 localhost 安全上下文下保持录音与下载可用。

## 性能测试

- 保存只执行一次 WAV 编码和顺序写入，不调用 ASR 或声纹模型。
- 以 60 秒音频验证写入耗时和内存占用无异常。

## 风险评估

- Android 旧系统文件位于 APK 专属目录，卸载 APK 后会被系统清理；界面提示实际路径。
- 浏览器下载行为受浏览器权限和下载策略影响，失败时保留当前音频并提示。
