# 2026-09-10 声纹分段后处理优化

## 任务描述

针对同一说话人 WAV 被切成相邻片段后，短片段相似度低于阈值并被标记为未知、ASR 文本重复的问题，优化 Android ASR APK 的声纹分段后处理逻辑。当前声纹模型、相似度算法和阈值保持不变。

## Design 需求

- 保留 Pyannote 分段和 Sherpa 聚类作为候选分段来源。
- 对相邻短片段执行注册声纹感知的保护性合并。
- 合并后重新提取声纹，只有命中同一注册说话人时才确认。
- 确认合并后只执行一次 ASR，避免重复文本。
- `SHERPA_MULTI` 和 `SHERPA_MULTI_FAST` 均支持传递 `speakerCount`。

关联设计：`docs/design/android-asr-apk.md` 的“2026-09-10 声纹分段后处理优化”。

## Spec 设计

- 候选分段先按 cluster 合并。
- 对每个候选分段计算注册声纹匹配结果。
- 对短且未知的相邻分段尝试合并并重新匹配。
- 只保留合并确认后的最终分段进行 ASR。

关联实现伪代码：`docs/spec/android-asr-apk.md` 的“2026-09-10 声纹分段后处理优化伪代码”。

## 自测用例

1. 同一 WAV 注册后进行 `SHERPA_MULTI`，相邻短片段合并后只返回一段连续 ASR 文本。
2. 同一 WAV 注册后进行 `SHERPA_MULTI_FAST&speakerCount=1`，短片段不会因略低于阈值单独变成未知。
3. 两个不同注册说话人的相邻片段不会因为短片段规则被错误合并。
4. 合并失败时保留原始片段、原始分数和阈值字段。
5. `speakerCount=AUTO` 的默认行为保持兼容。

## 风险评估

- 过短语音本身缺少稳定声纹信息，合并后仍可能低于阈值。
- 真实多人快速交替说话时，保护性合并需要依赖两侧注册说话人和合并后重新匹配，仍需使用多人 WAV 回归。
- 本任务不更换模型，因此不能解决模型本身跨音调泛化的全部问题。
