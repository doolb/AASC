# Wine TTS 队列与稳定性设计

## 目标

Wine TTS 服务沿用 `tts.js` 的固定并发 FIFO 队列语义，同时保证一个请求只绑定一个已预留的 Wine worker，避免处理函数再次查找空闲 worker 导致请求失败。

## 运行规则

- 服务启动固定数量的常驻 Wine worker。
- 请求按进入顺序进入 FIFO 队列；`drain` 只把任务分配给 ready 且 idle 的 worker。
- 任务出队时检查客户端是否已断连；排队中的断连任务直接移除。
- worker 单飞处理一个 SDK 请求；完成、失败或超时后才释放 worker。
- 队列长度和排队等待时间有上限，超限返回结构化 503 错误。

## 验收指标

- 固定 100 字 Unicode 文本的单请求成功率为 100%。
- 并发 1/2/3 时，所有未断连请求成功，队列状态最终回到 0。
- 断连请求不阻塞后续正常请求。
- 长稳测试记录请求延迟和进程树 RSS，区分服务基线与 worker 常驻增长。

## 本次实现结果

- 100 字单请求、2 worker 并发 6 请求和 5 组断连恢复场景全部通过。
- 100 字、3 worker、并发 3、总计 100 次 HTTP 压测：100/100 成功，TPS 约 0.55，平均 5.43 秒，P50 5.44 秒，P95 6.81 秒，P99 8.30 秒。
- 进程树 RSS：ready 约 270 MB，峰值约 522 MB，结束约 430 MB，较 ready 增长约 160 MB；该结果不能判定为稳定，需后续专项处理 SDK/句柄增长。
