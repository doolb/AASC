# TTS 生成失败返回设计

## 背景

当前 `/api/tts` 在生成音频失败时虽然会进入异常分支，但返回结构不统一，前端也无法稳定读取失败原因，导致调用方难以判断失败类型。

## 目标

- 在 TTS 生成失败时始终返回 JSON 错误结果。
- 返回结构保持统一，便于前端与外部调用方处理。
- 不影响成功时继续返回 `audio/wav` 音频流。

## 方案

- 为接口增加统一错误返回函数。
- `/api/tts`、`/api/voices`、参数校验失败场景统一输出 `success: false` 的 JSON。
- 前端在收到非 2xx 响应时优先解析 JSON，展示后端返回的具体失败原因。

## 完成状态

- 已完成：统一 TTS 失败返回结构并补充前端错误提示处理。
