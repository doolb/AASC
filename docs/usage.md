# Web MediaCenter - 使用说明

## 1. 快速开始

命令行调用服务器 API 的完整说明见：[API 使用与命令行工具](api-usage.md)。

### 1.1 安装依赖

```bash
cd web-mediacenter
npm install
```

### 1.2 启动服务器

```bash
npm start
```

服务器启动后会显示访问地址：

```
==================================================
媒体中心服务器已启动
==================================================
控制端地址: http://192.168.1.39:8081/control
显示端地址: http://192.168.1.39:8081/display
==================================================
```

### 1.3 访问界面

- **控制端**: 在浏览器中打开 `http://<服务器IP>:8081/control`
- **显示端**: 在显示设备上打开 `http://<服务器IP>:8081/display`

## 2. 控制端使用

### 2.1 上传文件

1. 点击 **"选择图片/GIF"** 或 **"选择视频"** 按钮
2. 选择要上传的文件
3. 文件会自动上传并发送到当前选中的显示端

### 2.2 URL 发送

1. 在 URL 输入框中输入图片或视频的 URL
2. 点击 **"发送"** 按钮
3. 媒体会发送到当前选中的显示端

### 2.3 服务器资源

- 显示已上传的所有媒体文件
- 点击 **"播放"** 发送到显示端
- 点击 **"删除"** 删除文件
- 点击 **"刷新"** 更新列表

### 2.4 显示端选择

- 显示所有已连接的显示端
- 点击选择要控制的显示端
- 显示端信息包含 IP 地址和屏幕尺寸

### 2.5 显示控制

#### 画面填充

| 按钮 | 效果 |
|------|------|
| **适应** | 媒体完整显示在屏幕内，保持比例 |
| **高度铺满** | 媒体高度填满屏幕，宽度自适应 |
| **宽度铺满** | 媒体宽度填满屏幕，高度自适应 |
| **裁剪** | 媒体铺满屏幕，可通过裁剪框选择显示区域 |

#### 视频播放

- **播放/暂停**: 控制视频播放状态
- **进度条**: 拖动调整播放进度
- **音量**: 调整音量大小

### 2.6 画面裁剪

1. 选择 **"裁剪"** 填充模式
2. 在预览区域拖动裁剪框调整位置
3. 拖动裁剪框四角调整大小（等比缩放）
4. 点击旋转按钮预览旋转效果
5. 点击 **"重置裁剪"** 恢复默认

**注意**: 裁剪框比例与显示端屏幕比例一致，只能等比缩放。

## 3. 显示端使用

显示端语音会话的详细使用说明见：[语音三种会话状态](usage/voice-conversation.md)。

Windows Node 子显示端的系统级语音转文字输入说明也见：[Windows 子显示端语音转文字输入](usage/voice-conversation.md#八windows-子显示端语音转文字输入)。

正式 Android 显示端的 OCR/YOLO11n 通过控制端任务面板调用；任务会请求服务器视觉接口，再由服务器转发给显示端本地推理。

本地 LLM 网关的外部模型名映射可在控制端“任务列表”中找到“本地 LLM 网关”任务，点击“默认映射”打开面板。每行填写外部客户端使用的模型名，并选择服务端模型清单中的内部模型；保存后，网关会在请求入口自动完成映射。空行、重复外部模型名或不存在的内部模型不会保存。

### 任务 URL 路由

任务服务可以在 `context.registerRoute()` 中注册 URL，路由统一由运行 AASC 的设备通过 `8081` 接收，不需要任务或网页自己监听新端口。服务端任务直接处理请求；显示端/子显示端任务通过已有 WebSocket 收到 `task:route_request`，再以 `task:route_response` 返回结果。停止、重启、异常和显示端断开都会清理对应实例的路由。

因此，同一个 `llm-server` 或其他任务可以分别运行在不同设备上，每台设备使用自己的 `8081`；同一设备内相同的 HTTP 方法和路径不能被多个任务实例同时占用。当前不提供跨设备统一负载均衡，也不新增独立的 HTTP 配置保存接口。

普通正式 APK 的 ASR、TTS、声纹、RapidOCR、YOLO 和降噪模型均按需从服务器下载并缓存在 APK 私有目录，安装包不携带模型；服务器模型清单和准备命令见：[正式 Android 统一模型分发](design/android-model-distribution.md)。需要完整离线包时运行下面的独立命令，模型会从 `res/models` 按固定白名单打入 APK：

### 独立 ASR 测试 APK 的 Sherpa 声纹测试

独立测试 APK 位于 `3rd/tts-server/android-asr`，构建并安装 Debug APK：

```bash
npm --prefix 3rd/tts-server run build:android-asr
adb install -r 3rd/tts-server/android-asr/app/build/outputs/apk/debug/app-debug.apk
```

当前测试 APK 暂时只内置 `ERes2Net-base FP32` 声纹模型和多人分段所需的 Pyannote 模型，不包含 large、V2 或 INT8 声纹 embedding 模型。

打开 APK 后先录音或选择 WAV。普通 ASR 的“ASR 文字降噪”只影响文字识别；Sherpa 区域的“声纹降噪”只影响声纹注册、分段和匹配。输入名称后点击“注册当前音频声纹”，再使用单段、多段或快速多段测试；多人测试可选择自动估计或 1-5 人。结果区域会显示 ASR 文本、匹配名称、相似度、阈值、阶段耗时，以及每个分段的 speaker、相似度、文字和错误。

声纹注册库只保存在 APK 进程内存中，重启 APK 后需要重新注册。APK 内置网页与原生页面共用当前进程的声纹协调器和注册库；网页入口仍可通过 APK 显示的 HTTPS 地址访问。

### APK 内置 Node.js 子服务器

`apk-display` 启动后会在前台 Service 中启动 `server-launcher.js`，再由 launcher 启动 `server-app.js`。首次连接时填写主服务器根地址，例如 `https://192.168.1.39:8081`；WebView 继续打开主服务器 `/display`，内置 Node 子服务器主动连接主服务器 `/server`。

APK 构建默认使用项目内 `3rd/android-node-runtime/arm64-v8a` 的 Android Node Runtime；只需准备独立服务器运行包：

```bash
export AASC_ANDROID_NODE_PACKAGE_DIR="$PWD/.local/android-node-package"
npm run build:apk
```

项目内 Runtime 包含可执行 `node` 及其动态库；如需使用其他 Runtime，可通过 `AASC_ANDROID_NODE_RUNTIME_DIR` 覆盖。构建脚本会在生成 APK 前校验这些依赖，并生成 SHA-256 manifest 打入 APK，不会复制仓库日志、模型、用户媒体或其他 `3rd` 内容。APK 节点首版仅启用媒体库、显示网关和热更新，不启动 ASR、Puppeteer、外部 CLI 或 Agent 子进程。

HTTPS 开发证书会同时绑定到主服务器和 APK；如果更换主服务器证书或访问地址，必须确保新证书 SAN 覆盖访问地址，并重新构建 APK。APK 只会信任系统/用户证书以及构建时绑定的主服务器证书。

### 正式显示端完整离线 APK

离线 APK 使用独立应用 ID `com.aasc.display.offline`，文件名为 `aasc-display-offline.apk`，安装后默认启动本机 `https://127.0.0.1:8081/display`。构建默认使用项目内 Android Node Runtime，只需准备生产服务器运行包：

```bash
export AASC_ANDROID_NODE_PACKAGE_DIR="$PWD/.local/android-node-package"
npm run build:apk:offline
```

如果发布包目录还没有生产依赖，先在该目录执行一次：

```bash
npm ci --omit=dev --ignore-scripts --prefix "$AASC_ANDROID_NODE_PACKAGE_DIR"
```

离线 APK 可显式启动到第二显示屏（例如 Android 虚拟 Desktop display 2）：

```bash
adb -s <设备序列号> shell am start --display 2 --windowingMode 1 \
  -n com.aasc.display.offline/com.aasc.display.MainActivity
```

真机验收时，ASR 可上传 `res/models/sensevoice/test_wavs/你好，小爱.wav` 验证原生识别；TTS 可调用 `/api/tts/generate` 后检查返回的 `audio/wav`，再发送控制端 `tts` 播放消息验证播放结束事件。

当前离线包内置正式运行集约 949.3 MiB 模型（含默认的 `qwen3.5-0.8b-claude-opus-distilled-mnn`、SenseVoice、streaming Zipformer、声纹 base FP32 + pyannote、GTCRN、嵌入式 TTS、RapidOCR 和 YOLO11n）。offline APK 首次启动无历史选择时会直接从 APK 安装目录加载该 Qwen 模型，不复制到在线模型 active 目录。显示页右上角的“控制端”按钮可弹出或隐藏同源控制端页面；普通 APK 不受此构建命令影响。

Android 9/API 28 设备首次启动 APK 时，会弹出“照片、媒体内容和文件”共享存储授权框。选择允许后，APK 内置 Node 子服务器即可按媒体库配置访问 `/storage/emulated/0/` 及其子目录，例如：

```text
/storage/emulated/0/Download
/storage/emulated/0/DCIM
```

媒体库的 `path` 仍通过控制端的本地媒体库配置设置；上传、创建目录和删除操作受媒体库 `readonly` 设置保护。拒绝授权不会阻塞显示端连接，但共享存储媒体库会返回权限错误。当前实现只保证 Android 9/API 28，Android 10+ 的整个共享存储访问不在本功能范围内。

### Offline 热更源与资源同步

Offline APK 会按顺序尝试家庭内网、公司内网和外网热更源：

```text
http://192.168.1.39/mnt/aasc-offline/
http://10.221.70.87/mnt/aasc-offline/
http://c.aasc.us/mnt/aasc-offline/
```

发布器的上传目标不随热更读取源增加而改变：本机默认写入 `/mnt/aasc-offline`，外网通过 SCP 写入
`as@120.79.245.103:~/a/aasc-offline`。如果本机热更目录不同，发布时使用 `--local-root` 指定。

从外网资源包同步到本机时执行：

```powershell
npm run sync:offline-update -- --skip-signature-verification --source-url "http://120.79.245.103/mnt/" --local-root "D:\Program Files\nginx-1.29.5\html\mnt"
```

父目录模式下，`--local-root` 也可通过 `AASC_OFFLINE_LOCAL_ROOT` 指定，`--source-url` 指向远端父目录。服务更新清单从远端 `aasc-offline/` 读取，写入本地 `aasc-offline/`；远端 `mmd/` 目录树同步到本地同级 `mmd/`。上例的目标路径为
`D:\Program Files\nginx-1.29.5\html\mnt\aasc-offline` 和
`D:\Program Files\nginx-1.29.5\html\mnt\mmd`。传统直接指向 `/aasc-offline/` 的 `--source-url` 仍只同步服务更新。

Offline 更新同步会验签并校验 code、dependencies、min APK 和 data-repair 资源，完整 Offline APK 不参与同步；同版本 hash 冲突会中止且不替换清单。
同步时会显示当前资源文件名、单文件传输字节和百分比，以及全部资源的整体下载进度；日志模式会节流输出。
同步前会检查目标目录中的同版本文件；文件大小和 SHA-256 都匹配时直接复用并跳过下载。发现同版本文件内容冲突会在发起下载前报错。

MMD 同步会递归读取 `/mmd/` 下的同源目录索引，显示文件名和总进度；只替换远端列出的文件，不删除本地额外文件。`.offline-mmd-sync-state.json` 保存远端文件元数据和本地 SHA-256，远端 ETag/Last-Modified 与大小未变、本地 hash 也匹配时会跳过重复下载。

如果本机没有清单公钥，可显式添加 `--skip-signature-verification` 跳过本地 RSA 验签。此时命令会提示清单来源未经认证；大小和 SHA-256 只校验下载文件是否符合该清单，不能证明清单可信。清单结构、资源路径、资源白名单和哈希校验仍会执行，Android 客户端仍强制验签。

普通聊天 Agent 后端的配置和会话规则见：[普通聊天 Agent 后端](usage/llm-agent.md)。

### 3.4 Android 显示端时间同步

当 Android 显示端时间明显不正确时，可以通过 ADB 将其同步为主机当前时间。先确认设备已连接：

```bash
adb devices
```

关闭自动校时后，使用 Android AlarmManager 设置主机时间（`date -s` 在普通 ADB shell 下可能没有设置系统时间的权限）：

```bash
adb -s <设备序列号> shell settings put global auto_time 0
host_millis=$(date +%s%3N)
adb -s <设备序列号> shell cmd alarm set-time "$host_millis"
```

同步后检查 Android 时间和时区：

```bash
adb -s <设备序列号> shell date
adb -s <设备序列号> shell date +%s
adb -s <设备序列号> shell getprop persist.sys.timezone
```

应确保 Android 与主机处于同一时区（例如 `Asia/Shanghai`），并且两端 Unix 时间戳相差不超过几秒。

### 3.5 MMD/VRM 角色与灯光

独立 MMD AR 对比测试可直接用手机浏览器打开 <https://c.aasc.us/mnt/mmd-ar/>，无需安装测试 APK 或连接 AASC 服务。先点击“定位”拍摄并保存一张纹理清晰的基准图，再选择当前 JS 或 MindAR 跟踪器开始测试；首次使用时允许浏览器访问摄像头。网页与旧 APK 的定位图保存在不同浏览器 origin 下，需重新校准。

网页初次加载 PMX 时会显示分阶段百分比和进度条。该百分比包含 PMX、纹理、VMD 和模型初始化的阶段权重，100% 表示模型已可显示，不表示单个文件下载结束。

在 HTTPS 测试页转动手机或调整浏览器窗口时，MMD 画布会跟随新尺寸。正式显示端和测试网页都可在“灯光”标题后查看当前实际渲染分辨率（Canvas 宽×高像素）；它可能因最多 2 倍的渲染像素比限制而小于屏幕标称物理分辨率。

显示端打开“角色”并等待模型加载后，可点击右上角“定位”。点击“拍照校准”会打开独立弹窗：先在实时画面中拍照，再在同一位置拖动四个角点选择细节丰富的基准图区域，最后保存。选择定位图并点击“开始定位”后，摄像头画面显示在角色下方；识别到基准图时，角色脚底会跟随基准图中心。点击“停止定位”释放摄像头并恢复普通角色布局。自然图片应有文字或明显纹理；低光、反光、遮挡和快速转动可能使定位暂时丢失。若持续显示“查找中”，根据提示增加光线、靠近并摆正基准图，或保持镜头平稳。图片保存在当前显示端浏览器本地，不上传服务端。

定位中的摄像头画面只覆盖媒体内容；语音状态、任务状态、角色和聊天界面显示在它上方。

控制端可在对应显示端的“设备能力”中开启或关闭“摄像头采集”。关闭后该显示端会立即停止摄像头拍照、预览和图片定位，不再读取视频设备；设置按显示端保存，重连后自动恢复。麦克风录音开关独立生效。

“PMX Toon 明暗”默认关闭，主光和补光使用普通的法线朝向计算：背向某盏灯的表面不会接受该灯的直射光；补光若从另一面照入，仍可照亮该面。开启开关可恢复模型原有的卡通明暗。此设置仅作用于 PMX，沿用灯光面板的本地保存；之前明确保存的开启状态会保留，点击“恢复默认”会关闭 Toon。它不是 ACES 色调映射开关，不影响 VRM、环境光、角色阴影或 AO。

“灯光”面板提供独立补光开关、颜色、强度（0–5）和方向（经度/纬度）。补光默认关闭，开启后可照亮角色暗面，但始终不投射阴影；主光的角色阴影开关保持独立。设置保存在当前浏览器，点击“恢复默认”会关闭补光。

面板还提供“PMX 边缘光 1/2”，两组均默认关闭，各自可设置颜色、强度（0–5）和方向。启用后只在对应方向的角色轮廓叠加颜色，不会像补光那样照亮正面，也不投射阴影。两组可同时使用，恢复默认时一起关闭；VRM 不受影响。

聊天面板关闭、角色画布可交互时，可从角色身上或旁边空白处拖动旋转角色；按在角色上但只轻点并松开时才触发角色触摸。移动达到 8 像素后按拖动处理，松开不再触发触摸。

显示端打开“角色”后，点击右上角“灯光”可调整环境光、主光和角色阴影。PMX 角色还有默认开启的“PMX 环境遮蔽 AO”开关：开启后衣服、头发和身体相邻处会有更明显的接触暗部，关闭可减轻图形设备负担。开关下方可调整 AO 颜色（默认 `#931231`）、强度（`0–2`，默认 `0.6`）及半径（角色高度的 `1–20%`，默认 `6%`）；颗粒噪点由保边模糊减轻，半径过大仍可能使暗部过宽。PMX 角色还可设置“PMX 物理频率”，范围为 30–90 Hz，默认 65 Hz；频率是物理目标步进值，实际计算还受页面帧率及每帧最多 3 个物理子步限制，调高频率会增加计算量。“旋转暂停物理阈值”默认为 720°/秒，可在 30–1440°/秒调节；角色旋转速度超过该值时，布料物理暂时停止，减速后重新贴合当前姿态并恢复。上述设置立即应用并保存在当前浏览器，刷新页面后恢复；此前保存的自定义阈值继续生效，点击“恢复默认”可改用 720°/秒。VRM 角色不使用 PMX AO、物理频率或旋转阈值。

已有浏览器保存的 AO 自定义值不会被新默认值覆盖；要使用这组新参数，请在“灯光”面板点“恢复默认”。

AO 分辨率可在“半分辨率（默认）”与“全分辨率”间切换，修改后立即生效并保存。半分辨率最多为绘制像素的一半、且不超过 `1280×720`；全分辨率使用当前显示缓冲区的完整像素，可能改善细节，但高分屏会明显增加 GPU 占用。画面或触控变慢时切回半分辨率。此设置仅用于 PMX，不影响 VRM。

PMX 模型自带的材质“环境色”会被显示端始终忽略；它不随灯光滑块恢复。将环境光和主光强度都设为 `0` 时，当前无其他发光来源的 PMX 人物应呈黑色。VRM 材质不受此规则影响。

## 4. 使用场景

### 4.1 单屏展示

1. 在显示设备上打开显示端页面
2. 在控制设备上打开控制端页面
3. 选择显示端，发送媒体

### 4.2 多屏同步

1. 在多个显示设备上打开显示端页面
2. 在控制端选择不同的显示端
3. 分别发送媒体到各个显示端

### 4.3 投屏演示

1. 将显示端页面投屏到大屏幕
2. 使用控制端控制媒体播放
3. 实时调整画面效果

## 5. 常见问题

### Q: 显示端列表为空？

**A**: 确保：
- 显示端页面已打开
- 显示端与控制端连接到同一服务器
- 网络连接正常

### Q: 视频无法自动播放？

**A**: 浏览器安全策略可能阻止自动播放，点击视频区域或按空格键手动播放。

### Q: 裁剪框位置不对？

**A**: 
- 确保显示端已正确连接
- 检查显示端屏幕尺寸是否正确显示
- 尝试重置裁剪

### Q: 文件上传失败？

**A**: 检查：
- 文件大小是否超过限制
- 服务器磁盘空间是否充足
- uploads 目录是否有写入权限

## 6. 网络配置

### 6.1 局域网访问

服务器默认监听 `0.0.0.0`，可从局域网任意设备访问：

```
http://<服务器IP>:8081/control
http://<服务器IP>:8081/display
```

### 6.2 端口配置

通过环境变量修改端口：

```bash
PORT=3000 npm start
```

### 6.3 防火墙

确保防火墙开放服务器端口（默认 8081）。
