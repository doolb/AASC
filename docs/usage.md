# Web MediaCenter - 使用说明

## 正式显示端 TTS 口型（2026-10-10，源码已接入，待正式服务包发布）

「动作 → 口型」默认勾选「同步 TTS 口型」。本机聊天、文本朗读及本机接收的远程文本语音，都会按音频实际播放进度驱动PMX嘴型；无需打开动作面板。暂停、缓冲和拖动时闭嘴，继续播放后从当前位置接续，结束或中断恢复原表情。VMD/MPL动作同时运行，不重置物理。

沿用中文拼音五元音映射，字音节奏按文本估算并缩放到音频时长，尚无TTS逐字/音素时间戳。常见MMD嘴型自动识别，也可手工设置「嘴型映射」；无可用嘴型时只播放语音。口型准备失败、文本超限不会停止音频。后台释放口型，回前台若仍在播则继续。

保留无声文字预览，最多400字符；TTS当前句最多4000字符/16KiB，超限跳过口型。关闭同步开关可在语音播放时手动预览，该开关只影响本页，刷新恢复开启。「停止口型」只停止当前句口型，语音继续；下一句自动同步。当前模型可通过 `DisplayMmd.setLipSyncExpressions(token, [[index, weight]])` 设置临时权重，传空数组释放；token来自getManualExpressions，换模型需重新读取。

固定拼音ESM资源随正式代码包分发，缺失时执行 `npm run prepare:mmd-lipsync`。首次预览或TTS口型时才加载字典，不上传文字、不新增npm生产依赖。正式包尚未构建发布。

## 独立MMD-AR文字口型预览（2026-10-10，已发布外网）

打开「动作 → 口型」，输入内容，点击「播放口型」。角色原有VMD/MPL动作照常运行；「停止口型」只释放嘴部临时覆盖，恢复当前动作和手动表情，不切换动作、不重置物理。

当前为不发声的估算节奏预览：中文按拼音、数字逐位中文读音驱动A/I/U/E/O，标点处闭嘴停顿；不是TTS音素同步。可输入最多400字符。常见MMD嘴型自动识别，名称非标准时展开「嘴型映射」手工选择；缺失的元音使用其他已映射嘴型近似。拉丁文字按拼写元音近似，效果不等同英语发音。

首次点击播放才加载本地拼音字典，内容不上传、不调用LLM/TTS或麦克风。进入后台、切换模型/物理重载或编辑会停止预览。若构建缓存缺失，可运行 `npm run prepare:mmd-ar-lipsync` 准备固定版本字典；不需要安装新的生产依赖。

## 正式显示端 MPL（2026-10-10，源码已接入，待正式包发布）

正式显示端「动作 → MPL 动作」可粘贴已生成的MPL，也可点击「填入动作＋表情示例」或「填入表情示例」。首次PMX就绪会自动填入混合示例，不自动播放；点击「编译并播放」后才加载本地WASM，在Worker生成同一份骨骼/表情VMD。支持取消编译、停止并恢复原动作与播放开关、下载VMD。无需网页调用LLM或上传代码。

表情语句为 `morph "PMX原始表情名" 0.8;`，写在pose中单独一行；名称来自「表情」分类，保留空格和全半角字符。手动表情选择优先，取消覆盖后才能看到同名MPL表情。骨骼语法需要标准MMD骨骼，纯表情无需标准骨骼。播放会替换当前动作，沿用模型的循环/单次模式；循环保持物理连续，显式换动作/换模型仍初始化。

固定编译器资源已准备于正式 `js/vendor/mmd-mpl/0.3.6-2d3b1c7e3429/`，缺失时执行 `npm run prepare:mmd-mpl`，JS/WASM/LICENSE/SOURCE.json应一起进入代码包。输入64KiB、输出8MiB、编译超时30秒；错误不覆盖新选择。TTS口型已另行接入源码，详见本页「正式显示端 TTS 口型」，待正式包发布。

## 正式显示端表情控制（2026-10-10，源码已接入，待正式包发布）

在正式显示端点击「动作」，展开「表情」。按当前PMX自动分眉毛、眼睛、嘴型和其他，点击启用/取消，滑条分别调强度，可叠加多项。清除恢复当前VMD表情；不支持的Morph禁用。换动作保留手动选择，同模型物理重载保留，换模型清空。

供后续口型控制的页面接口：

```javascript
const state = window.DisplayMmd.getManualExpressions();
const mouth = state.items.find(item => item.supported && item.panel === 3 && item.name === 'あ');
if (state.ready && mouth) {
    window.DisplayMmd.setManualExpression(mouth.index, 0.6); // 启用当前模型对应的嘴型
    window.DisplayMmd.setManualExpression(mouth.index, null); // 释放覆盖，恢复动作
}
// window.DisplayMmd.clearManualExpressions(); // 清除全部手动覆盖
```

表情名称/索引来自当前模型，换模型后应重新读取；0是主动覆盖为闭合/零权重，null是释放。以上示例的「あ」仅用于有该Morph的模型，不是所有模型的固定嘴型名称。后续已接入按文本与音频进度同步的TTS临时覆盖，见本页「正式显示端 TTS 口型」；仍不使用音素时间戳。

## MMD-AR TAA / FSR2抗锯齿与Canvas渲染倍率（2026-10-09）

本地独立网页已修正FSR2轮廓扩张：重建保留前景/背景覆盖比例，比例1不会用相邻前景替代背景中心。请在最新构建下比较斜边；真实GPU静态对照已验证，手机动态画面仍需复测。既有TAA和FSR2比例设置保留，外网/APK以实际发布版本为准。

独立测试页“灯光→抗锯齿”保留抗锯齿总开关，新增“TAA / FSR2”方式选择；总开关默认关闭，方式默认TAA。TAA保留现有历史颜色/相机与深度重投影、累积强度默认0.90（0–0.95）。FSR2选项采用普通WebGL2 Shader时域升采样近似，内部渲染比例默认0.67，可调0.50–1.00；`canvasScale`仍控制最终画布尺寸。该实现不接AMD官方FSR2 SDK，不生成/读取物体运动矢量，仍利用相机矩阵与深度历史。FSR2最终输出另有轻量对比度边缘滤波以缓和静态轮廓锯齿/跨帧爬行；该滤波只作用于FSR2，不改TAA历史或内部比例，可能轻微软化细线并增加少量全分辨率采样。快速头发、衣服或角色运动仍可能出现残影、闪烁或保守回退当前帧；可切回TAA、降低历史强度/缩放比例或关闭抗锯齿。接触阴影启用时间采样，SSGI保留有效历史，PNG导出维持目标尺寸与透明合成语义。

同一分类可调“抖动强度”0–2（步长0.05、默认1）与“抖动周期”4/8/16/32帧（默认8）。强度1保持原幅度，0取消空间偏移但仍累积历史；较大强度可能使画面变软。周期是跨帧采样位置的循环长度，每帧仍只绘制一次场景。两项本地保存、刷新恢复，灯光复位回1/8；改值清TAA/SSGI历史，不改变角色位置、相机距离或Canvas倍率。两种抗锯齿模式均不使用物体运动矢量。

面板顶部实际分辨率旁可调Canvas渲染倍率0.25–2，步长0.25、默认1，倍率相对自动DPR（上限2）。DPR2时0.5倍对应CSS像素尺寸，1倍保持原尺寸，2倍像素约增至四倍；设备尺寸上限会限制实际大小并提示。调整即时生效、本地保存、刷新恢复，灯光复位恢复TAA关闭/倍率1。修改倍率或后台返回保留角色和相机变换。

TAA/FSR2需要WebGL2；不支持时禁用抗锯齿控件，倍率仍可使用。增加倍率、历史目标与升采样会增加GPU/显存成本，FSR2近似模式是否提速取决于设备与场景，手机需要实机验收。本次只更新本地独立网页构建，外网和APK以实际发布版本为准。

## MMD AR刚体迎风面积与风速换算（2026-10-02，当前独立测试实现）

Ammo和刚体XPBD复用web-physics-wind.mjs数值计算。经纬度是世界风来源，气流方向取其相反方向；模型旋转不旋转世界风。每个刚体按姿态把相对气流单位方向转换到自己的局部坐标，再取PMX碰撞代理迎风投影面积，而不是骨骼点或骨骼连线面积。

- 球：A=πr²，各方向相同。
- 盒：A=4×(height×depth×|nx|+width×depth×|ny|+width×height×|nz|)，PMX三尺寸是半长；三个面按迎风投影叠加，薄盒正面强、侧面弱。
- 胶囊：A=πr²+2×r×height×sqrt(max(0,1−ny²))，height为两球心间距、胶囊长轴为局部Y；沿长轴吹较小，横向吹较大。

当前没有独立风速滑块，风力强度S经过0.3秒缓动、按模拟时间/世界位置连续阵风调制后，换成有效风速sqrt(20×S)。稳定恒风无阵风时，S=0.3/1/10/30对应2.45/4.47/14.14/24.49模型单位/秒；没有标定成m/s。强度加倍使风速约乘sqrt(2)，不能理解为风速加倍。阵风改变局部速度大小，既有方向保持。

相对气流U=气流速度−受力点速度；自由type1及无骨骼位置驱动的type2在COM受力，只用COM线速度。位置驱动type2额外取角速度×真实偏移的点速度。基础阻力向量F0=0.5×A×|U|×U；同向跟随时减小、逆风时增大、同速时为0，超过气流速度后阻力反向。实际提交原求解器的力还乘1/(1+h×有效逆质量×0.5×A×|U|)，按子步稳定衰减。

受控type2不移动位置，风矩为真实偏移×稳定阻力，局部各轴按惯量×12rad/s²限幅。自由体通过现有关节产生摆动；type0不直接受风。当前属于碰撞体空气阻力近似，不含真实布料表面、挡风或升力。本轮只核对并更新说明，没有修改运行代码。

## MMD AR风吹衣服摆动的模拟路径（2026-10-02）

当前PMX刚体路径通过风力/力矩推动动态刚体，关节限制其运动，物理结果回写布料骨骼，再由蒙皮使衣服网格变形。衣服需要对应的可活动骨骼、刚体和关节；仅跟随骨骼的type0或全锁约束不会因加大风而自动变软，位置驱动type2主要通过旋转表现摆动。

进一步可改进的真实网格受风模型（尚未实现）：把骨骼关联的衣服区域视为布料片，估计面积/朝向，使用相对气流速度（风速减布料局部速度）和迎风面积计算近似气动力，力的量级可采用0.5×空气密度×阻力系数×迎风面积×相对风速平方；这是参考阻力方程的近似，需要统一模型长度/速度单位，现有0–30参数仍是效果等级。按受力位置将力和力矩分配给现有刚体，保留PMX根部锚定/关节限位，以阻尼抑制高频抖动，使用连续阵风和空间差异产生起伏，最后叠加沿风向的挡风比例。布料片朝向应来自对应表面几何，不能把任意骨骼局部轴直接当表面法线。

独立测试Ammo/刚体XPBD已按碰撞代理面积和相对气流施加阻力；顶点布料按真实三角面积和表面朝向施力，本次未改动，仍缺少相对风速与挡风。顶点布料直接更新自由粒子及网格，不依靠少量刚体表现褶皱。当前可用物理、风方向/强度/阵风控件观察已有布料链摆动；更细的小褶皱需更密的物理控制或独立网格布料求解，不能仅靠少量PMX刚体获得。参考：[NASA阻力方程](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/drag-equation/)。本次刚体受风实现见上节；此处说明网格与刚体路径的区别。


## MMD AR风力与挡风的当前行为（2026-10-02）

## XPBD相同风力下不同布料的响应差异（2026-10-01）

Ammo使用同样的风力系数10：自由刚体F=质量×10×当前风强度，type2近似风矩同样使用最长1单位力臂与局部各轴12rad/s²限幅。Ammo与XPBD没有额外的风力倍率差；相同设置下表现仍会受各自关节/接触求解及惯量计算差异影响。

XPBD子步数可以手动比较3/5/10/15/20，观察同模型动作下的关节误差和物理耗时。默认45沿用原Ammo纠错基准数值，尚未经过手机性能调优；60FPS下10/20/45分别为每秒600/1200/2700个完整子步，每步重新检测碰撞并求解关节和接触。实际步长为帧间隔/N，掉帧会使子步变长；多加子步不保证解决接触或模型参数问题，需同条件实测。

Ten Minute Physics源码默认值（2026-10-01核对）：[第22节刚体](https://matthias-research.github.io/pages/tenMinutePhysics/22-rigidBodies.html)为10子步，默认整步0.02秒，子步0.002秒；[第25节关节](https://matthias-research.github.io/pages/tenMinutePhysics/25-joints.html)为20子步，整步0.03333秒，子步约1/600秒；[第14节布料](https://matthias-research.github.io/pages/tenMinutePhysics/14-cloth.html)为15子步，整步1/60秒，子步1/900秒。不能只比较子步数量：当前接入在60FPS下10子步也约1/600秒，与第25节默认子步时长接近；这只是步长对照，不代表物理实现/效果相同。

与Ammo步数比较：Ammo当前默认物理90Hz，以累计余量执行固定步长，在稳定60FPS下平均每帧1.5个完整物理步（通常交替1/2步）；XPBD设10/45时每帧各执行10/45个完整子步，即每秒600/2700步，完整步次数约为Ammo的6.7/30倍。该比例不是耗时比例：XPBD每子步一轮位置及速度求解，Ammo每步内部还会迭代求解约束；[Bullet源码](https://github.com/bulletphysics/bullet3/blob/master/src/BulletDynamics/ConstraintSolver/btContactSolverInfo.h)默认迭代上限为10，当前没有读取本地Ammo构建实际配置，不能直接认定实际每步恰好10轮。XPBD每子步重新检测碰撞是当前明确的额外开销，真实耗时仍看面板同条件对照。

XPBD复用已有PMX球/胶囊/盒刚体、质量、阻尼、六轴位移/角度限制、弹簧与碰撞分组，再回写原骨骼；不需要修改模型，也不是逐顶点的布料模拟。平移/旋转弹簧刚度分别换算为柔度1/k，0不启用该轴弹簧；硬限位仍生效。骨骼密度和蒙皮不变，不能凭空产生更细的布料褶皱。XPBD与Ammo手感不保证一致。

基准控件范围为3–180、步长1，保留默认45及已有保存值。Ammo下显示“纠错基准Hz”，继续控制ERP；XPBD下同一控件显示“每帧子步数”，值10就是每帧10个子步，常规位置/速度每子步1轮，自写XPBD另补旋转锁轴纠正，步长为有效帧间隔÷子步数（如60FPS时10子步约1/600秒）。XPBD暂不使用“物理Hz”，滑条禁用但保留原值，切回Ammo恢复。风继续适用。“布料计算”下方显示当前求解器、刚体数量、XPBD当前子步数/每子步1轮及帧物理耗时（包含当前画面帧的物理子步及骨骼回写，不是总帧耗时或公平性能基准）；可在同模型/动作/频率/风/诊断开关下进行现场对照。

自写XPBD已补位置静摩擦、两侧平均摩擦/反弹系数与合成速度纠正，一阶姿态积分/回算、逐刚体0.5rad限角和阻尼/驱动顺序。胶囊侧面平行支撑最多两个解析点，保留解析碰撞、SAP和对象池。设置为3–180子步、默认45、常规每步一轮，并补一次旋转锁轴硬投影，没有新增控件。本地web-dist已同步，实际精度、稳定性和耗时待现场观察。

XPBD已补关节硬限位速度约束：锁定轴消除相对速度，范围限位只限制继续越界的速度，区间内弹簧运动继续保留。静止接触允许随形状大小缩放的极小穿透容差，速度接触响应已优化；低速恢复系数被抑制，用于减少反复推出和回弹。未新增参数，实际抖动改善仍需在同模型、动作及子步数下观察。

XPBD包含刚体形状之间的离散碰撞和摩擦/反弹，遵守分组/掩码及关节相连禁碰；没有连续碰撞检测，极快运动可能穿透。仅支持PMX Spring 6DOF关节，球/胶囊/盒子之间的接触诊断及刚体显示均接入新求解器。已有网页和APK共同构建流程已接入，本轮仅生成本地web-dist；未重新打包APK、发布或提交。手机效果/性能待验收，本轮未运行或新增自动测试。

## MMD AR骨骼小球遮挡（2026-10-01）

在独立测试页“动作 → 骨骼”开启“显示骨骼（小球）”，可切换“小球相互遮挡”。默认关闭；开启后离相机近的小球挡住后方小球，小球仍透过角色显示。设置即时生效、本地保存，刷新或换模型继续使用，AO及法线预览不改变小球之间的遮挡规则。

“遮挡处不透明度”默认50%：被角色挡住的球面半透明，露在角色外的部分保持不透明。0%隐藏被挡住的部分，100%保持完整不透明；设置独立于小球相互遮挡，自动保存。此诊断会在需要时额外绘制角色深度，开启球间遮挡另有球深度预绘，实际手机帧率待验收。

此开关只控制小球像素，名称、选中轴和轻点选择保留现有诊断行为；“隐藏角色”仍会同时隐藏小球。本地web-dist已同步，未重新打包APK或发布外网。

## MMD AR补光沿用主光阴影（2026-10-01）

独立测试页选择“补光沿用主光阴影”时，补光同时继承主光的几何遮挡与背光区域。“灯光→补光”可设置过渡起点/终点（-1至1，默认-0.3/0.3）：起点以下淡出为0，终点以上完整保留主光阴影可见度，之间平滑过渡；负值让补光延伸到略背光位置。默认点积0保留一半补光，以减缓强补光下的硬折线。范围自动保存、即时生效，灯光“恢复默认”回-0.3/0.3；交叉调整时另一端自动推开0.01。开启主光阴影时生效，关闭主光阴影沿用原无继承回退；其他补光模式按原方式工作。本地web-dist已同步，未打包APK或发布。

背光区域通过片元法线与主光方向的点积判断，二者处于同一视图坐标系；不是屏幕空间深度/AO计算。几何遮挡仍来自主光阴影贴图。

## MMD AR主光阴影偏移（2026-10-01）

独立测试页“灯光 → 主光”提供“阴影深度偏移 bias”（-0.005–0.005，默认-0.0005）和“阴影法线偏移 normalBias”（0–0.1场景单位，默认0.02）。近距离条纹明显时，一次调一项：可先把bias试调至-0.001，再视画面尝试normalBias 0.03。偏移过大造成接触阴影脱离时应减小；滑块即时生效并保存，刷新恢复，灯光“恢复默认”回原来两值。

这两个控件只调整主光；补光沿用主光阴影的已有模式会复用主光结果，补光独立生成阴影时保持原参数。保持当前阴影贴图及光照强度。本地web-dist已同步，实际条纹改善待画面验收，本轮未重新打包APK或发布外网。额头半透明覆盖层的AO问题按用户要求暂不处理。

## MMD AR低模浅凹 AO 抑制（2026-10-01）

在独立测试页打开“灯光 → AO → 浅凹抑制”，范围0–45°、步长0.5°，默认10°。拉近相机后低模内凹折痕明显时，可逐步调高；数值越大，浅内凹的AO越弱，也会减弱真实浅凹槽的遮蔽。它调整采样方向高出当前表面的角度门限，不改变模型法线，也不是两个面的法线夹角。设置即时生效并自动保存，灯光“恢复默认”回到10°；半/全分辨率和半分辨率补算使用同一门限，法线预览不受影响。

本轮同步本地 `3rd/mmd-ar-test/web-dist`，未更新现有APK或发布外网。正式显示端未设置此测试参数时保留原AO门限；10°是可调整的起始值，实际模型近距离观感待手工验收。

独立 MMD AR 测试APK已同步网页全部功能并修复灯光面板；原生摄像头预览跟随手机横竖屏旋转，方向变化同步角色投影。本地目录/PMX/两类VMD、模拟输入、原生定位与标定见 [MMD AR 测试APK使用](usage/mmd-ar-native-slam.md)。

## TTS 内存音频下发（2026-09-30，待重启/发布后生效）

服务端仍发送音频URL，音频保存在进程内存，保留10分钟；缓存最多128MiB/1024条，单段最多16MiB，满额时新生成请求会报错。一个URL可供多个播放端在有效期内读取，过期或服务器重启后失效。128MiB只限制缓存，并非进程RSS上限。新音频不写tts_*.wav；启动前遗留WAV按过期规则汇总清理，清理完成后停止磁盘扫描。

控制端左侧“声纹”页向下滚动至“语音生成设备”卡片，新增“音频缓存上限 (MiB)”输入和“保存容量”按钮。默认128MiB，可填16–1024整数MiB；保存到服务端后立即生效，其他控制端同步，重连会恢复持久化值。首次部署新代码需重启服务端并刷新控制端；之后修改容量无需重启。降低上限保留有效音频，已占容量超过新上限时暂停接受新音频，直到旧音频过期。

Node子显示端下载/Buffer播放不再写audio_*.wav。Windows使用已有Windows PowerShell及SoundPlayer内存流，Linux需要已有aplay；macOS内存播放需要ffplay。无需新增npm依赖。部署此改动后需重启服务端和Node子显示端加载新代码；本轮尚未重启、发布或进行实际声音播放验收。

### 1.3 Node Offline min 跨平台服务器入口

`release/allserver-min.js` 可在 Windows 或 Linux 上用 Node.js 直接启动，不需要构建 Android APK。生产部署建议使用 Node.js 24 LTS；截至 2026-09-26，记录的推荐补丁版本为 `v24.21.0`。本开发机当前是 `v26.8.1`；入口会在 `--help` 中同时显示这两个版本。当前最低兼容版本为 `20.18.1`，但生产环境优先选择受支持的 LTS 版本。

Node Offline min 的配套下载资源统一放在 [外网 node-min 目录](http://120.79.245.103/mnt/node-min/)，包括 `allserver-min.js`、不内置 Node 的 `aasc-display-noserver.apk` 和内置 Node 的 `aasc-display-withserver.apk`；这些文件不在 `aasc-offline` 更新目录中。

目标机只需安装 Node.js（内含 npm），并能访问 Offline 更新源和 npm registry。将 `allserver-min.js` 单独复制到可写的数据根目录即可；若放在名为 `release/` 的子目录，则使用该子目录的上级作为数据根目录。启动器先从现有签名 `manifest.json` 下载独立的 `nodeMinSeeds` ZIP，补齐 `release/config`、`release/userconfig` 和 `release/task`，再下载 code ZIP 并使用其中的 `package.json` / `package-lock.json` 安装生产依赖；不需要预先拷贝源码或运行 `npm ci`：

```bash
node release/allserver-min.js
```

Linux 放置示例：

```bash
mkdir -p /opt/aasc/release
cp allserver-min.js /opt/aasc/release/
cd /opt/aasc
node release/allserver-min.js
```

也可以直接放在数据根目录运行：

```bash
mkdir -p /opt/aasc
cp allserver-min.js /opt/aasc/
cd /opt/aasc
node allserver-min.js
```

Windows PowerShell 放置示例：

```powershell
New-Item -ItemType Directory -Force C:\aasc\release
Copy-Item .\allserver-min.js C:\aasc\release\
Set-Location C:\aasc
node .\release\allserver-min.js
```

直接放在数据根目录时：

```powershell
New-Item -ItemType Directory -Force C:\aasc
Copy-Item .\allserver-min.js C:\aasc\
Set-Location C:\aasc
node .\allserver-min.js
```

首次安装与后续热更新都以各自 code ZIP 中的 package manifest 为准，在目标机为当前操作系统安装依赖；不下载 Android dependencies ZIP。种子 ZIP 由 Offline 签名 manifest 校验，解压后只补缺失文件，不覆盖已有配置和任务结果。服务以 release 模式读取上述三个目录；任务索引中标记为 `running` 的服务会按服务既有规则尝试恢复。更新器启动时检查一次，默认每 5 分钟轮询；可用 `--interval-ms 0` 关闭定时检查。若 npm registry 不可用，首次部署无法完成依赖安装；已有版本则继续运行。若服务端还是旧清单且目标目录没有初始数据，需要先发布包含 `nodeMinSeeds` 的更新清单。

更新 `release/config`、`release/userconfig` 或 `release/task` 的默认种子后，与代码包一起生成并发布独立 ZIP：

```bash
npm run build:offline-update -- --mode code-only --code-version <新版本>
npm run publish:offline-update -- --mode code-only --manifest-file <生成的manifest文件>
```

服务器保存 `node-min-seeds/node-min-seeds-v<版本>.zip`，清单发布时最后更新，启动器按签名清单下载。更新后的代码和种子缓存保存在 `updates/allserver-min/`；配置、用户配置和任务数据保存在项目根目录的 `release/`，模型、日志和上传数据继续使用项目根目录。`--root <目录>` 可指定项目根；`AASC_OFFLINE_UPDATE_BASE_URLS` 可用逗号分隔覆盖更新源，`AASC_NODE_MIN_UPDATE_INTERVAL_MS` 可配置默认轮询间隔。运行 `node release/allserver-min.js --help` 查看参数。

### 任务 URL 路由

任务服务可以在 `context.registerRoute()` 中注册 URL，路由统一由运行 AASC 的设备通过 `8081` 接收，不需要任务或网页自己监听新端口。服务端任务直接处理请求；显示端/子显示端任务通过已有 WebSocket 收到 `task:route_request`，再以 `task:route_response` 返回结果。停止、重启、异常和显示端断开都会清理对应实例的路由。

因此，同一个 `llm-server` 或其他任务可以分别运行在不同设备上，每台设备使用自己的 `8081`；同一设备内相同的 HTTP 方法和路径不能被多个任务实例同时占用。当前不提供跨设备统一负载均衡，也不新增独立的 HTTP 配置保存接口。

普通正式 APK 的 ASR、TTS、声纹、RapidOCR、YOLO 和降噪模型均按需从服务器下载并缓存在 APK 私有目录，安装包不携带模型；服务器模型清单和准备命令见：[正式 Android 统一模型分发](design/android-model-distribution.md)。需要完整离线包时运行下面的独立命令，模型会从 `res/models` 按固定白名单打入 APK：

### APK 内置 Node.js 子服务器

`apk-display` 启动后会在前台 Service 中启动 `server-launcher.js`，再由 launcher 启动 `server-app.js`。首次连接时填写主服务器根地址，例如 `https://192.168.1.39:8081`；WebView 继续打开主服务器 `/display`，内置 Node 子服务器主动连接主服务器 `/server`。

APK 构建默认使用项目内 `3rd/android-node-runtime/arm64-v8a` 的 Android Node Runtime；只需准备独立服务器运行包：

```bash
export AASC_ANDROID_NODE_PACKAGE_DIR="$PWD/.local/android-node-package"
npm run build:apk
```

项目内 Runtime 包含可执行 `node` 及其动态库；如需使用其他 Runtime，可通过 `AASC_ANDROID_NODE_RUNTIME_DIR` 覆盖。构建脚本会在生成 APK 前校验这些依赖，并生成 SHA-256 manifest 打入 APK，不会复制仓库日志、模型、用户媒体或其他 `3rd` 内容。APK 节点首版仅启用媒体库、显示网关和热更新，不启动 ASR、Puppeteer、外部 CLI 或 Agent 子进程。

HTTPS 开发证书会同时绑定到主服务器和 APK；如果更换主服务器证书或访问地址，必须确保新证书 SAN 覆盖访问地址，并重新构建 APK。APK 只会信任系统/用户证书以及构建时绑定的主服务器证书。

### Offline 热更源与资源同步

Offline APK 会按顺序尝试家庭内网、公司内网和外网热更源：

```text
http://192.168.1.39/mnt/aasc-offline/
http://10.221.70.87/mnt/aasc-offline/
http://c.aasc.us/mnt/aasc-offline/
```

发布器的上传目标不随热更读取源增加而改变：本机默认写入 `/mnt/aasc-offline`，外网通过 SCP 写入
`as@120.79.245.103:~/a/aasc-offline`。如果本机热更目录不同，发布时使用 `--local-root` 指定。

从外网资源包同步到本机时执行一次同步：

```powershell
npm run sync:offline-update -- --skip-signature-verification --source-url "http://120.79.245.103/mnt/" --local-root "D:\Program Files\nginx-1.29.5\html\mnt"
```

需要持续检查时，可显式指定正整数分钟间隔；省略 `--interval-minutes` 时默认为 10 分钟：

```powershell
npm run sync:offline-update -- --watch --interval-minutes 5 --skip-signature-verification --source-url "http://120.79.245.103/mnt/" --local-root "D:\Program Files\nginx-1.29.5\html\mnt"
```

watch 启动后立即执行首轮；每轮完整结束后等待指定分钟再开始下一轮，轮次串行执行。单轮失败会记录错误并在等待后继续；按 Ctrl+C 会取消等待并停止后续轮次，若当时正在同步则等当前轮安全结束后退出。不带 `--watch` 仍只同步一次；`--interval-minutes` 只能与 `--watch` 搭配。

父目录模式下，`--local-root` 也可通过 `AASC_OFFLINE_LOCAL_ROOT` 指定，`--source-url` 指向远端父目录。服务更新清单从远端 `aasc-offline/` 读取，写入本地 `aasc-offline/`；远端 `mmd/` 目录树同步到本地同级 `mmd/`。上例的目标路径为
`D:\Program Files\nginx-1.29.5\html\mnt\aasc-offline` 和
`D:\Program Files\nginx-1.29.5\html\mnt\mmd`。传统直接指向 `/aasc-offline/` 的 `--source-url` 仍只同步服务更新。

Offline 更新同步会验签并校验 code、dependencies、min APK 和 data-repair 资源，完整 Offline APK 不参与同步；同版本 hash 冲突会中止且不替换清单。
同步时会显示当前资源文件名、单文件传输字节和百分比，以及全部资源的整体下载进度；日志模式会节流输出。
同步前会检查目标目录中的同版本文件；文件大小和 SHA-256 都匹配时直接复用并跳过下载。发现同版本文件内容冲突会在发起下载前报错。

MMD 同步会递归读取 `/mmd/` 下的同源目录索引，显示文件名和总进度；只替换远端列出的文件，不删除本地额外文件。`.offline-mmd-sync-state.json` 保存远端文件元数据和本地 SHA-256，远端 ETag/Last-Modified 与大小未变、本地 hash 也匹配时会跳过重复下载。

如果本机没有清单公钥，可显式添加 `--skip-signature-verification` 跳过本地 RSA 验签。此时命令会提示清单来源未经认证；大小和 SHA-256 只校验下载文件是否符合该清单，不能证明清单可信。清单结构、资源路径、资源白名单和哈希校验仍会执行，Android 客户端仍强制验签。

普通聊天 Agent 后端的配置和会话规则见：[普通聊天 Agent 后端](usage/llm-agent.md)。

### 3.4 Android 显示端时间同步

当 Android 显示端时间明显不正确时，可以通过 ADB 将其同步为主机当前时间。先确认设备已连接：

```bash
adb devices
```

关闭自动校时后，使用 Android AlarmManager 设置主机时间（`date -s` 在普通 ADB shell 下可能没有设置系统时间的权限）：

```bash
adb -s <设备序列号> shell settings put global auto_time 0
host_millis=$(date +%s%3N)
adb -s <设备序列号> shell cmd alarm set-time "$host_millis"
```

同步后检查 Android 时间和时区：

```bash
adb -s <设备序列号> shell date
adb -s <设备序列号> shell date +%s
adb -s <设备序列号> shell getprop persist.sys.timezone
```

应确保 Android 与主机处于同一时区（例如 `Asia/Shanghai`），并且两端 Unix 时间戳相差不超过几秒。

本地重新生成测试网页前可运行 `npm run prepare:mmd-ar-vendor` 校验/补齐 A-Frame、MindAR 和官方 `.mind` 固定版本文件，再运行 `npm run build:web:mmd-ar-test`。生成的网页 AR 脚本和目标文件从站点同源加载，不再依赖 A-Frame/MindAR CDN；模型资源仍按既有来源准备。

独立测试网页的重力开关位于右上角“定位 → 重力旋转”分类左侧。首次有效姿态为零点，完整实时倾斜方向驱动角色锚点；“重力居中”重设零点，手动旋转角度保留。重力死区默认 0.5°，忽略相对上次接受目标的微小变化；重力缓动默认 20ms，控制到达完整目标的速度。两个参数设为 0 可分别关闭过滤，保存于当前浏览器，与相机跟随参数分开。外网以实际发布版本为准。

独立重力模式可在同一分类勾选“显示摄像头画面”，默认关闭，启用重力后可操作。单独使用时仅显示视频背景；图片定位同时运行时取消勾选只隐藏背景，不停止识别。校准预览独立显示；关闭重力/画面、后台和离开会释放独立流，回前台按开关恢复。视频沿用真实/模拟摄像头选择。灯光、定位、动作面板默认不透明度50%，之前手动保存值仍恢复；顶部固定测试提示已移除。本轮已生成本地web-dist，尚未发布外网。

独立测试网页的“动作 → 本地模型与动作”支持“选择模型目录”或“多选 PMX＋贴图”。目录选择保留相对路径；多文件选择需一次选中模型与全部贴图，且贴图名称能够唯一匹配。多个 PMX 需从下拉框明确选择。点“选择 VMD 动作”可给当前模型换动作；“恢复默认动作”只换动作，“恢复默认模型与动作”恢复内置米娅。动作开关开启且当前已有 VMD 时，新选本地模型自动沿用当前内置/本地动作，从头播放；关闭动作或当前无 VMD 时，新模型不自动带动作。物理与动作播放开关仍可用。缺失/歧义贴图和损坏动作会提示错误，并保留此前成功加载的内容。本地文件不上传、不持久化，刷新后需重新选择；手机目录/多选以浏览器实际支持为准，外网以实际发布版本为准。确认文件后底部和本地资源区显示读取、贴图、绑定姿态恢复与物理初始化阶段；读取显示可确定比例，未知阶段显示等待提示，成功100%后约1.5秒收起，失败保留原因，多PMX等待选择。完整操作见 `3rd/mmd-ar-test/README.md`。 换模型、手动切换 VMD 和恢复默认动作均先恢复模型绑定姿态（T Pose），从绑定姿态建立物理；原物理/播放关闭时保持关闭或暂停，不提前应用动作第 0 帧，初始化失败恢复旧动作。 新物理首次步进前清零线/角速度及残留力，自动循环重播不调用新增清理。 提交后的首个实际渲染帧只推进物理并隐藏初始化角色，下一帧才按当前动作开关播放；继承的本地动作引用保留，物理重载仍可读取。 切换成功释放旧Ammo物理，失败/过期释放暂存物理，避免切换累积；若已报`abort(OOM)`需刷新恢复，外网以实际发布版本为准。

独立测试网页“动作 → 物理”新增“启用风”，默认关闭。开启后可调风力强度0–30（默认0.3）、风向经度−180至180°、纬度−90至90°（均默认0、步长1°），以及阵风幅度0–100%（默认0为恒风）。经纬度和灯光一致表示风从哪边吹来：0/0从角色前方（场景+Z）吹来，正90°经度从+X吹来，正纬度从上方吹来。风力强度是效果等级，调整强度有0.3秒缓动；偏好自动保存，刷新/切换模型或动作后保留，关闭风保留布料已有速度。黄色type2继续保持骨骼位置约束，仅受近似风矩影响；灰色无刚体骨骼及红色type0不直接受风。效果来自PMX刚体近似，手机布料手感和额外CPU开销仍需实测。

独立测试网页默认纠错基准45Hz、物理90Hz。纠错基准滑条同样在“动作 → 物理”，范围30–180、步长5Hz；仅改变关节误差纠正强度。缺失/非法值采用新默认，已经手动保存的65/180等值继续恢复；要在已有浏览器体验新默认，请手动将纠错设45Hz、物理设90Hz。灯光“恢复默认”会将物理重置90Hz，纠错基准单独保存。

独立 mmd-ar 网页在“动作 → 物理 → PMX 物理频率”提供 30–180Hz 调节，默认 90Hz、步长 5Hz。调节立即应用并保存，刷新、换模型或换动作后保持选值。全频率的子步预算均覆盖最多 0.1 秒的画面帧间隔，避免低频掉帧丢失模拟时间；每个 Ammo 固定子步都会插值运动学锚点的位置和旋转，并驱动有骨骼的 type2 刚体位置，旋转继续由物理求解，跨画面帧保留未满一步的时间，正常步进保留布料速度；切换/复位、频率变化和后台恢复同步插值历史。关节纠错率按默认45Hz归一时间，减小高Hz时重复纠错带来的扰动；仍保留PMX质量、弹簧与旋转阻尼，不能保证不同步长的布料手感完全相同。旧480Hz保存值恢复时限制为180Hz。这控制物理模拟频率，画面刷新仍由浏览器决定，高频会增加计算量。本地 web-dist 已生成，本轮尚未发布外网。

type2稳定性修复只针对有骨骼关联的刚体：将原先画面帧末的位置强制回位改为每个固定子步插值位置目标，按“目标位置减当前刚体位置，再除以子步时长”设置线速度，由Ammo积分到目标。屏蔽自由平移力响应，但保持原质量/角惯量及物理旋转；受控积分期间暂时跳过线性阻尼，结束后恢复，旋转阻尼保持。无骨骼type2继续自由动态。跨Hz关节纠错率归一是另一个全关节修复，骨骼小球显示不会修改这些物理行为。

骨骼诊断小球本身没有物理刚度/柔度。物理参数来自PMX关联刚体及刚体间关节：关节有XYZ三轴平移弹簧和旋转弹簧，当前MMDPhysics按各轴调用Ammo的setStiffness；刚体质量、惯量、线性/旋转阻尼也影响响应。当前接入没有XPBD的独立compliance（柔度）参数，ERP表示关节误差纠正比例，不等同弹簧刚度；显示开关不会修改这些参数。

测试构建已修正动态刚体旋转回写骨骼时的父子换算，避免后蝴蝶结等骨骼在较大组合旋转下持续自旋。刷新本地web-dist即可加载新物理模块，无需调整骨骼小球大小或清空刚体速度；此修正不消除PMX关节/碰撞产生的所有细小扰动，已安装APK须重新打包后才获得新版本。

旋转回写问题的关键是乘法顺序：旧逻辑把“旧骨骼世界旋转的逆乘物理世界目标”得到的差量左乘旧局部旋转，在多轴组合旋转下不等于正确的局部目标，旧矩阵滞后时还会产生反馈。当前直接读取当帧父级世界旋转并取逆，使用“局部旋转 = 父级世界旋转的逆 × 物理骨骼世界目标”，归一后写入骨骼；不再沿用旧姿态求增量。关键代码为web-physics-stability.js中的getWorldQuaternion(parentQuaternion).invert()及parentQuaternion.multiply(worldQuaternion).normalize()。固定刚体回归旧骨骼每次可跳转约120度，新回写为0；用户已反馈明显改善，真实刚体细小扰动仍单独观察。

独立网页在“动作 → 骨骼”分类左侧勾选开关，用小球显示骨骼关节点，透过模型可见；默认关闭，记住设置，刷新和换模型后恢复。展开分类可看图例：红＝type0（跟随骨骼）、黄＝type2（位置跟随骨骼、旋转由物理驱动）、绿＝type1（位置和旋转由物理驱动）；灰色为无关联刚体。同一骨骼多个类型按type1、type2、type0优先显示一个球。颜色对应加载后实际配置，关闭物理时不改变颜色。小球只用于观察，不参与物理、阴影或AO；当前本地web-dist可用，外网以实际发布版本为准。

当前PMX碰撞计算使用模型定义的刚体体积，形状可为球体、盒体或胶囊体；骨骼小球、骨骼层级连线和局部轴只作诊断显示，不作为碰撞形状。type0由骨骼驱动刚体姿态，有绑定骨骼的type2由骨骼驱动位置；Ammo计算刚体之间的碰撞及刚体间关节约束，再按type1回写骨骼位置/旋转、按type2回写旋转，骨骼带动网格变形。因此调节诊断小球大小不会改变碰撞范围；选中后的累计记录来自关联刚体之间的实际接触。

在同一“动作 → 骨骼”分类可拖动“小球大小”（0.2～3倍，默认1倍）并勾选“显示骨骼名称”（默认关闭）；两项保存在当前浏览器。名称贴近小球、随骨骼移动，中文描边；密集位置可能重叠，可按需关闭全量名称。

开启骨骼后轻点小球可选中，显示白环、该骨骼名称及局部轴：X红、Y绿、Z蓝，轴末端带字母。拖动继续旋转模型，双指沿用原操作，点空白或关闭骨骼取消选择。碰撞体开关开启时，选中后仅显示该骨骼自身绑定的刚体和从选中开始累计实际接触过的直接对手；不扩展到对手的其他碰撞对象。点“清空累计碰撞”可重置，后续接触仍会再次记录。换选、换模型或重建物理清除累计；VMD切换保留骨骼选择，换PMX取消选择。无关联刚体的灰骨骼没有自身接触记录；物理关闭时只显示自身配置位置并提示未模拟。当前独立本地web-dist可用。

独立网页在“动作 → 骨骼”分类内新增“显示碰撞体（线框）”，与分类标题左侧的骨骼小球开关独立，可以同时开启，默认关闭并记住设置。按PMX球/盒/胶囊的尺寸显示，红type0、黄type2、绿type1，透过角色可见；物理开启时读取实际刚体位置与旋转，无关联骨骼的刚体也显示。关闭物理时预览随骨骼/模型变换的配置位置，提示“未模拟”。颜色表示配置类型，线框不参与碰撞、AO或阴影；切换模型释放旧资源。本地web-dist已生成，外网以实际发布版本为准。

正式显示端的“定位”面板默认选 MindAR：先拍照并框选定位图，等 PMX 模型显示后点“开始定位”；识别到目标后相机跟随，失锁时保持最后视角。可在面板切换底面/立面及平移死区、旋转死区、缓动、相机距离；若设备上 MindAR 无法使用，可手动切回“旧 JS”。灯光面板有“播放动作”和“启用 PMX 物理”开关，物理切换会重载当前模型。正式功能已通过 Offline code-v41 发布到内外网；已安装包须检查热更，Android 真机视觉效果仍待现场验收。

测试网页在灯光面板“物理”分类提供默认开启的“启用 PMX 物理”开关。关掉会重新加载当前模型，以真正无 Ammo 物理的状态观察裙摆是否穿模；重新打开也会重载模型，动作从头播放。选择保存在当前浏览器。正式显示端和旧测试 APK 不提供此开关。

当前测试网页已取消 PMX 初始化时套用 VMD 第 0 帧及隐藏物理预热。新模型首个实际渲染帧只更新物理、不显示角色，第二帧才推进 VMD 并显示；关闭“播放动作”后刷新，第二帧从绑定姿态显示。布料物理仍可改变后续姿态。

网页专用 A-Frame 定位找到目标后，会在目标平面上显示半透明蓝色矩形和中心十字；图形随目标移动、旋转和缩放，不将定位姿态应用给 MMD 角色，模型本身仍正常加载与渲染。目标丢失或停止后蓝框隐藏。手机实拍的首锁及透视对齐仍待现场验证。


网页初次加载 PMX 时会显示分阶段百分比和进度条。该百分比包含 PMX、纹理、VMD 和模型初始化的阶段权重，100% 表示模型已可显示，不表示单个文件下载结束。

在 HTTPS 测试页转动手机或调整浏览器窗口时，MMD 画布会跟随新尺寸。正式显示端和测试网页都可在“灯光”标题后查看当前实际渲染分辨率（Canvas 宽×高像素）；它可能因最多 2 倍的渲染像素比限制而小于屏幕标称物理分辨率。

HTTPS MMD AR 测试页的“定位图”可直接选“MindAR 官方示例”。点击“查看 MindAR 官方测试图”，在另一台屏幕显示或打印该图片，再用当前设备摄像头对准它；同一部手机的摄像头不能拍到自身屏幕。已有自行保存的定位图不会被覆盖，官方示例不能删除。第一分类的按钮会在“开始定位”和“结束定位”间切换；拍照校准弹窗在短竖屏内可滚动。主光分类标题前的“主光阴影”开关默认开启；补光阴影可选无阴影、沿用主光阴影或补光自身阴影。关闭主光阴影后，补光“沿用主光”相当于无阴影，但“补光自己的阴影”仍可独立投影。使用补光前须打开补光开关。

HTTPS MMD AR 测试页目前使用与 MindAR Basic 相同的 A-Frame 目标锚点定位，原 Controller 的 25%／35%／50%／75%／100% 识别分辨率选项已移除；A-Frame 使用摄像头原始帧。请将定位图平放，选中官方卡片或保存的自定义图后点击“开始定位”：识别到图片时，蓝色矩形和中心十字贴着目标，MMD 角色脚底对应图片中心；移动拍摄设备可从不同角度观察角色。丢失目标时角色继续显示在原位置，相机停在最后一次定位视角，重新找到后继续跟踪；停止定位回到普通展示视角。当前比例是测试用的“角色高度约为图片宽度 1.5 倍”，不是按真实物理尺寸标定。高分辨率手机的帧率、真机首锁和透视对齐仍需现场验收；外网以实际发布版本为准。

测试页在定位面板“相机跟随”中提供四个滑条：平移死区默认定位图宽度的 0.5%、旋转死区 0.5°、缓动 120 ms、相机距离 100%。前两项抑制微小识别抖动，缓动越高画面越稳但跟手越慢；三项都可调到 0。相机距离可从 100% 降至 50%，沿相机到定位图中心连线拉近，不移动角色模型。设置仅在当前浏览器保存，滑动即时生效；此版本已发布到外网测试页。

测试网页的模拟图片定位在浏览器切到后台时会释放旧视频流，返回前台会自动用原定位图恢复；手动停止、换图或切回真实摄像头时不会自动恢复。真实摄像头仍需手动重新启动。定位只调整观察角色的相机，不缩放或移动 PMX 模型根节点，避免改变已有布料/刚体的世界变换。

无摄像头电脑可在同一定位面板的“视频输入”选择“模拟摄像头”，从本地选取相机画面图片。模拟画面宽度为 960 像素，高度按原图宽高比计算；预览与左右两个竖向滑条也随原图比例变化，不再固定 16:9。预览上方滑条调缩放、左侧调经度透视、右侧调纬度透视、下方 0–360° 滑条先转动平放的原图，再计算经纬度透视；鼠标拖动图片只平移，点“重置透视”恢复正面、0° 水平旋转、100% 缩放和居中。四角来自固定焦距的三维平面投影，不能自由拖动。此时“拍照校准”会显示当前模拟画面，点击拍摄后冻结同一比例的帧；测试网页上可拖动蓝色矩形内部移动选区，拖动边或角改变宽高，然后保存为新的定位图。模拟视角与拍后矩形是两套独立操作。开始定位后 MindAR 也使用模拟画布流，两者都不请求实体摄像头。原始模拟图片不会上传或保存，保存的定位图仍保留在当前浏览器的 IndexedDB。切换回真实摄像头时先停止当前操作。测试页可从内网 `/mnt/AASC/3rd/mmd-ar-test/web-dist/` 或发布后的外网 `/mnt/mmd-ar/` 打开；外网以实际发布版本为准。

显示端打开“角色”并等待模型加载后，可点击右上角“定位”。点击“拍照校准”会打开独立弹窗：先在实时画面中拍照，再在同一位置拖动四个角点选择细节丰富的基准图区域，最后保存。选择定位图并点击“开始定位”后，摄像头画面显示在角色下方；识别到基准图时，角色脚底会跟随基准图中心。点击“停止定位”释放摄像头并恢复普通角色布局。自然图片应有文字或明显纹理；低光、反光、遮挡和快速转动可能使定位暂时丢失。若持续显示“查找中”，根据提示增加光线、靠近并摆正基准图，或保持镜头平稳。图片保存在当前显示端浏览器本地，不上传服务端。

定位中的摄像头画面只覆盖媒体内容；语音状态、任务状态、角色和聊天界面显示在它上方。

桌面显示端在 MMD 画布上用左键拖动旋转角色、滚轮连续缩放相机、右键拖动平移角色。手机单指拖动旋转、轻点触发角色互动；两指移动可平移角色，并按指间距无级缩放相机。正式 APK 和 HTTPS mmd-ar 测试页使用同一套手势语义；角色平移相对定位锚点生效，相机缩放改变观察距离。PMX 相机裁剪 near 固定为 1，VRM 正式显示相机 near 也固定为 1。调整只在当前运行时生效，停止 AR 或重载模型后恢复。

### 3.6 MindAR 官方 Basic 独立示例

打开 <https://c.aasc.us/mnt/mind-basic/> 可体验 MindAR 官方 Basic 示例，也可使用自定义图片目标。点击“拍摄自定义定位图”并授权摄像头后先拍摄完整画面；照片上默认叠加四边各内缩 10% 的蓝色矩形选区，可拖动框体移动、拖动边或角任意调整大小，选区始终保持矩形；没有单独裁剪缩略图。确认蓝框后保存，也可重拍。保存后从目标列表选中并开始定位，浏览器本地调用 MindAR Compiler 编译，显示百分比进度。照片与矩形选区保存在当前站点 IndexedDB，不会上传；清除站点数据后需重新拍摄。上方控制面板默认展开，可收起以减少对画面的遮挡，并可随时重新展开。官方卡片目标仍可选择，识别官方或自定义目标都会显示 Softmind 动画模型。页面与 MMD AR 测试页相互独立；A-Frame、MindAR 和模型依赖 CDN。Softmind 模型署名为 hiukim，CC BY 4.0。

页面另提供默认关闭的“IMU 姿态实验”。点击“启用 IMU 辅助”后按浏览器提示授权设备运动传感器；可分别启用虚拟场景姿态防抖和定位图丢失时的短时位移补偿。IMU 只辅助虚拟模型姿态，不处理摄像头画面；补偿有时长和距离上限，不能替代视觉定位。不同手机/浏览器的传感器数据与轴向可能不同，真机效果仍待检查。

控制端可在对应显示端的“设备能力”中开启或关闭“摄像头采集”。关闭后该显示端会立即停止摄像头拍照、预览和图片定位，不再读取视频设备；设置按显示端保存，重连后自动恢复。麦克风录音开关独立生效。

“PMX Toon 明暗”默认关闭，主光和补光使用普通的法线朝向计算：背向某盏灯的表面不会接受该灯的直射光；补光若从另一面照入，仍可照亮该面。开启开关可恢复模型原有的卡通明暗。此设置仅作用于 PMX，沿用灯光面板的本地保存；之前明确保存的开启状态会保留，点击“恢复默认”会关闭 Toon。它不是 ACES 色调映射开关，不影响 VRM、环境光、角色阴影或 AO。

“灯光”面板提供独立补光开关、颜色、强度（0–5）和方向（经度/纬度）。补光默认关闭，开启后可照亮角色暗面，但始终不投射阴影；主光的角色阴影开关保持独立。设置保存在当前浏览器，点击“恢复默认”会关闭补光。

面板还提供“PMX 边缘光 1/2”，两组均默认关闭，各自可设置颜色、强度（0–5）和方向。启用后只在对应方向的角色轮廓叠加颜色，不会像补光那样照亮正面，也不投射阴影。两组可同时使用，恢复默认时一起关闭；VRM 不受影响。

聊天面板关闭、角色画布可交互时，可从角色身上或旁边空白处拖动旋转角色；按在角色上但只轻点并松开时才触发角色触摸。移动达到 8 像素后按拖动处理，松开不再触发触摸。

显示端打开“角色”后，点击右上角“灯光”可调整环境光、主光和角色阴影。PMX 角色还有默认开启的“PMX 环境遮蔽 AO”开关：开启后衣服、头发和身体相邻处会有更明显的接触暗部，关闭可减轻图形设备负担。开关下方可调整 AO 颜色（默认 `#931231`）、强度（`0–2`，默认 `0.6`）及半径（角色高度的 `1–20%`，默认 `6%`）；颗粒噪点由保边模糊减轻，半径过大仍可能使暗部过宽。PMX 角色还可设置“PMX 物理频率”，范围为 30–90 Hz，默认 65 Hz；频率是物理目标步进值，实际计算还受页面帧率及每帧最多 3 个物理子步限制，调高频率会增加计算量。“旋转暂停物理阈值”默认为 720°/秒，可在 30–1440°/秒调节；角色旋转速度超过该值时，布料物理暂时停止，减速后重新贴合当前姿态并恢复。上述设置立即应用并保存在当前浏览器，刷新页面后恢复；此前保存的自定义阈值继续生效，点击“恢复默认”可改用 720°/秒。VRM 角色不使用 PMX AO、物理频率或旋转阈值。

已有浏览器保存的 AO 自定义值不会被新默认值覆盖；要使用这组新参数，请在“灯光”面板点“恢复默认”。

AO 分辨率可在“半分辨率（默认）”与“全分辨率”间切换，修改后立即生效并保存。半分辨率最多为绘制像素的一半、且不超过 `1280×720`；全分辨率使用当前显示缓冲区的完整像素，可能改善细节，但高分屏会明显增加 GPU 占用。画面或触控变慢时切回半分辨率。此设置仅用于 PMX，不影响 VRM。

“AO 采样次数”可选 12、24（默认）或 32 次，修改后立即生效并随灯光设置保存在当前浏览器。高强度下有明显颗粒时可选 32 次；如果手机帧率下降，先切回 24 或 12 次、半分辨率。现阶段使用按深度保边的空间降噪，没有跨帧降噪，模型移动时仍可能有少量闪烁。

“AO 模糊轮数”可选 0–3（默认 1），每轮可单独设置 1–5 AO 像素的模糊半径（默认 3）。0 轮用于对比原始 AO，轮数增加可进一步柔化颗粒，但会增加 GPU 负担，也可能抹掉细节；手机上建议从默认 1 轮试起。半径按 AO 目标像素计算，与上方按角色高度计算的“AO 半径”不是同一个参数。设置会即时生效并随灯光设置保存，恢复默认回到 1 轮、半径 3。

PMX 模型自带的材质“环境色”会被显示端始终忽略；它不随灯光滑块恢复。将环境光和主光强度都设为 `0` 时，当前无其他发光来源的 PMX 人物应呈黑色。VRM 材质不受此规则影响。

## 5. 常见问题

### Q: 显示端列表为空？

**A**: 确保：
- 显示端页面已打开
- 显示端与控制端连接到同一服务器
- 网络连接正常

**A**: 浏览器安全策略可能阻止自动播放，点击视频区域或按空格键手动播放。

**A**: 
- 确保显示端已正确连接
- 检查显示端屏幕尺寸是否正确显示
- 尝试重置裁剪

### Q: 文件上传失败？

**A**: 检查：
- 文件大小是否超过限制
- 服务器磁盘空间是否充足
- uploads 目录是否有写入权限

### 当前顶点模式：骨骼跟随与自碰撞

“顶点布料（CPU）”和“顶点布料 GPU（WebGL2）”现在都保留原骨骼物理，顶点层只做形状跟随、附件连接、身体接触和布料自碰撞，不重复施加风和重力。无固定点的包体/装饰也先跟随原骨骼，近距离同链附件按相对偏移约束连接；关联组开关会同步，关闭组仍按骨骼运动并作为接触表面。

### GPU 顶点布料超时恢复（2026-10-03）

独立 mmd-ar 的 GPU 顶点布料初始化或单次更新超过500ms时，停止顶点层并保留Ammo骨骼物理，面板显示回退原因。计算分批提交且同一时间仅保留一个任务；500ms包含提交、调度和GPU等待，并非纯GPU计时。刷新不自动恢复GPU顶点模式，需要手动选择；网址追加 `?safePhysics=1` 可强制Ammo启动。已提交GPU命令/驱动编译无法中断，首次超时仍可能超过500ms。

SSGI每帧以未合成GI的场景颜色/深度更新双缓冲历史；前帧SceneColor经深度引导Reduction、普通Z的近/远深度HZB与相机重投影，验证有效才用于本帧射线命中。首帧、相机/投影切断或历史深度不匹配会回退当前SceneColor；动态角色无专用运动矢量，动画区域可能拒绝历史。不会无条件累积上一帧SSGI输出。屏幕空间只处理当前可见深度层，屏外/透明多层衣物与头发可能遗漏；间接光是漫反射近似，不含镜面反射。Reduction/HZB和质量档位会增加GPU开销，目标设备的实际画面与帧时仍需验收。此实现仅进入独立测试页/测试APK副本，未修改正式显示端。

- 接触阴影与SSGI命中使用有限步数/细化；SSGI提供可调双边降噪0–3轮，GI亮点限幅可能使小尺度反弹光略柔和；高质量和滤波轮数增加GPU开销。


## 独立 MMD-AR：MPL 动作播放

### 手动表情（独立网页）

打开「动作 → 表情」，页面自动从当前 PMX 读取 Morph 名称、英文名和面板分类，按眉毛、眼睛、嘴型、其他显示。不限于米娅，也可用于用户选择的本地 PMX；切换模型后自动更新。米娅当前有29项（嘴型12、眼睛11、眉毛6），名称保留模型原文，包括尾随空格、半角字符和重复名称。

点击表情按钮启用，再点取消；多项可同时启用。拖动每项的0–100%滑条会自动启用该项，可分别设置强度；0%仍属于手动覆盖，可抑制动作自带的同名表情。点击「清除手动表情」解除全部覆盖，恢复当前VMD自带表情（没有表情轨道时恢复原值）。手动选择会在动画更新后应用，因此播放VMD不会覆盖选中项目；其他项目继续由VMD控制。换动作保留选择，同模型物理重载保留；换模型清空，刷新不保存。

当前支持顶点Morph和直接引用顶点Morph的组合项；加载器未实现的骨骼、UV、材质或其他组合项会显示但禁用。静态GLB或没有Morph的PMX显示原因。表情只影响当前预览，不修改PMX文件，不随工程保存，也不写入MPL或导出VMD。运行 `npm run build:web:mmd-ar-test` 生成网页；实际浏览器表现待验收，外网以发布版本为准。

### MPL输入

仅独立网页：打开「动作 → MPL 动作」，粘贴 LLM 已生成的 MPL，点击「编译并播放」。也可先点击「填入动作＋表情示例」或「填入表情示例」（按当前 PMX 自动选择表情）。默认PMX加载完成后自动填入点头＋表情示例，用户已编辑的代码不会被覆盖。网页不调用 LLM，代码在浏览器 Worker 内编译为 VMD，不上传服务器；首次点击才下载同站点的约564KiB WASM编译器。纯 MPL 或包裹整段代码的 ` ```mpl ` 围栏都可输入，围栏以外的说明文字需要手动删除。

以下是米娅的动作＋表情示例；按钮会自动使用当前模型的真实名称。

```mpl
@pose normal {
    head reset;
    morph "口角上げ" 0;
    morph "笑い" 0;
}
@pose nod {
    head bend forward 20;
    morph "口角上げ" 0.7;
    morph "笑い" 0.7;
}
@animation nod_once {
    0: normal;
    0.5: nod;
    1.5: normal;
}
main {
    nod_once;
}
```

### MPL表情

在 `@pose` 内写 `morph "PMX原始表情名" 权重;`，权重0–1。名称从「动作 → 表情」复制，必须保留原始字符和空格；通用于任意受支持的PMX，不限于米娅。例子（米娅）：

```mpl
@pose normal {
    head reset;
    morph "口角上げ" 0;
    morph "笑い" 0;
}
@pose smile {
    head bend forward 10;
    morph "口角上げ" 0.8;
    morph "笑い" 0.5;
}
@animation greet {
    0: normal;
    0.5: smile;
    1.5: normal;
}
main {
    greet;
}
```

删除示例中的两个head语句即可只播放表情。「填入表情示例」自动选择当前模型嘴型/眼睛/眉毛等可用表情，生成纯表情时间线；这是格式示例，具体表情组合需按模型调整。组合姿势可以写 `0.5: pose1 & pose2;`。

骨骼和表情编译为同一份VMD，下载也包含表情。表情关键帧线性过渡；0秒未指定的受控表情默认零，后续未指定则沿用上一时间点权重，回到无表情须显式写0。手动表情仍优先；看到覆盖提示时取消对应手动选择或「清除手动表情」即可查看MPL效果。

未知、不支持或同名重复的Morph会报错；同一量化帧同一表情定义不同权重也会报错。VMD名称要求可无损编码为Shift-JIS且不超过15字节，不自动截断/改名。骨骼和表情各最多70,000条帧，其他输入/输出/时长上限沿用原限制。此语法是独立网页扩展，未修改上游WASM；手动面板本身的选择不自动写入代码。

时间单位是秒，角度是度；每条语句单独一行、以分号结束，结束大括号单独一行，姿势定义在动画之前。MPL 原语法见 [MMD-MPL](https://github.com/AmyangXYZ/MMD-MPL)。一个 `main` 引用多个动画时，各时间线使用原来的绝对时间，不自动首尾拼接。

播放会替换当前 VMD，未指定的骨骼回到绑定姿态，不与旧动作叠加；沿用当前模型的循环/单次播放方式和现有骨骼/物理处理。「停止并恢复原动作」恢复进入 MPL 前的动作与播放开关；正在编译时该按钮改为「取消编译」。如果另外选择了模型或动作，不再覆盖新选择。「下载 VMD」可把最近一次编译成功的结果保存为 `mpl-motion.vmd`，之后通过「选择 VMD 动作」再次载入。

纯骨骼/表情姿势（仅第0帧）会补成1秒静态保持，避免循环零时长动作导致无效时间；下载的 VMD 也包含该保持帧。

循环与物理：独立网页已显式设置 `resetPhysicsOnLoop=false`，默认动作、本地VMD、MPL（含点头＋表情示例）循环均保持物理继续计算，不在循环边界重置刚体、清零速度或清理求解器状态。手动换动作、换模型及其他显式初始化仍按现有流程处理。修复前共享播放器继承库默认true；MPL未单独增加循环重置，之前默认动作的实际表现未做运行验证。

需要 PMX；骨骼语句需要标准日文 MMD 骨骼，纯表情不依赖标准骨骼。静态西施等 GLB 不支持；部分骨骼不匹配显示缺失名称，骨骼和表情都无匹配才拒绝播放。编辑/Blender工程模式请先退出并切到预览。语法错误不会替换原动作。输入最大64KiB，编译超过30秒自动终止，输出最大8MiB、最长一小时；刷新不保留输入或自动播放。

构建直接运行 `npm run build:web:mmd-ar-test`，固定编译器首次构建下载，之后校验缓存复用；也可用 `npm run prepare:mmd-ar-mpl` 提前准备。生成网页内保留 GPL-3.0 许可证与源码来源清单。骨骼版此前于2026-10-10发布外网；本次MPL表情扩展和默认动作＋表情示例已重新构建并于2026-10-10发布外网，刷新后使用；实际浏览器/手机播放仍待验收。

## MMD-AR编辑器首版

左上角“编辑/预览/渲染”切换工作区，“展开/收起”控制面板。编辑PMX时暂停动作/物理并恢复绑定姿态，选择刚体或关节后改数值或拖动彩色轴；尺寸工具用于刚体。Ctrl多选可批量改值；撤销/重做保留100步。刚体位置相对关联骨骼，关节位置为模型坐标，方向/角限位以度显示；碰撞掩码为十进制0～65535。删除刚体会同时删除连接它的关节，可撤销。镜像复制后核对骨骼与关节连接端。

切“预览”重建物理使修改生效；进度条定位时自动关闭物理，可再勾选。正面/侧面/背面固定观察视角，“自由视角”恢复原视角控制。保存工程生成自包含ZIP，包括原始PMX/贴图/动作、物理修改及场景设置，使用PBR材质源的工程还带源GLB；通过“打开工程”重新加载。工程保存不是导出已修改PMX，不会覆盖源模型。渲染区可设图片宽高和透明背景，导出当前姿态PNG；图片尺寸64～4096并受设备上限约束。首版不包含视频输出。

“展开 → 导出 PMX”下载`原名称-edited.pmx`，把当前刚体/关节数值与增删、复制、镜像结果写入模型文件。编辑状态也能直接导出；把新PMX和原贴图放在相同相对路径，再用网页或PMX Editor打开。原文件的网格、材质、骨骼等数据保留，刚体重排会同步冲量表情/软体锚点引用，已删除刚体的对应元素移除。场景光照、动作和求解器设置另存工程ZIP。此下载支持HTTP网页，不需要目录写权限；旧ZIP缺少来源且含增删/改名时会拒绝含糊导出并提示重新加载原PMX。

### Blender 工程（按需加载，用户暂缓后续维护）

网页构建前运行 `npm run prepare:mmd-ar-blender-engine` 安装固定版本构建依赖，再运行 `npm run build:web:mmd-ar-test`。HTTPS 桌面 Chromium 打开网页后，点击左上角“Blender工程”，浏览器会立即询问本地目录读写权限；选择含 `.blend` 的工程目录，再点“打开工程”。选中目录后才下载 Blender 工作区代码与预览资源；选择并打开 `.blend` 时再下载约38 MB压缩核心WASM/数据并启动引擎。用户取消目录选择、普通首屏与测试 APK 都不下载这些资源。

工作区显示 Blender 工程预览，可旋转观察、请求 Cycles PNG 渲染、保存并关闭。改动写回用户选择目录中的原生 `.blend`，同目录图片/贴图按相对路径供 Blender 使用；工程文件不会上传服务端。目录句柄保存在当前 HTTPS origin 的 IndexedDB，权限失效时点“重新授权目录”。部署服务器必须返回 `COOP: same-origin` 与 `COEP: credentialless`，并按 `Content-Encoding: br` 提供 `.br` WASM 资源。Apache 部署还需启用 `mod_headers`，并在引擎资源目录允许 `.htaccess` 使用 `Header` 指令。首期不支持 Firefox、Safari、APK；未编入引擎的 Blender 插件和自定义扩展不会自动安装。实现边界见 `docs/design/mmd-ar-blender-workbench.md`。
