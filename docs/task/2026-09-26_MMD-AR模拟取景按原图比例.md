# MMD AR 模拟取景按原图比例

- 日期：2026-09-26
- 范围：仅 HTTPS MMD AR 测试网页；不修改正式显示端的 AR 流程，不构建 APK，不发布外网。
- 需求：当前模拟取景按固定 960×540，用户明确要求以原图宽度为横向基准，按原图比例计算高度。

## Design 需求

加载本地图片后，以 960 像素为模拟画面宽度，纵向按解码后的原图宽高比取整。预览、纬度滑条、视频流、拍照校准和 MindAR 输入保持同一比例。未选图前允许 960×540 占位；失败或超出 GPU 能力时保留之前有效画面，并提示原因。

## Spec 设计与受影响代码

- 先更新 `docs/spec/mmd-ar-test-apk.md`，写入原图尺寸、画布尺寸、预览/滑条联动和异常规则的伪代码。
- `3rd/mmd-ar-test/display-mmd-ar-sim-camera.js`：图片解码后计算取景高度，更新 WebGL 视口和尺寸 uniform，按原图比例更新预览与纬度滑条。
- `3rd/mmd-ar-test/build.js`：页面说明由固定 960×540 改为按原图比例。
- `tests/mmd-ar-sim-camera.test.js`：竖图切横图、布局、视频流、拍照保存和 MindAR 定位回归。
- 同步更新 design、usage、README、todo、自测与 changelog。

## 自测、兼容性、性能与风险

- 自测：网页构建；竖图、横图的画布/预览比例；模拟拍照和保存尺寸；MindAR 模拟首锁及流释放；语法与差异检查。
- 兼容性：真实摄像头使用原有原始帧；正式显示端和旧测试 APK 不加载此网页专用脚本。
- 性能：固定 960 像素横向输出，避免直接使用数千像素原图作为模拟视频；过高画面在 GPU 视口上限外拒绝加载。
- 风险：竖图显著增加画布像素数，手机浏览器可能降低定位帧率；真实设备需另行验收。
- 预计工时：约 1 小时。实际测试结果记录在 `docs/self-test.md`。
