# 快捷面板清空当前媒体

日期：2026-10-10。状态：代码和定向自测已完成；服务包待构建发布，Android实机待验收。

## 任务与设计需求

用户要求在控制端快捷面板播放按钮后加清空当前媒体按钮。采用「清空媒体」文案，目标是快捷面板当前选择的显示端；清空媒体呈现及其恢复状态，保留媒体文件、角色与聊天。设计见 ../design/display-control-refactor.md。

## Spec 设计

先同步 ../spec/floating-control.md 中的伪代码，再实现 `control/clearMedia`：选择与连接检查、服务端空状态持久化与权威广播、显示端停止和释放、控制端结果同步。重复清空应幂等，迟到媒体加载不能恢复画面。

- src/apps/web-mediacenter/ui/public/js/websocket.js：权威结果对应当前显示端时，同步播放/文本/列表/预览状态。

## 需求分析（analyze-requirement-level，enterprise）

- 结论：方案可开发，用户已确认实施。主等级 L5（清空业务规则），次等级 L6（消息与模块契约）；直接风险中，建议下放为 L4。
- 证据：用户「在播放按钮后面」确定入口；「清空当前播放的媒体」确定操作目标；现有 handleControl/play 仅暂停而服务端 currentMedia/currentPlaylist 会恢复，支持需要跨端清理的判断。
- 置信度：L5 两条强证据权重6、L6一条中证据权重2，邻层一致系数0.9，结果0.675。评分：清晰度23/25、证据17/20、完备度18/20、风险18/20、落地14/15，总分90/100。
- 断点及行动：现有暂停不会清空呈现，新增明确清空动作；保存状态仍可恢复，清空需持久化并广播结果；异步加载可能回填，增加失效检查。
- L4 草案：已有声明=选中显示端/WS/stopPlaylist/persistDisplayState；新增定义=clearMedia动作和权威结果；操作流程=选中目标→校验连接→命令→停止清空→保存→广播→同步面板。具体伪代码见 spec。
- 后续技能可选：ai-code-translation / project-pseudocode-sync / 仅保留分析；当前暂不调用额外技能。用户确认本方案后按项目正常代码实施流程继续。

## 自测用例

1. 按钮紧跟播放按钮，点击发给快捷面板选择的目标。
2. 未选择、断线、发送异常提示且不显示虚假已清空状态。
3. 图片/视频/音频/文本/网页全部清空，文本语音和列表推进停止。
4. 已暂停媒体、临时媒体及重复清空兼容；其他显示端不受影响。
5. 清空后预览/播放标记/文本分页/批量进度消失，权威结果不误改其他目标。
6. 刷新和重连仍为空状态，迟到加载结果不回填。

## 兼容性与性能

验证横竖屏现有浮动布局及播放/暂停控制不回退；沿用 WS，不增加依赖、轮询或逐帧工作。实机 Android/WebView 媒体类型与刷新恢复待实施后验收。优先使用 package.json 已有 scripts；无定向脚本时用 node --test 运行对应测试。

## 风险与预计工时

风险：旧加载回调回填、播放进度晚到覆盖空状态、多控制端结果不同步；通过加载失效、服务端状态校验和权威广播规避。预计实现与定向验证约1–2小时，实际发布按后续授权范围执行。按已确认方案实施，完成后标记服务包待打包并上传代码/状态。
