# Pi Agent 无回复诊断与控制端聊天日志

## 任务描述

处理 Pi Agent 偶发没有回复、错误型空 `agent_end` 被当作成功以及控制端无法从日志确认回包归属的问题。增加受 requestId 关联的 Pi 生命周期日志，并补充控制端聊天输入/响应日志。

## design 需求

- 记录 Pi 请求入队、启动、关键 RPC 事件、完成、失败和超时。
- `agent_end` 中的错误助手消息不能解析为成功空文本；可重试事件不能提前结束请求。
- 控制端 `chatMessage` 和 `chatResponse` 打印 requestId，支持判断 Pi、服务器和前端分别在哪一层丢失。
- 日志避免打印完整 prompt、API Key 和大段响应内容。

## spec 设计

- `PiRuntimeManager` 接收可选 logger，所有生命周期记录通过该回调进入服务器 `Pi` 分类日志。
- `agent_end` 先检查 `willRetry`、助手错误停止原因和空文本，再决定继续、失败或成功。
- `handleChatMessage` 在发送 `chatResponse` 前记录 requestId、成功状态和消息长度；控制端入站日志记录 content 摘要。

## 自测用例

- Pi 正常文本流记录开始、事件和完成日志。
- 错误型空 `agent_end` 触发失败回调并拒绝请求。
- 空成功 `agent_end` 不产生成功空回复。
- `willRetry` 的 `agent_end` 不提前完成请求。
- 请求超时记录 requestId 和超时日志。
- 控制端聊天输入及成功/失败 `chatResponse` 均包含 requestId 日志契约。

## 兼容性测试

- 普通 LLM、已有 Pi 工具转换和控制端 requestId 回包行为不变。
- 未注入 logger 时 `PiRuntimeManager` 仍可独立运行。
- 日志分类仍使用服务器现有 `Pi`/`WS` 分类，不改变日志文件清理策略。

## 性能测试

- 生命周期日志只保存事件类型、requestId 和长度摘要，不复制完整响应。
- logger 异常不能阻塞 Pi RPC 处理。

## 风险评估

- Pi RPC 事件字段可能随版本增加，错误判断只依赖已有标准字段并保留未知事件兼容性。
- 增加日志会提高高频事件数量，因此不记录每个文本增量的完整内容。
