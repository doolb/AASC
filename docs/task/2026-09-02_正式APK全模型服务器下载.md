# 正式 APK 全模型服务器下载

## 任务描述

将正式 `android-display` APK 的视觉、降噪、ASR、TTS 和声纹模型统一改为服务器按需下载，APK 不再内置可更新模型。服务器保留推理在显示端本机执行的架构。

## Design 需求

- 统一模型分发设计见 `docs/design/android-model-distribution.md`。
- 新增视觉和降噪清单/下载路由；复用现有 ASR、TTS、声纹路由。
- RapidOCR 支持四个 pipeline 文件，YOLO 支持 n/s/m/l/x 模型 ID。
- 下载使用 SHA-256、`.tmp` 和原子改名；任务失败返回结构化错误。
- 独立测试 APK 不在本任务改造范围内。

## Spec 设计

- 伪代码见 `docs/spec/android-model-distribution.md`。
- 先增加服务端清单、安全路径和 APK 构建约束失败测试，再实现生产代码。

## 受影响功能模块和代码

- 服务端：模型清单服务、`server-app.js` 路由、API 文档和 npm 模型准备命令。
- APK：`VisionModelManager`、`DenoiseModelManager`、`VisionRuntime`、`NativeBridge`、YOLO 模型选择和 Gradle 资产任务。
- WebView：视觉请求可携带模型 ID，默认 `yolo11n`；能力信息继续区分桥存在和本地模型就绪。
- 文档：design/spec/usage/todo/changelog。

## 自测用例

1. 服务端清单只展示真实存在的资源，非法模型 ID/文件名返回 400，缺失资源返回 404。
2. RapidOCR、YOLO11n 和 GTCRN 的下载 hash 校验、断点失败清理和本地缓存复用通过。
3. Gradle 不再执行视觉/降噪模型复制或 YOLO 导出，APK 资源表不含这些模型。
4. APK debug 构建、JVM 单测、服务器启动及 HTTP 清单/下载请求通过。
5. 真机首次 OCR、YOLO、ASR、TTS/降噪路径能从默认本机服务器下载并加载；重复推理复用缓存。
6. `/mnt/tmp` 现有游戏截图至少完成 OCR 与 YOLO11n 一次真实显示端链路。

## 兼容性测试

- 新 APK + 新服务器：模型首次下载、缓存重启和模型切换。
- 新 APK + 旧服务器：清单缺失时错误可见且媒体显示不受影响。
- 旧 APK + 新服务器：旧视觉协议仍可转发。
- 没有 YOLOs/m/l/x ONNX 时，清单不返回这些模型而不会影响 yolo11n。

## 性能测试

- 下载耗时、下载后首次加载耗时、缓存命中耗时分别记录。
- OCR/YOLO 推理仍验证单小核和 ORT intra/inter 线程 1/1。
- 记录 APK 安装包模型资源大小为 0，服务器模型目录大小和各文件 hash。

## 风险评估

- 首次推理增加网络等待；通过清单、进度和本地缓存降低重复等待。
- 服务器资源未准备会导致对应模型不可用；路由动态只列出真实文件并在文档提供准备命令。
- 下载途中断电可能留下临时文件；原子改名和失败清理避免加载半文件。
- 大尺寸 YOLO 模型可能造成内存压力；模型切换时释放旧 session，默认仍使用 yolo11n。
