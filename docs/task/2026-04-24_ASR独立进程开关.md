# 任务：ASR 独立进程开关

## 任务描述

- 目标：增加可配置开关，把服务端语言识别执行迁移到独立进程，降低主进程 RSS 占用和抖动
- 范围：仅调整服务端 ASR 执行模式，不改动识别接口协议和控制端调用方式

## Design 需求

- 在 `asr` 配置增加 `isolateProcess` 开关与运行参数
- 开启开关后，主进程通过 IPC 与子进程通信；子进程负责加载 `sherpa-onnx-node`
- 子进程异常退出支持自动重启，识别请求支持超时保护
- `/api/asr/status` 可返回当前是否启用隔离进程，便于观测

## Spec 设计（伪代码）

```
init(options):
    isolateConfig = resolveIsolateProcessConfig(options)
    if isolateConfig.enabled:
        asrInstance = new IsolatedAsrProcessClient(options)
    else:
        asrInstance = new SherpaOnnxASR(options)

IsolatedAsrProcessClient.startWorker():
    worker = fork(asr-worker-process.js)
    bind message + exit
    worker.send({type: 'init', options})

IsolatedAsrProcessClient.recognize(audioPath):
    ensure ready
    id = createRequestId()
    pendingRequests[id] = {resolve, reject, timeout}
    worker.send({type: 'recognize', id, audioPath})
    return Promise

asr-worker-process:
    on init:
        asr = new SherpaOnnxASR(options)
        send ready status
    on recognize:
        text = await asr.recognize(audioPath)
        send response
```

## 自测用例

- 用例1：`isolateProcess.enabled=false`
  - 预期：行为与原先一致，`/api/asr/status` 返回 `isolatedProcessEnabled=false`
- 用例2：`isolateProcess.enabled=true`
  - 预期：ASR 可正常识别，`/api/asr/status` 返回 `isolatedProcessEnabled=true`
- 用例3：子进程异常退出
  - 预期：主进程触发自动重启；重启期间请求返回明确错误，不出现卡死

## 兼容性测试

- 保持 `/api/asr/recognize` 与 `/api/asr/status` 原有字段兼容（新增字段为非破坏性）
- 不影响显示端本地 WASM ASR 回退流程

## 性能测试

- 在同样压测参数下比对主进程 RSS 峰值（隔离前/隔离后）
- 关注识别延迟变化和 429 比例，确认 IPC 成本可接受

## 风险评估

- 子进程频繁崩溃会造成短时不可用，已通过自动重启与请求超时保护缓解
- IPC 增加少量延迟，需在高并发压测下确认阈值
