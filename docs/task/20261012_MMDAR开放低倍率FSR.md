# 独立MMD-AR开放低倍率FSR重建

日期：2026-10-12。状态：已完成；本轮只修改独立 `mmd-ar-test`，正式显示端不变。

## 任务描述

在独立MMD-AR的FSR输出重建倍率下拉菜单中增加0.25×和0.5×，并让本地设置归一化、Canvas输出尺寸及时域历史目标接受这两个倍率。保留1×默认值和现有1×/2×/4×行为。低倍率表示最终输出Canvas小于基础Canvas，由网页显示区域放大；不表示提高内部场景输入分辨率。

## Design需求

- 只扩展 `3rd/mmd-ar-test` 独立端；正式显示端 `src/apps/web-mediacenter` 不修改。
- 选项集合为0.25、0.5、1、2、4，默认值仍为1；旧存储与非法值仍回退到1。
- 只在抗锯齿启用、FSR2模式和WebGL2可用时使用重建倍率；场景输入、PNG旁路、TAA和关闭抗锯齿行为保持原样。
- 调整帮助与运行状态说明，使低倍率降低输出分辨率/缓冲成本、高倍率增加输出分辨率/缓冲成本的含义清楚。
- 不新增服务器配置、HTTP接口、生产依赖或APK发布操作。

## Spec伪代码

```text
fsr2ReconstructionScale ← 0.25/0.5/1/2/4之一，默认1；不合法或缺失时归一为1
BaseSize ← CSS尺寸×自动DPR×canvasScale
FSR有效 → SceneSize ← BaseSize×fsr2Scale；PresentSize ← BaseSize×fsr2ReconstructionScale
PresentSize低于BaseSize → 低分辨率Canvas由页面显示区域放大，输出历史缓冲按实际PresentSize分配
TAA/关闭/不支持WebGL2 → 重建倍率不改变旧输出尺寸语义
PresentSize变化 → resize Canvas与时域历史目标并清除旧历史；SceneSize保持由既有设置决定
PNG或诊断旁路 → 使用请求尺寸；完成后恢复预览尺寸与历史状态
```

## 受影响功能模块和代码

- `3rd/mmd-ar-test/web-render-settings.mjs`：倍率归一化及运行状态说明。
- `3rd/mmd-ar-test/web-render-settings-build.js`：独立面板选项和帮助说明；通过现有构建生成本地网页资源。
- `3rd/mmd-ar-test/README.md`：同步独立端FSR倍率使用说明。
- `tests/mmd-fsr-reconstruction.test.js`、`tests/mmd-ar-temporal-aa-browser.test.js`：独立端合法值、尺寸、历史目标和Shader回归；正式端既有行为仍由同一测试覆盖。
- 独立端设计、spec、自测、todo和变更日志。

## 自测用例

1. 归一化接受数字及字符串形式的0.25/0.5/1/2/4，非法值仍回退到1。
2. 固定BaseSize时五档输出尺寸按倍率变化，SceneSize不随重建倍率改变。
3. 时域历史目标尺寸与实际输出匹配；重建档位变化清空历史，之后可继续使用历史。
4. 普通TAA、关闭抗锯齿和不支持WebGL2沿用基础尺寸，PNG尺寸旁路不叠加倍率。
5. 执行 `node --test tests/mmd-fsr-reconstruction.test.js` 与 `npm run build:web:mmd-ar-test`。

## 兼容性测试

- 独立端既有本地存储键和1×默认不变；既有1×/2×/4×输出契约不变。
- 正式显示端、本地渲染设置字段、服务端配置和HTTP接口不变。
- 设备输出上限仍只限制输出；基础场景输入不由输出倍率反向推算。

## 性能测试

场景输入固定时，0.5×相对1×具有约1/4的输出像素面积，0.25×约1/16；输出颜色及历史缓冲随实际尺寸分配。定向测试确认尺寸契约，不把像素面积比例外推为整帧GPU耗时比例；设备帧时与观感留待手机验收。

## 风险评估

- 低于1×时Canvas分辨率低于页面显示分辨率，放大后可能更模糊或出现锯齿；菜单说明需避免将其理解为提高画质的超分档位。
- 极小/奇数尺寸仍由现有取整和最小尺寸逻辑处理；WebGL尺寸上限及历史资源释放逻辑不变。
- 不更改重建Shader算法，不承诺解决动态残影或恢复输入阶段已丢失的细节。

## 实施与验证结果

- 独立面板已提供0.25×/0.5×/1×/2×/4×，默认1×；菜单说明和运行状态会解释低倍率缩小输出并由页面放大，以及相应的画质/成本变化。
- `node --test tests/mmd-fsr-reconstruction.test.js`：8/8通过。独立端接受五档并验证输出尺寸、固定场景输入、时域目标/历史清理；正式端仍只接受1/2/4。
- Chromium SwiftShader Shader回归：独立端50组（10角度×5倍率）通过，输入保持64×64、输出分别为16×16/32×32/64×64/128×128/256×256，WebGL错误为0；正式端原30组回归通过。
- `npm run build:web:mmd-ar-test`成功，构建后的 `web-dist/index.html` 确认含五档选项；Vite输出既有的大chunk体积提示。
- 未修改正式端配置/代码，未改Offline状态文件（`minApk`、`servicePackage`、`dependenciesPackage`当前均为`true`），未发布网页、服务包或APK，未操作服务器。

预计工时：1小时；实际实现与定向验证已完成。硬件手机画质和GPU帧时仍待既有FSR设备验收事项覆盖。

## 后续反馈

用户反馈0.25×/0.5×及高倍率画面效果都不好，后续要求正式端与独立端统一固定为1×，并继续要求移除重建倍率界面控件。本任务记录的五档实现已由 `docs/task/20261012_MMDARFSR仅保留1x.md` 撤回并替代；此前验证仅作为历史结果保留。
