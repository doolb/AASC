# MMD-AR后台空闲清理重置视角

创建：2026-10-08；完成：2026-10-09。用户确认方案后实现，实际模型/模拟定位浏览器回归与Web构建通过；手机系统后台恢复待设备验收。

## 任务与需求分析

用户原句：“还有浏览器从后台切回,会重置角色位置,和相机距离”。目标为独立测试页普通预览前后台切换后保留人工拖动、缩放和旋转，同时保证实际AR及校准资源正常释放。现场浏览器是否触发pagehide尚未知，设计同时覆盖visibilitychange与pagehide，不依赖猜测具体浏览器事件组合。

按analyze-requirement-level的enterprise模式记录：主等级L6（预览与AR生命周期的行为契约），次等级L5（自动清理/前台恢复流程）；评审可开发，代码执行仍需项目规则要求的方案确认。证据：用户明确位置与距离重置（强，L6）；实际模型根与zoom数值复现（强，L6）；visibilitychange→stopAr→cancelPending→releaseSystem调用链（强，L5）。置信度为6/9×0.90=0.60。层级清晰度23/25、证据充分度20/20、实现完备度17/20、风险暴露度18/20、L4落地性14/15，总92/100，直接开发风险中。建议下放L4：用释放前AR状态与自动清理标记串联复位策略；伪代码见对应spec。断点为原静态resize回归未覆盖生命周期，行动为增加实际模型后台回归及保留活动AR资源释放/恢复回归。此次先保留分析结果，不额外调用代码翻译或伪代码同步技能。

## 根因与实测

实际Chromium/SwiftShader加载本地生成页的米娅模型，关闭动画/物理干扰，手动缩放1.8并平移80/40像素，触发真实页面visibilitychange监听器。隐藏前AR idle、tracking=false、AR相机active=false。角色根从[1.7391567, 9.2302761, 0]变为[0, 10.0998544, 0]；cameraZoomFactor从1.8变为1；相机Z从27.9015059变为50.2227107。变更在隐藏事件后已经发生，可见事件后保持重置值。

记录到的调用栈：document.visibilitychange→stopAr→stopTrackerSession→MmdArTestAframeTracking.cancelPending→releaseSystem→DisplayMmd.resetArCameraPose。共享stopAr还会调用resetTrackedDisplay，适配器独立pagehide入口也调用cancelPending。现有resize已改为updateProjectionMatrix，不是这次实际根平移丢失的原因。

## Design与Spec方案

design记录自动清理的空闲预览保留契约；spec先定义释放前状态、自动清理标记、取消请求/释放资源与显示复位策略。生命周期清理仅在独立测试页普通预览时保留变换；显式开始定位/手动停止和模型初次加载保持已有复位语义。适配器空闲自动取消不得退出一个不存在的AR相机；显式取消默认仍复位。活动AR继续停止识别、摄像头及IMU；模拟定位仅按既有恢复目标与代次条件重启。

## 自测、兼容与性能

- 实际模型缩放/平移/旋转后，隐藏/可见循环及pagehide/pageshow前后根position/quaternion/scale、相机position/quaternion、zoom一致；角色仍可见。
- resize仍适配尺寸/projection，不重新拟合；首次加载/更换模型保留初始自动取景。
- 活动模拟定位隐藏后旧轨道ended；前台建立不同ID新轨道；手动停止后不恢复。
- 等待相机准备或识别启动时切后台，迟到任务不能重新持有摄像头；校准流仍释放。
- 正式显示端生命周期策略限制在原行为；独立网页与APK适配器共享资源释放规则。浏览器合成生命周期回归不能替代手机操作系统后台恢复验收。
- 清理时只新增状态判断，无模型遍历、每帧计算或资源分配；预计不增加稳态渲染开销。

## 风险与预计工时

主要风险为共享控制器和适配器重复清理、提前读取状态失败导致错误判断及异步启动取消遗漏。释放前捕获状态并以真实模型/视频轨道双重回归验证；缺少诊断接口时保留旧复位策略。预计1小时，含实现、浏览器回归与构建。开发待确认条目已移除，设备验收单列。

## 执行记录与验证

- 用户“是”确认方案；先更新spec，然后增加真实模型回归，旧实现隐藏后根X从1.7391567变为0，功能断言按预期失败。测试桥接接口编写错误在修改生产代码前纠正，不计为功能RED证据。
- 首次修正后，普通预览和模拟轨道用例通过；扩展真实AR退出/手动停止检查发现idle显式停止倍率仍为1.8，按预期暴露语义回归。
- Ruling：适配器cancelPending/releaseSystem增加preservePreview参数且默认false，自动清理才传true。理由：生成HTML的蓝框模式使resetTrackedDisplay提前返回hide，显式停止的复位实际由适配器承担；一概跳过idle复位会破坏原操作。spec先同步，随后修改并重构建。
- Ruling：独立页pagehide取消once监听，正式页保留原策略。理由：BFCache恢复后仍应取消后续校准请求；实际回归在两次pagehide之后启动延迟摄像头请求，再次pagehide仍释放迟到流。
- 最终`node --test tests/mmd-ar-background-resume.test.js`：2/2通过、无跳过（约26秒）。真实模型逐分量容差1e-5验证两轮可见/隐藏、pagehide/pageshow/resize；覆盖蓝框与直接复位分支，1.8倍缩放及80/40像素平移保留。画布可见像素>1000；两个延迟校准请求的真实canvas视频轨道ended；实际AR相机active由true回false；手动停止zoom回1且根X回0。模拟定位旧轨道结束、新轨道ID不同、手动停止后不恢复。
- `npm run build:web:mmd-ar-test`成功，当前本地生成页包含新清理逻辑及指纹。没有新增依赖；既有Offline状态minApk=true/servicePackage=true/dependenciesPackage=false保持，没有构建APK或外网发布。
- 扩展相机动作/重力检查共8项：5通过、2失败、1跳过。两项失败均为既有VM夹具未提供动态import回调（ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING）；用HEAD 5bc3abae的共享控制器源码替换读取进行基线对照，仍同样4通过/2失败。相机VMD浏览器用例仍因其旧浏览器路径未配置跳过；没有将此结果描述为全仓测试通过。
