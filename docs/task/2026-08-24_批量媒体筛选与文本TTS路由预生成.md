# 任务：批量媒体筛选与文本 TTS 路由预生成

## 任务描述

批量模式增加文本、音频、图片、视频、网页五类选择框，控制端只上报所选类型，服务器负责最终筛选。文本播放增加基于手动语音能力的选中设备路由，并预先生成下一句，当前句结束后连续播放。

## Design 需求

- 见 `docs/design/text-media-routing.md`。
- 兼容缺少 `mediaTypes` 的旧控制端。
- 不自动上报“无扬声器/不可播放”；语音播放能力由控制端手动设置。
- 远程 TTS 必须有播放结束回执，不能以“已发送音频”代替“播放完成”。

## Spec 设计

- 见 `docs/spec/text-media-routing.md`。
- 协议字段：`mediaTypes`、`voiceTargetDisplayId`、`textPlaybackRemote`、`textSentenceTtsFinished`、`prefetch`。

## 受影响功能模块与代码

- 批量播放：`media-library.js`、`playlist-app-service.js`、`websocket.js`、`server-app.js`。
- 显示端文本播放：`text-media-player.js`、`display.html`。
- 文本 TTS：`text-media-tts-service.js`、`text-media-ws-integration.js`。
- 能力设置：`display-list.js`、`device-list.js`及服务器能力合并逻辑。

## 自测用例

1. 五类复选框默认全选，取消类型后请求仍包含未筛选的原始输入，服务器返回仅匹配项。
2. `mediaTypes` 缺失、空数组、未知值时保持旧版全部播放行为。
3. 当前显示端关闭语音播放时，服务器把文本 TTS 发到本次选中的首个语音设备。
4. 未选中语音设备时文本继续显示，当前句错误后继续下一句。
5. 当前句播放时只预生成一个下一句，结束后使用缓存；暂停/翻页/停止后旧回包无效。
6. 远程语音设备播放结束后，源显示端才请求/播放下一句。

## 兼容性测试

- 旧批量客户端不发送 `mediaTypes`。
- 旧文本客户端不发送路由和预生成字段。
- 图片/GIF、HTML/web、音频、视频既有播放流程不受影响。
- 显示端重连恢复批量文本时路由字段可用或安全降级。

## 性能测试

- 单显示端 TTS 仍按设备串行生成。
- 预生成上限为一个句子，避免 TTS 队列和内存无界增长。
- 批量筛选在服务器扫描阶段完成，不增加控制端文件遍历和传输。

## 风险评估

- 远程播放需要新增回执，旧显示端不能识别时按无回执错误超时/跳过策略兼容。
- 目标设备离线会导致当前句等待，服务端需返回可定位错误，不能阻塞整篇文本。
- 同一语音目标被多个源文本播放共享时，按播放上下文标识隔离回执。
