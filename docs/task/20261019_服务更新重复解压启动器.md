# 服务更新重复解压启动器

## 任务描述

Note8 更新服务时仍显示“解压 launcher”，即使签名清单的启动器指纹未变化。消除相同启动器的重复预解压，保留完整性校验与旧清单兼容。

## Design 需求与 Spec 设计

- 设计见 `docs/design/android-offline-js-launcher.md` 的“服务更新时重复解压 launcher 修复”。
- 伪代码见 `docs/spec/android-offline-js-launcher.md` 同名章节。
- 当前运行文件与已验签指纹相同即跳过 `stageLauncher` 的预解压；服务代码正常解压后必须再次核对签名启动器指纹。

## 受影响模块与代码

- `src/apps/server/boot/offline-launcher/releases.js`：提前判等，并在 `validateCode` 校验目标启动器文件集合。
- `tests/offline-js-launcher.test.js`：单次 code 解压、差异切换、旧清单和伪造指纹拒绝。
- 启动器 design/spec、todo、changelog 及 Offline 待出包状态。

## 自测、兼容与性能

- `npm run test:offline-launcher`：42/42 通过；相同指纹只记录一次 `code` 解压，未出现 `launcher` 解压；签名指纹与代码 ZIP 不符时拒绝健康提交。
- `node --test tests/offline-update-package.test.js`：17/17 通过；包构建器仍按内容变化递增独立启动器版本。
- 旧清单仍使用原始 ZIP 逐字节比较；不同指纹仍进入固定 supervisor 的切换/回退流程。
- 相同指纹减少一次代码包解压与目录写入，仍计算当前实际文件和目标解压文件的指纹。

## 风险与预计工时

- 修复修改启动器自身，首次安装修正版需要一次正常的启动器切换；后续纯服务更新才跳过。
- 预计 1–2 小时；Note8 真机连续两个版本的更新表现待出包后验收。
