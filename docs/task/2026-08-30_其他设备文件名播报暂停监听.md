# 其他设备文件名播报暂停监听

## 任务描述

修复其他显示设备播报媒体文件名时，非声纹模式的监听设备没有暂停录音的问题。文件名自动播报改用服务器统一 TTS 路由，使服务器能够广播播放状态。

## Design 需求

- 显示端不再本地生成和播放文件名 TTS。
- 文件名通过服务器统一 TTS 生成和下发。
- 复用现有 `voiceTtsPlaybackState` 跨设备状态、播放 ID 和完成回报。
- 非声纹设备收到任一目标设备的文件名播报状态时暂停监听，所有相关播报结束后恢复。

## Spec 设计

- 新增显示端到服务器的 `mediaNameTts` 请求。
- 服务端调用 `generateTtsWithFallback()`，再通过 `sendToDisplay()` 下发 `tts/playAudio`。
- 统一出口自动创建播放状态并广播，目标端继续回报 `voiceTtsPlaybackFinished`。

## 自测用例

1. 自动播报文件名时发送 `mediaNameTts`，不再直接调用本地 `playTTS`。
2. 服务端收到请求后使用统一 TTS 生成并向来源显示端下发 `tts/playAudio`。
3. 统一 TTS 下发产生 `voiceTtsPlaybackState`，其他非声纹监听端复用暂停逻辑。
4. 播放完成回报后，服务器广播结束状态并恢复监听。
5. 运行文件名 TTS 路由、显示端监听和 TTS 回归测试。

## 兼容性测试

- 手动 TTS、语音回复、天气播报和文本媒体 TTS 不改变。
- 自动播报关闭时不发送文件名 TTS 请求。
- 声纹模式继续保持录音，不受暂停逻辑影响。
- 目标显示端离线时沿用统一 TTS 的失败处理。

## 性能测试

- 文件名 TTS 增加一次显示端到服务器的 WebSocket 请求，但复用已有 TTS 生成调度和音频缓存路径。
- 同一文件名不新增重复播放；多显示端仍按各目标显示端原有播报语义处理。

## 风险评估

- 服务端 TTS 生成失败时文件名不会播报，但不会影响媒体文件本身播放。
- 播放状态依赖显示端完成回报，已有服务器超时机制负责兜底解除暂停。
