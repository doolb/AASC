# 五子棋游戏提示依赖回执文案

日期：2026-10-20

## 任务描述

按用户提供的最终文本替换当前游戏 `System:` 正文中的常驻提示：允许回复开头最多八条独立调用行；凡调用需要 GM 确认或查询数据，本次不继续发其他调用行；每次回复另起行附自然语言。目录与规则示例分别独占一行，目录结果返回后才按需查询规则。

## Design 需求与 Spec 设计

设计见 `docs/design/game-gomoku.md`，伪代码见 `docs/spec/game-gomoku.md`。继续由正式 `chatStream` 生成现有 raw 消息的 `System:` 标记，游戏桥仅替换其后拼接的提示正文。保留旧尖括号格式与现有最多八条的解析能力，新的等待约束只用于引导模型输出。

## 受影响模块与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：替换 `GAME_PROMPT`，将目录和规则示例拆为独立行。
- `tests/game-gomoku.test.js`：核对实际传给聊天服务的提示含等待与自然语言要求、目录和规则示例顺序。
- `docs/spec/game-gomoku.md`、`docs/design/game-gomoku.md`、`docs/usage/game-gomoku.md`、`docs/todo.md`、`changelog.md`：同步约束、待验收项与执行结果。

## 自测用例、兼容性与性能

运行 `npm run test:game-chat`，确认旧格式和多条合法调用仍可解析，用户落子仍须等 GM 回执再选择 AI 落子。此变更只修改静态提示，不增加网络调用或服务端持久状态；实际模型是否每次附自然语言仍需真实 Qwen 与显示端验收。

## 风险与预计工时

自然语言附在查询回复后，可能影响模型后续 GM 续接；保留桥接层过滤与权威棋盘校验并用既有测试覆盖。预计约一小时。

## 执行结果

已按用户最终文本替换 `GAME_PROMPT`，由原聊天服务继续生成 `System:` 前缀；目录和规则示例各占独立行。`npm run test:game-chat` 31/31 通过，覆盖新提示传递、旧格式、多条调用和 GM 确认后落子。

隔离真实 Qwen `aasc-qwen-flash` + 现有“小爱”角色 + 正式 `chatStream` 复测：模型依次发目录、等 GM、发规则、等 GM、开 9 路棋盘，快照版本 1。另一隔离会话再发送“我下 C3”：GM 确认 User C3，模型选择 AI H8，快照版本 3、轮到 User。该轮最终自然语言却误称“报错好几次”，与已成功的 GM 回执矛盾；需后续核对模型叙述与真实显示端体验。隔离棋局及聊天状态在测试结束后清理，没有改动正式棋盘。
