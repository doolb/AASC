# Offline 发布更新日志

## 任务描述

为 Offline min APK 热更新增加发布更新日志：发布者在生成签名清单时接收本次版本的日志，Android Offline APK 检测到新版本后在更新卡片中展示版本、大小和更新内容。

## design 需求

- 发布日志属于 `payload.components.apkMin`，随签名清单一起签名和发布。
- 支持 `--release-notes-file` 读取 UTF-8 文本；日志为空时省略字段，保持旧清单兼容。
- 日志首尾空白裁剪、限制 4096 个 Unicode 字符，保留内部换行；超限在打包阶段拒绝。
- 更新卡片显示日志标题和内容；无日志时继续显示原有版本/大小文本。
- 长日志最多展示 6 行并省略尾部，不遮挡控制端按钮和诊断浮层。

## spec 设计

```text
createOfflineMinApkArtifact(options):
    releaseNotes = read options.releaseNotesFile as UTF-8 text when provided
    releaseNotes = trim(releaseNotes)
    require Unicode character count <= 4096
    apkMin = {versionCode, versionName, ..., sha256}
    如果 releaseNotes 非空：apkMin.releaseNotes = releaseNotes
    对 payload 重新签名并验证

OfflineUpdateManifest.parse:
    解析 apkMin.releaseNotes（可选）
    如果存在：必须是字符串，trim 后长度 <= 4096
    缺少字段时返回 null

MainActivity.showMinApkUpdatePrompt:
    显示版本和下载大小
    如果 releaseNotes 非空：显示“更新内容”及日志，最多 6 行并省略尾部
    否则隐藏日志区域
```

## 受影响的功能模块和代码

- `scripts/ops/offline-min-apk-package.js`：增加日志文件读取、长度校验和 CLI 参数。
- `OfflineUpdateManifest.kt`：解析并校验可选日志；`OfflineUpdateManager` 复用现有清单对象传递流程，无需改变下载逻辑。
- `MainActivity.kt`、`activity_main.xml`、`strings.xml`：更新卡片展示日志。
- `tests/offline-min-apk-package.test.js`、`tests/android-offline-apk.test.js`、`OfflineUpdateManifestTest.kt`：覆盖发布、验签、显示和旧清单回退。
- `docs/design/android-offline-hot-update.md`、`docs/spec/android-offline-hot-update.md`、Offline APK design/spec、todo/changelog：同步记录。

## 自测用例

- 日志文件写入签名清单，签名验证后内容保持一致。
- 缺少日志字段的旧清单解析成功，更新卡片隐藏日志区域。
- 4097 个 Unicode 字符被拒绝；空白日志不写入字段。
- Android 更新卡片显示日志，超过 6 行时省略尾部。
- 现有 Offline 静态回归、Android JVM 单测和发布器测试通过。

## 兼容性测试

- Android 9/API 28、SM-N9500、Display 2 Desktop 虚拟屏。
- v10 清单作为无日志旧版本仍能被新代码解析；新日志字段不影响 code/dependencies 更新。

## 性能测试

- 日志只在清单读取和更新卡片展示时处理，限制 4096 字符，不增加 APK 下载量。

## 风险评估

- 日志文本来自签名清单，不能由未签名服务器响应修改；显示使用 TextView，不执行 HTML/Markdown。
- 过长内容被限制为 6 行，完整日志仍保留在发布清单中供发布端查看。
