# 任务：TTS 压测脚本

## 任务描述

- 目标：新增可复用压测脚本，量化 TTS 生成链路在并发场景下的稳定性和内存变化
- 范围：新增脚本与文档，不改动业务协议

## Design 需求

- 脚本直接调用 `/api/tts/generate`
- 支持配置总请求数、并发、超时、输出频率、文本/音色/语速
- 默认联动 `/api/system-stats`，输出服务端内存峰值和曲线
- 支持关闭服务端采样，用于轻量连通性测试

## Spec 设计（伪代码）

```
main():
    args = parseArgs()
    body = {text, voice?, speed?}

    if pollSystemStats:
        startSystemStatsPolling()

    启动 N 个 worker:
        循环发送 /api/tts/generate
        统计 success/failed/latency
        周期输出本地进程内存

    等待全部 worker 完成
    stopSystemStatsPolling()
    输出汇总 + 服务端峰值 + ASCII 曲线
```

## 自测用例

- 用例1：默认参数运行脚本
  - 预期：输出进度、成功率和内存统计
- 用例2：`--no-system-stats`
  - 预期：不访问 `/api/system-stats`，其余逻辑正常
- 用例3：服务端不可用
  - 预期：请求失败计数递增，脚本可结束并给出错误统计

## 兼容性测试

- 不影响现有 `/api/tts/generate` 协议
- 不影响服务端主流程和前端调用路径

## 性能测试

- 以 `--total 100 --concurrency 10` 观察服务端 RSS 峰值
- 对比加固前后曲线波动和失败率

## 风险评估

- 文本过长可能放大上游 TTS 处理时延，需要结合业务文本长度调参
- 高并发压测会触发真实 TTS 服务负载，需在测试环境执行

## 预计工时

- 约 1 小时（脚本 0.7h + 文档 0.3h）
