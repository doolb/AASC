## Design与Spec

现有chat-system默认规则修订为图片true/视频false，新增/旧配置/HTML/编辑/保存回退一致，不覆盖显式true。配置沿既有WS持久化。生视频证据与拟方案见design/chat-video.md和spec/chat-video.md；暂不接入视频运行逻辑。

## 需求分析

默认enterprise；主L6媒体契约、次L5默认规则/任务流程，风险低（默认值）至中（视频Provider异步协议）。证据为“视频上传开关默认关闭”“豆包,qwen,glm生成视频”“接入聊天里”。评分层级24/25、证据18/20、完备17/20、风险19/20、落地14/15，总92；强证据L6两条/L5一条、邻层系数0.9，置信度0.60。默认值可开发并已确认；视频需真实任务创建与结果结构补充后实施。建议下放L4为默认规范化与表单数据流、VideoJob提交/查询/落盘/同消息替换。

修改llm-service.js、chat.js、upload.html、self-test.js及媒体配置/浏览器测试。新旧字段缺省false、显式true/false保留；新建表单不勾选、编辑旧配置不勾选、保存与权威同步一致；图片仍默认true。npm run test:chat-images 35/35，补充明确true/新增默认值后的定向7/7通过。无新增网络功能或原生修改；servicePackage=true待构建，未部署。预计默认值20分钟，视频核查约30分钟，后续实现需方案确认。
