# MMD AR低模浅凹AO抑制

## 需求与确认

拉近相机后低模内凹面交界出现明显AO暗带。用户确认增加可调角度门限，法线保持原样。设计见 `docs/design/mmd-ar-test-apk.md`；算法伪代码见 `docs/spec/mmd-ar-test-apk.md`，已先于代码更新。

## 实施范围

- `display-pmx-ao.mjs`：原AO与合成补算复用同一角度权重函数/门限，未设置保留旧默认。
- `web-panel-groups.js`：灯光AO分类增加0–45度滑块、默认10度、本地保存与灯光恢复默认。
- 既有构建复制上述资源并生成指纹；生成web-dist，不改构建入口、不构建APK。
- 更新使用、README、自测记录与发布状态；已有servicePackage=true保持。

## 手工验收用例（待执行）

1. 拉近同一低模内凹交界，比较4.5/10/20度，确认暗带随门限提高减弱，模型法线预览不改变。
2. 半/全分辨率、边界修正开关均生效，半分辨率补算没有旧门限暗线。
3. 刷新恢复保存值，灯光恢复默认回10度；存储受限时本次调整仍有效。
4. 发丝/衣服接触处仍有较陡遮蔽，较大门限使浅凹AO减弱为预期限制。
5. 正式显示端无测试设置时保留旧默认；纯网页无原生定位桥仍使用MindAR。

## 检查、兼容与性能

仅静态语法、差异和网页构建；本轮不新增或执行测试，手机视觉待手工验收。共享shader支持WebGL2，沿用原采样数量、深度图、模糊与补算；仅每帧计算一次正弦并更新两组uniform，无额外渲染通道。独立APK下次构建会带相同资源，本轮不声称已同步APK。

## 风险与预计工时

无法单凭同一深度几何区分低模折痕和真实浅凹，抑制会同时影响二者。默认10度为可调整起始值；正式端原行为不变。预计实现/构建约20分钟，设备验收另计。
