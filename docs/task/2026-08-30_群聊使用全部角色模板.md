# 群聊使用全部角色模板

## 任务描述

当前控制端群聊会根据消息前缀选择单个角色模板，并删除角色名前缀；没有前缀时还会默认选择第一个模板。子显示端语音也可能只把匹配到的单个助手模板作为系统提示词。群聊应同时提供全部已配置角色模板，用户原始消息完整保留。

## Design 需求

- 群聊从控制端“模板”列表读取全部角色模板，按角色名和模板内容组合为统一系统提示词。
- 用户消息原样发送，例如 `小爱，今天天气怎么样` 不删除“小爱”或其他前缀。
- 控制端文本群聊、主显示端语音群聊和子显示端语音群聊使用同一规则。
- 私聊继续只使用选中的单个模板；工作 AI 角色继续使用 Agent 自己的角色配置。
- 群聊历史继续使用统一群聊会话，不按单个角色模板切分。

## Spec 设计

- `getGroupSystemPrompt()`：读取当前 `chatTemplates`，拼接基础系统提示词和所有非空角色模板；没有角色模板时返回基础系统提示词。
- `handleChatMessage(options)`：`mode === 'group'` 时忽略单角色 `templateTarget` 和语音传入的单角色提示词，使用 `getGroupSystemPrompt()`；`mode === 'private'` 时保持原单模板逻辑。
- 控制端群聊：保留 `content === displayContent === 用户原始消息`，不设置 `templateTarget`。
- 语音群聊：角色名只参与等待唤醒状态的输入接受判断，`voiceCommand` 解析出的 chat 消息保持完整原文并显式按 `group` 处理。

## 受影响的功能模块和代码

- `src/external/llm/llm-service.js`：群聊系统提示词组合。
- `src/apps/server/boot/server-app.js`：普通聊天、语音聊天的群聊路由。
- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：语音角色名前缀保留。
- `src/apps/server/modules/voice/display-voice-conversation.js`：等待唤醒时接受角色名加消息。
- `src/apps/web-mediacenter/ui/public/js/chat.js`：控制端群聊不再裁剪角色名前缀。
- `tests/group-chat-templates.test.js`、`tests/display-voice-conversation.test.js`、`tests/chat-stream-request-id.test.js`：行为和契约回归。

## 自测用例

1. 配置“小爱”和“妲己”两个模板，群聊请求同时包含两个角色模板和基础系统提示词。
2. 发送“小爱，今天天气怎么样”，请求消息仍完整包含“小爱”，未设置单角色模板目标。
3. 子显示端等待唤醒时发送带角色名的语音，进入群聊输入；不带角色名的普通聊天仍需唤醒词。
4. 私聊角色请求仍只发送目标角色模板，工作 AI 角色请求不走普通 LLM 群聊提示词。
5. 群聊上下文条数大于 0 时继续带统一群聊历史。

## 兼容性测试

- 无模板时使用基础系统提示词。
- 旧控制端仍可发送 `templateTarget`，私聊行为不变；群聊由服务端统一收敛为全部模板。
- 主显示端、子显示端和控制端三种输入来源均使用群聊原始消息。

## 性能测试

- 模板只在请求组装时遍历一次，不新增 WebSocket、录音链路或 TTS 队列。
- 群聊提示词受现有 `maxTokens` 和历史预算限制。
- 页面脚本编译和 `git diff --check` 通过。

## 风险评估

- 多个模板会增加系统提示词 token 占用，现有最大 token 和历史预算会减少可用历史或输出空间。
- 多个角色模板可能存在指令冲突，通过角色名称分隔和群聊综合回答说明降低歧义。

## 预计工时

约 1 小时。

## 实现结果

- 新增 `getGroupSystemPrompt()`，将当前聊天模板列表中的全部角色名称和模板内容拼接到群聊系统提示词。
- 控制端群聊不再按角色名前缀选择单一模板或裁剪消息；带角色名的群聊消息也跳过控制端本地内置命令分流。
- 子显示端和主显示端语音将角色名用于群聊输入接受判断，发送给 AI 的文本保留完整原文。
- 服务端群聊强制清除旧客户端传入的单角色 `templateTarget`，统一使用群聊模板和 `group/default` 历史分区；私聊、工作 AI Agent 保持原逻辑。
- 验证：群聊模板、控制端路由、语音会话和相关 LLM/显示端回归共 33/33 通过；页面内联脚本编译和 `git diff --check` 通过。
