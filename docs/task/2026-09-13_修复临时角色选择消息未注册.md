# 修复临时角色选择消息未注册

## 任务描述

控制端临时页签选择角色后一直不能再次选择，角色选择器保持禁用。

## 根因

服务端已经实现 startTemporaryConversation 的 Fallback 处理，但没有把消息类型加入控制端 WebSocket controlTypes 注册表。消息未进入 Fallback，控制端收不到成功或失败回包，temporaryRolePending 无法清除。

## 修复方案

- 将 startTemporaryConversation 加入服务端控制端消息类型注册表。
- 保持现有单组临时会话替换逻辑和错误回包逻辑不变。
- 增加回归断言，确保处理分支和消息注册同时存在。

## 受影响文件

- src/apps/server/boot/server-app.js
- tests/temporary-role-contract.test.js
- docs/design/chat-system.md
- docs/spec/chat-system.md

## 自测用例

1. 控制端选择第一个临时角色，收到服务端快照后选择器恢复可用。
2. 不刷新页面再次选择另一个临时角色，旧临时会话被替换。
3. 选择不存在的角色时收到 temporaryConversationError，选择器恢复可用。
4. 通过 SSH 执行定向测试和完整 npm test。

## 执行结果

- 定向测试：temporary-role-contract 2/2、display-voice-conversation 11/11、server-app 语法检查通过。
- 完整测试：667 项中 663 项通过，4 项失败均为已有显示端 injectTouch、睡眠模式、语音监听和本地声纹策略契约失败；临时角色契约测试通过。
- 远端服务：通过 SSH 执行 npm run restart:server，/api/chat/config 健康检查通过。

## 兼容性与风险评估

本次仅补充已有消息的 WebSocket 注册，不改变配置文件、临时会话数据结构或普通群聊/私聊流程；风险为新增消息现在会正确进入既有处理器。
