# Termux 服务器代码下发与双进程热更

## 任务描述

通过主服务器 `/server` 下发服务器代码，由 Termux Bootstrap 校验、安装并重启现有双进程服务器；更新失败时恢复旧代码。

## Design 需求

- Termux 继续使用 `npm start` 和现有 `server-launcher.js`/`server-app.js` 双进程结构。
- Bootstrap 是一次性更新工具，不常驻、不创建第三个 Node 服务进程。
- 主服务器提供版本清单和 gzip 代码包。
- 代码包只包含 `src/`、`package.json`、`package-lock.json`；安装 `src/` 时合并覆盖，保留未随包发布的本地目录。
- 不覆盖 Termux 的 `config/`、`res` 用户资源和任务运行数据、`node_modules/`、`logs/` 和 HTTPS 证书。
- 停止服务后更新，启动后检查健康接口，失败恢复旧版本。

## Spec 设计

1. 新增发布服务，计算代码包大小和 SHA-256，并提供 `/server` 与 `/server/package`。
2. 新增无第三方依赖的 Termux Bootstrap：`run` 使用启动器双进程运行，`update` 执行下载、校验、备份、复制、重启和回滚。
3. Bootstrap 支持 `sv stop/start`，同时允许测试注入直接停止/启动函数。
4. 更新包解压必须限制在 staging 目录并拒绝路径穿越。

## 自测用例

- 发布清单稳定返回版本、大小、SHA-256 和包地址。
- 代码包只包含白名单路径，不包含日志、`3rd`、依赖、配置、媒体、任务运行数据、模型和证书。
- Bootstrap 校验错误大小、错误 SHA-256 和路径穿越包时拒绝更新。
- 更新成功会停止并重新启动服务，且保留配置、媒体、依赖和日志。
- 健康检查失败会执行旧代码回滚。
- `run` 模式只产生启动器和服务两个 Node 进程。

## Termux 真实验收

- 目标设备：ADB `192.168.1.6:5555`，Android 9，arm64，Termux 0.118.3。
- 启动 `aasc-server-test`，检查 `/api/status`、`/upload`、`/display`。
- 检查节点向主服务器注册并能发送心跳。
- 从主服务器下载代码包，执行一次成功热更并检查服务恢复。
- 使用故意错误包验证回滚后 `/api/status` 恢复。
- 检查 Node 进程分别为启动器和服务进程，未遗留旧进程。

## 兼容性测试

- 保留 `/api/subservers`、`/display`、`/upload` 和现有 WebSocket 路径。
- 主服务器 HTTPS 自签名证书和 Termux 现有证书不被覆盖。
- `node_modules` 不重新安装，依赖版本沿用 Termux 当前安装。

## 性能测试

- 清单读取复用包缓存，不重复打包。
- 代码包下载使用流式传输，更新过程中不把整个包长期保存在内存中。
- 记录下载、校验、停止、启动和健康检查耗时。

## 风险评估

- `/server` 当前无认证，包内容可被局域网访问；认证后续补充。
- 更新期间服务会短暂不可用；健康检查失败时会再执行一次回滚重启。
- 若 Termux 被 Android 系统冻结，runit 和直接启动都可能无法维持进程；本次只验收当前在线设备。
