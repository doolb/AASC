# 显示端监听状态与最近识别文本

## 任务描述

将控制端显示端列表中的语音监听能力从“⚙️ 能力设置”弹窗中独立出来，直接显示每个显示端的监听开关、当前监听状态和最近一次 ASR 回传文本。

## Design 需求

- 每个显示端条目直接显示监听开关，不需要打开能力设置。
- 状态至少区分监听中、等待唤醒、已关闭和不可用。
- 收到 `voiceInput` 时按 `displayId` 更新最近识别文本，并区分 partial/final。
- 监听开关继续复用 `capabilities.voiceRecording` 和 `updateCapabilities` 协议。
- 不改变唤醒词、私聊/群聊、TTS 完成后计时和声纹门控流程。

## Spec 设计

```text
DeviceList.displayVoiceInputs[displayId] = { text, isFinal, timestamp }
voiceInput -> 保存对应显示端最近文本 -> DeviceList.render()
点击监听开关 -> 合并当前 capabilities -> 只修改 voiceRecording -> updateCapabilities
状态优先级: 不可用 > 已关闭 > 监听中 > 等待唤醒 > 已启用
```

## 自测用例

- 显示端条目直接存在监听开关，不依赖能力设置弹窗。
- `voiceRecording=false` 显示“已关闭”，点击开关发送 `updateCapabilities`。
- `voiceListening=true` 显示“监听中”；等待唤醒状态显示“等待唤醒”。
- 不支持录音时显示“不可用”。
- `voiceInput` 只更新对应 displayId 的最近文本，不串到其他显示端。
- partial/final 文本标记正确，原有 Chat 处理仍被调用。

## 兼容性测试

- 控制端无 WebSocket 或无显示端时不抛异常。
- 子显示端和普通 Display 均使用同一显示列表逻辑。
- 旧显示端缺失对话状态时仍可根据 `voiceSupported`、`voiceListening` 和 `voiceRecording` 显示状态。

## 性能测试

- 每次语音回传只重绘控制端显示列表，不触发 ASR/TTS 或服务器额外请求。
- 最近文本只保留每个显示端一条，不持续增长内存。

## 风险评估

- 控制端刷新页面后最近识别文本清空；它仅用于当前页面观察，不作为业务历史。
- 直接开关和能力弹窗同时操作时，服务端最后一次 `updateCapabilities` 生效。
