# 豆包纯Node会话复用（实现完成）

- 任务描述：按Qwen已有Responses方式复用豆包上游会话，下一轮只发新增输入，保持纯Node传输。
- design需求：`docs/design/chat2api-doubao-web.md`文首会话复用需求；复用现有普通LLM引用、账号绑定及私有会话存储。
- spec设计：`docs/spec/chat2api-doubao-web.md`文首L4草案；ready/uncertain状态、候选续接字段、完整回复提交、流式锁与失败隔离。
- 需求分析：主L6（Provider续接契约），次L5（状态流），落实为L4字段和流程；新增状态不得与旧observed字段混用。
- 受影响代码：新增`chat2api-doubao-session.js`及测试；修改`chat2api-doubao-chat-adapter.js`、`chat2api-doubao-node-protocol.js`、`chat2api-responses-service.js`、`chat2api-response-session-store.js`、`chat2api-provider-registry.js`及对应测试。Core和llm-service复用既有绑定/引用机制，定向验证。
- 自测用例：两轮同ID且不重放历史、ACK与完成事务、旧观测兼容、身份/模式隔离、流式/非流式、取消/超时/未消费、同会话串行/不同会话独立、Store恢复与Pi snapshot/delta。
- 兼容性：Qwen及其它Provider、无状态chat/completions、Cookie-only网页和WAV/TTS保持既有行为；只把通过真实验证的Node状态加入续接能力。
- 性能测试：同会话并发正确排队且取消可退出；未消费锁按原请求时限释放；继续256KiB/8MiB/120秒限制，不新增无限会话队列。

- 预计工时：约半日至一日，受真实协议字段验证影响。
- 不明确项：section/index的必要性与来源以获授权短对话验证为准；浏览器模式及think/expert原生续接不列入首轮。
