# 显示端录音模式与控制端回放

## 任务描述

在控制端显示面板增加显示端录音模式选择，支持普通 ASR、最长 60 秒单次录音和边录边回传的实时录音；单次/实时模式不调用 ASR，只将音频回传控制端播放。

## Design 需求

- 使用当前 `PcmAudioCapture` 和 VAD 逻辑，保持 16kHz 单声道音频格式。
- `asr` 保持现有语音监听和 ASR 识别行为。
- `single` 返回完整 WAV，`realtime` 返回 PCM16 分片；两者不进入 ASR、声纹或 `voiceInput`。
- 服务端按控制端连接和 `requestId` 定向转发，限制同一显示端并发请求和 60 秒最大时长。

## Spec 设计

- 新增 `VoiceRecordingMode`、`DisplayRecordingSession` 和三组 WebSocket 消息。
- `PcmAudioCapture` 增加流式 PCM 回调能力，但保留既有完整 WAV 和分段行为。
- 控制端 VAD 卡片增加模式选择、录音按钮、状态反馈和 WAV/Web Audio 播放；树形显示端节点只保留监听开关。

## 自测用例

1. 默认 `asr` 模式保持现有 ASR 上传，新增模式不调用 `/api/asr/recognize`。
2. `single` 模式检测到语音结束后返回 WAV，最长 60 秒，控制端可播放。
3. `realtime` 模式按递增序号回传 PCM 分片，控制端连续播放且不创建大量独立音频元素。
4. 同一显示端重复开始、非法模式、无录音能力、显示端/控制端断开均返回结构化错误并清理状态。
5. 切换模式时不同时创建两条麦克风采集链路，切回 `asr` 后自动监听可恢复。

## 兼容性测试

- 普通浏览器显示端和 Android APK WebView 均继续使用服务器提供的 `display.html`。
- 旧显示端不处理新消息时，旧 ASR/媒体/TTS 消息继续按原流程运行。
- 服务器 ASR 开关关闭不影响 `single`/`realtime` 回传。
- 控制端浏览器不支持 Web Audio 时，单次 WAV 仍保留手动播放降级。

## 性能测试

- 单次录音最多回传一份不超过 60 秒的 WAV。
- 实时模式仅保留短 PCM 分片和播放队列，不在服务端累积整段音频。
- 实时播放使用单个 AudioContext 的时间轴排队，避免每个分片创建独立 HTMLAudioElement。

## 风险评估

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 实时分片网络抖动造成卡顿 | 中 | 控制端保留 50ms 起始缓冲并按 AudioContext 时间轴排队 |
| 麦克风与持续 ASR 监听冲突 | 中 | 模式切换停止未完成 ASR 段，同一显示端只维护一个采集 session |
| 音频消息过大或串会话 | 中 | 单次限制 60 秒，实时限制序号、session、目标 socket 和超时 |
| 旧客户端不认识新消息 | 低 | 新功能只由新控制端触发，旧消息类型和 ASR 链路不改变 |
