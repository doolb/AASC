# 任务：显示端语音唤醒与监听控制

## 任务描述

让正式显示端支持唤醒词、3 分钟无有效对话后重新唤醒，以及控制端按显示端关闭语音监听；关闭声纹识别时仍可使用 ASR、唤醒词和对话。

## Design 需求

- 见 `docs/design/display-voice-conversation.md`。
- `voiceRecording` 用户能力作为对应显示端的监听开关。
- 声纹开关与监听开关分离。
- TTS 全部实际播放结束后再启动 3 分钟计时。

## Spec 设计

- 见 `docs/spec/display-voice-conversation.md`。
- 服务端按 displayId 校验监听能力和语音会话状态。
- 显示端复用 TTS 队列结束回调和已有 ASR 结果显示。

## 自测用例

1. 关闭单个显示端“语音录音”能力后，该显示端立即停止录音，TTS 结束不自动恢复。
2. 重新开启后进入等待唤醒，普通文本不触发命令。
3. `你好小爱`、`小爱你好` 可唤醒；`小爱开始对话` 可进入小爱私聊。
4. 私聊中说 `妲己开始对话` 可切换目标；`结束对话` 可重新等待唤醒。
5. 有效回复的多段 TTS 全部播放结束后才开始 180 秒计时。
6. 180 秒无有效对话后，普通语音被丢弃，重新说唤醒词才恢复处理。
7. 关闭声纹后，普通 ASR 仍能触发唤醒和对话；未注册说话人不再被声纹过滤。

## 兼容性测试

- 普通浏览器显示端、Android Display APK、旧子显示端连接均可工作。
- 旧 Go/C#/Node 子显示端继续使用原有语音命令流程，不要求新增唤醒协议。
- 声纹开/关、多人模式开/关、TTS 播放和 WebSocket 重连组合验证。
- 控制端能力编辑器仍可保存其他显示能力。

## 性能测试

- 监听开关切换不增加轮询；只使用已有 WebSocket 消息。
- 计时器每个显示端最多一个，重复 TTS 结束会清理并重建，不产生计时器泄漏。

## 风险评估

- 现有聊天会话状态部分是全局的，显示端唤醒状态必须按 displayId 管理，避免监听状态串台。
- 旧协议没有 TTS 完成回执，计时逻辑仅绑定正式网页自身可观察的音频 ended/error 事件。
- 关闭声纹后任何人都可以唤醒和发送对话，属于预期行为。
