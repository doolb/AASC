# Node子显示端裁剪移动

状态：用户已确认，源码与自动验证完成；Windows实际画面待现场验收。

- 任务描述：让Node端常驻mpv的视频/图片随控制端裁剪框拖动而移动可见区域，并支持缩放、位置尺寸输入及已有四方向旋转。
- design需求：见 `docs/design/node-display-mpv.md` 的裁剪移动追加需求；复用既有控制端与AASC消息、持久化和状态恢复。
- spec设计：见 `docs/spec/node-display-mpv.md` 的裁剪移动伪代码；等比缩放使用zoom、位置使用pan，连续输入合并、旧版本作废，切换模式复位。
- 受影响模块与代码：修改 `src/apps/voice-display-node/mpv-player.js`、`tests/node-display-mpv.test.js` 与 `tests/node-display-mpv-render.integration.js`；既有geometry/controller及服务端消息可复用，无需修改。同步usage/self-test/design/spec/task/todo/changelog。
- 自测用例：横纵移动、四角及边界、缩放、四方向、尺寸延迟就绪、无scale属性的旧mpv、连续输入最后值、切换填充无偏移、恢复状态、PID保持及TTS独立。
- 兼容性测试：Linux隔离Xvnc实际像素；Windows命名管道专项回归与目标机器验收，不能以IPC回执代替画面结果。
- 性能测试：合并高频拖动，至多一个更新任务，无无限队列；媒体/模式切换后无过期写入。
- 风险评估：不同mpv版本的属性支持、旋转后坐标与预览一致性、归零造成跳闪、等待命令回执的代次处理。排查时普通裁剪已有计算但无移动实屏结果；已通过zoom/pan、合并任务及Linux真实图片/视频像素验证处理，Windows现场结果仍待验收。
- 预计工时：约1～2小时实现与自动验证，Windows设备验收另计。
- 范围确认：用户确认“裁剪移动”为现有裁剪框拖动与位置输入，按已告知的四方向、zoom/pan和连续输入合并方案实施。
- 验证结果：`npm run test:node-display-mpv`21/21、`npm run test:node-display-mpv:render`2/2、`npm run test:node-display-mpv:real`1/1、`npm run test:offline-voice-display-node`22/22，共46项、零跳过。四方向16个裁剪位置及视频2个位置的像素符合期望，缩放减半及contain复位通过，PID保持；无scale旧版本和Linux/Windows协议通过。200次在途输入合并为少于20次写入，无归零中间值。
- 发布边界：仅Node代码变化，voiceDisplayNodePackage保持true；其他状态不变，未构建发布独立包或修改本机播放器配置。完成实现项从todo删除，Windows现场验收保留。
