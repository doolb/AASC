# Android 子服务器波浪号媒体路径映射

## 任务描述

将 Android APK 子服务器媒体库配置中的 `~/` 定位到应用专属外部目录 `/storage/emulated/0/Android/data/com.aasc.display/files`，同时保留 Node 子服务器内部 `HOME` 的私有目录语义，并兼容已经写入字面 `files/aasc-server/~` 的上传文件。

## Design 需求

- Android Service 使用 `getExternalFilesDir(null)` 获取实际目录，不硬编码包路径。
- 通过已有 Node 进程环境传递 `AASC_ANDROID_MEDIA_HOME`。
- LocalProvider 仅解析 `~`、`~/` 和 `~/子路径`，其他路径行为不变。
- 迁移旧字面目录时不覆盖外部目录中的同名文件；跨文件系统使用复制后删除。
- API 29+ 的 SAF provider 继续使用独立虚拟根 `/`，不与 `~/` 别名冲突。

## Spec 设计（伪代码）

```text
NodeServerService.startNodeProcess
    → root = NodeRuntimeInstaller.ensureInstalled()
    → androidMediaHome = getExternalFilesDir(null)
    → androidMediaHome 存在且为目录时设置 AASC_ANDROID_MEDIA_HOME=绝对路径
    → 否则不设置变量，保留 Node HOME 下的普通回退

LocalProvider(config.path)
    → path 为 ~、~/ 或 ~/子路径时：basePath = resolve(AASC_ANDROID_MEDIA_HOME 或 os.homedir, 子路径)
    → 其他 path：basePath = path.resolve(path)
    → Android 别名且旧字面目录存在时：connect 阶段逐项迁移
    → 目标同名：跳过并保留两边文件
    → rename 失败：复制目标后删除源文件
```

## 自测用例

- `~/` 解析为 `/storage/emulated/0/Android/data/com.aasc.display/files`。
- `~/photos` 解析为外部媒体根下的 `photos`。
- 旧字面目录文件可迁移；同名文件不覆盖。
- 模拟跨文件系统 `rename` 失败时，复制后删除成功。
- Android Service 环境包含 `AASC_ANDROID_MEDIA_HOME`，内部 `HOME` 不变。

## 兼容性测试

- 非 Android 环境的 `~/` 回退到 `os.homedir()`。
- Android API 28 直接路径媒体库保持可用。
- Android API 29+ SAF 虚拟 `/` provider 行为保持不变。

## 性能测试

- 仅在 Node 启动时对旧字面目录做一次浅层遍历；正常启动不扫描外部媒体目录。
- 迁移按文件执行，不影响新媒体库请求处理。

## 风险评估和预计工时

- 风险：外部目录不可用、授权变化或跨文件系统复制失败；均回退/记录错误，不阻断 Node 服务启动。
- 预计工时：1 小时。
