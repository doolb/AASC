# 2026-09-24 批量图片切换打断 TTS 修复

## 任务描述

用户反馈显示端批量播放切到下一张图片时，TTS 中断并回退播放，可能持续循环。当前 `showMedia()` 在每次切项时都对隐藏的音视频元素执行 `pause()`、清空来源和 `load()`；TTS 焦点恢复也可能对已在播放的元素再次调用 `play()`。

## 需求判级

- 默认 enterprise：主等级 L5（图片切项与 TTS 播放状态），次等级 L4（元素清理和恢复条件）；结论可开发，风险中，置信度 0.78。
- 已有声明：`playlistState.index`、`currentMediaType`、`mediaVideo`、`mediaAudio`、`ttsAudio.paused`。
- 新增定义：`previousMediaType` 与元素当前来源是否有效；不新增跨端消息或配置。
- L4 操作：读取前后媒体类型；只清理持有旧音视频来源的元素；图片切图仅替换图片来源；TTS 已在播放时跳过恢复调用。
- 下放判定：建议下放到 L4；断点是用户未区分自动/手动切项及 TTS 类型，按共用 `showMedia()` 与统一 TTS 音频元素覆盖两类路径。

## Design 需求与 Spec 设计

- 图片切图不重置未使用的音视频元素，减少 WebView 音频焦点扰动。
- 视频、音频跨类型切换继续释放旧来源和监听。
- TTS 恢复仅针对已暂停且未结束的当前语音，保留新语音首次播放。

## 自测用例

- 批量图片按间隔自动切换、手动下一张和循环回绕时，正在播放的聊天 TTS 不应中断、回退或重播。
- 勾选播报文件名时，文件名 TTS 继续按队列播报；图片切换不重置当前语音。
- 图片转视频/音频、视频/音频转图片时，旧媒体来源按需释放且新媒体正常播放。
- TTS 真实暂停后可有限次数恢复，正在播放时不重复调用 `play()`。

## 兼容性、性能与风险

- 不改服务端协议、播放列表数据结构或 Android 原生代码。
- 纯图片切项减少不必要的 `load()`；预计工时约 1 小时。
- WebView 音频焦点仍需在用户现场复现验证；若还有原生音频焦点事件，需要按日志继续定位。
