# MNN 编译命令固定路径

## 任务描述

记录当前项目已有的 MNN 源码路径和固定 revision，新增一个不需要手动填写环境变量的 npm 编译命令，同时保留 APK 构建流程的兼容入口。

## design 需求

- 默认复用 `build/third_party/MNN`，避免重新 clone 到临时目录。
- 默认使用已验证的 MNN revision `d407447ed56c4121a11ccbd266dc184ca1ead0c2`。
- 默认使用 NDK `28.2.13676358`。
- 保留环境变量覆盖，以支持其他机器和 CI。

## spec 设计

```text
buildMnnCommand:
  root = AASC_MNN_ROOT or projectRoot/build/third_party/MNN
  revision = AASC_MNN_REVISION or pinnedRevision
  ndk = ANDROID_NDK_HOME or ANDROID_HOME/ndk/28.2.13676358
  run existing MNN Android build script at root
  run make install
  write native artifact manifest

npm build:mnnllm-android:
  invoke buildMnnCommand

npm prepare:mnnllm-android:
  invoke the same buildMnnCommand for build:apk compatibility
```

## 受影响模块和代码

- `scripts/ops/prepare-mnnllm-android.js`
- `scripts/ops/mnn-build-config.js`
- `scripts/ops/build-apk.js`

- `tests/mnn-build-command.test.js`
- `docs/design/android-mnnchat-llm.md`
- `docs/spec/android-mnnchat-llm.md`

## 自测用例

- 检查 npm 同时存在 `build:mnnllm-android` 和 `prepare:mnnllm-android`。
- 检查脚本包含仓库默认 MNN 路径、固定 revision 和默认 NDK 版本。
- 检查环境变量仍可覆盖默认配置。
- 执行 `npm run build:mnnllm-android`，确认使用现有 MNN checkout 并生成 ready manifest。

## 兼容性测试

- 不改变 `build:apk`、`build:apk:offline` 和 `build:apk:offline:min` 的入口。
- 不改变 MNN ABI、编译选项、16 KB page-size 链接参数和 APK native 产物。
- 未重新生成完整 APK。

## 性能测试

- 只验证 MNN 原生增量编译命令；不增加 APK 启动阶段的网络下载。
- 已有完整 native 产物时由 MNN/CMake/make 自身决定增量复用。

## 风险评估

- 默认目录不存在时仍可能触发官方 MNN clone，需要网络；目录已存在且包含固定 revision 时不需要 fetch。
- 默认 NDK 路径仅适用于当前开发环境，其他环境可通过 `ANDROID_NDK_HOME` 覆盖。

## 2026-09-22 构建路径传递修复

- `prepare-mnnllm-android.js` 的默认 root/revision 与 `build-apk.js`、Gradle 共用同一解析模块。
- `build-apk.js` 在执行准备脚本后，将 root/revision 通过 Gradle `-P` 参数传入，不再依赖父 shell 的环境变量。
- `app/build.gradle.kts` 直接运行时回退到 `build/third_party/MNN` 和固定 revision；如果 checkout 不存在或缺少 `CMakeLists.txt`，给出明确错误。
- 这样 `npm run build:apk*` 与 `./gradlew :app:testDebugUnitTest` 使用相同 MNN 配置。
