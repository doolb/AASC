# 语音命令 TTS 单目标动态路由

## 任务描述

将语音命令产生的 TTS 从“显示端来源广播到全部语音播放设备”调整为“来源显示端优先、语音播放能力兜底”的单目标动态路由，并与文本媒体每句重新选择语音目标的规则一致。

## design 需求

- 显示端来源 `displayId` 是 TTS 播放首选目标，不改变命令执行和结果弹窗来源。
- 来源显示端离线或 `voicePlayback` 被关闭时，按当前在线显示端稳定顺序选择第一个可用语音播放设备。
- 控制端指定的 `targetDisplayId` 同样优先；目标无语音播放能力时使用同一兜底规则。
- 每个句子在生成开始和音频发送前动态读取在线能力，连续句子之间允许切换目标。
- 每个句子只向一个显示端发送音频；停止消息只发送给当前实际播放目标。
- `tts.device` 的 TTS 生成设备规则、控制端 `playOnControl` 行为和现有音频协议保持不变。

## spec 设计

```text
resolveVoicePlaybackTarget(preferredDisplayId, availableDisplayIds):
    过滤无效和重复显示端 ID
    如果 preferredDisplayId 在 availableDisplayIds 中:
        返回 preferredDisplayId
    返回 availableDisplayIds[0] 或 null

sendVoiceCommandTts(text, preferredDisplayId):
    生成音频
    每句重新读取在线 voicePlayback 显示端
    targetDisplayId = resolveVoicePlaybackTarget(preferredDisplayId, availableDisplayIds)
    targetDisplayId 存在 -> 只发送 tts/playAudio 到 targetDisplayId
    targetDisplayId 为空 -> 记录无设备并跳过

停止播报:
    使用当前语音会话记录的实际 targetDisplayId
    只向该目标发送 tts/stop
```

## 实施结果

- 服务端语音命令、语音聊天、搜索、帮助、确认、模式提示和修复模式 Agent 均改为单目标动态 TTS 路由。
- 文本媒体复用同一个来源优先/能力兜底目标解析器；本次没有改变 `tts.device` 生成规则、`playOnControl` 行为或音频协议。
- 受影响契约测试已同步新接口；语音相关定向测试 57/57 通过，完整 `npm test` 600/601 通过，唯一失败为已登记的 DeX `display-native-bridge.test.js` 原生 `injectTouch(down)` 环境契约。

## 自测用例

1. 来源显示端具备 `voicePlayback` 时，TTS 只发送到来源显示端。
2. 来源显示端关闭 `voicePlayback` 时，TTS 发送到第一个在线可用显示端。
3. 来源显示端在连续句子之间断开时，后续句子切换到备用显示端。
4. 控制端指定目标可用时只发送到指定目标；指定目标不可用时发送到备用目标。
5. 多个语音播放显示端在线时，同一句 TTS 只收到一份播放消息。
6. 没有可用语音播放显示端时不发送音频，服务端不抛出未处理异常。
7. 停止播报只停止当前实际目标，不误停止其他显示端。
8. `playOnControl=true` 仍只向控制端发送 `playOnControl`。

## 兼容性测试

- 浏览器显示端、Android APK 显示端和 Node 子显示端。
- `voicePlayback` 开启、关闭、断线和重新连接。
- `tts.device=server/display` 以及服务器 TTS 开关组合。
- 语音命令、普通语音聊天、搜索、帮助、确认和模式提示。
- 文本媒体现有源端优先和备用目标逻辑不改变。

## 性能测试

- 单句音频只生成一次，只向一个显示端发送一次。
- 目标解析为内存列表扫描，不增加 TTS 生成并发。
- 多句回复每句只增加一次能力列表读取，保持现有有序 TTS 调度。

## 风险评估

- 当前多显示端同时播报会变为单设备播报，属于本任务明确的行为变化。
- 目标在音频生成完成后失效时，当前句可能跳过；下一句按动态规则重新选择，避免向失效设备发送。
- 停止消息从全局广播变为实际目标定向，需要同步维护播放状态和完成回执的目标 ID。
