# 双端显示 Chat2API 请求模型名

## 任务描述

两端模型快选面板原来显示当前 LLM profile 保存的模型名。Qwen 轻量保存为 `Qwen3.6-Flash`，但普通聊天提交给 Chat2API 的请求名为 `aasc-qwen-mini`。面板改为显示实际提交的请求名，避免用户把配置名误认为本次请求名。

## Design 需求

- 控制端与显示端使用同一服务端权威请求名，不在页面复制三档映射。
- 仅调整面板展示和快照字段；当前 LLM 配置名、档位识别、Chat2API 映射与实际请求路径保持原有规则。
- Agent 配置显示不适用；未知配置显示原配置名并标注未匹配三档。

## Spec 设计

```text
读取当前 profile.model → 按开发名称表识别 Provider 与档位
识别成功 → 调用 tierRequestModel 计算请求名 → 在 chatModelTierConfig.selection.requestModelName 下发
识别失败或 Agent → requestModelName 为空
两端面板收到快照 → Agent 显示不适用；有请求名则显示请求名；否则显示原配置名并标注未匹配
```

## 受影响模块与代码

- `src/apps/web-mediacenter/ui/public/js/chat-model-tier-picker.js`：两端共用面板显示请求名。
- `src/apps/server/modules/chat/chat-model-tier-service.test.js`、`tests/chat-model-tier-browser.test.js`：服务和浏览器回归。

## 自测与兼容

- 验证 Qwen 轻量/普通请求名、豆包请求名、Agent 不适用和未知模型名回退。
- 验证控制端与显示端一致，并检查主题按钮状态。
- 旧快照缺少 `requestModelName` 时，面板回退显示原配置模型名，不影响选择与聊天。

## 性能、风险与工时

- 请求名由已有纯函数计算，不增加外部读取和网络调用；预估 1 小时。
- 页面展示的是发给 Chat2API 的请求别名，不能据此证明远端最终模型权重；自定义 Chat2API 映射可能改变后续上游目标。
