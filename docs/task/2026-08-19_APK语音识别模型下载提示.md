# APK 语音识别模型下载提示

## 任务描述

修复 APK 首次下载语音识别模型时，界面在下载启动阶段没有任何提示的问题，并增加模型 SHA-256 校验缓存。

## Design 需求

- 模型状态切换为 `downloading` 后立即显示“语音模型下载中 0%”。
- 模型下载过程中继续显示实际进度。
- APK 页面重新连接或轮询能力状态时，如果已经处于 `downloading`，应根据当前状态恢复提示。
- 浏览器非 APK ASR 路径保持不变。
- 服务器保存模型和 tokens 的 `.sha256` 文件，APK 下载完成后校验并保存本地 hash。
- APK 下次启动只读取本地 hash 与服务器 hash 比较，不重新计算模型文件 hash。
- 服务器 hash 暂时不可访问时，已有模型和本地 hash 均存在则沿用上次已验证结果。

对应设计文档：`docs/design/android-native-asr.md`。

## Spec 设计

- `AsrModelManager.ensureModel()` 在进入 `downloading` 状态后，后台下载线程启动前回调 `{state: "downloading", progress: 0}`。
- `display.html` 通过统一的 `showNativeAsrDownloadProgress(progress)` 显示 0 到 100 的安全整数进度；缺少进度时按 0 处理。
- `detectCapabilities()` 读取到 `downloading` 时立即调用上述显示函数，不改变 `voiceRecognition=false` 的能力语义。
- `ModelDownloader` 下载到 `.tmp` 后计算 SHA-256，只有与服务器 `.sha256` 内容一致才原子改名。
- `AsrModelManager` 保存本地 `.sha256` 文件；下次启动只比较保存值和服务器值，不重新读取模型计算 hash。

对应实现文档：`docs/spec/android-native-asr.md`。

## 自测用例

1. 未下载模型时，调用 `ensureModel()` 后先收到 `downloading, progress=0`，再收到实际进度。
2. 能力探测返回 `state=downloading, progress=42` 时，界面显示“语音模型下载中 42%”。
3. 能力探测返回 `state=downloading` 且无进度时，界面显示“语音模型下载中 0%”。
4. `ready` 仍显示“语音识别已就绪”，`error` 仍显示失败原因。
5. 浏览器环境不具备 `NativeDisplay` 时，原有 ASR 路径不受影响。
6. 下载完成后 hash 不匹配时，模型文件不改名，进入失败状态。
7. 已有模型和本地 hash 时，启动只比较本地 hash 与服务器 hash，不重新计算模型文件。
8. 真机使用 `3rd/ttslive/models/sensevoice/{zh,en,ja,ko,yue}.wav` 验证 APK 原生识别。
9. WebView 页面回调更新 origin 后，JavaBridge 调用 `asrEnsureModel()` 能进入模型管理器下载流程。

## 性能测试

- 只增加两个很小的 hash 文件请求；首次下载完成后额外顺序读取一次已落盘 `.tmp` 计算 hash。
- 后续启动不读取 234MB 模型计算 hash，仅比较两个小文本 hash。
- 下载进度仍由原有文件读取循环上报。

## 风险评估

- WebView 页面极早期收到回调时，已有 `onNativeAsrModel` 防护和状态探测兜底；若页面尚未完成加载，后续 `asrStatus()` 探测会恢复提示。
- 进度值经过 0 到 100 限制，避免异常服务端头信息导致界面显示非法百分比。
- 服务器 hash 文件必须在模型更新时同步更新，否则 APK 会重新下载或拒绝加载。
- 未修改非 APK ASR 分支，浏览器兼容性风险较低。
