# Pi Agent 默认超时调整为 600 秒

## 任务描述

将服务器托管 Pi Agent 单次 RPC 请求的默认超时时间从 120 秒调整为 600 秒，和 Claude 默认超时保持一致；保留测试及特殊调用通过构造参数注入短超时的能力。

## Design 需求

- PiRuntimeManager 默认请求超时为 600000ms。
- 请求超时仍然终止当前 Pi 子进程并清理会话，下一次请求可以重新启动。
- 不改变显式传入的短超时配置，保证超时清理测试快速执行。

对应设计文档：`docs/design/llm-agent-mode.md`。

## Spec 设计

- `PiRuntimeManager(options)` 使用 `options.requestTimeoutMs`，未传入时回退到 `600000`。
- RPC 请求在该时限内未完成时停止当前 session，并回调错误；子进程退出和非法协议继续走相同清理路径。

对应实现文档：`docs/spec/llm-agent-mode.md`。

## 自测用例

- 默认构造 `PiRuntimeManager` 时，`requestTimeoutMs` 等于 600000。
- 注入 10ms 超时时，请求仍会终止子进程并清理会话。
- 正常 RPC 流式响应、profile/template/权限隔离、子进程退出处理继续通过。

## 兼容性测试

- 仅改变 Pi Agent 的默认等待时长；直接 LLM、Claude 和已有显式超时调用不受影响。

## 性能测试

- 单元测试使用注入短超时，不增加测试等待时间。

## 风险评估

- 未及时返回的 Pi 请求最长可占用 600 秒；超时清理机制保持不变，避免进程泄漏。

## 完成结果

- Pi Runtime 单元测试：5/5 通过。
