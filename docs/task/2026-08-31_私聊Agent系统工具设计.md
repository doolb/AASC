# 私聊 Agent 系统工具设计

## 任务描述

记录私聊聊天 Agent 调用受限系统工具的后续设计，暂不修改现有私聊命令行为。

## Design 需求

- activePrivate 的原始文本后续统一交给当前聊天 Agent。
- Agent 只能调用服务端注册的控制工具，服务器负责参数、会话和权限校验。
- 第一阶段候选工具为结束对话、退出私聊、切换私聊助手、请求进入修复模式、静音和报时。
- 修复模式必须保留本地密码验证，Agent 不能绕过密码直接进入。
- Pi 和 Codex 共享工具定义与执行协议。

## Spec 设计

详见 `docs/spec/private-chat-agent-tools.md`，当前只包含伪代码设计，不代表已经存在可调用接口。

## 受影响的功能模块和代码

后续实现预计涉及：

- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：activePrivate 路由和兼容命令策略。
- `src/external/llm/llm-service.js`：普通聊天工具声明和调用结果转发。
- Pi/Codex Agent 适配器：统一工具调用格式转换。
- 修复模式、静音、时间和私聊会话服务：受限工具执行器。
- 对应单元测试和语音会话回归测试。

本次仅新增设计文档，不修改上述代码。

## 自测用例

后续实现时至少覆盖：

1. 普通私聊文本不调用工具时正常回复并保存历史。
2. 六个候选工具只能由 activePrivate 当前白名单调用。
3. 非法助手名、错误 displayId、过期 session 和未知工具均拒绝执行。
4. requestRepairMode 不能绕过密码，密码不进入 Agent 请求和普通历史。
5. Pi 与 Codex 的同一工具调用得到一致的服务端执行结果。

## 兼容性测试

- 等待唤醒、activeGroup 和现有搜索独立 session 保持不变。
- 工具后端不支持时不能伪造执行成功，并保留兼容回退策略。
- 现有私聊历史、TTS 和会话切换规则在方案确定前不变。

## 性能测试

- 工具注册表应为内存只读查询，不启动额外 Agent 进程。
- 工具调用只增加一次服务端校验和执行往返，不重复提交原始聊天文本。

## 风险评估

- Agent 工具具有状态副作用，必须由服务端白名单和会话绑定保护。
- Pi/Codex 工具协议不一致可能导致一套后端可用、另一套后端静默失败，因此必须先定义统一格式并做双后端契约测试。
- 切换助手时的历史和 session 回收尚未确定，暂不实现。
