# 系统指令动态播报全部命令

## 任务描述

修复浏览器显示端处于等待唤醒状态时说“系统。”被当作普通语音忽略的问题，并让“系统”命令播报当前所有可用语音指令。

## design 需求

- “系统”属于免唤醒系统帮助指令，支持末尾标点。
- 帮助文本不能继续依赖服务端硬编码字符串。
- 播报内容包含内置功能指令、自定义语音指令和会话/系统控制指令。
- 显示端语音输入继续使用通用 TTS 路由，控制端同时显示帮助弹窗。
- 显示端来源的帮助文本按句切分并串行生成，避免单次 TTS 请求携带整段超长帮助文本。
- 分句帮助消息使用同一 TTS 批次标识，只有最后一句实际播放完成后才结束语音会话；中间生成间隔不能触发提前完成。
- 完整帮助响应文本先下发到目标显示端立即弹窗，分句 TTS 在后台继续生成，不因 TTS 生成耗时延迟弹窗。

## spec 设计

- 在内置语音指令注册表中增加 `systemHelp`。
- 增加 `getVoiceCommandHelpText()`，从内置注册表和 `chat.getCommands()` 动态生成帮助文本。
- `showHelp` 处理分支调用动态帮助文本；等待唤醒状态通过同一内置指令判定直接放行。

## 自测用例

1. “系统。”被识别为免唤醒内置指令。
2. 等待唤醒状态下“系统。”被接受且不改变会话状态。
3. 动态帮助文本包含全部内置指令示例、描述和自定义关键词。
4. 显示端来源的帮助通过通用 TTS 路由播报。
5. 控制端帮助弹窗和原有系统指令处理保持兼容。

## 兼容性测试

- 浏览器显示端、Android Display APK WebView 和 Node/Go/C# 子显示端。
- 控制端系统帮助弹窗、内置命令列表、自定义语音指令和 TTS 播放路由。

## 性能测试

- 帮助文本仅在执行“系统”时按当前配置生成，不增加持续监听内存占用。
- 自定义命令数量增加时，文本生成保持线性遍历，不创建长期缓存。

## 风险评估

- 自定义命令过多会使单次 TTS 文本变长，仍按现有 TTS 队列和通用播放路由处理。
- 用户配置中的自定义动作可能包含内部动作文本，播报时只展示关键词和动作摘要，不执行动作。

## 实际完成

- 内置语音指令注册表新增 `systemHelp`，`系统` 和带末尾标点的 `系统。` 均可在等待唤醒状态下直接执行。
- 新增 `getVoiceCommandHelpText()`，动态汇总内置指令、自定义关键词及会话/系统控制指令。
- 显示端来源的 `showHelp` 使用动态文本并继续通过通用 TTS 路由播报，控制端同步打开帮助弹窗。
- 显示端帮助播报复用句子切分和 TTS 调度器，按原始顺序逐句生成播放；控制端帮助弹窗仍显示完整文本。
- 分句帮助消息携带统一的 `voiceTtsBatchId`，最后一句携带 `voiceTtsBatchEnd`；显示端只有批次最后一句实际播放完成后才发送 `voiceConversationTtsFinished`，停止播报时清空整个批次。
- 自测：系统帮助分句、批次完成状态、显示端语音会话、普通聊天和 TTS 路由相关回归 17/17 通过，服务端脚本语法检查通过。
- 完整帮助响应文本已先下发到目标显示端立即弹窗，分句 TTS 在后台生成，避免弹窗等待全部音频生成。
- 控制端帮助弹窗删除重复的静态“系统”条目，改由动态内置命令列表展示。
- 自测：语音会话、内置命令和 TTS 路由相关测试通过。
