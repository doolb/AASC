# 聊天模型三档双端快选

## 任务描述与需求

控制端和显示端右下角新增类似“音色”的模型入口，选择当前已配置账号的 Provider 与轻量、普通、专业三档。两端共享当前 Provider；每个 Provider 独立记住默认或上次选择的档位。Qwen 默认普通，豆包默认轻量。后续从此入口打开 Chat2API 外部登录，本次只保留禁用入口及方法。

## Design 与 Spec

- 设计：`docs/design/chat-system.md` 的“LLM 三档与双端快选”。开发维护服务端档位映射，两端不提供映射编辑。
- 伪代码：`docs/spec/chat-system.md` 的“LLM 三档与两端快选伪代码”。控制端和显示端通过 WebSocket 读取、写入、接收权威配置；断线禁止提交。
- 映射：Qwen 为 Qwen3.6-Flash/Qwen3.7/Qwen3.7-Max；豆包沿用 doubao/doubao-think/doubao-expert，思考参数 0/1/3。不使用 Lite。

## 受影响模块与代码

- `src/apps/server/modules/chat/chat-model-tier-service.js`：开发映射、配置规范化、账号过滤、保存与聊天目标解析。
- `src/apps/server/boot/server-app.js`：复用运行中的 Chat2API 代理、两端连接补发及消息处理、普通聊天接线。
- `src/external/llm/llm-service.js`：单次普通聊天覆盖 Responses 目标，续接指纹区分 Provider 和模型。
- `src/apps/server/modules/chat2api/chat2api-default-model-mappings.js`：Qwen 三档专用内部别名，保留旧公开别名行为。
- `src/apps/web-mediacenter/ui/public/{upload.html,display.html,css/chat-model-tier-picker.css,js/chat-model-tier-picker.js,js/control-chat-model-tier.js,js/display-chat-model-tier.js,js/display-stage.js,js/websocket.js,js/self-test.js}`：双端入口、权威回显与只读自测。
- `release/offline-release-status.json`：服务代码包待出包。

## 自测用例

- Provider 列表仅含已启用、有凭据、有三档映射的账号；无账号、停用、代理停止、非法 Provider/档位均不保存或不调用上游。
- Qwen 默认普通、豆包默认轻量；切换 Provider 保留各自档位，双端广播、刷新和断线重连一致。
- 三档请求进入既有 Chat2API Responses 服务；Qwen 专用别名与旧 `Qwen3.6-Flash → Qwen3.7` 兼容映射互不影响；自定义映射冲突明确失败。
- Agent 与未选择 Provider 的旧 LLM profile 行为保持；切换实际模型后旧 Responses 引用不复用。
- 两端面板键盘焦点、选中状态、窄屏位置和外部登录预留按钮。

## 兼容性、性能与风险

旧配置缺少 `chat.modelTierSelection` 时沿用现有聊天 profile；现有 Chat2API 模型别名和账号表不迁移。每次普通聊天对运行中账号与映射做轻量读取，不按每个候选模型探测网页，也不新增 HTTP 配置接口。主要风险是 Qwen 目标模型未经真实账号调用确认、豆包文字当前账号可能受上游风控，以及实际设备右下角遮挡；以上列为后续现场验收，不把账号格式校验当成远端成功。
