# 任务：显示端主题同步

## 任务描述

让显示端复用控制端当前服务端主题，使显示端 UI 在控制端切换主题后同步变化，同时保持图片、视频和网页媒体内容原样显示。

## Design 需求

- 控制端和显示端使用同一个服务端全局 `ui.controlTheme`。
- 显示端首次加载和 WebSocket 重连时读取/接收当前主题；控制端切换主题时已连接显示端即时更新。
- 主题适配显示端背景、等待提示、连接/状态文字、文本媒体和天气/语音等临时弹窗。
- 不修改 `img`、`video`、`iframe` 及网页媒体内部的内容、滤镜和样式。
- 主题仍使用当前 15 种配色，避免显示端单独维护另一份颜色含义。

## Spec 设计

- `server-app.js` 在 `POST /api/config/controlTheme` 成功保存后广播 `{ type: 'controlThemeChanged', theme }`。
- 显示端建立 `/display` WebSocket 后收到一次当前 `controlThemeChanged` 消息。
- `display.html` 加载 `theme.css` 和 `ui-theme.js`，初始化主题；收到主题消息时调用 `UiTheme.applyRemoteTheme(theme)`。
- `display.css` 使用主题变量替换显示端 UI 硬编码颜色，媒体节点保留原有样式边界。

## 自测用例

1. 显示端首次加载可应用服务端返回的 15 种主题。
2. 显示端收到 `controlThemeChanged` 后更新根元素主题，不刷新页面。
3. 控制端切换主题后，服务端向所有显示端广播主题。
4. 显示端等待提示、状态文字、文本媒体和临时弹窗使用主题变量。
5. 图片、视频、iframe 网页内容不被主题 CSS 覆盖。

实际结果：主题、显示端同步、旋转弹窗、文本媒体和播放恢复相关回归 44/44 通过；`node --check` 与 `git diff --check` 通过。

## 兼容性测试

- 旧服务端不发送主题消息时，显示端使用本地缓存或深色默认值。
- 显示端 WebSocket 重连后恢复服务端主题。
- 15 种主题、横竖屏、文本媒体和天气弹窗组合检查。

## 性能测试

- 显示端初始化最多一次主题 GET；WebSocket 主题通知只更新根节点属性。
- 不刷新页面、不重新加载图片/视频/网页、不增加轮询。

## 风险评估

- `theme.css` 原本包含控制端组件规则，加载到显示端后需确认无通用选择器误伤媒体节点。
- 显示端存在较多旧硬编码颜色，首轮只覆盖明确的显示端 UI 层，后续新增组件需继续使用主题变量。
- 服务端广播只影响已连接显示端，断线显示端通过初始化 GET/重连消息恢复。
