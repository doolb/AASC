# 短编号语音放行与五子棋落子棋盘回执

## 任务描述与 Design 需求

现场“下H4。”被短中文过滤；AI 成功落在 E6 后 GM 回执只进入界面提示，未交回模型，角色下一轮仍等待确认。用户要求语音文本含连续字母数字编号即放行，并将完整棋盘编码追加到每次成功落子的 GM 回执末尾。

## Spec 设计

```text
ASR 原文 → 提取连续字母数字片段（含中文数字） → 存在长度2至12且含字母和数字的片段 → 内容放行并保持原文
未命中编号 → 沿用中文要求和普通噪声过滤；内容放行不代发游戏调用
GM 接受落子 → 提交权威棋盘 → 回执现有字段后追加该棋盘编码 → 进入协议提示与模型续接
AI 落子成功 → 保留原叙述 → 含棋盘的 GM 回执交回模型 → 追加确认后的新答复
终局 → 回执同样附棋盘 → 另附胜负状态 → 同样续答
第七次模型回复刚成功落子或终局 → 预留一次确认；整体最多八次模型回复
```

## 受影响模块与代码

- `server-app.js`：编号内容过滤。
- `gomoku-game-service.js`：进行中及终局落子回执追加权威棋盘。
- `game-chat-bridge.js`：规则新增字段说明，AI 成功回执续送及确认预算。
- `asr-content-filter.test.js`、`game-gomoku.test.js`、`game-chat-session.test.js`：语音路由、连续棋步、终局和独立入口验证。
- ASR 过滤与五子棋 design/spec、文档索引、usage、todo、changelog，服务包状态。

## 自测与兼容性

- ASR 过滤 6/6：下H4、中文数字、原文路由、纯数字/短英文/非连续编号噪声。
- `npm run test:game-chat` 50/50：E6 成功后读到完整棋盘，下一轮 F2 正常继续；双方终局回执与胜负状态；普通自然语言；七次边界；既有简写与旧尖括号；独立 JS 会话入口。
- 显示端继续使用现有增量字段；GM 落子协议新增末尾字段，快照编码和摘要逻辑复用原实现。
- 对照本机真实日志诊断，测试仅使用隔离临时棋局；未操作用户当前棋局或调用真实账号发消息。

## 性能、风险与预计工时

棋盘最多225格加14个分隔符，每步新增最多240个文本字符（含前导逗号）；普通成功 AI 落子多一次模型调用，增加上游耗时与令牌使用。真实模型可能仍重复或误读坐标，GM 继续校验轮次、范围和空位；新代码与服务包部署后需真实角色验收。预计 1 小时。
