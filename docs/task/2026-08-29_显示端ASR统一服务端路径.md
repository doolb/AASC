# 显示端 ASR 统一服务端路径

## 任务描述（后续修正）

修复显示端监听虽然开启并显示“等待唤醒”，但没有最近识别回传的问题。录音端统一提交服务端公共 `/api/asr/recognize`；同时保留“服务端/显示端”设备选择，显示端模式由服务端按连接顺序转发给 ASR 提供端。

## Design 需求

- 浏览器和 Android 显示端只采集原始 PCM/WAV。
- 所有识别请求都提交服务端 `/api/asr/recognize`。
- 服务端统一处理 ASR、降噪、声纹匹配/分段和结果回传。
- 录音端不调用本地 Sherpa 或自身 Android 原生 ASR。
- `voiceRecognition` 表示显示端是否能作为 ASR 提供端，`voiceSupported` 表示公共 ASR 是否 ready。

## Spec 设计

```text
checkAsrStatus:
    GET /api/asr/status
    ready -> voiceSupported=true

startVoiceRecording:
    getUserMedia -> PcmAudioCapture
    VAD 分段 -> takeWav
    POST /api/asr/recognize

处理服务端结果:
    segments -> 逐段发送 voiceInput
    text -> 发送 voiceInput
    ignored/error -> 不伪造识别文本，继续监听
```

## 自测用例

1. 检查录音显示端通过 `/api/asr/status` 判断公共 ASR 可用性。
2. 监听主流程不调用 `SherpaASR.startStreaming/recognizeBuffer` 或本地 Android ASR。
3. 选择显示端时按 `displayClients` 连接顺序选择第一个 `voiceRecognition=true` 提供端。
4. 语音段统一 POST `/api/asr/recognize`，并回传 text/segments。
5. 现有监听状态、最近识别和服务端公共 ASR 回归测试通过。

## 兼容性测试

- 浏览器显示端。
- Android 显示端 WebView。
- 服务端 ASR 普通识别、声纹和多段结果。

## 性能测试

- 录音端不加载网页端本地 Sherpa 流式模型；显示端模式只在提供端 APK 中加载原生模型。
- 每个 VAD 语音段增加一次服务端公共请求，识别资源由服务端或选中的提供端管理。

## 风险评估

- 失去网页端本地流式 partial 结果，控制端只接收服务端公共接口返回结果。
- 服务端不可用时监听仍可采集，但会回传错误并继续等待下一段，不切换到本地识别。

## 实现结果

- display.html 的录音主流程统一提交公共接口；被选为提供端的 APK 保留 `asrAudio`/`asrResult` 原生处理分支。
- `/api/asr/recognize` 在 `server` 模式本机识别，在 `display` 模式按连接顺序转发，不固定优先任何 IP。
- ASR 设备设置页恢复“服务端/显示端”选择；用户能力覆盖可分别决定 1.39 是否仅录音、1.6 是否作为提供端。
- 验证：显示端监听契约 27/27，ASR/Android/主题相关回归 45/45，`zh.wav` 公共接口识别返回“开放时间早上9点至下午5点。”，显示端内嵌脚本语法检查通过。
