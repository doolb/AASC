# 群聊清空参数兼容修复

## 任务描述

修复控制端点击“清空”时群聊清空报“必须指定群聊或具体私聊会话”的问题。

## Design 需求

- 群聊清空范围由 `mode=group` 和空 `target` 唯一确定。
- 临时会话清空范围由 `mode=temporary` 和空 `target` 唯一确定。
- 群聊/临时会话即使收到多余的 `sessionId` 也必须兼容并忽略。
- 私聊仍必须同时提供 `target` 和 `sessionId`。
- HTTP 与 WebSocket 清空入口使用相同的服务端范围校验。

## Spec 设计

```text
validateScope(options):
    mode = options.mode 或 null
    target = options.target 或 null
    sessionId = options.sessionId 或 null
    如果 mode 是 group 或 temporary 且 target 为空:
        返回对应 mode，target=null，sessionId=null
    如果 mode 是 private 且 target、sessionId 都非空:
        返回 private/target/sessionId
    否则拒绝清空

控制端请求:
    request = { mode, target }
    如果 mode == private:
        request.sessionId = 当前私聊 sessionId
    调用 /api/chat/clear
```

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/js/chat.js`：群聊清空请求不发送私聊会话字段。
- `src/external/llm/llm-service.js`：统一放宽群聊/临时会话的多余 `sessionId` 校验并保留私聊严格校验。
- `src/external/llm/llm-service.test.js`：增加群聊参数兼容和私聊边界回归测试。
- `docs/design/chat-history-persistence.md`、`docs/spec/chat-history-persistence.md`、`changelog.md`：同步行为契约和变更记录。

## 自测用例

1. 群聊请求带 `mode=group,target=null,sessionId=default` 时成功清空群聊。
2. 群聊请求不带 `sessionId` 时成功清空群聊。
3. 临时会话带多余 `sessionId` 时仍按临时范围处理。
4. 私聊缺少 `target` 或 `sessionId` 时仍拒绝。
5. 控制端群聊请求不再发送 `sessionId`。

## 兼容性测试

- 旧控制端发送群聊 `sessionId=default` 仍可用。
- 新控制端发送群聊无 `sessionId` 可用。
- 私聊默认会话和非默认会话范围不变。
- HTTP 与 WebSocket 两条入口使用同一范围规则。

## 性能测试

- 仅增加一次参数归一化，不增加磁盘扫描和网络请求。

## 风险评估

- 如果错误地把非空 `target` 作为群聊请求，仍会进入拒绝分支，不会扩大清空范围。
- 私聊校验保持严格，避免误清空其他私聊会话。
