# 服务器统一下载并分发 MNN 模型

## 任务描述

修正 Android MNNChat 模型分发链路：服务器先按指定 `modelId` 从固定 ModelScope 仓库下载模型，按 manifest 校验文件大小和 SHA-256 后缓存到服务器；APK 只从服务器本地缓存接口下载当前选中的模型。提供 npm 命令下载指定模型 ID，不在 APK 请求时直接代理未缓存的 ModelScope 文件。

## design 需求

- MNN-LLM 模型由服务器统一下载、校验和缓存。
- ModelScope 只作为服务器固定上游源，客户端不可传入上游 URL。
- 服务器缓存路径为 `res/models/llm/<directory>/`。
- 缓存未完整就绪时，模型清单标记 `ready=false`，分发接口返回结构化未就绪错误。
- APK 继续只下载当前选中的模型，不改变单模型缓存、切换等待和原子安装流程。

## spec 设计

```text
downloadLlmModel(modelId, force):
  read fixed manifest definition
  acquire model cache lock
  reuse complete cache unless force
  download each ModelScope resolve file to staging/*.tmp
  verify size and SHA-256
  atomically replace model cache directory
  release lock and report ready

GET /api/llm/model-manifest:
  return model definitions with cached/ready state

GET /api/llm/model/:modelId/:filename:
  validate model and filename
  stream only the complete local server cache
```

新增命令：

```text
npm run download:llm-model -- --id <modelId>
npm run download:llm-model -- --id <modelId> --force
```

## 自测用例

1. 未缓存远端模型的 manifest 返回 `ready=false`，分发接口不返回远端 URL。
2. npm 命令使用固定 ModelScope 仓库和 revision 下载指定 ID。
3. 文件大小不一致时下载失败，staging 和 lock 被清理，旧缓存不变。
4. SHA-256 不一致时下载失败，半成品不进入模型目录。
5. 全部文件通过校验后才原子切换，重复执行复用缓存。
6. `--force` 会重新下载完整模型。
7. 未知 ID、未知文件名和路径穿越均被拒绝。
8. APK 的 `/api/llm/model/:modelId/:filename` 只读取服务器本地缓存。

## 兼容性测试

- 已缓存模型的现有 APK 下载协议保持不变。
- 未缓存模型返回明确未就绪错误，APK 不会直接访问 ModelScope。
- 现有 `/v1/chat/completions`、`/v1/responses`、`/v1/models` 和显示端模型切换协议不变。
- ModelScope 不可访问时不影响已完成缓存模型的分发和推理。

## 性能测试

- 重复下载已完整缓存模型不重复传输大文件。
- 服务器 hash 只在下载校验和缓存状态变化时执行。
- 分发请求直接读取本地文件，不在每个 APK 请求中重新访问 ModelScope。
- 并发下载同一模型时只有一个进程持有模型锁。

## 风险评估

- 磁盘空间：Qwen3.5 模型约 519 MiB，服务器需要预留模型缓存空间。
- 下载中断：通过 staging、临时文件和锁清理避免半成品被分发。
- 多进程并发：CLI 和服务器共享锁目录，避免同时写入同一模型目录。
- 上游变更：revision 和逐文件 hash 固定，ModelScope 内容变更会被拒绝。
- 旧 APK：服务器未缓存时会收到结构化错误，不能自动回退到主服务器或外部模型。
