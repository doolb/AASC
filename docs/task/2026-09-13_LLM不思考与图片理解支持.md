# LLM 不思考与图片理解支持

## 任务描述

为 AASC 本地 Android MNN-LLM 网关增加按请求关闭思考和图片理解能力，覆盖 Chat Completions、Responses 及 `/v1/chat/responses` 兼容入口。必须使用固定的阿里官方 MNN revision，不改变现有模型选择、显示端分流、CPU affinity、ASR/TTS 和任务通用流程。

## design 需求

- 请求可选 `enable_thinking` 布尔字段；`false` 应传入 MNN Jinja context，并且客户端不会收到思考块。
- 未提供 `enable_thinking` 时保持模型默认行为。
- Chat Completions 支持 `image_url`，Responses 支持 `input_image`；第一阶段只接受受限 `data:image/...;base64,...`。
- 图片经过服务端校验、WebSocket 转发、APK 有界解码后进入官方 MNN `MultimodalPrompt` 和 `visual.mnn`。
- 图片无效、超限或解码失败返回结构化错误，不静默改成文本推理，不回退主服务器。
- 图片临时资源在请求结束、错误、取消和断线时释放。

## spec 设计

```text
HTTP request
  -> normalize enable_thinking and protocol image parts
  -> validate model and acquire target display
  -> send llm.request(payload)

APK llm.request
  -> decode text parts and data URL images with bounds
  -> create PromptImagePart and <img>image_N</img> placeholders
  -> set MNN jinja.context.enable_thinking when explicitly requested
  -> call multimodal or text LlmSession response
  -> filter think blocks only when enable_thinking=false
  -> return llm.chunk and llm.completed
```

## 自测用例

1. Chat Completions `enable_thinking=false` 返回内容不含 `<think>` 块。
2. Responses `enable_thinking=false` 的 SSE 和非流式响应均不含思考内容。
3. Chat Completions `image_url` 触发 Qwen3.5 `visual.mnn`，不是文本降级。
4. Responses `input_image` 触发同一视觉路径。
5. 无效 MIME、非法 Base64、超大图片和远程 URL 返回 `LLM_IMAGE_INVALID` 或 `LLM_IMAGE_UNSUPPORTED`。
6. 图片推理完成、错误、取消和断线都释放临时 Bitmap/VARP/文件。
7. 无图片文本请求、旧客户端、ASR/TTS 和 LLM CPU 配置回归不受影响。

## 性能测试

- 对比文本、关闭思考文本、单图和多图请求的首 token、总耗时和峰值内存。
- 确认图片临时资源不会随连续请求增长。
- 确认 LLM 仍使用显式 `thread_num` 和独立 CPU policy，不改变 ASR/TTS。

## 风险评估

- MNN 视觉 API 需要 `PromptImagePart` 和 `visual.mnn`，不能继续使用纯文本 `PromptItem`；错误地走文本 API 会静默丢图。
- Base64 图片会增加 WebSocket 和 Java/native 内存峰值，必须限制 MIME、字节数、像素数和图片数量。
- `enable_thinking=false` 既依赖模型 Jinja context，也需要输出边界过滤，避免部分模型仍输出思考标记。
- native/Bitmap 资源跨 JNI 生命周期管理错误可能造成泄漏或崩溃，必须在 finally/RAII 路径释放。
