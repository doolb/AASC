# 豆包失效会话自动重建

## 任务描述

语音聊天续接豆包上游会话时出现 `doubao_session_uncertain`，当前 Responses 客户端把错误直接返回。改为自动清除失效上游引用，并在安全条件下重建上游会话。

## design 需求

- 保留控制端当前会话和聊天历史，只更换豆包上游会话。
- 非流式请求和流式尚无正文输出时，使用完整已选聊天上下文重试一次。
- 流式已有正文输出时不重发本轮，只清除引用供下一轮重建。
- 仅处理明确可重建错误；新会话失败时返回错误。

## spec 设计

```text
当前输入 + 当前会话历史 → 完整 Responses 输入
旧上游引用续接失败且错误属于可重建集合 → 删除旧引用
本轮尚未输出正文 → 无引用发送完整输入一次 → 保存新引用
本轮已有正文输出 → 返回本轮错误 → 下一轮无引用发送完整输入
```

## 受影响模块和代码

- `src/external/llm/llm-service.js`：Responses 请求和流式请求的恢复判定。
- `src/external/llm/llm-service-doubao-recovery.test.js`：本机模拟 Responses 服务的集成验证。
- `docs/design/chat-system.md`、`docs/spec/chat-system.md`：需求和伪代码。
- `docs/todo.md`、`changelog.md`：现场验收和完成记录。

## 自测用例

1. 非流式第二轮收到 `doubao_session_uncertain`，新请求不带旧 `previous_response_id`，携带系统提示、旧问答和本轮输入。
2. 流式第二轮在正文前收到该错误，自动新建上游会话，客户端只收到一份正文。
3. 流式已输出正文后收到该错误，本轮不重试；下轮请求不带失效引用。
4. 全新请求未携带上游引用时，即使收到同名错误也不自动重复发送。

## 兼容性测试

保留 Responses 对 404、`conversation_not_found` 和 `response_not_found` 的既有恢复行为；Chat Completions 协议不受此改动影响。

## 性能测试

正常请求不增加调用；失效会话最多额外发送一次完整上下文请求。无需新增持续后台任务。

## 风险评估

当流式部分正文已交付客户端时，自动重发可能导致重复输出，因此仅清除引用并返回错误。真实豆包账号的上游行为仍需现场观察。
