# 睡眠恢复检查控制端播放/暂停状态

## 任务状态：✅ 已完成

## 设计需求

参考：[design/display.md](../design/display.md)（睡眠恢复检查控制端播放/暂停状态）

## 问题描述

退出睡眠模式时视频直接播放，不检查控制端播放/暂停设置：
1. **单媒体**：睡眠前控制端暂停（isPlaying=false）的视频，退出睡眠后 `resumeSleepMedia()` 直接 `mediaVideo.play()` 自动播放
2. **播放列表**：睡眠前暂停（ps.paused=true）的播放列表，退出睡眠后直接播放当前视频（绕过 ps.paused）

## 根因

- 显示端无本地 `mediaIsPlaying` 变量跟踪控制端播放/暂停——`reportPlayState(playing)` 只上报服务端持久化，显示端自己不留状态
- `resumeSleepMedia()`（display.html）只判断 `mediaHtml.style.display` 或 `mediaVideo.src` 存在即 `play()`，无任何播放/暂停状态检查
- 播放列表的 `ps.paused` 标志存在但 `resumeSleepMedia` 不读
- 参照：重连恢复 `showMedia(..., state.isPlaying === false)` 正确保持暂停（display.html），但睡眠恢复走 `resumeSleepMedia` 无此逻辑

## 修复方案

1. **新增 `mediaIsPlaying` 本地变量**（单媒体控制端播放/暂停跟踪）：
   - `showMedia` 末尾：`mediaIsPlaying = !paused`（restoreState 恢复 isPlaying 时由 showMedia 一并写入）
   - `handleControl('play')`：`mediaIsPlaying = data.value === true`
2. **新增 `shouldPlayMedia()`**：
   - 播放列表激活时读 `playlistState.paused`（睡眠前控制端暂停播放列表则保持暂停）
   - 否则读单媒体 `mediaIsPlaying`
3. **`resumeSleepMedia()` 开头 `if (!shouldPlayMedia()) return`**：控制端暂停的媒体退出睡眠保持暂停

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/display.html`：mediaIsPlaying 声明 + showMedia/handleControl('play') 同步 + shouldPlayMedia + resumeSleepMedia 守卫
- `tests/display-sleep-mode.test.js`：+3 步（暂停单媒体/播放列表退出保持暂停、播放中单媒体退出恢复播放）
- `docs/spec/display-sleep-mode.md`：恢复时检查播放状态小节

## 自测用例

1. 单媒体播放中 → 睡眠前 handleControl('play', false)（mediaIsPlaying=false）→ 进入睡眠 → 退出睡眠 → 视频保持暂停
2. 单媒体播放中（mediaIsPlaying=true）→ 进入睡眠 → 退出睡眠 → 视频恢复播放
3. 播放列表暂停（ps.paused=true）→ 进入睡眠 → 退出睡眠 → 保持暂停（不自动播放）
4. `node tests/display-sleep-mode.test.js` → 30 步全绿

## 兼容性测试

- 重连恢复（restoreState isPlaying）路径不受影响：showMedia paused 参数已写 mediaIsPlaying
- 睡眠守卫（click/空格/play 命令拒绝）不受影响
- 播放列表自动切播、批量暂停/继续不受影响（shouldPlayMedia 仅在睡眠恢复时调用）

## 性能测试

- 无新增开销（一次布尔判断 + 变量赋值）

## 风险评估

- 低：仅睡眠恢复路径加守卫，正常播放路径（play 命令、showMedia）行为不变
- `mediaIsPlaying` 默认 false：睡眠恢复前未播放过媒体时 resumeSleepMedia 会 return（无媒体时本就无操作）
