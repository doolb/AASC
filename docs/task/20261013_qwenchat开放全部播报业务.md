## 需求与方案

在原有AI/Agent之外，文本阅读和systemBroadcast共享的报时、提醒、自定义、语音命令、系统提示可选择qwen-chat。保留现有业务默认值，由用户在语音配置选择；不新增开关、不自动改真实配置。豆包网页仍沿用其独立实验限制。账号、模型映射和WAV上游归Chat2API，现有AASC权威配置/重连复用。

## 自测与兼容性

- 四种业务qwen选择/同Provider音色继承/映射有效；不读取实际账户，传输只用本地模拟。
- 两个非AI配置保存成功且重载、权威回填与重连保留；页面可选、只读自测不误报。
- 普通文字生成完整WAV；仅emoji不连接上游、不缓存、不发送空路径；文本播放器继续下一句，预取/取消不串播放。
- 原AI/Agent模板选择、system/Qwen API/豆包API、豆包网页实验限制、无账号/停用/错误不回退。
- 优先npm run test:mmd-production:tts；无专用script的policy/settings/UI/text-media/voice定向用node --test；Chat2API代码若未变不重复其全量。

## 性能、风险、工时

只调整业务选择和空结果消费；沿用60秒、16MiB、分句/缓存/队列，不增加并发或默认请求。空结果和批次收尾为主要兼容风险，用定向模拟与隔离浏览器验证。预计半天内量级，按实际入口/回归结果调整；真实声音、长阅读和设备体验另需现场验收。
