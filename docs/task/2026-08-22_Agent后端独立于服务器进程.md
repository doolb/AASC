# Agent 后端独立于服务器进程

## 任务描述

修复服务器重启后控制端聊天 Agent 离线的问题，并将 Claude/Codex Agent 的实际进程、通信句柄和会话状态从 `server-app` 中剥离，改为由独立 Agent 后端宿主进程管理。服务器通过 Unix Socket IPC 调用后端，服务器重启不应终止仍在运行的 Agent。

## design 需求

- 每个角色继续拥有独立 Agent、提示词和聊天历史。
- 新增独立 detached Agent 后端宿主，统一持有 Claude FIFO 和 Codex stdio。
- 后端宿主使用固定 Unix Socket；服务器优先连接已有宿主，失效时才重新拉起。
- 服务器重启只重建 IPC 客户端，不主动停止 Agent。
- 后端宿主失效或 Agent 退出时显示离线，下一次聊天允许懒启动恢复。
- 保持控制端 roleList、chatChunk、chatResponse、TTS 和关闭所有 Agent 的现有协议。

## spec 设计

- 新增 `agent-backend-host.js`：独立进程、JSON Lines IPC、角色 bridge 生命周期。
- 新增 `agent-backend-client.js`：Unix Socket 连接、宿主拉起、请求/事件复用和代理 bridge。
- `AiRolesService` 在生产环境使用客户端代理，测试可继续注入 bridgeFactory。
- `restoreAll()` 改为异步状态恢复；服务启动完成后广播最新角色在线状态。
- `stopAll()` 和删除角色等待 IPC 停止请求完成，再清理服务端 bridge 和角色目录。

## 自测用例

1. 独立后端宿主启动后，客户端可通过 Unix Socket 查询状态和发送聊天请求。
2. 后端宿主存活时关闭客户端，再创建新客户端，原角色 bridge 仍在线且可继续聊天。
3. 模拟服务器重启：旧客户端销毁、新客户端连接同一 Socket，Codex thread 与 Claude bridge 不被重建。
4. Socket 失效时客户端可拉起 detached 后端宿主并重试连接。
5. Agent 流式增量、完成、错误事件继续映射为原有 `AiRolesService` 回调。
6. `stopAll` 停止角色 Agent 但不删除角色和后端宿主 Socket。
7. 删除角色先停止后端 bridge，再删除角色目录。
8. 既有 TTS、Markdown、roleList 和控制端在线状态测试继续通过。

## 兼容性测试

- Claude 既有 FIFO 重连测试继续通过。
- Codex JSON-RPC、无活动超时和权限参数测试继续通过。
- 服务器启动、控制端 WebSocket 角色管理和普通 LLM 聊天测试继续通过。
- 既有日志文件和 `res/tasks/*/results` 运行结果不纳入本次提交。

## 性能测试

- Unix Socket 单次控制请求不引入网络依赖；流式增量按行转发，不缓存完整回复。
- 服务器重启期间不重复启动 Agent，避免重复消耗模型进程和上下文。

## 风险评估

- 后端宿主异常退出时，活动中的 IPC 回复可能丢失；服务端必须返回离线状态并允许下一次消息重建。
- Socket 残留可能指向已退出进程；客户端连接失败后必须验证并清理旧 Socket，不能直接覆盖仍在监听的宿主。
- 多个服务器实例同时启动可能竞争拉起宿主；客户端连接重试和 Socket 原子监听失败必须保证最终只保留一个宿主。

## 预计工时

约 4 小时：IPC 宿主与客户端 2 小时，服务生命周期接入 1 小时，测试与文档 1 小时。
