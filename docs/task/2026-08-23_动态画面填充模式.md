# 动态画面填充模式

## 任务描述

为控制端和显示端增加动态画面填充模式，使画面在适应和铺满之间循环过渡。默认过渡 3 秒、每个状态停留 2 秒，并允许控制端按显示端配置这两个时间。

## Design 需求

- 新增 `dynamic` 填充模式。
- 循环顺序：适应停留 → 过渡到铺满 → 铺满停留 → 过渡到适应。
- 服务端保存 `dynamicFitConfig`，显示端重连后恢复。
- 切换模式、切换媒体或尺寸变化不能残留旧定时器。

## Spec 设计

- 使用独立 `DynamicFitController` 管理阶段和定时器。
- 显示端复用 contain/cover 目标宽高计算，使用 CSS width/height transition 动画。
- 控制端通过 `dynamicFitConfig` 控制消息下发 `{ transitionSeconds, holdSeconds }`。

## 自测用例

1. 动态控制器按 2 秒停留、3 秒过渡依次产生 contain/cover 阶段。
2. 停止后旧定时器不再改变画面，重新启动只存在一条循环。
3. 控制端修改参数后服务端保存并转发规范化值。
4. 控制端刷新/显示端重连后恢复动态按钮和两个时间输入。
5. 动态模式在图片和视频上平滑循环，切换其他模式立即停止。
6. 旋转、裁剪、HTML 媒体和已有填充模式不回归。

## 兼容性测试

- 保持旧状态中没有 `dynamicFitConfig` 时使用 3 秒/2 秒默认值。
- 保持 `contain`、`cover`、`height`、`width`、`crop` 协议和视觉行为不变。
- 普通浏览器和 Android WebView 均使用原生 CSS transition/setTimeout，不引入新依赖。

## 性能测试

- 动画只更新当前媒体元素宽高，不创建额外媒体节点。
- 循环过程中最多保留一个定时器，切换模式时清理。

## 风险评估

- 媒体元数据尚未加载时无法计算目标尺寸，待 load/loadedmetadata 后由现有 `applyCrop` 重新计算。
- 浏览器后台节流 setTimeout 属于浏览器正常行为，页面回到前台后继续下一阶段。
