# Offline 启动器独立版本与服务单独更新

## 任务描述

当前 code 版本变化就会触发 launcher 进程切换。将 launcher 内容独立编号；launcher 文件没有变化时只安装并启动新服务代码。

## 需求与设计

- code ZIP 继续携带 launcher，无额外发布产物。
- 签名清单记录 launcherVersion 与 launcherSha256；内容相同沿用版本，内容变化使用递增的 code 版本号。
- 更新端下载并校验目标 code 后比较目标与当前运行 launcher 的实际内容。相同只更新服务，不同按现有切换与回退流程处理。
- 旧签名清单缺少新字段时用实际内容比对兼容；首次发布新逻辑时旧 launcher 仍可能切换一次。

## Spec 与受影响模块

见 `docs/spec/android-offline-js-launcher.md`。修改 `scripts/ops/offline-update-package.js`、`src/apps/server/boot/offline-launcher/releases.js`、`controller.js`，增加共享的 launcher 内容指纹 helper，并更新 `tests/offline-js-launcher.test.js`、`tests/offline-update-package.test.js`。

## 自测与兼容

- 相同 launcher / 不同服务 code 只触发服务更新，保持 launcher 进程及状态指针。
- launcher 或共享文件变化触发原有切换；签名指纹与实际内容不一致拒绝更新。
- 验证旧清单兼容、打包版本沿用与递增、服务健康失败回滚和既有启动器切换测试。
- 使用 `npm run test:offline-launcher` 与 `node --test tests/offline-update-package.test.js`；不执行 APK 出包或发布。

## 风险与预计工时

APK 基线代码不包含此新逻辑，首次升级会按旧规则切换；需要现场验证 launcher 未重启而服务版本前进。预估开发与测试约 3 小时。
