# Offline 代码包自动升级依赖包

## 任务描述

当执行 Offline `code-only` 构建时，如果当前 `package-lock.json` 与已发布 dependencies 的 lock 指纹不一致，应自动升级为 `all`，递增依赖版本并生成新的代码包、生产依赖包和签名清单，避免用户手动判断依赖是否需要重新发布。

## design 需求

- lock 指纹一致时保持原有 code-only 行为。
- lock 指纹变化时自动使用当前 dependencies 版本加一；允许显式 `--dependency-version` 覆盖，但必须高于线上版本。
- 没有有效线上依赖基线时不自动猜测，仍要求显式 all/bootstrap。
- 构建自动生成依赖包；正式上传仍由现有发布命令执行，保持原子发布和精确清理规则。

## spec 设计

- `createOfflineUpdateArtifacts` 返回 `requestedMode`、实际 `mode` 和 `autoDependencyUpgrade`。
- `code-only` lock mismatch 时实际模式为 `all`，调用现有 `buildDependencyArchive`，清单同时替换 code/dependencies。
- lock match 时不执行 `npm ci`，依赖包路径为空并沿用线上 dependencies 组件。
- 代码包和依赖包仍使用同一个 lock SHA-256，并由同一签名清单原子发布。

## 自测用例

1. lock 指纹相同时，`code-only` 不运行 `npm ci`，不生成 dependencies 包。
2. lock 指纹变化时，`code-only` 自动生成递增版本 dependencies 包，manifest 同时引用两个新组件。
3. 显式依赖版本低于或等于线上版本时拒绝构建。
4. 没有有效 dependencies 基线时拒绝自动升级。
5. 新清单签名、code/dependencies hash 和 ZIP 内容校验通过。

## 兼容性测试

- 既有 code-only、all、bootstrap 测试保持通过。
- 发布器继续按实际清单组件上传，LAN/WAN 原子切换逻辑不变。
- 旧设备仍按签名清单中的 requiredDependencyVersion 选择已安装 release。

## 性能测试

- lock match 路径不执行依赖安装，保持 code-only 构建耗时。
- lock mismatch 路径额外执行一次生产依赖安装和 ZIP 打包，记录生成耗时与大小。

## 风险评估

- 依赖包可能较大，自动升级会增加构建和上传时间；清单仍只有在所有工件校验通过后才切换。
- 当前 package-lock 存在未预期变化时，会触发依赖版本递增；需要发布前检查依赖包大小和 lock 指纹。
- 构建失败不应留下可引用的半成品清单或覆盖已有版本文件。

## 预计工时

- 构建逻辑与单测：1 小时
- 文档与实际构建验证：0.5 小时
