# 语音修复模式

## 任务描述

在显示端通过语音输入进入修复模式，使用共用明文密码认证；修复模式下所有请求必须确认后交给可配置的工作 Agent，并暂停其他 TTS 播报。

## Design 需求

- 入口：显示端说“进入修复模式”；下一条输入作为密码。
- 配置：`repairMode.password` 为共用明文密码，`repairMode.role` 为 `aiRoles` 中的工作角色。
- 路由：复用 `AiRolesService`，不使用普通聊天 Pi Agent。
- 安全：密码不记录日志、历史或 Agent 请求；只接受显示端输入。
- 确认：每条修复请求需“确认/是/好的”提交，或“取消/拒绝”丢弃。
- TTS：进入后停止当前普通播报并抑制普通 TTS；修复提示与回复可以播报；退出后恢复。

## Spec 设计

服务端为每个显示端维护 inactive、awaitingPassword、active、pendingConfirmation 状态和超时；active 状态优先处理退出命令，其他文本进入待确认队列。确认后用配置角色调用 `aiRoles.chat`，沿用工作 Agent 的流式回调和 TTS 处理。

## 受影响功能模块和代码

- `src/apps/server/modules/voice/repair-mode.js`：纯状态机。
- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：新增修复模式内置命令。
- `src/apps/server/boot/server-app.js`：显示端拦截、密码校验、确认、Agent 路由、TTS 抑制和生命周期清理。
- `src/apps/server/modules/chat/agent-chat-tts.js`：支持修复 TTS 放行、普通 TTS 抑制。
- `config/config.json`：增加修复模式配置字段。

## 自测用例

1. 内置命令识别“进入修复模式”和“退出修复模式”。
2. 中文明文密码正确进入，错误密码不进入，密码不出现在日志/历史/Agent 内容。
3. 修复文本先生成确认提示；确认调用配置角色，取消不调用。
4. 非配置角色不能启动修复模式。
5. 修复模式停止普通播报；修复提示和回复仍可播报；退出恢复。
6. 断开显示端、关闭监听和超时清理状态。

## 兼容性测试

- 普通显示端唤醒、普通聊天、普通对话确认和控制端工作 Agent 行为保持不变。
- 旧子显示端继续使用原有语音命令路径，不要求新增修复协议。

## 性能测试

- 状态转换只操作单显示端 Map 和计时器，不增加 ASR 推理。
- 修复 Agent 仍沿用现有流式 TTS 调度器，不改变普通并发上限。

## 风险评估

- 明文密码属于用户明确要求，配置文件泄露会导致修复模式被进入；部署时应限制配置文件权限。
- 普通 TTS 抑制依赖统一发送出口，新增播报路径必须继续使用该出口或显式声明修复放行。
