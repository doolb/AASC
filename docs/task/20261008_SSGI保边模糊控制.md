# SSGI可调保边模糊控制

日期：2026-10-08。状态：代码、自动测试与Web构建完成；实际画面/设备验收待后续。用户选择AO式模糊控件，默认1轮/3px。

## 任务描述

用户反馈独立MMD-AR测试页的SSGI反弹光有较多颗粒，询问能否像AO一样加入模糊。现有SSGI并非完全无模糊：已固定执行一轮横/纵5抽头深度与法线双边滤波；本任务将其扩展为可调的多轮保边滤波。

## Design 需求

- 在“接触阴影 / 间接光（实验）”面板新增SSGI“模糊轮数”0–3选择及每轮独立的“模糊半径”1–5效果像素控件。
- 默认1轮、半径3px；复用现有 `aasc.mmdArTest.screenLighting.v1` 本地设置键，旧设置缺模糊字段时按新默认值。
- 深度/法线/切平面距离边缘权重继续生效，避免轮廓跨表面串色；仅滤波SSGI反弹光RGB，接触阴影alpha沿用中心像素，不让GI降噪软化接触阴影。
- 0轮旁路滤波；多轮在两个已有中间目标间ping-pong，禁止同纹理读写。接触阴影单开时不执行GI滤波轮次。
- 接触阴影和SSGI实验总开关保持默认关闭；不引入时域累积、历史帧或拖影。

## 自测用例

1. 旧存储缺字段和非法轮数/半径回到1轮/[3,3,3]；控制在轮数0–3与半径1–5；刷新持久化、灯光恢复默认回1轮/3px。
2. 0轮时原始SSGI目标直接供合成，不执行滤波绘制；1–3轮按H/V各一次绘制，radius分别使用对应轮设置。
3. GI开启时只滤波反弹光RGB，接触阴影alpha与滤波前中心像素相同；GI关闭/仅接触阴影时不执行GI滤波。
4. 多轮在target[1]/target[2]之间交替，无输入/输出目标相同；轮廓深度/法线边界不跨表面混色。
5. `node --test tests/mmd-ar-screen-lighting.test.js`、相关语法检查和 `npm run build:web:mmd-ar-test` 通过。
6. 对比低/中/高质量及0–3轮截图；记录平坦表面颗粒变化、薄发丝/轮廓细节和帧耗时。自动/设备显示需可用浏览器或目标设备时另行确认。

## 兼容、性能与风险

- 实验总开关默认关闭，保留旧页面行为；旧localStorage对象只补默认模糊字段，不丢弃现有质量、强度和半径值。
- 现有固定半径为5抽头一轮；新默认1轮/3px略增强模糊。更多轮数会增加低分辨率全屏绘制和纹理采样，可能柔化小尺度反弹光。
- 边缘双边权重避免几何跨边扩散，但屏幕空间缺少屏外数据和透明多层信息，无法保证所有衣物/头发场景无伪影。
- 只改变SSGI RGB，接触阴影alpha不模糊；不添加跨帧累积，不能承诺消除随运动变化的全部噪点。
- 不改正式显示端、服务配置、APK或Offline发布状态。
