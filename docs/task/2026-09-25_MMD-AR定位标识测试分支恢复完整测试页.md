# MMD AR 定位标识测试分支恢复完整测试页

## 任务描述

恢复 HTTPS MMD AR 测试网页的完整测试 harness，包括 PMX/VMD 模型、Three.js/Ammo、灯光/AO、物理、旋转交互及定位 UI。MindAR 识别到目标时，仅在网页专用测试模式中显示定位标识，然后立即 `return`，不把该帧定位姿态应用到模型。APK 和正式显示端行为保持不变，并将完整网页重新发布到既有 `/mnt/mmd-ar/` 地址。

## 受影响模块

- `3rd/mmd-ar-test/build.js`：保留完整网页资源 staging，并为 HTTPS 页面注入标记测试开关和标记 DOM。
- `src/apps/web-mediacenter/ui/public/js/display-mmd-ar.js`：只在网页测试开关下显示/隐藏标记，识别到后提前返回；普通模式继续应用模型姿态。
- `3rd/mmd-ar-test/display-mmd-ar-benchmark.js`：继续使用 MindAR 单算法网页适配层，不引入纯定位轻量页。
- `docs/design/mmd-ar-test-apk.md`、`docs/spec/mmd-ar-test-apk.md`、`docs/usage.md`、`docs/self-test.md`、`docs/todo.md`、`changelog.md`。

## Design 需求与 Spec 伪代码

完整 MMD 测试场景照常加载。目标识别分支在网页标记测试开关开启时，使用识别姿态计算 cover 舞台坐标、显示屏幕标记并结束本帧处理，不触发 `DisplayMmd.setArPose`。目标丢失、异常、无姿态或停止时隐藏标记。测试开关仅由静态 HTTPS 测试页设置。

## 自测用例

- 构建输出仍包含 MMD canvas/runtime、Three.js、Ammo、模型 profile、默认 PMX/纹理/VMD 和 MindAR 固定资源。
- 首页仍初始化角色模型与完整灯光/定位面板。
- 静态检查定位标记分支在 `setPose` 后立即返回，返回之前没有模型姿态更新调用。
- 普通 APK 和正式显示端不设置测试标记开关，沿用原模型定位行为。
- 远端首页与所有本次构建资源均可访问且 SHA-256 与本地一致。

## 兼容性、性能与风险

定位算法和识别分辨率设置不变；标记为不拦截输入的 DOM 覆盖层。完整 MMD 仍会占用 WebGL/GPU，定位测试分支只避免将识别姿态应用于模型，并不降低模型渲染或 MindAR 本身的负载。真机首锁、标记视觉对齐和页面交互需现场验收。
