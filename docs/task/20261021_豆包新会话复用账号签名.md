# 豆包新会话复用账号签名

## 需求与设计

用户询问新会话能否复用上次签名，已用当前浏览器/设备做隔离协议验证，未查网上资料。真实证据及方案见chat2api-doubao-web design/spec对应节。拟普通Node模式改为同账号、同凭据及模式共享最近有效签名，正文和权威会话仍独立；等待用户按AGENTS确认生产改动。

## 自测、兼容与性能

Note8/min72 + 最新适配器隔离源码，临时测试副本关闭自动补发：一次原生prepare、三次Node HTTP2，同URL，新会话两个且local ID不同、消息ID三个不同；Responses三轮14/15/28字、HTTP200且完成，签名年龄35511毫秒。权威上游会话两个，ready轮数1/2。登录样本自动清理，仅按隔离记录逐一删除两个测试官网会话（status_code0），API Key剩余0；临时目录和新增转发清理，原9222保留。正式账号、AASC聊天及生产代码未改。

## 候选实现与受影响模块

chat2api-doubao-chat-adapter.js、chat2api-doubao-signature-store.js及定向测试；内存/私有文件按账号、凭据与模式共享，兼容旧按会话文件；失效清理同签名关联记录并只重签补发一次。保持消息和新会话参数独立、取消和总时限语义，原生关闭开关不改。拟补新会话/续聊/重启/凭据及账号隔离、旧文件兼容、失效后不重新载入坏签名的Responses测试。

## 风险、工时与状态

只有普通模式约36秒短时成功，未证明长期/其它模式；上线后仍依赖单次刷新恢复。账号级共享需避免多个会话重新加载失效条目及并发迟到删除新签名。预计实现和回归1小时；方案待确认，功能与产物状态未改。实现仅服务代码，既有min APK待构建项保持。
