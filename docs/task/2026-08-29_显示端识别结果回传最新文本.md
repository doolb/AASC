# 显示端识别结果回传最新文本

## 任务描述

控制端显示端列表在“监听中/等待唤醒”时显示“最近识别：暂无识别回传”。当显示端已经完成 ASR、但声纹没有匹配到注册用户时，服务端会提前丢弃 `voiceInput`，导致控制端看不到实际识别文字。需要回传所有有效识别文字，同时每个显示端只保留最新一条显示。

## Design 需求

- 所有有效 ASR 文字先回传控制端，包括声纹未匹配的结果。
- 声纹未匹配的结果只用于控制端观察，不进入唤醒、对话或命令处理链路。
- 控制端每个显示端只保留最新一条，不累积历史。
- 不改变监听状态、等待唤醒状态和 3 分钟对话计时规则。

## Spec 设计

```text
服务端收到 display.voiceInput:
    text 为空 -> 按现有规则忽略
    text 非空 -> broadcastToControls({ type: 'voiceInput', displayId, text, isFinal, speaker })
    voiceprint 开启且 speaker == null -> return
    继续执行现有显示端状态、唤醒和命令处理

控制端收到 voiceInput:
    displayId 无效或 text 为空 -> return
    latest = { text, isFinal, timestamp: now }
    voiceInputByDisplay[displayId] = latest
    重新渲染
    新结果覆盖旧结果，不追加历史数组
```

## 自测用例

1. 声纹关闭时，显示端识别文字回传控制端并显示最新一条。
2. 声纹开启且匹配成功时，文字回传控制端并继续进入命令处理。
3. 声纹开启但未匹配时，文字仍回传控制端，但不触发唤醒、对话或命令。
4. 连续识别多条文字时，控制端只显示最后一条。
5. 显示端进入等待唤醒时，识别结果仍可观察，不改变等待唤醒过滤规则。

## 性能测试

- 控制端仍使用单条 Map 数据，不新增识别历史数组，内存占用不随识别次数增长。
- 服务端只增加一次控制端广播，不增加 ASR 推理或命令处理次数。

## 风险评估

- 控制端可能看到未注册说话人的文字，但这些文字不会触发命令处理，符合观察与安全隔离要求。
- 控制端页面刷新或显示端重连后仍不恢复历史，只展示新的最新结果。

## 实现结果

- 服务端调整 `voiceInput` 处理顺序：先广播所有有效识别文字，再对未匹配声纹结果停止命令处理。
- 控制端继续按显示端覆盖保存最新一条，不新增历史数组。
- 验证：监听状态、显示列表、语音会话、监听回传和 WebSocket 重连相关测试 7/7 通过；`node --check` 服务端和控制端脚本通过。
