# LLM chunk 日志完成后输出

## 任务描述

停止服务端逐条打印 LLM 流式 `llm.chunk` 日志，保留实时转发；在 `llm.completed` 到达后只打印一次完整生成文本。

## design 需求

- `llm.chunk` 进入按 `displayId + requestId` 的临时缓冲，不单独写 WS 日志。
- `llm.completed` 优先使用完整结果文本，否则使用聚合缓冲，只打印一条日志并清理缓冲。
- `llm.error`、显示端断线和清理连接时释放对应缓冲，不打印半截生成内容。
- 不改变显示端到网关的流式链路、HTTP SSE 和非流式响应。

## spec 设计

```text
llm.chunk(displayId, requestId, text)
  -> logBuffer[displayId + requestId] += text
  -> forward unchanged
  -> no WS log

llm.completed(displayId, requestId, text)
  -> finalText = text or logBuffer
  -> delete buffer
  -> log one complete result
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：增加 LLM 日志缓冲、完成时输出和断线清理。
- `tests/llm-chunk-log.test.js`：增加不逐 chunk 打印的静态契约测试。
- `docs/design/android-mnnchat-llm.md`、`docs/spec/android-mnnchat-llm.md`、`docs/todo.md`、`changelog.md`。

## 自测用例

1. 连续收到多个 `llm.chunk` 时不产生对应 WS 日志。
2. 收到 `llm.completed` 后只产生一条完整结果日志。
3. 完成消息无文本时使用 chunk 聚合文本。
4. 错误或显示端断线后清理缓冲，不泄漏 requestId。
5. 网关仍收到并处理每个 `llm.chunk`，流式 HTTP 客户端行为不变。

## 风险评估

- 风险：未完成请求的文本缓冲长期占用内存。
  - 控制：完成、错误、断线和死连接清理均删除对应 requestId 缓冲。
- 风险：完整结果包含特殊字符影响日志可读性。
  - 控制：沿用现有日志文本格式，不改变结果内容，只改变输出时机。
