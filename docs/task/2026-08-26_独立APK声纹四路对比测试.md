# 独立 APK 声纹测试范围收敛为 Sherpa 两路

## 任务描述

在 `3rd/tts-server/android-asr` 独立 Android APK 中增加浏览器访问的声纹测试网页，删除 WeSpeaker 测试，只保留两种 Sherpa 流程。

## Design 需求

- 保留现有原生 ASR 页面和 HTTP 服务。
- 浏览器访问 APK HTTP 地址，不使用主项目服务器和 WebSocket。
- 加入 Sherpa 单段匹配、Sherpa 多人分段匹配。
- 支持 WAV 选择和网页录音。
- 展示匹配人名、相似度、分段、模型状态、阶段耗时和错误。
- Sherpa 两种路径统一调用 APK 内置 sherpa-onnx AAR；单段使用 embedding + manager，多段使用 diarization + 分段 embedding + manager。

## Spec 设计

- 新增 `VoiceprintTestCoordinator` 统一分派两种 Sherpa 模式。
- 新增 Sherpa 单段/多人 engine，复用独立 APK 的 AAR 和 SenseVoice ASR。
- `AsrHttpServer` 新增 `/api/voiceprint/status`、`/api/voiceprint/register`、`/api/voiceprint/test`。
- `AsrWebPage` 增加模式选择、注册声纹、运行测试和结果渲染。

## 受影响功能模块和代码

- `3rd/tts-server/android-asr/app/src/main/java/com/aasc/asr/AsrWebPage.kt`
- `3rd/tts-server/android-asr/app/src/main/java/com/aasc/asr/AsrHttpServer.kt`
- `3rd/tts-server/android-asr/app/src/main/java/com/aasc/asr/` 新增声纹测试类
- `3rd/tts-server/android-asr/app/build.gradle.kts`
- `3rd/tts-server/android-asr/app/src/main/assets/` 声纹测试模型
- `3rd/tts-server/android-asr/app/src/test/` 声纹纯逻辑测试

## 自测用例

1. 网页能从电脑/手机访问 APK HTTP 地址。
2. `/health` 和声纹状态接口能报告模型状态。
3. 同一注册 WAV 和测试 WAV 在 Sherpa 单段模式返回同一 speaker。
4. Sherpa 多人模式返回所有分段，并保留未匹配 speaker。
5. Sherpa 单段模式返回 speaker、ASR 文本和耗时。
6. Sherpa 多人模式返回分段、speaker 和 ASR 文本。
7. 空音频、非法模式、模型未加载时返回明确 JSON 错误。
8. 现有 `/api/asr` 和原生 ASR 页面回归通过。

## 兼容性测试

- Android 9、arm64-v8a、SM-N9500 真机。
- 电脑浏览器和手机浏览器访问同一 APK 地址。
- 16 kHz WAV、44.1 kHz WAV、网页录音三类输入。
- 不影响主项目 `com.aasc.display` APK。

## 性能测试

- 每个模型只初始化一次。
- 单段和多人模式分别记录模型加载、embedding、匹配、分段、ASR 和总耗时。
- 连续 10 次测试不出现线程、句柄或内存持续增长。

## 风险评估

- 多人分段会显著增加推理时间，页面必须显示阶段耗时。
- Sherpa embedding 与分割模型同时加载可能增加内存；模型只初始化一次，并串行化声纹任务。

## 预计工时

约 4-6 小时，包含 runtime 接入、网页/API、纯逻辑测试、APK 构建和真机验证。

## 首轮真机测试结果（2026-08-27）

- 测试设备：SM-N9500，Android 9，arm64-v8a；测试输入均为 16kHz、单声道、16bit WAV。
- 注册库：`zh.wav → ZH`、`en.wav → EN`；测试音频：`zh.wav`、`en.wav`、`zh-en.wav`（串接）、`zh-en-mix.wav`（混合）。
- WeSpeaker 单段：4/4 成功。`zh.wav` 匹配 ZH（1.000），`en.wav` 匹配 EN（1.000），`zh-en.wav` 匹配 ZH（0.731），`zh-en-mix.wav` 匹配 EN（0.670）；文字均有返回。
- WeSpeaker 多段：0/4 成功，4 个音频均在重复滑窗 embedding 阶段触发 `OutOfMemoryError`；去掉 ASR 模型后仍复现。
- Sherpa 单段：4/4 成功；四个音频均返回文字和注册名称。
- Sherpa 多段：4/4 成功；`zh-en.wav` 能分出 ZH/EN，但有短未知段和重叠；`zh-en-mix.wav` 返回重叠 ZH/EN 段，文字以 EN 为主。
- 结论：当前最稳定的是 Sherpa 单段和 Sherpa 多段；WeSpeaker 单段可作为匹配基线，WeSpeaker 多段需先解决 native 内存问题，暂不接入网页/APK。
- 本轮使用的临时测试代码、测试 APK、设备临时音频和模型已清理，未改生产代码。

## 范围调整（2026-08-27）

- 删除 WeSpeaker 模型、运行时、注册/测试接口和网页模式。
- 保留 Sherpa 单段与 Sherpa 多段，继续使用 `zh.wav`、`en.wav`、中文后串接英文以及中英文混合四个 WAV 做回归。
- 注册接口使用 HTTP WAV 二进制请求体和 URL speaker 名称；测试接口使用 `mode=SHERPA_SINGLE|SHERPA_MULTI` 查询参数。
- 声纹库只存在 APK 进程内存，不引入持久化和主项目服务器同步。
