# 任务：控制端显示内置命令列表

## 任务描述

控制端已有“系统指令帮助”弹窗，但内置命令说明是静态 HTML，无法体现当前服务端实际支持的免唤醒内置功能。改为由语音命令服务提供统一清单，控制端动态展示命令示例、功能说明和唤醒要求。

## Design 需求

- 复用现有“系统指令帮助”弹窗，不新增独立页面。
- 展示服务端当前内置功能命令，包括报时、提醒、静音、天气、搜索、播放等。
- 每条命令展示示例、功能说明和“无需唤醒”标记。
- 普通聊天、自定义命令和会话控制词不列为免唤醒内置功能。
- WebSocket 重连后重新加载，服务端清单作为唯一数据来源。

## Spec 设计

```text
Chat 初始化或 WebSocket 重连:
    发送 getBuiltinVoiceCommands

服务端收到 getBuiltinVoiceCommands:
    调用 voiceCommand.getBuiltinVoiceCommands()
    返回 builtinVoiceCommands(commands)

控制端收到 builtinVoiceCommands:
    保存 commands
    如果帮助弹窗存在 -> 渲染命令卡片

渲染每条命令:
    显示 examples
    显示 description
    显示 wakeRequired=false 对应的“无需唤醒”标签
```

## 自测用例

1. 服务端返回非空内置命令清单。
2. 清单包含“现在几点”，每项包含示例数组和功能说明。
3. 控制端请求、接收并渲染 `builtinVoiceCommands`。
4. 系统指令帮助弹窗显示动态命令区域和“无需唤醒”标签。
5. WebSocket 重连后重新请求命令清单。

## 兼容性测试

- 不改变原有 `getChatCommands` 自定义命令协议。
- 不改变语音命令执行、唤醒状态机和显示端协议。
- 深色和浅色主题均使用现有主题变量显示。
- 服务端命令清单不可用时，控制端显示加载/空列表提示，不影响其他聊天功能。

## 性能测试

- 仅在控制端初始化和 WebSocket 重连时请求一次清单。
- 清单保存在内存，不新增轮询、持久化文件或 ASR/TTS 请求。

## 风险评估

- 新增 WebSocket 消息类型需要保持服务端和控制端版本兼容；旧控制端忽略未知消息不影响原有功能。
- 内置命令定义增加展示字段后，必须保留 matcher 与展示数据的一致来源，避免列表误导用户。

## 预计工时

约 1 小时，包含服务端清单、控制端渲染、样式、测试和文档同步。
