# 跨显示端 TTS 期间暂停监听

## 任务描述

修复 TTS 播放显示端与录音/ASR 显示端不是同一台设备时，录音显示端仍持续采集并把房间内播报声识别成用户指令的问题。将原有播放目标本机暂停扩展为服务端协调的跨显示端播报状态。

## design 需求

- 任一显示端开始播放 TTS 时，所有未启用声纹识别的录音显示端暂停 PCM/VAD。
- 播放目标实际结束、失败或停止后，所有相关录音端恢复。
- 多目标、多句 TTS 不能因单个目标或单句提前结束而误恢复。
- 暂停期间复用已有麦克风、AudioContext 和 PCM 采集器。
- 旧显示端缺少完成回报时必须有超时兜底。

## spec 设计

- 服务端统一 `sendToDisplay()` 为 `tts/playAudio` 注入 `voiceTtsPlaybackId`，并广播 `voiceTtsPlaybackState=started`。
- 显示端播放结束回传 `voiceTtsPlaybackFinished`，服务端广播对应 `finished` 状态。
- Web 显示端维护远程活动播放 ID 集合，与本地暂停状态合并。
- Node 子显示端沿用已有 `recorder.pause()/resume()`，补充跨端状态和完成回报。

## 自测用例

1. 显示端 A 录音、显示端 B 播报：A 在 B 播报期间不发送 `asrAudio`，B 结束后 A 恢复。
2. 两台播报显示端同时播放：第一台结束时 A 仍暂停，全部结束后才恢复。
3. 连续多句 TTS：播放 ID 不同，句间不误恢复。
4. TTS 播放失败/停止：录音端收到结束状态并恢复。
5. 旧播放端不回报完成：服务端超时后录音端自动恢复。
6. 开启声纹识别：录音端忽略全局暂停状态。
7. 播报目标本身同时录音：本地暂停和跨端暂停不重复创建或释放音频资源。

## 兼容性测试

- Web 显示端到 Web 显示端。
- Web 显示端到 Node 子显示端。
- Node 子显示端到 Web 显示端。
- 多显示端 TTS 广播、文本媒体逐句 TTS 和停止播报。
- 旧客户端忽略新消息时的服务端超时恢复。

## 性能测试

- 连续 20 条 TTS 期间不创建新的 Web `AudioContext` 或麦克风轨道。
- 多台显示端同时播报时，服务端播放状态定时器按播放 ID可控增长并在完成后清理。

## 风险评估

- 播放完成回报丢失会导致短暂暂停，由超时机制限制最长暂停时间。
- 同一音频发给多个目标必须区分目标完成状态，不能使用单一全局布尔值。
- 本地 TTS 与远程 TTS 共用音频元素，完成回报必须携带对应播放 ID，避免串联旧回报。
