# ASR 测试 APK 内置麦克风无声诊断

## 任务描述

SM-N9500 测试 APK 暴露系统默认、主内置、后置内置和蓝牙等输入项。用户确认主内置麦克风音质较好，但录音回放没有声音；需要保证主内置麦克风可被明确选择，并能定位录音线程、实际路由和 PCM 信号是否正常。

## design 需求

- 主内置麦克风优先作为首次运行默认项；已保存选择和显式系统默认选择保持不变。
- 两个内置麦克风使用不同的可读名称；通过 `TYPE_BUILTIN_MIC` 的 `address=back` 区分后置输入；输入设备名称显示 Android 设备 ID。
- 录音线程使用阻塞读取并记录实际路由设备、样本数、峰值和 RMS。
- 录音结束后区分有效录音、PCM 全零和启动失败，不改变现有蓝牙 SCO 的 8 kHz 采集与重采样。

## spec 设计

- 新增 `AudioCaptureStats` 数据结构及 `AudioRecorder.captureStats()` 查询入口。
- `AudioInputDevice` 增加主内置/后置内置类型名和首次运行默认选择策略。
- `MainActivity` 在停止录音后展示实际路由和音量统计；静音 PCM 显示明确诊断信息。

## 受影响模块

- `AudioInputDevice.kt`、`AudioRecorder.kt`、`AudioCaptureStats.kt`、`MainActivity.kt`
- `AudioInputDeviceTest.kt`、`AudioCaptureStatsTest.kt`、`tests/android-asr-apk.test.js`
- ASR 测试 APK design/spec/todo/changelog 文档

## 自测用例

1. 新安装或清除选择后，存在 ID 10 时默认选择主内置麦克风。
2. ID 10 和 ID 11 在下拉框中显示不同的内置麦克风名称及设备 ID。
3. 录音使用 `READ_BLOCKING`，停止后能显示实际路由、样本数、峰值和 RMS。
4. 输入全零时页面显示“没有有效声音”，不能误报为普通有效录音。
5. 蓝牙 SCO、系统默认和既有设备回退链路保持兼容。

## 兼容性测试

- Android 9/API 28：验证 `AudioRecord.routedDevice`、`READ_BLOCKING`、设备 ID 10/11 和 Bluetooth SCO 不崩溃。
- 其他 Android 版本：实际路由不可用时显示未知设备，但保留样本统计和录音结果。

## 性能测试

- 信号统计在已有录音循环内完成，不新增采集线程、不改变 ASR 推理输入采样率。
- `READ_BLOCKING` 避免空数据时忙循环，录音停止和资源释放保持原有时序。

## 风险评估

- 不同厂商可能不返回有效 `routedDevice` 或输入电平，页面允许显示未知设备，但仍保留样本统计。
- 设备地址命名可能不同；无法识别 `back` 时仍显示通用内置主麦克风名称和设备 ID。
- UI 自动化桥可能无法点击测试 APK，真实三种麦克风的峰值和回放仍需现场确认。
