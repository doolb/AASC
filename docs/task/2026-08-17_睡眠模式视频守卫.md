# 睡眠模式视频未暂停修复（播放路径缺睡眠守卫）

## 任务状态：✅ 已完成

## 设计需求

参考：[design/display.md](../design/display.md)（睡眠模式视频播放守卫）

## 问题描述

睡眠模式下视频仍会播放：
1. **单视频**：进入睡眠后视频 pause，但点击页面后视频恢复播放（有声音/继续播）
2. **批量播放**：播放列表视频在睡眠中播完自动切播下一个，视频持续播放

## 根因

进入睡眠只调 `pauseSleepMedia()` 做一次 `mediaVideo.pause()`，但视频播放/恢复路径没有 `isSleepPaused()` 守卫（睡眠守卫此前只用于 TTS 三条路径）：

| 路径 | 位置 | 问题 |
|------|------|------|
| `document click` 监听 | display.html | `display:block && paused` 时任何点击页面都 `mediaVideo.play()`（无人值守盒子睡眠中点击遮罩/系统 UI 即恢复；puppeteer 实测确证） |
| `keydown` 空格 | display.html | 睡眠中空格切换播放/暂停 |
| `handleControl('play', value=true)` | display.html | 睡眠中控制端发播放命令 resume 视频 |
| `playCurrentItem()` | display.html | `ended`/`error`/`timer` 触发自动切播，睡眠中视频持续切播 |

## spec 设计

参考：[spec/display-sleep-mode.md](../spec/display-sleep-mode.md)（「睡眠期间视频播放路径守卫」小节）

```
document click 监听:
    若 isSleepPaused(): return          # 睡眠中点击不恢复视频
    若 display==='block' && paused: mediaVideo.play()

keydown 空格:
    若 isSleepPaused(): return          # 睡眠中忽略空格播放/暂停切换

handleControl 'play' (value=true):
    若 isSleepPaused(): break           # 睡眠中拒绝播放命令（value=false 暂停仍生效并上报）

playCurrentItem():
    若 isSleepPaused(): return          # 睡眠中不切播（ended/error/timer 触达时跳过，唤醒后恢复当前项）
```

## 自测用例

1. 单视频播放中（display=block）→ 进入 sleep → `paused=true`
2. 睡眠中 `document click` → 视频保持暂停（修复前 resume）
3. 睡眠中 `keydown 空格` → 视频保持暂停
4. 睡眠中 `handleControl('play', true)` → 视频保持暂停（play 命令拒绝）；`play` false 仍暂停并上报
5. 播放列表 sleep 中 `playCurrentItem()` → 不加载播放列表项（哨兵 src 不被覆盖）、index 不推进
6. `node tests/display-sleep-mode.test.js` → 27 步全绿

## 兼容性测试

- 唤醒（normal/active）：`resumeSleepMedia` 正常续播当前视频（守卫不拦截唤醒路径）
- 批量播放暂停/继续/上一个/下一个（`handlePlaylistControl`）：不受守卫影响（playCurrentItem 仅在睡眠时 return）
- 控制端 play 命令正常态仍生效（守卫仅在睡眠时拦截 value=true）

## 性能测试

- 无新增开销：每处守卫是 O(1) 布尔判断

## 风险评估

- 低：守卫仅在睡眠态拦截，正常态行为不变
- 唤醒路径 `resumeSleepMedia` 不受影响（睡眠→正常时正常续播）
