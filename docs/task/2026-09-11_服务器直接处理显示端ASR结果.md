# 服务器直接处理显示端 ASR 结果

## 任务描述

将显示端上传录音后的 ASR/声纹业务处理从显示端迁移到服务器。服务器负责同一人的相邻分段拼接、不同人的切句、未识别声纹的分数回显、跨显示端去重和现有语音命令门控；显示端只负责上传录音和显示 HTTP 返回结果。

## Design 需求

- 设计文档：`docs/design/server-side-asr-voice-input-processing.md`
- 服务器接收 `displayId` 及可选录音时间区间。
- 相邻同一非空说话人分段直接拼接，`speaker=null` 保留为独立分段。
- 未识别声纹回传文字、相似度和阈值，但不触发命令。
- 兼容旧版 `voiceInput` WebSocket。

## Spec 设计

- 实现文档：`docs/spec/server-side-asr-voice-input-processing.md`
- 新增纯分段合并模块，服务器 HTTP 入口与旧 WebSocket 入口共用处理函数。
- 显示端上传 `displayId`、`speechStartAt`、`speechEndAt`，不再回传 `voiceInput`。

## 自测用例

1. 相邻同一说话人分段合并为一句，分数列表和时间保留。
2. 不同说话人不合并。
3. `speaker=null` 分段保留文字、分数和阈值，且不进入命令处理。
4. 显示端上传带 `displayId` 后，服务器直接广播并处理，不再产生新的 `voiceInput` 回传。
5. 旧版显示端主动发送 `voiceInput` 仍能进入原有链路。
6. 控制端上传不带 `displayId` 时不触发显示端语音命令处理。

## 兼容性测试

- 浏览器显示端与正式 Android APK 的 `/api/asr/recognize` 响应兼容。
- `SHERPA_SINGLE`、`SHERPA_MULTI`、`SHERPA_MULTI_FAST` 结果兼容。
- 服务端 ASR 和显示端 ASR 路由兼容。
- 旧版 `voiceInput` WebSocket 消息兼容。

## 性能测试

- 合并操作仅遍历一次分段，时间复杂度 O(n)。
- 不增加音频推理次数；每个 HTTP 请求只使用已有 ASR/声纹结果。
- 定向 Node 测试、JavaScript 语法检查和全量 Node 测试。

## 风险评估

- 显示端和服务器版本不同时，旧服务端可能无法利用 `displayId`，因此保留旧 WebSocket 兼容链路。
- `displayId` 缺失时无法安全把控制端上传归属到显示端，服务端只返回结果不代处理。
- 未识别分段继续回显可能增加控制端日志量，但不会触发命令。
