# 显示端同 ID 重连清理

## 任务描述

修复 Agent Puppeteer 测试浏览器长期保持显示端连接的问题：同一 `displayId` 重连时，旧 WebSocket 的延迟 `close` 回调会误删新连接；ViewBind 显示端列表还会重复登记同一 ID。

## Design 需求

- 一个 `displayId` 只保留一个当前 WebSocket。
- 新连接接管旧连接，旧连接关闭事件不得影响新连接。
- 当前连接关闭时才执行显示端移除、ViewBind 清理和业务断开回调。
- 不改变不同 `displayId` 并发连接、状态恢复和正常断开行为。

对应设计文档：`docs/design/websocket.md`、`docs/design/display.md`。

## Spec 设计

- `server-app.js` 登记显示端前关闭同 ID 旧连接。
- `server-app.js` 的 `close` 回调按 `displayClients.get(displayId).ws === ws` 做身份校验。
- `WSViewBindServer` 重连时移除旧 ViewBind；断开时按 WebSocket 身份校验。

对应实现文档：`docs/spec/websocket.md`。

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：显示端 WebSocket 接管与关闭清理。
- `src/core/viewbind/WSViewBindServer.js`：同 ID ViewBind 去重和安全断开。
- `src/core/viewbind/WSViewBindServer.test.js`：重连/旧连接延迟关闭回归测试。

## 自测用例

1. 同一 `displayId` 连接两次，ViewBind 列表数量保持 1。
2. 旧 WebSocket 调用 `handleDisplayDisconnect` 后，新 WebSocket 仍保留。
3. 当前 WebSocket 关闭后，列表数量变为 0。
4. 不同 `displayId` 同时连接仍全部保留。
5. 关闭遗留 Puppeteer 浏览器后，服务端 actors 列表不再包含 `display-fce1i3yy`。

## 兼容性测试

- Node.js + `ws` 8.x。
- 浏览器显示端、Android/WebView 显示端和 Node 子显示端保持现有连接协议不变。

## 性能测试

- 重连路径仅增加一次 Map 查询、列表去重和旧 WebSocket 关闭，不增加消息路径开销。
- 不改变心跳和高频状态上报频率。

## 风险评估

- 旧连接关闭事件与新连接登记存在异步竞态；通过 WebSocket 对象身份校验隔离旧事件。
- ViewBind 列表和服务端显示端 Map 分属两层；两层均执行去重，避免单层残留。
