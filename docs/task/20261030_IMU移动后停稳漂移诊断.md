## 机制判断与拟修复范围

源码先需要至少0.5秒静稳窗口，再连续确认0.7秒，叠加300ms输出，理想全新静置段至少约1.5秒才能在显示上清速；噪声或先前动作污染窗口会延后。1.26m/s²死区会隐藏小幅加速度，但不会消除已经积累的速度，也可能漏掉部分较慢减速。磁场辅助约束航向，本身不提供平移零速；单点加速度门槛又使建参常被打断。数据支持这些候选机制，不足以把完整轨迹误差归因于单一原因。

建议单独评审“停稳恢复”：在已学噪声与源时间对齐基础上统一窗口/累计置信，分别定义进入停稳和移动退出，联合验证恢复延迟、真实匀速/慢动作反例及位移误差，不无条件清速/衰减速度。同时对暂停重复源时间做历史去重复，保留最后有效运动历史及状态转换。拟改imu-engine.mjs/imu-denoiser.mjs、server.mjs、app.mjs和专项测试，具体L4草案/阈值及确认另行完成。
