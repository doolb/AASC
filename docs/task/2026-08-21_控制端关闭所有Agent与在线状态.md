# 控制端关闭所有 Agent 与在线状态

## 任务描述

在控制端系统设置中，在“重载服务端代码”按钮后增加“关闭所有 Agent”按钮。按钮只关闭当前运行的 Claude/Codex Agent 进程，不删除角色和任何角色文件。聊天 AI 角色 tab 显示 Agent 在线/离线状态；关闭全部 Agent 后实时刷新为离线。

## design 需求

- `AiRolesService.stopAll()` 统一停止内存中已连接的 Agent bridge，并清空运行时 bridge 状态。
- 新增 `POST /api/ai-roles/stop-all`，成功后广播最新 `roleList`。
- 角色 tab 使用服务端 `running` 状态显示在线/离线；控制端刷新后从 `roleList` 恢复状态。

## spec 设计

- `roleList.roles` 保留 `backend` 和 `running` 字段。
- `stopAll` 只调用 bridge.stop，不调用 RoleStore.remove。
- 下一次发送角色消息时按当前全局后端重新懒启动。

## 自测用例

- 点击关闭全部 Agent 后所有运行进程停止，角色仍存在。
- `role.json`、`history.json`、`workgroup/roles/<name>.md`、控制端 `history.md` 均保留。
- 关闭后服务端广播的角色列表全部显示 `running=false`。
- 角色 tab 显示在线/离线状态，控制端刷新后状态正确恢复。
- 关闭后再次发送角色消息，可以按当前后端重新启动。
- 没有运行 Agent 时点击按钮返回成功且停止数量为 0。

## 兼容性测试

- Claude 与 Codex 角色均支持停止。
- 删除角色仍保持原有“停止并删除角色数据”行为。
- 普通 LLM 聊天和 poll.js workgroup 队列不受影响。

## 风险评估

- 停止正在生成回复的 Agent 会使当前请求失败，控制端应显示失败状态；角色数据仍保留。
- bridge.stop 失败时继续处理其他角色，并返回已停止数量。

## 执行结果

已完成：

- 新增 `AiRolesService.stopAll()`，停止并清空当前 Claude/Codex bridge，使用 generation 防止已排队消息在停止后自动拉起 Agent。

- 系统设置中“关闭所有 Agent”按钮紧跟“重载代码”按钮，关闭操作保留所有角色、历史和角色定义文件。
