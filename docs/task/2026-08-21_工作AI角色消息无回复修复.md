# 工作 AI 角色消息无回复修复

## 任务描述

修复控制端向工作 AI 角色发送消息后没有回复的问题。

## design 需求

- Claude 角色桥必须以非交互流式模式运行。
- 角色消息从 FIFO 输入后，Claude 输出必须使用 stream-json，供桥接层解析成 `chatChunk` 和 `chatResponse`。
- 自定义 `commandArgs` 继续可覆盖默认 Claude 参数，测试替身不受影响。

## spec 设计

- 无自定义参数时默认使用 `--print --verbose`。
- 默认输入格式为 `stream-json`，输出格式为 `stream-json`。
- 开启 `--include-partial-messages`，保留流式增量事件。
- 使用 `--permission-mode bypassPermissions` 避免角色工作过程中被权限交互阻塞。
- 继续追加 `--append-system-prompt-file <prompt>`。

## 根因

原实现只追加提示词文件参数，Claude Code 默认进入交互模式；角色桥虽然把用户消息写入历史和 FIFO，但 Claude 进程退出，控制端收不到任何回复。

- `src/apps/server/modules/ai-roles/claude-bridge.test.js`。

## 自测用例

1. 无自定义 `commandArgs` 时包含完整 Claude stream-json 非交互参数。
2. 传入自定义 `commandArgs` 时保持原参数，不追加默认参数。
3. 现有假 Claude FIFO 流式回包测试全部通过。
4. 真实控制端发送 `chatMessage(mode=role)` 能收到 `chatChunk/chatResponse` 或明确错误。

## 兼容性测试

- Node.js AI 角色模块测试。
- Claude Code CLI 2.1.x。
- 控制端 `/control` WebSocket。

## 性能测试

- 不改变角色桥单进程和 FIFO 结构。
- 只在启动参数构造阶段增加固定参数，不增加额外轮询。

## 风险评估

- `bypassPermissions` 扩大角色进程权限，仅用于已有工作目录中的工作 AI 角色；参数保持可通过 `commandArgs` 自定义。
- Claude CLI 参数版本差异可能导致启动失败，错误会写入角色 `err.log` 并通过聊天失败回包返回。
