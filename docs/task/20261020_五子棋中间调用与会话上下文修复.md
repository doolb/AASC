# 五子棋中间调用与会话上下文修复

日期：2026-10-20

## 任务描述

用户要求支持自然语言前后包围的独立游戏调用行，例如叙述、`Game:五子棋,AI,落子,H8`、再叙述。另指出独立真实聊天入口第二轮原始请求没有上一轮上下文，且“小爱”角色设定在 `System:` 与 `User:` 重复。

## Design 需求与 Spec 设计

设计见 `docs/design/game-gomoku.md`，伪代码见 `docs/spec/game-gomoku.md`。游戏桥在有目标显示端时先收完整模型回复，再从任意位置识别独立 `Game:` 行；按权威 GM 校验结果输出叙述、语音与历史。行内普通文本仍不触发操作。独立真实聊天入口复用聊天服务 `addMessage` 保存每轮用户输入和 GM 校验后的最终助手正文，使用相同 private 会话键；GM 回执留在协议元数据。raw 组装中已作为 `System:` 完整末尾块的角色设定不再重复插为 `User:`。

## 受影响功能模块与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：中间独立行解析、完整回复缓冲与确认后展示。
- `src/apps/server/modules/game/game-chat-session.js`：真实角色会话按现有聊天历史接口保存用户与助手消息。
- `src/external/llm/llm-service.js`：raw 消息中的角色模板去重。
- `tests/game-gomoku.test.js`、`tests/game-chat-session.test.js`：中间调用、普通行内文本、GM 校验后展示、跨轮历史与 raw 角色去重。
- 五子棋 design/spec/usage、todo、changelog 和 Offline 待打包状态。

## 自测、兼容性与性能

运行 `npm run test:game-chat`，检查新旧协议、最多八条、非法调用、语音与聊天正文。用隔离棋局和“小爱”角色经本机 Qwen `aasc-qwen-flash` 复测目录→规则→9 路开局→User C3→AI 落子。由于任意位置都可能出现调用，有目标显示端的普通回复改为等整次模型输出后展示；无目标显示端仍走原流式聊天路径。上下文写入沿用已有私聊历史存储，不新增配置或网络端点。

## 风险与预计工时

完整回复缓冲会增加有目标显示端普通聊天的首字显示延迟。中间调用前的叙述若宣称成功，仍只能在 GM 校验完成后展示；失败批次丢弃。独立真实聊天测试若不隔离用户目录，会写入该角色的普通聊天历史，因此实测须使用临时运行目录。预计约两小时。

## 执行结果

定向测试 33/33 通过。隔离真实 Qwen 使用正式 `chatStream` 与“小爱”角色，依次完成目录、规则、9 路开局、User C3、AI E5；权威棋盘版本 3、轮到 User，最终叙述与回执一致。会话历史保存了两轮各一条用户消息和一条最终助手消息，未保存 GM 回执为普通聊天。

按用户追加要求，又用同一真实路径分别模拟一盘用户胜和一盘 AI 胜。用户胜盘 9 路、五次用户落子后 C5–G5 横向连五，权威版本 10、`User胜`；AI 胜盘用户下散子，AI 在 E5–E9 纵向连五，权威版本 11、`AI胜`。两盘均用独立临时棋局与临时聊天运行目录，测试后清理；第二盘模型终局文字仍说“接下来该你”，与权威终局矛盾，需另行修正或验收终局播报。真实显示端展示、空回复兜底也仍待后续验收。
