# 服务器 API 文档与命令行脚本

## 任务描述

整理当前 AASC 服务器 HTTP 接口，提供用户和 AI 可直接使用的 API 文档及 Bash 命令行脚本，覆盖播放、TTS 生成、ASR 识别、OCR、YOLO 和通用 HTTP 调用。

## Design 需求

- 完整记录当前稳定 HTTP 路由，不修改业务 API 协议。
- 高频操作提供独立 `.sh` 文件，其他接口通过通用调用器执行。
- 默认服务器为 `https://127.0.0.1:8081`，支持 `AASC_URL` 覆盖。
- 成功 stdout 输出 JSON，失败 stderr 输出错误并返回非零退出码。
- 删除、导入、停止、重启等高风险操作需要显式确认。
- `run-all.sh` 只调用无副作用的状态探针。

## Spec 设计

- `common.sh` 统一 curl、HTTPS、自签名证书、超时、临时文件和 HTTP 状态处理。
- `api-request.sh` 支持 JSON 和 multipart 参数。
- `play.sh` 调用 `/upload-file`；`tts-generate.sh` 调用 `/api/tts/generate`；`asr-recognize.sh` 调用 `/api/asr/recognize`；`vision-ocr.sh`/`vision-yolo.sh` 调用显示端本地视觉路由。
- `docs/api-usage.md` 记录服务器 API、WebSocket-only 边界和 AI 调用约定。

## 受影响的功能模块与代码

- 文档：`docs/api-usage.md`、`docs/design/api-usage.md`、`docs/spec/api-usage.md`、索引和使用说明。
- CLI：`scripts/api-tests/`。
- 工程配置：`package.json` 增加 `api:test`。
- 测试：`tests/api-cli-contract.test.js`。

## 自测用例

1. 每个脚本执行 `--help` 成功且不访问服务器。
2. `health.sh`、`media-list.sh` 和 `run-all.sh` 可访问本机服务器。
3. 使用 `/mnt/tmp` 现有音频/图片（如果服务能力在线）测试 ASR、OCR、YOLO；使用短文本测试 TTS。
4. `play.sh --file ... --display ...` 正确发送 multipart 文件和目标显示端。
5. 非法路径、缺文件、HTTP 4xx/5xx 返回非零退出码，错误不混入 stdout。
6. 危险接口缺少确认参数时不发出请求。

## 兼容性测试

- Bash 4+、curl；JSON 转义优先使用 jq，无 jq 时使用 Node.js fallback。
- HTTP/HTTPS 服务器地址、自签名证书和远程证书校验开关。
- Linux 用户手动执行、AI 通过 stdout/stderr/exit code 解析。

## 性能测试

- 只读探针串行执行，确认脚本不长时间持有临时文件。
- 文件上传使用 curl multipart，不在 shell 中复制大文件内容到变量。

## 风险评估

- 播放、TTS、ASR、OCR、YOLO 会产生服务端或显示端负载，脚本不默认加入 `run-all.sh`。
- 通用调用器可能调用任意 API；高风险方法和路径需要显式确认。
- 文档以当前路由源码为准，新增路由需要同步 API 目录。
