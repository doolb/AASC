# 任务：显示端状态栏独立开关

## 任务描述

控制端为每台显示端提供独立的状态栏显示开关。关闭状态栏时保留时间与媒体文件名、语音正文和模型任务进度。控制端竖屏导航保持左侧纵向布局。

## Design 需求

详见 `docs/design/display-status-bar.md`。配置按稳定 `displayId` 保存，默认显示；通过 AASC WebSocket 配置流程由服务端持久化、广播并在显示端重连时补发。

## Spec 设计

详见 `docs/spec/display-status-bar.md`。配置字段为 `showStatusBar`；控制端消息为 `setDisplayStatusBarConfig`，权威同步消息为 `displayStatusBarConfig` / `displayStatusBarConfigChanged`。

## 受影响模块与代码

- 控制端 `device-list.js` / `websocket.js` / `upload.css`：设备行开关及权威状态同步。
- 服务端 `server-app.js` / `config-app-service.js`：输入校验、按 `displayId` 持久化、显示端初始化补发和控制端广播。
- 显示端 `display.html` / `display.css`：接收配置并隐藏指定状态提示。
- `release/offline-release-status.json`：服务端和网页热更新代码变更后将 `servicePackage` 设为 `true`。
- 对应 design/spec/task、索引、usage、自测文档、todo 和 changelog。

## 自测用例

1. 两台显示端分别设置开/关，确认状态互不覆盖。
2. 刷新控制端、显示端并断线重连，确认设置按各自 `displayId` 恢复。
3. 关闭时确认连接状态、语音/摄像头状态、音频监视器和会话倒计时隐藏。
4. 关闭时确认时间、文件名、语音正文和模型任务进度仍显示；重新打开后状态提示恢复。
5. 旧配置缺少字段时默认显示；控制端竖屏下导航仍位于左侧。

## 兼容性测试

- 新服务端与旧显示端：旧端忽略未知配置消息，继续显示状态提示。
- 新显示端与旧配置：默认开启状态提示。
- 多控制端：一端修改后，其他控制端收到服务端权威值。

## 性能测试

- 配置只在用户操作和 WebSocket 初始化/广播时传输，不增加轮询或渲染循环。

## 风险评估

- 隐藏的语音状态区参与旋转布局测量；使用 `visibility` 保留节点尺寸，避免影响布局计算。
- 设备标识使用 `displayId`，避免相同 IP 的多个显示端共享配置。
- Offline 服务包状态只标记待构建，不代表已构建或发布。

## 预计工时

- 约 1–2 小时，含实现、文档同步与静态检查；现场多设备/重连验收另计。
