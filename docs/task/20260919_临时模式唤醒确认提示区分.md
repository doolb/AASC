# 任务：临时模式唤醒确认提示区分

## 任务描述

调整临时模式首次语音响应：纯助手名唤醒时替换现有长进入提示，助手名带内容时增加一次短确认；后续临时消息和一次性群聊不重复使用临时模式确认。

## Design 需求

- 只说已配置助手名：进入临时模式，不写入聊天，从唤醒确认候选池随机播报一条。
- 助手名加内容：进入临时模式，从内容确认候选池随机播报一条，再发送原始内容。
- 保留临时会话超时、历史上下文、TTS 暂停计时和一次性群聊现有语义。

## Spec 设计

```text
waitingWake + 纯助手名:
    状态迁移到 activeGroup/windowType=temporary
    temporaryWakePrompts = ['嗯，我在', '哎，我在', '我在呢', '在呢', '听着呢']
    sendConversationPrompt(displayId, randomChoice(temporaryWakePrompts))
    不提交唤醒文本到聊天

waitingWake + 助手名及内容 + addressedGroupMode=temporary:
    状态迁移到 activeGroup/windowType=temporary
    temporaryContentAckPrompts = ['好的', '收到', '明白', '好嘞', '没问题', '交给我吧']
    sendConversationPrompt(displayId, randomChoice(temporaryContentAckPrompts))
    继续原有 processVoiceCommand/chat 处理原始文本

active temporary + 后续内容:
    不再发送首次确认

addressedGroupMode=oneShot:
    不启用临时模式确认文案
```

## 受影响功能模块和代码

- `src/apps/server/boot/server-app.js`：替换纯助手名临时唤醒提示，并为首次带内容临时唤醒增加短确认。
- `tests/display-voice-listening.test.js`：增加服务端提示分支契约检查。
- `tests/display-voice-conversation.test.js`：保持状态机输入分支和临时事件回归。
- `docs/design/display-voice-conversation.md`、`docs/spec/display-voice-conversation.md`：同步行为与伪代码。

## 自测用例

1. 等待唤醒时说“小爱”：收到唤醒确认候选池中的一条，不产生聊天消息。
2. 等待唤醒时说“小爱，介绍一下今天安排”：先收到内容确认候选池中的一条，随后正常进入临时聊天。
3. 临时模式内再次说普通内容：只处理聊天，不再次播报临时确认。
4. 一次性群聊配置下说“助手名+内容”：不使用临时模式确认文案。
5. 私聊唤醒、持续群聊进入/退出和临时模式超时行为不变。

## 兼容性测试

- 运行临时语音会话状态机测试。
- 运行显示端语音监听契约测试。
- 运行语音会话、天气、历史和 Chat2API 定向回归。

## 性能测试

- 短确认复用已有 TTS 路由，不新增 WebSocket 或持久化请求。
- 确认播报只在临时模式首次唤醒触发，不增加后续消息的 TTS 次数。

## 风险评估

- 低风险：改动只影响临时模式首次提示文本和一次新增确认播报；普通对话路由不变。
- 需现场确认：短确认和模型回答的连续 TTS 播放顺序，以及不同 TTS 设备配置下的播放目标。
