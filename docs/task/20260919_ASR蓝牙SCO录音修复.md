# ASR 测试 APK 蓝牙 SCO 录音修复

## 任务描述

修复 ASR 测试 APK 已识别蓝牙麦克风但录音结果为 0 秒的问题。目标设备为 Android 9/API 28，输入类型为 `AUDIO_DEVICE_IN_BLUETOOTH_SCO_HEADSET`。

## design 需求

- 蓝牙 SCO 录音开始前建立并等待 SCO 音频链路。
- 按 Android SCO 输入约束使用 8 kHz、单声道、PCM16 采集，再重采样成 ASR 固定的 16 kHz Float32 PCM。
- 停止录音或启动失败时释放 SCO，并恢复录音前的 AudioManager 模式。
- 检查 `AudioRecord` 的实际录音状态和负数读取错误，不再把启动失败静默成 0 秒。
- 普通内置/USB/有线输入保持 16 kHz 采集路径不变。

## spec 设计

- 新增 `BluetoothScoController` 管理 SCO 状态广播、超时、启动和释放。
- `AudioRecorder` 根据 `AudioDeviceInfo.type` 选择采样率，并将 SCO 采集结果重采样到 `SAMPLE_RATE=16000`。
- `AudioRecorder` 暴露失败原因，`MainActivity` 显示明确的录音启动失败状态。

## 自测用例

1. 选择蓝牙 SCO 麦克风后，SCO 状态连接成功再创建 `AudioRecord`。
2. 蓝牙录音采集 8 kHz，停止后返回 16 kHz、非空 Float32 PCM。
3. SCO 超时或 `AudioRecord` 启动失败时显示原因，不生成 0 秒假成功结果。
4. 停止蓝牙录音后恢复 AudioManager 原模式，并释放 SCO 请求。
5. 内置麦克风录音仍使用 16 kHz，已有录音和 ASR 流程不回归。

## 兼容性测试

- Android 9/API 28：重点验证 `startBluetoothSco`、状态广播和 8 kHz 输入。
- Android 12/API 31 以上：保持现有设备选择和蓝牙权限流程；旧版 SCO API 可用时继续兼容。
- 无蓝牙或非 SCO 输入：不启动 SCO，不改变原有 16 kHz 录音。

## 性能测试

- SCO 建链只发生在录音开始阶段，最长等待 8 秒，录音循环不增加阻塞等待。
- 重采样在线性数组上执行一次，不进入 ASR 推理线程。

## 风险评估

- 蓝牙 SCO 建链是异步的，设备或系统占用 SCO 时可能超时，需要明确提示用户重连或释放其他通话/录音应用。
- SCO 输入带宽和采样率受系统限制，8 kHz 重采样到 16 kHz 可能比原生 16 kHz 有一定识别质量损失。
- Android 厂商音频策略差异可能导致 `AudioRecord` 仍无法启动，但错误会被显式显示并记录。

## 2026-09-20 蓝牙无数据补充修复

- 现场反馈：蓝牙设备可枚举，但录音没有 PCM 数据；失败后选择器已回退为系统默认，日志中的 `selectedDeviceId` 变为内置麦克风 ID 10。
- 根因：测试 APK 的 SCO 控制器没有在连接成功后设置 `AudioManager.isBluetoothScoOn=true`，与正式显示端控制器行为不一致。
- 已修复：记录录音前 `isBluetoothScoOn`，连接成功后设置 SCO 开关，处理 `SCO_AUDIO_STATE_ERROR`，停止时恢复由控制器修改的开关和原始 AudioManager 模式。
- 待验证：重新安装 Debug APK 后选择蓝牙设备录音，确认页面显示实际路由为蓝牙 ID 922 且 PCM 峰值大于零。
