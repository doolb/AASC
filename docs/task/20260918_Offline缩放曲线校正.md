# Offline 缩放曲线校正

## 任务描述

根据 Display 2 与手机实测结果，修正 Offline APK WebView 初始缩放曲线。当前乘法公式在 `1920@160dpi` 产生 75%，在 `2309@480dpi` 产生约 271%，与现场可读性目标不符；改为分辨率比例和 DPI 比例的等权混合。

## design 需求

- 继续以 `1280px@320dpi` 为 100% 基准。
- 缩放百分比使用 `round((((长边 / 1280) + (densityDpi / 320)) / 2) × 100)`。
- 目标结果：`1920@160dpi -> 100%`、`2309@480dpi -> 165%`、`1280@320dpi -> 100%`、`720×1480@280dpi -> 102%`。
- 普通 APK、无效参数回退、Display metrics 读取方式、诊断浮层格式和输入坐标协议保持不变。

## spec 设计

```text
WebViewScalePolicy.initialScalePercent(offlineMode, widthPixels, heightPixels, densityDpi):
    如果 offlineMode == false：返回 100
    如果 widthPixels <= 0 或 heightPixels <= 0 或 densityDpi <= 0：返回 100
    longEdgePixels = max(widthPixels, heightPixels)
    resolutionRatio = longEdgePixels / 1280
    densityRatio = densityDpi / 320
    blendedRatio = (resolutionRatio + densityRatio) / 2
    返回 max(1, round(blendedRatio × 100))
```

## 受影响的功能模块和代码

- `WebViewScalePolicy.kt`：将长边与 DPI 的乘法组合改为等权平均。
- `WebViewScalePolicyTest.kt`：锁定 Display 2、手机和基准设备的目标百分比。
- Offline APK 设计/spec、热更新文档、任务清单和变更日志：同步新公式和验证结果。
- `release/apkbuild/allserver-min/app.json`、`tests/apk-build-profile.test.js`：生成新 min APK 时升至 v10。

## 自测用例

- Android JVM 单测覆盖 1280×720@320、1920×1080@160、2309×1080@480、720×1480@280、1920×1080@320、1280×720@160。
- 普通 APK 和无效分辨率/DPI 仍返回 100%。
- Offline 静态回归、APK 构建、ZIP/签名校验通过。
- 真机 Display 2 诊断浮层显示新计算值，服务健康接口和固定显示端 ID 保持正常。

## 兼容性测试

- Android 9/API 28、SM-N9500、Display 2 Desktop 虚拟屏。
- 现有 v9 覆盖安装路径和既有服务数据、任务索引、模型缓存保持可用。

## 性能测试

- 公式只在 WebView 创建和诊断浮层刷新时执行，计算量与当前实现相同。

## 风险评估

- 目标手机的最终视觉大小仍受 WebView viewport、系统字体和页面响应式布局影响；诊断浮层提供实际输入参数和计算值。
- Display 2 报告 `touch NONE`，无法通过 adb 完成真实触控回归；服务和 UI 自动化检查继续执行。
