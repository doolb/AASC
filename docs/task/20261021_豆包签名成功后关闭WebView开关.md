# 豆包签名成功后关闭WebView开关

## 需求、设计与确认

用户提出增加签名成功后关闭开关。拟Android Node直连成功prepare后销毁后台页面，保留Cookie与会话签名缓存，重签时重建；兼容fetch和外部登录页保持运行。用户已确认方案，默认关闭以保持现状。详细design/spec已先行记录草案，实现与回归已完成，详见完成记录。

## 受影响模块与数据流

Chat2API控制面板chat2api.js、控制端websocket.js、server-app.js及新增配置辅助模块；runtime/provider/adapter/Android bridge传递只读配置；DoubaoWebViewService.kt负责成功关闭及再建。沿用WS→config.set→权威广播→初始化补发，不增加HTTP配置接口。

## 自测、兼容、性能与风险

覆盖规范化/失败回滚/多控制端回显/重连默认，prepare与fetch隔离，旧APK能力确认，原生成功与失败关闭边界及保留Cookie重建；Responses签名缓存与一次补发保持，npm run check:chat2api及Kotlin定向测试。销毁需主线程并等待完成后释放账号锁，避免关闭后续请求；关闭可减少页面资源占用，但重签需重新加载官网，不能承诺释放整个进程内存。预计实现及回归1至2小时；不主动制造真实账号风控。

## 发布与待确认

会影响服务包及min APK；仅方案记录时不改产物状态。用户确认后先落实默认值与spec，再实现、测试、更新文档并标记待构建。已确认实施，先更新spec，再实现及验证。
