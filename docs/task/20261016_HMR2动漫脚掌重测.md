# HMR2.0b 动漫脚掌重测

- 日期：2026-10-16
- 状态：已完成试验，识别质量未改善
- 预计工时：1–2 小时

## 任务描述与设计需求

用户指出动漫图脚掌方向偏差。先区分报告绘制错误与模型原始输出错误；保持原版三图与正式MediaPipe全身IK不变，只在独立HMR2.0b本机报告比较同权重的裁剪框及水平镜像输入。BODY25左右语义必须可核对，候选不得覆盖原始JSON。详见[设计](../design/mmd-human-interface.md)。

## Spec 与受影响代码

按[实现伪代码](../spec/mmd-human-interface.md)执行：原始框、扩框、左移、右移和镜像使用同一官方checkpoint、ViTDet、SMPL与相机投影；镜像候选把原图X及3D X翻回，交换BODY25左右索引。改动`tmp/mmd-pose/depth-eval/hmr2-sam3d/run-hmr2.py`、`report.html`、`report.mjs`、`check-report.cjs`及关联设计、实现、使用、自测、待办和变更记录。结果JSON、权重和用户原图留在本机忽略目录。

## 自测、兼容性与性能

- 真实CPU运行四候选，逐项检查25点有限、相机投影回原图、BODY25镜像语义和原始结果不覆盖。
- Edge检查三图与四候选切换、原图叠点、立体骨架、WebGL回退、本机GET、390px布局和无脚本错误。
- 四候选推理分别约1941、957、869、793毫秒；同一进程加载一次模型，不据此声称手机速度。
- 正式MediaPipe、VAM及Offline发布状态不变；没有APK构建。

## 结果与风险

原版动漫左脚踝约`(291,345)`，大/小趾约`(268,394)`/`(289,388)`，未落在右侧可见鞋面。四候选两脚趾的Y仍为`389–404`，镜像候选甚至降至约`404/397`；没有一项达到脚掌改善条件。镜像XYZ经保存相机重投影误差小于`0.001px`，排除了报告坐标变换错误。报告保留原版默认，实验候选只用于排查。

当前模型在遮挡和动漫造型上仍可能给出错误脚掌朝向；手工调整可作为后续交互，但不得标作模型识别成功。正式IK不采用这些候选。
