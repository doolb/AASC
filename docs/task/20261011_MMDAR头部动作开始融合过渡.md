# MMD-AR 头部动作开始融合过渡

- 日期：2026-10-11。

- 用户需求：“也优化下开始播放动作时，能不能跟随的也融合过渡”。本次承接上一轮600ms头部恢复，扩展到开始播放与新头部动作接管。

## 需求分析

使用analyze-requirement-level默认enterprise模式。需求方向明确：相机/点击跟随到头部动作的开始阶段平滑融合。主等级L5（跟随→动作开始→播放→恢复流程），次等级L4（显示起点、身份、时间与四元数插值），建议下放至L4，能力等级L4。证据：用户要求优化开始播放动作；用户要求跟随也融合过渡；现有rotateHead新身份只清除旧恢复，而mixer默认120ms淡入且未传进入时长。

两条L5强证据权重6，L4中证据权重2，邻层一致性0.9，置信度0.675。评分：清晰度23/25、证据18/20、完备度17/20、风险17/20、L4落地13/15，共88/100。结论：方向可开发，用户以“暂时都使用配置的600ms”确认进入与恢复统一时长。主要风险：长过渡吞掉短动作；恢复中新动作接管跳变；循环/多层频繁重置进入；原基础姿态被显示插值污染。

## design和spec

对应 `docs/design/mmd-human-interface.md` 与 `docs/spec/mmd-human-interface.md` 的统一融合章节。已有声明为显示四元数、旋转通道身份/权重、跟随目标和600ms恢复。新增HeadEntry固定显示起点与本次进入时间；新身份从当前显示姿态开始，融合到实时动作加剩余跟随贡献；短动作也使用600ms，释放早于进入完成时从当前显示姿态转恢复。释放时切到既有600ms恢复，目标继续更新，进入与恢复互斥。

## 自测、兼容性与性能

- 普通相机/临时点击跟随开始动作：首帧等于上帧显示姿态，随后平滑融合；动作采样时间正常推进。
- 恢复中接管、同owner替换、不同owner新增、循环下一轮与层窗口开始：不中途先返回相机，显示起点承接当前姿态。
- 低强度动作保留剩余跟随，零强度/遮罩排除/非头部轨道不启动进入。
- 短动作保持600ms进入，进入中自然结束或停止从当前姿态转为600ms恢复、多头部层冲突维持优先级。

- 已有 `node --test tests/mmd-ar-human-head-recovery.test.js tests/mmd-ar-human-gaze.test.js` 16/16通过。另使用真实Three骨骼+HumanMixer+HumanGaze进行只读复现：恢复100ms后新动作零delta接管首帧变化67.63°；现有测试允许这一跳变，后续需要更新验收。
