# 五子棋当前游戏提示与目录回执核验

## 任务描述

在 AASC 聊天的现有 `System:` 正文中增加 `NowGame:游戏名`，让模型知道当前显示端是否有进行中的棋局。同时核对模型输出目录标签并附自然语言时，GM 列表回执是否进入下一次模型调用。

## 需求等级与风险

- 主等级 L6（提示词输入输出契约），次等级 L5（游戏回合流程），结论可开发；证据为权威棋局状态、`NowGame` 文本格式、目录 GM 续接三项具体约束。直接开发风险低，主要风险是把已结束棋局误报为当前游戏，或误将独立 Chat2API 请求当成 AASC 游戏回合。
- 下放到 L4：已有声明为棋局快照、游戏桥接层、raw 提示组装；新增定义为 `NowGame` 一行状态；操作流程为“读取目标显示端快照 → 进行中则填五子棋，否则填无 → 放在目录提示后 → 继续用原桥接层处理 GM”。
- 评审评分：层级清晰度 24/25、证据充分度 19/20、实现完备度 19/20、风险暴露度 18/20、L4 可落地性 15/15，总计 95/100；置信度 0.90。用户已明确选择只覆盖 AASC 聊天，并确认代码修改方案。

## Design 需求与 Spec 设计

- `docs/design/game-gomoku.md`：状态由当前显示端服务端权威棋局给出；进行中显示 `NowGame:五子棋`，无棋局或已结束显示 `NowGame:无`。
- `docs/spec/game-gomoku.md`：该行位于 raw `System:` 正文的目录提示后、原角色设定前；每次 AASC 聊天入口重新计算。同一轮中 GM 回执继续按现有协议续送，不将游戏逻辑接入独立 Chat2API 直连接口。
- Chat2API 会话记录表明 09:56 的模型原文为 `<Game:目录,AI,列表>` 并带自然语言，尖括号与英文逗号均存在；该独立会话只有请求和回复两条记录，没有经过 AASC 游戏桥接层，因此不修改标签解析器。

## 受影响模块与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：在读取初始权威快照时生成当前游戏行，接入现有系统提示拼接。
- `tests/game-gomoku.test.js`：检查无棋局、进行中棋局和目录标签后自然语言的 GM 续接。
- 五子棋 design/spec/task/todo/changelog：记录实际范围与剩余现场验收。

## 自测、兼容与性能

- 定向测试：`node --test tests/game-gomoku.test.js`，20/20 通过；目录标签后附叙述时第二次调用输入包含 GM 列表，第三次包含 GM 规则；无棋局和进行中棋局分别产生 `NowGame:无` / `NowGame:五子棋`。
- 保留现有单条 raw user 消息格式、GM 回执与 WebSocket 协议；不新增 Chat2API 工具行为，也不读取浏览器显示文本来推断模型原文。
- 每轮复用已有一次棋局快照读取，不增加额外网络请求；待服务代码包更新后在真实 AASC 聊天中验证提示与标签调用。预计工时约 30 分钟。
