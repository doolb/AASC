# 修复重复报时监听提前恢复

## 任务描述

修复整点报时默认重复播放三次时，第一次音频完成就向其他录音显示端发送 TTS 结束状态，导致录音在第二、第三次报时之间提前恢复的问题。

## design 需求

- 三次重复报时作为一个房间级 TTS 播放组。
- 播放组最后一次完成前，未启用声纹识别的显示端保持暂停监听。
- 普通单次 TTS 和多条独立 TTS 的现有完成语义保持不变。
- 兼容 Web 显示端逐条完成回报和 Node 子显示端一次性回报完成数量。

## spec 设计

- 报时消息携带 `voiceTtsPlaybackRepeatCount`。
- 服务端按播放目标和播放 ID保存 `repeatCount`、`completedCount`，只在完成数达到总数时广播 `finished`。
- Node 子显示端按播放 ID累计本地队列条数，并在队列结束时回报 `completedCount`。

## 自测用例

1. 三次报时只广播一次开始状态，第三次完成前不广播结束状态。
2. Web 端逐条回报三次完成后，录音端才恢复。
3. Node 端一次回报 `completedCount=3` 后，录音端恢复。
4. 普通单次 TTS 仍按一次完成回报结束。

## 兼容性与风险

- 未携带重复总数的旧 TTS 消息按单次播放处理。
- 旧显示端不回报时仍由原有 120 秒超时机制结束播放组。
- 停止或断开连接仍立即按异常结束组状态，不让录音永久暂停。
