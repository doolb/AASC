# 2026-09-20 显示端聊天操作布局与 MMD 控制

## 任务描述

调整显示端聊天输入区的操作按钮布局，修复聊天打开时语音播报文字仍可见的问题，并在控制端增加当前选中显示端的 MMD 显示/隐藏按钮。

## Design 需求

- 聊天输入框位于左侧，发送和清空按钮在右侧纵向排列。
- 聊天面板打开时完全隐藏语音播报文字，关闭后恢复当前文字；TTS 音频不受影响。
- 控制端增加“显示 MMD”“隐藏 MMD”，通过现有 WebSocket 控制当前选中的显示端。
- 不新增 iframe、HTTP 配置接口或独立 WebSocket；不改变媒体层、聊天历史和模型生命周期。

关联设计：`docs/design/display-chat-mmd.md`。

## Spec 设计

```text
聊天打开 -> updateVoiceTextVisibility(true) -> 隐藏播报文字但保留 TTS 音频
聊天关闭 -> updateVoiceTextVisibility(false) -> 恢复当前播报文字
控制端点击 MMD 按钮 -> control(mmdVisibility, bool) -> 当前显示端
显示端收到 control -> DisplayStage.setMmdVisible(bool) -> 更新 Canvas 层和交互状态
```

关联规格：`docs/spec/display-chat-mmd.md`。

## 自测用例

1. 显示端打开聊天，正在播报或新到 TTS 文字时，播报文字不可见但音频继续播放。
2. 关闭聊天后，当前仍有效的播报文字恢复显示。
3. 手机窄屏下输入框、发送和清空均不重叠；按钮在输入框右侧上下排列。
4. 控制端选中显示端后点击“隐藏 MMD”，对应显示端 Canvas 隐藏且聊天仍可用。
5. 点击“显示 MMD”后角色恢复，模型和动作上下文不丢失。
6. 未选显示端时点击按钮显示明确提示，不发送无目标消息。

## 兼容性测试

- 浏览器显示端与 Android WebView 显示端。
- 横屏、竖屏、键盘弹出和高 DPI 屏幕。
- 无模型、模型加载中、模型加载失败和已加载模型状态。
- 单显示端选中模式；不改变现有多显示端媒体发送逻辑。

## 性能测试

- 聊天打开/关闭不创建或销毁 MMD 运行时。
- 隐藏 MMD 使用既有可见性和渲染暂停路径，不新增轮询。
- 输入布局只使用 CSS，不增加布局定时器。

## 风险评估

- 中：显示端现有内联 TTS 和舞台模块都可能更新播报文字，需要保证聊天状态类与新文字到达时序一致。
- 低：MMD 控制复用既有 `control` 消息；未知 action 仍需保持原有转发行为。
- 低：按钮布局只影响显示端聊天输入区域，不影响控制端旧聊天界面。
