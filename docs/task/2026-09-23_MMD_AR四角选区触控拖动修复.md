# 2026-09-23 MMD AR 四角选区触控拖动修复

## 任务描述

修复独立 MMD AR 测试 APK 的拍照校准界面中四个白色选区角点无法可靠拖动的问题。校准弹窗随显示舞台旋转，视口触点须逆变换到画布逻辑坐标后再命中角点。

## Design 需求

- 角点触控命中和移动先应用 DisplayStage 当前角度的逆旋转，再按校准 canvas 逻辑宽高规范化到 0–1。
- 角点按下时捕获当前 pointerId；仅相同指针可更新被选中的角点。
- pointerup、pointercancel、lostpointercapture 均清空拖动状态，不关闭校准弹窗。
- 用文档级 move/up/cancel 接收捕获中的指针；重绘时只在图片尺寸变化时重设 canvas intrinsic 尺寸。
- 保持原有四边形面积/凸性校验和保存按钮启用规则；触控期间禁用浏览器默认滚动/缩放手势。
- 不增加服务器、生产依赖或 Offline APK 行为。

## Spec 设计

- 更新 `docs/spec/mmd-image-ar.md` 校准伪代码，定义舞台逆旋转坐标、指针捕获/结束状态和验证用例。

## 受影响的功能模块与代码

- `src/apps/web-mediacenter/ui/public/js/display-mmd-ar.js`：校准 canvas 坐标映射及拖动指针生命周期。
- `src/apps/web-mediacenter/ui/public/css/display-mmd.css`：校准 canvas 触控手势约束与可拖动命中体验。
- `3rd/mmd-ar-test/build.js`：构建时复用共享 AR JS/CSS；如需测试诊断只保留于独立 APK harness。
- `tests/display-mmd-ar-calibration.test.js`：覆盖四方向坐标反变换、四角命中、指针终止状态和 canvas 尺寸稳定。
- `docs/design/mmd-image-ar.md`、`docs/spec/mmd-image-ar.md`、`docs/self-test.md`、`docs/todo.md`、`changelog.md`。

## 自测用例

1. 在 0°、90°、180°、270° 舞台旋转值下，从四个白点分别拖动，只改变屏幕上被拖动的对应角点。
2. 拖动超出 canvas 边界后继续跟随活动指针；抬起后可以再次拖动。
3. pointercancel 或 lostpointercapture 后不残留拖动状态，校准弹窗仍保持打开。
4. 有效选区允许保存；退化、自交或面积不足选区继续禁用保存。
5. `npm run build:apk:mmd-ar-test` 构建成功并检查独立 APK 内容；在 SM-N9500 / Android 9 上安装并检查实际角点拖动。

## 兼容性测试

- 覆盖桌面鼠标指针与 Android 9 WebView 触控指针；坐标计算不依赖设备分辨率或像素密度。
- 测试 harness 和生产显示端共用同一 AR JS/CSS；不影响生产相机/目标数据、普通 MMD 触控和显示舞台其他旋转坐标。

## 性能测试

- 仅在角点拖动时重绘校准 canvas；不增加摄像头帧识别工作或常驻渲染循环。
- 检查拖动期间选区视觉跟手，目标 Android 上无明显迟滞。

## 风险评估

- 校准弹窗与舞台都参与旋转；映射必须使用舞台逆变换，并按四方向测试，不能只用旋转后矩形的轴对齐比例。
- pointer capture 丢失时未复位可能使下一次拖动失效；显式覆盖所有结束事件并做后续拖动回归。
- Android WebView 的相机预览涉及真实环境采集；本任务仅在获准的测试页验证触控，不上传或持久化测试照片。
