# 控制端 Agent 在线状态与关闭错误修复

## 任务描述

修复控制端聊天发送消息后 Agent 已启动但在线状态不能及时刷新，以及系统设置关闭所有 Agent 按钮在服务端返回非成功 HTTP 响应时直接报错的问题；同时明确 Agent 权限审批和聊天 Markdown 的当前行为。

## design 需求

- Agent 确认启动后立即广播角色列表，控制端显示在线。
- stop-all 后查询状态不得重新创建 Agent bridge。
- 控制端正确处理 HTTP 非 2xx、非 JSON 和业务失败响应。
- Claude/Codex 的自动审批和高权限策略写入设计说明；Markdown 暂不改动。

## spec 设计

- `AiRolesService.chat()` 在 `ensureStarted()` 成功后调用 `onStatus`。
- 服务端把 `onStatus` 映射为 `roleList` 广播。
- `AiRolesService.list()` 使用已有 bridge 或 PID 检测，不调用懒创建路径。
- `Settings.stopAllAgents()` 先检查 `response.ok`，再显示返回消息。

## 自测用例

- 首次 Agent 聊天在 Agent bridge 返回已启动后收到在线状态回调。
- Agent 全部停止后读取列表显示离线，且 bridge 创建次数不增加。
- 控制端代码包含 HTTP 状态检查和非 JSON 错误兜底。
- 运行 AI 角色相关 Node 测试、语法检查和 `git diff --check`。

## 兼容性测试

- Claude 和 Codex bridge 均支持状态回调。
- 旧控制端仍可使用 `mode=role` 发送 Agent 消息。
- 旧服务端返回 JSON 业务错误时继续显示 `message`。

## 性能测试

- 在线状态只在启动成功或状态失败时广播，不增加轮询。
- 角色列表查询不再创建 bridge，避免关闭 Agent 后产生额外进程对象。

## 风险评估

- Claude 使用 `bypassPermissions`，Codex 使用 `approvalPolicy=never` 和 `dangerFullAccess`；这是现有产品配置，需由用户承担工作区操作风险。
- Markdown 仍按纯文本显示，不引入解析器和潜在 XSS 面。
