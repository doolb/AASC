# 豆包网页release默认任务与Android查看入口

## 任务及最终授权范围

用户将“数据修复包默认运行”缩小为“先只改本地release配置，手机手动开任务”，并明确“WebView查看入口也要”。本次仅增加release首装任务种子和实际运行页面查看；不新增repair.js、自动启动配置、服务启动代码或数据版本，不在当前手机启动任务，不构建发布修复包/APK。

## 需求分析、design与spec

需求等级L6（运行页面入口与生命周期），次级L5（首装恢复及关闭返回后台）；建议下放L4，直接开发风险中，置信度0.90。证据为release配置限定、现有手机手动开任务、明确需要WebView查看入口三项强证据。评分24/25、20/20、19/20、19/20、15/15，总97/100，结论可开发。

设计见 `docs/design/chat2api-doubao-web.md`，伪代码先更新在 `docs/spec/chat2api-doubao-web.md`。已有声明为doubao.web任务、restoreAutoStartServices、原生隔离进程、页面缓存；新增定义为首装running实例与查看者身份；流程为恢复任务→首次请求懒加载→订阅并展示现有页→关闭卸载视图并继续后台运行。无需自动调用其他技能。

## 实施与受影响模块

- `release/task/doubao.web/results/index.json`：一个builtin/server/service/running实例d0baba01，默认9091/9224/vivaldi和空账号；不添加无人读取的config自动启动字段。
- `doubao-web.js`：任务widget新增查看按钮，运行状态给出android/desktop平台；原请求传输不变。
- `chat2api.js`：检查任务平台、原生桥版本、本机WebSocket；失败给出可见提示，避免把本机页面当成远端任务。
- `Chat2ApiNativeBridge.kt`、`MainActivity.kt`：仅Offline本机来源允许打开运行页，不读取或传递凭据。
- 新增 `DoubaoWebViewActivity.kt` 与Manifest声明：同chat2api_login进程、非导出、单实例页面；初始化相同数据目录，支持旋转和输入法调整。
- `DoubaoWebViewPageCache.kt`、`DoubaoWebViewService.kt`：进程内同一缓存按查看者身份订阅；前台附着时借用Activity上下文，关闭回后台移除上下文；先卸载视图再destroy，过期查看者不能清除新窗口。服务销毁后迟到回调不能重建页面。
- npm新增 `test:doubao-runtime-view`；同步usage/design/spec/self-test/todo/changelog与发布状态。

## 自测、兼容与性能

正式任务widget在真实Chromium中点击，覆盖Android成功、桌面、旧APK、远端服务、原生失败；用stageNodeMinSeeds暂存真实种子，再由TaskManager恢复唯一实例并停止，不启动真实浏览器、不发消息。JVM验证同页复用、查看关闭再开、换查看者/过期清理、先卸载后销毁、重建推送和查看异常隔离，以及本机来源约束。完整Chat2API回归检查既有直连、网页、登录和流式协议。

纯展示不增加定时器、截图、网络请求、预加载或账号切换；页面通知只在生命周期变化时运行。Android真机视觉、拖动验证码、软键盘、旋转与实际生成期间开关窗口需配套APK/服务部署后验收，不用浏览器桥stub冒充真机通过。

## 风险评估与预计工时

主要风险为双WebView、Activity泄漏和旧窗口卸载新页，通过共用缓存、上下文归还与查看者身份解决。静态页面引用仅在同一隔离进程共享，Service回收负责销毁；没有页面时只提示，不偷偷启动无授权Service或创建新登录页。首装种子不包含Cookie、账号或聊天内容。预计45～90分钟。数据修复与后续服务启动开关暂缓，无当前未明确需求。
