# IMU 手持死区与 50Hz 链路

日期：2026-10-17。状态：已实施并完成专项回归与 APK 构建；真机实际频率待验收。

## 任务描述与需求分析

用户要求角速度和加速度两个死区都开放上限，使手持高噪声也可校准；手机原生六轴采样目标为50次/秒，APK上传批次和电脑观察端估计帧各为50条/秒。后续Node测试服务会在Android本地运行，本轮保持现有架构兼容。

按`analyze-requirement-level`默认enterprise模式：结论为可开发；主等级L6（两个死区的输入、校准输出与显示契约），次等级L4（采样/窗口/定时步骤）、L7（房间消息频率）；直接开发风险中。层级清晰度22/25、证据充分度18/20、实现完备度15/20、风险暴露度18/20、L4可落地性14/15，总87/100。证据分别为“两个死区都开放上限”“手机拿在手上时加速度噪声会很高”“手机采样50次/秒”“服务器消息两者都50Hz”以及未来Android本地运行。下放判定为必须下放到L4：把无上限数值验证、3秒窗口、20ms原生采样请求、20ms两端发送调度和每连接平均50消息/秒限流分成可检查步骤，详见`docs/spec/imu-six-axis-test.md`末节。

## Design 需求与 Spec 设计

Design：`docs/design/imu-six-axis-test.md`的“手持死区无上限与50Hz链路”。校准不可只去掉最终1°/s和0.5m/s²上限，因为现有单帧幅值和窗口方差检查也会使高噪声窗口反复重采。需让用户看到真实阈值并能手调，同时提示阈值过大时慢动作可能被忽略。

Spec：先保存连续3秒、至少60点的有效样本；类型变化和断流重采；用平均力方向对齐候选姿态，再计算两个未截断死区；只应用非负有限值。Android请求两路20ms硬件周期，APK和电脑观察页分别按20ms发布，服务端以每连接平均50条/秒且容许短时抖动的预算限制流量。实际硬件回调率并非Android保证值，按源时间核对。

## 自测、兼容性、性能与风险

自测用例：高于旧上限的稳定噪声窗口仍完成校准，数值输入显示完整结果；无效、负值和空输入不污染估计器；断流/类型变化重采；APK批次与电脑轨迹各自接近50消息/秒，短时定时抖动不被误拒；旧单样本协议仍可接入。兼容性：模拟器、浏览器手机、旧APK与固定房间保持可用；Android本地部署此轮不实施。性能：原始样本和轨迹环形缓冲、APK待发队列和单批大小保持有界；50Hz消息时观察缓存窗口缩短，需要在使用说明中说明。风险：过大死区会掩盖实际平移/旋转；仅凭六轴不能可靠地区分高噪声手持静置与移动；Android`samplingPeriodUs`为目标提示，实际采样率取决于硬件和系统调度。预计实施与专项验证约2至3小时，真机频率和动作效果需设备验收。
