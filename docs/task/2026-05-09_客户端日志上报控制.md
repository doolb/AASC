# 客户端日志上报控制

## 任务描述
控制端可以设置显示端和控制端是否把日志上报到服务器，并可分等级控制上报级别阈值。

## Design 需求
- 控制端UI增加日志上报控制区域，可分别设置显示端和控制端的日志上报策略
- 显示端按配置过滤本地日志，上报符合条件的条目到服务器
- 控制端通过覆盖 console.log/error 拦截浏览器日志，上报符合条件的条目到服务器
- 级别阈值：error > warn > info > debug，选择某级别即上报该级别及更高级别（更严重）

## Spec 设计
- `setLogReport` — 控制端→服务器，设置某类设备的日志上报策略
- `logReportConfig` — 服务器→显示端/控制端，转发日志上报配置
- `clientLog` — 显示端/控制端→服务器，按配置上报的日志条目
- `logReportConfigApplied` — 服务器→控制端，确认配置已应用

## 受影响的功能模块和代码
- `src/apps/server/boot/server-app.js` — 添加 logReportStore、setLogReport handler、clientLog handler、连接时发送配置
- `src/apps/voice-display-node/main.js` — 添加 logReportConfig 接收、按配置上报 clientLog
- `src/apps/web-mediacenter/ui/public/upload.html` — 日志面板添加日志上报设置UI
- `src/apps/web-mediacenter/ui/public/css/upload.css` — 日志上报UI样式
- `src/apps/web-mediacenter/ui/public/js/log-viewer.js` — 添加日志上报配置方法、console覆盖拦截
- `src/apps/web-mediacenter/ui/public/js/websocket.js` — 处理新消息类型

## 自测用例
1. 控制端勾选"显示端上报"并选择级别 → 显示端收到 logReportConfig
2. 显示端 log() 按级别阈值判断后发送 clientLog → 服务器收到并存入 logBuffer
3. 控制端勾选"控制端上报" → console.log/error 被覆盖，日志发送到服务器
4. 控制端取消勾选 → console 恢复原始行为，不再拦截
5. 控制端设置级别为"警告及以上" → info/debug 级别的日志不被上报

## 兼容性测试
- 旧控制端不发送 setLogReport → 显示端默认不上报，行为不变
- 旧显示端不处理 logReportConfig → 忽略消息，行为不变
- 服务端 logReportStore 默认 { enabled: false, level: 'error' }

## 风险评估
低。所有新增消息类型独立，不影响现有流程。默认不上报，无需担心日志泄露。
