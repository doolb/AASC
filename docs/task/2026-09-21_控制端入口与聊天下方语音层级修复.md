# 控制端入口与聊天下方语音层级修复

## 任务描述

修复 Android Offline 显示端控制端入口垂直居中的问题，恢复左上角 12dp 边缘吸附；同时让语音聊天倒计时和 TTS 播报文字处于聊天层下方，避免聊天打开期间异步 TTS 刷新导致文字重新显示在聊天上方。

## design 需求

- 控制端入口使用 `TOP | START`，左侧和顶部保持 12dp 边距。
- 显示端聊天层、MMD 层和交互按钮整体高于语音状态、TTS 文字和聊天倒计时。
- 保留倒计时数值、暂停/恢复、旋转定位和 TTS 音频播放行为。

## spec 设计

- `display-stage-layers` 使用高于独立语音 UI 的 stacking context。
- `controlToggleButton` 的 XML 和运行时 `FrameLayout.LayoutParams` 使用左上角定位和 12dp 边距。
- 通过静态契约测试验证聊天层级高于语音倒计时/TTS 层，避免异步文本刷新穿透聊天。

## 自测用例

1. 检查 XML 控制端入口为 `top|start` 且边距为 12dp。
2. 检查运行时展开/折叠状态都保持左上角定位。
3. 检查交互舞台层级高于 `voice-status-row` 和 `voiceTextDisplay`。
4. 检查聊天倒计时的现有更新函数、暂停值和旋转布局未被删除。
5. 运行 Android Offline 和显示端语音 UI 定向测试，执行 JavaScript/Kotlin 静态检查。

## 兼容性测试

- 普通浏览器显示端和 Android Offline WebView 使用同一显示端层级规则。
- MMD 位于聊天上方的配置仍由现有 `over-chat` 规则控制。
- render-display 继续高于媒体、低于显示端交互舞台。

## 性能测试

- 不新增定时器、WebSocket 消息或 DOM 高频更新。
- 仅变更 CSS stacking context 和 Android 布局参数。

## 风险评估

- 低风险：整体舞台层级上调可能覆盖独立语音 UI，但这是本次需求的目标；睡眠遮罩仍保留更高层级。
- 不改变服务端计时器和音频播放，不影响聊天路由。
