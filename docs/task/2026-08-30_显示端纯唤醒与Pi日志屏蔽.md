# 任务：显示端纯唤醒修复与 Pi 详细日志屏蔽

## 任务描述

修复“你好，小爱。”在显示端等待唤醒时被误发到普通聊天的问题，并屏蔽服务器默认输出的 Pi Agent 详细生命周期日志。

## Design 需求

- 等待唤醒时优先解析纯唤醒命令，再解析带助手名的普通聊天。
- 纯“你好+助手名”或“助手名+你好”只切换到群聊，不发送聊天消息。
- “小爱，今天天气怎么样”仍保留完整原文，唤醒后进入群聊。
- 默认不向服务器日志注入 Pi 生命周期明细，保留错误处理和显式测试 logger。

## Spec 设计

- `reduceConversationInput()` 在 `waitingWake` 分支先判断 `command.type === 'wake'`。
- `PiRuntimeManager` 保持可注入 logger，生产服务器不传入默认 logger。

## 自测用例

- “你好，小爱。”返回纯 `wake` 事件，不产生聊天输入。
- “小爱，请介绍一下今天的安排”进入群聊并保留原始文本。
- “小爱开始对话”仍进入私聊。
- 服务器默认 Pi Runtime 不输出详细分类日志。
- Pi Runtime 显式注入 logger 的测试仍可收集生命周期事件。

## 兼容性测试

- 内置免唤醒指令继续在 `waitingWake` 执行。
- 旧 Go/C#/Node 子显示端继续使用原有语音命令流程。
- Pi Agent 错误回报和 requestId 诊断测试保持有效。

## 性能测试

- 纯唤醒句在状态机内完成判断，不增加 ASR 或 LLM 请求。
- 关闭默认 Pi 详细日志后减少日志写入和控制台输出。

## 风险评估

- 包含助手名但没有明确“你好”的语句仍按带地址的群聊输入处理，保持原有角色名唤醒体验。
- 关闭默认详细日志会降低正常请求的生命周期可见性，需要通过显式 logger 或错误日志诊断异常。
