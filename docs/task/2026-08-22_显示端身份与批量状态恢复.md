# 显示端身份与批量状态恢复

## 任务描述

修复批量播放场景下显示端重连后设置/模式未恢复、Agent 使用 `127.0.0.1` 与真实显示端难以区分，以及控制端切换显示端后仍显示上一个显示端批量列表的问题。

## Design 需求

1. 使用持久化 `displayId` 作为显示端状态主键，IP 只用于兼容旧数据、日志和展示。
2. Agent 或测试显示端使用显式独立 ID；非显示 Agent 不进入 `/display` 显示端集合。
3. 批量播放重连同时恢复通用显示状态与批量播放断点。
4. 控制端切换显示端时隔离批量状态，并按新显示端状态恢复或隐藏面板。

## Spec 设计

```text
显示端连接(displayId, clientIP):
    saved = config.getDisplayStateById(displayId, clientIP)
    displayData.displayId = displayId
    displayData.ip = clientIP
    后续所有 updateDisplayState 使用 displayId

显示端重连:
    如果 saved 存在:
        先发送 restoreState(state=saved)
    如果 saved.currentPlaylist 存在:
        再发送 playlistStart(startData, resumeIndex, resumeTime, resumeState)

控制端选择 displayId:
    清除旧批量面板与旧临时预览缓存
    发送 getState(displayId)
    收到 displayState:
        有 currentPlaylist -> 绘制该显示端批量项
        无 currentPlaylist -> 隐藏全部批量面板
```

## 自测用例

- 同一服务器上 `agent-local/127.0.0.1` 与 `display-main/192.168.1.39` 的状态不互相覆盖。
- 显示端重连后 rotation、fit、crop、volume、sleep、autoTts 与批量索引/时间/暂停状态都恢复。
- 显示端 A 播放批量媒体，控制端切换到无批量状态的显示端 B，批量面板立即隐藏。
- 显示端 B 自己有批量播放时，切换到 B 后只显示 B 的当前项。
- 后台 A 的进度消息不会覆盖当前选中的 B。

## 兼容性测试

- 旧版按 IP 保存的单显示端状态可在首次按 `displayId` 连接时迁移。
- 浏览器显示端现有 localStorage `displayId` 不变。
- 临时批量不把 base64 写入持久化状态。
- Agent 媒体发送仍按在线 `displayId` 路由。

## 性能测试

- 批量进度仍使用原有节流持久化策略。
- 控制端切换仅清理 DOM 和内存引用，不增加媒体库请求。

## 风险评估

- 同一旧 IP 下存在多个未带身份的历史客户端时无法可靠迁移，后续连接必须使用显式不同 `displayId`。
- 发送 `restoreState` 后再发送 `playlistStart` 会短暂加载一次历史单媒体，需确认批量消息顺序最终由列表接管。
