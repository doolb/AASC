# MMD AR 网页模拟摄像头透视输入

- 日期：2026-09-26
- 范围：只修改 `3rd/mmd-ar-test/` 的 HTTPS 测试网页；正式显示端和旧独立测试 APK 不变。
- 需求：无摄像头电脑选择本地图片模拟相机拍到的画面；四角透视拖动；独立开关显示/隐藏操作点，隐藏时保留变形。

## Design 需求

“定位图”仍是 MindAR 识别目标；新图片仅为输入帧。初始选择真实相机；模拟输入仅在当前网页会话中使用，不上传也不进入 IndexedDB。切换输入源必须先停止定位。透视四角要求非自交且面积足够，避免退化矩阵。帧持续输出，停止后释放资源。模拟识别不替代真机验证。

## Spec 设计与伪代码

见 `docs/spec/mmd-ar-test-apk.md` 的“无实体摄像头的透视模拟输入”。数据流：文件 → 位图 → WebGL 纹理 → 四角逆透视画布 → `captureStream` → A-Frame MindAR；UI 开关只改变角点覆盖层可见性。

## 影响模块

- `3rd/mmd-ar-test/build.js`：网页专用控件、脚本、样式和资源复制。
- `3rd/mmd-ar-test/display-mmd-ar-sim-camera.js`：选图、透视、持续输出、资源管理。
- `3rd/mmd-ar-test/display-mmd-ar-aframe.js`：真实/模拟视频源切换和停止清理。
- `tests/mmd-ar-sim-camera.test.js`：无实体相机浏览器回归。

## 自测与兼容性

1. `npm run build:web:mmd-ar-test` 成功，网页模式有控件，APK/正式显示端无控件。
2. 本地图片可加载，四角拖动改变帧内容，开关隐藏/恢复后透视不变，重置恢复默认。
3. 无摄像头环境模拟模式可完成 MindAR 官方目标首锁且 `getUserMedia` 零调用；停止后流轨道关闭。
4. 原真实相机模拟回放、面板折叠和官方/自定义定位图回归通过。
5. 失败图片、无 WebGL、未选图片和失效四角给出提示，不继续启动。

## 性能与风险

- 960×540、20fps WebGL 输出，避免 CPU 每帧重算图片像素；四角变化仅更新矩阵。
- 浏览器软件 GPU、同页 MMD 渲染会影响帧率；合成图片过于平整或倾斜过大时 MindAR 可能无法首锁。
- 图片只在本地内存使用，页面刷新需重选；模拟成功不证明真机摄像头曝光/焦距条件下成功。
- 预计工时：约 4 小时。

## 完成与发布

- `npm run build:web:mmd-ar-test` 成功；浏览器定位/面板回归 9/9 通过。无实体相机模式上传图片、调整透视、关闭/恢复控制点、重置、MindAR 官方目标首锁与停止释放均验证通过。
- 发布时仅更新 `index.html`、`js/display-mmd-ar-sim-camera.js`、`js/display-mmd-ar-aframe.js`；新脚本先上线，首页最后原子替换。旧首页使用新版 A-Frame 适配脚本时仍可回退到真实相机。
