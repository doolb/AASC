# 普通 APK 保留监听端口与 8071 真机验证

## 任务与确认

用户要求当前ADB上的普通APK服务端口改为8071，避免与Offline冲突。已使用现有setServerPortConfig保存并验证8071。发现NodeServerConfig每次启动强写8081；用户回复“可以”，确认进一步修复、更新普通APK并验证冷启动。

## 需求分析与设计

应用analyze-requirement-level enterprise模式：主L5（启动后端口保持与验证），次L4（配置数值与URL串联），置信度0.675（L5强证据3+3，L4中证据2，一致性0.9）；评分24/25+20/20+18/20+19/20+15/15=96，可开发、风险低，建议下放到L4。证据为用户“改为8071”与确认“可以”，实际原生冷启动强写8081，健康URL同样硬编码8081。两项修复行动为保留有效端口和动态构造探测URL。无需其他后续技能，直接按已确认方案实施。

design：docs/design/server-port-config.md；spec：docs/spec/server-port-config.md。声明级数据流先于代码更新：原配置 → 合法端口/默认值 → 启动写入；当前配置+协议 → 健康URL；现场配置 → 覆盖安装 → 冷启动 → 网络/广播/配置核对。

## 影响代码与步骤

1. NodeServerConfig.kt保留普通APK已有合法端口；Offline仍8081；提供只读端口解析。
2. NodeServerService.kt健康探测使用实际配置端口，损坏配置返回不健康。
3. NodeServerConfigTest.kt、NodeServerServiceTest.kt验证端口保持、类型/范围边界、Offline兼容与健康URL。
4. npm run build:apk生成withserver普通APK v2/0.1.1，仅定向覆盖当前SM-N9500普通v1，不安装Offline。
5. 依项目Node min配套规则上传重建的aasc-display-withserver.apk到外网node-min目录，核对公网状态/大小/SHA；不写Offline服务清单。
6. 记录测试/设备/发布结果，更新文档/todo/changelog，源码与minApk状态提交到origion。
