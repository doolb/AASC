# 豆包直连失败刷新签名补发一次

## 需求、设计与明确性

用户明确要求失败消息尝试一次重新生成并发送，并确认文件及方案。沿用需求等级分析技能enterprise：主L5失败恢复流程、次L6错误/流/取消契约；建议下放L4白名单、次数与截止时间控制。证据为一次重签补发、已输出内容边界及共享时限三项确认，置信度0.68；评分24/25、19/20、19/20、18/20、15/15，共95，可开发，中风险。详细设计及先行伪代码见chat2api-doubao-web对应节。

## 范围与实现

修改chat2api-doubao-chat-adapter.js，在现有单次尝试外增加一次恢复，握手及流式next错误共用额度。保留原prepared和nativeState，仅更换签名及剩余超时；缓存刷新后成功继续复用。取消、校验、容量及已有内容不重发，失败不创建额外会话。签名不保证官网幂等，ACK后失败的补发可能重复受理，按用户确认执行。

## 自测与兼容

更新android-prepare及doubao-responses定向测试，覆盖HTTP/SSE/断连恢复、流式/非流式、二次失败、消息ID及总预算、已有正文/思考、取消、不适用路径。优先npm run check:chat2api，不用真实账号制造风控。桌面和网页兼容保持既有行为，缓存128项边界保持；最多增加一次签名与一次HTTP2调用，未增加并发和独立计时器。

## 文档、发布与风险

同步design/spec/self-test/usage/todo/changelog，servicePackage=true保持；不改原生，不需要新APK。官网可能已经受理失败请求；不扩大为无限重试。预计实现及回归1小时，代码及回归已完成。用户已选定修复方向，不再切换其它技能。
