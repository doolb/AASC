# 五子棋多行 GameMap 回执

## 任务描述与 Design 需求

用户反馈 AI 不易从单行棋盘还原连续坐标，提供 `GameMap:` 后逐行输出、各行末尾保留 `/` 的格式。用户已明确缩小范围：不加显示端行号和字母，只改多行。

## 需求评审

enterprise：可开发，主L6、次L4，置信度0.68，低风险。强证据为明确的 `GameMap:` 输出契约和仅修改多行的范围约束，中证据为已有按行编码实现。评分24/25、19/20、19/20、18/20、15/15，总95/100。必须下放L4：从同一权威棋盘生成首行元数据及多行地图，并同步规则与消费端摘要。

## Spec 设计

```text
已有声明 := 权威棋盘、GM快照与落子回执、游戏桥及提示摘要
新增定义 := GameMap: + 换行 + 棋盘行；行间 / 加换行，末行无 /
权威快照/成功落子 → 首行元数据 → GameMap文本块 → 游戏桥原样送回模型
终局 → 落子元数据和地图之后追加独立胜负状态
提示摘要 → 只读取首行；完整协议原文保留地图
显示端board → 沿用紧凑编码；坐标及界面布局不变
```

运行 `npm run test:game-chat`。验证所有尺寸的行列数、样本坐标、双方成功落子、终局胜负、查看恢复、独立会话跨轮，以及提示摘要与聊天/TTS隔离。显示端继续消费原 `board`/增量格式；持久化棋局不迁移。格式化仍是O(N²)，每份地图新增N个左右换行字符，N最大15。
