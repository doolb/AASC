# 无声纹时 TTS 暂停显示端录音

## 任务描述

修复 Web 显示端未开启声纹识别时，TTS 播放期间仍持续采集麦克风，导致 TTS 回声进入 ASR、产生无效识别或重复触发指令的问题。复用子显示端 `mute` 录音模式的暂停/恢复语义，同时保留浏览器端已经建立的音频资源，避免暂停期间重新创建 Chromium 音频链路。

## design 需求

- 未开启声纹识别且持续监听时，TTS 队列开始播放前暂停 PCM/VAD。
- TTS 队列全部结束后恢复录音；队列句子切换期间不重复恢复。
- 暂停只清理当前语音段缓存，不释放麦克风轨道、AudioContext 和采集节点。
- 声纹识别开启时不改变现有录音和语音打断行为。

## spec 设计

- `PcmAudioCapture` 增加可复用的暂停标记和缓冲清理方法。
- 显示端 TTS 队列首次进入播放时调用 `pauseVoiceRecordingForTts()`。
- 显示端 TTS 队列变为空时调用 `resumeVoiceRecordingAfterTts()`，恢复前重置 VAD 状态。
- 停止播报和播放失败也必须走队列结束后的恢复路径。

## 自测用例

1. 未开启声纹识别、持续监听中播放一条 TTS：录音暂停，TTS 回声不产生 `asrAudio`。
2. 连续播放多条 TTS：第一条开始时暂停，句子切换不恢复，最后一条结束后恢复。
3. TTS 播放失败或停止播报：队列结束后恢复原先处于监听状态的显示端。
4. 开启声纹识别：不触发新的暂停逻辑，原有语音打断行为保持不变。
5. TTS 前没有开启监听：TTS 结束后不擅自打开监听。
6. 多次播放 TTS：复用同一个 `AudioContext` 和 PCM 采集器，不重复申请麦克风。

- 连续播放 20 条 TTS，确认暂停期间不创建新的 `AudioContext` 或 MediaStream。
- 持续监听 10 分钟并重复 TTS，确认 PCM/VAD 对象数量保持稳定。

## 风险评估

- 若只设置暂停标志而不清理旧语音段，TTS 前的半段语音可能在恢复后误提交，因此暂停时必须清空段缓存。
- 若每个 TTS 句子都恢复一次录音，会引入回声窗口，因此恢复只能发生在整个 TTS 队列为空时。
- 若停止播报遗漏恢复路径，显示端可能保持静音监听，需要统一从队列结束逻辑恢复。
