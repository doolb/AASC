# 启动器重复切换与豆包第三档错误排查

## 任务描述

用户反馈外网设备的 launcher 独立版本已是 131，但服务更新仍提示切换；豆包第三档聊天仍报错。启动器由目标设备 ADB 验证，聊天由本机服务验证。

## Design 与 Spec

- `docs/design/android-offline-js-launcher.md`、`docs/spec/android-offline-js-launcher.md`：按实际运行文件指纹和切换事件定位重复切换。
- `docs/design/chat2api-doubao-web.md`、`docs/spec/chat2api-doubao-web.md`：按真实错误样本复现第三档请求，避免把直接接口的会话冲突误认为控制端错误。

## 已完成只读验证

- 本机 ADB 只连接 Note8（`192.168.1.6:5555`）；其活动 launcher code 110、服务 code 112，不是目标外网设备。外网发布机无 ADB。
- LAN 签名清单 code 137、launcher 131；`launcherSha256` 与当前源码一致。`npm run test:offline-launcher` 41/41 通过。
- 本机 Chat2API 代理的第三档新会话非流式、流式及两轮续接成功；隔离配置下常规 LLM 服务从轻量切第三档也在非流式和流式成功。
- 直接对 Responses 强制沿用轻量档响应 ID 切专业档会返回 `doubao_session_conflict`（409）；常规 LLM 切档会重建引用，暂不能认定这是现场错误。

## 待确认与验收

- 外网目标设备的 ADB 地址或连接方式；读取活动状态、实际运行入口和日志，确认是否真的发生进程切换。
- 第三档现场错误文字或错误码、触发提问、是否在已有会话切档；复现后提出具体代码方案并按项目规则取得确认。

## 风险与预计工时

缺少目标设备和现场错误样本时，直接修改代码可能修错分支。定位后预计 1–3 小时，取决于设备可达性与错误重现条件。
