# 任务：TTS 内存风险加固

## 任务描述

- 目标：排查并修复服务端 TTS 生成链路在异常网络场景下的潜在资源泄漏风险
- 范围：`src/external/tts/tts-service.js` 及配置/API 透传，不改动业务调用方协议

## Design 需求

- 外部 TTS 调用增加请求超时，避免 socket 长时间悬挂
- 音频文件写入使用统一流管线回收机制
- 失败路径要删除半成品文件
- 非 200 错误响应限制可缓存错误体大小
- 配置支持在线调整超时和错误体上限

## Spec 设计（伪代码）

```
callExternalTTS(text, voice, speed, outputPath):
    req = http.request(options)
    req.setTimeout(requestTimeoutMs)

    on response:
        if status != 200:
            read error body with maxErrorBytes
            reject(error)
            return

        pipeline(response, fileWriteStream)
        if pipeline error:
            delete outputPath
            reject(error)
        else:
            resolve(outputPath)

    on request error/timeout:
        delete outputPath
        reject(error)
```

## 自测用例

- 用例1：正常 TTS 返回 200
  - 预期：生成 wav 成功，返回输出路径
- 用例2：模拟超时（不可达地址）
  - 预期：在 `requestTimeoutMs` 内失败返回，不出现长时间悬挂
- 用例3：模拟 500 且超大错误体
  - 预期：错误体截断到 `maxErrorBytes`，进程内存不突增
- 用例4：中途断流
  - 预期：写盘失败后清理半成品文件

## 性能测试

- 连续触发 TTS 请求，观察 RSS 曲线是否出现明显持续爬升
- 重点验证异常网络下连接可及时回收

## 风险评估

- 超时值过小可能导致合法慢请求误失败
- 错误体截断会减少调试信息，需要日志配合排查
