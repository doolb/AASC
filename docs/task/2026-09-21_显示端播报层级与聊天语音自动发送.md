# 显示端播报层级与聊天语音自动发送

## 任务描述

将聊天 TTS 和天气详情放入 MMD 上方、聊天层下方的播报辅助层；聊天打开时隐藏仍在有效期内的天气详情和 TTS 文字，关闭后恢复未到期内容。同时修复聊天层语音识别只回显、不自动发送或不更新显示端聊天窗口的问题。

## 设计需求

- 层级：媒体 < MMD < 播报辅助层 < 聊天层。
- 聊天打开/关闭只影响播报文字和天气弹窗可见性，不停止音频。
- 聊天层打开期间语音识别直接发送到当前聊天对象/会话，绕过普通语音确认拦截。
- 语音聊天流式消息同时发送到控制端和发起语音的显示端。

## 自测用例

1. MMD、聊天 TTS、天气详情和聊天层按目标顺序叠放。
2. 天气详情显示期间打开聊天，弹窗隐藏；关闭聊天且未超时，弹窗恢复；超时后不恢复。
3. TTS 文字在聊天打开时隐藏，关闭后恢复未结束的文字；音频持续播放。
4. 聊天层打开后语音输入无需确认即可进入当前聊天，会话选择正确。
5. 显示端收到 `chatInput`、`chatChunk`、`chatResponse` 并更新聊天气泡，控制端同步收到消息。
6. 普通聊天关闭时保持原有唤醒词、确认和指令路由。

## 兼容性与风险

- 普通浏览器显示端和 Offline WebView 共用同一 DOM/WS 协议。
- 不改变天气/TTS 服务端生成和音频播放协议。
- 聊天层绕过确认仅限 `chatLayerVisible=true` 的显示端来源，控制端和普通语音不受影响。

## 完成结果

- 已在 `display.html` 增加播报辅助层，将 TTS 文字和天气详情按“媒体 < MMD < 播报辅助层 < 聊天层”排列；天气弹窗使用 CSS 隐藏，保留原有超时，聊天关闭后未到期内容自动恢复。
- 已在服务端识别聊天层来源的显示端语音输入，跳过普通语音对话确认拦截，并通过 `sendVoiceChatUpdate` 同步控制端与来源显示端的聊天流。
- 已更新显示端层级、天气隐藏恢复和聊天语音自动发送契约测试。

## 后续缺陷修复

- 普通 `voiceCommand` 的 `response` 分支此前仍使用默认 `document.body` 宿主，导致普通 TTS 弹窗可能位于聊天层上方，且没有聊天打开抑制标记。
- 已将普通 response 弹窗改为追加到 `displayBroadcastLayer`，并设置 `suppressWhenChatVisible=true`，与天气详情弹窗统一处理。
- 已增加浏览器回归用例，实际验证普通 TTS 弹窗在聊天打开时隐藏、关闭后恢复，且生命周期计时不被重置。
