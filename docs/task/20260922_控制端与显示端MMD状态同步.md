# 2026-09-22 控制端与显示端 MMD 状态同步

## 任务描述

控制端的 MMD 显示/隐藏操作改为单个切换按钮；服务端按显示端记录 MMD 可见性；显示端手动
切换后同步到服务端，并让控制端、多控制端和显示端重连恢复同一权威状态。

## Design 需求

- 按 `displayId` 独立保存 `mmdVisible`，默认值为 `true`。
- 控制端只显示一个按钮，根据当前权威值显示“显示 MMD”或“隐藏 MMD”。
- 控制端和显示端的修改都通过服务端统一校验、保存和广播。
- 不新增 HTTP 配置接口，不销毁 MMD 模型、动作队列或聊天上下文。
- 兼容旧显示状态：没有 `mmdVisible` 时按显示处理。

关联设计：`docs/design/display-chat-mmd.md`、`docs/design/websocket.md`。

## Spec 设计

```text
控制端点击单按钮
  -> control/mmdVisibility(displayId, !mmdVisible)
  -> 服务端校验并 updateDisplayStateById
  -> control/mmdVisibility 下发目标显示端
  -> mmdVisibilityChanged 广播所有控制端

显示端点击单按钮
  -> mmdVisibilityRequest(displayId, !mmdVisible)
  -> 服务端使用同一持久化流程
  -> control/mmdVisibility 回传显示端
  -> mmdVisibilityChanged 广播所有控制端
```

关联规格：`docs/spec/display-chat-mmd.md`、`docs/spec/websocket.md`、`docs/spec/config.md`。

## 自测用例

1. 控制端只渲染一个 MMD 切换按钮，显示时按钮为“隐藏 MMD”，隐藏时为“显示 MMD”。
2. 控制端切换后目标显示端可见性改变，服务端状态文件出现对应 `displayId.mmdVisible`。
3. 显示端手动切换后控制端按钮实时同步。
4. 两个控制端同时在线时，任一端和显示端切换后两端状态一致。
5. 显示端刷新/重连后恢复服务端保存的 MMD 状态。
6. 控制端切换显示端时，不会沿用前一个显示端的按钮状态。
7. 旧状态没有 `mmdVisible` 时，MMD 默认显示且不报错。

## 兼容性测试

- 浏览器显示端、Android WebView 显示端和 Node 子显示端使用同一 WebSocket 协议。
- 旧显示端忽略新增的显示端上报消息时，控制端原有 `control/mmdVisibility` 仍可工作。
- 无 MMD 模型、模型加载中和模型加载失败时只更新可见层，不影响聊天、媒体和 TTS。

## 性能测试

- 每次状态修改只写入一次显示端用户配置，不增加轮询。
- 重连只发送一次 MMD 权威状态，不创建额外 WebSocket。
- 切换可见性不销毁或重新加载模型。

## 风险评估

- 中：显示端手动操作和控制端操作可能同时到达，必须让服务端最后一次合法请求覆盖并广播。
- 低：旧状态字段缺失，使用默认 `true` 兼容，不影响其他持久化字段。
- 低：新增消息类型只用于状态同步，不改变已有媒体控制消息语义。
