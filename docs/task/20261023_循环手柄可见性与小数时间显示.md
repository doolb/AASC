# 循环手柄可见性与小数时间显示

日期：2026-10-23。状态：源码与本地自测完成，待刷新控制页/Offline服务包更新验收。

## 任务描述与design需求

- 用户反馈开始手柄不可见；真实Chromium浅色主题截图已复现，上层range的白色背景覆盖下层手柄及公共轨道。
- 用户要求时间格式 `00:00.00`；达到一小时时显示 `1:00:00.00`。遵循给定两位小数格式，精度为10毫秒。
- 保持一条滑条两个手柄，修复可见性并实时显示小数时间，不改变循环协议和播放器。

## spec设计与受影响模块

- 先更新 `docs/spec/control-media-loop.md` 的透明叠层、手柄轮廓与小数/小时格式伪代码。
- `css/theme.css`：在浅色主题全局输入背景规则后增加区间range透明背景例外；仅匹配媒体区间，不改其它输入。
- `css/upload.css`：给两个浏览器的手柄增加外侧深色轮廓，保留浅色边框与实心填充。
- `js/control-media-loop.js`、`upload.html`：总百分之一秒分解小时、分钟、秒与小数，动态省略零小时，未知时长显示 `--:--.--`。
- `tests/media-loop-browser.test.js`：加载正式主题模块并切换全部15套主题，验证两手柄实际截图可见、轨道透明、鼠标/触屏仍可拖动；验证小时和进位。
- `js/self-test.js`与对应文档：只读检查区间range透明及时间格式，补充真实主题回归说明。
- 同步design/spec/task/todo/changelog/usage；仅 `servicePackage=true`，其它状态保持，不构建或发布。

## 自测、兼容性、性能

- 使用 `npm run test:media-loop`；修复前需复现浅色主题手柄遮挡，修复后逐主题检查截图像素与交互。
- 时间覆盖小数、不足一分钟、跨分钟、小时及十小时以上；屏幕和aria值一致。
- 兼容Chromium/WebView和Firefox对应伪元素；本机Chromium验证不替代Android真机观感。
- 只修改CSS和已有刷新中的字符串换算，不新增定时器、轮询或远端消息。

## 风险与预计工时

- 风险：主题!important覆盖、手柄靠近端点时混色、时间舍入跨分钟/小时；用局部例外、双层轮廓、统一整数分解规避。
- 预计约1小时。需求等级L6界面修正，L5格式约束，落地能力L4；三项直接证据为开始手柄不可见、00:00.00和有小时h:mm:ss.cc要求。
