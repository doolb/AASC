## design需求与已有能力

目标是保留RTMPose-m二维点与人物左右，用有体积、固定骨长/关节锚点、角度限制与碰撞的三维人体刚体，直接让真实相机下的投影接近图片。需要可视化胶囊/躯干代理及实际关节点，不能仅把预览线段改粗或仅检查一份拟合目标。

本地`web-human-physics-drive.mjs`已经为人体节点建立胶囊/球刚体、质量/惯量、分部位阻尼及原生6DoF约束/碰撞；`web-human-pose-lift.mjs`仍先拟合合法FK三维姿态，产生世界位置/旋转目标，再交给刚体弹簧追随。新方案是更换图像驱动目标，不重新引入另一套引擎，也不把当前实现误称为只有二维线段。

投影残差/相机优化的数学参考为[Ceres重投影误差示例](https://ceres-solver.readthedocs.io/latest/nnls_tutorial.html#bundle-adjustment)；约束动力学参考[MuJoCo计算文档](https://mujoco.readthedocs.io/en/stable/computation/)。这些资料支持问题表述，不是本项目Ammo实现或收益已验证的证据；本轮仍复用已有Ammo，不安装Ceres/MuJoCo。

```text
求解 := 相同初值/相机/预算的有限多候选 → 固定步长逐轮更新 → 记录投影/速度/锚点/限位/碰撞与目标落差 → 达到稳定阈值或预算耗尽 → 保留多解/失败原因
相机 := 姿态趋近后允许有界固定FOV相机匹配/交替迭代；固定身体尺度与根/相机规范，根朝向和镜头多解单列，不称真实镜头唯一恢复
输出 := 读取实际刚体姿态并通过现有父链映射到模型 → 同时检查实际PMX投影与原生刚体投影、锚点/角度和骨长 → 二者不一致保留失败，不拿刚体或target对齐代替显示人物对齐
生命周期 := 独立临时场景/世界，不写用户当前角色目标；换图/取消/超时停止预算与释放Ammo资源；仅正式接入另行确认后挂全身IK，PBD仍屏蔽
```

## 风险、兼容性与预计工作量

单张图片的前后屈曲、肢体绕轴和全身朝向/相机仍可能多解。碰撞体和角度范围只能排除部分不合理解；没有座椅的坐姿不能靠重力自动解释。当前刚体-显示映射及实际肩臂限位已有失败，需要首先定位，否则二维力可能只让代理对齐、人物仍偏。只作浏览器本地原型，沿用同一角色和现有静态图片流程；旧默认不变，先不下载深度模型。

预计原型1～2天，原生约束框架/映射若需修正另记录具体证据；首阶段检查模块与代理/PMX一致性，再推进图片力。package.json无此临时原型script，复用现有Node/Three/Ammo；不并行重建web-dist。未承诺优于现有方案或真实3D恢复，验收由同图实际正侧与误差/约束共同决定。
