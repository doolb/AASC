# 修复 LLM 流式请求客户端断开误判

## 任务描述

修复 `/v1/chat/completions` 和 `/v1/responses` 流式请求在请求体解析完成后被错误取消的问题，并让 `chatv2.py` 显示网关返回的流式错误。非流式请求已经可以正常回复，本任务只调整流式连接生命周期和错误可观测性。

## Design 需求

- 流式断开检测监听 HTTP 响应连接，而不是已完成请求体读取的请求对象。
- 正常推理完成后移除断开监听，再结束响应。
- SSE 错误必须被客户端显示，不得静默结束。
- 不改变模型路由、协议字段、非流式行为、SSL 默认策略和 ASR/TTS。

## Spec 设计

```text
server stream:
  set SSE headers
  res.once('close', cancelIfResponseNotFinished)
  await gateway request
  write completion and [DONE]
  remove close listener
  end response

python client:
  post with verify=args.verify_ssl
  raise/display HTTP error
  parse data lines
  display JSON.error code/message
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：修复 LLM SSE 断开监听对象。
- `Z:/ai/chatv2.py`：显示 HTTP/SSE 错误。
- `docs/design/android-mnnchat-llm.md`：补充流式生命周期设计。
- `docs/spec/android-mnnchat-llm.md`：补充伪代码和错误契约。

## 自测用例

1. 非流式 Chat Completions 仍能返回完整 `choices`。
2. 流式 Chat Completions 能收到文本 chunk 和 `[DONE]`。
3. 流式 Responses 能收到 delta 和完成事件。
4. 客户端断开时服务端取消对应 requestId 并释放队列计数。
5. 服务端返回 SSE error 时 `chatv2.py` 输出错误 code/message。
6. `--verify-ssl` 和默认跳过证书校验行为不变。

## 兼容性测试

- 旧非流式 OpenAI 客户端。
- curl 流式和非流式请求。
- `chatv2.py` 文本请求。
- `/v1/chat/completions`、`/v1/responses` 和 `/v1/chat/responses`。

## 性能测试

- 流式首 chunk 延迟不增加额外轮询或缓冲。
- 完成/取消后路由计数归零，无连接监听泄漏。

## 风险评估

- `res.close` 可能在正常响应结束时触发，因此必须在 `finally` 中移除监听并检查 `writableEnded/writableFinished`。
- 客户端错误输出只增加诊断信息，不改变成功响应内容。

## 预计工时

约 30 分钟，包含定向测试和一次真实接口验证。

## 实施结果

- 服务端 `server-app.js` 将 SSE 断开监听从 `req.close` 改为 `res.close`，并在正常完成前移除监听，避免请求体解析完成后误取消推理。
- `Z:/ai/chatv2.py` 增加 HTTP 非 2xx 输出、SSE `error` 事件输出和 `[DONE]` 结束识别；默认 SSL 跳过策略保持不变。
- 通过 `node --check src/apps/server/boot/server-app.js`。
- LLM 定向测试 20/20 通过。
- 通过 `npm run restart:server` 重启远端服务；真实 Qwen3.5 Chat Completions 流式请求收到完整 chunk 并以 `[DONE]` 结束。
- 全量 `npm test` 仍有触摸注入、睡眠恢复和 ASR/语音既有契约失败，与本任务无关，未扩大范围处理。
