# Offline 设备类别 UI 缩放系数校正

## 任务描述

真机手机分辨率长边约 `2309`、`densityDpi=480` 时，Offline 诊断显示缩放 `165%`，聊天、控制端和显示层仍偏小。需要在不改变物理/逻辑分辨率和媒体渲染尺寸的前提下，调整通用页面初始比例计算；该设备只作为验算样例，不增加设备特判。

## design 需求

- Offline 显示页和控制页统一调整 WebView 初始比例。
- 采用 `scaleFactor = (长边 / 1280) × (densityDpi / 320) × deviceCoefficient` 计算原始缩放因子。
- 通过当前 Display 的 `smallestScreenWidthDp` 区分手机和电脑；手机系数为 `1.108705`，电脑系数为 `1.0`。
- 将缩放因子限制在 `1.0～3.0`，再转换为 WebView 百分比；`2309×1080@480dpi` 手机样例计算为 `3.0`，即 `300%`。
- 普通 APK 固定因子 `1.0`；Display 2 按电脑系数计算且不低于因子 `1.0`。
- 不修改系统 density、屏幕分辨率、媒体层分辨率、模型渲染尺寸、输入坐标协议和页面业务布局。

## spec 设计

```text
WebViewScalePolicy.deviceClass(smallestScreenWidthDp):
    如果 smallestScreenWidthDp > 0 且 smallestScreenWidthDp < 600：返回 PHONE
    返回 COMPUTER

WebViewScalePolicy.scaleFactor(offlineMode, widthPixels, heightPixels, densityDpi, deviceClass):
    如果 offlineMode == false 或输入无效：返回 1.0
    longEdgePixels = max(widthPixels, heightPixels)
    resolutionRatio = longEdgePixels / 1280
    densityRatio = densityDpi / 320
    deviceCoefficient = deviceClass == PHONE ? 1.108705 : 1.0
    rawScaleFactor = resolutionRatio × densityRatio × deviceCoefficient
    返回 clamp(rawScaleFactor, 1.0, 3.0)

WebViewScalePolicy.initialScalePercent(..., deviceClass):
    返回 round(scaleFactor(...) × 100)
```

## 自测用例

- `1280×720@320dpi` 返回 `100%`。
- `1920×1080@160dpi` 电脑因子 `0.75`，下限为 `1.0`。
- `1920×1080@320dpi` 电脑返回 `150%`。
- `720×1480@280dpi` 手机返回约 `112%`。
- `2309×1080@480dpi` 手机原始约 `3.0`，最终返回 `300%`。
- 普通 APK、无效分辨率和无效 DPI 的回退行为不变。
- Android JVM 单元测试、Offline 静态回归和 APK ZIP 完整性检查通过。

## 兼容性测试

- Android 9/API 28、arm64、SM-N9500。
- Display 2 和手机内置屏幕分别确认显示页、控制页和诊断浮层使用同一缩放值。
- 普通 APK 保持 `100%` 策略。

## 性能测试

- 只改变 WebView 创建和诊断浮层刷新时的常量计算，不增加布局循环、网络请求或模型加载。

## 风险评估

- `setInitialScale()` 与页面 viewport 在不同 WebView 版本上可能存在视觉差异，需要以诊断浮层和真机截图/手工观察复核。
- `300%` 会减少手机可见 CSS viewport，可能增加页面滚动或控件换行；不改变原生媒体层和输入坐标。
