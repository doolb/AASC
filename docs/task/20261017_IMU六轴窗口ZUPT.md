# IMU 六轴窗口 ZUPT

状态：已实现并完成固定种子、浏览器轨迹接口及专项测试验证；真实手机定位精度另行现场验收。

## 任务描述、需求与分级

用户要求采用现有六轴 IMU 静稳处理方法，升级模拟器自动零速修正。当前本地轨迹真值静止但估计速度约2.1m/s，旧减速证据缺失使误差持续线性扩大。用户确认仅用六轴，接受长时间匀速可能误判的物理限制。主需求为 L5 静稳判定与零速更新流程，次需求为 L4 六轴窗口统计；风险中等，已明确仅模拟器自动执行、手机默认手动、真值只用于评估。

## Design / Spec

需求与边界见 `docs/design/imu-six-axis-test.md` 的“六轴窗口 ZUPT 需求”；实现伪代码见 `docs/spec/imu-six-axis-test.md` 的“模拟器六轴窗口 ZUPT”。滑动窗口计算角速度、去重力加速度和波动的静稳评分；有减速证据时较快修正，无证据但持续高评分时兜底归零。

## 影响模块

- `3rd/imu-six-axis-test/imu-engine.mjs`：有界窗口、评分、零速更新、快照诊断。
- `tests/imu-six-axis-engine.test.js`：静止残留速度、短暂安静、往返轨迹和匀速误判边界。
- `tests/imu-six-axis-browser.test.js`：浏览器真实拖动后核对轨迹接口的同源实时帧与分轴误差。
- `docs/design/imu-six-axis-test.md`、`docs/spec/imu-six-axis-test.md`、`docs/todo.md`、`changelog.md` 与 IMU 使用说明：行为、结果和限制。

## 自测、兼容、性能、风险

先用保存的当前轨迹及固定种子模拟作基线，再通过 `npm run test:imu:six-axis-test` 验证。对比运动中零速修正次数、静稳后的 X/Y/Z/总位置误差，确保真实浏览器手机、远程 APK 与线性加速度输入原有路径兼容。窗口最多80点，正常每帧仅对有限样本计算评分。静止与匀速不可凭六轴严格区分，兜底可能清掉真实匀速；不能倒推修复历史位置。真实设备定位精度另行验收。

## 完成与复测

固定种子三段平面往返，运动中没有额外归零；静止后最终逐轴误差由修改前 `[0.392445, 0.121296, -0.196885]` 米变为 `[0.399706, 0.124845, -0.200978]` 米，总误差约0.4647米。无减速证据但保留 `[0.15, 0.31, 2.09]` m/s 旧速度的静止输入，约1.9秒后自动归零；20秒时 Z 位置约3.95米，旧逻辑为41.8米且仍保留速度。仅凭六轴无法辨识长时间匀速，本次将该误判写入专项测试。浏览器真实拖动后，`/api/imu/trajectory` 返回同源实时帧及分轴误差。`npm run test:imu:six-axis-test` 20/20通过。现存旧网页需刷新并重新开始轨迹，旧位置误差不会回溯修复。
