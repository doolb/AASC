# 控制端服务器面板显示启动器版本

## 任务描述

在控制端“服务器”页显示当前服务器实际运行的 launcher 独立版本，并与服务代码版本分开。

## Design 需求与 Spec 设计

- `docs/design/sub-server.md`：定义版本显示位置、数据来源和旧设备兼容规则。
- `docs/spec/sub-server.md`：定义活动状态读取、可选版本字段和前端渲染伪代码。

## 受影响模块与代码

- `src/apps/server/modules/aasc/runtime-version-info.js`：从活动 launcher 状态读取独立版本，沿现有版本对象返回。
- `src/apps/web-mediacenter/ui/public/js/server-list.js`：在当前运行摘要和节点卡片加入“启动器”版本。
- `src/apps/web-mediacenter/ui/public/js/self-test.js`：校验已上报的启动器字段。
- `tests/runtime-version-info.test.js`、`tests/server-list-ui.test.js`：覆盖新、旧和缺失状态及双位置渲染。

## 自测用例与兼容性测试

- 新签名清单中的活动 launcher 版本与 code 版本不同，页面分别显示。
- 旧清单缺少 launcherVersion 时回退到 active.version；普通服务器缺少 launcher 状态时不显示伪造版本。
- 损坏状态文件不会影响现有服务版本；版本值安全渲染，刷新后随权威状态更新。

## 性能测试与风险评估

复用现有服务器列表刷新与状态查询，不新增轮询。版本信息由本机小型 JSON 文件读取；失败时降级为字段缺失。代码更改只影响服务包，不涉及 Android 原生或依赖产物。

## 预计工时

约 1 小时；外网设备实际版本仍需设备连接后核对。

## 执行结果

已从 `launcher-state.json.active` 读取独立启动器版本并沿现有服务器快照返回；服务器卡片和“当前运行版本”摘要均显示“启动器: vN”。旧清单回退到活动 code 版本，普通 Node 服务器与无效状态不显示该项。相关定向测试 10/10、`npm run test:subserver-update` 64/64 通过；外网设备显示效果留待服务包构建、设备上线后验收。
