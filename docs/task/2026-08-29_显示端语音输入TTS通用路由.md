# 显示端语音输入 TTS 通用路由

## 任务描述

修复显示端语音输入触发的 TTS 默认回放到输入显示端的问题，使语音命令和语音触发的普通对话统一使用服务端通用 TTS 生成与语音播放目标路由。

## design 需求

- `displayId` 继续用于命令执行、媒体控制和结果弹窗，但不作为显示端语音输入的默认 TTS 目标。
- 统一调用 `generateTtsWithFallback()`，根据在线 `voicePlayback` 能力向语音播放显示端发送音频。
- 保留控制端已有的 `playOnControl` 和指定显示端播放行为。
- 停止播报、唤醒提示和组合命令必须遵循同一目标规则。

## spec 设计

- 语音命令服务通过 `speakVoiceResponse()` 接收调用方 TTS 回调，不再直接调用底层 TTS 服务。
- 服务端为显示端来源注入 `onTts` 和 `onStop`，分别广播音频和停止消息。
- 语音触发的普通对话通过 `routeVoiceToAll` 在每句播放时读取当前语音播放目标。
- 弹窗类 `voiceCommand` 消息仅发送界面数据，不携带 `audioUrl`。

## 自测用例

1. 显示端说“现在几点”，TTS 通过通用生成路由发送，不生成后直接回发输入显示端。
2. 多个显示端具备 `voicePlayback` 时，显示端语音输入的 TTS 发送到全部在线目标。
3. 显示端说“停止播报”，全部在线语音播放显示端收到停止消息。
4. 显示端触发普通对话，逐句 TTS 使用通用目标列表，不隐式回落到来源显示端。
5. 控制端 `playOnControl` 和定向显示端命令行为保持不变。
6. 提醒确认、组合命令和播放选择响应不重复播放。

## 兼容性测试

- 显示端浏览器和 Android Display APK。
- 旧版 Go/C#/Node 子显示端沿用原有命令入口。
- `tts.device=server/display` 及服务器 TTS 开关组合。
- 无在线 `voicePlayback` 显示端时不抛出未处理异常。

## 性能测试

- 单句 TTS 只生成一次，同一音频 URL 可发送给多个目标。
- 不新增 TTS 生成并发；普通对话继续复用既有有序调度器。

## 风险评估

- 显示端语音输入的音频目标从单一来源变为全部在线 `voicePlayback` 目标，多个设备可能同时播报；这是通用路由要求的预期行为。
- 弹窗消息与音频消息拆分后，旧显示端只收到不带音频的 `voiceCommand` 时不会重复播放，音频由通用 `tts` 消息承载。
