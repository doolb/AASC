# Node子显示端退出时回收mpv

## 任务描述

修复子显示端按TUI `q`/`Ctrl+C` 退出会遗留mpv子进程的问题，并让终端断开`SIGHUP`走清理流程。无法捕获的`SIGKILL`和断电作为系统边界记录。

## Design需求

见`docs/design/node-display-exit.md`：所有可捕获退出原因共用一个幂等关闭协调器；VoiceDisplay逐项释放资源，异常不跳过媒体关闭；清理完成后才退出。

## Spec设计

见`docs/spec/node-display-exit.md`：协调顺序、SIGTERM/SIGKILL有界回收和进程级退出验收伪代码。

## 受影响功能与代码

- `src/apps/voice-display-node/tui.js`：键盘退出改为调用关闭回调。
- `src/apps/voice-display-node/main.js`：集中处理按键、SIGINT、SIGTERM、SIGHUP和启动失败。
- 新增`src/apps/voice-display-node/shutdown-controller.js`：幂等关闭协调。
- `VoiceDisplay.stop`：组件逐项关闭，确保异常时媒体仍关闭。
- 新增Node退出回归并更新design/spec/todo/changelog。

## 自测用例

TUI退出进入统一协调器；同时触发多个退出来源只停止一次；真实mpv fixture进程退出且IPC目录删除；某个前置清理失败时仍调用媒体关闭并返回失败退出码。

## 执行结果

- `npm run test:node-display-mpv`：53/53通过，包含实际独立mpv fixture进程回收、重复关闭幂等及清理失败继续释放媒体。
- 测试使用可控mpv子进程fixture验证生命周期，不代表目标设备/真实mpv画面实机验收；普通睡眠与深度睡眠遮罩已有独立的真实Xvnc渲染用例。
- `SIGKILL`不可捕获；尚未构建或部署新的Node独立包。

## 兼容性测试

TUI开启/关闭、Linux/macOS终端挂断`SIGHUP`、SIGINT/SIGTERM及`--no-tui`启动失败路径；Node独立包纳入新增模块。SIGKILL不具备进程内清理机会。

## 性能测试

关闭路径沿用mpv既有最长2秒的子进程回收等待；不增加运行期轮询或媒体播放开销。

## 风险评估与预计工时

重复信号、清理异常和TUI销毁时序可能造成重入；以共享Promise和实际子进程测试覆盖。预计1小时。
