# 子显示端 Windows 语音转文字输入

## 任务描述

为 Node.js 子显示端增加 Windows 系统级语音转文字输入：快捷键或“开始输入”激活，普通语音注入当前前台窗口，“返回”删除最近一次语音输入，“发送”发送 Enter，“结束输入”退出输入模式并播报状态。

## design 需求

- 仅支持 Windows，目标是其他获得焦点的系统窗口，不使用子显示端底部 TUI 输入栏。
- 使用全局快捷键 `Ctrl+Alt+Space` 和精确语音命令“开始输入”激活。
- 输入文本使用 Unicode 剪贴板 + Ctrl+V 注入，并尽力恢复原剪贴板。
- 返回/发送校验窗口句柄，窗口变化时不得误发按键。
- 输入模式下 ASR 结果不进入服务器聊天和语音命令处理链路。
- 开始/结束输入播放状态提示，提示期间暂停录音，播报结束或失败后恢复录音。
- 修复 Windows `SendInput` 原生结构尺寸和 PowerShell 中文输出编码，并保留 Win32 错误码。

## spec 设计

- 新增 `windows-voice-text-input` spec，定义输入状态、Windows 注入器、全局热键、ASR 旁路和测试伪代码。
- `main.js` 管理输入模式与返回记录，`asr-client.js` 携带本地输入标记，`server-app.js` 对激活词和 active 模式旁路处理。

## 实施结果

- 已新增 Windows 输入模块：通过隐藏 PowerShell 调用 Win32 `GetForegroundWindow`/`SendInput`，以 Unicode 剪贴板 + Ctrl+V 注入文本，并串行处理输入、返回和发送。
- 已在 Node 子显示端接入 `Ctrl+Alt+Space`、语音激活词“开始输入”、命令“返回”“发送”和“结束输入”；开始/结束时先播放状态提示，提示队列完成或失败后恢复录音。文本目标是用户当前前台窗口，不写入 TUI 底部输入栏。
- 已在服务端 ASR 路由增加本地输入旁路，active 模式只返回 ASR 文本给 Node，不进入服务器语音命令、聊天或 `voiceInput` 下发链路。
- 已修复 `INPUT` 联合体缺少原生最大成员导致的 `SendInput` 失败，并固定 PowerShell UTF-8 输出、记录 Win32 错误码；补充非 Windows、注入队列、窗口标识、可见字符计数、提示播报和 Node/服务端契约测试。
- 本次缺陷修复将“返回”设为唯一撤销命令；服务端状态提示不再创建 `voiceTtsPlaybackId` 或广播全局播放门控，Node 只等待来源端本地音频队列结束后恢复录音，并补充提示播放完成/失败日志。

## 自测用例

1. Node 子显示端在 Windows 注册 `Ctrl+Alt+Space`，按键切换输入模式。
2. 说“开始输入”只激活本地输入，不发送服务端语音命令。
3. 输入模式下连续识别中文，按每个 ASR 分段注入当前焦点窗口。
4. 说“返回”删除最近一段，重复返回按顺序删除历史输入。
5. 说“发送”向原窗口发送 Enter，并退出输入模式。
6. 说“结束输入”退出输入模式并播放结束提示，提示结束后恢复录音。
7. 输入/返回/发送期间切换窗口时不误操作新窗口。
8. PowerShell 失败、剪贴板占用、提示生成失败和服务端断线时进程不崩溃。

实际结果：本次相关定向回归 63/63 通过；5 个受影响 JavaScript 文件 `node --check`、`git diff --check` 通过。完整 `npm test` 共 620 项，619 项通过，唯一失败为现有 `display-native-bridge` 的 `injectTouch(down)` 契约，失败断言与本功能无关；当前环境不是 Windows，尚未执行记事本/浏览器实机验收。

## 兼容性测试

- Windows 10/11 Node 子显示端。
- 记事本、浏览器地址栏、普通文本编辑器和不支持粘贴的窗口。
- 普通语音模式、Windows 输入模式、ASR 服务端/显示端生成模式。
- 旧版请求不带 `textInputClient` 时保持既有语音命令链路。

## 性能测试

- 注入操作串行化，不产生多个并发 PowerShell 剪贴板操作。
- 单段文本只执行一次剪贴板设置、一次粘贴和一次恢复。
- 快捷键监听使用单个隐藏消息循环，不轮询前台窗口。

## 风险评估

- Windows 前台窗口变化可能造成目标失效；通过窗口标识校验拒绝返回/发送。
- 状态提示不能进入全局 TTS 播放门控；否则提示完成后来源端可能因残留远程播放标识而不恢复录音。本次修复要求状态提示只在来源 Node 本地队列中完成闭环。
- 剪贴板被其他程序占用可能导致当前段注入失败；保留状态并记录错误，不降级为破坏中文的逐字符输入。
- PowerShell 策略或系统权限可能阻止 Win32 调用；非致命失败不影响 ASR 和 WebSocket。
- Windows 实机仍需补充前台窗口、剪贴板占用和不支持粘贴窗口的手工验收。
