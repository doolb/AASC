# 修复动态画面填充过渡

## 任务描述

修复动态画面填充模式没有过渡过程、从适应尺寸直接跳到铺满尺寸的问题。

## 根因

动态阶段同时设置 transition 和目标宽高，浏览器不会为同一轮样式更新触发预期过渡；即使补充布局刷新，`applyCrop()` 仍会先清空 width/height，导致动态阶段没有稳定的旧尺寸作为插值起点。

## 修复内容

- 动态过渡阶段先写入 width/height transition，读取 `offsetWidth` 提交布局。
- 下一帧调用 `applyCrop({ preserveMediaSize: true })`，保留当前宽高，只写入新的目标宽高。
- 非动态模式继续使用原有 `applyCrop()` 清理逻辑。
- 增加真实 `display.html` + Puppeteer 回归测试，验证过渡中尺寸位于适应和铺满之间。

## 受影响文件

- `src/apps/web-mediacenter/ui/public/display.html`
- `tests/dynamic-fit-mode.test.js`
- `docs/design/dynamic-fit-mode.md`
- `docs/spec/dynamic-fit-mode.md`

## 自测用例

1. 动态模式进入铺满过渡约 0.5 秒时，尺寸大于适应尺寸且小于铺满尺寸。
2. 动态控制器原有阶段循环和停止逻辑保持通过。
3. 旋转、裁剪和媒体恢复相关测试保持通过。

## 风险评估

仅动态图片/视频阶段使用 `preserveMediaSize`；普通填充模式和 HTML 媒体不改变原有尺寸清理路径。
