# 2026-09-19 控制端与显示端 render 刷新诊断

## 任务描述

定位控制端显示面板持续调用 `render()`，以及显示端 `render-display` 持续更新的真实触发来源。

## design 需求

- 在服务端 displayList 广播、控制端 displayList 接收/重绘、显示端 renderUpdate 四个边界增加可关闭的诊断日志。
- 在控制端“语音播报 (TTS)”输入框 `ttsTextInput` 的初始化、焦点、鼠标、输入和 DOM 变化边界增加诊断日志；不进入 TTS 请求链路。
- 日志以 1 秒窗口汇总，包含计数、displayId/instanceId、调用来源或数据字段。
- 不改变刷新行为，便于现场复现后根据日志继续修复。

## spec 设计

- 使用 `docs/spec/render-refresh-diagnostics.md` 中的伪代码定义观测点。
- 诊断日志不参与业务状态、不发送额外 WebSocket 消息。

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`
- `src/apps/web-mediacenter/ui/public/js/websocket.js`
- `src/apps/web-mediacenter/ui/public/js/device-list.js`
- `src/apps/web-mediacenter/ui/public/display.html`

## 自测用例

- 开关打开时，控制端收到 displayList 能看到 1 秒汇总日志。
- 开关打开时，DeviceList.render 持续调用能看到次数和调用栈来源。
- 开关打开时，服务端能看到 displayList 广播来源集合。
- 开关打开时，显示端 render-display 收到高频更新能按实例看到更新次数。
- 默认关闭时不输出本次新增的诊断日志。
- TTS 输入框诊断对 focus/click 等生命周期事件立即输出，高频事件按 1 秒窗口汇总；不记录文本内容，只记录长度和元素状态。
- 未收到高频消息时不产生额外定时器或 WebSocket 流量。

## 风险评估

- 诊断埋点默认关闭，不增加现场控制台和服务端输出；不改变运行逻辑。
- 后续需要复现时仅打开 `ENABLE_RENDER_REFRESH_DIAGNOSTICS`，确认来源后再删除或长期关闭诊断埋点。
