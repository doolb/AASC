# 五子棋多行标签与控制端提示

- 任务描述：AI 可以在回复开头连续输出多行 Game 标签，每条独占一行，后接自然语言；控制端聊天逐条显示调用和 GM 回执的灰色 tips。
- 需求判级：主等级 L5（批量执行与失败语义），次等级 L6（标签格式、GM 回执和聊天展示契约）；现场已有单标签协议、明确输入格式与控制端提示样式，结论可开发。风险是批次中途失败会留下已确认的前序操作，需要把全部已执行回执送回模型纠正。
- design 需求：沿用当前 `raw` 单条 user 消息；简洁的标签规则紧跟 `System:` 标记，目录指令提示在其后，再接原角色设定。连续标签按出现顺序逐条校验，最多八条；叙述只有整批成功后才显示、朗读。每条标签与 GM 均进入控制端 tips。
- spec 设计：两个及以上标签必须在回复开头连续独占行，标签段之后允许自然语言；单标签同一行叙述兼容。先校验整段格式，再按当前版本和回合逐条执行；失败时停止后续、保留已确认操作、将成功与失败 GM 按序回送模型；全部成功且已有叙述、轮到 User 时直接结束。控制端协议提示保存/渲染上限 128 条。
- 受影响功能和代码：`game-chat-bridge.js`、`llm-service.js`、控制端 `chat.js`；`game-gomoku.test.js` 和 `gomoku-chat-tip-browser.test.js`。五子棋权威落子校验、显示端事件协议保持原样。
- 自测用例：同一回复 User H3 与 AI H4 两行标签及末尾叙述；第二条落子失败时停止第三条、回送两条 GM 并丢弃失败叙述；同一行两标签和九标签拒绝整批；单标签同一行叙述兼容；控制端多条实时 tips 和超过 20 条的历史恢复。
- 兼容性测试：五子棋桥接、聊天请求 ID、普通语音聊天及控制端 Chromium 渲染；无活动棋局的普通聊天继续流式，单标签调用不改变原流程。
- 性能测试：每批最多八条标签、单轮至多七次模型续接；浏览器最多渲染和持久化 128 条 tips。批量成功时可减少 User/AI 连续落子的模型往返次数。
- 风险评估：批次前序成功、后序失败不会回滚前序棋步；模型可能依据过期棋盘预写不合法的第二步，由现有版本/回合/空位检查阻止，失败叙述不播报。目录与规则读取仍建议等待各自 GM 回执。
- 预计工时：约 1 小时。
- 验证结果：五子棋、控制端浏览器、普通聊天请求 ID 与显示端语音合同测试 25/25 通过，脚本语法与差异检查通过。当前豆包模型隔离请求返回目录标签并在其后附自然语言，没有写入现有聊天或棋盘。
- 状态：源码与定向测试完成；待服务代码包加载后做真实多标签模型和设备回归。
