# 显示端摄像头拍照预览与 AI 图片聊天

## 任务描述

为控制端增加显示端摄像头卡片，支持单摄像头选择、单次拍照、实时监控式预览，并将单次照片作为聊天图片输入发送给普通 LLM。

## design 需求

- 参见 `docs/design/display-camera-chat.md`。
- 一次只使用一个摄像头；实时视频不保存、不进入 AI。
- 浏览器和 Android WebView 首期支持，Windows 子显示端明确显示不支持。

## spec 设计

- 参见 `docs/spec/display-camera-chat.md`。
- 服务端只做 WebSocket 转发、权限边界和大小校验。
- 图片消息使用 `chatMessage.images`，LLM 请求使用多模态 user content。

## 自测用例

1. 摄像头能力为 false 时卡片按钮禁用，Windows 显示端不发起采集。
2. 多摄像头列表可刷新、切换时旧轨道被停止，单次拍照只返回一张图片。
3. 实时预览持续更新控制端图片，停止后没有后续帧，服务端不写盘。
4. 单次照片可以加入聊天输入、预览、移除并随普通 LLM 请求发送。
5. Agent 图片消息返回明确错误；文本聊天和既有录音回归不受影响。

## 兼容性测试

- Chrome/Edge 浏览器显示端。
- Android WebView 显示端，验证 CAMERA 和 VIDEO_CAPTURE 权限。
- Windows `voice-display-node` 能力列表显示不支持。
- 无摄像头、拒绝权限、摄像头断开和显示端重连。

## 性能测试

- 实时预览约 400ms 一帧，限制低分辨率 JPEG 和消息大小。
- 连续预览 5 分钟无服务端磁盘文件增长和未清理定时器。
- 图片聊天不会阻塞控制端渲染和已有音频播放。

## 风险评估

- 浏览器设备标签需要授权后才稳定，使用回退名称。
- 不同 AI 后端对图片协议支持不同；首期统一走 OpenAI Chat Completions/Responses 兼容的图片内容格式。
- Android 厂商 WebView 权限行为可能不同，需要真机回归。

## 2026-09-13 黑帧修复补充

### 问题

- Android WebView 实时预览已有画面，但单次拍照在 `video.play()` 完成后立即执行 Canvas 截帧，可能在首个真实视频帧提交前得到黑图。

### 修复方案

- `display.html` 优先使用视频轨道的 `ImageCapture.takePhoto()` 获取照片 Blob 并转换为 Base64；不支持或失败时才使用 Canvas 兜底。
- Canvas 兜底等待多个 `requestVideoFrameCallback` 帧并延迟稳定时间，旧版 WebView 使用可绘制状态轮询和延迟绘制；2 秒内未获得有效帧则返回错误并释放摄像头轨道。
- 实时预览继续使用原有约 400ms 定时帧策略。

### 自测用例

- `tests/display-camera-chat.test.js` 增加首帧等待、`readyState`、`requestVideoFrameCallback` 和单次拍照调用顺序断言。
- Android 真机通过 `npm run upload:apk` 重新构建、安装并启动 `com.aasc.display/.MainActivity`。

## 2026-09-13 自动刷新与显示端状态补充

### 需求

- 控制端摄像头卡片不再要求用户先点击“刷新摄像头”；支持摄像头的在线显示端首次出现在当前卡片时自动读取设备列表。
- 显示端增加摄像头状态提示，覆盖刷新、拍照、实时预览、停止和错误状态。

### 实现

- `device-list.js` 为每个在线显示端保存自动刷新状态，列表未加载时异步发起一次 `listDisplayCameras`；设备离线后清理状态，避免旧设备数据残留。
- `display.html` 新增摄像头状态 DOM 和状态更新逻辑；`display.css` 增加不同状态颜色和移动端尺寸样式。
- 自动刷新只枚举设备，不自动开启视频流或实时预览；拍照、实时预览和原有摄像头协议保持不变。

### 自测用例

- `tests/display-camera-chat.test.js` 增加自动刷新和显示端状态断言。
- 通过 `npm run upload:apk` 重新构建、安装到 `192.168.1.6:5555` 并启动真机 APK。

## 2026-09-13 LLM 状态更新导致摄像头列表收起修复

### 需求

- 控制端展开摄像头列表后，LLM 状态更新不得销毁摄像头下拉框或导致列表自动收起。

### 实现

- `DeviceList.handleLlmStatus()` 继续更新显示端 LLM 状态，但只调用 `renderLlmModelPanel()`，不再调用完整的 `DeviceList.render()`。
- 设备列表、VAD、录音和摄像头卡片不因 LLM 状态回传而重建；LLM 状态列表仍由现有 WebSocket 路由逐条处理。

### 自测用例

- `tests/display-camera-chat.test.js` 断言 LLM 状态处理函数刷新模型面板且不调用完整渲染。
- 通过摄像头定向测试和 JavaScript 语法检查；`git diff --check` 仅发现工作区已有的其他文件尾随空格。
