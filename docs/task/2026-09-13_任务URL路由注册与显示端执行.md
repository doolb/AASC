# 任务 URL 路由注册与显示端执行

## 任务描述

为任务底层增加 URL 路由注册能力，使不能自行监听端口的网页显示端也能执行服务任务；路由统一挂载 AASC 当前服务端口，暂定 `8081`。

## design 需求

- 服务端任务和显示端/子显示端服务任务使用统一 `context.registerRoute()` 接口。
- AASC 主服务接收 HTTP 请求；显示端通过 WebSocket 处理请求，不监听独立端口。
- 路由按方法和路径防冲突，并绑定任务实例。
- 任务停止、重启、异常、显示端断开和服务销毁时清理路由与等待请求。
- `llm-server` 接入任务路由，保留现有 LLM 协议路径和 `8081` 入口。

## spec 设计

```text
HTTP :8081
  -> TaskRouteRegistry
  -> server handler 或 task:route_request
  -> task:route_response
  -> HTTP response
```

## 自测用例

1. 服务端任务注册 GET/POST 路由后可以通过统一分发器处理请求。
2. 不同实例注册同一 method/path 时后注册失败。
3. 停止实例后路由不可再访问，等待中的显示端请求返回服务不可用。
4. 显示端注册路由收到确认后，HTTP 请求可以经 WebSocket 到达对应 handler。
5. 显示端 handler 可以返回 JSON、普通文本和流式 chunk。
6. 显示端断开时路由清理且 pending 请求返回 503。
7. `llm-server` 注册 `/v1/models`、`/v1/chat/completions`、`/v1/responses` 和 `/v1/chat/responses`。
8. 现有非任务路由、LLM 网关协议和显示端普通任务执行不回归。

## 兼容性测试

- 未运行任务时，既有固定 HTTP 路由继续按原逻辑工作。
- 浏览器显示端和 Node 子显示端都遵守 `type`、`routeId`、`requestId` 消息约定。
- 任务服务自动恢复后重新注册路由，不读取新增独立 HTTP 配置。
- 不增加独立任务端口，不改变现有 `8081` 默认端口。

## 性能测试

- 路由查找使用 `method + path` Map，单次请求为常数级查找。
- 显示端请求只携带已解析的 JSON body 和必要 headers，不复制 Express 对象。
- pending 请求、路由和本地 handler 在结束/超时/断连后及时删除。

## 风险评估

- 路由冲突可能影响已有固定入口；动态路由中间件只在注册命中时拦截，未命中继续交给旧路由。
- 显示端断连会使在途 HTTP 请求失败；统一返回 503/504，避免连接永久挂起。
- 路由暴露沿用当前 AASC 局域网 HTTP 边界，本次不新增鉴权；后续可在注册器统一增加鉴权钩子。
