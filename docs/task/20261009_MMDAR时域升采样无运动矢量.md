# 独立 MMD-AR：TAA / FSR2 抗锯齿模式（无运动矢量）

日期：2026-10-09。状态：实现、定向测试和本地网页构建完成；Android WebView/手机实机画面与性能待验收。用户后续反馈轮廓锯齿/爬行且比例1.0无改善，单独改进任务见`docs/task/20261009_MMDAR_FSR2边缘滤波优化.md`。

## 需求与范围

用户要求基于现有TAA增加新的抗锯齿选项，并明确不处理运动信息；最终澄清是两种互斥方式：TAA或者FSR2。新增FSR2模式为WebGL2片元Shader实现的时域升采样近似，不直接集成AMD官方SDK，也不生成/读取物体或骨骼运动矢量。允许复用相机矩阵与深度历史重投影。

范围仅为独立MMD-AR测试网页及其生成资源；保留现有TAA、Canvas倍率、PNG导出、正式显示端和Blender输出契约。UI保留现有抗锯齿总开关，新增TAA/FSR2模式选择；默认总开关关闭，旧数据按TAA模式解释。

## 设计与契约

依据：`docs/design/mmd-ar-test-apk.md`“基于现有TAA的FSR2模式”节；`docs/spec/mmd-ar-test-apk.md`“抗锯齿模式TAA/FSR2契约”伪代码。

- 新增`aaMode='taa'|'fsr2'`及`fsr2Scale=0.67`（0.50–1.00，步长0.01），保留`taaEnabled=false`总开关，使用现有本地存储key并兼容旧字段/设置。
- `canvasScale`仍控制最终Canvas backing buffer；FSR2模式内部渲染尺寸=实际输出尺寸×`fsr2Scale`。维持相机aspect和AR投影按输出画布计算。
- FSR2模式的当前场景颜色/深度与AO、接触阴影、SSGI目标使用内部尺寸；jitter按内部像素计算。当前颜色先进行深度引导的空间重建，再与全输出分辨率的历史颜色重投影/混合；历史颜色/深度双缓冲为输出尺寸。
- 历史重投影只根据相机矩阵和深度；深度/覆盖变化拒绝，颜色邻域裁剪并降低历史权重。不生成或读取运动矢量；动态角色可能残影、闪烁或退化为当前帧。
- WebGL2不可用、总开关关闭、显式诊断/PNG捕获时不低分辨率降档场景；普通TAA路径保持现有1:1尺寸行为，两个模式互斥、不串行运行。

## 需求等级评审

企业模式：主等级L6，次等级L5/L4，结论“可开发”，置信度0.68（中），直接开发风险中，90/100。必须下放至L4数据流：抗锯齿总开关/模式→最终输出与内部输入尺寸→低分辨率jitter场景颜色/深度→空间重建→相机/深度历史拒绝与混合→全分辨率输出。主要断点为无物体运动矢量；以明确范围、深度/颜色拒绝及真实动态模型测试控制，不新增速度缓存。

## 自测与兼容性

- 旧存储没有`aaMode/fsr2Scale`时迁移到TAA/default；总开关/模式/FSR2比例保存刷新复位；两种模式互斥。
- 普通TAA原有抖动矩阵/尺寸/像素结果契约不变；FSR2低分辨率目标宽高正确、历史和Canvas保持输出尺寸，jitter按内部尺寸。
- FSR2开启/关闭/切换/比例/尺寸/设备限制清理历史；读写目标不别名；异常恢复矩阵、renderTarget和viewport。
- 真实WebGL2 Shader编译/链接、边缘与透明alpha、深度/覆盖拒绝、相机移动、空历史首帧。
- WebGL2能力旁路、AO/接触/SSGI组合、PMX/GLB/VMD/AR投影、PNG捕获指定尺寸和预乘alpha兼容。

## 性能与风险

固定模型、相机、输出倍率与效果组合，比较TAA/FSR2模式的输入/输出尺寸、全帧GPU完成时间、目标数和显存估值；区分场景渲染节省与全分辨率重建成本。SwiftShader仅用于正确性，不代表手机性能。

风险：没有物体/骨骼运动矢量，动态内容可能拖影或被保守拒绝；全分辨率历史目标占显存，重建增加片元采样，未保证所有设备提速。新模式默认关闭，结果提示标明运动局限，移动设备仍待验收。

预计实施4–8小时，另计设备画面与性能验收；不承诺手机帧率。
