# 五子棋终局 GM 回执字段精简

日期：2026-10-20

## 任务描述

用户指出终局 GM 落子与状态两行都有 `User`，其中一个字段原本代表下一手，但棋局已结束。用户指定终局格式：`Game:五子棋,GM,落子,344a,10,User,E2` 与 `Game:五子棋,GM,状态,344a,10,9,User胜`。

## Design 需求与 Spec 设计

见 `docs/design/game-gomoku.md`、`docs/spec/game-gomoku.md`。进行中回执保留既有字段；终局落子只写到坐标，终局状态只写尺寸和最终结果。内部棋局和显示端增量保持既有 turn/result，以免影响同步与 UI；控制端和显示端的 GM 状态摘要显示胜负。

## 受影响模块与代码

- `src/apps/server/modules/game/gomoku-game-service.js`：按是否终局生成不同字段长度的 GM 落子与状态行。
- `src/apps/server/modules/game/game-chat-bridge.js`：状态协议摘要显示最终结果。
- `tests/game-gomoku.test.js`：校验终局两行的精确结构，确认进行中格式兼容。
- 五子棋 design/spec/usage、todo、changelog 与服务包状态。

## 自测、兼容性与性能

运行 `npm run test:game-chat`；测试 User 胜、AI 胜、进行中落子及状态查询。桥接层用权威快照识别终局，不依赖 GM 落子行的尾部胜负字段；显示端使用结构化增量，继续获得完整 result。此变更只缩短终局文本回执，不增加请求或存储。

## 风险与预计工时

外部若自行按固定字段数解析终局 GM 文本，需要同时接受新短格式；项目内检索未发现此类依赖。GM 快照格式本次不改。预计约一小时。

## 执行结果

`npm run test:game-chat` 37/37 通过。隔离真实 Qwen `aasc-qwen-flash` 和“小爱”角色分别复测用户 E2 连五及 AI E9 连五：用户胜权威版本 10，模型收到 `GM,落子,03a7,10,User,E2` 与 `GM,状态,03a7,10,9,User胜`；AI 胜权威版本 11，模型收到 `GM,落子,3c26,11,AI,E9` 与 `GM,状态,3c26,11,9,AI胜`。两盘各两次模型请求，均正确识别胜方并追加终局答复。测试使用临时棋局和聊天运行目录，结束后清理；真实显示端与 TTS 尚未验收。
