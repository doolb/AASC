# 本地 LLM 网关复用通用实例流程

## 任务描述

本地 LLM 网关点击“创建实例”时复用既有内置服务任务流程，支持选择不同运行目标和目标设备，不增加 LLM 专用实例处理。

## design 需求

- `llm-server` 作为常驻内置服务任务保留。
- 服务型内置任务从任务卡创建时进入通用实例配置页。
- 目标设备、实例提交、运行、停止、恢复和日志使用现有任务引擎。
- 服务实例按现有 `taskName + target + displayId` 规则隔离。

## spec 设计

```text
点击 llm-server 创建实例
  -> 通用内置任务配置页
  -> 选择 server/display/subdisplay 和目标设备
  -> task:submit 创建 draft
  -> 现有任务引擎启动/停止/恢复服务
```

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/js/task-panel.js`：服务型内置任务统一打开通用配置页。
- `src/apps/server/modules/task-engine/builtin-tasks/llm-server.js`：保持服务实现和网关上下文，不增加创建特例。
- `tests/task-panel-llm-server.test.js`：验证服务任务入口和通用目标字段。
- `docs/design/android-mnnchat-llm.md`、`docs/spec/android-mnnchat-llm.md`、`docs/todo.md`、`changelog.md`。

## 自测用例

1. `llm-server` 点击创建实例打开通用配置页。
2. 选择服务端创建实例，实例进入标准 draft/running 生命周期。
3. 选择显示端或子显示端时保留 displayId 并使用标准任务转发链路。
4. 不同 displayId 创建的服务实例互不覆盖。
5. 现有其他内置任务创建流程保持不变。

## 兼容性测试

- 控制端既有一次性内置任务和视觉任务入口不变。
- 服务端任务引擎现有 `server`、`display`、`subdisplay` 目标不变。
- `llm-server` 运行时仍通过 `context.llmGatewayService` 获取网关。

## 性能测试

- 创建实例不增加模型下载或推理操作。
- 仅改变前端入口，任务提交和服务启动开销保持现有水平。

## 风险评估

- 风险：服务型任务进入配置页后，用户可能选择网关实现未部署的显示端目标。
- 控制：由通用任务执行链路返回标准失败状态；不增加 LLM 专用绕过逻辑。

## 实施结果

- 已将任务面板的服务型内置任务统一导入通用配置页。
- `llm-server` 未增加任务名专用判断，继续由任务元数据和任务引擎处理。
- 已验证服务模式、视觉内置任务和任务链接相关前端契约不受影响。
