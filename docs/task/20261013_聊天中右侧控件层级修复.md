# 任务：聊天中右侧控件层级修复

## 任务描述

显示端聊天打开时，右侧灯光、动作和定位按钮仍高于聊天界面，会覆盖消息或输入区域。让交互层在聊天打开期间退到聊天层下方，聊天关闭后恢复原有层级。

## Design 需求

- 复用现有 `body.display-chat-open` 状态，不新增开关、消息或配置。
- 聊天打开时交互层使用低于聊天层的层级；聊天位于 MMD 上方时聊天层为 15，默认层序时为 20，交互层为 14。
- 聊天关闭时交互层恢复现有层级 50，保证灯光/动作/定位入口继续正常操作。
- 保留设置面板展开时的舞台层级、面板定位、聊天与 MMD 上下顺序及聊天关闭按钮行为。

## Spec 伪代码

```text
过程 setChatVisible(visible)
  state.chatVisible = visible
  更新 chatLayer 可见性
  如果 visible
    设置 body.display-chat-open
    interactionLayer.zIndex = 14
    确保 interactionLayer 低于 chatLayer（zIndex 为 15 或 20）
  否则
    移除 body.display-chat-open
    interactionLayer.zIndex 恢复为 50
  不改变 MMD/聊天层序或媒体播放状态
```

- `tests/display-chat-opening-browser.test.js`：检查聊天层序、输入命中及关闭后按钮恢复。
- `docs/design/display-chat-mmd.md`、`docs/spec/display-chat-mmd.md`：记录设计规则与伪代码。

## 自测用例

1. 默认聊天层序下，聊天打开时交互层低于聊天层，聊天输入与灯光按钮所在点由聊天控件接收。
2. MMD 置于聊天上方时，聊天仍高于交互层，聊天输入命中有效。
3. 两种层序关闭聊天后，交互层恢复到 50，灯光按钮再次接收点击。
4. 运行显示端聊天/MMD 定向浏览器测试和 `git diff --check`。

## 兼容性

- 继续使用 `DisplayStage.setChatVisible` 已维护的页面状态类，旧服务端和 WebSocket 协议不变。
- 设置面板已经展开后再打开聊天时，聊天覆盖按钮组；关闭聊天后面板层级和展开状态按原样恢复。
- 不依赖 Android 原生能力，浏览器和 APK WebView 共用 CSS 行为。

## 性能

- 只增加一条基于既有 body 状态类的 CSS 层级规则；不增加定时器、DOM 重建、网络请求或逐帧工作。

## 风险评估

- 交互层中的舞台按钮在聊天打开期间均位于聊天下方，避免它们遮挡聊天；聊天自身的关闭按钮保持可操作。
- `display-chat-open` 由现有聊天显隐流程统一切换，关闭时移除类即可恢复默认层级。
- 低风险，影响仅限聊天显示期间的视觉层级与触摸命中。
