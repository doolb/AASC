# 2026-09-23 未启用声纹时处理 TTS 期间语音输入

## 任务描述

为有硬件回声抑制能力的设备增加可选开关：关闭声纹识别时，TTS 播放期间不再由服务端丢弃识别出的语音输入，使其能继续进入既有显示端语音会话/聊天处理链路。

## Design 需求

- 在控制端声纹设置中新增“声纹关闭时仍处理 TTS 期间语音”复选框。
- 新配置 `voiceprint.acceptVoiceInputDuringTtsWithoutVoiceprint` 默认 `false`，保持现有行为。
- 配置仅在 `voiceprint.enabled=false` 时影响播放期间的服务端 ASR 输入拦截。
- 既有 `pauseRecordingDuringPlayback` 保持独立；该项开启时显示端仍暂停采集，因此要接收 TTS 期间输入必须关闭它。
- 绕过 TTS 输入拦截后仍执行原有修复模式、唤醒词和显示端语音会话门控。
- 声纹启用时的未匹配说话人处理保持不变。

## Spec 设计

- `/api/voiceprint/config` GET 返回该布尔项，POST 校验并持久化。
- 默认缺失按 `false`；非法非布尔值返回 400，不修改已有配置。
- 服务端 ASR 音频流入口和统一 `processDisplayVoiceInput` 入口共用同一配置语义。
- 设置界面沿用现有声纹配置面板及接口，不新增配置读取/保存接口。

## 受影响功能模块与代码

- 控制端设置：`src/apps/web-mediacenter/ui/public/upload.html`、`src/apps/web-mediacenter/ui/public/js/voiceprint-panel.js`
- 配置默认值与 API：`src/apps/server/modules/config/config-app-service.js`、`src/apps/server/boot/server-app.js`
- 文档：对应 ASR/语音输入 design/spec、全局播放录音 spec、`docs/todo.md`、`changelog.md`、语音会话使用说明

## 自测用例

1. 配置缺失或关闭，声纹关闭且 TTS 播放中：识别结果按现有规则忽略。
2. 开关打开、声纹关闭、播放时暂停录音关闭：TTS 期间识别结果继续进入原有会话/唤醒门控。
3. 播放时暂停录音开启：显示端仍暂停普通 ASR 录音，新开关不改变本地采集行为。
4. 声纹开启且 `speaker=null`：即使新开关打开，仍不触发唤醒、聊天或命令。
5. 新语音进入同一聊天会话：由现有聊天请求逻辑停止该会话的旧 TTS。
6. POST 非布尔配置：返回 400 且不覆盖已保存值。

## 兼容性

- 旧配置文件没有新字段时按 `false` 读取，原有 TTS 回声拦截行为不变。
- 旧控制端不提交新字段时，服务端保留已保存值；旧显示端不需要新增消息字段。
- 声纹开启、单次/实时录音以及 TTS 播放队列协议保持既有行为。

## 性能与风险

- 不增加 ASR/TTS 并发、采集通道或消息轮询；只在现有结果拦截条件读取一个配置值。
- 设备回声抑制能力不同；硬件未有效消除 TTS 回声时，误识别可能触发语音指令或聊天，因此默认关闭并由用户显式开启。
- 该开关是服务端全局配置；启用后所有适用的显示端输入都沿用同一策略。
