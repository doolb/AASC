# Chat2API 模型映射优先级对齐原版

## 任务描述

修复 AASC 内置 Chat2API 在指定 Provider 的自定义模型映射场景下，负载均衡器先返回请求模型、覆盖全局 `actualModel` 的问题。目标是与原版 Chat2API 一致：候选账号选择阶段即完成模型映射，Provider adapter 收到的模型必须是最终实际模型。

## design 需求

- Provider 内置模型映射优先于全局模型映射。
- 没有 Provider 内置映射时使用全局精确或通配符映射。
- 没有任何映射时保留原始请求模型。
- 指定 Provider 的用户自定义模型仍允许进入候选账号，但最终请求使用映射后的实际模型。
- 账号筛选和最终 Provider 请求必须使用同一个 `actualModel`。

## spec 设计

- `createChat2ApiLoadBalancer` 接收统一 `modelMapper`。
- `availableCandidates` 为每个候选 Provider 调用 `modelMapper.resolveModel(requestedModel, provider)`。
- 候选记录中的 `actualModel` 使用解析结果；核心适配层继续透传该值到 Provider adapter。
- 没有注入 modelMapper 的独立测试/兼容调用保留本地映射回退逻辑。

## 受影响的功能模块和代码

- `src/apps/server/modules/chat2api/chat2api-load-balancer.js`：候选账号的 actualModel 解析。
- `src/apps/server/modules/chat2api/chat2api-runtime.js`：将 modelMapper 注入负载均衡器。
- `src/apps/server/modules/chat2api/chat2api-load-balancer.test.js`：新增自定义 Qwen 映射回归测试。
- `src/apps/server/modules/chat2api/chat2api-core-adapter.test.js`：验证核心将实际模型交给 adapter。
- `docs/design/chat2api-builtin-task.md`、`docs/spec/chat2api-builtin-task.md`、`docs/todo.md`、`changelog.md`：同步设计和变更记录。

## 自测用例

- `Qwen3.6-Flash` 指定 qwen Provider 时，候选 `actualModel` 为 `Qwen3.7`。
- Qwen adapter 最终请求体 `data.model` 为 `Qwen3.7`。
- Provider 内置映射仍优先于全局映射。
- 无映射请求仍使用原模型。
- 现有轮询、最低用量、故障转移和 Provider 支持性测试不回归。

## 兼容性测试

- 旧配置没有模型映射时行为不变。
- 自定义 Provider 和未注入 modelMapper 的单元测试继续可运行。
- Qwen、其他 Native Provider 和通用 OpenAI Provider 均继续接收字符串 actualModel。

## 性能测试

- 每次候选 Provider 只解析一次模型映射，不在 adapter 内重复覆盖。
- 映射读取继续复用现有数据存储，未增加网络请求。

## 风险评估

- Provider 内置映射与全局映射同时存在时优先级改变，需保留原版行为并用测试锁定。
- 模型映射数据损坏时沿用现有数据存储错误，不静默发送错误模型。
