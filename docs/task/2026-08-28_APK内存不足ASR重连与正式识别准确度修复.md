# APK 内存不足 ASR 重连与正式识别准确度修复

## 任务描述

修复正式 Display APK 在 ASR 模型加载内存不足时反复初始化、造成 WebSocket/页面不停重连的问题；同时解决正式 APK 普通 ASR 准确度低于独立测试 APK 的差异。用户未开启声纹时，验证范围只包含普通非流式 ASR。

## Design 需求

- 正常内存时仍按当前 CPU 核心数创建 recognizer；内存预算不足时自动回退为 1 个 recognizer。
- 单 recognizer 仍不足或构造时发生 OOM 时，释放已创建资源并停止自动重试，不关闭 WebSocket。
- 正式 APK 采集原始 PCM 并封装 WAV，避免 WebM/Opus 有损编码。
- 关闭浏览器层隐式 `echoCancellation`/`noiseSuppression`，GTCRN 仍由独立配置开关控制。

## Spec 设计

```text
启动 ASR:
  requestedSlots = CPU policy 的核心数
  memoryPlan = 按每 recognizer 预算计算 effectiveSlots
  内存足够 -> effectiveSlots=requestedSlots
  只够单实例 -> effectiveSlots=1
  单实例也不足 -> 返回 memory error

加载模型:
  构造 recognizer pool
  构造过程中 OOM -> 释放已构造 slot，保存内存错误状态

录音:
  APK -> AudioContext 原始 Float32 -> 16kHz mono -> WAV
  浏览器 -> 保留 MediaRecorder/WebM 兼容路径

内存错误:
  display.html 停止录音并上报 voiceRecognition=false
  后续普通 asrAudio 只返回错误，不再次调用 asrEnsureModel
```

## 受影响功能模块和代码

- `src/apps/android-display/app/src/main/java/com/aasc/display/AsrMemoryPolicy.kt`：可测试的内存预算与 slot 回退策略。
- `src/apps/android-display/app/src/main/java/com/aasc/display/AsrModelManager.kt`：加载前内存判断与不可自动重试错误状态。
- `src/apps/android-display/app/src/main/java/com/aasc/display/AsrEngine.kt`：按策略传入实际 slot 数并捕获 OOM。
- `src/apps/android-display/app/src/main/java/com/aasc/display/AsrEnginePool.kt`：部分构造失败时释放 native slot。
- `src/apps/android-display/app/src/main/java/com/aasc/display/NativeBridge.kt`：保持识别错误边界稳定。
- `src/apps/web-mediacenter/ui/public/display.html`：APK 原始 PCM/WAV 采集、浏览器音频处理参数、内存错误停止重试。
- `src/apps/android-display/app/src/test/`、`tests/`：内存策略、池释放、显示端音频契约测试。

## 自测用例

1. 内存充足时按 `1 大核 + 2 小核` 创建 3 个 recognizer。
2. 多 slot 预算不足时降级为一个 slot。
3. 第 N 个 recognizer 构造抛 OOM 时，前 N-1 个 slot 全部释放。
4. 内存错误状态下连续收到多个 ASR 请求，只返回错误，不重复调用模型加载。
5. 正式 APK 原始录音使用 16kHz mono WAV，普通浏览器仍可走 WebM。
6. `zh.wav`、`en.wav` 通过测试 APK 和正式 APK 识别，确认模型输出链路一致。
7. 真机内存不足场景下 APK 不反复重连，WebSocket 保持稳定。

## 兼容性测试

- 普通浏览器显示端继续兼容原有 MediaRecorder/WebM 路径。
- 旧版 Display APK 继续使用原有桥接兼容逻辑。
- 声纹关闭时不加载或调用声纹匹配路径。
- 服务端 ASR 模式不改变接口和结果格式。

## 性能测试

- 比较测试 APK 与正式 APK 的 `zh.wav`、`en.wav` 识别文本和耗时。
- 记录正式 APK 识别前后的 Native Heap/PSS。
- 验证内存充足时核心数并发仍存在，内存紧张时只降低 slot 数。

## 风险评估

- 原始 PCM 录音会增加 JS 侧短时 Float32 缓冲，但只保留当前语音段并在发送后释放。
- 浏览器不支持原始 PCM 采集时直接提示录音不可用，避免悄悄回退到有损 WebM。
- 单 slot 回退会降低并发 ASR 吞吐，但只在内存不足时发生。
- WebM 仍作为 `handleAsrAudio` 的兼容输入格式保留。

- ✅ [2026-08-28] APK 本地识别录音使用原始 PCM/WAV；普通浏览器和服务端路径同样使用 WAV。
