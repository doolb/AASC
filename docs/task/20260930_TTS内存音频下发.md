# TTS 内存音频下发

## 需求与范围

消除服务端下发的tts_*.wav临时文件，减少写盘/扫描/逐文件删除开销。用户已确认保留URL播放协议，把数据存放改为内存，并一起去掉Node子显示端audio_*.wav。开发已完成，待重启/发布和现场验收。

## 已核对链路

外部TTS在tts-service.js写盘；显示端回传在server-app.js统一fallback写盘。现有生成调用方主要取basename后构造URL，涵盖API、Agent、文本媒体、语音、聊天、报时/提醒。Node的URL和Buffer播放器均在播放前写临时WAV。

## 设计与规范

见docs/design/tts.md、docs/spec/tts.md同名2026-09-30章节。新增独立缓存模块和HTTP音频处理，TTL10分钟、缓存总量128MiB/1024条、单段16MiB；HTTP收集有限、只缓存完整成功音频、容量不足拒绝新增，不驱逐有效排队引用。现有随机音频URL可多次读取，HEAD/单段Range/断连按音频资源处理；重启后临时引用失效。

## 追加容量设置（已实现）

用户要求总上限先放开到128MiB并在控制端增加设置。默认128MiB、16–1024整数MiB；规范化规则由tts-audio-cache-config.js集中定义，配置getter与缓存复用。控制端upload.html/tts.js/websocket.js通过现有WebSocket发送、保存、广播和重连同步，server-app只接受控制端消息，config.set失败保持旧运行值。降低上限不驱逐有效引用，超过新上限时拒绝新增；部分tts.init不覆盖容量。无回包10秒解除等待，重连补发权威值。Android禁用外部TTS时也独立恢复缓存容量。

待现场验证：默认/边界/非法输入规范化、保存失败不改变容量、多控制端同步、重连/进程重启恢复；降低到已占容量以下不丢旧URL，过期后可继续生成，提高上限立即生效。未执行这些测试或实际播放。

## 受影响代码

- src/external/tts/tts-service.js：HTTP响应收集/入缓存、停止新WAV写盘。
- src/external/tts/tts-audio-cache.js与src/apps/server/modules/tts/tts-audio-http.js：Buffer、有效期、总量/条数/单段限制与GET/HEAD/Range。
- src/apps/server/boot/server-app.js：显示端回传入缓存、静态路由前内存音频响应。
- Node：src/apps/voice-display-node/audio-player.js，Linux/Windows标准输入播放，保持PCM/AEC、队列、打断及回执；macOS Buffer使用ffplay；显式文件afplay保持。下载可取消且有限，代次隔离旧结束，stop同步通知恢复录音；16位PCM/AEC按RIFF块读取并下混。
- release/offline-release-status.json的servicePackage已有true，保持待构建；没有新增npm生产依赖。

## 性能与风险

减少磁盘开销，缓存有总量和条数限制，在途响应/解码/发送另占内存；容量不足拒绝新增、长队列超出有效期及服务器重启造成旧URL失效需明确处理。此方案仍待完整合成后下发，不宣称首字延迟变短。上游TTS引擎内部文件输出另属其实现。
