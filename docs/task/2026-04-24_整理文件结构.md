# 任务记录：整理文件结构

## 任务描述

- 需求来源：用户提出“整理文件结构”。
- 目标：统一项目目录说明，消除 readme 中的旧结构残留，并将本次目录治理纳入 design/spec/changelog。

## Design 需求

1. 新增“工程目录结构”设计文档，描述根目录职责和治理规则。
2. 更新设计索引，保证模块可检索。
3. readme 的项目结构树对齐当前真实目录。

## Spec 设计

1. 新增“工程目录结构”实现文档（伪代码）。
2. 伪代码覆盖：目录职责定义、结构同步流程、文件归位校验、发布清单。
3. 更新实现索引，保证文档闭环。

## 影响模块与代码

- 文档索引：`docs/design.md`、`docs/spec.md`
- 设计文档：`docs/design/project-structure.md`（新增）
- 实现文档：`docs/spec/project-structure.md`（新增）
- 项目说明：`readme.md`
- 任务状态：`docs/todo.md`
- 变更日志：`changelog.md`

## 自测用例

1. 检查 `readme.md` 项目结构树是否包含 `aasc/`、`auto-brain/`、`res/`、`src/`、`voice-display*`。
2. 检查 `docs/design.md` 是否存在 `project-structure.md` 索引项。
3. 检查 `docs/spec.md` 是否存在 `project-structure.md` 索引项。
4. 检查 `docs/design/project-structure.md` 与 `docs/spec/project-structure.md` 可正常打开。

## 兼容性测试

- 仅文档变更，不影响运行时接口与协议。

## 性能测试

- 无运行时代码变更，无额外性能影响。

## 风险评估

1. 风险：结构文档与未来目录变化不同步。
2. 缓解：将结构同步流程写入 spec 并纳入发布清单。

## 预计工时

- 0.5 人时（文档整理与索引同步）。

## 不明确需求记录

- 初始阶段先完成“结构说明与索引治理”；随后根据用户确认，继续执行实际目录迁移。
