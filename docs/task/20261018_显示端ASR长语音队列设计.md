# 显示端 ASR 长语音队列设计

日期：2026-10-18；状态：等待用户确认阈值与队列容量，尚未实现。

## 任务描述与设计需求

显示端语音经 `/api/asr/recognize` 转发到所选 ASR 显示端。多个长录音当前可并发进入 Android 的 `AsrEnginePool`，占用全部推理槽位。目标是按真实音频时长分流，同一识别显示端每次仅下发一个长录音，短录音继续沿用原并发路径。详见 `docs/design/server-side-asr-voice-input-processing.md`。

## Spec 伪代码与受影响模块

见 `docs/spec/server-side-asr-voice-input-processing.md`。拟在 `src/apps/server/boot/server-app.js` 的显示端 ASR 分支调用独立的长语音队列模块，长任务按目标 displayId FIFO 串行，在实际下发后启动原 60 秒响应计时；短任务直通。拟补 `tests/` 下队列与路由测试，并同步文档与 `release/offline-release-status.json` 的 `servicePackage=true`。无需 Android 原生修改或 min APK。

## 自测、兼容性与性能

计划覆盖真实 WAV 时长边界、同目标长任务串行、不同目标独立、短任务不等待、HTTP 断连移除、失败/超时释放及队列满错误。ASR 文本、声纹分段、requestId、业务来源与回显格式继续使用现有契约。长任务等待增加响应时延，需观察设备 ASR 槽位占用与短语音延迟。

## 风险评估、待确认项与工时

需求主层级为 L5 调度规则，次层级为 L6 转发契约；建议下放 L4 为时长分类、按显示端入队、释放及结果传播。直接风险中等，关键断点是“长”的时长阈值和等待容量。候选值为 ≥10 秒、每目标最多等待 8 条；另一候选为 ≥15 秒。容量满拟明确返回繁忙。待用户确认后实施，预计开发和定向验证约 3 小时。
