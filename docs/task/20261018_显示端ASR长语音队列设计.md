# 显示端 ASR 长语音队列设计

日期：2026-10-18；状态：源码与定向测试完成，待设备验收。

## 任务描述与设计需求

显示端语音经 `/api/asr/recognize` 转发到所选 ASR 显示端。多个长录音原先可并发进入 Android 的 `AsrEnginePool`，占用全部推理槽位。现按真实音频时长分流：阈值默认 10 秒，可设置 1–120 秒；每目标长任务并发默认 1，可设置 1–8；短录音继续直通。每目标最多等待 8 条。详见 `docs/design/server-side-asr-voice-input-processing.md`。

## Spec 伪代码与受影响模块

见 `docs/spec/server-side-asr-voice-input-processing.md`。`src/apps/server/modules/asr/display-asr-long-queue.js` 负责时长解析、FIFO 准入及远端配置校验；`server-app.js` 在显示端 ASR 分支调用它，并在控制端 WebSocket 初始化时发送权威配置。`upload.html`、`tts.js`、`websocket.js` 增加设置与同步。测试覆盖队列和真实浏览器消息路由。`servicePackage=true` 已标记；无需 Android 原生修改或 min APK。

## 自测、兼容性与性能

定向测试覆盖真实 WAV 时长边界、同目标长任务串行、不同目标独立、等待取消、失败释放、运行时并发变化、队列满、配置保存失败回退和浏览器重连回显。ASR 文本、声纹分段、requestId、业务来源与回显格式继续使用现有契约。真机需观察多条长录音与短语音并发时的槽位占用、响应时延及断线恢复。

## 风险评估、待确认项与工时

需求主层级为 L5 调度规则，次层级为 L6 转发契约；落地为时长分类、按显示端入队、释放及结果传播。直接风险中等：长任务排队会增加端到端延迟，等待 8 条后返回 HTTP 503；WAV 和时间戳均无效时仍直通。预计开发和定向验证约 3 小时；当前离线验证通过，现场负载与真机效果待验收。
