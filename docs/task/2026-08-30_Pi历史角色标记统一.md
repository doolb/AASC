# 任务：Pi 历史角色标记统一

## 任务描述

统一 Pi Agent 续聊消息和历史重建文本中的用户/助手标记，避免 `User:`、`AI:`、`Assistant:` 与裸文本混用。

## Design 需求

- Pi 内部继续使用原生 `user`/`assistant` 角色。
- 每次续聊发给 Pi 的用户文本统一以 `User:` 开头。
- 重建历史使用 `User:` 和 `Assistant:`，不再使用 `AI:`。
- 不把 `AI:` 拼入助手真实回复内容。

## Spec 设计

- `PiRuntimeManager` 续聊分支对 `continuationPrompt` 做幂等 `User:` 前缀处理。
- `llm-service` 的历史重建序列化把助手标记输出为 `Assistant:`。

## 受影响的功能模块和代码

- `src/apps/server/modules/chat/pi-runtime-manager.js`
- `src/external/llm/llm-service.js`
- `src/apps/server/modules/chat/pi-runtime-manager.test.js`
- `src/external/llm/llm-service.test.js`
- `docs/design/llm-agent-mode.md`
- `docs/spec/llm-agent-mode.md`

## 自测用例

- 首次初始化历史保留 `User:`/`Assistant:` 成对标记。
- 第二次及后续 Pi RPC 消息以 `User:` 开头。
- 已带 `User:` 的消息不会重复添加前缀。
- Pi 内部助手消息仍按 `assistant` 角色提取。

## 兼容性测试

- 普通 LLM 的 OpenAI 消息结构不变。
- Pi 工具调用、错误处理和会话隔离不变。
- 旧历史中的 `AI:` 仅在重新初始化时按新规则输出，不修改原始历史文件。

## 性能测试

- 每条续聊消息只增加固定长度前缀，不复制历史。

## 风险评估

- 上游模型若依赖旧 `AI:` 文本标记，改用 Pi 标准 `Assistant:` 后需要回归确认；Pi 内部角色和工具链不受影响。
