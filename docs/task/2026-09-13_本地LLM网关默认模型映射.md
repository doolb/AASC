# 本地 LLM 网关默认模型映射

## 任务描述

在控制端任务列表的“本地 LLM 网关”任务卡片新增“默认映射”配置按钮，弹出面板维护外部模型名到本地模型 `modelId` 的映射，并让网关读取该动态配置。

## Design 需求

- 配置属于主服务器 LLM 网关运行参数，使用现有 WebSocket 远端配置流程。
- 支持多条映射；外部模型名唯一，目标模型必须来自已发布模型清单。
- manifest 内置 `modelId`/alias 优先于动态默认映射。
- 服务端通过 `config.set('llm.defaultModelMappings', ...)` 持久化并广播规范化后的权威值。
- 服务端限制最多 64 条映射、单个外部名称和内部 ID 最长 256 个字符，避免异常消息阻塞配置写盘和广播。

## Spec 设计

- `LlmDefaultModelMapping { externalModelName, modelId }`。
- 控制端发送 `llm.defaultModelMappings.set`，服务端返回/广播 `llm.defaultModelMappings`。
- 空映射行删除；重复名称和未知 `modelId` 返回 `llm.defaultModelMappingsError`，不覆盖旧配置。
- 网关 `validateRequest` 先解析 manifest，再解析动态映射，后续保持 ready 和显示端路由校验。

## 受影响功能模块和代码

- 配置管理：增加 LLM 默认映射默认值和规范化保存入口。
- LLM 网关：读取动态映射并参与外部模型名解析。
- WebSocket 服务端：连接初始化、设置消息、权威广播和错误回包。
- 任务引擎：声明 LLM 任务卡片的专用映射按钮元数据。
- 控制端任务面板：映射弹窗、清单选项、保存/取消和广播刷新。
- 文档与测试：LLM design/spec/usage、任务文档、todo、changelog、路由与 UI 契约测试。

## 自测用例

1. 映射面板可打开、添加、删除和取消编辑。
2. 保存合法映射后，服务端广播去空格后的权威配置。
3. 空行被忽略，重复外部名和未知 `modelId` 被拒绝。
4. 网关使用动态映射将外部模型名转换为内部 `modelId` 后再路由。
5. manifest alias 与内部 `modelId` 仍优先，旧请求行为不变。

## 兼容性测试

- 无历史 `llm.defaultModelMappings` 时按空数组运行。
- 旧控制端忽略新增消息不影响模型选择和网关请求。
- 断线时不新增本地错误映射；重连后收到服务端当前配置。

## 性能测试

- 映射数量保持小规模，单次请求只增加一次动态映射线性查找，模型 ready 校验继续复用既有流程。
- 不增加模型下载、推理或显示端路由的额外网络请求。

## 风险评估

- 配置模型名与 manifest alias 冲突可能产生歧义，保存时拒绝冲突输入。
- 目标模型未 ready 时允许保存，但请求阶段仍返回现有模型不可用错误。
- 多控制端同时保存时以后到达的服务端规范化结果为最终权威状态。
