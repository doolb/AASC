# 显示端高 DPI 适配、本机模型入口和 MMD 显隐恢复

## 需求与等级

- L6 主需求：控制端隐藏 MMD 后，显示端断线重连仍按 `displayId` 恢复权威隐藏状态，并处理初始化时序和保存失败。
- L5 次需求：render-display 在高 DPI 屏幕缩小显示；Offline APK 的“本机模型”入口移动到左上角并避开安全区。
- L7 交付边界：网页/服务资源需要标记 `servicePackage=true`；本机模型入口属于 Offline APK 内显示资源，保持 `minApk=true`。不在本任务构建或发布 APK。
- 用户确认方案：render-display 根据 DPR 反向缩放并限制在可用视口；语速/音量/TTS配置不属于本任务。

## Design 需求

1. render-display 的文字、横条和间距按 `devicePixelRatio` 等比缩小，DPR=1 保持原大小；适配四向旋转、媒体名避让并约束实际包围盒。
2. Offline 原生能力存在时“本机模型”按钮固定在显示舞台左上角；遵守旋转映射安全区与软键盘内缩量；网页无本机模型能力时隐藏。
3. MMD 状态按 `displayId` 保存。只有 `config.set` 成功后才更新服务器内存和广播；显示舞台脚本就绪前到达的服务端权威状态需暂存并由舞台初始化消费。
4. 重连依旧由 WebSocket 初始化消息下发权威状态；缺少有效值时明确默认显示。

## 自测用例

1. DPR 1 和 DPR 2 下运行真实 render-display，比较缩放比例并检查 0/90/180/270 度避让及视口边界。
2. Offline 原生桥存在时按钮左上定位包含安全区；无桥时按钮隐藏；其他交互按钮仍处于原位置。
3. 服务端 MMD 隐藏写入成功后广播 false；保存失败时不广播成功状态且内存不变。
4. DisplayStage 加载前收到 false，初始化后仍保持隐藏；按 displayId 重连收到已保存的 false。
5. 运行相关 Node 测试和 render-display 冒烟、JavaScript 语法检查、`git diff --check`。

## 兼容性与性能

- DPR=1 和缺少 DPR 属性回退至 1；旋转仍使用现有显示舞台坐标与媒体名避让流程。
- 按钮继续复用 NativeDisplay 本机模型桥和现有控制事件，不新增接口或消息。
- MMD 持久化沿用 `config.updateDisplayStateById` 和 AASC WebSocket 初始化；无新增轮询或网络请求。
- UI 缩放只在布局/来源/旋转更新时计算，不加入逐帧循环。

## 风险与工时

- 风险：CSS 变换会影响旋转包围盒；通过真实 Chromium DPR 1/2 四向回归验证。
- 风险：异步保存失败路径须保持显示端和控制端状态一致；严格保存后才更新内存/广播。
- 预计工时：实现 2–3 小时，回归与文档 1–2 小时，合计 3–5 小时。
