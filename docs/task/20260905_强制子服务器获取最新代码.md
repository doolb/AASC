# 强制子服务器获取最新代码

## 任务描述

在控制端“服务端”设置中增加一个手动按钮，强制所有在线子服务器从主服务器重新获取最新代码。主服务器和子服务器继续使用主动 WebSocket 连接；子服务器继续采用启动器进程、服务进程和一次性 Bootstrap 三者分工，不实现权限认证、自动发现或自动更新。

## design 需求

- 新增 `POST /api/aasc/servers/force-update-all`。
- 只筛选非主服务器、在线且已有主动 WebSocket 连接的节点。
- 通过 `server.update` 携带 `force=true` 下发。
- Bootstrap 强制模式为清单和代码包请求增加缓存绕过参数。
- 保留现有大小、SHA-256、路径白名单、健康检查和失败回滚。

## spec 设计

```text
控制端点击按钮
    → 二次确认
    → POST /api/aasc/servers/force-update-all
    → 主服务器并发发送 server.update({ force: true })
    → 子服务器返回 accepted 并启动 Bootstrap update --force
    → Bootstrap 重新获取并校验代码包
    → 停止服务、备份、替换、启动、健康检查
    → 失败时恢复旧代码
    → 控制端显示批量结果
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：批量强制更新接口、节点请求载荷、Bootstrap 参数。
- `scripts/termux/aasc-server-bootstrap.cjs`：解析 `--force` 并绕过清单/代码包缓存。
- `src/apps/web-mediacenter/ui/public/upload.html`：增加按钮和请求处理。
- `tests/server-api-contract.test.js`、`tests/subserver-update-ui.test.js`、`tests/termux-server-bootstrap.test.js`：契约、界面和 Bootstrap 行为测试。

## 自测用例

1. 控制端显示“强制获取最新代码”按钮并调用正确接口。
2. 主服务器只向在线、已连接、非主服务器下发 `force=true`。
3. Bootstrap 能解析 `--force`，并为清单与代码包 URL 增加一次性参数。
4. 强制更新仍执行校验、重启、健康检查和回滚。
5. 无在线子服务器、部分失败和全部接受均返回可见汇总。

## 兼容性测试

- 普通 `server.update` 行为保持不变。
- 普通 `update-all` 接口行为保持不变。
- Termux Node.js 与主服务器现有双进程启动模型兼容。

## 性能测试

- 批量下发仍使用 `Promise.all` 并发请求。
- 强制更新不增加常驻内存进程，仅增加一次代码包下载。

## 风险评估

- 强制更新会在版本号未变时重启子服务器，按钮必须二次确认。
- 代码包下载失败或校验失败时不得停止当前服务。
- 主服务器当前 `/server` 暂无权限认证，仍属于局域网测试边界。
