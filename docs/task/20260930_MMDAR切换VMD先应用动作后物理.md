# MMD AR 手动切换 VMD 先应用动作后物理

- 状态：已完成，网页已生成，未发布。
- 需求：手动选择 VMD 切换动作时，先关闭物理，应用新动作后再开启物理。
- design：独立网页的本地/默认动作替换使用同一切换流程；解析失败保留旧角色和动作。
- spec：见 `docs/spec/mmd-ar-test-apk.md` 的同日新增方案。先解析 clip，再暂停物理、无物理应用第0帧、更新骨骼世界矩阵，根据原物理开关初始化新物理，最后提交新 helper。
- 代码范围：`3rd/mmd-ar-test/web-local-assets-inject.js`，新增 `web-motion-switch.mjs` 与 `tests/mmd-ar-motion-switch.test.js` 定向用例；更新 `build.js` 复制和指纹依赖。
- 已确认：原物理开关关闭时保持关闭；原动作暂停时应用新动作初始姿态后保持暂停；此功能不改变正式显示端或模型首载逻辑。
- 自测：顺序严格先姿态再物理，物理/播放原开关保留，损坏VMD/失败回滚，过期结果不覆盖新模型，本地模型和默认模型都可换动作，动作与原旋转物理保护兼容。
- 兼容与性能：保留模型资源路径、灯光、定位、重力和手动变换；仅切换动作时应用一次第0帧，不执行长时间物理预热；真实布料观感待现场验证。
- 风险：新旧 helper 共用网格，必须避免在途帧推进或失败污染旧骨骼姿态；物理恢复需从新姿态初始化，而不是继续旧刚体位置/速度。
- 预计工时：约1小时，额外现场验收。

- 需求明确性：用户已确认切换顺序及关闭/暂停保持、失败保留，边界明确。enterprise 默认评审：主 L5（解析→暂停→应用→恢复流程，强证据6），次 L6（动作与物理契约、失败保留，中证据2）；置信度6/8×0.90=0.675；23/25、18/20、18/20、18/20、14/15，总分91，可开发，中风险。建议下放至L4；序号、帧门控和姿态回滚已写入 spec。后续技能 ai-code-translation / project-pseudocode-sync / 仅保留可选；当前按已确认任务开发，不自动调用其他技能。

- 实施结果：解析完成后冻结当前网格的 helper 帧，旧物理暂停；恢复绑定姿态/表情，新 helper 无物理应用第0帧并更新矩阵，再使用同一 helper 的固定 vendor 初始化物理（无预热/重复初帧）。失败或过期清理暂存动作，仅旧 helper 与网格仍属于当前模型时恢复姿态；保留原物理与播放开关。
- 验证结果：定向6/6通过，含固定 vendor 的真实动画 mixer 与 Ammo 初始刚体位置；真实网页本地资源扩展回归3/3通过，手动VMD与恢复默认动作均先姿态后物理。重力6/6、既有PMX/helper/物理40/40通过。网页构建、静态语法和定向差异空白检查通过；真机视觉与性能待现场验收。
