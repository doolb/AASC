# 任务：显示端透明背景与服务启动修复

## 任务描述

修复主题同步后显示端连接状态、天气弹窗和文本背景透底的问题，并修复服务端配置模块导出未定义主题函数导致的启动崩溃。

## Design 需求

- 配置服务模块必须能正常加载，并正确导出 `normalizeControlTheme`。
- 显示端连接状态、文本媒体、语音提示、任务状态和天气/语音弹窗使用不透明主题表面。
- 不改变图片、视频、iframe 网页内容和主题同步协议。

## Spec 设计

- `config-app-service.js` 从同目录 `control-theme-config.js` 引入 `normalizeControlTheme` 后再导出。
- 显示端 UI 表面使用各主题均为不透明颜色的 `--bg-secondary`。
- 深色主题仍可使用 `--bg-surface-strong` 作为控制端组件变量，但显示端不直接依赖其透明值。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/css/display.css`

## 自测用例

1. 直接加载配置服务模块不抛出 `ReferenceError`。
2. 配置服务模块导出的主题规范化函数可正常处理合法和非法主题。
3. 连接状态、文本媒体和天气弹窗背景使用不透明主题变量。
4. 图片、视频和 iframe 不增加滤镜或主题覆盖。

实际结果：配置服务、主题同步、显示端旋转/播放恢复和文本媒体相关回归 45/45 通过；`node --check` 与 `git diff --check` 通过。

## 兼容性测试

- 保持 15 种主题白名单和控制端主题接口不变。
- 保持显示端 WebSocket 主题通知、旋转弹窗和媒体播放逻辑不变。
- 兼容旧配置文件和旧显示端资源。

## 性能测试

- 修复只涉及模块加载引用和 CSS 变量，不增加请求、轮询或运行时计算。

## 风险评估

- 显示端深色主题弹窗由半透明叠加改为不透明主题表面，视觉层级更稳定，但不再透出媒体背景。
- 配置服务新增静态模块引用，无循环依赖；主题白名单仍由独立模块维护。
