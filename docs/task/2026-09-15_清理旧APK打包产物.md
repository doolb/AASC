# 清理旧 APK 打包产物

## 任务描述

清理旧 APK 打包方式生成的 Runtime、APK 和服务器运行包临时目录，并将部署入口切换到新的 Release profile 输出路径。

## 设计需求

- 新构建输出使用 `release/apkbuild/<profile>/output/`。
- `upload:apk` 使用 `release/apkbuild/withserver/output/aasc-display.apk`。
- 删除旧的 `src/apps/android-display/app/build/` 和根目录 `build/android-node-package*` 生成物。
- 保留 `release/apkbuild/`、`build/third_party/MNN`、源码、模型和任务结果。

## Spec 设计

```text
updateApkDeployPath:
    APK = release/apkbuild/withserver/output/aasc-display.apk
    禁止引用 src/apps/android-display/app/build/outputs/apk

cleanupLegacyApkArtifacts:
    删除已确认的 app/build 生成目录
    删除 build/android-node-package* 临时目录
    保留 Release profile 输入和第三方 MNN 目录
```

## 受影响的功能模块和代码

- `scripts/ops/apk-deploy.js`
- `tests/script-layout.test.js`
- Release profile design/spec 文档
- 旧 APK/Node package 生成目录

## 自测与风险

- 静态验证部署脚本只引用 Release profile 输出。
- 删除目标均为未跟踪生成目录，不涉及 Git 文件、模型和任务结果。
- 删除后旧版 Gradle 默认目录需要重新构建才会产生；新构建使用 profile 独立目录。

## 执行结果

- 已将旧 `src/apps/android-display/app/build/` 和 10 个 `build/android-node-package*` 目录移入系统回收站。
- `release/apkbuild/` 和 `build/third_party/MNN` 保持不变；清理目标均已从工作区消失。
- 工作区 `build/` 当前仍保留第三方 MNN 等其他构建内容，约 1.6G。
- `apk-deploy.js` 已切换到 `release/apkbuild/withserver/output/aasc-display.apk`，避免新构建后继续寻找旧路径。
