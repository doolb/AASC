# 应用层 TTS 长文本分段与混合代码输入

日期：2026-10-18。状态：源码与定向测试完成，待 Android 真机验收。

## 任务描述和 Design 需求

现场两次“今天天气怎么样”把约 1036 字的完整天气详情作为单次显示端离线 TTS 输入，均返回 SDK `80048028`。用户明确要求保留完整天气详情并分段播报，同时覆盖天气、提醒、聊天、手动朗读等所有播报入口。现有共享分句器只有标点/逗号边界，没有单段长度上限；部分语音命令和提醒直接调用单次生成。另有 ASR `A一。` 因仅一个汉字被屏蔽；用户确认要保留原文通过。

## Spec 设计与受影响模块

1. `src/core/utils/sentence-splitter.js`：在现有句子规则上增加有界分段；无标点长段也必须拆开，不截断正文，不切开 Unicode 代理对。聊天、手动朗读、文本媒体及已有帮助分句可共用这一规则。
2. `src/apps/server/boot/server-app.js`：语音命令控制端/显示端回调、搜索和系统播报等直接生成入口复用分段及既有播放队列，保持顺序、批次完成和停止语义。
3. `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：天气控制端与显示端都提交完整详情，详情展示仍为同一完整文本。
4. `src/apps/web-mediacenter/modules/reminder/reminder-app-service.js`：提醒内容按段生成并用现有显示端队列播报。
5. `src/apps/server/boot/server-app.js` 的 `hasValidContent`：仅放行紧凑字母与中文数字混合短代码，保留 ASR 原文。

先更新 `docs/spec/tts.md`、`docs/spec/display-voice-conversation.md`、`docs/spec/sherpa-asr.md` 的伪代码，再更新运行代码。独立 `/api/tts/generate` 保持单 URL 协议，播报流程在应用层拆分。

## 需求分级与实施记录

按 `analyze-requirement-level` 的 enterprise 口径，主等级 L6（跨天气、提醒、聊天和手动朗读的输入/输出约束），次等级 L5（分句、队列、取消顺序），需下放到 L4 伪代码。证据为“所有播报入口”“完整天气详情分段播报”“A一保留原文”三项已确认边界；直接开发风险中，主要在旧入口漏分段及停止后继续下发。L4 拆解已写入三份 spec：已有声明为 `splitIntoSentences`、`generateTtsWithFallback`、`hasValidContent`；新增定义为有界分段和语音命令取消会话；操作流程为按边界分段、逐段生成入队、停止检查与原文放行。源码完成后，定向语音测试 39/39、现有 TTS 脚本 23/23 通过；真机 `80048028` 根因仍未证实。

## 自测、兼容性和性能

- 分句测试：超过上限的无标点中文、英文、emoji及完整天气文本均逐段覆盖原文，段长有界，原顺序不变。
- 播报测试：天气完整详情、提醒、聊天和手动朗读逐段生成、播放队列顺序、停止与批次结束；短文本保持原行为。
- ASR 测试：`A一。` 和类似混合代码原样通过；`A中。`、单汉字、纯英文短噪声和纯数字继续过滤。
- 性能：控制单段输入降低 Embedded SDK 单次负担；长文增加生成次数，沿用现有顺序队列和取消机制，避免无界并发。
