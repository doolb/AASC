# HMR2.0b 单模型三图骨骼测试

日期：2026-10-16。状态：已完成独立测试；质量未达到接入VAM的要求。

## 任务描述与设计

用户把原先HMR2.0b/SAM 3D Body双模型对照收窄为只看HMR2.0b。在本机以同一真人坐姿、二次元和交叉腿示意图及固定人工人物框检查BODY25、相机投影、左右腿归属、遮挡和脚掌方向；浏览器只展示结果，正式MediaPipe全身IK不变。需求见`docs/design/mmd-human-interface.md`。

## 实现伪代码与受影响文件

伪代码见`docs/spec/mmd-human-interface.md`。独立临时实现位于忽略目录`tmp/mmd-pose/depth-eval/hmr2-sam3d/`：`audit.py`检查官方权重/三图，`run-hmr2.py`严格加载checkpoint的ViT、SMPL head与SMPL层张量，按官方`smplx.lbs`、顶点关节选择与BODY25映射输出3D和原图投影，`report.html`/`report.mjs`只展示HMR，`check-report.cjs`用Edge验证真实JSON、绘图和手机宽度。同步`docs/usage/mmd-pose-model-testing.md`、`docs/spec/self-test.md`、`docs/todo.md`与`changelog.md`。不改生产Worker、UI、骨骼或发布配置。

## 自测用例、兼容与性能

三张原图和人工框尺寸/SHA审计；官方checkpoint长度/SHA、网络权重严格加载及SMPL张量形状、BODY25映射检查；三图须保存有限的XYZ、相机和原图XY。Edge读取真实结果、叠图和3D绘制，检查390px无溢出及仅本机GET。Windows Python3.10 CPU环境实跑，不把Python环境或浏览器报告误称为手机本地推理。记录模型加载、逐图前向耗时与进程峰值工作集。质量以用户确认的坐姿“抬高膝属于人物左腿”为重点人工核对；无人工真值的动漫和示意图只做视觉观察。

## 风险评估与预计工时

官方checkpoint虽未随包提供单独SMPL中性模型文件，却包含SMPL层所需`shapedirs`、`v_template`、`J_regressor`、`posedirs`、`parents`、`lbs_weights`和BODY25映射。只在本机调用官方依赖`smplx.lbs`重建，不分发权重或模型张量。由于没有用独立SMPL文件运行整套`HMR2`包装类，不能声称逐字调用了原版`load_hmr2`；网络及SMPL计算路径与其源代码对应。ViT-H checkpoint约2.7GB，6GB显存环境选择CPU，浏览器/手机端推理尚未论证。预计数小时，实际已完成。

## 实测结果

官方4D-Humans源码提交`efe18deff163b29dff87ddbd575fa29b716a356c`；Windows本地仅对缓存路径和OpenGL默认平台做适配并记录补丁SHA。三图真实推理通过；第一次实测单图约0.7–1.1秒，带进程峰值记录的复测约1.5–2.0秒，模型加载约6.1秒，CPU峰值工作集约5.9GiB。Edge三图真实结果、叠图和XYZ画布通过，390px无横向溢出、无脚本错误、只发本机GET。

真人坐姿结果未满足目标：模型右膝投影约(179.6,172.2)，左膝约(209.8,191.2)；可见抬高膝更接近右膝，而用户确认它属于人物左腿，左脚投影还超出236px原图宽度。动漫手/脚和交叉腿示意图末端也存在偏差。由于左右腿归属未可靠解决，保留HMR2.0b独立报告，不接入VAM，也不替换MediaPipe默认。报告为`http://127.0.0.1:56173/_depth/hmr2-sam3d/report.html?image=seated`；私人图片、模型、JSON和截图均在忽略目录，不上传Git。
