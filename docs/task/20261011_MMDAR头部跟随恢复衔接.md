## 需求分析

analyze-requirement-level enterprise模式，主等级L5（动作释放后恢复跟随流程）、次等级L4（姿态状态和插值），建议下放到L4，能力等级L4。证据：用户明确先优化恢复；用户指出恢复转到跟随位置过快；现有代码动作完全占用后将yaw/pitch清零重新缓动，混合器默认动作淡出仅120ms、stop立即移除请求。恢复的实际显示姿态没有独立连续过渡。

两条L5强证据权重6，L4中证据权重2，一致性系数0.9，置信度0.675。结论：恢复方向可开发，600ms时长与具体文件方案已确认。评分：清晰度23/25、证据17/20、完备度16/20、风险17/20、L4落地13/15，共86/100。风险中：自然淡出与停止路径需统一，后续动作接管不能误启动旧恢复，基础骨骼保存不能累积注视贡献。

## design与spec

对应docs/design/mmd-human-interface.md、docs/spec/mmd-human-interface.md新增恢复章节。已有声明为Human旋转占用、gaze头部状态、headMs和目标；新增HeadRecovery持有显示姿态、动作身份及恢复时间。流程为动作释放 → 保存显示起点 → 约600ms平滑四元数回归当前跟随终点 → 普通跟随。目标动态更新，恢复只起计时一次；新动作接管取消旧恢复。

## 自测与兼容性

- 相机跟随 → 头部动作 → 自然结束；动作中手动停止；淡出阶段返回跟随。
- 恢复途中新动作接管，连续动作替换/不同owner，不误恢复到旧目标。
- 30/60/120fps、零delta、卡顿间隔，首恢复帧无可见角度跳变，计时不重复重启。
- 相机和临时点击目标变化，headMs普通跟随仍保持原速度；眼球/手动眼球、口型、物理不变。
- 模型切换、后台/隐藏/编辑/销毁不残留上个姿态；不增加RAF或timer。
