# 任务：配置模块迁移到 App 层

## 任务描述

- 目标：将配置模块从 Core 层迁移到 server App 层，明确配置属于应用装配能力
- 范围：迁移模块文件路径并修正引用，不改变配置 API 语义

## Design 需求

- 新路径使用 `src/apps/server/modules/config/config-app-service.js`
- `server-app` 与 `framework/aasc/agents` 统一依赖新路径
- Core 层不再承载应用配置模块

## Spec 设计（伪代码）

```
迁移 config 模块:
    oldPath = src/core/config/config.js
    newPath = src/apps/server/modules/config/config-app-service.js

替换引用:
    server-app.js -> require('../modules/config/config-app-service')
    framework/aasc/agents/index.js -> require('../../../apps/server/modules/config/config-app-service')

保持导出契约:
    get/set/getTtsConfig/setTtsConfig/getDisplayState...
```

## 受影响模块与代码

- `src/apps/server/modules/config/config-app-service.js`（新增）
- `src/core/config/config.js`（删除）
- `src/apps/server/boot/server-app.js`
- `src/framework/aasc/agents/index.js`
- `docs/spec/config.md`
- `docs/design/layered-architecture.md`
- `docs/spec/layered-architecture.md`

## 自测用例

- 用例1：服务端启动读取配置
  - 预期：`/api/tts/config`、`/api/asr/status` 正常返回
- 用例2：AASC 路径读取配置
  - 预期：`aasc/agents` 初始化不报错

## 兼容性测试

- 配置文件位置仍为 `config/config.json`
- 对外 API 和字段保持兼容

## 性能测试

- 本次为路径迁移，无新增运行时负担

## 风险评估

- 主要风险是相对路径错误导致启动失败，已通过 `node --check` 与 `require` 自测规避

## 预计工时
