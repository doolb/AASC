# APK 共享存储访问

## 任务描述

为 Android APK 显示端增加当前 Android 9/API 28 设备对 `/storage/emulated/0/` 及其子目录的直接读写能力，使内置 Node 子服务器的本地媒体库可以访问设备共享存储。

## Design 需求

- 仅支持当前 Android 9/API 28 目标设备的直接共享存储访问。
- 通过 `READ_EXTERNAL_STORAGE` 和 `WRITE_EXTERNAL_STORAGE` 声明及运行时授权实现访问。
- 权限声明设置 `maxSdkVersion=28`，不把 Android 10+ 的兼容性扩大为整个共享存储直接读写。
- 存储权限拒绝不能阻塞显示端连接，但共享存储媒体库操作必须返回明确的系统权限错误。
- 保留 LocalProvider 的路径越界保护和只读媒体库写保护。

## 自测用例

1. API 28 返回 READ_EXTERNAL_STORAGE 与 WRITE_EXTERNAL_STORAGE 两项权限。
2. API 29 及以上不返回共享存储权限，也不包含 MANAGE_EXTERNAL_STORAGE。
3. API 28 只有同时授予读写权限才判定共享存储可用。
4. APK Manifest 的两项权限均限制到 API 28。
5. Android 9 真机授权后，Node 媒体库列出 `/storage/emulated/0/Download` 并在隔离测试目录完成写入、建目录和删除。
6. 拒绝权限后显示端仍能连接主服务器，媒体库请求失败且不访问测试目录外路径。

## 兼容性测试

- Android 9/API 28、arm64-v8a 真机 SM-N9500。
- `minSdk=26` 的 Android JVM 单元测试。
- API 29+ 仅执行 Manifest/策略契约检查，不宣称支持整个共享存储根目录。

## 性能测试

- 启动时只进行两项权限状态检查，不增加轮询或文件扫描。
- 授权不会复制媒体文件；Node 直接使用共享存储路径。

## 风险评估

- 共享存储权限覆盖范围较大，媒体库 path 仍必须由用户明确配置，前端删除操作继续需要现有确认流程。
- Android 10+ 的分区存储不属于本任务支持范围；后续若需要支持，需单独设计 SAF 或特殊权限流程。
- 用户拒绝授权时 Node 服务仍可运行，必须通过媒体库请求错误识别授权缺失。
