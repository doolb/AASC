# Codex 响应无活动超时修复

## 任务描述

修复 Codex Agent 在持续输出流式内容但总响应时间超过 60 秒时被误判超时并变为离线的问题。

## design 需求

- 默认超时从 60 秒调整为 10 分钟。
- 超时按“连续无活动”计算，而不是从请求开始固定计时。
- 收到流式增量后重置计时器。
- 正常收到完成事件后保持 Agent 在线。

## spec 设计

- `CodexBridge` 增加统一的当前轮次超时重置方法。
- `item/agentMessage/delta` 到达时重置当前轮次计时器。
- 超时仍调用原有错误回调和 bridge 回收逻辑，避免真正卡死的 Agent 永久占用。

## 自测用例

- 延迟超过测试初始超时但期间收到流式增量的 Codex 回包能够正常完成。
- 正常完成后 bridge 仍处于在线状态。
- 原有 Codex thread、代理和 stop 测试继续通过。
- 运行 AI 角色测试、语法检查和 `git diff --check`。

## 兼容性测试

- 不改变 JSON-RPC 请求格式、threadId 和 HTTPS_PROXY 设置。
- 真正连续无活动超过 10 分钟时仍返回超时并回收 bridge。

## 风险评估

- 超时时间变长后，网络完全卡死的 Agent 最多占用 10 分钟；流式活动会继续续期。
- 不修改当前工作区其他未提交的 Markdown、日志和任务结果文件。
