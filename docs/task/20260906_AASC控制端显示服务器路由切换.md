# 20260906 AASC 控制端显示服务器路由切换

## 任务描述

控制端继续从主服务器 `/control` 进入，但可以选择当前显示服务器。选中子服务器后，控制消息、显示消息和 HTTP 控制 API 走子服务器；子服务器离线自动回主服务器，恢复后自动切回。用户手动选择主服务器时，不被自动恢复覆盖。

## Design 需求

- 主服务器是固定控制端入口和 AASC 节点注册入口。
- 当前目标由主服务器维护，支持主服务器、在线子服务器和临时回退状态。
- 显示端页面跟随当前目标服务器的 `/display`，不是只更换 WebSocket 地址。
- 显示端保存主服务器回退地址，子服务器断线后可回到主服务器。
- 主服务器和子服务器通过既有主动 `/server` WebSocket 通信，不新增独立转发进程。
- 媒体文件不复制，媒体索引和媒体 URL 保留所属节点地址。

## Spec 设计

- `AascServerRouteManager` 每 5 秒同步节点状态。
- `GET /api/aasc/route` 返回当前路由。
- `POST /api/aasc/route/select` 在主服务器执行手动切换。
- 主服务器发送 `control.message`、`display.message`、`display.route`。
- 子服务器处理本地控制消息和显示消息，并以 `control.broadcast` 回传事件。
- 主服务器在选中子服务器时代理 `/api/*`、`/upload-file`、`/media-list`、`/media/*`。
- 显示端接收 `aascDisplayRoute`，按 targetUrl 导航，连接错误时按 fallbackUrl 回退。

## 自测用例

1. 选择在线子服务器，路由 activeNodeId 变为子服务器。
2. 选中子服务器后将节点状态置为 offline，路由自动回到 main-server 并保存 fallbackNodeId。
3. 节点恢复 online 后，路由自动切回原子服务器。
4. 自动回退后手动选择 main-server，子服务器恢复时仍保持 main-server。
5. 不能选择离线子服务器。
6. 主服务器控制端收到当前路由变化，服务器卡片更新。
7. 显示端收到 aascDisplayRoute 后切换到子服务器 /display。
8. 子服务器 WebSocket 断开后显示端导航到主服务器 /display。
9. 选中子服务器时 HTTP API 和文件上传经过主服务器代理转发。

## 兼容性测试

- 主服务器模式：现有本地控制端、显示端和 AASC 节点注册保持可用。
- 子服务器模式：继续使用主动 `/server` WebSocket 和既有 Termux 启动方式。
- 未收到路由消息的旧显示端：继续使用当前页面同源 WebSocket。
- 控制端不提供手动直连地址，统一从主服务器 AASC 入口通过服务器卡片切换目标。

## 性能测试

- 路由状态每 5 秒轮询一次，不扫描媒体文件。
- HTTP 代理使用流式请求和响应，不在主服务器缓存上传内容。
- 显示端路由消息只在路由变化或显示端连接初始化时发送。

## 风险评估

- 子服务器地址必须可被浏览器访问，否则显示端会按回退地址回主服务器。
- 主服务器 HTTP 代理不能替代节点认证，当前沿用 AASC 主动连接的信任边界。
- 子服务器离线瞬间的控制请求可能返回 502 或路由错误，待下一次心跳同步后自动恢复主服务器处理。
- 媒体文件仍可能直接由所属子服务器提供，浏览器需要能访问该节点地址。

## 主服务器统一设备与媒体库视图补充

### 任务描述

在主服务器控制端统一展示主服务器和在线子服务器的设备列表、媒体库和目录内容；服务器卡片提供目标切换及子服务器控制端入口。

### 自测用例

1. 主服务器控制端按主服务器和子服务器分组显示设备列表。
2. 远程显示端选择后，控制消息通过所属子服务器 AASC 会话下发。
3. 主服务器媒体库和子服务器媒体库同时出现在媒体库选择器。
4. 子服务器媒体目录可浏览，远程媒体 URL 保留所属节点地址。
5. 主服务器卡片在显示端数量为 0 时仍提供切回入口。
6. 在线子服务器卡片提供连接控制端链接。
