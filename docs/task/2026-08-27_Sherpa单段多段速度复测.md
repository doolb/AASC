# Sherpa 单段/多段速度复测

## 任务描述

复测独立 Android ASR 测试 APK 中 Sherpa 单段和多段声纹流程的真机速度，使用既有四个 WAV，并给出阶段耗时和优化判断。

## Design 需求

- 在已注册 `ZH`、`EN` 的前提下，通过 HTTPS API 分别调用 `SHERPA_SINGLE`、`SHERPA_MULTI`。
- 记录 APK 返回的 `elapsedMs`、`diarizationMs`、`embeddingMs`、`asrMs` 和分段数量。
- 区分单语音频与中英多语音频的速度差异，不修改生产代码。

## Spec 设计

- 单段：一次 embedding、一次 ASR 和一次匹配。
- 多段：diarization 后对合并分段逐段执行 embedding、ASR 和匹配。
- 结果写入设计、spec、todo 和 changelog 文档。

## 受影响的功能模块和代码

- 运行模块：`3rd/tts-server/android-asr` 的 HTTPS `/api/voiceprint/*` 接口。
- 文档：`docs/design/android-voiceprint-test-apk.md`、`docs/spec/android-voiceprint-test-apk.md`、`docs/task/2026-08-27_Sherpa单段多段速度复测.md`、`docs/todo.md`、`changelog.md`。
- 生产代码：无修改。

## 自测用例

- 注册 `zh.wav → ZH`、`en.wav → EN`。
- 测试 `zh.wav`、`en.wav`、`zh-en.wav`、`zh-en-mix.wav` 的两种模式。
- 校验八次请求均返回 HTTP 200 和耗时字段。

## 兼容性测试

- SM-N9500、Android 9、arm64-v8a。
- HTTPS 地址：`https://192.168.1.6:18080`。

## 性能测试结果

| 文件 | 单段 | 多段 | 多段分段数 |
|---|---:|---:|---:|
| `zh.wav` | 5745ms | 5553ms | 1 |
| `en.wav` | 7290ms | 7050ms | 1 |
| `zh-en.wav` | 14335ms | 31683ms | 6 |
| `zh-en-mix.wav` | 8097ms | 14249ms | 2 |

单语音频多段只有一个分段，耗时与单段接近；中英串接和混合音频多段分别约为单段的 2.21 倍和 1.76 倍。多段瓶颈主要是分段和逐段 ASR。

## 混合语音补充复测

- `zh-en-mix.wav` 单段匹配 `EN`，ASR 以英文为主。
- 普通多段返回重叠 `EN 1.077–6.376s` 和 `ZH 1.077–5.009s` 两段，两个分段 ASR 仍以英文为主。
- 快速 2 人模式返回相同分段，`11920ms`；普通多段 `11955ms`，仅快约 35ms。
- 原因：混合语音只有两个输出分段，快速模式减少的 embedding 次数有限；Sherpa 不执行语音源分离。

## 风险评估

- 不同 CPU 模式、设备温度和首次 native cache 状态会造成耗时波动，本次数据用于同一设备上的相对比较。
- 多段分段数量变化会直接影响 embedding 和 ASR 次数，不能用单语音频耗时推算多语音频耗时。
