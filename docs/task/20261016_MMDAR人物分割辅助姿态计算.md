# 人物分割辅助骨骼计算评估

状态：新方案待用户确认；本轮仅查代码与官方资料、记录设计/spec。没有下载分割模型、修改运行代码、改正式入口或运行新推理。原三图/RTMPose/深度/肩髋报告保持。

## 任务描述与design需求

用户要求在骨骼计算前先将人物单独分离，减少椅子、道具、背景对识别和深度取样的干扰。沿用浏览器/手机本地ONNX及全身IK唯一正式入口；先三图临时对照，不自动部署。当前worker仅RTMPose整图+固定1.25边距，未分割或逐人定位；已有肩髋弱约束未修复真人前后腿，不能把新增抠图当必然修复。

输入固定真人侧身坐姿、动漫跪坐、交叉腿示意三图。保留原图，分割输出原尺寸人物浮点掩码和透明人物预览，比较原图、人物框裁剪原图、同框中性背景抠图。重投影和相机继续使用原图坐标/aspect，显式保存裁剪/缩放/填充双向映射；人物服饰/头发保留，不能生成或补全遮挡身体。

## 模型依据与资源约束

候选PPHumanSeg来自[OpenCV Zoo README](https://raw.githubusercontent.com/opencv/opencv_zoo/main/models/human_segmentation_pphumanseg/README.md)，目录Apache-2.0，提供ONNX及真实示例；[官方前后处理](https://raw.githubusercontent.com/opencv/opencv_zoo/main/models/human_segmentation_pphumanseg/pphumanseg.py)为RGB192×192、除255/mean=std=0.5、NCHW，输出两类先逆缩放再argmax。优先原精度；不因为INT8文件更小默认效果等价。正式下载前固定revision，之后实测字节数/SHA与输入输出、是否已softmax；当前只核对源码，不编造资源大小或手机速度。

[MediaPipe人像分割官方说明](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter)支持Web与类别/置信度mask，[ONNX社区Selfie模型卡](https://huggingface.co/onnx-community/mediapipe_selfie_segmentation)列本地Web示例和Apache-2.0。其人像定位不代表已验证本项目全身坐姿、动漫/示意图，首轮只将其作为备用资料，不同时扩张多个模型试验。

## spec设计与L4数据流

```text
已有声明 := 三张原图 + 固定RTMPose/深度缓存/321骨初值 + 参考相机/真实PMX与Ammo
新增定义 := 人物掩码/置信信息/主体范围与未知原因 + 三输入变体 + 原图坐标变换 + 分割质量与回退状态
顺序 := 固定身份的分割本地推理 → 原图大小掩码与透明预览 → 先查是否保留手脚/衣物/头发与是否误含椅子道具 → 不合格回退原图并保留失败
二维 := 原图基线与两个同框变体分别RTMPose → 逆裁剪/缩放/填充回原图 → 保持左右和模型分数，不把原基线当人工真值
深度 := 原图上下文推理 → 掩码约束取样归属与边界 → 肩髋独立前后弱约束 → 关节链/遮挡消歧；抠图深度只作为另列对照
实际 := 可用变体同初值/相机/预算 → 原生+PMX投影/骨长/角度/前后腿/执行差；未通过不能自动切默认
边界 := 掩码只区分人/背景，不等于人体部位或左右腿实例，不给遮挡关节补z，不自动精修或生成新人物
```

## 自测与兼容性

- 已知坐标/不同长宽比/奇数尺寸/填充的正反映射，原图点叠加一致，不混用裁剪图aspect作为原图相机。
- 全空/全满/非有限/主体不明与多连通部件不静默当成功；不能简单保留最大连通片丢掉分离手脚。
- 人物与背景/掩码边界取样分别检查；不因mask内部就补深度或提升姿态分数，衣物和同人交叠仍未知。
- 三图可视化分割/抠图完整性，原图/裁剪/抠图二维点/分数分列，遮挡脚掌与示意文字保持失败证据；原图与旧数据摘要保持。
- 掩码可用才继续实际双重回读，骨长/限位/执行差与真人前后腿符号单列；既有原生/PMX缺陷不忽略。
- Worker/换图/取消/释放与窄屏；本机桌面WASM先验，手机/WebGPU另测，不拿官方设备指标当本机结果。

## 性能、风险与预计工时

分割增加下载/初始化/像素处理与推理，需记录各段及内存；模型大小与手机预算尚未实测。首轮原型预计1个工作日，若分割本身漏脚/动漫失效，保留失败与原图回退，不强行进入3D。背景去除可能丢掉椅子与身体的相对遮挡/深度线索，因此深度主线保持原图上下文，先用mask排除背景取样；抠图图像不保证适合深度模型。多人、细致手工修mask或更重交互分割模型不作为未确认附加范围。

## 需求分层enterprise

需求明确为在现有骨骼流程前拆出人物；主L6（分割输入输出与姿态/深度接线），次L5（变体、未知与回退），必须下放L4。强证据“先把人物单独拆分”指分割模块，“做骨骼计算时”指现有流程接线；置信度3/6×0.9=0.45。层级24/25、证据18/20、完备14/20、风险19/20、落地14/15，共89/100。结论为临时评估可开发，效果验收需补充：输入缺分割/资源固定身份→确认后锁revision/契约/摘要，否则对照不可复现；异常缺漏肢/多主体规则→显式拒绝回退，否则裁掉手脚；验收缺人工掩码/3D真值→三图可视化与同初值实际回读，否则把去背景当准确还原。技能不引入额外流程确认，实施仅遵守用户项目代码方案确认规则。
