# 五子棋多标签 GM 校验与落子确认

## 任务描述

修复模型在两个合法 Game 标签之间插入自然语言时，桥接层直接返回“标签格式无效”的问题；保留单次回复多标签能力，并让用户落子先获得 GM 确认。

## Design 需求

见 `docs/design/game-gomoku.md`。标签使用英文逗号的位置参数，最多八条。合法的标签之间允许自然语言；每条操作仍由 GM 按权威版本、轮次与棋盘校验。用户落子后若同一回复提前预写 AI 落子，该 AI 标签与预写叙述不采信，模型收到 GM 增量后重新决定棋步。

## Spec 设计

见 `docs/spec/game-gomoku.md`。解析首个开头标签及后续标签 → 保留标签顺序与叙述 → 逐条执行并收集 GM → 遇 User 落子后存在预写 AI 落子则在 User GM 成功处暂停并续接模型 → GM 失败则停止、丢弃预写叙述 → 全部成功且需续接时回送每条 GM。

## 受影响模块

- `src/apps/server/modules/game/game-chat-bridge.js`：提示词、批量标签解析、GM 回执和落子确认点。
- `tests/game-gomoku.test.js`：交错标签、预写 AI 落子、批次 GM 失败、合法多标签回执。
- `docs/design/game-gomoku.md`、`docs/spec/game-gomoku.md`、`docs/todo.md`、`changelog.md`：同步行为与待验收状态。

## 自测用例

- 目录与规则两条标签中间插入叙述，确认没有格式错误，两个 GM 回执都交给下一次模型调用。
- User H3 与预写 AI H4 之间插入叙述，确认只先执行 H3；第二次模型调用收到 H3 的 GM 增量后再落 H4，预写叙述不显示和朗读。
- 多标签第二个真实棋步轮次错误时，确认 GM 给出具体错误、停止剩余操作，已确认操作保留。
- 非法位置参数、超过八条和伪造 GM 角色仍给出格式错误；单标签兼容性保持。

## 兼容性与性能

不改变 WebSocket 消息类型、棋局持久化格式与显示端协议。每条回复仍最多八个标签，桥接续接最多七次；附加检查至多扫描八条标签和其余简短文本，开销可忽略。

## 风险评估

模型仍可能在 GM 回执前预写结果；桥接层丢弃该回复的相关叙述并让模型重新决策。2026-10-20 本机用 Responses 协议对 Chat2API 豆包做一次隔离请求，返回 `doubao_risk_control`（403），需在安全验证恢复并发布新版后用真实 AASC 对话验收。
