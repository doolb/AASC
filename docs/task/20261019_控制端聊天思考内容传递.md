# 控制端聊天思考内容传递

## 任务描述

修复 Chat2API 上游已有独立 `reasoning_content`，经 Responses 转换后控制端 Think 按钮不出现的问题。

## Design 需求与 Spec 设计

见 `docs/design/chat-output-filter.md` 与 `docs/spec/chat-output-filter.md`。思考和最终回答分字段传递；控制端沿用现有 Think 弹窗，聊天历史保留思考。

## 受影响模块与代码

- `chat2api-responses-service.js`：非流式和流式转换独立思考字段。
- `llm-service.js`：消费 Responses 思考字段并合并到聊天分流、历史和播报。
- Responses/LLM/控制端定向测试、文档索引、待办、变更日志与服务代码包状态。

## 自测、兼容性与性能

覆盖上游同时返回思考和回答、只返回回答、分块思考和回答、完成态/历史及旧 Responses 客户端忽略新字段。每个增量只做追加处理；不新增网络请求。

## 风险评估与预计工时

需避免把思考写进 `output_text` 或下一轮上下文；模型自行输出 `<think>` 时继续走原解析。预计 2–3 小时。

## 需求等级

主等级 L6（字段契约），次等级 L5（流式与历史流程）；下放判定“必须下放”，能力等级 L4。已在 spec 中定义“已有声明、字段、操作流程”；输入、输出和旧行为边界明确，可开发。主要风险是思考与回答顺序及续接历史混写。
