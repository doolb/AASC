# Chat2API 核心内置任务

## 任务描述

将 `/mnt/Chat2API` 的核心代理能力移植到 AASC，作为 `chat2api.proxy` 常驻内置任务运行，不依赖 Chat2API Electron 应用或外部源码目录。完整范围包括 Provider 管理、OAuth 登录、API Key、多账号负载均衡、OpenAI 兼容代理和 AASC 控制端配置。

## design 需求

- 保留 Chat2API 核心 Provider、OAuth、账号、负载均衡、模型映射和代理协议能力。
- 排除 Electron、IPC、React、窗口、托盘和独立更新器。
- 上游核心放在独立目录，AASC 适配层负责任务生命周期、配置、日志、管理 API 和控制端 UI。
- 保留 GPL-3.0 许可证、版权和上游版本信息，支持后续同步更新。

## spec 设计

- 内置任务使用 `mode=service`，返回 `stop()` 控制器。
- 代理提供 `/v1/chat/completions`、`/v1/models`、`/v1/completions`。
- 管理接口覆盖配置、Provider、账号、OAuth 和 API Key。
- 用户数据保存到 `~/.config/aasc-user/chat2api/`，凭据脱敏、私有权限和原子写入。

## 受影响功能模块和代码

- `3rd/chat2api-core/`：Chat2API 上游核心快照和许可证说明。
- `src/apps/server/modules/chat2api/`：核心装配、配置、存储、管理接口和代理生命周期。
- `src/apps/server/modules/chat2api/chat2api-gateway.js`：控制端同源 HTTPS 到 Chat2API 本机代理的安全转发。
- `src/apps/server/boot/server-app.js`：注册同源 Chat2API 网关。
- `src/apps/server/modules/task-engine/builtin-tasks/chat2api-proxy.js`：内置任务入口。
- `src/apps/server/modules/task-engine/builtin-tasks/registry.js`：任务注册。
- `src/apps/web-mediacenter/ui/public/js/chat2api.js`：控制端配置面板。
- `docs/design/chat2api-builtin-task.md`、`docs/spec/chat2api-builtin-task.md`：设计和伪代码。

## 自测用例

- 内置任务启动、重复启动、停止、重启和端口释放。
- `/v1/models`、非流式聊天、流式 SSE、模型映射和标准错误响应。
- Provider、账号、API Key 的增删改查和脱敏展示。
- OAuth 成功、失败、超时、错误 Provider 和重复回调。
- 多账号轮询、故障转移、账号禁用和全部失败。
- AASC 原有 LLM profile、Pi Agent、TTS 和其他内置任务回归。

## 兼容性测试

- Node.js CommonJS 主服务与移植核心的模块加载兼容。
- Linux 服务端和 Windows 开发环境的端口、浏览器 OAuth 回调兼容。
- Chat2API 上游版本同步后 Provider 字段、流式协议和管理数据迁移兼容。
- 旧 AASC 配置和未启用 Chat2API 任务时行为不变。

## 性能测试

- 单账号和多账号并发聊天请求吞吐、首字节延迟和 SSE 长连接。
- Provider 故障转移额外延迟和连接回收。
- 任务停止/重启后句柄、监听端口、SSE 连接和 OAuth 状态无泄漏。
- API Key、Provider 和账号列表在大规模配置下的读取耗时。

## 风险评估

- Chat2API 为 GPL-3.0，直接移植和发布必须保留许可证、版权和对应源代码。
- Chat2API 当前是 Electron + TypeScript，核心抽取可能需要模块格式和依赖适配。
- OAuth 页面和回调依赖 Provider 行为，可能随上游网站变化而失效。
- Provider 账号凭据属于敏感数据，必须避免进入普通日志、任务参数和备份快照。
- 上游更新可能同时改变协议、模型字段和数据格式，需要锁定版本并保留回归测试。

## 预计工时

完整移植预计 3～7 个工作日，具体取决于 OAuth Provider 数量、AASC 控制端表单复用程度和数据导入格式。
