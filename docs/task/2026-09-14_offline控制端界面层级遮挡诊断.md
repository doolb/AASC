# Offline APK 控制端界面层级遮挡诊断

## 任务描述

用户点击 offline APK 的“控制端”按钮后，控制端界面没有显示。需要确认是否被启动遮罩或显示端 WebView 覆盖，完成最小修复并在 Display 2 真机回归。

## design 需求

- 显示端 WebView 作为底层内容。
- 控制端 WebView 打开后必须覆盖显示端 WebView。
- 控制端按钮在控制端 WebView 之上，启动遮罩仅在服务未就绪期间覆盖全部页面。
- 普通 APK 和 offline APK 共用清晰、可验证的页面层级规则。

## spec 设计

- 检查 `MainActivity.setupWebView()` 中 display/control WebView 的插入顺序。
- 检查 `toggleControlPage()` 是否执行可见性切换和 `/control` URL 加载。
- 检查 `offlineStartupPanel` 在本地 display 成功后是否隐藏。
- 使用 Android 真机截图、UI 自动化树、窗口焦点和源码绘制顺序确认遮挡层。

## 自测用例

- Display 2 启动 offline APK 后，显示端页面和“控制端”按钮可见。
- 启动遮罩隐藏后点击按钮，控制端 WebView 应位于显示端 WebView 之上。
- 控制端页面加载同源 `/control`，按钮仍在最上层并可关闭控制端。
- 启动遮罩显示时，遮罩应拦截页面操作；遮罩隐藏后不得继续拦截控制端按钮。

## 兼容性测试

- 当前设备：Samsung SM-N9500，Android 9/API 28，Display 2。
- 普通 APK 需保持服务端授权开关行为不变。
- offline APK 需保持控制端入口默认显示。

## 性能测试

- 调整层级不新增 WebView 或重复加载 `/control`。
- 打开/关闭控制端不触发显示端 WebView 重建。

## 风险评估

- 仅调整绘制层级时需避免启动遮罩失去最高层保护。
- 若只修改按钮层级而不修改控制端 WebView 层级，问题仍会复现。
- 真机旋转/DeX 多显示场景需要确认原生层级与网页内容坐标不互相影响。

## 预计工时

约 30 分钟，包括最小修复、契约测试和 Display 2 真机回归。

## 诊断与修复结果

- 启动遮罩不是当前根因：设备截图显示本地 display 页面已经正常加载，遮罩未覆盖页面。
- `MainActivity.kt` 先执行 `webContainer.addView(wv, 0)` 添加 display WebView，再执行 `webContainer.addView(control, 0)` 添加 control WebView。
- Android ViewGroup 后加入/更高索引的子视图绘制在上层，因此 display WebView 会覆盖 control WebView。控制端按钮自身仍可能显示并响应点击，造成“点击后没有界面”的现象。
- 已将控制端 WebView 改为插入索引 1，使其位于 display WebView 之上、控制按钮和启动遮罩之下。
- 新增图层顺序回归测试，`tests/android-offline-apk.test.js` 为 11/11 通过；Android `:app:testDebugUnitTest` 构建成功。
- 使用最新 offline APK 卸载重装到 Samsung SM-N9500 的 Display 2；Node Runtime 首次展开成功，本地 display 页面正常连接。
- 通过键盘聚焦并触发“控制端”按钮后，UI 自动化树出现第二个 `/control` WebView，页面标题为“媒体上传端”；再次触发后恢复单个“媒体显示端” WebView 和“控制端”按钮。
