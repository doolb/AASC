# Node子显示端ASS信息叠加

状态：用户明确位置与网页版一致后完成实现与自动验证；Windows实际画面待现场验收。

- 任务描述：在常驻mpv中用ASS显示网页现有的时间、连接状态、TTS当前播报文字与ASR回显。
- design需求：见 `docs/design/node-display-mpv.md` 的ASS信息叠加；对齐网页最终布局/格式，采用本端事件，默认媒体能力开启后无媒体也显示黑底信息。
- spec设计：见 `docs/spec/node-display-mpv.md` 的L4草案；独立OSD层、中文换行/转义、队列条目生命周期、30秒隐藏与会话重放，裁剪缩放不影响字幕布局。
- 受影响模块与代码：已新增 `src/apps/voice-display-node/mpv-overlay.js`，修改main.js、media-controller.js、mpv-player.js、audio-player.js；更新专项与render测试、使用/自测/设计/实现/待办/变更日志。
- 自测用例：固定时间/时间推进、连接中/已连接/断开或错误、正确显示当前播放条目而非刚收到的后续条目；停止/失败/旧回调不污染新字幕；成功与ignored识别格式、30秒隐藏、新结果延长；括号/反斜杠/换行/Unicode及长文本。
- 兼容性测试：Linux/Windows命令和IPC、现有PowerShell/aplay TTS、录音暂停/AEC/打断与提示播报回调；字体回退与四旋转、窗口调整、原生panscan及裁剪。Windows实屏另验。
- 性能测试：时钟最多1Hz，事件合并、一个刷新任务，文本长度/行数有界；旧会话不写入、不因时钟重复启动崩溃进程，退出无计时器泄漏。
- 风险评估：ASS文本必须转义；中文字体可能缺字；字幕不能依赖暂停的媒体时间轴；队列级回调不等于逐条播放；原录音模式会覆盖onPlayStart/onPlayEnd，必须使用独立条目通知；长句显示应有界且不会遮住时间和ASR。
- 预计工时：约2～4小时实现、专项回归与Linux实际画面验证，Windows设备验收另计。
- 范围确认：本轮按当前TTS条目显示而非精确逐字时间轴/网页全部滚动历史；TTS结束暂留30秒、停止/失败立即清除，ASR30秒；媒体能力开启时启动黑底信息窗口。用户追加布局一致要求后按该方案实施。
- 验证入口：优先 `npm run test:node-display-mpv`、`npm run test:node-display-mpv:render`、`npm run test:node-display-mpv:real` 与 `npm run test:offline-voice-display-node`，按AudioPlayer实际影响补充原有语音测试。已执行功能/兼容回归；未构建或发布独立包。

- 位置校正：网页TTS最终是顶部居中，ASR是底部语音按钮上方；0/180与90/270的TTS最终偏移不同，须复现真实布局函数结果。增加浏览器真实CSS/布局函数对照与ASS实屏回归。
