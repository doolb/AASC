# PMX 取消初始化首帧与物理预热

- 日期：2026-09-27
- 状态：本地实现与自动化验证完成，真实浏览器/Android WebView 视觉待验收

## 任务描述与设计需求

用户在 MMD AR 测试页对照物理开关时发现开物理默认不是 T-pose、关物理却是 T-pose。确认不应由物理初始化隐式应用 VMD 第 0 帧，同时要求移除首次加载的 180 步隐藏预热。参见 `docs/design/mmd-pmx-vmd-local.md` 与 `docs/design/mmd-ar-test-apk.md`。

## 实现规格与受影响模块

`docs/spec/mmd-pmx-vmd-local.md` 规定：带物理 PMX 创建 helper 时显式传 `warmup=0`、`animationWarmup=false`，首载和显式切换 VMD 均不在 `helper.add` 中推进动画或物理。删除区分首载/切换的预热步数参数与 180 步常量。受影响代码为 `src/apps/web-mediacenter/ui/public/js/mmd-pmx-helper.mjs`、`display-pmx-runtime.js` 和相关测试。Three.js vendor 文件不改。

## 自测与兼容性

- 带刚体 PMX 首载和换动作均传 `warmup=0`、`animationWarmup=false`；无刚体/关闭物理路径保持 `physics=false`。
- VMD 播放开启时从首次渲染帧推进；关闭时初始化阶段维持 PMX 绑定姿态，后续物理仍可能改变布料位置。
- `npm run build:web:mmd-ar-test` 和定向 Node 测试；正式显示端共享运行时代码，需要后续现场验收。

## 性能与风险

取消同步预热可减少首次加载阻塞，但布料初次可见时可能发生收敛跳动或短时穿模。用户需要在本地网页和目标 Android WebView 比较开关物理、播放/暂停动作及首屏耗时。预计修改和回归约 1 小时；真机视觉验收另计。
