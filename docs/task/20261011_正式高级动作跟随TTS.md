# 正式高级动作跟随TTS

状态：用户“是”确认两阶段方案，源码及定向自测完成；待新服务包发布/真机验收。

任务描述：根据AI回答中的Emoji/高级动作标记播放角色动作；用户进一步明确，TTS开始请求生成时同时解析/准备动作，TTS生成好后音频与动作同步播放。继续使用配置600ms进入/恢复。

Design需求：docs/design/mmd-ar-production-offline.md的TTS方案；只对实际播放的AI回答调度，文字历史、未播报回答、报时/文章/思考不触发；口型和音频播放器继续复用。

Spec设计：docs/spec/mmd-ar-production-offline.md的TTS草案；服务端实际启动生成任务时发送动作准备消息，生成结果playAudio沿用同一句标识；显示端本地请求生成在请求发起时准备动作。原始标记文本关联净朗读文本，句标识、来源序号与模型token隔离；生成和解析/资源准备并行，动作准备阶段不接管模型或改写当前音频来源。音频位置缩放文本时间线；准备、发声、暂停、续播、打断分别处理。自动链路只处理有限高级动作/表情。

受影响模块及拟改文件：server-app.js及agent-chat-tts.js既有AI回答TTS生成任务，增加生成开始的WebSocket动作准备消息及贯穿准备/playAudio的同句标识；新增独立消息辅助模块，避免扩展大段分支。display.html的TTS入队、客户端生成及实际播放入口；display-lipsync-audio.js的来源元数据；新增mmd-tts-actions.mjs及音频调度/事件时间模块；复用mmd-reply-parser/gestures/source与Human接口，必要时为mmd-human-interface/mixer添加仅作用于自动轨道的外部时钟能力。不改音频路由及Provider配置。最终实现文件范围在确认后依据最小改动落定。

自测：TTS请求生成时动作解析同时开始，生成延迟期间动作已准备但模型未被接管；音频与动作同句提交播放，多句并发乱序结果仍顺序播放且不串句；准备失败不阻断语音，生成失败/取消释放准备结果，生成开始及结果路由目标变更不误接管。排队等待/预加载时不执行，第一句先播无需完整回复；标记在实际音频位置触发；暂停/缓冲/继续、改变播放速率、跳播/回拖去重；句子源快切、结束回调换句不误清新会话；停止/错误/新回答/token/后台阻断迟到编译；无声音或历史不触发；手动高级动作不被旧会话释放；真实TTS口型保持唯一写入者、600ms衔接。计划增加有意义的TTS动作单元/真实浏览器自测并更新self-test文档，优先npm现有test:mmd-production及browser入口。

兼容性：旧TTS消息没有新增元数据时不猜测AI身份，不影响发声和原口型；普通文字预览和手动高级动作继续可用；独立测试构建检验共享注入及导入指纹。正式网页变更只标记servicePackage，不额外改变APK或生产依赖状态。

性能：只在存在当前自动会话时读取音频时钟，复用有限事件列表与模板资源；暂停取消调度帧，后台释放；测试浏览器耗时不当作Android性能结论。
