# AI 任务系统通用能力与控制端显示

## 任务描述

将任务 URL 路由注册能力纳入 AI 任务系统规则，同时梳理现有任务使用的通用上下文、Widget、侧边栏和控制端展示能力，使用户任务可以自主管理控制端页面资源和交互逻辑。

本任务不引入控制端页面/动作白名单。用户任务是项目维护者自行管理的代码隔离单元，任务资源由任务自身负责维护。

## design 需求

- 在 `docs/design/ai-rules.md` 中定义 AI 任务系统通用能力和用户任务自管理边界。
- 在 `docs/design/remote-task-system.md` 中统一描述任务元数据、任务上下文、控制端 UI、Widget、生命周期和 URL 路由。
- 修正内置任务始终在服务端执行的过时描述，明确遵守任务目标声明。

## spec 设计

- 在 `docs/spec/ai-rules.md` 和 `docs/spec/remote-task-system.md` 增加伪代码。
- 用户任务元数据透传 `sidebar`、`sidebarManifest`、`widget` 和 `configButton`。
- 内置任务和用户任务统一使用 `control.actions` 声明任务级/实例级控制端页面或弹窗，不再由任务面板按具体任务名称编写页面分支。
- 内置任务与用户任务遵循同一元数据和上下文契约；后续不依赖特权服务的内置任务可以迁移到 `res/tasks/<taskName>/`，控制端无需增加任务名分支。
- 用户服务补齐 `postWidgetUpdate`、`onWidgetAction` 等与内置服务一致的任务上下文能力。
- 控制端继续复用 `TaskPanel`、`SidebarRegistry`、Widget API 和 Control API，不新增白名单注册层。

## 受影响的功能模块和代码

- `tests/task-common-capabilities.test.js`、`tests/task-panel-llm-server.test.js` 及任务路由测试：验证通用任务契约和控制端页面回归。

## 自测用例

1. 内置任务列表继续返回 `sidebar`、`widget` 和 `configButton`。
2. 用户任务列表可以返回 `sidebar`、`sidebarManifest`、`widget` 和 `configButton`。
3. 用户服务上下文包含 `postWidgetUpdate` 和 `onWidgetAction`，动作按实例隔离。
4. 用户任务 Widget 能在任务实例详情和侧边栏中显示，并可发送任务动作。
5. URL 路由注册相关测试保持通过。

## 兼容性测试

- 未声明新元数据的旧用户任务继续使用原有任务列表和执行流程。
- 既有内置任务 `llm-server` 的默认映射能力和 Widget 行为不变，只将页面实现迁移到通用 `control.actions`。
- 不新增 HTTP 配置读写接口，不改变 AASC `8081` 端口和既有 WebSocket 消息类型。

## 性能测试

- 任务列表仅透传已有模块导出的元数据，不新增轮询或独立连接。
- Widget 动作仍按 `instanceId` Map 查找，保持常数级分发。
- 侧边栏清单只在任务列表刷新时同步，不增加显示端请求。

## 风险评估

- 用户任务自带控制端 HTML/JavaScript，页面异常由任务自身负责；控制端需要保留现有容器和脚本清理机制。
- 用户任务元数据加载失败时降级为无 UI 元数据，不阻塞任务列表。
- 用户服务动作必须按实例保存和清理，避免同名任务实例互相响应。

## 实现结果

- 内置任务和用户任务列表统一透传 `sidebar`、`sidebarManifest`、`widget`、`control.actions`，旧 `configButton` 仅保留兼容。
- `TaskPanel` 通过通用 Control API 创建任务级/实例级弹窗，负责消息分发、Widget 更新、关闭清理和定时器清理，不再按 `llm-server` 任务名编写页面分支。
- `llm-server` 默认映射表单由任务自身维护 HTML/JavaScript，并继续使用原有 `llm.defaultModelMappings.get/set` 消息、服务端校验、持久化和权威广播。
- 用户服务上下文补齐任务身份、目标/模式、Widget 更新、Widget 动作、消息流和 URL 路由能力；内置任务迁移到用户任务时可复用同一契约。
- 未增加控制端页面/动作白名单，也未增加独立 HTTP 配置接口或新的监听端口。

## 验证结果

- 任务通用能力、LLM 页面和 URL 路由定向测试：23/23 通过；LLM/通用能力测试：11/11 通过。

- 相关 Node.js 文件语法检查、LLM 控制页面脚本编译检查和 `git diff --check` 通过。
