# 控制端任务面板竖屏适配

## 任务描述

Offline APK 竖屏时任务面板最右侧结果列被裁切。竖屏将任务卡片变为横向滚动任务条，实例列和结果列在其下方全宽排列；横屏保持现有三列。

## Design 需求

见 `docs/design/remote-task-system.md`“控制端任务面板竖屏适配”。

## Spec 设计

见 `docs/spec/remote-task-system.md`“控制端任务面板竖屏布局伪代码”。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/js/task-panel.js`
- `src/apps/web-mediacenter/ui/public/css/upload.css`
- `tests/task-panel-portrait-layout.test.js`
- 任务系统 design/spec、索引、todo、self-test 与 changelog

## 自测用例

- 竖屏任务轨道可横向滚动，卡片不被压缩到不可读。
- 实例列和结果列在任务轨道下方，宽度不超过视口。
- 搜索过滤、任务选择和实例/结果渲染行为不变。
- 横屏仍为任务、实例、结果三列。

## 兼容性测试

覆盖 Android Offline 常见窄屏尺寸和桌面横屏浏览器；不改变 task:* WebSocket 消息。

## 性能测试

仅改变 DOM分组和CSS布局，不增加轮询、逐帧监听或任务数据请求。

## 风险评估

任务分类标题与卡片原本是同列直接子节点，需要保证新增分组包装在横屏通过 `display: contents` 保持原布局；浏览器测试同时验证两种方向。

## 预计工时

约 1 小时。

## 实施与验证记录

已将 `_renderTaskList()` 的分类任务卡片包装为独立分组轨道；横屏通过 `display: contents` 保持原三列任务列表，竖屏改为横向任务轨道、全宽实例列和全宽结果列。搜索过滤仍通过 `.task-card` 查询。

验证：`node --test tests/task-panel-portrait-layout.test.js` 共2/2通过；竖屏覆盖360×800且检查轨道可滚动、实例/结果列不越界、文档无横向溢出；横屏覆盖1280×720并确认原宽度三列。Offline Android WebView现场观感待设备验收，未构建或发布服务包/APK。
