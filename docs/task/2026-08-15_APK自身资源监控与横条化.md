# 2026-08-15 APK 自身资源监控 + render-display 横条化 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal（任务描述）：** 两个相互独立但相关的改动：
1. APK 原生资源接口：`NativeBridge` 新增 `getSystemStats()`，返回 APK 设备自身的 CPU 使用率与内存信息（对齐 PC 端 `win-monitor` 数据格式）。
2. render-display 横条化：硬件监控覆盖层从 260×260 圆形双仪表改为**单行内联横条**布局，大幅降低占空间。

APK 设备自身的资源信息**在本地渲染**：render.js 检测到 `window.NativeDisplay` 时定时轮询 `getSystemStats()`，将 APK 设备作为监控覆盖层里的一个独立来源展示（来源名 = 设备型号），无需改服务端。

**Design 引用：** 本任务由 `docs/design/android-display-stats.md` 设计文档支撑（APK 原生接口 getSystemStats 定义、render.js 本地轮询与自清理、单行横条布局、兼容与降级、测试计划）。

**Architecture:** NativeBridge 新增 `getSystemStats()`（/proc/stat CPU 采样 + ActivityManager 内存）同步返回 JSON；render.js 检测到 NativeDisplay 时每 800ms 轮询，把 APK 设备作为监控覆盖层里的独立来源，与 PC 端 system-stats 推送共用同一套单行横条渲染（纯 DOM/CSS，无 canvas）。

**Tech Stack:** Kotlin（Android 7+）、原生 JS（var 风格，遵循现有代码）、DOM/CSS 渲染（无 canvas、无框架）。

## 全局约束

- 数据格式对齐 PC 端 `win-monitor`：`cpuPercent`/`memPercent`（%）、`memTotal`/`memUsed`（GB，1 位小数）
- render.js 遵循现有 var 风格、中文注释、无 ES6 箭头函数（注入到 display.html，兼容性）
- 覆盖层维持现有细边框样式（`border:1px solid rgba(255,255,255,0.06)` + 圆角），不加面板框/每行独立框
- 保留现有 `applyRotationStyle()` 旋转适配与左下角定位
- APK 本地来源不产生 GPU/温度数据（Android 无 nvidia-smi），对应字段缺省不渲染
- 不产生一大段 if-else-else if 链（AASC 规则）
- 修改前已在设计阶段获用户确认（docs/design/android-display-stats.md）
- 每任务完成后按 CLAUDE.md 规范更新 todo/spec/changelog 文档

**Spec 更新说明：** `docs/spec/android-display.md` 桥接口（window.NativeDisplay）伪代码表格追加 `getSystemStats` 一行，描述同步返回 APK 自身资源、hostname=Build.MODEL、CPU 读 /proc/stat 两次采样差值、内存读 ActivityManager.getMemoryInfo()、GB 1 位小数。

- [x] **Step 1: 添加 import 与 CPU 采样状态字段**

- [x] **Step 2: 新增 `@JavascriptInterface fun getSystemStats()` 桥方法**

- [x] **Step 3: 实现 readCpuPercent() 完整 CPU 采样**

## 自测用例

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| 1 | APK 真机本地来源 | APK 启动 render-display 任务 → 覆盖层出现横条 | 来源名为设备型号，CPU/内存数值每 ~1s 刷新，CPU 百分比随负载变化（如播放视频时上升） |
| 2 | PC 来源回归 | PC 端 system-stats 推送 | 正常渲染横条（CPU/内存/GPU/温度），覆盖层高度明显下降 |
| 3 | 多来源 | APK + PC 同时在线 | 两行横条互不干扰 |
| 4 | task:stop | 控制端停止任务 | 覆盖层移除，无定时器泄漏（控制端无报错） |
| 5 | 浏览器显示端 | 浏览器打开 /display 下发 render-display | 行为与之前一致，仅布局为横条，无桥不轮询 |
| 6 | 旋转 | 旋转 90°/270° | 横条覆盖层位置正确（applyRotationStyle 适配保留） |
| 7 | getSystemStats 首次调用 | 覆盖层刚出现时 | cpuPercent=0，后续正常刷新 |

## 性能测试

- 本地来源 800ms 轮询 `/proc/stat` 与 `getMemoryInfo()`：均为极快只读操作，开销可忽略，不阻塞主线程（JavaBridge 后台线程执行）
- 覆盖层高度由 ~780px（3 来源圆形仪表）降到 ~40px/来源；纯 DOM/CSS 渲染，无 canvas 重绘开销

## 兼容性测试

- 浏览器显示端（无 NativeDisplay）：不轮询，仅布局变化，行为不受影响
- PC 来源无 GPU/温度：对应条/小字不渲染
- Android 7+（minSdk 24）：`/proc/stat` 与 ActivityManager.getMemoryInfo() 为系统标准 API，各版本可用

## 风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| getSystemStats 首次调用无 CPU 基线返回 0 | 低 | 首次采样仅建立基线，第二次起正常；覆盖层刚出现时 CPU 显示 0 属预期 |
| getSystemStats 解析失败/异常 | 低 | 捕获异常跳过本次更新，下轮轮询继续 |
| 覆盖层被 task:stop 移除后定时器泄漏 | 低 | 每次触发先检查 _renderTaskUpdates[instanceId]，不存在 clearInterval 退出 |
| Android 无 nvidia-smi，本地来源无 GPU/温度 | 无 | 字段缺省不渲染，仅横条少 GPU 条 |
