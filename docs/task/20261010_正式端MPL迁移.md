# 正式端MPL迁移

## 需求与设计

用户要求MPL一起接入正式端。设计 `docs/design/mmd-display-mpl.md`；实现前伪代码 `docs/spec/mmd-display-mpl.md`。正式/独立共用编译器及UI，不调用LLM，不自动同步TTS。

## 执行

- 先写伪代码，新增共用只读模型快照，迁移MPL三模块与面板。
- 共享固定版本资源准备脚本，正式本地部署JS/WASM/许可证与来源清单。
- 独立构建复用源码并保持模块指纹，迁移循环不重置物理。
- 保持servicePackage=true，同步设计/实现/使用/todo/changelog。
- 源/生成模块语法与依赖静态检查、固定资源校验、web-dist构建；不新增或运行测试。

## 人工验收、兼容性与性能

- 首次默认动作＋表情示例、纯表情、输入报错、取消30秒编译、原动作与播放开关恢复、VMD下载。
- 只在点击编译时加载WASM；桌面与Android WebView/module Worker、HTTP/同源HTTPS和子目录部署。
- 编译中换模型/动作、物理重载、手动覆盖、短动作循环头发衣物连续性、独立编辑模式保护。

## 风险与预计工时

预计1–2小时。骨骼语法需要标准MMD骨骼；当前Morph范围仍受Three加载器限制。上游WASM与JS固定配对附GPL-3.0原许可证，静态部署必须同时包含所有运行依赖。性能与实际设备播放待人工验收。

## 完成结果

面板、共享三模块、只读快照和本地固定资源接入完成，独立构建在stage中显式切换本地资源模块并保持指纹，不重复挂载MPL UI。循环物理reset=false迁至正式共用helper。prepare:mmd-mpl及web-dist构建成功；12源文件与正式/生成各7模块语法、依赖/指纹、固定资源大小/SHA-256和差异空白检查通过。未新增或运行测试；正式包构建发布和实际播放待验收。
