# 任务：系统搜索取十条结果并展示五条

## 任务描述

系统搜索当前只返回 Bing 第一条结果，Bing 排序变化时可能返回较旧页面。改为 `search.web` 单次内置任务读取前十条真实搜索结果，解析 Bing 摘要中的时间并排序，返回最新的五条；语音流程播报前三条，该任务同时支持控制端手动调用。

## Design 需求

- 系统搜索候选限制为前十条真实网页结果。
- 优先使用绝对日期，兼容中文和英文日期格式；没有绝对日期时解析相对时间。
- 有日期结果优先于无日期结果；全部无日期时保持 Bing 原顺序，取前五条。
- 搜索频道、搜索历史和显示端弹窗展示最多五条结果，语音 TTS 播报前三条。
- `fetchLimit`、`displayLimit`、`ttsLimit` 保存为 `search.web` 任务级全局配置，无需创建实例即可设置。
- 不改变搜索频道、搜索历史、TTS 和 `first_result` 响应协议。
- 搜索任务只返回 `data.result` 数组，不执行 TTS、搜索频道、历史或聊天等外部处理。
- 通过任务注册表暴露 `search.web`，语音调用和控制端手动调用共享同一实现。

## Spec 设计

- 新增纯函数解析 Bing 结果时间，传入 `now` 以便测试固定时间。
- 新增纯函数从候选结果中选择最新项；排序稳定，日期相同时保持 Bing 原顺序。
- `search.web.run` 只解析 `#b_results > li.b_algo` 前十项，再调用选择函数并截取前五条；语音层通过任务引擎注入的 runner 调用它。

## 自测用例

1. 中文绝对日期 `2026年8月21日` 能正确解析。
2. 英文绝对日期 `Aug 21, 2026` 能正确解析。
3. `1天前`、`1 day ago` 能按固定当前时间换算。
4. 十条候选中日期较新的结果排在前面并返回前五条。
5. 无日期候选排在有日期候选之后，全部无日期时按 Bing 顺序保留前五条。
6. 只解析真实 `b_algo`，不把嵌套或非结果 `li` 当成候选。
7. 控制端手动调用 `search.web` 返回标准任务结果，任务本身不产生 TTS、频道和历史副作用。

## 兼容性测试

- 系统搜索、LLM/Pi 搜索、搜索频道历史和 TTS。
- 语音调用和控制端任务列表手动调用。
- 中文 Bing 页面和英文 Bing 页面。
- 日期缺失、相对日期、绝对日期和日期相同场景。

## 性能测试

- 每次任务只请求一次 Bing 页面，仅增加前十条 DOM 文本解析和常量级排序，不启动 Chromium 或 Pi。

## 风险评估

- 搜索摘要日期代表 Bing 展示的页面/内容时间，不一定等于目标网页实际更新时间。
- 相对日期按当前服务器时间换算；只有天级信息时不推断具体时分秒。
- Bing 页面结构变化可能导致候选数量减少；无日期或无候选时保留既有错误/首条回退逻辑。
- 任务引擎手动调用会生成标准一次性实例记录；任务执行结束后不保留运行进程或会话。
