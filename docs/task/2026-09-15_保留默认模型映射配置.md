# 保留默认模型映射配置

## 任务描述

模型映射回归测试发现当前配置已包含 Qwen 映射，但配置服务的代码默认值仍为空数组。需要让新配置或旧配置缺少 `llm.defaultModelMappings` 字段时，默认保留：

```text
qwen3.5-0.8b -> qwen3.5-0.8b-claude-opus-distilled-mnn
```

显式保存空数组仍作为用户主动关闭映射的配置，不在每次读取时强行补回。

## Design 需求

- 默认模型映射属于 LLM 网关配置，不改变模型清单、模型文件或 `.mmap` 行为。
- 默认外部名为 `qwen3.5-0.8b`，内部模型 ID 为 `qwen3.5-0.8b-claude-opus-distilled-mnn`。
- 配置字段缺失时返回内置映射；已存在的显式配置，包括空数组，保持原值。

## Spec 设计

- `config-app-service.js` 的默认配置提供一条 Qwen 映射。
- `llm-local-routing.test.js` 验证读取到默认映射及其完整字段。
- 网关仍按 manifest 内部模型名/alias 优先、默认映射兜底的规则工作。

## 自测用例

1. 默认配置包含指定外部模型名和内部模型 ID。
2. 网关收到 `qwen3.5-0.8b` 时解析到指定内部模型 ID。
3. 已有配置中的显式空数组不会被读取逻辑自动补回。
4. 默认内部模型 ID 存在于 LLM manifest。

## 兼容性测试

- 保持已有 WebSocket `llm.defaultModelMappings.get/set` 协议不变。
- 保持已有 manifest alias 优先级和 ready 检查不变。
- 不涉及 APK 构建、模型复制或 `.mmap` 生成。

## 性能测试

- 默认值仅在配置初始化时复制，不增加每次 LLM 请求的模型扫描。
- 映射条目仍受既有 64 条和单字段 256 字符限制。

## 风险评估

- 新安装实例会多一个默认入口别名，但不会改变 `/v1/models` 的内部模型清单。
- 如果 APK 或服务器缺少该模型文件，请求仍由现有 ready 检查返回不可用错误，不伪造成功。
