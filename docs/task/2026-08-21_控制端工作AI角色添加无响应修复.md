# 控制端工作 AI 角色添加无响应修复

## 任务描述

修复控制端聊天面板点击“+”输入工作 AI 角色后无任何反应的问题，并确保角色列表、删除和历史请求都能通过 WebSocket 稳定处理。

## design 需求

- 角色管理消息在 WebSocket 服务初始化阶段显式注册。
- 添加/删除成功后广播最新角色列表。
- 角色服务异常返回 `roleError`，控制端可以显示错误提示。
- 保留通用控制消息回退逻辑，避免影响未迁移消息。

## spec 设计

- 新增角色 WebSocket handler 注册模块。
- `roleList` 返回角色列表。
- `roleAdd` 调用 `aiRoles.add` 后广播角色列表。
- `roleDelete` 校验并删除角色后广播角色列表。
- `roleHistory` 校验并返回角色历史。
- 所有 handler 使用 try-catch 将异常转换为 `roleError`。

## 受影响的功能模块和代码

- 控制端聊天角色 tab。
- WebSocket 服务端控制消息分发。
- `src/apps/server/modules/ai-roles/ai-roles-ws-handler.js`（新增）。
- `src/apps/server/boot/server-app.js`。
- AI 角色 WebSocket handler 单元测试。

## 自测用例

1. `roleList` 能返回空列表或已有角色列表。
2. `roleAdd` 成功后创建角色并广播 `roleList`。
3. `roleAdd` 重名或服务异常时返回 `roleError`。
4. `roleDelete` 成功后广播列表，不存在角色返回 `roleError`。
5. `roleHistory` 能返回角色历史，不存在角色返回 `roleError`。
6. 控制端点击“+”输入角色名后出现角色 tab。

## 兼容性测试

- Node.js WebSocket 单元测试。
- 现有 AI 角色 service/role-store 测试。
- 控制端浏览器 WebSocket 连接。

## 性能测试

- 角色管理消息保持同步文件操作，单次请求只读取一次角色列表。
- 不启动 Claude 进程，添加角色不会引入后台常驻进程。

## 风险评估

- 新 handler 与旧回退逻辑重复时可能造成维护分叉，因此服务启用新路由后移除 `role*` 的通用 handler 注册，回退分支仅作为无 WSViewBind 服务时的兼容路径。
- 角色持久化仍使用原有安全名称校验，不改变数据目录和协议字段。
