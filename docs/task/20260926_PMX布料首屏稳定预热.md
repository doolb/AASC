# PMX 布料首屏稳定预热

## 任务描述

修复 `mmd-ar` 页面刷新后，PMX 布料在模型出现后的短时间内轻微向上漂移。该问题发生在 PMX/Ammo 物理启动阶段，不属于 MindAR 跟踪或摄像头定位。

需求等级：L4，本地运行时启动稳定性修复；不改变远端配置、协议、模型资源或跨模块数据边界。

## Design 需求

- 依据：`docs/design/mmd-pmx-vmd-local.md` 的 PMX 原始单位与布料物理章节。
- 带刚体 PMX 首次加载时，在 staged 模型仍不可见的阶段预热物理；预热完成才将模型显示。
- 使用已经修复的 `scale = (1, 1, 1)` 物理网格，在 VMD 第 0 帧姿态下预热 180 步。不得将模型缩放问题重新引入预热流程。
- 显式切换 VMD 时继续使用 0 步预热，避免每次换动作都额外等待。
- 无刚体 PMX、物理初始化失败回退路径及 VRM 行为保持不变；不修改 Ammo vendor、模型、VMD、物理参数或相机。

## Spec 设计

先更新 `docs/spec/mmd-pmx-vmd-local.md` 的伪代码：

```text
首次 PMX load -> 建立不可见 stagedPivot -> 建 helper(warmup=180)
                 -> 预热完成后提交并显示 -> 下一帧开始正常 VMD/物理更新
切换 VMD -> 建 helper(warmup=0)，保留既有动作切换行为
```

## 受影响模块与代码

- `src/apps/web-mediacenter/ui/public/js/mmd-pmx-helper.mjs`：将 warmup 步数作为显式参数传入 helper；只在首次模型加载使用 180。
- `src/apps/web-mediacenter/ui/public/js/display-pmx-runtime.js`：初次 staged PMX 准备传入启动预热值，动作切换保持 0。
- `tests/mmd-pmx-helper.test.js`、`tests/display-mmd-runtime.test.js`：覆盖初次加载与动作切换的预热值、预热期间模型隐藏和无物理回退。
- `docs/design/mmd-pmx-vmd-local.md`、`docs/spec/mmd-pmx-vmd-local.md`、`docs/todo.md`、`changelog.md`：同步设计、实现及验证状态。

## 自测用例

1. 带刚体 PMX 首次加载传入 180 步预热；`MMDAnimationHelper.add` 完成前 stagedPivot 保持不可见。
2. 带/不带 VMD 的首次物理初始化都遵循同一启动预热；没有刚体时不初始化 Ammo、不预热。
3. VMD 动作切换仍传入 0 步预热；循环、单次播放、旋转和物理频率语义不变。
4. Ammo 初始化失败时仍回退无物理 helper，模型和 VMD 不因预热失败流程受到影响。
5. 运行 PMX helper、物理旋转、显示端 runtime 与 MMD AR 相关测试；测量预热的同步耗时，确认工作区中实际模型资源缺失时不声称完成真机视觉验收。

## 兼容性、性能与风险

- 兼容性：只对首载且确有刚体的 PMX 使用预热；VRM、无刚体 PMX、模型切换失败回退和后续动作切换不变。
- 性能：最多执行 180 次同步物理更新，会增加模型首屏可见前的 CPU 时间；记录自动化合成物理夹具耗时，真实米娅 PMX 与 Android WebView 需单独现场测量。
- 风险：只有当前物理网格保持单位缩放时预热才安全；若后续改动引入非单位缩放，必须先修复坐标/物理一致性再启用预热。
