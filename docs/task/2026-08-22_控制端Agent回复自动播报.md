# 控制端 Agent 回复自动播报

## 任务描述

控制端工作 AI 角色（Agent）回复目前只显示文字，不会像普通 LLM 回复一样在流式输出时自动生成并播放 TTS。补齐 Agent 流式回复的 TTS 路由，保持控制端播放、显示端播放和多显示端选择的既有语义。

## Design 需求

- Agent 回复使用与普通 LLM 相同的流式播报流程和目标：完整句子到达即生成 TTS，`playOnControl` 优先，其次 `displayIds`，最后 `displayId`；完成时冲刷尾句。
- Agent 文字流与历史记录协议不变。
- TTS 生成失败只记录日志，不影响文字回复完成。

## Spec 设计

```text
Agent chatChunk 增量
  -> 累积 pendingText
  -> chat.splitIntoSentences(pendingText)
  -> 完整句子逐句进入串行 TTS 队列
Agent chatResponse 完成
  -> 冲刷 pendingText 尾句
  -> 发送 chatResponse（不等待 TTS）
  -> stripMarkdown + tts.generateTTS
  -> playOnControl 或 tts/playAudio
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：Agent 分支接入 TTS 生成和路由。
- `tests/agent-chat-tts.test.js`：覆盖控制端、单显示端、多显示端和失败隔离。
- `docs/design/ai-roles.md`、`docs/spec/ai-roles.md`：同步 Agent 自动播报设计和伪代码。
- `docs/todo.md`、`changelog.md`：记录任务状态。

## 自测用例

1. Agent 完成回复且 `playOnControl=true` 时发送 `playOnControl`，不发送显示端 TTS。
2. Agent 完成回复且选择一个显示端时发送 `tts/playAudio`。
3. Agent 完成回复且选择多个显示端时向每个显示端发送 TTS。
4. Markdown 标记在生成 TTS 前被清理。
5. TTS 生成失败时文字 `chatResponse` 仍保留，后续句子继续处理。
6. Agent 流式增量产生完整句子时立即进入 TTS；完成事件只处理尾句，不重复播报前面的句子。

## 兼容性测试

- 普通 LLM 既有聊天流式、TTS 和控制端播放测试保持通过。
- Agent `chatChunk`、`chatResponse`、角色历史和请求号行为保持不变。
- 未选择播放目标时不新增无目标下发。

## 性能测试

- 句子 TTS 生成串行执行，避免音频顺序错乱。
- 不新增轮询或模型请求；每个 Agent 回复仅按句生成一次音频。

## 风险评估

- 低：仅复用既有 TTS 服务和 WebSocket 播放协议。
- Agent 与普通 LLM 统一按流式完整句子生成语音；TTS 队列串行执行，避免音频顺序错乱。
