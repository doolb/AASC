# RTMPose-m增加人体三维辅助模型评估

状态：可行性调研与试验方案，待用户确认；本轮未修改运行代码、下载新模型或执行新推理。

## 需求与范围

用户询问“RTMPose-m可不可以加上深度估计模型”。沿用已明确的浏览器/手机本地ONNX、静态图片及全身IK唯一入口。目标是改善手脚前后、躯干与屈膝的三维估计；不将像素表面深度直接当人体内部关节，不承诺恢复真实相机/绝对距离。

## 方案与证据

- 当前RTMPose-m Body7只给17点二维；旧MediaPipe有估计world，本项目保留兼容解码，但示意图可靠姿态失败、坐姿腿部偏差已有历史证据，不能默认其深度就是正确答案。
- 首选试验：RTMPose-m保留原图二维约束，另对同一原图/同一人物运行RTMW3D，核对三轴SimCC、裁剪、轴向、尺度和关节语义后，将三维骨段构型作为软先验交给已有真实PMX FK/限位拟合。RTMW3D读图片，不是接收RTMPose17点的附加z头。
- 对照：当前FK、RTMPose+旧MediaPipe三维先验、RTMPose+RTMW3D先验；MediaPipe失败保留真实失败，不用低可信点补齐。
- 备选：单帧2D→3D Pose Lifter可消费二维点，但需核对COCO/H36M语义及训练归一化；视频多帧模型不当静态照片模型直接套用。先不新增此路线权重。
- Depth Anything V2默认模型输出相对像素深度图；被遮住的膝踝取样会落到前景衣服或另一条腿上，只能另作表面/遮挡辅助，不能替代关节三维模型。故不作为本轮主线。

参考：官方[MMPose/RTMW论文](https://arxiv.org/abs/2407.08634)、[rtmlib三维ONNX推理](https://github.com/Tau-J/rtmlib/blob/main/rtmlib/tools/pose_estimation/rtmpose3d.py)、[RTMW3D权重接线](https://github.com/Tau-J/rtmlib/blob/main/rtmlib/tools/solution/wholebody3d.py)、[OpenCV旧模型解码](https://github.com/opencv/opencv_zoo/blob/main/models/pose_estimation_mediapipe/mp_pose.py)、[Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)。这些说明路线存在，不代表本机浏览器或手机已验证。rtmlib把xy与z按不同规则解码，不能不核对就把三分量当统一米制坐标。

## 风险、性能与预计工作量

三维模型同样会误判二次元/遮挡；错误先验需低权或拒绝，不能让错误深度压过清晰二维和关节硬约束。单图深度/相机多解仍在；ONNX存在不代表ORT Web算子/内存/手机性能已支持。临时试验预计0.5～1天，导出/量化/手机适配如遇问题另报，正式接入依试验结果评估。本轮无额外生产依赖、APK、Offline状态或发布变更。
