# 恢复显示端 ASR 提供端选择

## 任务描述

恢复 ASR 设备“服务端/显示端”选择。录音显示端仍统一调用服务端公共 `/api/asr/recognize`，选择“显示端”时由服务端按现有显示端连接顺序选择 ASR 提供端，不固定优先某个 IP。

## Design 需求

- 192.168.1.39 可以只负责录音，不直接调用自己的 ASR。
- 192.168.1.6 开启 ASR 提供能力后，可被服务端选为提供端。
- 选择提供端严格复用之前的连接顺序，不对 192.168.1.6 做特殊优先。
- `voiceRecognition` 表示本地 ASR 提供能力，`voiceSupported` 表示公共 ASR 可用性。

## Spec 设计

```text
录音显示端:
    PCM/WAV 分段
    POST /api/asr/recognize

服务端:
    device == server -> asr.recognize(file)
    device == display -> 按 displayClients 迭代顺序查找 voiceRecognition=true
                         发送 asrAudio 给第一个提供端

被选显示端:
    NativeDisplay ASR 识别
    返回 asrResult
    服务端转换为公共接口 text/speaker/segments 响应
```

## 自测用例

1. ASR 设备页面同时显示服务端和显示端选项。
2. 选择显示端时不按 IP 固定优先，按连接顺序选择第一个可用提供端。
3. 录音显示端只 POST 公共接口，不调用自己的本地 ASR。
4. 被选 Android 显示端仍能处理 `asrAudio` 并回传 `asrResult`。
5. 192.168.1.39 与 192.168.1.6 的能力状态可分别显示。

## 实现结果

- 已恢复控制端“服务端/显示端”ASR 选择；录音显示端仍只提交公共 `/api/asr/recognize`。
- `display` 模式通过 `displayClients` 插入顺序选择第一个 `voiceRecognition=true` 的显示端，不包含任何 IP 优先级。
- 192.168.1.39 当前为 `voiceRecognition=false` 的录音端，192.168.1.6 当前为 `voiceRecognition=true` 的 APK 提供端。
- APK 提供端恢复 `asrAudio`、原生异步 ASR 和 `asrResult` 回传；普通浏览器不会被选为提供端。
- 自测：相关 Node 回归 45/45；服务端/前端语法检查和 `git diff --check` 通过；`zh.wav` 公共接口经显示端路由识别成功。
