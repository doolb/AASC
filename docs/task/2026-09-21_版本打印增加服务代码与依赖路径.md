# 任务：版本打印增加服务代码与依赖路径

## 任务描述

在已有控制端运行版本打印中增加服务代码实际路径和依赖实际路径，解决只看 `v4` 无法确认进程是否真的使用热更依赖目录的问题。

## Design 需求

- 版本信息继续显示 APK、服务代码、依赖和显示端版本。
- 新增 `codePath`、`dependenciesPath`、`dependencySource`。
- 路径必须来自 Node 进程实际运行参数：代码路径取代码入口根目录，依赖路径取 `AASC_NODE_MODULES_DIR` 或默认根依赖目录。
- 不改变依赖选择、热更新、APK 原生逻辑和模型资源。

## Spec 设计

- `getRuntimeVersionInfo` 接收项目根目录、代码根目录和依赖根目录。
- 服务端 AASC 节点 metadata、`/api/status` 共用同一版本信息对象。
- 控制端服务器摘要和服务器卡片统一渲染路径字段，并对文本做 HTML 转义。

## 受影响的功能模块和代码

- `src/apps/server/modules/aasc/runtime-version-info.js`
- `src/apps/server/boot/server-app.js`
- `src/apps/web-mediacenter/ui/public/js/server-list.js`
- `tests/runtime-version-info.test.js`
- `tests/server-list-ui.test.js`
- `docs/design/runtime-version-display.md`
- `docs/spec/runtime-version-display.md`

## 自测用例

1. active release 存在时，版本字段仍优先使用 active release。
2. 传入独立代码根目录和依赖根目录时，返回绝对路径。
3. `legacyDependencies=true` 时来源显示为 `legacy-root`。
4. 控制端服务器摘要和卡片显示服务代码路径、依赖路径。
5. 路径包含 HTML 特殊字符时不会产生未转义标记。

## 兼容性测试

- 没有新版本字段的旧 AASC 节点继续显示原有版本号。
- 没有 active release 的普通服务继续回退到 APK/项目基线。
- 不需要重新构建 APK 或依赖包。

## 性能测试

- 版本读取只增加两个路径拼接和字符串格式化，不扫描目录、不读取模型、不增加服务启动 I/O。

## 风险评估

- 低风险：新增字段只读，不改变服务启动和依赖加载。
- 路径字段可能较长，前端使用可换行文本显示，避免撑破服务器卡片。

## 预计工时

- 约 30 分钟，包含定向测试和文档同步。
