# 2026-10-12：MMD-AR IK 镜头手势与 VaM 风格膝盖控制

## 任务描述与授权

用户确认 IK 开启时空白处可拖动相机、IK 控制点继续拖动骨骼，并确认增加左右膝控制点及改善深屈膝；同时反馈左右镜头环绕方向相反，要求反转。IK 关闭时保留原模型旋转/平移手势。

需求等级：镜头操作为 L5 业务行为，旋转/平移接口为 L6；膝盖控制是 L5 交互与 L6 求解器约束。整体跨层但分模块落地。风险中等，需维持控制点事件捕获、脚踝/膝盖多目标求解与 PMX 限位的一致性。

范围：反转 IK 相机水平环绕；增加左右膝可拖动目标；提高求解轮数；仅膝骨允许相对本帧原姿态最多150°修正，其他骨骼保持45°；如 PMX 提供 IK link 范围，则始终执行该范围。保留头/手/脚控制、IK关闭时旧模型手势、AR跟踪相机权威。目标是接近 VaM 的膝节点控制和深屈膝观感，不实现其关节 comply/弹簧、软体或皮肤碰撞物理。

## 设计与伪代码

- 设计文档：`docs/design/mmd-human-interface.md` 的“IK 操作时的镜头手势”与“VaM 风格的 PMX 膝盖控制与屈曲”。
- 实现前伪代码：`docs/spec/mmd-human-interface.md` 对应章节。
- 指针按下时锁定 IK 会话用途；IK 开启时左拖环绕相机，水平 yaw 使用负的像素增量；右拖/双指中心拖平移，捏合/滚轮缩放。命中 IK 控制点优先于画布手势。
- IK 开启时控制点含头、左右腕、左右膝、左右踝；未拖动点跟随语义骨骼，拖动点锁定到相机朝向平面目标。
- 活动目标按轮次交替执行一次 CCD 扫掠，最多12轮、单步最多15°；各链节先限制相对本帧基准修正，再应用原 PMX IK link 角度范围。膝骨最大修正150°，其余骨骼45°；最终统一检查各目标误差。
- IK 关闭时保留旧模型手势。AR 跟踪直接驱动相机期间拒绝自由相机写入；不新建 RAF、持久化配置或碰撞扫描。

## 自测、兼容性与性能

1. IK 开启时从空白处向右拖，镜头按反向轨道方向左绕；向左拖则相反；IK关闭时模型旋转方向不变。
2. IK 开启后显示头、腕、膝、踝控制点；拖动单膝可改变膝节点位置，拖脚控制踝目标；同时拖膝和脚时最终误差按全部目标统计。
3. 深蹲或收腿目标下膝关节可超过旧45°上限；PMX提供的最小/最大角度仍是最终约束，其他骨骼仍受45°基准上限。
4. IK控制点拖动不触发相机或点击注视；双指平移/缩放、桌面右键平移、IK关闭旧手势、pointercancel、AR相机保护全部回归。
5. 使用真实 PMX 浏览器夹具检查控制点可见及拖动后的画面变化；目标与模型缺少膝语义骨骼时优雅隐藏该膝点并显示能力状态。

兼容范围：标准日文 PMX 和英语 Humanoid 膝骨别名；无膝骨的非标准模型沿用其余控制点。性能预算为每帧最多7个活动末端×12轮×每链最多12节骨骼；仅拖动控制点时执行求解，普通帧无新遍历/RAF。浏览器和手机帧时需作为限制记录。

## 风险评估与预计工时

- 膝目标与脚踝目标在同一腿链上可能互相竞争；用轮次交替求解，并在全部目标之后统一测距、报告最终不可达状态。
- 150° 是膝骨相对当前动画姿态的上界，不替代 PMX 限位；Euler 限位模型异常时按已有 PMX 解析范围和不可达状态处理，不能强行覆盖模型约束。
- 更高迭代预算最多使活动目标的单帧计算量约翻倍；仅用户拖动期间触发，仍须通过真实浏览器与构建检查。
- VaM 控制节点与物理关节系统不等价；当前任务只实现可拖膝节点和深屈膝，不宣传完整物理复刻。
- 预计 1–2 个开发日，含代码、定向测试、浏览器回归、WEB构建和文档同步；手机触控观感单独验收。
