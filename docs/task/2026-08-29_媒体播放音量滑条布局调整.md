# 媒体播放音量滑条布局调整

## 任务状态

- ✅已完成 [2026-08-29][2026-08-29]

## 任务描述

将控制端主显示控制区的音量滑条移动到媒体播放进度条下面，让播放进度和音量控制形成连续的媒体控制区域。

## Design 需求

- 主控制区媒体播放控件按播放控制、进度、音量的顺序排列。
- 音量滑条紧跟 `progressSlider`，不再位于文本模式控件之后。
- 快捷控制面板的独立音量滑条不调整。

## Spec 设计

```
媒体播放 control-item:
    播放控制行
    progressSlider
    volumeValue + volumeSlider

保持:
    DOM id 不变
    updateProgress/updateVolume 不变
    seek/volume WebSocket 协议不变
```

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/upload.html`：调整主媒体播放区域的 DOM 顺序。
- `docs/design/control.md`：补充媒体播放控件布局设计。
- `docs/spec/upload.md`：同步布局伪代码和交互协议。
- `tests/media-control-layout.test.js`：验证进度条后紧接音量控件，且快捷控制面板未被改动。

## 自测用例

1. 解析主显示控制区，确认 `progressSlider` 后紧接 `volumeSlider` 所属音量控件。
2. 确认 `volumeSlider`、`volumeValue`、`updateVolume` 未改名，原有音量协议仍可用。
3. 确认 `floatingVolumeSlider` 仍存在且未移动。
4. 执行相关 Node 测试、页面脚本语法检查和 `git diff --check`。

## 兼容性测试

- 保持桌面浏览器、移动浏览器使用原生 `range` 控件。
- 不改变显示端 `display.html`、服务器音量协议和快捷控制面板行为。

## 性能测试

- 仅调整静态 HTML 节点顺序，不增加脚本监听器、网络请求或运行时计算。

## 风险评估

- 低风险：控件 ID、内联事件、JavaScript 查询选择器和 WebSocket 消息均保持不变。
