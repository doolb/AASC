# 任务：显示端等待唤醒时执行内置指令

## 任务描述

显示端开启语音监听但处于 `waitingWake` 时，当前服务端会把所有非唤醒词识别文本丢弃，导致“现在几点”等内置功能指令无法执行。调整为内置功能指令免唤醒直通，同时继续拦截普通聊天和自定义命令。

## Design 需求

- `waitingWake` 状态允许现有内置功能指令直接执行。
- 内置指令执行后保持 `waitingWake`，不会隐式进入群聊或私聊。
- 普通聊天、自定义关键词命令、唤醒/对话控制词仍遵守原有唤醒状态机。
- ASR、声纹门控、监听开关和激活状态下的命令流程保持不变。

## Spec 设计

```text
显示端最终 voiceInput(text):
    先广播有效识别文字
    声纹未匹配 -> 结束，不进入任何命令处理
    如果 data.isFinal 且 text 非空:
        conversation = handleDisplayConversationInput(displayId, text)
        如果 conversation 未接受:
            如果 conversation.state == waitingWake 且 isBuiltinVoiceCommand(text):
                直接进入 voiceCommand 处理
            否则记录忽略并结束
        如果 conversation.event.type == input:
            进入 voiceCommand 处理

isBuiltinVoiceCommand(text):
    使用 voiceCommand 的统一内置功能指令识别规则
    返回 true -> 报时、提醒、静音、天气、搜索、播放等内置功能
    返回 false -> 普通聊天、自定义命令和会话控制词

内置指令执行后:
    不改变 waitingWake
    不启动 active 对话超时计时器
```

## 自测用例

1. `waitingWake` 下输入“现在几点？”被接受为内置指令。
2. `waitingWake` 下输入“你好，今天过得怎么样”仍被忽略，不能当普通聊天处理。
3. `waitingWake` 下输入“你好小爱”仍进入 `activeGroup`。
4. 内置指令直通后会话仍为 `waitingWake`，不启动 3 分钟激活计时。
5. 已激活状态下内置指令和普通语音行为不变。
6. 声纹未匹配结果仍只回传控制端，不执行内置指令。

## 兼容性测试

- 浏览器显示端和 Android 显示端统一适用。
- 旧 Go/C#/Node 子显示端继续走原有流程。
- 控制端发送的 `voiceCommand` 不改变。
- 内置指令关闭/开启指令模式时不改变原有配置持久化逻辑。

## 性能测试

- 每条最终识别文本只进行一次内置指令分类，不增加 ASR 请求。
- 不新增定时器；`waitingWake` 下内置指令不启动会话计时器。

## 风险评估

- 内置指令识别范围扩大后，环境中的语音可能触发静音、播放或提醒等操作；范围限定为已有明确关键词的内置功能，不放行普通聊天和自定义命令。
- 分类规则必须与 `processVoiceCommand` 共用，避免门控允许但实际解析不执行。
