# 网页显示端语音模型启动预热

## 任务描述

在第一条语音请求前，由网页显示端根据已有服务端配置主动触发正式 APK 的 ASR 和声纹模型加载。只修改网页显示端，不修改 Android 原生层、服务端、控制端或 WebSocket 协议。

## design 需求

- WebSocket 建立后读取已有 `/api/config/asrDevice` 与 `/api/voiceprint/config`。
- ASR 设备为 `display` 时调用已有 `NativeDisplay.asrStatus()`/`asrEnsureModel()`。
- 声纹配置读取后复用已有 `NativeDisplay.voiceprintConfigure()` 和声纹库同步流程，保持现有启用/禁用及提取模式兼容。
- 预热请求按配置键去重，配置变更时允许重新加载；失败不阻塞页面和首请求回退。

对应设计：`docs/design/android-display.md`。

## spec 设计

- 在 `display.html` 增加页面级预热状态和 `prewarmDisplaySpeechModels()`。
- 在 WebSocket `onopen` 触发预热；复用现有 `asrConfig`、`voiceprintConfig` 状态处理和 NativeBridge 回调。
- 不新增服务端消息、HTTP 接口、Android 方法或模型文件。

对应伪代码：`docs/spec/android-display.md`。

## 受影响功能模块与代码

- 网页显示端：`src/apps/web-mediacenter/ui/public/display.html`。
- 静态契约测试：新增 `tests/display-speech-model-prewarm.test.js`。
- Android 原生、服务端和控制端不改。

## 自测用例

1. WebSocket 建立后，ASR 只在设备为 `display` 时调用预热接口，声纹按现有配置流程调用。
2. 相同配置的 HTTP 结果和 WebSocket 配置不会重复调用 NativeBridge。
3. 配置变更生成新配置键时可以重新触发配置。
4. NativeBridge 不存在、HTTP 请求失败或模型状态为内存不足时，页面不抛出未处理异常。
5. 页面刷新/重连清除本轮去重状态，下一次连接可重新预热。

## 兼容性测试

- 普通浏览器显示端没有 NativeBridge 时不影响原有 WebSocket、ASR 和声纹流程。
- 旧版 APK 没有相关桥方法时只跳过预热，不影响已有请求路径。
- 正式 APK 使用现有 `asrEnsureModel`/`voiceprintConfigure`，不要求重新编译 Android 原生层。

## 性能测试

- 预热只在 WebSocket 建立后执行一次，配置相同的重播消息不重复下载/加载。
- 两个配置查询异步执行，不阻塞页面连接和录音启动。
- 服务端模式不触发显示端模型下载，避免无效内存和带宽占用。

## 风险评估

- 页面启动时预热可能与 WebSocket 配置消息同时到达，因此必须使用配置键去重。
- Android 原生桥状态仍由既有回调报告，网页只能提前触发，不能改变原生资源释放策略。
- 网络不可用时预热失败，保留既有首请求重试和错误显示行为。

## 预计工时

- 网页预热协调和去重：1 小时
- 静态契约测试与文档同步：0.5 小时
