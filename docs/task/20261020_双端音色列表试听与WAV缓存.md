# 双端音色列表试听与 WAV 缓存

日期：2026-10-20
状态：源码与定向测试完成；真实账号和 Android 设备听感待验收。

## 任务描述

控制端、显示端共用音色面板的每个目录项增加试听。服务端随机选固定短句，按该项音色合成；页面自己缓存最多 30 份 WAV，重播直接从页面内存播放。试听不改变当前音色配置。

## 设计需求

见 `docs/design/tts-providers.md` 的“双端音色列表试听”。用户明确要求缓存 WAV 文件本身由音色界面维护；缓存是页面内存，不仅保存临时 URL。

## Spec 设计

见 `docs/spec/tts-providers.md` 同名伪代码。WebSocket `previewTtsVoice` 请求只允许 Provider、voice、requestId；服务端随机短句合成后用 `ttsVoicePreview` 返回音频 URL。页面下载 WAV 到 Blob 对象 URL，LRU 最多 30 条，淘汰释放 URL。重复点击直接本地播放。

## 受影响模块与代码

- `src/apps/server/modules/tts/tts-provider-ws.js`：试听身份/字段校验、固定短句及合成回包。
- `src/apps/server/boot/server-app.js`：控制端和显示端消息注册/转交。
- `src/apps/web-mediacenter/ui/public/js/websocket.js`：控制端试听回包分发。
- `src/apps/web-mediacenter/ui/public/js/tts-voice-picker.js`、`css/tts-voice-picker.css`：两端共用列表按钮、本地 WAV 缓存和状态。
- `tests/tts-provider-ws.test.js`、双端音色浏览器测试：协议与交互回归。

## 自测用例

1. 点击试听合成固定短句且指定 Provider/音色，选择权威值不变；点击选择仍保存。
2. 同一项再次点击不发合成请求，直接播放同一份页面 WAV；关闭再打开仍能重播。
3. 30 项上限、最近使用淘汰及对象 URL 释放；语速/音量/模型变化不误用旧缓存。
4. 服务端拒绝未登记身份、非法字段和 system 无目录试听；生成失败、下载失败、播放失败可恢复。
5. 双端列表布局、选中/未选中主题样式、键盘焦点、手机与横屏面板不溢出。

## 兼容性测试

`npm run test:tts-voice-picker`；现有音色保存、查询和跨端广播回归。旧客户端继续使用原选择消息，不受新试听消息影响。

## 性能测试

页面缓存项数不超过 30；短句只生成单段，重播不调用服务端。检查 LRU 淘汰后对象 URL 被释放，避免重复试听持续增长。

## 风险评估

主要风险是在线 Provider 合成耗时、浏览器拒绝异步音频播放和大量 WAV 占用内存。合成与播放错误需可见、可重试；30 条上限控制引用数量，实际音频大小仍由既有 16 MiB 单段限制约束。真机听感与授权播放行为需现场验收。
