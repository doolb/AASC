# APK 控制端入口边缘收缩

## 任务描述

将 Offline/普通 Android APK 的原生“控制端”入口改为左侧边缘收缩标签。点击收缩标签时只展开完整按钮，第二次点击完整按钮才打开控制端页面；关闭控制端页面后恢复收缩状态。

## Design 需求

- 复用现有 `controlPageAllowed` 授权和 Offline 默认显示规则。
- 收缩态不打开 WebView，只改变入口按钮外观和尺寸。
- 展开态显示原有“控制端”文案；点击后沿用原有 `/control` WebView 加载逻辑。
- 关闭控制端页面、服务端取消授权或返回显示端时恢复收缩态。
- 不改变显示 WebView、控制 WebView、启动遮罩和更新卡片的图层顺序。

## Spec 设计

```text
controlButtonState = COLLAPSED

点击 controlToggleButton:
    if 未获授权:
        忽略
    else if controlWebView 不可见 and controlButtonState == COLLAPSED:
        controlButtonState = EXPANDED
        显示完整“控制端”按钮
    else:
        按原逻辑显示或隐藏 controlWebView
        如果隐藏 controlWebView:
            controlButtonState = COLLAPSED

设置入口授权或恢复显示页:
    controlButtonState = COLLAPSED
    按原授权规则决定按钮是否可见

布局变化:
    controlToggleButton 保持贴合左侧边缘
    controlToggleButton 始终位于控制 WebView 上方
```

## 自测用例

1. Offline APK 授权后默认显示收缩标签。
2. 第一次点击只展开完整按钮，控制 WebView 仍隐藏。
3. 第二次点击才显示控制 WebView 并加载 `/control`。
4. 关闭控制页、返回显示页或撤销授权后恢复收缩态。
5. 普通 APK 未授权时入口保持隐藏。
6. 旋转或尺寸变化后入口仍贴合左侧边缘，且不改变 WebView 层级。

## 兼容性测试

- 普通 APK 和 Offline APK 共用入口状态逻辑。
- Display 2、横竖屏和高 DPI 设备检查入口尺寸及触摸区域。
- Android 返回键关闭控制页后只恢复收缩标签，不回退控制 WebView 历史。

## 性能测试

- 收缩/展开只更新一个原生按钮，不触发 WebView reload。
- 不新增权限、服务、定时器或网络请求。

## 风险评估

- 双击或快速连续点击可能在展开和打开页面之间产生误触；点击状态机必须在主线程串行执行。
- 入口仍需保持在控制 WebView 上方，避免再次出现“按钮可点击但页面被遮挡”。

- Debug 构建和真机启动/点击验证：约 0.5 小时。
