# APK 内置 Node.js 子服务器

## 任务描述

将 `apk-display` 改造为内置 Node.js 子服务器的 AASC 节点。APK 启动器启动 Node.js 双进程服务，子服务器主动连接主服务器；WebView 显示端仍连接主服务器 `/display`。

## Design 需求

- 首版只支持 `arm64-v8a`、Android 8/API 26+。
- Node.js Runtime、服务器运行包解压到 APK 私有目录。
- Android Service 启动 `server-launcher.js`，launcher fork `server-app.js`。
- 子服务器角色固定为 `subserver`，主服务器地址默认 `https://192.168.1.39:8081` 且可手动修改。
- 不启用 ASR 隔离、Wine、Puppeteer、外部 CLI、桌面 TUI 等额外子进程能力。
- 显示端仍加载主服务器 `/display`，媒体库由子服务器提供并通过 AASC 主动连接管理。

## Spec 设计

详见 `docs/spec/android-embedded-node-server.md`：Runtime 校验安装、节点配置、双进程生命周期、主动连接、显示端地址和失败处理伪代码。

## 受影响功能模块和代码

- Android `MainActivity`、Manifest、Gradle 和新增 `NodeServerService`/Runtime 安装器。
- Node.js 服务器启动参数、Android 能力开关和运行目录适配。
- Android Node Runtime/服务器包构建与校验脚本。
- Android 单元测试、Node.js 契约测试和 APK 构建验证。

## 自测用例

1. 首次启动能校验并安装 Runtime，随后启动 launcher 和 server-app。
2. WebView URL 为主服务器 `/display`，不是本机 URL。
3. 子服务器主动注册、心跳和断线重连正常。
4. 主服务器控制端可看到 APK 节点并聚合媒体库。
5. APK 媒体库能浏览目录、上传、删除和 Range 播放。
6. server-app 崩溃由 launcher 重启；launcher 异常由 Android Service 退避恢复。
7. 停止服务不残留 Node 子进程。
8. ASR/Wine/Puppeteer/外部 CLI 不启动且返回明确不可用错误。

## 兼容性测试

- Android 9 arm64 真机：安装、启动、主服务器连接和媒体库操作。
- Android API 26 模拟器或真机：Runtime 安装、Service 生命周期和 WebView 主服务器加载。
- 主服务器 HTTP/HTTPS 地址手动切换；自签名证书提示不影响页面加载。
- 主服务器不可达、局域网地址变化、本地端口占用和 Runtime 校验失败。

## 性能测试

- 首次 Runtime 安装时间和 APK 私有目录占用。
- Service 启动后 Node 内存占用和 30 分钟空闲稳定性。
- 大文件 Range 播放不复制到主服务器内存。
- 主服务器断线重连不产生重复 launcher 或 Node 进程。

## 风险评估

- Node.js Android Runtime 和部分 npm 原生依赖可能需要独立 arm64 构建；不兼容依赖必须隔离，不能阻塞基础服务。
- Android 后台限制可能影响长期保活，首版依赖前台 Service，不承诺厂商级永久保活。
- APK 节点 HTTPS 证书属于内网测试边界，首版不实现认证。
- 进程树终止和 server-launcher 的 fork 行为需要真机验证，避免出现孤儿进程。
- APK 体积会因 Node Runtime 和 node_modules 增加，需要构建产物检查。

## 预计工时

Runtime 打包链路 1 天；Android Service 和配置 1 天；Node.js Android 能力裁剪 0.5 天；测试、构建和真机验证 1 天。Node Runtime 若需从源码移植，另行增加构建周期。
