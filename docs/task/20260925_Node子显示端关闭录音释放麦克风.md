# Node 子显示端关闭录音能力时释放麦克风

## 任务描述

控制端关闭 `voiceRecording` 后，Node 子显示端仍持有底层麦克风设备。修复能力关闭、WebSocket 断开及重连期间的采集生命周期，并保证服务端保存的关闭覆盖对 Node 子显示端生效。

## design 需求

- Node 子显示端首次连接和重连时，先等待服务端权威 `capabilitiesUpdated`，收到允许前不得打开麦克风。
- `voiceRecording=false` 停止录音循环并释放 PvRecorder/AudioIO 设备；未完成的 ASR 结果不再进入语音处理。
- `voiceRecording=true` 且 ASR 就绪后重新建立单一采集流；短时 TTS 暂停仍复用当前流。
- 断线时释放麦克风并使此前的能力确认失效。
- 服务端对 Node 子显示端恢复 `userCapabilities`，并将用户覆盖值合并到子显示端默认能力中。

## spec 设计

显示端连接：

```text
服务器初始化子显示端能力为 SUB_DISPLAY_CAPABILITIES
如果 savedState.userCapabilities 存在:
    规范化并恢复 userCapabilities
    capabilities = merge(SUB_DISPLAY_CAPABILITIES, userCapabilities)
收到子显示端 capabilities 声明:
    capabilities = merge(SUB_DISPLAY_CAPABILITIES + 硬件声明, userCapabilities)
    下发 capabilitiesUpdated
```

Node 子显示端：

```text
启动/重连:
    recordingEnabled = false
    voiceRecordingCapabilityKnown = false
    等待服务器 capabilitiesUpdated

capabilitiesUpdated:
    voiceRecordingCapabilityKnown = true
    如果 voiceRecording !== true:
        recordingEnabled = false
        recorder.stop()  // 关闭并释放底层采集设备
    否则:
        recordingEnabled = true
        ASR 就绪 -> 启动采集

断线:
    voiceRecordingCapabilityKnown = false
    recordingEnabled = false
    recorder.stop()

ASR 请求完成:
    再检查录音能力；能力已关闭 -> 丢弃结果
```

对应实现伪代码：`docs/spec/display-capability.md`。

## 自测用例

1. 关闭 `voiceRecording` 后系统麦克风占用指示熄灭，录音器停止并释放设备。
2. 正在上传 ASR 时关闭能力，结果返回后不进入语音命令处理。
3. 重新开启能力后，ASR 就绪时恢复单一采集流；TTS 暂停/恢复仍正常。
4. 关闭后重连，服务端仍返回 `voiceRecording=false`；收到权威配置前不访问麦克风。
5. WebSocket 断开时释放采集设备；重连后按服务端最新能力恢复。

## 兼容性测试

- 子显示端继续声明自身硬件能力；服务端用户覆盖值优先于该声明。
- 网页显示端能力恢复逻辑保持原有默认能力和用户覆盖行为。
- TTS 播放期间的临时暂停仍调用录音器 `pause()`，不反复关闭、打开硬件设备。
- 未收到服务器能力确认时按关闭处理，避免因旧服务器或消息延迟提前启用麦克风。

## 性能测试

- 能力关闭时不轮询、不持有麦克风设备；能力开启时最多运行一个录音循环。
- 能力状态变化不增加 WebSocket 轮询或 ASR 请求。

## 风险评估

- 首次连接必须等服务端回传权威能力后才能录音，旧服务端若不发送 `capabilitiesUpdated`，子显示端将保持麦克风关闭。
- 重新开启时需等上一次录音 Promise 完成后再创建采集器，避免底层设备并发占用。
- 操作系统设备指示与具体驱动释放时机需在目标 Windows 节点现场验收。

## 执行结果

- 已完成：Node 子显示端在服务端确认录音能力前保持关闭；能力关闭和连接断开都会停止采集器并释放底层输入设备；能力重新开启时等待旧录音 Promise 结束再启动。
- 已完成：PvRecorder 停止时即使 `stop()` 抛错也继续调用 `release()`；两类采集器重新启动时清除旧暂停状态。
- 已完成：服务器重连初始化对 Node 子显示端应用已保存的 `userCapabilities`，避免客户端 `voiceRecording=true` 声明覆盖持久化关闭状态。
- 未运行自动化测试；目标 Windows 子显示端麦克风占用指示、重连和启停仍待现场验收，见 `docs/todo.md`。
