# 显示端重连恢复声音输出设备

## 任务描述

控制端选择的声音输出设备已经由服务端按 `displayId` 保存。显示端 WebSocket 重连或页面重新加载时，必须使用服务端下发的上次保存值重新建立原生输出路由；不能因为页面内存中的 key 没变化而跳过应用。

## design 需求

- 保留现有 `setAudioOutputConfig` 的服务端持久化和 `audioOutputConfig` 权威下发。
- 网页显示端每次收到服务端 `audioOutputConfig` 都重新调用已有 `applyAudioOutputDevice`。
- 设备不可用时保留请求 key，并通过既有状态消息回报回退，不覆盖服务端保存值。

## spec 设计

- `handleAudioOutputConfig(data)` 规范化 `data.deviceKey`。
- 将服务端配置视为重连恢复指令，无论 key 是否变化都调用 `applyAudioOutputDevice`。
- 原生路由成功或回退后继续通过 `audioOutputStatus` 回报控制端。

对应伪代码：`docs/spec/android-display.md`。

## 受影响功能模块与代码

- 网页显示端：`src/apps/web-mediacenter/ui/public/display.html`。

## 自测用例

1. 服务端下发与页面内存相同的输出设备 key 时，网页仍调用原生输出路由。
2. 服务端下发不同 key 时，网页调用新 key。
3. 原生设备不可用时，保留请求 key 并回报 fallback/error 状态。
4. 控制端选择后服务端仍按 displayId 持久化，后续重连继续下发该值。

## 兼容性测试

- 没有 NativeBridge 输出接口的浏览器显示端继续回报 unsupported，不影响页面连接。
- 旧版 Android 显示端忽略未知 `audioOutputConfig`，不影响既有音频播放。
- 系统默认输出 key `default` 继续支持恢复和回退。

## 性能测试

- 仅在收到服务端输出配置时调用一次路由，不增加轮询。
- 输出设备 key 仍限制为最多 512 个字符。

## 风险评估

- WebSocket 重连时强制路由可能触发一次系统音频路由切换，但能避免页面内存状态与原生实际状态不一致。
- 输出设备断开时不删除保存 key，设备恢复后可再次自动尝试使用。

## 预计工时

- 网页恢复条件修复：0.25 小时
- 回归测试和文档同步：0.5 小时

## 执行结果

- 已完成：`display.html` 收到服务端 `audioOutputConfig` 时无条件重新调用 `applyAudioOutputDevice`，相同 key 也会重新建立原生输出路由。
- 已保留：服务端按 `displayId` 持久化 `audioOutputDeviceKey`，设备暂时不可用时不覆盖保存值，只回报 fallback/error 状态。
- 验证通过：显示端音频/输出设备及相关声纹回归测试 13/13、内联脚本语法检查、`git diff --check`。
- 未修改 Android 原生层、服务端和控制端，不需要重新构建 APK。
