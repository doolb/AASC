# HMR2.0b FP32与FP16精度对照

日期：2026-10-19。状态：独立测试完成；未生成或修改正式服务/前端/模型源码。

## 范围与公平性

用户希望测试HMR FP32与FP16区别。使用既有HMR2.0b checkpoint、官方本机补丁和真人坐姿/动漫跪坐/交叉腿示意图三份实际xyxy输入。A为网络FP32，B为ViT+head参数/输入FP16（含head内6D旋转解码）；两模式SMPL LBS及相机投影统一FP32，不是GPU、AMP或ONNX测试。本轮不实现API/MMD入口、不上传图片、安装CUDA或生成FP16模型文件。

CPU环境实测Python3.10.0 / PyTorch2.6.0+cpu，无CUDA构建；Half Conv/Linear/LayerNorm/GELU/Softmax/Normalize/Cross小算子通过。32GB物理RAM起始仅约4GB可用：两模式独立进程，mmap/meta/assign加载完整状态，构造时只令ViT drop-path linspace保持CPU以兼容item，SMPL clone保留FP32。严格装载后才转换B网络Half；新FP32与旧XYZ/XY/相机逐值差0，证明该加载方式不改业务数值。

三图SHA与精确预处理tensor、box_center/box_size/img_size冻结，相同缓存输入B再转Half；不把旧三图框改成xywh、不镜像、不静默交换左右或修复脚掌。相机B的pred_cam先转FP32后做全图变换/投影，完整LBS保留BODY25足部蒙皮点。

## 执行及兼容性

- 先用两模式网络做兼容探测；直接Half head真实报`mat1 and mat2 must have the same dtype, but got Float and Half`。仅临时prehook将默认FP32零token转换到head权重dtype，零值与context不变，未改官方源文件或全局默认dtype。
- 每模式CPU4线程/eval/禁梯度，每图预热1次＋3热次，共24次完整推理，另有网络兼容性probe。同模式首次与热测及3热次XYZ/XY/pose/shape/cam输出差均0。
- 加载、转换、probe与网络/LBS/投影计时分开；`loadMs`为meta/mmap初始化，首次权重触达进入probe，不能用约0.4秒宣称完整服务启动时间。热总时不含加载/读图/预处理/序列化，包含LBS及投影；不拿旧inferenceMs（未含投影）直接同比。
- FP32与FP16独立进程串行，未同时驻留两个模型；不控制用户服务器进程，测试进程均正常退出0，没有异常未收集任务。

## 结果

|样本|25点XYZ欧氏RMS/最大差 mm|原图XY RMS/最大差 px|FP32/FP16热总时秒|FP16耗时倍数|
|---|---:|---:|---:|---:|
|真人坐姿|0.6416 / 1.3786|0.0824 / 0.1936|2.129 / 16.867|7.92|

每点mean/P95/最大、相机/betas、旋转正交/det与24旋转角差、原图脚掌角/3D足轴/normal均另存。最大3D足轴角差0.0722°，normal0.0942°；24旋转最大角差0.0766°。旋转角度仅为度量做float64最近SO(3)投影，不修改实际推理矩阵；实际Half矩阵最大正交Frobenius残差约0.002094，det约0.998429～1.001078，无非有限/相机后方点。真人四出画点两模式相同；原左右膝上下关系和动漫脚掌偏差未修复，不能拿数值接近替代姿态真值验证。

各9热次整体总时中位FP32 2.0856s、FP16 16.8559s；范围1.9613～2.2518s / 16.7264～17.2739s。当前CPU FP16约慢8倍，GPU/AMP及当前用户系统负载下的泛化性能未验，CPU部署建议FP32。
