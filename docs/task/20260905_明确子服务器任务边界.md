# 明确子服务器任务边界

## 任务描述

记录 AASC 网络中主服务器、显示端和子服务器的任务执行边界，明确普通任务优先由显示端处理，子服务器仅作为可选的服务型执行节点。

## Design 需求

- 显示端优先执行媒体渲染、播放控制、截图、录音、ASR、TTS、OCR 和 YOLO 等本地能力任务。
- 子服务器用于媒体库/NAS/数据库、Node.js/Puppeteer/后台脚本、离线持续运行、资源隔离、网络出口、聚合和网关等场景。
- 主服务器负责 AASC 网络入口、节点注册、心跳、消息路由和媒体索引。
- 当前不要求部署子服务器，也不要求所有显示端任务经过子服务器。

## Spec 设计

```text
任务到达
    → 查询匹配显示端
    → 有匹配显示端则直接执行
    → 无匹配显示端且允许服务节点执行，则选择主服务器或子服务器
    → 否则返回能力不可用
```

## 自测用例

1. 设计文档明确显示端优先级高于子服务器。
2. 设计文档明确列出子服务器的适用条件。
3. spec 使用伪代码描述显示端优先、服务节点回退流程。
4. 现有 `SubServerManager` 的职责被限定为已选服务节点的管理和转发。

## 兼容性测试

- 不修改现有服务器代码、路由和显示端行为。
- 不删除现有子服务器配置和健康检查设计。

## 性能测试

- 本次为文档和架构边界更新，不产生运行时性能变化。

## 风险评估

- 后续实现任务路由时，需要为每类任务补充能力声明和服务端回退契约。
- “最近服务器”与负载选择暂不属于本次边界，后续需要单独评审。
