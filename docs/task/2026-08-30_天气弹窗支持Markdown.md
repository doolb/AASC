# 任务：天气弹窗支持 Markdown

## 任务描述

让显示端天气和普通语音详情弹窗支持 Markdown，复用控制端已有安全渲染器，同时保持 TTS 使用纯文本和原有显示时长策略。

## Design 需求

- 天气弹窗与普通语音详情弹窗统一支持 Markdown。
- 复用 `ChatMarkdown.render`，不引入外部依赖。
- 原始 HTML 和危险链接必须被安全转义或拒绝。
- TTS 仍使用 `data.text`，不播报 Markdown 标记。
- 弹窗时长继续按原始文本计算，最短 5 秒、最长 90 秒。

## Spec 设计

- `showVoiceResponsePopup` 将内容交给 `ChatMarkdown.render` 后插入 `.voice-response-content`。
- 在显示端样式中补充 Markdown 块元素的间距、表格、代码块和列表样式。
- 保持天气、普通语音响应共用弹窗和旋转布局。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/display.html`
- `src/apps/web-mediacenter/ui/public/css/display.css`
- `tests/display-voice-ui.test.js`
- `tests/chat-markdown.test.js`

## 自测用例

- 天气详情中的标题、加粗、列表、表格、代码块可以渲染。
- 普通语音 `detailText` 同样可以渲染 Markdown。
- `<script>` 等原始 HTML 不执行。
- `javascript:` 链接不生成可执行链接。
- TTS 仍使用不含 Markdown 标记的 `data.text`。

## 兼容性测试

- 原有纯文本天气详情正常显示。
- 语音确认、搜索结果、播放选择弹窗不改变。
- 显示端四向旋转和弹窗自动关闭逻辑不改变。

## 性能测试

- 复用现有轻量级渲染器，无新增网络请求和依赖。
- Markdown 内容仍受已有弹窗最大尺寸和滚动限制。

## 风险评估

- Markdown 渲染结果由 `innerHTML` 插入，必须继续使用安全渲染器，不能直接插入原文。
- 复杂 Markdown 只保证现有渲染器支持的语法，不扩大解析范围。
