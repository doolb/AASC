# 2026-09-23 MMD AR 测试 APK 按钮触摸修复

## 任务描述

SM-N9500 内屏上的独立 MMD AR 测试 APK 中，“灯光”和“定位”按钮点击后只有蓝色触摸反馈，面板没有打开。修正 Android WindowInsets 与 WebView 页面控件定位的边界不一致，并在真机确认按钮点击事件及面板状态。

## Design 需求

- 根据 Android 窗口 Insets 计算 WebView 页面右侧安全距离，不使用设备分辨率硬编码。
- 在独立测试页把灯光/定位控件放入实际可点击区域；关闭 WebView 默认蓝色点击高亮，保留真实按钮交互反馈。
- Activity 记录右上区域原生 ACTION_DOWN/UP 坐标；测试页记录 DOM pointerdown/click 目标与面板状态，便于对照确认触摸是否到达网页控件。
- 测试 harness 保留 `display-interaction-layer`（z-index 50）父层，避免 z-index 10 的交互 MMD canvas 抢占按钮 hit-test。
- 不改正式显示端共享 MMD/AR 代码，不构建或发布 Offline APK。

## Spec 设计

- 先更新 `docs/spec/mmd-ar-test-apk.md` 伪代码：Activity 读取 Insets、换算 CSS px、同步页面 CSS 属性；测试页根据安全距离布局并记录按钮事件。
- 页面加载完成或 Insets 改变时刷新 CSS 属性；触摸日志记录原生 raw/local 坐标、DOM 目标、入口 ID 与面板展开状态。

## 受影响的功能模块与代码

- `3rd/mmd-ar-test/app/src/main/java/com/aasc/mmdartest/MainActivity.kt`：读取和监听 Android WindowInsets；向 WebView 页面同步 CSS 安全距离；保留现有沉浸式窗口与本地 HTTP 生命周期。
- `3rd/mmd-ar-test/build.js`：仅为独立测试页生成安全区域 CSS 和灯光/定位触摸诊断。
- `docs/design/mmd-ar-test-apk.md`、`docs/spec/mmd-ar-test-apk.md`、`docs/todo.md`、`docs/self-test.md`、`changelog.md` 与本任务记录。

## 自测用例

1. `npm run build:apk:mmd-ar-test` 成功，独立包名与原模型资源完整性检查通过。
2. 在 SM-N9500 内屏 display 0 点击灯光按钮，DOM target 为按钮，日志出现 pointerdown/click，灯光面板可打开/关闭。
3. 点击定位按钮，DOM target 为按钮，日志出现 pointerdown/click，定位面板可打开/关闭。
4. 按钮可见区域不进入应用不可用的右侧 Insets；旋转模型的拖动操作仍可用。
5. 应用重启后 APK 内置 PMX/VMD、灯光本地设置和原有安全边界不回归。

## 兼容性测试

- Android 9/API 28 的 SM-N9500 为必测设备；Insets 值按当前窗口动态读取，不依赖 `1480×720` 等固定分辨率。
- 静态检查低版本 Android WebView 无 `env(safe-area-inset-right)` 时，页面回退使用原有基础边距。
- 不改变正式显示端页面、服务协议或 APK 权限。

## 性能测试

- Insets 仅在窗口 Insets 回调或页面完成加载时更新 CSS，不在渲染帧循环中执行 JS。
- 按钮事件诊断仅记录低频 pointerdown/click，不采集或持久化其他触摸数据。
- 确认 PMX/VMD 帧率和模型拖动无可见回归。

## 风险评估

- Android 沉浸式模式下 system inset 可能为零，因此取 system 与 stable Insets 的有效值，并处理密度到 CSS px 的转换。
- Insets 更新可能早于网页加载；页面加载完成时需补发当前值，避免首次布局仍使用零值。
- 设备系统栏方向因旋转变化；每次 Insets 回调更新，不缓存设备专属像素常量。

- 约 1–2 小时，包含 Insets 同步、测试页诊断、独立 APK 构建和 SM-N9500 真机回归。
