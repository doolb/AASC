# 显示端游戏列表入口与棋盘恢复

## 任务描述与需求

原五子棋恢复按钮固定在左下角，会遮挡聊天按钮。用户要求在聊天按钮上方放“游戏”按钮，点击打开游戏列表；有正在进行的游戏时，按钮显示对应游戏名。

## Design 需求与 Spec 设计

- 对照 `docs/design/game-gomoku.md` 和 `docs/spec/game-gomoku.md`：游戏入口与聊天入口共用纵向按钮列，游戏列表向上展开。
- 游戏列表来自显示端声明的游戏能力；首版只有五子棋。当前活动 AI 对话存在进行中棋局时显示“五子棋”，否则显示“游戏”。
- 手动隐藏的已有棋盘可从列表恢复；没有棋局时提示通过聊天请 AI 开局。点击目录本身不创建棋局，也不调用 AI。
- 退出对话或打开聊天时收起游戏列表；保留服务端权威棋盘和已有 `gameView` 协议。

## 受影响模块与代码

- `src/apps/web-mediacenter/ui/public/display.html`：游戏入口、游戏列表和显示端能力声明。
- `src/apps/web-mediacenter/ui/public/js/display-game.js`：列表状态、名称切换及棋盘恢复。
- `src/apps/web-mediacenter/ui/public/css/display-game.css`：按钮列和列表浮层。
- `tests/display-game-browser.test.js`：入口位置、列表点击、活动状态与恢复回归。
- `docs/usage/game-gomoku.md`、五子棋设计/实现文档、`docs/todo.md`、`changelog.md`：同步当前行为。

## 自测、兼容、性能与风险

- 浏览器测试核对“游戏”在“聊天”正上方且聊天点击区域未遮挡；无棋局时列表不创建棋局；手动隐藏后发权威版本的恢复请求；退出对话后入口名称恢复；演示和旋转逻辑保持可用。
- 旧服务端沿用 `gameRecover` / `gameView` 消息，旧棋局文件无需迁移；首版列表只有当前已实现的五子棋，未来增加游戏时同步扩展显示端能力和对应 UI 处理。
- UI 只创建一项列表和少量状态更新，不增加网络轮询；主要风险是 Android WebView 不同视口与安全区的实际观感，待服务代码包安装后设备验收。
- 预计工时：约 1 小时；需求边界明确，无待确认项。
