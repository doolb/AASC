# 媒体重连恢复播放进度

## 任务描述

修复显示端处于暂停状态时 WebSocket 重连后 video 从 0 秒重新加载的问题，并让 audio 与非临时批量播放恢复上次播放位置和暂停状态。

## Design 需求

- 单媒体保存 `currentMediaProgress`，包含当前播放秒数和媒体总时长。
- 批量播放保存当前索引、当前项播放秒数、总时长和 `playing/paused` 状态。
- 重连时显示端在 `loadedmetadata` 后 seek，再按持久化播放状态决定播放或暂停。
- 旧状态没有进度字段时从 0 秒兼容恢复；图片批量仅恢复当前索引；HTML 滚动位置不在本次范围。
- 进度写配置需要节流，暂停、切换媒体、切换批量项时强制同步最新值。

## Spec 设计

详见 `docs/spec/batch-playlist.md`、`docs/spec/audio-media.md`。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/display.html`：恢复参数、video/audio seek、批量进度上报。
- `src/apps/server/boot/server-app.js`：进度缓存、持久化、重连消息参数。
- `src/apps/server/modules/config/config-app-service.js`：显示端进度默认状态。
- `tests/display-playback-resume.test.js`：恢复字段与消息链路回归测试。

## 自测用例

1. 暂停 video 后重连，仍停在上次 `currentTime`，不从 0 秒开始。
2. 暂停 audio 后重连，仍停在上次 `currentTime`。
3. 播放中的 video/audio 重连后从缓存位置继续播放。
4. 批量播放重连后恢复当前索引、当前 video/audio 项时间和暂停/播放状态。
5. 图片批量仍恢复当前索引，旧配置缺少进度字段时不报错并从 0 秒兼容。
6. 播放进度高频上报不会每次都同步写配置；暂停和切项会立即保存。

## 兼容性测试

- Chromium 浏览器与 Android WebView 的 video/audio `loadedmetadata` 恢复。
- 旧状态没有 `currentMediaProgress`、`resumeTime`、批量时间字段时正常恢复。
- 临时批量不把 base64 写入配置，现有临时列表生命周期不变。

## 性能测试

- `timeupdate` 只更新内存并按时间窗口持久化，不产生等量配置文件写入。
- 重连恢复不新增媒体下载，仅复用原媒体 URL/base64。

## 风险评估

- 媒体元数据尚未加载时不能立即设置时间，必须等待 `loadedmetadata`。
- 浏览器自动播放策略仍可能阻止恢复播放，但暂停位置应正确保留，控制端播放按钮可再次触发。
- 临时批量断开后仍无法恢复 base64 内容，继续沿用现有设计。
