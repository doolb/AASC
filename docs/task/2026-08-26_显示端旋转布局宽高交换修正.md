# 显示端旋转布局宽高交换修正

## 任务描述

修正显示端在 90°/270°旋转时文本元素仍按未旋转物理视口定位，导致连接状态、媒体名和播报文本可能越出屏幕边界的问题。

## design 需求

- 0°/180°使用视口原始宽高。
- 90°/270°交换视口宽高，形成旋转后的逻辑画布。
- 连接状态、媒体名、时间、语音状态和播报文本按逻辑画布重新计算可用区域和位置。
- 文本仍按 90°/180°/270°整体旋转，字号保持桌面 36px、移动端 27px。

## spec 设计

- 在 `applyRotation()` 内计算 `layoutWidth`、`layoutHeight`。
- 90°/270°使用 `viewportHeight` 作为逻辑宽度、`viewportWidth` 作为逻辑高度。
- 为文本元素设置基于逻辑画布的最大宽度/高度和边距，并基于实际变换包围盒校正固定定位，避免旋转后右侧或底部越界。
- 保持现有 UI 四角映射和 TTS/ASR 共用节点。
- 内容异步变化时由 `MutationObserver` 触发布局重算；固定文本不对尺寸、位置和 transform 使用过渡动画。

## 自测用例

- 静态测试验证 90°/270°计算交换后的逻辑宽高。
- 静态测试验证旋转文本元素使用逻辑画布约束。
- 验证连接状态、媒体名、播报文本均进入同一布局规则。
- 运行显示端、文本媒体和 TTS 相关回归测试。
- 实测旋转布局回归 6/6、相关静态与逻辑回归 40/40、显示端集成回归 9/9 通过。

## 兼容性、性能与风险

- 只使用浏览器现有视口尺寸和 CSS 约束，不改变 WebSocket 协议。
- 旋转切换时增加少量尺寸计算，无持续轮询或网络开销。
- 视口 resize 后需重新应用布局，避免窗口尺寸变化恢复旧约束。
