# 控制端临时会话游戏协议提示保留

日期：2026-10-20

## 任务描述

用户希望控制端聊天面板也持续显示游戏协议调用和 GM 回执的灰色 tips。控制端已有实时 `chatGameProtocol` 渲染，但显示端发起的临时角色会话在完成后使用独立快照重绘；该快照未复制 `gameTrace`，提示因此消失。无历史快照的完成分支也会用正文覆盖流式提示。

## Design 需求与 Spec 设计

见 `docs/design/game-gomoku.md` 与 `docs/spec/game-gomoku.md`。服务端临时会话快照复制已校验的助手 `gameTrace`；普通历史规范化保留 `GameUser`、`GameAI`、GM 的类型；控制端没有最终历史快照时继续显示本轮实时收集的协议提示。提示仍只作为界面元数据，不进入模型输入或朗读。

## 受影响模块与代码

- `src/apps/server/boot/server-app.js`：临时角色会话消息复制 `gameTrace`。
- `src/external/llm/llm-service.js`：规范化游戏协议 kind 时保留新角色名。
- `src/apps/web-mediacenter/ui/public/js/chat.js`：无历史快照时保留实时提示。
- `tests/gomoku-chat-tip-browser.test.js`：验证临时会话完成态与无历史快照完成态。
- 五子棋 design/spec/usage、todo、changelog 和服务包状态。

## 自测用例、兼容性测试与性能测试

运行 `node --test tests/gomoku-chat-tip-browser.test.js` 与 `npm run test:game-chat`。核对同一 requestId 的提示顺序、临时会话完成后仍可见、无历史快照时不消失、普通历史保留操作者类型。每条助手消息最多复制 128 条已限制长度的协议记录，额外内存和序列化开销有明确上限；无游戏操作的普通聊天不增加该字段。

## 风险评估与预计工时

多控制端在不同会话页签观看时，仍需按当前 requestId 和会话快照过滤；本次不改变路由。服务包更新后需在控制端与显示端实际聊天中验收。预计约一小时。

## 执行结果

控制端浏览器用例 1/1、`npm run test:game-chat` 41/41 与 `git diff --check` 通过。临时会话快照现在包含 `gameTrace`，无历史完成态保留实时提示；`servicePackage=true` 待构建，真实两端待部署验收。
