# TTS语速仅走原生接口

## 任务状态

- 源码完成；按用户明确要求移除 WAV 变速，语速只使用上游/原生模型参数。待服务包/min APK 发布后进行设备验收。

## 任务描述

声纹面板继续按 Provider 分别配置语速（-10 至 10），音量维持全局单入口（0 至 100）。任一 WAV 后处理不得调整样本数、时长或语速。上游没有明确原生语速字段的 Provider/模型隐藏语速输入；Android 显示端离线 TTS 使用 Embedded Speech SSML 原生语速。

## 需求等级评审（enterprise）

- 结论：可开发；主等级 L6（跨适配器参数契约），次等级 L5（Provider能力显示与旧APK回退规则）。
- 置信度：0.90（需求与边界已有多轮确认，语速/音量职责明确）。
- 评分：层级清晰度 24/25，证据充分度 18/20，实现完备度 17/20，风险暴露度 18/20，L4 可落地性 14/15，总分 91/100。
- 证据：用户要求“wav不要调整语速，只使用原生模型接口”；用户确认“语速还是分别配置，不支持语速的tts方式，不显示”；已核对 Qwen-Audio `input.rate` 和豆包 `speech_rate` 原生字段、Qwen3-TTS HTTP 未声明语速字段、Android Embedded Speech SSML `prosody rate` 支持。
- 主要风险：模型能力展示和服务端实际入参不一致会造成静默忽略或请求失败；Android旧APK不认识新速度桥。按同一能力判定、旧桥非零语速显式报错并复用服务端fallback控制。
- 能力下放：必须下放 L4；下述伪代码串联 Provider 模型、原生语速请求、Android WS 桥及 WAV 音量处理。

## Design 需求

- `adjustWavVolume(buffer, volume)`只调整 PCM 幅值，保持样本数、采样率与时长；移除速度参数及重采样逻辑。
- Qwen-Audio 3.0/3.1 TTS 仅在上游 `input.rate` 范围 0.5–2.0 内传原生语速；Qwen3-TTS HTTP 未声明 `rate` 时隐藏语速，不发送该字段、不本地变速。
- 系统 TTS、国内千问网页与豆包 API 继续只使用原生语速字段；豆包网页朗读固定语速且隐藏设置。
- Android显示端的 `ttsGenerate` 携带 -10 至 10 语速；新 APK 使用 Embedded Speech SSML `prosody rate`。旧 APK 在零语速时沿用既有入口，非零语速显式返回不支持并走现有服务器回退策略。
- 单一全局音量入口、Provider独立语速配置/迁移、AASC WebSocket 权威配置、缓存与播放协议继续有效。

## 自测用例

1. WAV音量处理前后样本数/时长不变，PCM幅值按比例变化；音量100保持字节不变。
2. Qwen-Audio上游请求包含`input.rate`且输出PCM样本数不被本地变速；越界倍率在请求前拒绝。
3. Qwen3-TTS上游请求不带`rate`；语音面板按模型隐藏语速，保存不提交字段，服务端不应用该Provider历史语速。
4. 豆包API仍发送`speech_rate`；qwen-chat仍发送原生speed；system调用外部TTS仍传速度。
5. Android零语速调用SpeakText；非零语速SpeakSsml，-10/10映射为0.5x/2x并正确转义XML正文。
6. 新Android桥接收带速度消息；旧桥speed=0兼容，非零回错并按服务端开关决定fallback。
7. 音量共享、Provider独立语速、保存/广播/重连与缓存播放路由不回归。

## 兼容性、性能与风险

- 旧客户端和旧APK仍可调用旧原生TTS桥；非零语速请求不会静默忽略。
- 新旧合成器并发、slot retire、60秒超时和WAV缓存容量策略不变；SSML只在非零速度额外生成有界文本。
- SSML转义避免用户文本破坏标记；若上游/Android模型拒绝原生语速，沿用原错误和显示端服务端fallback。
- Offline 服务包与 Android min APK 都受影响；`servicePackage=true`、`minApk=true`，依赖包不受影响。
