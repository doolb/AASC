## 定位证据与对照（2026-10-15）

在同一指定会话中，/im/conversation/info与/im/chain/single均HTTP200/status_code=0，网页有4个message_text_content；错误并不是这两个会话读取请求失败。全新恢复和同窗口刷新均观测到真正的semi-toast-error/role=alert，“非法请求”精确文本，不只用body字符串作结论。

进一步纳入accounts.doubao.com认证请求后，发现/passport/token/beat/web/返回data.error_code=401，/passport/account/info/v2/返回13；部分security_token_beat/get_oauth_token/biz_auth返回2035。只读Cookie域元数据显示：sessionid仅存在www.doubao.com，accounts.doubao.com无sessionid；profile.allowedOrigins和cookieBundles都只覆盖www，且原生setCookie使用host-only。这是明确的跨子域登录恢复缺口。

对照只在隔离WebView内存复制已有www白名单Cookie到固定accounts来源，不改服务账号库或生产代码，不读写新聊天；刷新后精确toast不再出现，token/beat/web的data.error_code=0，account/info/v2为success，目标4条消息保持。部分安全SDK接口仍2035，不宣称所有Passport功能已通过。后续单独删除accounts host-only sessionid时仍观察到该来源有session，说明网页已补全其它域级Cookie，不能把该次删除当有效的反向对照；以初始域缺口、正常读取和首次临时补齐前后证据为准。

未证明网页设备存储缺失是本次提示根因；该项不加入本次生产修复。没有更改Node对话body、会话ID、请求签名或用户账号身份。
