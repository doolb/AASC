# 控制端历史临时会话查看

## 任务描述

为已保存的临时会话历史增加控制端只读查看能力。控制端临时页签展示最近配置数量内的历史会话组，支持查看消息内容，但历史组不能恢复、续聊或改变当前临时会话。

## Design 需求

- 服务端按临时消息的 `sessionId` 聚合历史组，排除当前临时会话并按结束时间倒序返回。
- 历史组沿用 `temporaryHistoryGroups` 配置上限，默认最近 10 组。
- 复用现有 `temporaryConversation` WebSocket 快照，连接、更新和刷新时同步历史组。
- 控制端显示历史组摘要和完整消息，查看时只读；返回当前对话后恢复发送能力。

## Spec 设计

- `getTemporaryConversationSnapshot()` 增加 `historyGroups` 数组。
- 历史组字段为 `sessionId`、`startedAt`、`endedAt`、`roleName`、`messageCount` 和 `messages`。
- 控制端 `Chat` 增加历史组状态和只读查看状态，历史选中时渲染历史消息并禁用输入发送。

## 受影响的功能模块和代码

- `src/apps/server/modules/voice/temporary-conversation-history.js`：提供历史组摘要和消息选择。
- `src/apps/server/boot/server-app.js`：在临时会话快照中广播历史组。
- `src/apps/web-mediacenter/ui/public/js/chat.js`：增加历史组列表、只读查看和返回当前对话。
- `tests/temporary-conversation-history.test.js`、控制端契约测试：覆盖历史组同步和只读状态。
- `docs/design/display-voice-conversation.md`、`docs/spec/display-voice-conversation.md`：同步设计和伪代码。

## 自测用例

1. 新临时会话开始后，上一组出现在历史列表中。
2. 历史列表最多显示 `temporaryHistoryGroups` 组。
3. 点击历史组可以查看完整消息，当前临时输入框不可发送。
4. 点击返回当前对话后恢复当前消息和发送能力。
5. 控制端重连后仍能收到历史组，旧客户端忽略新增字段不报错。

## 兼容性、性能与风险

- 复用已有 WebSocket 消息，不新增 HTTP 接口；旧客户端忽略 `historyGroups`。
- 只同步配置范围内的历史组；历史消息仍受既有保留策略和模型 token 裁剪约束。
- 历史消息可能较长，控制端只展示服务端已保留的最近组，不支持编辑和续聊，避免误写旧会话。
