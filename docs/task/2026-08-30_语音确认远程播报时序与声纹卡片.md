# 语音确认远程播报时序与声纹卡片

## 任务描述

修正自动确认模式在远程显示端播放确认提示时提前启动倒计时的问题，并将声纹管理页面的语音相关设置统一为大卡片布局。

## Design 需求

- 自动确认窗口必须从所有实际播放目标完成确认提示后开始。
- 播放完成前不得提交原始语音；确认窗口内到达的“取消”只清理待确认内容，不进入聊天。
- 声纹管理页面的主要设置使用统一大卡片，确认模式使用独立大卡片并与声纹识别设置并列。
- 确认倒计时使用深浅主题均可读的高对比提示色块。

## Spec 设计

```text
创建自动确认记录 -> 登记每个实际 TTS 播放目标
播放目标完成 -> 删除对应目标
全部目标完成 -> 开始7秒取消窗口
窗口内取消 -> 清理记录，不发送聊天
窗口到期 -> 提交原始语音
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：关联 TTS 播放完成回执与待确认记录。
- `src/apps/web-mediacenter/ui/public/upload.html`：声纹页面卡片结构。
- `src/apps/web-mediacenter/ui/public/css/upload.css`：大卡片样式。
- `tests/display-voice-conversation-confirmation.test.js`：增加时序和布局契约。

## 自测用例

1. 来源显示端不是播放目标时，TTS 完成前不发送 `chatInput`。
2. 所有播放目标完成后才发送 `conversationConfirmWindow`。
3. 确认窗口内说“取消”不产生普通聊天请求。
4. 声纹页面主要设置均带统一大卡片类名，确认模式位于独立大卡片内。

## 兼容性测试

- 无可用播放目标、TTS 生成失败时保留原有 7 秒取消兜底。
- 手动确认、关闭模式、声纹注册和服务器 ASR/TTS 开关不变。

## 性能测试

- 每个待确认记录只登记实际播放目标，不增加额外轮询。
- 卡片布局仅改变控制端静态样式，不增加网络请求。

## 风险评估

- 多个播放目标中任一目标异常可能延迟确认窗口，因此继续复用现有 TTS 播放超时回收机制。
- 既有未提交用户改动可能包含日志和生成文件，本次不清理、不覆盖。
