# SubAI动作生成与对话接入设计

状态：设计文档完成，待整体开发方案确认；没有新增运行代码。用户已明确SubAI在模型面板独立选Provider/模型，并确认完整播放成功后自动保存候选版本。

- 任务描述：主AI理解自然语言动作，显示端优先使用已有动作，缺库则派发动作SubAI生成MPL，编译并播放。
- design需求：[SubAI与对话动作设计](../design/sub-ai-actions.md)。角色独立配置和上下文，现有Human单一播放入口，候选不自动改active。
- spec设计：[伪代码草案](../spec/sub-ai-actions.md)。包括配置消息、意图/能力摘要、缺库生成、prepare/start、一次修复、取消及schema2候选。
- 受影响模块：server/chat新增SubAI配置/服务及动作协调；server-app装配；共用模型面板与两端消息；Human/MPL/TTS/动作库存储和导入导出。真实候选路径见design模块表。
- 执行切片：一，已知动作对话与direct接通；二，SubAI角色选择、独立Provider/具体模型调用、未知动作生成/完整播放后候选保存；三，有界修复、缓存、多端与实机验收。
- 自测用例：Provider/模型一致、配置revision/保存失败、主AIprofile/历史不变；本地命中零SubAI；未知动作调用所选模型；半截/重复协议；无音频动作；语音过期跳过；实际完成才保存一次候选；active不变；停止/失败不保存；schema1迁移、导入导出、配额和写入失败；取消与模型切换迟到零播放。
- 兼容性：普通LLM/Agent聊天出口统一；现有已知TTS动作不回归；控制端/显示端模型面板一致，Agent主profile也可独立选择动作SubAI；多PMX能力按端校验；Node mpv不支持MPL时明确unsupported。schema2需新版读写，老程序不能直接回读，部署前备份。
- 性能测试计划：先量命中库与缺库生成p50/p95、编译延迟、取消收敛、每轮调用/token与移动端帧时；20秒总预算、每轮两次与并发配额为建议初值，不是实测结果。
- 风险：本地库对服务端不可见、未知标记被现有解析丢弃；mpl.play立即播放且优先级高；register/revise会改active；模型输出语法可编译不等于动作质量。分别用库摘要/最终解析、prepareMpl、独立候选存储及实机PMX画面验收处理。
- 预计工时：依现有LLM适配兼容情况约3～5个开发日含自动化与桌面浏览器验证；移动实机/账号风控和复杂动作视觉迭代另计，尚未实测承诺。
- 待确认：整体模块方案及建议的首版Provider范围、只执行用户明确动作、随语音迟到跳过；实际验收设备/PMX实施时指定。自动保存候选已确认，不再列为未知。
- 本轮验证：核对package.json已有scripts及真实模块/API、文档引用和差异；仅设计，无模型调用/动作播放/构建或功能测试通过声明；发布状态未改。
