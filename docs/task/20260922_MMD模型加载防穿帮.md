# 2026-09-22 MMD 模型加载防穿帮

## 任务描述

修复 PMX 模型加载期间材质逐个出现、VMD 尚未完成时模型已经显示，导致画面出现半成品或默认姿势穿帮的问题。

## Design 需求

- 继续使用本地同源 PMX/VMD 资源和现有白名单。
- 模型、纹理和动作全部准备完成后再显示新模型。
- 模型切换失败时保留已有完整模型；首次加载失败时保留占位降级。
- 不扩展到灯光设置、Offline APK 或外网发布。

## Spec 设计

- 每次 PMX/VMD 请求创建独立 `LoadingManager`。
- `stagedMesh` 和 `stagedHelper` 在提交前不加入场景和当前动作状态。
- 成功后停止旧动作、释放旧模型并原子提交 staged 资源。
- 失败后释放 staged 资源并保持旧模型。

## 受影响功能模块和代码

- `src/apps/web-mediacenter/ui/public/js/display-pmx-runtime.js`
- `tests/display-mmd-runtime.test.js`
- `docs/design/mmd-pmx-vmd-local.md`
- `docs/spec/mmd-pmx-vmd-local.md`

## 自测用例

1. PMX runtime 使用独立 `LoadingManager` 等待模型引用的纹理完成。
2. VMD 在 staged PMX 上准备完成后才提交动作 helper。
3. PMX/VMD 资源准备完成后才将模型加入场景。
4. 失败时释放 staged 资源并保留旧模型或显示占位。
5. 本地 HTTPS 显示端状态为“PMX 模型已加载”，页面无异常。

## 兼容性测试

- Node.js `node --test tests/display-mmd-runtime.test.js`
- Chromium 本地 `/display` 页面。
- VRM runtime、聊天、媒体和既有 Canvas 占位路径保持原有接口。

## 性能测试

- 纹理和 VMD 仍由浏览器并发请求；只延后场景提交，不重复下载资源。
- 隐藏 MMD 时仍暂停渲染循环，不增加轮询。

## 风险评估

- 加载完成前用户会继续看到旧模型或占位，首屏可见时间可能略晚，但不会看到半成品。
- 单个纹理失败会让本次 staged 模型提交失败；已有模型不受影响。
- 未修改资源目录、模型文件、Offline APK 和外网发布流程。
