# MMD AR 半分辨率边界修正开关

- 需求：半分辨率下正常 AO 与法线预览都按表面深度匹配，避免近远物体边界混用；提供默认开启、保存选择的开关。
- 设计/spec：`docs/design/mmd-ar-test-apk.md`、`docs/spec/mmd-ar-test-apk.md`。
- 影响：测试页 `web-ao-boundary.js` 转换 AO/模糊/合成 shader；`build.js` 应用生成转换并更新指纹；`web-panel-groups.js` 添加开关。正式源码与 APK 不变，不新增外部接口或第二张深度图。
- 数据流：整数 AO 像素映射源深度 → 中心四邻点取较连续深度斜率 → 四候选按斜率预测深度校验 → 有效候选双线性合成，否则当前像素复用原 AO/法线公式补算；保边模糊也按源深度归属拒绝跨表面邻点。
- 容差：四分之一视空间像素尺寸、八倍深度量化估计、视距相对数值下限取最大，不绑定用户半径。
- 开关：`aasc.mmdArTest.aoEdgeCorrection.v1` 默认 true；存储不可用不影响本次切换。实际全尺寸时禁用控件并旁路，返回低分辨率恢复保存值。
- 自测：`node --test 3rd/mmd-ar-test/web-ao-texel.test.js 3rd/mmd-ar-test/web-ao-boundary.test.js tests/mmd-ar-web-panel-groups.test.js`；覆盖斜面、前景重叠与相交、细条、透明背景、奇偶尺寸、预算缩放、全尺寸旁路、开关持久化和禁用恢复。
- 性能：128×128 桌面 SwiftShader 同步渲染五次均值对照开关，另加 24 条细条构成边界密集场景；仅作开销观察，不作为手机帧率结论。
- 风险：屏幕深度只有最前方表面，不能保证遮挡后信息或亚像素几何完全恢复；补算像素多时可能接近全分辨率开销，真机待验收。
- 预计工时：2 小时。仅本地构建，本轮不发布、不打 APK。
- 验证结果：构建、前序法线/白边 GPU 回归、新增开关/边界 GPU 回归 2/2、面板回归 7/7 通过。128×128 重叠场景法线大误差像素 156→52、AO 184→105；相交场景 148→46、603→577，轮廓 alpha 与全尺寸旁路差异为 0。
- 性能结果：SwiftShader 普通场景开关关闭/开启约 0.96/1.10ms，24 条细条约 2.26/3.74ms；需真机评估，不能宣称所有半分辨率细节与全分辨率相同。
