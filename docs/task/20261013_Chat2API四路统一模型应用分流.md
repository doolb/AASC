## 已批准首批

1. 现有文字聊天＋四路TTS先统一。API两路现成实现是TTS，不因注册而自动支持新聊天模型/ASR/图片/视频；四类内容明确区分，未接入组合请求前拒绝。
2. Chat2API实例/v1/responses与现有网关；instructions开头唯一<chat2api>JSON</chat2api>控制块，Provider解析application/voice/speed/volume/format。普通聊天自然语言保持。
3. TTS为非流式WAV Base64，不进入聊天历史或接受续接引用；旧speech仍二进制WAV。Qwen/豆包文字原生续接保持。
4. 首版API账号由用户在Chat2API手动配置/导入；不自动搬迁/删除旧密钥，也不在运行时回退读旧值。若要求自动迁移，先补预览、冲突保护与回滚设计。

用户过去对豆包Node/WAV的“可以/是”不代表批准本次新架构或实际API密钥迁移。

## 兼容性、性能、风险和工时

- 兼容：公开聊天名/网页账户ID/原生续接保留；output_audio为项目扩展；API两路切换前需完成Chat2API账号准备，不靠双凭证源掩盖漏配。
- 性能：音频≤16MiB，Base64≤24MiB，代理请求上限保持50MiB；只在JSON出口编码。首版不建媒体上传/视频任务队列，不宣称已有媒体性能证据。
- 风险：文本层吞媒体、模型归属与voice混淆、TTS误用聊天会话、下载取消缺口、密钥双存与音频日志；按spec设置前置校验和兼容回归。
- 真实请求、实际凭证迁移、主服务操作和出包发布须另有具体授权；本轮实现及测试均使用虚构账户与本地音频。
- 工时：首批约3–5开发日量级，取决于账号/UI迁移口径；新增ASR/图片/视频按具体模型另估，不作交付时刻承诺。
