# AASC 控制端批量重载子服务端代码

## 任务描述

在控制端“服务端”设置区域增加“重载所有子服务端代码”按钮，使用主服务器 AASC 节点连接批量下发已有 `server.update` 命令。

## Design 需求

- 主服务器新增批量更新 API。
- 只选择在线且已建立主动 WebSocket 连接的子服务器。
- 不包含 `main-server`。
- 并发下发，返回节点级结果，允许部分失败。
- 控制端二次确认，请求时禁用按钮并显示汇总提示。
- 不实现自动更新、权限认证和主服务器自更新。

## Spec 设计（伪代码）

```text
POST /api/aasc/servers/update-all
    → registry.getAll() 获取节点快照
    → 排除 main-server、offline 和无连接节点
    → 并发 registry.request(nodeId, server.update, {})
    → 归一化节点结果 { nodeId, name, status, accepted, message }
    → 返回 total、accepted、failed 和 results
```

```text
点击控制端按钮
    → confirm
    → fetch POST /api/aasc/servers/update-all
    → 禁用按钮
    → HTTP 或 JSON 失败显示错误
    → 成功显示节点更新汇总
    → finally 恢复按钮
```

## 受影响功能模块和代码

- 主服务器 AASC 节点批量请求 API。
- 控制端服务端设置按钮和请求状态。
- 控制端 API 契约与 UI 测试。

## 自测用例

1. 批量接口只向在线、有连接的子服务器发送 `server.update`。
2. 主服务器节点不会收到更新请求。
3. 节点部分失败时接口仍返回节点级汇总。
4. 没有在线子服务器时返回空汇总。
5. 控制端包含正确按钮文字和 API 调用。
6. 控制端请求期间按钮禁用，异常时恢复可用。

## 兼容性测试

- 现有单节点 `POST /api/aasc/servers/:nodeId/request` 不变。
- 子服务器 `server.update` 处理器和 Bootstrap 不变。
- 既有“重载代码”和“关闭所有 Agent”行为不变。

## 性能测试

- 节点更新请求并发执行，不串行等待节点。
- 批量操作只遍历内存注册表，不访问节点地址探测。

## 风险评估

- 多个子服务器同时更新会同时消耗网络和磁盘资源。
- 节点在请求发送后断开时，结果标记失败，由下一次手动操作重试。
- 当前无权限认证，按钮可触发局域网内所有已连接子服务器更新。

约 1 小时。
