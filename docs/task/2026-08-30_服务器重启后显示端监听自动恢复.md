# 服务器重启后显示端监听自动恢复

## 任务描述

服务器重启后，显示端 WebSocket 可能重新连接，但持续语音监听没有自动恢复；部分 Android WebView 在服务器重启时只触发 WebSocket `error`，也会使重连流程停止。

## Design 需求

- 每次 WebSocket 建立后重新检查服务端 ASR 状态。
- ASR 暂未就绪时可重试，恢复后自动启动原本开启的显示端监听。
- WebSocket `error` 事件进入统一重连路径。
- 不绕过控制端的 `voiceRecording` 开关，不因旧回调重复启动录音。

## Spec 设计

```text
WebSocket onopen:
    发送显示端能力和状态
    重新检查 /api/asr/status

ASR 检查 ready:
    更新 voiceSupported
    回传 voiceStatus/capabilities
    监听开关开启且当前未监听 -> 启动录音

ASR 检查失败或未就绪:
    回传不可用状态
    页面活跃且监听开关开启 -> 延迟再次检查

WebSocket error:
    仅当前连接生效时清理 socket
    调度唯一重连定时器

pagehide:
    取消所有重连/重试定时器
    阻止旧回调继续恢复监听
```

## 自测用例

1. WebSocket 首次建立和重连都重新调用 ASR 状态检查。
2. ASR 暂未就绪时会延迟重试，恢复后可自动启动监听。
3. 用户关闭 `voiceRecording` 后，ASR 恢复不会强制启动录音。
4. WebSocket 仅触发 `error` 时会清理异常连接并继续重连。
5. 页面离开后不再执行重连或 ASR 重试回调。

## 性能测试

- ASR 未就绪时只保留一个延迟重试定时器。
- WebSocket 和 ASR 状态回调均校验页面/连接仍有效，避免重复申请麦克风。

## 风险评估

- 服务器持续不可用时会产生低频状态请求，默认重试间隔不低于 5 秒。
- ASR 状态确实不可用时保持监听关闭，不绕过能力开关。
- WebSocket error/close 同时触发时必须保持重连单飞。

## 实现结果

- WebSocket 每次建立后重新执行 `checkAsrStatus()`；服务端 ASR 未就绪或请求失败时每 5 秒重试。
- ASR 恢复后通过既有能力回传链路触发自动监听，控制端关闭 `voiceRecording` 时不会绕过开关。
- WebSocket `error` 主动清理异常连接并复用唯一重连定时器；`close` 回调通过当前 socket 校验避免重复重连。
- 页面离开时取消 WebSocket/ASR 定时器并使旧请求回调失效。
- 验证：重连与语音相关聚焦测试 14/14 通过，`git diff --check` 通过。
