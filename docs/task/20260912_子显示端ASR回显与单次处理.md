# 子显示端 ASR 回显与单次处理

## 任务描述

修复 Node 子显示端只打印“服务器忽略该段音频”而不回显识别文本的问题，并统一子显示端与网页显示端的 ASR 回显格式。子显示端上传一次音频后，由服务器完成 ASR、声纹门控和语音命令处理，客户端不再使用 ASR 结果通过旧 `voiceInput` 消息二次上报。

## Design 需求

- 保留服务器返回的完整 ASR 响应，尤其是 `ignored` 响应中的 `text`。
- 支持 `segments`、`ignoredText` 和普通 `text` 三种回显数据。
- 回显显示说话人、声纹相似度和阈值时，保持网页显示端的格式。
- 原始识别文本只交给服务器处理一次，不截断工作角色名或群聊前缀。
- 键盘手动输入仍保留原有 `sendVoiceInput` 链路。

## Spec 设计

```text
识别音频:
    Node 上传 WAV 和显示端上下文到 /api/asr/recognize
    服务器完成识别、声纹门控和命令处理
    Node 解析完整响应并格式化本地回显
    Node 不从 ASR 回调再次发送 voiceInput

回显响应:
    success + segments -> 逐段显示说话人或未识别声纹信息，并追加 ignoredText
    success + text -> 显示 text
    ignored + text -> 显示 text
    ignored 无 text -> 显示忽略原因
```

## 自测用例

1. ignored 响应中的 `text` 不被客户端清空。
2. 带说话人的分段显示 `[说话人] 文本`。
3. 未匹配声纹的分段显示相似度、阈值和原文。
4. success 响应附带 `ignoredText` 时完整回显。
5. ASR 回调不调用 `sendVoiceInput`，同一音频只上传一次。
6. 键盘手动输入仍调用 `sendVoiceInput`。
7. 含工作角色名的原始文本不被客户端截断或改写。

## 兼容性测试

- 服务器普通 ASR `text` 响应保持可回显。
- 服务器声纹 `segments` 响应与网页显示端展示语义一致。
- Node PvRecorder 和 naudiodon 两种录音器的上传入口不变。
- 旧服务器未返回新字段时仍可显示普通文本或忽略原因。

## 性能测试

- 只在响应处理期间生成回显字符串，不复制音频 Buffer。
- 不增加第二次 ASR HTTP 或 WebSocket 文本请求。
- 分段回显仅处理服务器已返回的文本和数值字段。

## 风险评估

- 取消旧的 ASR 结果二次上报后，要求服务器能通过 `displayId` 找到来源显示端；当前 Node 请求已携带该字段。
- 服务器未处理请求时只记录警告/回显，不自动重新发送，避免重复执行命令。
- TUI 文本长度受现有 blessed 区域限制，长分段只影响显示，不影响服务器处理。
