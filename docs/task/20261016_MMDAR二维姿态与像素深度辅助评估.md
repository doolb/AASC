# RTMPose二维与像素深度辅助评估

状态：用户在刚体原型执行中明确追加结合深度，本机WASM三图推理及物理弱排序对照已完成；没有稳定收益，正式未接入。结果见刚体投影任务执行记录。

## 需求与design

二维识别、人物左右、图片预览与相机对应继续使用RTMPose-m。新深度模型只读取同一图片，输出像素相对深度图，作为可拒绝的前后关系辅助，不重新检测或交换身体语义。沿用浏览器/手机本地ONNX、全身IK唯一正式入口、图片不上传；先做本机三图临时试验，不默认接入。

候选为Depth Anything V2 Small，官方24.8M参数、Apache-2.0，并列出社区ONNX和Transformers.js浏览器实现；社区模型卡提供ONNX权重，浏览器路线有参考，但本机/手机尚未验证。核查来源：[官方项目](https://github.com/DepthAnything/Depth-Anything-V2)、[ONNX模型卡](https://huggingface.co/onnx-community/depth-anything-v2-small)。相对深度非真实米制关节距离，表面深度也不是被遮住的关节深度。

## spec与流程

```text
已有声明 := 三张用户图/当前RTMPose二维语义与分数 + PMX真实FK/共享限位 + 参考相机 + 本机ORT Web/取消代次
新增定义 := 深度模型身份/固定revision/大小/SHA/许可/预后处理/原始浮点深度图/输出方向与归一化 + 像素对应/邻域统计/不确定标记/前后排序候选
输入 := 同一原图分别到RTMPose与深度模型 → 各自预处理 → 显式逆变换回原图，不覆盖或伪造RTMPose world
诊断先行 := 原始浮点深度与归一化展示分开保存 → 核对近远方向/缩放与裁剪 → RTMPose点和骨段叠加深度图 → 保存邻域变化及污染风险
辅助 := 只对可解释的可见表面给弱前后排序参考，不直接以像素值作关节z或米制xyz；遮挡/出画/低分/边界混合/无法判断归属 → 标记不确定或拒绝该提示，不靠插值填隐藏膝踝
拟合 := 原二维与骨长/共享关节约束优先 → 低权排序候选辅助选择 → 相同初值和参数三图对照 → 真实物理回读/正侧面/相机门槛
边界 := 深度模型不会修复已有FK初值敏感性/目标到实际执行落差；单列既有问题，不把二维残差降低当真实3D恢复
生命周期 := 临时原型独立；正式接入若另行确认，沿用全身IK按需加载/取消/换图与模型代次/原子提交/失败保留旧目标
```

## 自测、兼容性和风险

核查相对深度方向与原图映射的合成样本、非法尺寸/NaN/出画/低分/混合邻域拒绝；不能仅靠光滑低方差证明关节可见，未知遮挡直接标记不确定。测试固定初值、RTMPose点原样保留、同权重与取消/迟到结果保护、实际270子步骨长/限位和目标落差；模型失败不改旧目标。首版静态临时报告不改变真实用户当前角色。二次元/示意图、遮挡和衣物都可能造成错误深度或无有效提示；本轮目标为确认信息是否有用，不承诺稳定还原。

预计临时评估半天至一天，导出/算子/手机问题另记录。已有package.json无此临时评估script，确认后复用现有Node/ORT工具；不安装Python或新增生产依赖，不同时重建web-dist。未知信息为具体导出revision/精度/Web算子与性能、三图有效提示率与实际收益，均由试验补证，未经核对不写成已验证。

## 需求分层（enterprise）

明确性检查：输入、平台、保留二维语义和暂不正式接入均可由已有对话确定；具体深度导出/提示有效性是待试验证据，不要求用户决定数值算法。主L6（深度辅助输入输出与坐标契约），次L5（按需/拒绝/失败与试验流程），必须下放L4。

证据：保留RTMPose二维（L6强3）；RTMW不再用于新路线（L6强3）；用户接受浏览器手机本地ONNX且全身IK唯一入口（L5强3）。置信度6/9×.9=.60。层级24/25、证据19/20、完备13/20、风险19/20、落地13/15，共88/100。结论：临时方案可评估，正式接入需补充：输入输出缺固定导出/近远方向契约，需逐项核对否则可能反向或错位；依赖缺本机Web/手机算子与内存，需实测否则可能无法运行；验收缺可见/遮挡提示及实际骨架收益，需保留失败/同初值对照否则只是多生成一张深度图。L4拆解见上方spec；本轮不调用代码翻译或伪代码专用同步技能，不因技能流程另增重复选项问题。
