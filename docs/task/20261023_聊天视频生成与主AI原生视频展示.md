# 聊天视频生成与主AI原生视频展示

## 任务与授权

用户确认完整视频接入，明确同时覆盖主AI自身生视频和SubAI生视频。遵循同一聊天消息展示、多视频与本地历史，视频上传默认关闭。design/spec为chat-video模块；改代码前已更新伪代码。

## 已实现模块

- chat-output-videos与Native视频解析：明确作品类型，Responses流/非流、仅视频与多视频，不把封面/普通文字链接当作品。
- video-catalog/jobs/service和doubao-video-result：独立账号/模型选择、任务API、私有状态、查询/重启恢复；现有Provider头抽取和媒体流聚合保持适配器小于1000行。
- SubAI生视频worker与主回复媒体协调器：占位、后台等待、本地视频/封面、同记录更新、重复指令防再次生成。
- llm-service/history-store、游戏流回调、server-app、双端chat及共用picker：原会话续聊、播放器、多媒体/空正文历史、清空/删除取消防迟到、WS权威配置。

代码文件清单由本次提交记录提供；新增test:chat-videos以及控制端只读播放器自测。

## 自测与性能

- 视频套件包含任务API/账号隔离、Native流与非流、多个视频去重、视频下载/文件头/大小/取消、重启仅查询、长ID、IM原消息隔离、模型WS权威保存、历史与实际播放器；最后一段失败保留其他视频。
- 图片35/35、Chat2API413/413、流式66/66、清空/生命周期27/27通过；视频完整31/31，另有豆包/GLM两段实际样片各2/2双端浏览器回放通过；空usage帧不影响后续视频事件。
- 视频按流写文件，不整段进内存，单文件256MiB；任务最多16个未完成/128条，等待上限20分钟。聊天/TTS不等待视频生成和下载。
- 兼容旧图片事件名chatImageMessage/cancelChatImage，扩展videos/videoGeneration；纯文字、图片与现有生图选择不受影响，视频输入入口仍未接入。
