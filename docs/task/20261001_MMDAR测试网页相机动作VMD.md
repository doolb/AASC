# MMD AR 测试网页相机动作 VMD 选择与播放

- 日期：2026-10-01。
- 状态：已完成实现、构建与自动验证；未发布外网，待现场验收。
- 任务描述：在 mmd-ar HTTPS 测试网页的动作面板上，增加选择本地 MMD 相机动画 VMD 并播放的功能；动作分类下新增「相机动作」开关和只读进度。
- design 需求：见 `docs/design/mmd-ar-test-apk.md` 的「2026-10-01 测试网页相机动作 VMD」。仅普通预览生效；「选择相机 VMD」位于「本地模型与动作」分组；循环播放；选文件后默认开启播放；进度只读；「恢复默认模型与动作」同时清除相机动作；不含相机关键帧的 VMD 明确报错。
- spec 设计：见 `docs/spec/mmd-ar-test-apk.md` 的「测试网页相机动作 VMD（2026-10-01，已实现）」伪代码。`loadVMD` 解析校验、`buildCameraAnimation` 生成循环 clip、固定 MMDAnimationHelper 绑定预览相机、定位中不推进、关闭恢复预览视角、far 按机位最远距离放宽。
- 受影响模块和代码：`3rd/mmd-ar-test/build.js`、`web-panel-groups.js`、`web-local-assets-ui.mjs`，新增 `web-camera-motion-inject.js`；仅注入生成的 `display-pmx-runtime.js` / `display-mmd.js` 网页副本，不改正式显示端源码与旧 APK。
- 自测用例：
  - 注入模块对当前 runtime/display 源锚点唯一（缺锚点构建失败），生成副本含相机动作 API；
  - 合成仅相机关键帧 VMD：加载成功、时长正确、进度随时间推进、相机位姿变化；
  - 关闭开关：停止推进并恢复加载前的预览视角，再开启从暂停处继续；
  - 不含相机关键帧的 VMD（内置 miya-default.vmd）：明确报错且不影响已加载相机动作；
  - 恢复默认模型与动作：清除相机动作并复位预览；
  - 动作分类包含相机动作开关与相机动作进度；本地资源分组包含选择相机 VMD 与当前名称；
  - 既有动作播放/物理/本地资源/面板测试回归。
- 兼容性测试：桌面与手机浏览器文件选择；与角色动作 VMD 同时播放；开启/停止 MindAR 定位往返；拖动/缩放/体感观察；物理开关重载模型；横竖屏与后台切换。
- 性能测试：相机 VMD 仅在预览帧推进 mixer，不增加物理与 IK 计算；加载只解析一次；稳态渲染不额外分配；far 放宽只影响投影，不改变 AO 采样配置。
- 风险评估：定位与相机动画互斥（已按「定位中暂停、退出恢复」处理）；播放中与拖动/缩放/体感观察的优先级（拖动仍旋转模型，缩放/体感不改变相机）；相机 VMD 机位距离大时需放宽 far 又需控制 AO 深度精度（按机位最远距离计算）；选择到角色动作 VMD 需明确报错。
- 需求评审（enterprise 默认；可选 standard）：可开发；主等级 L6，次等级 L5；建议下放到 L4。
  - 强证据 L6：选择本地相机 VMD 并播放、动作分类开关与进度、仅预览/循环/只读约束（用户确认），共权重 9；中证据 L5：定位暂停与退出恢复的状态流程，权重 2。置信度 9/11×0.90≈0.74。
  - 层级清晰度 23/25，证据充分度 18/20，实现完备度 17/20，风险暴露度 17/20，L4 可落地性 14/15；总分 89/100。直接开发风险中低。
  - 断点通过「定位中暂停、恢复默认清理、无相机帧报错、far 按机位距离计算」解决；L4 三段草案已写入 spec。
