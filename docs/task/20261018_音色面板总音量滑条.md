# 音色面板总音量滑条

日期：2026-10-18

## 任务描述与需求

用户希望在音色选择面板调整总音量，确认采用现有全局 TTS 音量，控制端和显示端均提供滑条。当前代码默认及本机保存值均为 100。需求层级为 L4：在现有 TTS 配置和双端快选入口内增加交互，不新增业务配置字段。

## Design 需求

见 `docs/design/tts-providers.md` 的“双端音色面板总音量”。两端共享 0–100 音量；拖动预览，松手保存；以服务端权威值为准，断线禁用并显示默认 100。音量调整不改变 Provider、音色或语速；新音量用于后续 TTS 生成。

## Spec 设计

见 `docs/spec/tts-providers.md` 的“双端音色面板全局音量滑条”。快选消息使用 `setChatTtsSelection { provider, volume, requestId }`；服务端仅接受有限整数 0–100，拒绝与 voice/speed 混写；写入 `defaultVolume`，广播 `ttsProviderConfig`。失败恢复原值，超时重取。

## 受影响模块与文件

- 面板与共享逻辑：`display.html`、`control-tts-voices.js`、`tts-voice-picker.js`、`tts-voice-picker.css`、`self-test.js`。
- 权限与配置消息：`tts-provider-ws.js`；沿用现有 `config.set` 持久化链路。
- 定向验证：`tests/tts-provider-ws.test.js`、`tests/control-tts-voices-browser.test.js`，及现有显示端/配置快选测试。
- 文档与产物状态：design/spec/usage/todo/changelog、`release/offline-release-status.json`。

## 自测、兼容性和性能

- 运行 `npm run test:tts-voice-picker`，覆盖双端初值、拖动不提交、松手提交、两端同步、0/100 边界、非法与混合写入拒绝、保存失败回滚、断线重连。
- 保留声纹页原 `setTtsProviderConfig` 编辑途径及显式请求音量覆盖。旧客户端不发送 volume，旧方式/音色/语速消息继续按原规则处理。
- 滑条 change 一次只发一条保存消息，input 不请求服务端；额外 DOM 和配置读写为常数规模，不新增上游合成或依赖。

## 风险与预计工时

主要风险是双端晚到操作误改当前方式，以及保存失败后滑条读数与权威配置不一致；通过独立根级 patch、请求 ID 和广播回滚验证。预计开发与离线验证约 2 小时，设备听感需现场另测。
