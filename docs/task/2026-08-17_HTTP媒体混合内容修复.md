# HTTP 媒体混合内容修复 + Range 流

## 任务状态：✅ 已完成

## 设计需求

参考：[design/media-library.md](../design/media-library.md)（HTTP 媒体混合内容修复 + Range 流）

## 问题描述

服务器启用 HTTPS（res/certs 存在 → useHttps=true）后，显示端页面为 `https://IP:8081/display`：

1. **手动输入 http:// 媒体地址无法播放**：控制端 URL 输入框输入 `http://192.168.1.39/mnt/AASC/res/uploads/xxx.mp4`（文件本身 200/video/mp4/Range 206 正常），下发到显示端后 `mediaVideo.src = http://...`，被浏览器/WebView 混合内容策略拦截 → 黑屏/无法播放
2. **http 媒体库（mnt/mnt2）同样被拦**：`HttpProvider.getPublicUrl` 恒返回 `http://{baseUrl}` 原始地址（Local/Smb 已支持 isHttps，Http 遗漏）
3. **192.168.1.101 不可达时服务器 init 挂死**：`_fetchHtml`/`getFileStream` 无超时，connect() 卡在 SYN-SENT 2-3 分钟，8081 一直不监听
4. **附带缺陷**：库代理端点不支持 Range（视频无法 seek）；HttpProvider 文件 URL 尾斜杠 404；_parseHtml 把 fancy-index 表头排序链接误当媒体项

## 根因

- `sendToDisplay`（所有媒体下发唯一出口）未对 http:// URL 做同源重写
- 无通用 HTTP 代理端点
- HttpProvider 未跟随 Local/Smb 的 isHttps 代理方案
- HttpProvider 请求无超时

## spec 设计

参考：[spec/media-library.md](../spec/media-library.md)（parseRange / Range 流返回约定 / HttpProvider 代理 URL / 通用代理端点）

```
rewriteMediaUrl(url):
    若 useHttps 且 url 以 http:// 开头:
        返回 "/api/media-proxy?url=" + encodeURIComponent(url)

sendToDisplay(displayId, data):
    if data.url: data.url = rewriteMediaUrl(data.url)   // 统一出口重写

GET /api/media-proxy?url=<编码>:
    校验 url 为 http(s)://
    SSRF 防护: 禁 localhost/127.x/::1/0.0.0.0/169.254.x/.local/fe80:（内网放行）
    upstream = HTTP(S) GET(url, {headers: Range 透传, 超时: 15s})
    relay 上游状态码 206/200 + Content-Type/Content-Range/Accept-Ranges/Content-Length
    upstream.pipe(res); req close 时 destroy upstream

parseRange(rangeHeader, totalSize):
    解析 bytes=start-end / bytes=start- / bytes=-suffix
    非法/越界返回 null（调用方回退 200 整流）

getFileStream(filePath, range?) 各 Provider 统一返回 {stream, statusCode, headers}:
    无 range: statusCode 200, headers.Content-Length=totalSize
    有 range: statusCode 206, headers 含 Content-Range "bytes {start}-{end}/{totalSize}"
HttpProvider.getFileStream: URL 去尾斜杠 + Range 转发上游 + 8s 超时 + relay 上游 206/200 与响应头
HttpProvider.getPublicUrl: 返回 "{协议}://{IP}:{port}/api/media-libraries/{id}/proxy/{encodeURIComponent(path)}"
HttpProvider._fetchHtml: 加 8s 超时
HttpProvider._parseHtml: 过滤 fancy-index 表头排序链接 + Parent Directory

库代理 GET /api/media-libraries/:id/proxy/*:
    用 getFile 的 size 解析 Range（本地/SMB）→ getFileStream(id, path, range)
    http 库 size 未知回落全量（不回归）
```

## 自测用例

1. 手动输入 `http://192.168.1.39/mnt/AASC/res/uploads/1774540973631_27401_1.mp4` → sendToDisplay 重写为 `/api/media-proxy?url=...`（服务器日志确认）→ 显示端可播放（Apache 访问日志 206 全量下载 + 分段续传）
2. /api/media-proxy Range 透传：`Range: bytes=0-99` → 206 + Content-Range `bytes 0-99/16275103`
3. /api/media-proxy SSRF：localhost/127.0.0.1 → 403
4. 库代理端点 Range：本地/SMB 视频 → 206；http 库 → 200 全量（不回归）
5. HttpProvider.getPublicUrl → 同源 HTTPS 代理 URL（单测）
6. 192.168.1.101 不可达 → init 8s 内完成（服务器重启 2.5s 就绪，无 SYN-SENT 挂起）
7. _parseHtml 垃圾条目 4 → 0（模块级验证）
8. `node --test tests/media-library-app-service.test.js` → 8 全绿

## 兼容性测试

- 浏览器显示端：https 页面加载 http 媒体 → 代理 URL（同源 https）不拦截
- Android WebView 显示端：MIXED_CONTENT_ALWAYS_ALLOW 已放行，代理 URL 同源正常
- HTTP 服务器模式（useHttps=false）：rewriteMediaUrl 不重写，http 库保持原始 URL 直连（兼容旧行为）

## 性能测试

- 通用代理流式转发 + Range 透传：固定缓冲，不整段载入（16MB 视频内存占用 KB 级）
- 8s 超时保证不可达服务器快速失败，不再阻塞 init

## 风险评估

- **SSRF**：代理端点禁本机/回环/云元数据，内网放行（媒体库本身即内网资源，威胁模型为已认证控制端）
- **显示端零改动**：display.html 未改，重写仅在服务端 sendToDisplay 出口
- **播放列表**：item.url 来自 getPublicUrl（已同源代理 URL），不经 rewriteMediaUrl，行为一致
- 已知边界：html 媒体走代理后，iframe 内嵌 http 子资源仍受 iframe 混合内容限制（主视频/图片可播）
