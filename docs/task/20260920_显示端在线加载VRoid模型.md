# 显示端在线加载 VRoid 模型

## 任务描述

将显示端的 MMD/VRM 占位 Canvas 接入真实 `three.js + three-vrm` 运行时，默认使用 VRoid Hub 模型页面
`https://hub.vroid.com/en/characters/1786977751194326803/models/3931412591784052736`。
模型通过服务端解析和同源代理在线获取，不将 VRM 二进制打入 APK。

## Design 需求

- 聊天、VRM 和媒体仍在同一个 `display.html` 舞台中。
- VRM Canvas 保持透明，默认位于聊天下方；聊天隐藏时模型可以接收点击。
- 模型页面地址只允许 VRoid Hub 的角色模型 URL。
- 服务端使用 VRoid `optimized_preview` 接口和 `X-Api-Version: 11` 获取可加载的 VRM 流。
- 服务端解包 VRoid 返回的 AES-256-CBC + zstd 预览载荷，并按 `PIXIV_vroid_hub_preview_mesh` 5.0 的确定性种子恢复 POSITION 顶点，校验为正常 GLB 后再提供同源模型响应；不引入 AGPL 的第三方 deoptimize 工具。
- 浏览器通过版本化的 Cache API/HTTP 缓存复用已恢复模型；在线失败时降级为占位模型。

## Spec 设计

- `ModelProfile` 增加 `sourceUrl`、`characterId`、`modelId`、`modelUrl` 和 `cacheKey`。
- 增加服务端 VRoid profile 解析接口和 VRM 二进制代理接口。
- 增加本地 vendor 的 `three.js`、`GLTFLoader`、`KTX2Loader` 和 `three-vrm` ES module。
- `display-mmd.js` 负责运行时加载、错误降级、可见性和点击转发；独立 VRM 模块负责 WebGL、VRM 解析、缩放、动画循环和 Raycaster。

## 自测用例

1. 合法 VRoid 页面 URL 可解析出 characterId 和 modelId。
2. 非 VRoid 主机、非角色模型路径和非法 ID 被拒绝。
3. profile 接口返回同源 modelUrl，不返回未校验的任意外部地址。
4. VRM 代理带 `X-Api-Version: 11`，正确跟随 VRoid 到 CloudFront 的重定向，解包 AES-CBC + zstd 载荷、恢复优化顶点并返回 GLB。
5. 显示端 HTML 使用 import map 和本地 vendor runtime，不创建 iframe 或第二条 WebSocket。
6. three-vrm 加载成功后不再绘制 Canvas 占位；加载失败时聊天、媒体和占位降级仍可用。
7. 模型隐藏、聊天显示、窗口缩放和高 DPI 下 Canvas 不改变 CSS 视觉尺寸。
8. 模型隐藏且聊天关闭时点击模型可发布 `mmd.interaction`。
9. Android WebView 使用恢复后的同源模型进行 WebGL 渲染，模型几何和材质正常生成。

## 兼容性测试

- 桌面 Chromium/Chrome：同源 profile、VRM 代理、WebGL 和透明 Canvas。
- Android 9 WebView/API 28：display 2、透明 WebGL、在线下载、缓存命中和失败降级。
- 当前真机 `192.168.1.6:5555`：页面状态为“VRM 模型已加载”，WebGL2 可用；同源恢复模型通过 WebView WebGL 渲染为正常角色。
- 无 WebGL 或断网：聊天和媒体继续工作，占位模型可操作。

## 性能测试

- 记录 profile 请求、模型首字节、模型解析完成和首帧渲染的耗时。
- 首次下载使用模型实际大小，后续打开验证 Cache API/HTTP 缓存命中。
- 隐藏 MMD 时停止渲染循环；聊天输入和媒体播放不受影响。

## 风险评估

- VRoid Hub 的临时资源需要网络，且官方 API 需要 OAuth；本任务使用公开预览资源，不把登录凭证放入 APK。
- VRoid 预览封装格式可能调整；当前只接受解包后带 `glTF` 头的 GLB，格式变化时安全降级为占位模型。
- VRoid 预览顶点恢复依赖资源路径和扩展时间戳；未知版本不猜测变换，安全降级为占位模型。
- 模型资源可能因平台策略、授权或 CloudFront 变化而不可用，必须保留降级占位。
- three-vrm 和模型解析增加首屏资源体积，采用动态 import 和按需模型加载降低影响。
- VRM 0.0 与 VRM 1.0 的动作接口不同；本任务先完成模型显示，VMD/VRMA 动作另行验证。
