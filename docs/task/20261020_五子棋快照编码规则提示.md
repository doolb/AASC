# 五子棋快照编码规则提示

日期：2026-10-20

## 任务描述

用户指出模型可能看不懂 `Game:五子棋,GM,快照,17f0,5,9,User,进行中,X......../...` 的棋盘编码。隔离真实 Qwen 曾在已有 AI 白棋的 E5 再次落子，被 GM 拒绝。用户要求在五子棋规则里解释快照。

## Design 需求与 Spec 设计

见 `docs/design/game-gomoku.md` 与 `docs/spec/game-gomoku.md`。五子棋专属规则增加 GM 快照字段顺序和编码含义：`/` 从上到下分行、行内从左到右按字母列、第一行是数字 1、`.` 空位、`X` 用户黑棋、`O` AI 白棋；模型落子前应确认目标格是 `.`。同一份规则由 GM 按需查询和进行中的 `NowGame` 提示复用。

## 受影响模块与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：扩充 `GOMOKU_RULES`。
- `tests/game-gomoku.test.js`：校验规则查询与活动棋局提示一致，验证第五行 E 格已被 AI 占用。
- 五子棋 design/spec/usage、todo、changelog 与服务包状态。

## 自测、兼容性与性能

运行 `npm run test:game-chat`；隔离本机 Qwen 用相同 A9 用户原话复测模型是否避开已占位置。规则仅增加少量提示文本，不改快照协议、棋盘持久化或 WebSocket。额外提示会增加每轮进行中聊天的 token 使用。

## 风险与预计工时

模型可能仍误读棋盘或选中已占用位置，GM 会继续拒绝非法落子。该提示不能替代权威棋盘校验；真实显示端体验需现场验收。预计约一小时。

## 执行结果

`npm run test:game-chat` 38/38 通过。隔离真实 Qwen `aasc-qwen-flash` + “小爱”角色在第 5、6 行 E 列已有 `O` 的 9 路快照上接收用户原话“我下 A9。我继续下散子，你尽量连五获胜。”；三次模型请求均含新增规则。模型先发 User A9，获 GM 第 6 手确认后选 AI F5，GM 第 7 手确认、轮到 User；未重试已占的 E5，最终自然语言与两次回执一致。单次样本不能保证以后每次都正确，真实显示端仍待验收。测试使用临时棋局和聊天运行目录，结束后清理。
