# Node获取mpv鼠标点击

状态：方案待确认，未修改生产代码。

- 任务描述：将常驻mpv窗口内的鼠标点击与坐标传入Node。
- design需求：docs/design/node-display-mpv.md的mpv鼠标点击采集章节。
- spec设计：docs/spec/node-display-mpv.md的待确认伪代码；Lua键绑定与mouse-pos采样经现有JSON IPC进入Node本地事件。
- 拟定范围：左/中/右键、左键双击、按下/松开/有效click；窗口坐标/OSD尺寸/旋转后ASS逻辑坐标。采集接管对应鼠标键，不默认添加播放、暂停、翻页或ASS按钮动作；不监听全局桌面。
- 受影响模块与代码：拟新增src/apps/voice-display-node/mpv-pointer.lua与mpv-pointer.js，修改mpv-player.js与media-controller.js，补tests/node-display-mpv相关单元/IPC及隔离实屏验证；同步使用、自测与项目文档。
- 自测用例：按钮/阶段/消息校验，hover与无效坐标、四方向逆变换、有效按下/松开、原生单双击顺序、尺寸/会话更换、能力关闭/退出、重复绑定与Lua缺失错误。
- 兼容性测试：Linux/Windows支持Lua的mpv共用桥接，维持原媒体/文本朗读与ASS信息层；Windows实际DPI/点击现场验收另计。
- 性能测试：只发送需要的按键事件，不持续轮询鼠标位置；事件长度/队列有界，重建/关闭释放桥接，不重复启动mpv。
- 风险评估：不同mpv构建可能缺Lua；鼠标绑定接管默认按键行为；双击通常伴随单击；窗口坐标与源媒体像素不同；窗口移出/尺寸变更需清理点击状态。
- 待确认：先做本地事件采集，后续具体点击业务由用户指定。
- 预计工时：约2～4小时完成桥接、事件标准化与Linux隔离实屏回归；业务按钮及Windows设备验收另计。
- 验证入口：优先npm run test:node-display-mpv及test:node-display-mpv:render，按变更补独立包检查；本轮只核对官方API和现有接收链路，尚未执行点击功能测试。
- 参考：mpv官方https://mpv.io/manual/stable/ 的Lua key bindings、mouse-pos、client-message。
