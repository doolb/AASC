# 服务器启动后隐藏分辨率诊断

## 任务描述

Offline APK 的分辨率、DPI 和 WebView 缩放诊断浮层在内置 Node 服务启动成功后继续显示 30 秒，随后自动隐藏，避免长期遮挡显示内容。

## design 需求

- 诊断浮层仍在服务启动前显示，便于观察启动阶段的分辨率和缩放配置。
- 以 `NodeServerService.STATUS_STARTING` 作为当前实现中的服务器启动成功点。
- 从收到成功状态开始计时 30 秒，服务重启再次进入该状态时重新计时。
- 不修改实际 WebView 缩放，只改变诊断浮层可见性。

## spec 设计

```text
refreshOfflineDisplayInfo:
  calculate display metrics and WebView scale
  show OfflineDisplayInfo

updateOfflineStartupStatus(status):
  if status == STATUS_STARTING:
    show OfflineDisplayInfo
    cancel previous hide timer
    schedule hide timer after 30 seconds

hide timer:
  set OfflineDisplayInfo visibility to GONE

onDestroy:
  cancel hide timer
```

## 自测用例

- 诊断浮层仍计算并显示当前分辨率、DPI 和缩放值。
- `STATUS_STARTING` 触发 30 秒延迟隐藏。
- 服务失败、解包或安装阶段不提前隐藏诊断信息。
- Activity 销毁时取消延迟任务。
- WebViewScalePolicy 和实际缩放调用保持不变。

## 兼容性测试

- 普通 APK 不显示诊断浮层的行为保持不变。
- Offline 启动遮罩、控制端按钮、服务更新卡片和 WebView 页面不受影响。

## 性能测试

- 仅增加一个主线程延迟任务，不增加 WebView、Node 服务或渲染循环开销。

## 风险评估

- `STATUS_STARTING` 表示 Node launcher 已成功创建；若后续需要严格以 8081 健康检查为准，应另行新增明确的服务 ready 状态。
