# MindAR Basic 可信度观测

- 需求：增加 MindAR 可信度相关指标和界面，说明对官方输出的既有处理。
- 设计/实现：见 `docs/design/mindar-basic-web.md` 可信度观测章节与 `docs/spec/mindar-basic-web.md` 伪代码。
- 完成内容：独立质量观测模块，复用官方点对和拟合矩阵；启发式分数、数量/比例、点分布面积、重投影误差及过期/丢失/停止状态；停止时移除包装。
- 影响文件：新增 `3rd/mind-basic/mind-basic-quality.js`，调整页面与控制脚本，新增 `tests/mind-basic-quality.test.js`，更新说明文档。
- 自测：27/27 定向回归通过；覆盖质量公式、分辨率归一、无效输入、原矩阵不变、调用上下文、方法恢复、取消回调、异常传播，以及原有融合/拍照流程。
- 兼容：依赖固定 MindAR 1.2.5 内部字段；不可用时显示状态，不伪造概率。无需 Google 服务，IMU 未启用时仍可观察。
- 性能：每个跟踪帧对已存在的点对做 O(n) CPU 统计，面板 10Hz 刷新上限；未增加 GPU 图像回读或额外识别，真机帧率待测。
- 风险：拟合残差与分布不能保证真实定位准确，经验分数尚未标定，因此暂不接入融合权重。
- 预计工时：约 40 分钟；发布状态：尚未发布，需同步 6 个运行资源。


真实库接入检查：Chromium 加载本地 A-Frame 1.5.0/MindAR 1.2.5，向模拟摄像头绘制官方卡片，使用真实 .mind 与跟踪算法（glTF 使用空模型）。一次采样为 21/32 有效点、特征分布 67%、RMSE 0.34 px、72/100 分；IMU 未启用时也正常显示。停止处理后面板分数清空并显示过期，触发丢失显示“定位已丢失”，点击停止显示“未运行”。最初使用 networkidle 等待导航超时，改用 DOMContentLoaded 后接入与状态检查完成。JS 语法与定向 diff 空白检查通过。此检查不等于手机实拍精度、完整模型加载或性能验收。
