# 聊天历史安全备份、导入导出与误删修复

## 任务描述

修复自动测试或普通聊天保存时因内存历史不完整而删除私聊历史文件的问题；增加上一天 `aasc-user` 全量配置单份自动备份、聊天记录和整个配置目录导入导出、明确范围清空保护。当前仍连接现有服务器，暂不实现自动测试请求级隔离。

## design 需求

- 普通历史保存不得清理内存中暂时不存在的历史文件。
- 清空、删除和替换导入必须明确指定范围并先备份。
- 按 Asia/Shanghai 每天保存上一天 `aasc-user` 下所有持久化配置的一份备份，覆盖旧备份。
- 控制端提供聊天历史和整个 `aasc-user` 目录的导入/导出；目录导入默认合并，替换必须显式指定。

## spec 设计

- 通过历史存储模块进行 JSON 原子写入、上一天备份、导入解析和消息去重。
- `llm-service` 维护待写入文件集合，只有显式变更的空文件才允许写空数组。
- 空范围 `clearHistory()` 拒绝执行，不再全量清空。
- 服务端新增聊天历史导入导出接口，前端调用后刷新当前历史。

## 自测用例

1. 当前内存只有群聊时保存，不删除已有私聊文件。
2. 显式清空小爱某个 session 后，只写空的目标文件内容，其他私聊不变。
3. 无范围清空请求被拒绝并留下日志。
4. 每天只保留一份上一天备份，新日期备份覆盖旧备份。
5. 导出 JSON 可重新导入，重复消息不重复写入。
6. 替换导入前可以恢复原历史。
7. 控制端导入后显示最新聊天记录。
8. 整个 `aasc-user` 配置目录导出后可在临时目录合并/替换导入，路径穿越和运行时文件被拒绝。

## 兼容性测试

- 旧数组格式聊天历史仍可读取。
- 旧消息缺少 `sessionId/profileName/templateId` 时继续使用原有默认值。
- 现有群聊、私聊会话筛选和删除本轮接口保持可用。
- Chat2API/Pi 会话文件不被历史导入导出误处理。

## 性能测试

- 普通消息仍使用 2 秒防抖保存。
- 备份只在每天首次保存或启动时执行一次，递归复制 `aasc-user` 下持久化文件并排除运行时文件。
- 导入去重使用消息 ID/稳定指纹，不增加 LLM 请求。

## 风险评估

- 当前自动测试仍会把测试消息写入真实群聊；测试隔离暂不实现，已保留为 todo。
- 上一天备份只保留一份，超过一天的备份不会在本地保留。
- Chat2API 内部上下文不能完整映射为 UI 历史，因此不自动恢复其 System/工具消息。

## 执行结果
