# 豆包普通与专业档回复解析

## 任务描述

用户反馈三档快选中豆包只有轻量能回复。排查普通和专业档的 Node 网页适配器，保证思考与最终答案分离且正文正常返回。

## Design 需求与 Spec 设计

- `docs/design/chat2api-doubao-web.md`：以实际 SSE 思考块的完成标记为依据，关闭思考通道后将新文字块作为答案；保留思考隔离和旧双边界兼容。
- `docs/spec/chat2api-doubao-web.md`：同一 `block_id` 的 `10040` 块从 `is_finish=false` 到 `is_finish=true` 时退出思考；每个 `10000` 文字块首次确定通道后保持归属。

## 受影响功能模块与代码

- `src/apps/server/modules/chat2api/chat2api-doubao-chat-adapter.js`：修正思考结束状态转换。
- `src/apps/server/modules/chat2api/chat2api-doubao-chat-adapter.test.js`：覆盖普通/专业两档流式与非流式、思考隔离和完整结束。
- `docs/todo.md`、`changelog.md` 与 Offline 出包状态：记录已验证结果和剩余部署验收。

## 自测用例与兼容性测试

- 修复前当前账号下 `doubao-think`、`doubao-expert` 短句均返回 `doubao_empty_response/502`；一次只读事件形状检查确认同块完成标记和答案增量。
- 修复后两个档位在同一账号的新会话中分别得到 4 字和 23 字非空正文；专业档 326 字思考内容单独留在 `reasoning_content`，不记录实际内容或凭据。
- 运行 `npm run check:chat2api`；保留旧双边界、空正文失败、取消、超时与账号会话隔离用例。本机服务已通过现有脚本重启；两端界面及 Offline APK/ADB 留待设备验收。

## 性能测试与风险评估

每个思考边界仅增加常数时间状态判断，无额外网络请求。不同上游版本若不给出可识别结束边界，继续明确报空正文，不把思考文本泄露为答案；长回复与多账号实际行为仍待验证。
