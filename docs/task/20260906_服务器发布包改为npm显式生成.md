# 2026-09-06 服务器发布包改为 npm 显式生成

## 任务描述

将主服务器代码发布包从 HTTP 请求时自动生成，改为由 npm 命令显式生成。发布接口只读取已经生成的 tar.gz 和 manifest，避免修改代码后因服务进程缓存继续下发旧包。

## Design 需求

- 增加 `npm run build:server-package`。
- 发布产物固定为 `res/temp/aasc-server-release/` 下的 tar.gz 和 manifest.json。
- 保留 `src/`、`package.json`、`package-lock.json` 白名单及现有排除规则。
- `/server`、`/server/manifest`、`/server/package` 不得触发打包。
- 批量更新子服务器前检查已生成发布包。
- APK、媒体、配置、日志、模型和证书不进入发布包。

## Spec 设计

- `ServerReleaseService.buildPackage()` 只由 npm 发布脚本调用。
- `ServerReleaseService.getManifest()` 只读取并校验 manifest.json 与压缩包。
- `ServerReleaseService.streamPackage()` 只流式读取已校验压缩包。
- 清单和压缩包使用临时文件生成后原子替换。
- 清单与压缩包大小或 SHA-256 不一致时拒绝下发。

## 自测用例

1. 未执行 npm 命令时读取清单，不能自动生成压缩包。
2. 执行 `npm run build:server-package` 后，清单和压缩包可读取。
3. 清单大小或 SHA-256 与实际包不一致时拒绝读取。
4. 压缩包只包含发布白名单路径。
5. 并发执行显式构建时只保留一个构建任务。
6. 批量更新子服务器前没有发布包时返回明确错误。

## 兼容性测试

- Termux Bootstrap 继续使用 `/server` 和 `/server/package`。
- 服务器更新、备份、回滚、健康检查流程保持不变。
- APK 不参与本次发布包流程。
- Windows/Unix 项目脚本均使用 Node.js 路径和现有 tar 工具链。

## 性能测试

- HTTP 清单和下载接口不再执行 tar。
- 清单读取会校验发布包 SHA-256，确保下发完整性。
- 显式打包只在用户执行 npm 命令时发生。

## 风险评估

- 未重新执行 npm 命令时，子服务器继续使用上一次发布包；接口会明确提示。
- 主服务器发布目录被手工删除或篡改时，更新会被拒绝。
- 发布包构建失败不会替换旧清单；临时文件会被清理。
