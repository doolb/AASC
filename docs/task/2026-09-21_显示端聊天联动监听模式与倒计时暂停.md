# 显示端聊天联动监听模式与倒计时暂停

## 任务描述

显示端打开聊天层时，将语音监听会话切换到当前聊天对象；聊天层打开期间暂停服务器端监听会话倒计时，关闭聊天层后从暂停时的剩余时间继续倒计时。聊天层内切换对象时同步更新当前显示端的监听目标。

## design 需求

- 群聊映射到 `activeGroup`。
- 私聊和角色聊天映射到 `activePrivate`，目标为对应角色名。
- 只影响当前显示端，不广播到其他显示端，不修改持久化远端配置。
- 监听能力关闭时不强行开启监听。

## spec 设计

- 显示端通过 `displayChatVisibility` 消息上报聊天层可见性和当前聊天上下文。
- 服务端维护当前显示端的临时聊天层状态，暂停/恢复权威会话计时器。
- 暂停保存 `remainingMs`，恢复时使用该值计算新的 `expiresAt`。
- 显示端倒计时只消费服务端的 `expiresAt` 与 `remainingMs`。

## 自测用例

1. 打开显示端聊天层，服务端收到 `displayChatVisibility(visible=true)`，会话切换为当前聊天对象并暂停倒计时。
2. 聊天层打开期间切换群聊、私聊和角色，当前显示端监听目标同步变化，`remainingMs` 不减少。
3. 关闭聊天层，服务端从保存的 `remainingMs` 恢复倒计时并在到期后进入 `waitingWake`。
4. 语音监听未启用时，打开/关闭聊天层不把 `disabled` 改成活动状态。
5. 两个显示端分别打开不同聊天层时，彼此会话目标和倒计时互不影响。

## 兼容性测试

- 普通浏览器显示端和 Offline APK WebView 共用同一 WebSocket 消息。
- 旧显示端不发送 `displayChatVisibility` 时，继续使用原有语音会话和倒计时逻辑。
- 既有 TTS 暂停/恢复倒计时逻辑保持原行为。

## 性能测试

- 聊天层开关和对象切换只发送单条轻量状态消息，不新增 WebSocket 连接。
- 倒计时仍由服务端单个 `setTimeout` 管理，不新增客户端高频同步。

## 风险评估

- 中风险：聊天层状态和语音会话状态通过异步 WebSocket 消息同步，断线期间可能暂时显示旧状态。
- 服务端收到重连后的当前聊天层状态后重新校正；未收到状态时维持旧版语音会话逻辑。
