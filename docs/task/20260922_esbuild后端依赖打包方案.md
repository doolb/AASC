## 任务描述

评估使用 esbuild 处理 AASC 后端纯 JavaScript 依赖的可行性，目标是减少服务运行包中纯 JS 依赖的文件数量，同时保留原生模块、模型、动态任务和现有 Offline 发布链路。

## Design 需求

- 保留 `server-launcher.js` 稳定入口和源码发布回退路径。
- 纯 JavaScript 依赖可以进入独立 bundle。
- ASR、TTS、声纹原生模块、Puppeteer 浏览器资源和模型保持外置。
- 动态 `require()`、用户任务、NodeJsRunner 和数据修复能力不能失效。
- 先生成独立验证 bundle，验证通过后才评估接入正式服务代码包、依赖包和 Offline APK。

## Spec 设计

1. 新增独立 esbuild 构建命令和输出目录，不直接替换当前启动入口。
2. 使用 Node.js/CommonJS 目标构建后端入口。
3. 将原生模块、Puppeteer、模型和动态运行时依赖列为 external。
4. 生成 bundle manifest、文件清单和 SHA-256，不改变当前正式发布 manifest。
5. 验证 HTTP、WebSocket、ASR、TTS、声纹、Chat2API、动态任务、数据修复和 Offline 更新回滚。
