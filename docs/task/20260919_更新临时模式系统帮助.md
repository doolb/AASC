# 任务：更新临时模式系统帮助

## 任务描述

将临时模式的两种首次输入方式同步展示到控制端“系统指令帮助”页面和语音系统帮助播报中。

## Design 需求

- 只说助手名：临时唤醒指定助手，随机播报短确认并等待后续内容。
- 助手名加内容：临时唤醒指定助手，随机播报短确认并直接处理内容。
- 控制端页面和语音帮助使用一致的行为说明，不改变命令解析逻辑。

## Spec 设计

```text
控制端系统帮助:
    显示 {助手名字} -> 临时唤醒，随机短确认，等待内容
    显示 {助手名字}+内容 -> 临时唤醒，随机短确认，直接处理内容

语音系统帮助:
    getVoiceCommandHelpText() 加入同样的两条临时模式说明
    说明首次确认来自随机候选池
```

## 受影响功能模块和代码

- `src/apps/web-mediacenter/ui/public/upload.html`：更新控制端系统指令帮助页面。
- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：更新系统帮助语音文本。
- `tests/builtin-command-list.test.js`、`tests/display-voice-builtins.test.js`：增加两处帮助内容契约。
- `docs/design/display-voice-conversation.md`、`docs/spec/display-voice-conversation.md`：同步帮助规则。

## 自测用例

1. 控制端系统帮助显示纯助手名临时唤醒说明。
2. 控制端系统帮助显示助手名加内容直接提问说明。
3. 语音执行“系统”时，帮助文本包含上述两条说明和随机短确认说明。
4. 其他内置命令、私聊和群聊帮助保持存在。

## 兼容性测试

- 运行控制端内置命令列表测试。
- 运行语音系统帮助测试。
- 运行显示端语音会话和临时历史回归测试。

## 性能测试

- 仅增加帮助文本，不增加语音命令处理或 TTS 请求次数。

## 风险评估

- 低风险：只修改静态帮助文本和对应伪代码，不改变状态机和消息协议。

## 预计工时

- 约 15 分钟。
