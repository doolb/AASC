# 子显示端 ASR 来源绑定

## 任务描述

修复 Node 子显示端 ASR 已识别但服务器不继续处理语音指令的问题。根因是 ASR HTTP 请求使用本地候选 `displayId`，且 Node 未保存服务器通过 WebSocket 确认的显示端 ID；服务器又直接使用请求 ID 判断在线显示端，导致来源不一致时只完成识别、不进入声纹门控和语音命令链路。

## Design 需求

- WebSocket 握手后的服务器 `displayId` 作为 Node 本次连接的权威来源。
- Node 的 ASR 请求同时携带表单 `displayId`、`X-AASC-Display-Id` 和 `X-AASC-Display-Kind: subdisplay`。
- 服务器先绑定在线显示端，再执行统一 ASR 结果处理；不依赖 ASR 后第二次 `voiceInput`。
- 失效来源只允许在明确标记子显示端且同 IP 存在唯一在线子显示端时回退；无法唯一绑定时保留 ASR 回显但不触发命令。

## 受影响功能模块和代码

- `src/apps/voice-display-node/main.js`：保存并等待服务器确认的 `displayId`，ASR 使用权威 ID。
- `src/apps/voice-display-node/asr-client.js`：发送来源 ID 和子显示端类型请求头。
- `src/apps/server/boot/server-app.js`：解析、校验并绑定 ASR 来源，绑定成功后进入语音命令处理。
- `tests/node-display-asr-source-binding.test.js`：来源绑定契约回归测试。

## 自测用例

1. Node 收到 `displayId` 消息后保存服务器返回的 ID。
2. Node 未收到服务器确认 ID 时不启动普通 ASR 上传。
3. ASR 请求包含表单 `displayId` 及两个来源请求头。
4. 在线 ID 可直接绑定并执行服务器语音处理。
5. ID 失效时，唯一同 IP 子显示端可回退绑定；多候选或非子显示端不回退。
6. 来源无法绑定时仍返回识别文本，但不调用显示端语音命令入口。
7. ASR 响应不触发第二次 `voiceInput`。

## 兼容性测试

- 网页显示端不带来源类型请求头但携带在线 `displayId` 时，保持原有服务器处理。
- 旧 Node 只携带表单 `displayId` 时，在线 ID 仍可直接绑定。
- 已有旧版 WebSocket `voiceInput` 入口保持兼容。

## 性能测试

- 来源绑定只读取内存中的 `displayClients`，不增加音频磁盘 I/O。
- ASR 请求仍为单次上传，新增请求头和一次 Map 查找，开销可忽略。

## 风险评估

- 服务器未返回 `displayId` 时 Node 会等待超时并重连，避免使用未确认身份误触发命令。
- 同 IP 多个子显示端且请求 ID 失效时只回显、不执行命令，优先保证不串台。
- ASR 识别结果本身不受来源绑定失败影响。
