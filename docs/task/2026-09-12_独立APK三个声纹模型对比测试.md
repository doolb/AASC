# 独立 APK 三个声纹模型对比测试

## 任务描述

在 `3rd/tts-server/android-asr` 测试 APK 中增加三个 Sherpa 声纹 embedding 模型的选择和对比测试：保留现有 ERes2Net-base，并加入 ERes2Net-large、ERes2NetV2。ASR、流式 ASR、降噪、Pyannote 分割模型和既有声纹测试模式保持不变。

## Design 需求

- 原生页面和内置网页都能选择三个声纹模型。
- 同时只加载一个模型，切换时释放旧 native 引擎并清空旧模型注册库。
- 模型选择不持久化，默认使用 ERes2Net-base。
- 显示当前模型名称、embedding 维度、匹配分数和耗时。

## Spec 设计

- `VoiceprintModel` 维护模型 ID、显示名称和 APK 资源文件名。
- `VoiceprintModelFiles` 复制三个 embedding 模型及现有 segmentation 模型。
- `VoiceprintTestCoordinator` 串行加载模型并在切换后清空进程内声纹库。
- `MainActivity` 和 `AsrWebPage` 复用同一模型选择流程。
- `AsrHttpServer` 增加测试 APK 内部模型切换路由和状态字段。

## 自测用例

1. 模型目录完整性要求三个 embedding 文件和 segmentation 文件全部存在。
2. 模型 ID、名称、资源文件名和三选一顺序稳定。
3. HTTP 状态返回当前模型及三个可选模型；无效模型返回 400。
4. HTTP 模型切换成功后返回新模型并清空注册库。
5. 原生页面和网页均显示三个模型选项。
6. ASR、流式 ASR、降噪和既有三种声纹测试模式回归通过。
7. Android JVM 单元测试和 Debug APK 构建通过。

## 兼容性测试

- Android 9/API 28、arm64-v8a。
- 三个模型均由现有 Sherpa `SpeakerEmbeddingExtractor` 加载。
- 切换模型后需重新注册，旧声纹不跨模型复用。
- 原有 HTTP 注册/测试接口参数保持兼容，仅增加模型状态和切换能力。

## 性能测试

- 记录三个模型的加载耗时、embedding 提取耗时和总测试耗时。
- 同一设备、同一 CPU 模式、同一注册/待测 WAV 下比较相似度和耗时。
- 只加载一个 embedding 模型，避免三个模型同时常驻。

## 风险评估

- 大模型加载可能耗时更长或触发设备内存不足，失败时必须显示未就绪且不影响 ASR。
- 不同模型的 embedding 不可混用，因此切换后清空注册库。
- 模型资源较大，APK 体积增加；模型文件保留各自上游许可信息。
