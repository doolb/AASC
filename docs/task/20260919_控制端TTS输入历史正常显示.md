# 2026-09-19 控制端 TTS 输入历史正常显示

## 任务描述

恢复控制端 TTS 输入框的浏览器原生历史提示，解决历史弹窗只首次出现并且鼠标移入后自动关闭的问题。

## design 需求

- 使用浏览器原生输入历史，不实现新的历史弹窗。
- 为输入框提供稳定字段名并显式允许 autocomplete。
- 使用独立 `autocomplete="on"` 表单，为浏览器提供稳定的表单上下文。
- 不在 focus/blur 时重建或替换输入节点，避免主动关闭原生历史弹窗。
- 不改变 TTS 发送流程。

## spec 设计

- 使用 `docs/spec/tts-input-history.md` 中的伪代码。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/upload.html`
- `src/apps/web-mediacenter/ui/public/js/tts.js`

## 自测用例

- 检查输入框存在 `name="ttsTextInput"` 和 `autocomplete="on"`。
- 检查 TTS 输入框位于 `ttsForm`，表单和提交按钮均使用 `autocomplete="on"` 语义。
- 确认 TTS 模块不记录输入内容、不创建自定义历史弹窗。
- 失焦后输入框仍为原节点，值保持不变，且节点仍使用 `ttsTextInput` ID。
- 连续点击输入框，确认浏览器原生历史提示具备重复出现条件。
- Node 语法检查和 `git diff --check` 通过。

## 风险评估

- 不同浏览器/WebView 对原生历史提示的展示策略可能不同；表单上下文只提供标准 HTML 语义，不强行控制浏览器 UI。
- 不读取、不持久化、不上传输入历史内容。

## 预计工时

- 输入属性和表单上下文：0.3 小时
- 浏览器/WebView 回归：0.2 小时
