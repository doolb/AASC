# 修复聊天配置导致历史不可见

## 任务描述

恢复被覆盖的 `qwen3.5` 聊天 profile，并修复聊天历史查询仅按当前 profile 过滤导致群聊、私聊和临时聊天记录显示为空的问题。

## Design 需求

- `config/config.json` 保留现有 TTS、ASR、语音窗口和其他运行配置，只恢复 `chat` 下的 `qwen3.5` profile 与 activeProfile。
- 历史文件不删除、不迁移，已保存的旧 profile 消息仍可在控制端查看。
- 继续保留新消息的 profile 标记和 LLM 会话隔离；历史可见性不等于把旧消息拼接进当前模型上下文。

## Spec 设计

- 配置启动时校验 `activeProfile` 是否存在于 `llmProfiles`。
- `getHistory()` 合并持久化历史并按时间排序，不隐藏已加载的旧 profile 消息。
- 明确的删除单轮、清空模式和当前私聊会话仍使用原有范围约束。

## 受影响的功能模块和代码

- `config/config.json`
- `src/external/llm/llm-service.js`
- `tests/` 聊天历史兼容契约测试
- `docs/design/chat-system.md`
- `docs/spec/chat-system.md`
- `docs/todo.md`
- `changelog.md`

## 自测用例

1. 启动服务后 `/api/chat/config` 返回 `activeProfile=qwen3.5` 且 profile 存在。
2. `/api/chat/history` 返回原有群聊、私聊和临时历史，不为空。
3. 新消息仍使用当前 profile 写入，旧消息不被重写或删除。
4. 清空/删除接口仍只影响明确指定的范围。
5. 相关 JavaScript 语法检查和聊天历史定向测试通过。

## 兼容性测试

- 没有 `profileName` 的旧消息仍按兼容默认值加载。
- 只有 `default` profile 的配置仍可启动并发送新消息。
- 历史文件缺失、损坏和多个 profile 混合时服务不崩溃。

## 性能测试

- 历史加载仍只扫描现有 `chat-history*.json` 文件。
- 查询只增加一次内存合并，不新增 HTTP 接口或额外轮询。

## 风险评估

- 恢复 `qwen3.5` 会改变当前新消息的 LLM 路由；该变化由用户明确确认后执行。
- 历史展示范围扩大后，控制端可能看到旧 profile 的记录，但不会自动把旧 profile 消息提交给当前模型上下文。

## 执行结果

- 已恢复 `config/config.json` 中的 `qwen3.5` profile 和 activeProfile，保留其他模块当前配置。
- `llm-service.js` 的历史展示不再按 activeProfile 隐藏已加载消息；LLM 上下文仍按 profile 隔离。
- 已完成配置 JSON、服务端语法、聊天历史契约测试和重启后的接口回归验证。
