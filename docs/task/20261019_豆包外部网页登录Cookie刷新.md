# 豆包外部网页登录 Cookie 刷新

日期：2026-10-19；状态：设计与浏览器对照完成，运行代码待方案确认。

用户提出固定“请只回复测试 OK/测试成功”指令可能被上游识别为脚本行为；当前失败与自然问候成功的样本还混有时间和会话状态差异，因此只列待验证线索。后续实测使用自然对话，并分别记录新会话与续接结果。

同会话追加现场测试：从豆包最近会话确认刚才“早”请求创建的会话及回复，用同账号 Node ready 状态续接，仅发送“早”。上游 ACK 与原会话 ID 一致，收到“早安～今天也要顺顺利利✨”、4 个分块并正常结束；本地控制端历史未修改。

重导后的追加现场测试：同账号通过 Node 发送全新会话、用户正文仅“早”，收到“早呀☀️”、4 个流分块并正常结束。与前次测试指令短句的 403 结果并存，不能把两次差异直接归因于消息文字或账号重导。

按用户要求继续执行删除重导：预检当前浏览器受支持 Cookie 和原账号 `nodeProfile` 后，删除原豆包账号并确认账号数为 0；使用现有 OAuth 完成接口导回同一账号 ID。恢复后豆包账号数为 1，其他账号未变，登录只读验证通过。Node 全新文字请求仍为 `doubao_risk_control`（403）、无正文；控制端聊天历史未删除。本次不修改运行代码。

现场追加验证：从当前 Vivaldi 页面取受支持的 Cookie，沿用原 `nodeProfile`，调用既有 OAuth 开始和完成接口并指定原账号 ID。账号 ID 与数量保持不变，规范 Cookie 与此前相同；只读验证为通过。随后 Node 全新文字请求在正文前收到 `doubao_risk_control`（403）。这只验证当前保存流程能更新原账号，不等于 Android 外部网页按钮已具备回存能力；风控仍待单独定位。

## 任务描述与设计需求

用户要求沿用当前 Chat2API“打开外部网页”的登录方式，在完成豆包安全验证后保存网页实际需要的 Cookie。现有外部网页只恢复已保存的六项 Cookie，完成按钮不回写账号。Vivaldi 中人工拖动验证后网页一次聊天成功；Node 用原六项、刷新六项、完整浏览器 Cookie 三种方式仍均返回 `doubao_risk_control`（403）。浏览器实发另有动态 `a_bogus` 和其他字段，全量 Cookie 保存不可被写成 Node 风控已修复。需求设计见 `docs/design/chat2api-doubao-web.md`。

## Spec 伪代码与受影响模块

见 `docs/spec/chat2api-doubao-web.md`。拟修改 `chat2api-login-profiles.js` 的豆包捕获声明、`Chat2ApiCredentialCapture.kt` / `Chat2ApiAuthWebView.kt` 的固定官方来源 Cookie 读取、`Chat2ApiLoginActivity.kt` / `MainActivity.kt` 的外部网页完成结果、`chat2api.js` 的原账号刷新回调、`chat2api-account-web-session-service.js` 的来源恢复，以及 `chat2api-data-store.js` / `chat2api-doubao-chat-adapter.js` 的受限快照校验与使用。原有六项规范 Cookie 与 nodeProfile 保留；完整网页 Cookie 按来源独立保存并受容量限制。服务端使用绑定账号的一次性刷新操作；失败不覆盖旧资料。

## 自测用例

- Android 捕获固定官方来源的当前 Cookie、人工验证后点击完成、取消、资料不完整与重复提交。
- 同名不同来源 Cookie、Cookie 数量和大小上限、非法名称/值、错误来源、账号版本冲突与失败保留旧资料。
- 账号网页恢复按原来源写入、旧六项账号仍可恢复；Node 构造请求使用新快照且不打印秘密。
- 本机定向测试、`npm run check:chat2api` 和 Android JVM 单测；真实豆包 Node 能否消除 403 另行验收，不能以格式测试代替。

## 兼容性、性能与风险评估

旧账号没有新快照时继续用原六项；其它 Provider 捕获和恢复不变。完整 Cookie 快照只对固定官网请求使用，限制名称、大小、数量，避免越域和日志泄露；写入必须绑定当前账号并原子替换，防止旧外部窗口覆盖新登录。额外 Cookie 体积应有界，验证后再更新 `servicePackage` 与 `minApk` 待出包状态。主等级 L5 登录刷新流程，次等级 L6 凭据契约，必须下放 L4 捕获、校验、回写和恢复步骤；风险中高，预计实现与定向验证约 4–6 小时。
