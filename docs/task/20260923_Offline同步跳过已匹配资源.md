# Offline 同步跳过已匹配资源

## 任务描述

Offline 同步脚本先下载资源，再检查本地目标是否已有相同文件，导致重复运行仍重新传输所有资源。调整为下载前预检并复用本地已匹配文件。

## Design 需求

- 下载前检查所有同步组件的目标路径和本地文件状态。
- 本地文件为普通文件，且大小和 SHA-256 均与当前清单一致时，跳过 HTTP 下载并标记为已复用。
- 目标缺失时才下载；同版本目标存在不同内容时，在任何资源下载前失败。
- 下载后保留安装阶段的二次检查，处理预检后并发变化。
- 复用项显示 `[已复用]` 和整体进度；传输项的日志前缀标记 `[下载进度]`。
- 清单仍在所有缺失资源通过大小/SHA-256 校验并安装后原子替换。

## Spec 设计

见 `docs/spec/android-offline-hot-update.md` 的 `syncOfflineUpdate` 伪代码：先建立包含目标路径与本地状态的 componentPlan，再下载 missing 项。

## 受影响的功能模块和文件

- `scripts/ops/sync-offline-update.js`：下载前预检、复用日志和进度标签。
- `docs/design/android-offline-hot-update.md`：本地复用策略。
- `docs/spec/android-offline-hot-update.md`：预检和同步流程伪代码。
- `docs/usage.md`：同步复用行为说明。
- `changelog.md`：变更记录。

## 自测用例

- 同步目标已有同版本、同大小、同 SHA-256 文件时不请求该资源并报告已复用。
- 目标缺失时下载一次，大小和 SHA-256 校验后再原子安装。
- 同版本内容冲突在下载前失败，清单不切换。
- 预检后并发写入相同目标时，安装阶段二次检查仍安全地复用。
- 进度日志明确区分 `[已复用]` 与 `[下载进度]`。

## 兼容性与性能

- 不改变命令参数和清单格式；二次运行减少不必要的网络流量。
- 本地复用需要读取已有文件计算 SHA-256，代价为本地顺序读盘。

## 风险评估

若已有版本文件内容冲突，脚本将更早失败；这是原有拒绝覆盖策略，只是把检查前移到下载之前。原子清单切换和 Android 验签规则保持不变。
