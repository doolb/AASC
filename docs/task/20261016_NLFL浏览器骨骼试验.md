# NLF-L 浏览器骨骼试验

日期：2026-10-16。状态：完成独立对照，未接入正式全身IK。

## 需求与设计

按用户确认，与已完成的NLF-S使用同一v0.2.0版本、三张原图、固定人物框和55°假设相机，对比原始24点XYZ、浏览器本地推理和图像叠加。L输入384×384，S输入256×256，保持原图相机一致并分别计算裁剪相机内参。原图、模型和结果只留忽略目录，不提交Git。

## 实现与影响

伪代码见`docs/spec/mmd-human-interface.md`。临时实现位于`tmp/mmd-pose/depth-eval/nlf-l/`：官方权重、单人裁剪FP32参考、固定24点ONNX导出、CPU/JS数值对照、原图浏览器WASM/WebGPU、可旋转XYZ报告和S/L并排页。同步设计、实现、使用说明和变更日志。正式MediaPipe Worker、VAM骨骼与构建输入均未改。

## 自测与兼容

权重495696900字节，ONNX471422850字节；SHA-256与复现命令见使用说明。CPU ONNX对官方FP32归一化最大误差三图分别为1.37e-6、5.42e-6、7.15e-6。JS重建对官方FP32 XYZ最大差均低于0.001mm。浏览器WASM/WebGPU均完成三图本机GET和叠图，390px宽度无横向溢出。WASM热运行约1705–1740ms；本机GTX1660 WebGPU首图969ms、其后128–140ms。浏览器与官方FP32 XYZ数值差最高0.611mm，仅验证实现一致。手机真机未测。

## 质量与风险

真人坐姿的抬高腿仍显示橙色右腿，与用户确认的左腿不符；动漫手臂和示意图交叉腿仍偏离。L未显示比S稳定改善，不应用到VAM。人工人物框与55°视角不代表自动检测和真实相机。官方完整半精度封装在本机CPU过慢，本次参考仅使用其官方单人裁剪、特征、解码和重建函数的FP32路径；不能宣称完整封装结果。ONNX体积较大，浏览器内存和手机性能是后续风险。
