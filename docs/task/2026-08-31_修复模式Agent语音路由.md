# 修复模式 Agent 语音路由

## 任务描述

修复模式工作 Agent 回复生成成功但没有在通用语音播放端播报的问题。当前实现将请求来源显示端作为 Agent TTS 的唯一播放目标，来源端和实际语音播放端分离时会导致用户听不到回复。

## Design 需求

- 修复模式 Agent 回复沿用通用语音播放目标，不默认播放到语音来源端。
- 每句 TTS 播放前动态获取当前在线且支持 `voicePlayback` 的显示端。
- 播放目标为空时只保留文字回复，不伪造播放状态。
- 继续携带 `allowRepairModeTts=true`，避免被修复模式的普通 TTS 抑制逻辑拦截。
- 生成端和播放端继续分离，`tts.device=display` 时可由任意可用显示端生成音频。

## Spec 设计

扩展 Agent TTS 播放器支持 `getDisplayIds` 动态目标解析。修复模式创建 TTS 流时不传入来源 `displayId`，改为通过该回调获取通用播放目标；来源 `displayId` 只用于修复状态、文字响应和错误反馈。

## 受影响功能模块和代码

- `src/apps/server/modules/chat/agent-chat-tts.js`：支持每句播放前动态解析显示端。
- `src/apps/server/boot/server-app.js`：修复模式 Agent TTS 改用通用播放目标和通用生成偏好。
- `tests/agent-chat-tts.test.js`：验证来源显示端与播放显示端分离时的动态路由。
- `tests/repair-mode-server-contract.test.js`：验证修复模式使用通用语音播放显示端列表。
- `docs/design/display-voice-conversation.md`、`docs/spec/display-voice-conversation.md`：同步设计和伪代码。

## 自测用例

1. 来源端为 `display-source`、通用播放端为 `display-speaker` 时，Agent TTS 下发到 `display-speaker`。
2. 当前播放端列表变化后，下一句使用最新列表。
3. 修复模式抑制开启时，带 `allowRepairModeTts=true` 的 Agent TTS 仍生成并发送。
4. 没有可播放显示端时不下发音频，但工作 Agent 文字回复仍正常回传。
5. 普通 Agent TTS 继续受修复模式抑制。

## 兼容性测试

- 普通聊天 Agent、控制端播放、单显示端和多显示端 Agent TTS 行为保持不变。
- 修复模式提示语、确认/取消提示和退出提示继续使用现有通用 TTS 流程。

## 性能测试

- 每句只执行一次内存中的显示端能力查询，不增加 TTS 生成请求。
- 不新增 Agent 进程、音频缓存或长期定时器。

## 风险评估

- 播放端在句子生成和下发之间断开时，该句可能无目标而只显示文字；下一句会重新解析目标。
- 多个播放端在线时会按通用语音策略同时播报，保持与普通显示端语音输入一致。

## 预计工时

约 1 小时，包含路由修复、回归测试和文档同步。

## 执行结果

- 已完成 Agent TTS 每句播放前动态读取通用 `voicePlayback` 显示端列表，不再默认使用修复请求来源端。
- 已保留 `allowRepairModeTts=true` 放行标记，修复模式 Agent 回复不会被普通 TTS 抑制。
- 验证：Agent TTS 测试 9/9 通过；修复模式业务测试 4/4 通过；相关源文件语法检查通过；服务端动态播放端契约断言通过。
- `repair-mode-server-contract.test.js` 的既有配置断言因工作区当前 `config/config.json` 使用密码“暖暖”而失败，未修改该用户配置。
