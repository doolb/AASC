# 外部视频焦点切换导致显示端画面冻结修复

## 任务描述

外部 APK 播放视频时，Android 显示端内部视频出现画面暂停但声音继续播放的现象。需要避免外部应用焦点切换后 WebView 视频渲染面被强制重建，同时保留全屏系统栏恢复行为。

## Design 需求

- `MainActivity.onWindowFocusChanged(true)` 继续恢复沉浸式系统栏。
- 焦点回归时不再执行 WebView `INVISIBLE`/`VISIBLE` 切换。
- 通过 `postInvalidate()` 请求普通重绘，不修改网页视频的播放、音量和媒体状态。
- 只有明确的画面异常入口才能触发渲染面重建，不能把每次窗口焦点回归当作黑屏处理。

## Spec 设计

```text
onWindowFocusChanged(hasFocus):
    调用父类实现
    hasFocus == false -> return
    hideSystemUi()
    webView 存在 -> webView.postInvalidate()
    不调用 webView.setVisibility(INVISIBLE/VISIBLE)
```

## 自测用例

1. 显示端播放视频时切换到外部视频 APK，再返回显示端，内部视频画面和声音均继续播放。
2. 窗口焦点回归时仍调用 `hideSystemUi()`。
3. 窗口焦点回归时调用 `postInvalidate()`，不调用 WebView 可见性切换。
4. 控制端明确暂停视频时，不因窗口焦点回归自动播放。
5. WebView 未创建或已回配置页时，焦点回归不崩溃。

## 性能测试

- 焦点回归只提交一次轻量重绘请求，不额外销毁或重建 WebView、视频解码器和音频管线。
- 不增加网页媒体 `play()` 重试和音频焦点请求。

## 风险评估

- 部分旧设备真实 GPU 黑屏可能不再由每次焦点回归自动修复；需要后续以画面异常检测作为更精确的重建条件。
- `postInvalidate()` 不能修复视频 Surface 已经失效的情况，但不会制造新的 Surface 重建和音视频状态分离。

## 实现结果

- `MainActivity.onWindowFocusChanged(true)` 保留 `hideSystemUi()`，改为对 WebView 调用 `postInvalidate()`。
- 删除焦点回归时的 `INVISIBLE`/`VISIBLE` 切换，避免外部应用焦点切换后重建视频 Surface/SurfaceTexture。
- 回归测试：显示端媒体焦点契约 9/9 通过，相关显示端/语音/文本媒体/睡眠回归命令退出码 0。
- `npm run build:apk` 构建成功；Debug APK 已覆盖安装到 `192.168.1.6:5555`，并通过 `npm run start:apk:display -- 2` 启动，进程存活且未发现 `FATAL EXCEPTION`。
- 真机当前可观察到外部视频应用任务与显示端任务并存；外部应用切换下的画面连续性仍需在设备上按实际视频场景人工确认。
