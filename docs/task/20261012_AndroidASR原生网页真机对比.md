# Android ASR 原生与网页真机速度/输出对比

## 任务描述

在 ADB Android 真机上对照独立 Android ASR 测试 APK 的原生推理与 ASR 网页 Worker/WASM 推理。测试 res/models/sensevoice/test_wavs 下全部音频，比较热态识别耗时及输出文本；追加单文件大核/小核对比。

需求等级：测试验证任务，不修改产品行为；目标是获取同设备、同模型、同输入下的实测数据。

## Design 需求

- 同一 SM-N9500 Android 设备与 SenseVoice INT8 模型、tokens。
- 遍历 test_wavs 中全部 7 个普通文件，自动语言模式，关闭 ASR 降噪，每份音频测两轮。
- 为排除解码器差异，网页 AudioContext 先统一解码/下混/重采样为 16 kHz 单声道 PCM；相同音频样本分别交给网页 Worker 和原生 HTTPS 本机接口。
- 推理耗时只读取各运行时报告的模型就绪后 elapsedMs。首次网页模型装载单独记录。
- 在一条代表性短音频上原生分别固定大核、小核各运行三轮，记录应用状态确认的核心范围。
- 无人工参考转写时只比较两端文本一致性，不推导识别正确率或 CER/WER。

## Spec 设计

伪代码流程见 docs/spec/android-asr-web-test.md 的“Android 原生与网页性能对比伪代码”。本轮 Web Worker 与原生 APK 共用相同输入 PCM；原生走 /api/asr 的 application/octet-stream 分支，CPU 模式由 APK CPU 模式选择器持久化并由 AsrCoordinator 在推理线程应用。

## 受影响模块与代码

- 读取 res/models/sensevoice/test_wavs 全部 7 个音频文件。
- 使用 3rd/tts-server/android-asr/web-dist 中已构建的 Worker/WASM 静态资产及 res/models/sensevoice 模型。
- 使用已安装的 com.aasc.asr 0.1.0/1 Debug APK、原生 HTTPS /api/asr 接口。
- 本机临时 HTTP 同源测试页、ADB 端口转发和结果采集仅位于临时运行环境；未新增仓库代码、修改 APK、模型或正式服务。

## 自测用例

1. 健康检查确认原生模型、流式模型和 HTTPS 服务就绪。
2. 全部 7 个输入逐一由网页解码为 16 kHz mono；同一份 PCM 分别送两端，每条两轮。
3. 检查两端文本逐字符一致，并分别记录 Worker 与原生 API 推理 elapsedMs。
4. 选择你好，小爱.wav；确认原生大核绑定核心4–7、小核绑定核心0–3，各识别三次；检查结果文本相同。
5. 测后将原生模式恢复为 AUTO，确认健康接口状态；关闭服务并移除 adb forward/reverse 映射。
6. 更新设计、伪代码、自测、待办和变更记录；运行 git diff --check。
7. 对用户指定标注的 `妲已妈妈.wav` 追加网页热态三轮与原生大/小核各三轮；剔除句末标点后按字符编辑距离计算 CER。

## 兼容性测试

- 真机：SM-N9500，Android 9，arm64-v8a；原生 APK versionName 0.1.0、versionCode 1。
- 网页：Samsung Internet 26.1，User-Agent 报告 Chromium 122；系统 WebView 132 已安装，但网页对比由 Samsung Internet 执行。
- CPU：设备在线核心0–7；APK运行时报告 BIG=4–7、LITTLE=0–3，读取到频率上限分别为2361600/1900800 kHz。
- a.wav 的实际容器为48 kHz mono WebM/Opus，非 WAV；本轮通过浏览器解码并共享 PCM，因此不覆盖原生 MediaExtractor 对该格式的解析兼容性。

## 性能测试

全量热态对比（每文件两轮，单位 ms）：

| 音频 | Web 两轮 | 原生两轮 | Web/原生均值 | 两端输出 |
|---|---:|---:|---:|---|
| a.wav | 7413 / 7106 | 5247 / 5224 | 7259.5 / 5235.5 | 123321。 |
| a.wav.converted.wav | 7118 / 7485 | 5174 / 5254 | 7301.5 / 5214 | 123321。 |
| dajimama.wav | 4624 / 5009 | 3127 / 3195 | 4816.5 / 3161 | 打字妈妈。 |
| dajimama2.wav | 6519 / 6968 | 4075 / 4158 | 6743.5 / 4116.5 | 打字妈妈。 |
| 你好啊你好啊你好啊.wav | 8723 / 8768 | 5258 / 5264 | 8745.5 / 5261 | 你好啊你好啊你好啊。 |
| 你好，小爱.wav | 5082 / 5076 | 2943 / 2976 | 5079 / 2959.5 | 你好，小爱。 |
| 妲已妈妈.wav | 4547 / 4527 | 2763 / 2659 | 4537 / 2711 | 打住妈妈。 |

全文件等权平均：Web 6354.6 ms，原生 4094.1 ms；平均值之比为1.55，原生平均少耗时35.6%。14组配对推理的输出完全一致。网页第一次推理 wall 20192 ms，其中下载/初始化和推理混合；Worker 本次报告纯推理 4794 ms。原生模型在计时前已就绪，首次热身请求 wall 3915 ms、推理 3678 ms；首次启动未作同条件比较。

核心模式结果（你好，小爱.wav，模型已热）：大核核心4–7为1400/1406/1422 ms，均值1409 ms；小核核心0–3为2960/3040/2910 ms，均值2970 ms。小核约耗时2.11倍，大核平均快约52.5%。所有结果文本均为“你好，小爱。”。

全量对比中同一音频的 AUTO 原生均值为2959.5 ms，接近固定小核均值2970 ms；由于未采样每次识别线程的 sched_getcpu，不能据此断定 AUTO 模式实际选择了小核。

原生与网页 ASR 均配置 numThreads=1；原生初始全量基准使用 AUTO，可由系统调度在全部核心运行；网页 Worker 未设置亲和性。设备频率调度、温度和其他应用负载会改变绝对耗时，以上数据只代表本机当前条件，不是跨设备保证或 P95 测试。

## 风险评估与预计工时

- 首次网页模型下载包含网络/存储/初始化耗时，必须和热态 ASR 解码时间分开报告。
- 全量目录没有人工参考转写，原有两轮配对结果只证明两端输出一致；用户后续仅为 `妲已妈妈.wav` 明确指定文件名作为标注，本次 CER 结果不推广到其他文件。
- 测量时设备有其他显示端/WebView活动，存在并行负载；大核/小核结果采用各三轮均值，不作长期热稳结论。
- 预计 1 小时；实际复用 APK、模型和现有 Web Worker，完成真机执行和文档记录。

## 执行结果

- 全量 7 文件、每文件两轮完成，Web/原生两端输出 14/14 配对完全一致；平均推理时间 Web 6354.6 ms、原生 4094.1 ms。
- 单个你好，小爱.wav 大/小核各三轮完成，核心亲和性在 APK UI 与健康 API 中均核实；大核均值1409 ms、小核2970 ms。测试后恢复 AUTO。
- 模型 SHA-256：SenseVoice INT8 为 c71f0ce00bec95b07744e116345e33d8cbbe08cef896382cf907bf4b51a2cd51；tokens 为 f449eb28dc567533d7fa59be34e2abca8784f771850c78a47fb731a31429a1dc。
- 停止原生 HTTPS 测试服务并删除 adb 端口映射。未修改运行时代码、APK、模型、Apache 或 Offline 发布状态。

### 用户标注样本补测（2026-10-12）

用户明确指定 `妲已妈妈.wav` 的文件名“妲已妈妈”为人工参考文本。音频为 16 kHz、单声道、2.304 秒；Samsung Internet 26.1 的 Worker/WASM 对 WAV 使用 AudioContext 解码后热态识别三轮，原生 APK 通过 `audio/wav` 接口解码，使用 `language=auto`、ASR 降噪关闭、`numThreads=1`，大核和小核各三轮。网页与原生分开运行；网页未绑定核心，原生模式由 APK CPU 选择器设置并由 `/health` 健康接口确认。

| 运行环境 | 核心模式 | 三轮推理耗时（ms） | 均值（ms） | 三轮输出 |
|---|---|---:|---:|---|
| Samsung Internet Worker/WASM | Android 自动调度 | 4588 / 4645 / 4531 | 4588.0 | 打住妈妈。 |
| Android 原生 APK | BIG（核心 4–7） | 1276 / 1263 / 1259 | 1266.0 | 打住妈妈。 |
| Android 原生 APK | LITTLE（核心 0–3） | 2677 / 2712 / 2620 | 2669.7 | 打住妈妈。 |

网页首轮模型加载 wall 为20275 ms，其中 Worker 推理为4947 ms；上表只列热态推理。原生大核比小核平均快约52.6%，网页平均耗时约为大核3.62倍、小核1.72倍。各模式输出相同；移除句末标点后，输出“打住妈妈”与参考“妲已妈妈”的字符编辑距离为2，CER为50%。这项标签仅由用户针对本文件明确指定，不代表其他文件名都是标注。

完成后原生 CPU 模式已恢复 AUTO，健康接口确认 `cpuMode=AUTO`；HTTPS 服务已停止，ADB forward/reverse 映射已删除。首轮尝试曾在浏览器模型加载期间同时调用原生，APK 进程被 Android 回收，故不计入数据；最终网页与原生测试分开执行并各自完成三轮。未修改仓库运行代码、APK、模型或正式服务。
