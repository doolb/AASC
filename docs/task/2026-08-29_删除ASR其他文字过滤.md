# 删除 ASR 其他文字过滤

## 任务描述

删除测试 APK、正式 Display APK、控制端配置和服务端 ASR 链路中的“过滤其他文字”开关及对应的 `zh-en-filter` 后处理模式。保留 `auto`、`zh`、`en` 语言选择、降噪、快速多段和流式 ASR。

## Design 需求

- 测试 APK 和正式 Display APK 不再显示过滤开关。
- 服务端不再保存、广播或应用 `filterOtherText`。
- Android 原生桥不再接收过滤参数，ASR 结果不再按 Unicode 脚本删除字符。
- `zh-en-filter` 不再作为语言模式；直接请求时返回参数错误。
- 普通 ASR、声纹分段 ASR 和流式 ASR 的其他功能保持不变。

## Spec 设计

```text
asrOptions = { languageMode: auto|zh|en, denoise: Boolean }
display.html 收到 asrConfig -> 调 asrConfigure(languageMode, denoise)
识别结果 -> trim(text) -> 返回
HTTP language 只接受 auto、zh、en
```

## 受影响功能模块和代码

- 网页：`upload.html`、`display.html`、`js/tts.js`。
- 服务端：`server-app.js`、`config-app-service.js`、`config/config.json`。
- 正式 APK：`NativeBridge.kt`、`AsrLanguageMode.kt`、`AsrEngine.kt`。
- 测试 APK：`AsrLanguageMode.kt`、`AsrCoordinator.kt`、`VoiceprintTestCoordinator.kt`、`AsrHttpServer.kt`。
- 测试和文档：ASR 配置契约、语言模式单测、design/spec、变更日志。

## 自测用例

- 控制端页面无“过滤其他文字”复选框及 `zh-en-filter` 选项。
- 服务端 ASR 配置响应只包含 `languageMode`、`denoise`，不包含 `filterOtherText`。
- 正式 APK 桥接和识别路径不再出现过滤参数。
- `auto`、`zh`、`en` 仍可解析，`zh-en-filter` 返回不支持。
- 中文、英文、日文混合识别结果不被脚本过滤器删除。

## 兼容性测试

- 流式 ASR 保持固定中英双语 Zipformer 和既有 WebSocket 协议。
- 既有降噪、快速多段、声纹匹配和唤醒词链路不改变。
- 浏览器无原生桥时继续使用服务端 ASR，但不执行文字脚本过滤。

## 性能测试

- 删除结果后处理后，不增加识别耗时和模型内存占用。
- 正式 APK Debug 构建成功，Android JVM 和 Node 契约测试通过。

## 风险评估

- 自动语言模式下可能继续返回日文或韩文字符，但结果不会再被静默删除，便于后续针对模型或语言提示优化。
- 删除 `zh-en-filter` 后，依赖该参数的外部调用需要改用 `auto`、`zh` 或 `en`。
