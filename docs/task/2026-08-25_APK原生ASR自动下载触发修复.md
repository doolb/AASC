# 任务：APK 原生 ASR 自动下载触发修复

## 任务描述

修复 APK 显示端能力检测异常导致原生 SenseVoice 模型不自动下载的问题，并补充服务器动态开启显示端 ASR 时的下载触发逻辑，为后续真机识别速度和内存稳定性压测恢复可用前置条件。

## Design 需求

- WebGPU 异步探测不能在 capabilities 对象初始化期间直接写入该对象。
- 首次能力探测发现原生 ASR 状态为 not_ready/error 时调用 asrEnsureModel()。
- 服务器动态推送 localAsrEnabled=true 且原生 ASR 未就绪时，同样调用幂等下载入口。
- 不改变模型 hash 校验、下载缓存、原生识别协议和浏览器 WASM 回退行为。

## Spec 设计

detectCapabilities:
  webgpuDiag = ''
  capabilities = 构造基础能力对象，并在 WebGPU 异步探测中只写 webgpuDiag
  capabilities 初始化完成后，如 webgpuDiag 非空则写入 capabilities._webgpuDiag
  nativeAsr 状态为 not_ready/error → 调用 asrEnsureModel

on asrConfig(localAsrEnabled=true):
  st = asrStatus()
  ready → 恢复 voiceRecognition 能力
  not_ready/error → 调用 asrEnsureModel，等待 ready 回调后恢复能力

## 自测用例

1. node --test tests/android-asr-download-prompt.test.js
2. 构建 npm run build:apk，确认 debug APK 生成。
3. 安装 APK 后设置 asr.device=display 并重连显示端，确认设备创建 files/models/sensevoice 并出现下载进度。
4. 确认模型 hash 校验成功、状态进入 ready，显示端上报 voiceRecognition=true。
5. 以 zh.wav 走 /api/asr/recognize，确认识别文本非空。

## 真机验证结果（2026-08-25）

- SM-N9500 / Android 9 / arm64-v8a 已安装新 APK；`files/models/sensevoice/` 自动生成模型、tokens 及两个 hash 文件，WebView `asrStatus()` 返回 `state=ready`，自动下载与加载前置链路通过。
- 服务器显示端列表确认 APK `display-dffht48c` 上报 `voiceRecognition=true`；压测期间临时关闭另一台桌面显示端的 ASR 能力以避免抢路由。
- `asr-stress-test.js --total 5 --concurrency 1` 的 5 次请求均路由到 APK，但全部返回“显示端 ASR 识别失败”，未得到非空识别文本；第 5 项自测不通过。
- 模型加载后 APK Native Heap 约 493MB，连续请求期间基本稳定；调试声纹匹配时出现 `VoiceprintEngine.match` native 崩溃并导致进程退出，声纹链路需与 ASR 分开修复和压测。
- 当前阻塞项：`NativeDisplay.asrRecognize()` 对有效 PCM 返回 `{}`，具体原生识别结果/异常封装链路待单独修复。

## 兼容性测试

- 浏览器显示端不注入 NativeDisplay 时仍走原有 WASM/服务端路径。
- APK 已存在模型缓存时不重复下载，只加载本地已验证模型。
- Android 9 / arm64-v8a 真机。

## 性能测试

- 模型就绪后执行短音频连续识别，记录平均、P95、最大延迟。
- 连续识别期间每秒采集 APK PSS、Native Heap、进程存活和 logcat 异常。
- 识别结束静置 30 秒，比较峰值与最终内存，确认没有持续增长。

## 风险评估

- WebGPU 诊断字段改为延后写入，不影响 WebGPU 可用性判定和诊断内容。
- asrEnsureModel() 依赖服务器 origin 已由主线程缓存；缓存为空时仍返回明确错误。
- 模型下载与加载可能占用约数百 MB 内存，真机验证需关注 OOM/系统回收。
