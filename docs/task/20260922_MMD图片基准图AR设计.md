## 任务描述

为当前显示端 VRM/PMX MMD 增加普通图片基准图 AR 方案：用户先拍摄一张照片，手动选择定位区域，之后使用手机摄像头识别该区域并让角色跟随图片平面移动。

## Design 需求

- 首期使用普通自然图片，不强制 QR、ArUco 或 AprilTag。
- 显示端本地完成拍照、四角选区、目标编译和实时跟踪。
- 摄像头帧、基准图片和特征索引不上传服务器。
- 目标和校准参数保存到显示端 IndexedDB。
- AR 摄像头视频位于 MMD Canvas 下方，不改变聊天、媒体和 WebSocket 层级。
- 保留 VRM SpringBone、PMX 刚体和动作更新。
- 暂不实现 ARCore、WebXR、深度遮挡和真实地面识别。
- 图片定位入口放在显示端右上角现有“灯光”按钮区域，位于灯光按钮正下方；AI/聊天继续使用已有“聊天”入口，不新增 AI 模式按钮。
- “定位”面板负责已保存目标、拍照校准、运行中切换定位图和停止定位；不关闭摄像头或 MMD runtime。
- 识别引擎暂通过 `ImageTargetTracker` 契约预留，未选定具体本地图像识别库时显示“识别引擎未就绪”。
- 六轴体感只用于放大角色的虚拟相机观察角度；不会调用角色旋转接口，角色仍由屏幕拖动旋转。

## Spec 设计

- 新增 `MmdImageArController`、`ImageTargetTracker`、`ArTargetStore` 和 `MmdArPoseAdapter` 伪代码契约。
- 使用 `ArTarget` 保存图片 Blob、四角选区、目标索引和可选实际宽度。
- 使用 `ArPose` 输出可见性、置信度、位置、旋转和缩放。
- 使用姿态平滑和短时丢失保持减少角色抖动。
- 首期不新增服务端 WebSocket 消息；后续远程启停另行设计。

## 自测用例

- 拍照并默认生成四角选区。
- 手动调整合法四边形并保存目标。
- 刷新页面后从 IndexedDB 恢复目标。
- 目标被识别时角色跟随移动、旋转和缩放。
- 短暂遮挡后恢复跟踪，角色不跳回原点。
- 停止 AR 后摄像头轨道释放，MMD、媒体、聊天和 WebSocket 正常。
- 摄像头权限拒绝、选区质量不足、识别失败均有提示。
- 显示端右上角可从“灯光”正下方打开“定位”；定位按钮能随 tracking/lost 状态更新文字。
- AR 跟踪过程中切换已保存定位图，摄像头和 MMD runtime 保持运行，旧目标失败时可恢复。
- 无识别依赖时可以完成目标本地保存、读取、删除和校准流程，并明确提示识别引擎未就绪。
- 启用体感观察后，权限、灵敏度和重新居中可用；禁用或停止定位后相机视角恢复默认，角色拖动角度保留。

- 10–15 FPS 目标检测对 CPU 的影响。

- WASM/Worker 资源体积和 Offline APK 增量。

## 风险评估

- 普通自然图片受光线、反光、纹理和遮挡影响，可能不如规则标记稳定。
- 未填写实际宽度时只能得到相对尺度。
- 没有深度数据时无法实现真实物体遮挡。
- Android WebView 摄像头权限和 WebAssembly 性能存在设备差异。
- 图像识别依赖必须随 Offline 资源发布，不能依赖 CDN。
