# APK 显示端主服务器连接修复

## 任务描述

修复 Android APK 显示端无法持续连接主服务器的问题：一是 APK 私有目录中的 Node Runtime 被解压为不可执行权限，导致内置 AASC 子服务器没有启动；二是 WebView 页面导航允许自签名证书，但同源 WSS 重连仍可能被 Chromium 的 TLS 校验拒绝。

## Design 需求

- Node Runtime 的 Android arm64 可执行文件放入 APK 原生库目录，以避免 AssetManager 解压到应用私有目录后丢失执行权限。
- 主服务器开发证书补充当前局域网访问地址的 SAN。
- APK 通过 Network Security Config 绑定主服务器公开证书，页面和 WSS 使用一致的 TLS 信任链。
- 未绑定或主机名不匹配的证书必须取消连接，不得对任意自签名证书调用 `proceed()`。
- 保留 display.html 已有的唯一重连定时器、过期 WebSocket 隔离和 error/close 重连行为。

## Spec 设计

- `docs/spec/android-display.md`：APK 证书信任和显示端 WSS 重连伪代码。
- `docs/spec/android-embedded-node-server.md`：原生 Node 库打包、启动和失败处理伪代码。

## 受影响的功能模块和代码

- Android Manifest、Network Security Config、主服务器证书资源和 `MainActivity` SSL 错误处理。
- Node Runtime 准备脚本、Gradle 原生库输入和 `NodeServerService` 启动路径（保留工作区已有未提交修复）。
- `tests/android-display-tls.test.js`、显示端 WebSocket 重连契约测试、Android Node 单元测试。
- 主服务器 `res/certs/cert.pem` 的 SAN；不更换现有私钥。

## 自测用例

1. 证书包含 `IP:192.168.1.39`、`DNS:localhost`、`IP:127.0.0.1`。
2. APK Manifest 引用 Network Security Config，配置引用 APK 证书资源。
3. APK 原生库包含可执行的 `libaasc_node.so`，旧的 `assets/runtime/arm64-v8a/node` 不再进入新包。
4. 主服务器重启后，设备显示端通过 WSS 自动重连并重新发送显示端能力信息。
5. Node 子服务器启动后主服务器日志出现 `node.register`，不再出现 `Permission denied`。
6. 证书不匹配时页面和 WSS 连接均被取消并记录错误。

## 兼容性测试

- Android 9/API 28、arm64-v8a 真机 SM-N9500。
- Android API 26+ 的 Debug APK 构建和安装。
- `https://192.168.1.39:8081` 的 HTTPS/WSS 连接。
- 仍使用合法系统 CA 的 HTTPS 主服务器。
- 手动输入 HTTP 地址时保持现有 HTTP/WS 兼容行为；HTTP 不使用自签名证书信任逻辑。

## 性能测试

- APK 启动后 Node 原生库加载不额外复制 49 MB 可执行文件到应用私有目录。
- 主服务器短暂重启期间，WSS 重连最多保持一个定时器和一个活动连接尝试。
- 证书校验不增加页面轮询频率；仅在 TLS 错误或 socket error 时进入既有 3 秒退避。

## 风险评估

- APK 只信任构建时绑定的主服务器公开证书；更换主服务器证书后需要重新构建 APK。
- 主服务器地址变化但证书 SAN 未覆盖时，APK 会拒绝连接，这是预期的安全失败。
- Node 原生库仍要求构建环境提供 Android arm64 Runtime；构建输入缺失时应明确失败。
- 不修改现有私钥，证书替换后主服务器必须重启，旧连接会短暂断开。
