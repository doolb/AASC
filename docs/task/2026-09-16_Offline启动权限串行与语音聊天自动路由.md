# Offline 启动权限串行与语音聊天自动路由

## 任务描述

修复 Android offline APK 启动时录音、摄像头和通知权限连续请求造成摄像头权限延迟到下次启动才出现的问题；修复控制端手动切换聊天模式后，显示端持续监听识别到的普通文本仍处于 `waitingWake` 而未进入聊天的问题。

当前阶段沿用 offline APK 服务进程的全局聊天模式：手动切换群聊/私聊后，同步当前在线且已开启语音监听的显示端。以后再将聊天模式和私聊目标改为按显示端独立保存与路由。

## Design 需求

- 权限按录音、摄像头、Android 13+ 通知顺序串行请求；每次系统回调后继续检查下一项，拒绝不阻断队列，已授权项跳过。
- 录音或摄像头本轮获准后，待权限队列结束再重载 WebView；不得因为权限申请自动修改用户的语音监听开关。
- 仅 `AASC_OFFLINE_MODE=1` 且控制端消息来源为 `controlManual` 时，根据服务端当前全局聊天模式同步在线显示端语音状态。
- 全局群聊设为 `activeGroup`；全局私聊设为 `activePrivate` 并绑定当前私聊目标，使用既有持续会话计时。
- 只更新语音监听已开启的显示端，不替用户打开麦克风；普通部署不触发该同步。
- 将“每个显示端独立保存聊天模式、助手目标与私聊会话，并独立路由语音聊天”登记为后续待办，本任务不实现。

## Spec 设计

```text
continueStartup:
    连接本地/远程显示服务并申请音频焦点
    requestNextStartupPermission()

requestNextStartupPermission:
    按 RECORD_AUDIO -> CAMERA -> Android 13+ POST_NOTIFICATIONS 查找首个未授权权限
    找到未授权权限 -> 发起单项请求并等待回调；授权或拒绝后都继续队列
    全部检查完成 -> 若录音/摄像头本轮获准则重载 WebView

handle setChatSession(session, source):
    chat.setSession(session)
    广播权威全局 chatSession 给控制端
    如果不是 OFFLINE_NODE_MODE 或 source != controlManual:
        返回
    对当前在线且 voiceRecording=true 的每个显示端:
        session.mode == private -> activePrivate(target=session.privateTarget)
        session.mode == group -> activeGroup
        启动现有持续会话计时器
    不改变 voiceRecording 能力
```

## 受影响的功能模块和代码

- `src/apps/android-display/app/src/main/java/com/aasc/display/MainActivity.kt`：串行权限请求与 WebView 延迟刷新。
- `src/apps/server/boot/server-app.js`：offline 模式下手动聊天会话同步到在线显示端语音会话。
- `src/apps/server/modules/voice/display-voice-conversation.js`：生成手动群聊/私聊对应的有效会话状态。
- `tests/android-offline-apk.test.js`、`tests/display-voice-manual-chat-sync.test.js`：权限顺序、offline/source 门控、全局群聊/私聊路由与监听关闭边界。
- `docs/design/*.md`、`docs/spec/*.md`、`docs/todo.md`、`changelog.md`：记录当前全局行为及未来 per-display 独立保存任务。

## 自测用例

1. 首次启动按录音、摄像头、通知逐项请求；上一个权限拒绝后仍请求下一个。
2. 已授权权限不会再次请求；本轮录音或摄像头获准后，权限队列结束时只刷新一次 WebView。
3. offline 模式下手动选择私聊后，所有当前在线且监听开启的显示端进入相同 `activePrivate` 目标，普通 ASR 文本进入当前全局私聊。
4. offline 模式下手动选择群聊后，所有当前在线且监听开启的显示端进入 `activeGroup`，普通 ASR 文本进入当前全局群聊。
5. 监听关闭的显示端状态不被打开；非 offline 部署、非手动来源和不支持的会话模式不触发同步。
6. 语音唤醒引起的控制端被动模式同步不重复重置全部显示端计时器。

## 兼容性测试

- 普通 APK 的现有连接和权限拒绝行为保持兼容。
- 非 offline 服务端继续保留既有会话/语音状态处理。
- 显示端唤醒、内置语音命令、声纹未匹配门控及语音回复来源路由不变。
- 关闭语音监听后，offline 全局模式同步不得自动重新开启采集。

## 性能测试

- 手动模式切换只遍历当前在线显示端一次；不新增轮询或 HTTP 请求。
- 权限队列每次只显示一个系统权限请求；WebView 最多在本轮队列完成后刷新一次。

## 风险评估

- 暂用全局 chatSession 意味着 offline 服务上的在线显示端共享当前群聊/私聊目标；按端隔离留待后续任务。
- 多个显示端可同时识别同一说话内容；继续复用现有同声纹跨端去重，声纹关闭时仍可能出现重复输入。
- 权限被拒绝时相应网页能力保持不可用，但不阻断 APK 启动或后续权限请求。
