# 固定 Release 签名配置

## 任务描述

为 `android-display` 配置独立且固定的 Release keystore，避免构建环境变化导致 APK 签名变化；保留现有 debug 签名流程。

## Design 需求

- Release 使用复制自原 `~/.android/debug.keystore` 的 `~/.android/aasc-release.keystore`。
- 密码和别名使用被 Git 忽略的本地配置或环境变量。
- Release 配置缺失时构建直接失败，不自动生成新签名。
- 不提交 keystore、密码和本机 `local.properties`。

## Spec 设计

- Gradle 读取本地签名属性，创建 `aascRelease` signingConfig 并绑定到 release buildType。
- 只有 Release 任务校验 keystore、密码和别名；debug 构建继续使用默认签名。
- 签名身份通过 keystore 文件持久化，构建后使用证书指纹验证。

## 受影响功能模块和代码

- `src/apps/android-display/app/build.gradle.kts`
- `src/apps/android-display/local.properties`（本机忽略配置）
- `docs/design/android-display.md`
- `docs/spec/android-display.md`

## 自测用例

1. Release keystore 存在且配置完整时，Release 构建成功。
2. Release keystore 缺失时，Release 构建在签名配置阶段失败。
3. 连续构建 Release APK，证书 SHA-256 指纹保持一致。
4. debug 构建不依赖 Release 密码配置，现有 debug 流程不受影响。
5. `git diff --check` 通过，keystore 和密码不出现在 Git 跟踪文件中。

## 兼容性测试

- Android 9 / arm64-v8a 真机安装 Release APK。
- 现有 debug APK 仍保持原有 debug 签名行为。

## 性能测试

- 签名配置不增加运行时内存和运行时线程。
- Release APK 仅增加签名处理时间，不改变应用运行逻辑。

## 风险评估

- 固定 keystore 丢失后无法覆盖更新已安装 Release APK，需要卸载重装；当前固定签名为测试用途 Debug 密钥，正式发布前必须替换为生产密钥。
- 密码只保存在本机忽略文件或环境变量，备份 keystore 时必须同步保护密码。
- 当前设备上的旧 APK 使用另一套签名，不能通过本次新 Release 配置直接覆盖。

## 预计工时

- 约 30 分钟，包括配置、构建和证书指纹验证。
