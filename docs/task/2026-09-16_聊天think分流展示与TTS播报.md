# 聊天 think 分流展示与 TTS 播报

## 任务描述

保留模型 `<think>`/`<thinking>` 标签内的正文：控制端聊天把思考内容收进 Think 按钮弹窗；显示端语音回复气泡同时展示思考正文和最终回答；TTS 按模型输出顺序播报两部分，但不能读出标签本身。

## Design 需求

- 聊天流分开维护最终回答、思考正文和去标签的原始播报顺序。
- 控制端历史及实时气泡只内联显示最终回答；Think 按钮弹窗显示思考内容。
- 显示端语音回复气泡以安全 Markdown 显示 think 正文和回答。
- TTS 收到标签内文本及正常回答，按模型输出顺序分句；标签不进入 TTS。
- 历史记录独立保存 reasoning 和 speech；旧记录兼容且 reasoning 不进入后续 LLM 上下文。
- 保留孤立结束标签之前的角色提示泄漏防护。

## Spec 设计

- `ThinkOutputFilter` 返回 `{ answer, reasoning, speech }` 及对应增量；流式标签跨 chunk 时不泄漏标签片段。
- `chatChunk`/`chatResponse` 保持 `message` 为回答并新增 `reasoning`/`speech` 字段。
- 控制端只在 Think 模态框渲染 reasoning；显示端语音回复将无标签 speech 放入现有安全 Markdown 气泡。
- TTS 分句器消费 speech 增量，确保 think 与回答依原始顺序播报。

## 自测用例

1. 成对 `<think>`/`<thinking>` 标签的正文进入 reasoning 和 speech，标签本身不进入任一字段。
2. 分片标签跨 chunk 时不泄漏标签文本；普通 answer 继续即时流式输出。
3. 孤立 `</think>` 前结构化提示词不显示、不播报；未闭合 think 在结束时保留为 reasoning/speech，但不进入 answer。
4. Responses、Chat Completions、Agent profile 的控制端流式回包区分 message 与 reasoning；TTS 分句为去标签的完整输出顺序。
5. 控制端历史渲染仅把 answer 放在气泡正文，Think 按钮弹窗使用安全 Markdown 显示 reasoning。
6. 显示端语音回复气泡显示 think 和回答；历史播放优先使用 speech，旧记录回退到 content。

## 兼容性测试

- Responses 与 Chat Completions 流式输出；普通模型无 think 标签时 answer、speech 保持一致。
- 完整、跨 chunk、多个及未闭合 `<think>`/`<thinking>` 标签，以及孤立结束标签。
- 控制端群聊、私聊、角色、临时会话；显示端语音回复弹窗。
- 没有 reasoning/speech 字段的旧历史与旧控制端消息。
- 不改变 Chat2API 对外 `reasoning_content` 协议和 MNN `enable_thinking` 请求语义。

## 性能测试

- 分流仅处理当前聊天文本，单轮内存开销与已生成文本长度线性相关。
- 不额外请求模型或重复生成 TTS 音频；沿用既有句子队列。
- Think 弹窗按需渲染，不增加每条历史消息的 Markdown 全量二次渲染。

## 风险评估

- 标签跨 chunk、嵌套/缺失结束标签可能导致正文误分；通过独立 parser 测试边界行为。
- think 可能含提示词泄漏；孤立结束标签前缀继续按既有规则丢弃，标签外答案规则不扩大。
- reasoning/speech 持久化增大聊天历史；字段独立、沿用消息长度上限，旧数据格式保持有效。
- Think 内容会被实际播报；这是用户指定行为，标签不播报，TTS 队列仍使用现有停止/路由机制。
