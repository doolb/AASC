# 显示端旋转角落位置校正

## 任务描述

修正显示端 90°/270° 旋转后固定文本虽然没有越界，但实际旋转包围盒没有贴合目标四角，导致上下和左右边距出现明显偏移。

## design 需求

- 90°/270°继续使用交换后的逻辑画布宽高。
- 根据文本元素当前使用的 `top`、`bottom`、`left`、`right` 锚点，重新对齐旋转后的实际包围盒边缘。
- 长中文仍必须保持在物理视口边距内，连接状态、媒体名、语音状态和播报文本使用同一规则。

## spec 设计

- 扩展旋转文本布局校正：读取 `getBoundingClientRect()`，将 `left/right/top/bottom` 对应的包围盒边缘对齐到 20px 边距。
- 90°/270°分别覆盖四角映射，保留内容变化监听和 resize 重算。
- 增加真实 Chromium 回归，验证每个文本元素的目标锚点误差不超过 1.5px。

## 自测用例

- 先运行四角锚点回归，确认当前实现会因旋转包围盒向内偏移而失败。
- 验证 90°/270°下连接状态、时间、媒体名、语音状态和播报文本均贴合对应边距。
- 运行长中文越界、内容异步更新、显示端集成和文本媒体回归。

## 兼容性、性能与风险

- 只调整显示端固定文本的 CSS 定位，不改变 WebSocket 协议和媒体播放流程。
- 每次旋转、resize 或文本变化增加一次轻量包围盒读取与定位修正。
- 长文本尺寸超过可用空间时仍由最大宽高约束限制，需持续验证窄屏和高 DPI 场景。
