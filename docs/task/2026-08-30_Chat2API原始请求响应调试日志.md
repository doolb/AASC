# Chat2API 原始请求响应调试日志

## 任务描述

为 AASC 内置 Chat2API 增加可控的原始请求/响应调试日志，方便排查 Provider 协议、认证和响应解析问题。日志必须默认关闭，开启后可从服务日志中按 requestId 还原一次请求的内部 Provider 调用链，但不能泄露凭据，也不能因为日志失败影响聊天请求。

## design 需求

- 在 Chat2API 配置中增加 `debugRawTraffic` 和 `rawTrafficMaxBytes`。
- 控制端可查看、修改这两个配置；默认关闭，最大日志预算默认 256 KiB。
- 统一追踪所有 Provider HTTP 请求，包括会话创建、Token 刷新、设备注册、聊天请求和轮询请求。
- 记录脱敏后的 URL、请求方法、请求头、请求体、响应状态、响应头和原始响应流块。
- 对 Authorization、Cookie、Token、Ticket、签名、API Key、密码和 URL 同类查询参数脱敏；超过字节预算后标记截断。

## spec 设计

- 通过 `createRawTrafficLogger` 生成带字节预算的追踪器。
- Provider adapter 在一次核心请求开始时读取配置并包装 `httpClient`，内部所有 HTTP 调用复用同一个 AASC requestId。
- 流式响应使用 Node Transform 记录后原样透传，不能改变现有 SSE/gRPC 解析输入。
- 调试关闭时直接调用原始 HTTP client，不序列化请求体和响应内容。
- 日志 sink 抛错、序列化失败或流日志失败均被隔离，正常请求继续执行。

## 自测用例

- 默认配置为关闭，Provider 请求过程中不产生原始流量日志。
- 开启后请求日志包含 requestId、Provider、脱敏 URL、请求体和请求头。
- 响应日志包含状态、响应头和完整预算内的非流式响应体。
- SSE 与 Kimi gRPC 流在日志追踪后仍输出完全相同的解析结果。
- Authorization、Cookie、token、ticket、signature 和 URL 查询凭据不出现在日志中。
- 请求/响应超过上限时日志包含 `truncated=true`，且请求不会失败。
- 配置拒绝非布尔开关、非整数或超出范围的字节数。
- 控制端能渲染开关、大小输入框并提交配置。

## 兼容性测试

- 已有 `config.json` 缺少新字段时使用默认关闭和 256 KiB。
- 不传入追踪器直接创建 Provider adapters 时保持原有调用行为。
- 非流式 JSON、SSE、压缩 SSE 和 Kimi gRPC-Web 响应均保持现有解析结果。
- 未开启调试时不增加原始响应流消费、日志文件写入或 Provider 请求字段。

## 性能测试

- 调试关闭时只读取一次请求配置，不复制或序列化请求/响应内容。
- 调试开启时单次请求日志受 `rawTrafficMaxBytes` 限制，超过后不继续累积内存。
- 流式响应透传不等待日志写入，不引入额外网络往返。

## 风险评估

- 开启调试会把聊天内容写入服务日志，控制端应明确提示仅用于临时排障，用户需主动关闭。
- 新增敏感字段时若未进入脱敏规则，可能出现凭据泄露；测试覆盖通用敏感关键词和 URL 查询参数。
- 二进制 Provider 响应不适合直接打印，采用截断 base64 表示并保持原始字节透传。
- 追踪器必须完全隔离异常，避免日志问题导致账号被误判失败。
