# 显示端聊天对象和历史切换修复

- 日期：2026-09-22
- 状态：已完成

## 任务描述

修复显示端聊天对象下拉菜单只显示一个助手、群聊/助手切换后历史内容串线，以及控制端收到会话切换后不刷新历史的问题。聊天数据必须继续由正常服务器接口提供，显示端不得依赖 Android APK 内部文件路径。

## Design 需求

- 设计文档：`docs/design/display-chat-mmd.md`
- `assistantConfig.assistants[]` 中的多个助手分别作为私聊对象，显示名称只使用助手名称。
- 群聊是独立对象，显示名称固定为“群聊”。
- 历史按 `mode`、`target`、`sessionId` 由服务器筛选，显示端通过现有 WebSocket `chatHistory` 请求获取。
- 切换对象或会话时不能继续显示旧对象历史；控制端收到权威会话后也必须重新渲染。

## Spec 设计

- 伪代码文档：`docs/spec/display-chat-mmd.md`
- 增加多助手名称归一化、目标构建、范围历史请求/响应和控制端重绘流程。

## 自测用例

1. 助手配置含多个助手时，显示端对象菜单逐一显示每个助手名称。
2. 群聊菜单只显示“群聊”，不显示“所有角色/私聊”等内部提示。
3. 切换群聊、助手 A、助手 B 后，每个目标只显示服务器返回的对应历史。
4. 同一助手切换 `default` 和其他 `sessionId` 后历史互不混入。
5. 显示端发送 `chatHistory` 时不访问本地文件路径；服务端按范围返回。
6. 控制端收到 `chatSession` 广播后立即重新渲染已有历史。
7. 旧控制端不带范围字段请求历史时，仍得到全量控制端历史并隐藏 think。

- 现有群聊、私聊、角色模式、清空聊天、think 展示和语音监听路由。

- 旧客户端仅发送 `chatHistory/source` 的行为保持不变。

## 性能测试

- 范围筛选只在已加载的服务端历史数组上进行，不增加磁盘读取次数。
- 对象切换只触发一次 `chatHistory` 请求和一次 DOM 重建，不创建新的 WebSocket。
- 控制端会话广播只重绘当前历史，不重复加载模型或媒体。

## 风险评估

- 旧消息缺少 `mode` 字段时按群聊兼容，避免历史丢失。
- 服务端返回全量历史时，显示端仍按当前目标过滤，降低旧服务包混用时的串线风险。
- 私聊目标名称变化会形成新的目标键；不自动迁移历史，避免误合并不同助手。
