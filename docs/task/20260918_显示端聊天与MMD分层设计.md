# 显示端聊天与 MMD/VRM 同位分层设计

## 任务状态

- 日期：2026-09-19
- 状态：第一阶段已实现，已构建 v20 min 并完成 code v11 热更真机验证；VRM/MMD 本地运行时待后续阶段
- 预计工时：5～8 个工作日（协议与聊天壳 2～3 天、VRM/MMD 运行时 2～3 天、动作协议和回归 1～2 天）

## 任务描述

为浏览器显示端设计一个与控制端共享数据的聊天入口，并在同一全屏舞台中增加 VRM/MMD 角色显示和动作控制。媒体继续位于最底层，聊天与 MMD 共享屏幕位置并支持上下视觉层级切换；角色聊天页面顶部提供会话切换。

本任务已确认按同一 `display.html` 拆分聊天/MMD 的 JS、CSS 和运行时模块，不使用 iframe；第一阶段已实现并打包到 Offline min v20，未新增模型二进制。

## Design 需求

- 设计文档：[display-chat-mmd.md](../design/display-chat-mmd.md)
- 显示端运行在浏览器，聊天入口提供对象选择和角色聊天页面。
- 不新增独立聊天或 MMD HTML 文档；模块挂载在同一个 `display.html` 的分层容器中。
- 聊天和 MMD 代码、样式分离，使用同页事件总线，不使用 iframe/postMessage。
- 角色聊天页面顶部提供角色与会话选择器，角色 A/B 的历史和上下文隔离。
- 控制端与显示端使用现有 WebSocket 聊天链路同步 `chatMessage`、流式回复、历史和会话切换。
- 当前首期沿用全局聊天上下文；按 `displayId` 独立会话留在后续任务。
- 媒体层为底层，VRM/MMD 和聊天使用同一个全屏舞台；默认 MMD 位于聊天下方，交互控制层始终在最上方。
- 采用 three-vrm 直接加载 VRM；通过 mmd-parser 和适配器播放 VMD/VRMA，并参考 MMDAgent-EX 命令语义。
- 高级动作使用模型无关的 `mmd.action.plan`；低级接口提供受限的 `MOTION_ADD`、`MOTION_DELETE`、`MODEL_BINDFACE`、`MODEL_BINDBONE` 兼容语义。
- 复杂动作生成通过异步 `mmd.motion.generate` 扩展，不能阻塞聊天首包。
- 聊天隐藏时，MMD Canvas 获得触摸事件；点击模型通过 Raycaster 触发本地动作，聊天联动默认关闭。
- 资源优先使用本地离线包或服务端缓存，外部 VRoid 地址只作为初始登记来源。
- 不拆分独立聊天或 MMD HTML，不使用 iframe/postMessage；通过同一页面的 JS/CSS 模块和事件总线协作。
- 首期先提供同页聊天壳、分层、隐藏切换和 MMD Canvas 交互骨架；VRM/MMD 运行时资源接入按后续阶段逐步启用。
- 显示端聊天/MMD 两个开关固定在交互层左下角，适配底部安全区和软键盘内缩。
- `render-display` 只位于媒体层之上，低于 MMD、聊天和交互控制层；聊天页面复用主题变量。
- 对象和会话切换改为同页 HTML 下拉菜单，不使用 Android WebView 系统原生下拉框。
- 下拉菜单普通、悬停/聚焦、已选中和已选中交互状态使用不同主题色，避免选项状态难以辨认。
- 聊天窗口改为全屏同位层；外层和消息列表背景透明，媒体可透出，顶部栏、消息气泡、状态栏、输入区和菜单保持实色。
- 显示端聊天对象支持 `assistantConfig.assistants[]` 中的多个助手；群聊单独显示为“群聊”，每个助手使用独立私聊目标和会话历史。
- 聊天历史只通过现有服务器 WebSocket 接口按 `mode/target/sessionId` 获取，不由显示端读取设备文件路径；对象或会话切换时清空旧视图并渲染服务器返回的范围历史。
- 控制端收到权威 `chatSession` 后立即重新渲染对应历史，避免切换群聊/助手时仍显示上一对象内容。

## Spec 设计

- 伪代码文档：[display-chat-mmd.md](../spec/display-chat-mmd.md)
- 设计覆盖舞台层级、移动端动态高度、软键盘、高 DPI Canvas、对象选择、会话切换、WebSocket 同步、模型缓存、动作计划、低级命令和错误回退。

## 自测用例

1. 显示端打开聊天入口，能看到角色/助手/群聊对象；无模型对象仍可聊天。
2. 进入角色后，会话选择器固定在顶部；切换角色或 session 后历史不串线。
3. 显示端发送消息，控制端能看到同一条消息；流式 `chatChunk` 和最终 `chatResponse` 两端一致。
4. 重复 `requestId`、过期 session 和断线重连不会重复插入消息。
5. 聊天隐藏、MMD 隐藏、MMD 上下层切换不影响媒体播放和输入控件操作。
6. 本地 VRM 加载成功时能播放待机和预置 VMD/VRMA；模型加载失败时聊天和媒体仍可用。
7. 高级动作计划能执行预置动作；非法资源、脚本、URL、越界骨骼和未知低级命令被拒绝。
8. think 内容按照显示端/控制端既有规则展示，TTS 不读取 think 标签，动作计划不进入聊天气泡。
9. 竖屏、软键盘、高 DPI、页面隐藏/恢复场景下无明显 UI 放大、遮挡或渲染循环泄漏。
10. 无外网时，已缓存模型和动作能运行；无模型时显示占位状态且聊天正常。
11. 聊天显示时聊天面板可输入；聊天隐藏后点击模型可以触发本地动作，且不会创建第二条 WebSocket。
12. 同一个 `display.html` 加载聊天、舞台和 MMD 模块；切换聊天可见性不重新加载页面、不丢失会话。
13. Offline min v20 在真机上覆盖安装后，服务健康接口返回 200，显示端 WebView 能连接 `https://127.0.0.1:8081`，无新增模块语法错误。
14. code v11 热更后 `active-release.json` 保留 code v11、`pendingHealth=false`，无 `failed-release.json`；显示端能看到同页聊天/MMD 开关。
15. 聊天/MMD 两个开关位于显示端左下角，底部安全区和键盘弹出时不被遮挡。
16. 页面使用 `defer` 加载模块时，点击聊天入口能生成聊天窗口，不会只切换空的聊天容器。
17. render-display 覆盖媒体但不遮挡聊天；对象和会话下拉菜单显示为页面内主题化菜单。
18. 下拉菜单未选中、悬停/聚焦和已选中状态的背景/文字颜色明显不同，且随主题变量变化。
19. 聊天窗口铺满舞台，空白区域能看到媒体，顶部栏、消息气泡、输入区和菜单保持实色且文字可读。
20. code v11 真机验收：聊天全屏透明背景、实色控件、下拉颜色区分和 WebSocket 聊天历史正常；无系统 Spinner/CheckedTextView。
21. 配置包含多个助手时，显示端对象菜单逐一显示助手名称；群聊菜单只显示“群聊”，切换每个助手后历史不串线。
22. 显示端请求聊天历史时使用现有 WebSocket `chatHistory` 的范围字段；服务端返回群聊或指定助手/会话历史，客户端不依赖 Android 本机文件路径。
23. 从显示端或控制端切换群聊/助手后，控制端和显示端均清空旧消息并显示新对象对应的历史。

## 风险评估

- VRM/VMD 骨骼和表情命名不一致：通过角色资源映射表和动作白名单处理，缺失轨道按部分播放降级。
- 全屏 Canvas 可能遮挡聊天：交互层固定最高层级，MMD Canvas 默认不接收聊天区域点击。
- 手机软键盘和高 DPI 可能导致舞台放大：使用动态视口、CSS 尺寸与实际绘制尺寸分离，并做 Android WebView 真机回归。
- 模型资源体积大：按角色懒加载，版本化缓存，首期不把所有模型放进首包。
- AI 动作计划可能包含危险字段：服务端和客户端双重校验，只允许资源 ID、语义动作和有限参数。
- 复杂动作生成延迟或失败：异步执行，立即返回聊天正文，使用待机动作和缓存回退。
- 当前全局聊天上下文与未来按 displayId 隔离存在迁移成本：将 displayId 作为可选上下文字段保留，避免重新设计消息结构。
