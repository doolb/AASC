# MMD AR 测试网页灯光与定位面板分组

## 需求与边界

- 将测试网页的灯光、定位长面板内相关设置折叠成分类；保留两个现有入口。
- 仅 `build:web:mmd-ar-test` 输出与外网 HTTPS 测试页变化；正式显示端和独立测试 APK 不变。
- 第一组默认展开，其他组默认收起，用户可独立开合；原控件 ID、值、事件与本地持久化不变。

- 测试：`tests/mmd-ar-web-panel-groups.test.js` 校验覆盖率、初始状态与正式源文件不变。

## 自测与兼容性

1. 构建网页，检查 9 个分类、所有原控件 ID、网页同源路径和 PMX/MindAR 清单。
2. 手机宽度检查折叠标题、滚动、灯光恢复默认与定位拍照/跟踪操作；分类收起不触发控件事件。
3. 检查网页专用代码没有进入 APK 构建路径；正式 `display.html` 不修改。
4. 上传前后核对 HTML 大小和 SHA-256，并检查 HTTPS 页面可用。

## 性能、风险与工时

- 分类使用原生 `details`，不增加运行时依赖或服务器请求；渲染开销可忽略。
- 风险：构建提取时遗漏新控件、移动按钮后事件无法触发。通过未归类节点检测和控件 ID/交互回归处理。
- 预计 2–3 小时，含构建、网页验证和外网上传。

### 分类文字误触修复

现场反馈点分类标题时只会切换开关。根因是原描述文字仍在复选框标签中，并占据标题大部分宽度；测试只点了右侧展开按钮。将原文字移入全宽展开按钮，复选框标签仅保留开关，原输入 ID/事件不变。新增浏览器真实标题点击、复选框点击与再次收起断言；构建和定向测试 3/3 通过。仅原子替换外网首页，HTTP 200，34,993 bytes，SHA-256=`f2daf5204103db0b71d583fc645031fa68a6e9e5c597e8d216c31ec14c8fc20c`；真机触摸仍待现场验收。

### 完整页面点击不展开修复

再次现场反馈分类仍展不开。完整线上页面复现 AO 分类点击前后 `hidden=true`；原灯光与定位面板都对内部点击调用 `stopPropagation`，导致 `document` 上的分类监听不可达。将监听直接绑定到各分类按钮。新增完整生成页、全部业务脚本的浏览器回归；旧页失败，新页 4/4 通过，灯光和定位分类均可开合。发布后线上浏览器实测 AO 收起→展开→收起、定位跟踪组收起→展开。只替换外网首页，HTTP 200，34,949 bytes，SHA-256=`7e03c8da6c8e795f7562df7e14e2dfe9ff91d5061e4faf8abb7e467c29d528ee`；APK 不变。
