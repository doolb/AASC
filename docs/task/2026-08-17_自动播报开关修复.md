# 自动播报开关修复 + 持久化

## 任务状态：✅ 已完成

## 设计需求

参考：[design/display.md](../design/display.md)（自动播报开关持久化 + 转发修复）

## 问题描述

控制端关闭「自动播报」后，显示端播放媒体时文件名仍会语音播报。

## 根因

- 控制端「自动播报」按钮发 `{type:'tts', action:'setAutoTts', enabled}` 到服务端
- 服务端 `setAutoTts` 分支**只更新 time.announce（整点报时）任务的 enabled**，记录日志「报时: 关闭」，**未 `sendToDisplay` 转发到显示端**
- 显示端 `autoTtsEnabled` 恒为默认 `true`，播放媒体时 `announceAndReport` 判定 `autoTtsEnabled && mediaName` 为真 → `playTTS(文件名)` → 照播

**模式对比**：同一 handler 的 `control` 消息各 action 处理后统一 `sendToDisplay(displayId, data)`，`tts` 的 stop/play 也显式转发，唯独 `setAutoTts` 分支（提交 8fccf52 加入）漏了转发。

**连带**：显示端 `autoTtsEnabled` 初始 true 且不持久化，刷新/重启后开关状态丢失。

## spec 设计

参考：[spec/websocket.md](../spec/websocket.md)（显示端状态 autoTts 字段 + setAutoTts 持久化转发）

```
服务端 handleControlMessageFallback, type==='tts', action==='setAutoTts':
    更新 time.announce 任务 enabled（整点报时）
    if displayData:
        displayData.state.autoTts = (data.enabled === true)
        config.updateDisplayState(displayData.ip, { autoTts })
    sendToDisplay(displayId, data)      // 转发显示端，媒体文件名播报开关生效

显示端 handleRestoreState(state):
    if state.autoTts !== undefined:
        autoTtsEnabled = !!state.autoTts    // 刷新/重启恢复；旧数据无字段保持当前值
```

## 自测用例

1. WS 发 setAutoTts=false → 服务端日志 `>> tts action=setAutoTts`（转发）+「报时: 关闭」
2. config `displayStates.<ip>.autoTts` 持久化
3. 显示端刷新/重启 → restoreState 恢复 autoTts（不重新播报）
4. `node tests/display-sleep-mode.test.js` → 24 步全绿

## 兼容性测试

- 批量播放：autoTtsEnabled 仍由 `announceName` 临时覆盖、结束后恢复（batch-playlist 既有逻辑不受影响）
- 旧持久化数据无 autoTts 字段 → handleRestoreState 跳过，保持当前值（降级安全）

## 性能测试

- 无新增开销：一次状态字段持久化 + 一条 WS 转发

## 风险评估

- 低：仅补转发 + 持久化一个布尔字段，不改播报主链路
- 附带修复的测试 h+1 边界属测试自身时间敏感 bug，与产品代码无关
