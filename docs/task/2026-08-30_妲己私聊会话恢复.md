# 妲己私聊会话恢复

## 任务描述

修复控制端进入妲己私聊时只显示“默认会话”的问题。保留已有聊天历史，避免控制端异步加载期间提交不完整会话列表覆盖服务端数据，并在会话元数据缺失时从历史消息恢复会话条目。

## design 需求

- 服务端保存会话状态时，按助手和会话 ID 合并客户端数据，不因缺失条目删除服务端已有会话。
- 列出指定助手的会话时扫描私聊历史，补回历史中存在但元数据文件中缺失的 `sessionId`。
- 原会话名称无法从历史消息恢复时，使用会话 ID 作为显示名称。
- 前端普通状态保存不提交 `sessions` 元数据快照，创建和删除会话仍由服务端会话接口维护。

## spec 设计

- 新增 `mergeSessionEntries(existing, incoming)`，按会话 ID 去重并保留服务端未出现在客户端快照中的条目。
- 新增 `recoverSessionsFromHistory(target, sessions, historyItems)`，恢复目标助手的私聊会话并确保默认会话存在。
- `setSession()` 使用合并逻辑保存会话状态。
- `listSessions()` 在返回前执行历史恢复并持久化变化。

1. 服务端已有默认会话和历史会话，客户端只提交默认会话，历史会话仍保留。
2. 妲己历史包含 `mp454fe0e8dz`，会话元数据只有默认会话时，列表恢复两个会话。
3. 恢复逻辑忽略其他助手、群聊和重复 sessionId 的消息。
4. 前端保存会话状态不发送 `sessions` 字段。

## 兼容性测试

- 旧版没有 `sessions` 字段的会话状态继续自动初始化默认会话。
- 旧历史没有 `sessionId` 的消息继续归入 `default` 会话。
- 既有创建、删除、切换会话接口保持原行为。
- 原有私聊历史文件只读扫描，不迁移、不删除消息内容。

## 性能测试

- 会话列表请求只扫描已经加载到内存的历史消息；恢复结果按时间排序后按 sessionId 去重。
- 不改变消息历史上限、LLM 请求和 TTS 处理路径。

## 风险评估

- 历史消息不记录会话名称，恢复的非默认会话可能显示为 sessionId，需要用户后续重新命名（当前接口没有名称恢复来源）。
- 客户端删除会话仍走显式删除接口；普通状态保存不会删除服务端会话。
