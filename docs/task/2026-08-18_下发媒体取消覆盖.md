# 下发媒体取消手动覆盖（临时激活优先级高于 override）

## 任务状态：✅ 已完成

## 设计需求

参考：[design/display.md](../design/display.md)（睡眠模式优先级与下发媒体）

## 问题描述

手动覆盖 `sleepOverride('sleep'/'deep')` 进入睡眠后，下发媒体（控制端播放）触发 `activateTemporarily()` 只**临时压过覆盖 60 秒**，激活窗口过期后 `checkSleepMode()` 回落手动覆盖（deep/sleep）——下发媒体没有真正取消覆盖状态，用户看完媒体又回到睡眠。

## 根因

`activateTemporarily()` 只设置 `activationUntil` 激活窗口 + 强制 active，不清 `manualSleepMode`；`checkSleepMode()` 优先级为「临时激活 > 手动覆盖 > 时段」，激活过期后手动覆盖仍在 → 回落覆盖。

## 修复方案

`activateTemporarily()`（下发媒体 / sleepActivate 临时激活统一入口）同时取消手动覆盖：

```
activateTemporarily():
    manualSleepMode = null              # 取消手动覆盖：下发媒体即退出覆盖
    activationUntil = Date.now() + 60000
    applySleepState('active')
```

`checkSleepMode()` 优先级不变（临时激活 > 手动覆盖 > 时段），但覆盖被取消后两者不会同时有效：下发媒体 → 显示 60 秒 → 过期后按正常时段判定（不再回落覆盖）。

## 自测用例

1. override=deep → activateTemporarily() → state=active、manualSleepMode=null、黑幕消失
2. 激活窗口过期 → checkSleepMode → 不回落 deep（enabled=false → normal，无黑幕）
3. `node tests/display-sleep-mode.test.js` → 27 步全绿

## 兼容性测试

- 正常下发媒体（无覆盖）行为不变：激活 60 秒
- sleepOverride='normal' 仍手动清除覆盖（既有路径不受影响）
- 覆盖期间下发媒体：覆盖被取消，媒体正常显示

## 性能测试

- 无新增开销（一次变量置 null）

## 风险评估

- 低：仅一处入口行为变更，覆盖语义从「临时压过」改为「下发媒体即取消」
- 覆盖仍可通过再次 `sleepOverride('sleep'/'deep')` 重新建立
