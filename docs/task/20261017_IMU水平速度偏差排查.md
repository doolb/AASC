# IMU 水平速度偏差排查

日期：2026-10-17。状态：先完成现有样本分析；用户随后确认通用六轴采样链路修正，代码与专项自测已实施，真机动作精度待验收。

## 任务描述与需求等级

用户反馈“水平速度偏差大”，后确认动作为拿手机竖直上举再下放；仍没有真实速度参考与完整停稳片段。按 `analyze-requirement-level` 的 enterprise 模式，此项暂判**需补充**，主层级L6（估计器输出契约），次层级L4（采样与积分步骤），置信度约0.56，直接开发风险高。评分：层级清晰度15/25、证据充分度8/20、实现完备度8/20、风险暴露度14/20、L4可落地性9/15，总54/100。已有证据为用户缺陷描述、固定房间原始样本、原生采样代码；缺少实际网页处理后轨迹。

能力下放判定：必须下放到L4。先取得同一时段的原始六轴、估计速度、静稳状态及两传感器时间差，再把误差归因拆成采样对齐、姿态误差、去重力残差和零速修正阶段。L4草案：已有声明为`NativeImuSample`、`ImuEngine.push`、`imu.frame`；新增定义为`HorizontalDriftSegment { rawSixAxis, estimatedVelocity, restState, sensorTimeSkew }`；操作流程为“采集同帧数据 -> 标记运动阶段 -> 比较原始力、姿态与世界加速度 -> 确定需修正的步骤”。

需补充：范围与目标方面，现已知竖直上举/下放，但末帧仍转动，建议覆盖停止后的持续静置，否则无法验证零速修正；输入输出方面，缺少电脑观察端处理后速度轨迹及两路采样时间，建议在后续方案中补齐，否则无法追溯错位；验收与观测方面，缺少真实运动速度或可接受误差阈值，建议至少以停稳后水平速度归零为可验收条件，否则无法判断改善。

## 现有样本结论

固定房间最近120条约7.2秒样本中，前约5秒静置后自动零速修正生效，最后约2秒含明显运动。角速度峰值约2.35rad/s，末帧仍约2.13rad/s；姿态相对静置累计变化约57°，加速度模长在6.73至13.54m/s²之间。用当前APK观察估计器从静置段重放，末帧速度约`[0.632,-0.387,1.294]m/s`，水平长度约1.44m/s。关闭世界加速度滤波后约1.444m/s，关闭加速度死区后约1.440m/s，说明这两项参数不是主因。采样间隔平均约0.061秒，动作中大量旋转与加速度变化；原生两路时间差最多允许100ms，但样本未记录实际差值，不能认定时间错位就是根因。用户明确选择“暂不改，先分析现有样本”，本轮没有改估计器、服务端或APK。

进一步统计：119个相邻时间间隔中，约40ms有58次，约80ms有61次，有效频率16.5Hz。原生采样上限约50Hz，但`MainActivity.kt`和`sender.js`均只保留最新待处理样本，限流后发送间隔增加且不自动恢复，快速动作的中间测量会丢失。候选通用方案：保留硬件时间戳的连续陀螺仪/加速度计样本，按时间插值配对并小批次传输；拥塞丢弃时显式标记断流；电脑依源时间逐样本积分并把APK观察估计帧写入已有轨迹接口。该方案仍不能保证竖直动作的水平速度严格为零；若仅需特定竖直动作，可另设用户手动开启的竖直约束模式。方案尚待用户确认，未改代码。

外部依据：[Android SensorEvent API](https://developer.android.com/reference/android/hardware/SensorEvent)规定事件时间戳对应测量时刻；[AOSP传感器批量说明](https://source.android.com/docs/core/interaction/sensors/batching)说明延迟上报不改变测量时间戳；[智能手机MEMS误差实验论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10490716/)指出采样离散化、时间误差与姿态误差会累积到速度和位置。这里的具体成因仍需新数据验证。

## 用户确认后的实施范围

需求：使用通用六轴数据链路减少快速竖直动作中的水平速度偏差，并让电脑观察页保存处理后速度轨迹。Design：`docs/design/imu-six-axis-test.md` 的“APK 竖直动作水平速度偏差的采样链路修正”。Spec：`docs/spec/imu-six-axis-test.md` 的“APK 连续六轴批量传输与观察轨迹”。先写Spec伪代码，再改以下模块。

受影响代码：`MainActivity.kt`分别缓存原生两路硬件时间戳并插值配对，`sender.js`有界排队及批量发送，`server.mjs`原子校验、逐条入库和广播，`imu-room.mjs`兼容单条及批次，`app.mjs`逐样本积分并发布观察帧，`imu-engine.mjs`响应显式断流标记。同步APK页面提示、两份使用说明、设计/规格/待办/变更日志。

自测用例：引擎收到`gap`后冻结位置并清零速度；房间批次顺序、两路时间、非法批次原子拒绝及旧单样本兼容；浏览器APK观察页按批次累计样本并经轨迹接口查到估计帧。兼容性：旧APK仍可发送`imu.sample`，模拟器和手机浏览器保留原输入流程。性能：原生和WebView各最多128条待发，WebSocket每批最多8条，单批验收有界，原始样本查询最多500条。风险：系统回调时序或拥塞仍可能造成缺口，六轴无法保证绝对水平速度，真实上举/下放须安装新APK再测。预计实施约2小时；真机现场验收另行记录。
