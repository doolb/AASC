# External 层第一步迁移任务

## 任务描述

- 目标：保持接口不变，将 `server.js` 对外部能力依赖切到 `src/external`。
- 范围：新增 External 兼容服务文件，更新入口引用，不改业务行为。

## design 需求

- 明确 External 第一阶段采用“兼容转发”方式迁移。
- 保持 App -> External 依赖方向。

## spec 设计

- 增加 External 兼容迁移伪代码。
- 明确 server 引用 `src/external/*`，External 再转发到旧 `core/*`。

## 受影响模块与文件

- `server.js`
- `src/external/asr/asr-service.js`
- `src/external/tts/tts-service.js`
- `src/external/llm/llm-service.js`
- `src/external/README.md`
- `docs/design/layered-architecture.md`
- `docs/spec/layered-architecture.md`
- `docs/task/2026-04-23_External层第一步迁移.md`
- `changelog.md`
- `docs/todo.md`

## 自测用例

1. 执行 `node --check server.js` 通过。
2. 执行 `node -e "require('./src/external/asr/asr-service')"` 通过。
3. 执行 `node -e "require('./src/external/tts/tts-service')"` 通过。
4. 执行 `node -e "require('./src/external/llm/llm-service')"` 通过。

## 兼容性测试

1. 外部 API 路径与消息流程保持不变。
2. 旧 `core/*` 仍保留，避免一次性大迁移风险。

## 性能测试

1. 本次仅路径重定向，不涉及算法改动，性能影响可忽略。

## 风险评估

- 风险：双路径并行期间维护成本增加。
- 缓解：后续第二阶段将实现体从 `core` 迁入 `src/external` 后收敛。
