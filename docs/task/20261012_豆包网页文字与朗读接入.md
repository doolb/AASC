## 任务描述与范围

以独立的豆包网页 Provider 接入 Chat2API 纯文字 LLM，模型名映射网页快速、思考、专家模式；参考 qwen-chat 增加仅 AI/Agent 可选的 `doubao-chat` TTS，前提是先验证网页朗读能合成指定任意文本并取得可安全校验的音频。与现有 `doubao-api` 语音资源和三方多模态统一草案隔离，不接入图片、文件、视频、音乐或上游原生工具调用。

## 设计与 spec 落地

1. Chat2API 已注册 `doubaochat` 内置Provider、固定来源校验和账号导入白名单；手动新增因缺安全登录校验拒绝。文字适配器已实现SSE增量、历史重放、固定错误、流取消及HTTP断连传递，未启用原生续接；Node直连403后不自动重试。
2. Chat2API Speech 显式模型到 Provider 分派，保持千问 `qwen-chat` 原语义；用户批准B后已新增实验性网页朗读适配器，默认禁用，真实运行仍待验收。TTS 业务端增加 `doubao-chat` 薄适配器、白名单模型/音色、AI/Agent模板和现有 WebSocket 权威配置。
3. 复用现有生产依赖和 HTTP Bearer 代理入口；不自动扫描用户 Chrome Cookie、不把凭证下发到 TTS 设置、不增加管理服务或独立配置 HTTP 接口。

## 兼容性与性能

- 保留账号列表脱敏、已有四种 TTS 设置、千问默认音色及豆包开放 API 密钥与资源 ID；不迁移或覆盖旧凭据。直接 HTTP 若因风控不可用，须明确报告，需要用户确认才能让 CDP 成为运行时依赖。
- SSE 和音频按受限字节/时限流处理，取消请求释放网络资源；TTS 尽量沿用 60 秒总时限、16 MiB WAV 上限；不读写个人聊天正文和原始上游包。
- 风险：网页接口不稳定、独立短文的一例正例不能推定任意长度/账号/音色可用、Android Node/WASM与设备播放未验收、账号可能验证码/风控；不虚构生产可用。
- 原阶段预计工时：文字LLM及集成测试约1–2日，网页TTS协议验证另1–3日；当前阶段预计工时与未完成边界以文末续接记录为准。

## 尚不明确

- 独立Frontier短文合成的一例正例不依赖既有回复，收到TaskStarted、SessionStarted、4个TTSResponse和TTSEnded；未保存Cookie、帧或音频。仍不保证任意长度、音色和账号，不证明完整Ogg或转WAV已可用，业务Provider不可提前显示为可用。
- 手动新增仍因缺安全只读身份端点拒绝；凭证包只校验格式。Node文字直连已验证403风控；think/expert、网页fetch运行模式及真实绑定未验收。HTTP断连取消已接通并有定向测试证据。
