# MMD AR 模拟图双侧透视与水平旋转

- 日期：2026-09-26
- 范围：仅 HTTPS 测试网页的模拟摄像头控制；正式显示端和旧测试 APK 不变。
- 需求：原经度滑条从下方移至模拟图左侧，保留原左右透视倾斜；下方改为 0–360° 画面内水平旋转。右侧纬度和上方缩放保留。

## Design 需求

四个滑条与画布拖动平移分别控制独立姿态分量。下方旋转先在原图平面内绕法线改变方向，再由左侧经度和右侧纬度构成透视；重置恢复 0°。转换前后按取景宽高比换算等长的 X/Y 单位，避免非方形画布下形变。两个竖向滑条均按所选原图比例和下方滑条实际宽度计算高度，不超过预览高度。

## Spec 设计与受影响代码

- 先更新 `docs/spec/mmd-ar-test-apk.md` 的控件位置、状态、透视投影和测试伪代码。
- `3rd/mmd-ar-test/build.js`：左侧放经度，右侧纬度；下方新增 0–360° 水平旋转控件与对应样式。
- `3rd/mmd-ar-test/display-mmd-ar-sim-camera.js`：新增水平旋转姿态分量；在三维平面中先旋转再投影，转换画布宽高比；两个竖向滑条同步尺寸与重置。
- `tests/mmd-ar-sim-camera.test.js`：布局、90° 几何关系、重置、拍照与 MindAR 回归。

## 自测、兼容性、性能与风险

- 自测：网页构建；无摄像头 Chromium 切换竖图/横图、四滑条和画面拖动；模拟拍照、首锁与流释放；相关定位回归。
- 兼容性：模拟图片本身与已存定位图分离；真实摄像头、正式显示端和旧 APK 不受控件变更影响。
- 性能：在现有四角投影计算中增加常量级二维旋转，不增加视频纹理上传次数。
- 风险：浏览器滚动与长竖图预览可能影响手机触控，需真机复测。
- 预计工时：约 1 小时；实际测试结果写入 `docs/self-test.md`。
