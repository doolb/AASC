# 2026-09-23 显示端旋转布局适配

## 任务描述

使显示端 MMD、聊天界面、灯光/定位控件和底部三个操作按钮跟随现有显示端旋转角度布局及旋转；旋转后保持面板可见、按钮可点、MMD 指针交互坐标正确。

## Design 需求

- 沿用 `currentRotation` 的 0°、90°、180°、270°值作为唯一旋转来源。
- 对 MMD、聊天层、灯光/定位入口和面板、底部“聊天/角色/停止播报”按钮分别应用相同旋转几何，保留播报层与各层之间的 z-index 顺序。
- 90°/270°交换逻辑宽高后绕视口中心旋转；物理外层舞台和已有独立播报层不重复旋转。
- 将 AR 实时视频背景同步旋转，保持视频、MMD 与控制层对齐。
- 映射刘海/安全区和软键盘遮挡边距；灯光与定位面板限制在旋转后逻辑视口范围内。
- 旋转后反算 MMD Canvas 指针逻辑坐标；保持模型点击/拖动及聊天操作正常。
- 不新增远端配置、服务端消息或持久化状态；不重建聊天或 MMD runtime。

## Spec 设计

- `docs/spec/display-chat-mmd.md`：新增 `getRotationStageGeometry`、`applyStageRotation`、`applyRotation`、MMD/AR 校准逆旋转指针坐标伪代码。
- `display-stage.js` 从 `window.currentRotation` 计算逻辑舞台尺寸、安全区/键盘边映射并更新 MMD、聊天、交互控件、AR 校准层和 AR 视频。
- `display-mmd.js`、`display-mmd-ar.js` 将 MMD/校准触摸点逆变换到逻辑 Canvas 坐标，维持四种角度下模型拖动和图片校准角点选择一致。

## 受影响的功能模块和代码

## 自测用例

1. 分别设置 0°、90°、180°、270°，确认 MMD、聊天层、灯光/定位入口与面板、底部三个按钮朝向和媒体一致。
2. 四种方向分别打开聊天、灯光和定位面板，确认边缘不越界、不遮挡，所有控件可点击和滚动。
3. 四种方向分别拖动 MMD 模型和 AR 校准四角，确认屏幕坐标映射、点击命中和图片选区方向正确。
4. 检查播报字幕、TTS/天气弹窗只旋转一次，定位相机画面与 MMD 对齐。
5. 旋转方向切换时保持聊天消息、输入内容、会话选择、MMD 模型和动作状态。

## 兼容性测试

- 桌面浏览器与 Android WebView 验证四种角度、视口缩放、刘海安全区和软键盘。
- 仅窗口尺寸变化时继续使用 ResizeObserver/visualViewport 重新排版；未设置旋转角度时按 0°兼容旧行为。

## 性能测试

- 旋转或窗口尺寸变化时仅重设 Canvas 尺寸并更新 CSS 变量，不重载模型、动作、聊天历史或摄像头。
- 确认连续 resize/orientationchange 合并在现有 resize 链，避免新增高频循环。

## 风险评估

- CSS transform 后 Canvas 的 `getBoundingClientRect()` 是物理包围盒；未做逆变换会导致模型点击/拖动错位。
- 安全区和键盘遮挡属于物理边缘，需按旋转角度映射到逻辑边缘，否则会出现面板/按钮被遮挡。
- 播报层已独立旋转，必须留在物理舞台之外以免双重旋转。
