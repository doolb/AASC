# 正式显示端 OCR 短边缩放

## 任务描述

为正式 Android 显示端 OCR 任务增加可选的图片短边尺寸参数，通过现有服务器 HTTP/WebSocket 路由传递到 APK 本地 RapidOCR。服务器不推理，YOLO 不增加缩放参数。

## Design 需求

- `shortSide=0` 保留当前自动行为。
- 正数表示目标短边上限，只缩小不放大；控制端预置 `384`、`512`、`736`。
- OCR 文字框坐标映射回原始图片坐标。
- 服务器和任务引擎校验参数，服务器只转发。

## Spec 设计

- OCR 内置任务增加 select 参数并在 JSON 请求中发送 `shortSide`。
- `/api/vision/ocr` 校验 `0` 或 `256..2048` 整数，WebSocket `visionOcr` 带同名字段。
- APK 保留原有 `ocrRecognizeAsync`，增加带尺寸的原生桥方法；YOLO 协议不变。
- `RapidOcrEngine` 对工作 Bitmap 做按比例缩小，返回原图尺寸和映射后的文字框。

## 受影响的功能模块与代码

- Android：`OcrImageScale.kt`、`RapidOcrEngine.kt`、`VisionRuntime.kt`、`NativeBridge.kt`。
- 服务端：`server-app.js`、视觉内置任务客户端和 OCR 任务。
- 控制端：`task-panel.js`、`display.html`。
- 文档：OCR/YOLO design、spec、usage、todo、changelog。

## 自测用例

- Node 任务测试：OCR 发送 `shortSide`，YOLO 不发送。
- Node 路由契约：服务器校验并转发 OCR `shortSide`，显示端选择带尺寸桥方法。
- Android JVM：尺寸合法性、只缩小策略、坐标映射。
- Android debug APK 构建并安装到 Android 9 arm64 真机。
- 使用 `/mnt/tmp` 现有游戏截图测试 `0/736/512/384`，记录耗时、框数和结果状态。

## 兼容性测试

- 旧 APK 仍可处理 `shortSide=0` 的 OCR 请求。
- 旧 APK 收到正数尺寸请求时返回明确的不支持错误。
- YOLO 请求字段和推理行为保持原状。

## 性能测试

- 同一显示端、同一组现有截图比较四种设置的本地 OCR 耗时。
- 记录成功率、平均耗时、平均文字框数、CPU affinity；无标注集时只做定性准确性说明。

## 风险评估

- 缩小过度可能损失小字号文字；由调用方选择 `736`、`512` 或 `384`。
- 坐标映射使用实际工作 Bitmap 尺寸，避免整数取整造成比例误差。
- 服务器不识别或不支持尺寸时返回结构化 400/不支持错误。

## 预计工时

- 文档与失败测试：0.5 小时。
- 任务、路由、WebView 和 APK：1.5 小时。
- 构建、真机截图对比和回归：1.5 小时。

## 执行结果

- Node 视觉任务、路由和显示端契约测试 8/8 通过；服务端 `node --check` 通过。
- Android `testDebugUnitTest` 通过，`npm run build:apk` 构建成功；新 APK 安装到 Android 9 arm64 真机 `192.168.1.6:5555`。
- 服务端 `/api/vision/status` 确认 `serverInference=false`，显示端 `display-umwo5k6l` 注册 OCR/YOLO 能力；非法 `shortSide=255` 返回 HTTP 400。
- 使用 `/mnt/tmp` 现有 4 张游戏截图，通过内置 OCR 任务走 HTTP→WebSocket→APK 本地推理，四档共 16/16 成功，全部为“单小核（核心 0）”；结果仍返回原图尺寸。
