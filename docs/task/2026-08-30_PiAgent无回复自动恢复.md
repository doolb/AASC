# 任务：Pi Agent 无回复自动恢复

## 任务描述

避免 Chat2API/上游短暂空回复或 Pi RPC 会话异常后，后续聊天请求长期卡在同一个 Pi 会话队列中。

## Design 需求

- Pi 请求排队等待时间与实际 RPC 执行时间分开计时，默认排队超过 30 秒直接失败。
- 空回复、RPC 错误或错误型 `agent_end` 后立即销毁当前 Pi session，不能继续复用异常进程。
- 空回复和可恢复 RPC 错误最多用新 Pi session 自动重试一次。
- 超时、协议错误、配置错误不做无条件重试，保持明确失败回包。
- 保留 requestId、失败原因和会话重建摘要日志，不恢复完整 prompt 或密钥打印。

## Spec 设计

- `PiRuntimeManager` 增加 `requestQueueTimeoutMs`，默认 30000 毫秒。
- 队列任务过期后不再调用 `runRequest`，并让串行队列继续收敛。
- `agent_end` 空文本、助手错误、RPC error/失败事件调用 session 失效清理。
- 可恢复错误通过新 session 重试一次，最终失败才调用外层 `onError`。

## 自测用例

- 上游正常返回文本时，Pi 仍能正常流式回调并完成。
- 空 `agent_end` 会关闭旧 session，并自动新建 session 重试成功。
- RPC 错误会关闭旧 session，重试一次后仍失败时只回调一次最终错误。
- 前一个请求不返回时，后续请求排队超过 30 秒返回排队超时，不继续向 Pi 写入。
- 服务器重启和 `stopAll` 能清理重试创建的全部 session。

## 兼容性测试

- 保持 Pi 的 `User:` 续聊格式、模板权限白名单、Chat2API 工具转换和普通 LLM 分支不变。
- 保持显式注入 logger 的测试能力；生产环境仍不输出详细 Pi 生命周期日志。

## 性能测试

- 正常请求不增加额外模型调用。
- 仅空回复或可恢复 RPC 错误增加最多一次重试。
- 排队超时任务不创建新的 Pi 进程，不增加上游请求。

## 风险评估

- 自动重试可能导致可恢复错误产生两次上游请求，因此限制为一次并只针对明确可恢复错误。
- 队列超时值过短可能误判慢请求；默认 30 秒只限制排队，不限制正常 RPC 的 600 秒执行超时。
- session 失效后重试会重新发送初始化 prompt，但不会重复追加应用历史。
