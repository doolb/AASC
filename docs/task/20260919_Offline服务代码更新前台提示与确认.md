# 2026-09-19 Offline 服务代码更新前台提示与确认

## 任务描述

解决 Offline APK 只提示 min APK、服务 `code/dependencies` 更新静默执行的问题。服务更新需要在 Android 前台显示候选版本和下载大小，用户确认后才停止旧 Node、下载校验服务包、切换 active release 并重新启动服务。

## design 需求

- 复用现有 LAN 优先、WAN 备用、域名解析替换 IP、RSA 清单验签和服务版本规划。
- code-only 与 all 两种服务更新都进入同一前台更新卡片。
- 用户未确认前只读取清单，不下载服务包。
- 更新失败继续启动旧 release；成功后沿用 pending health 和回滚机制。
- min APK 继续使用原有的用户确认和 Android PackageInstaller 流程。

## spec 设计

- `OfflineUpdateManager.checkForServerUpdate(root)` 只检查清单并返回目标 code/dependencies 版本、更新计划和下载大小。
- `NodeServerService` 接收 `EXTRA_APPLY_SERVER_UPDATE`，停止当前 Node 后调用 `applyServerUpdate`，通过应用内广播报告进度、完成和失败。
- `MainActivity` 在服务启动完成或恢复前台时检查服务更新，与 min APK 共用更新卡片；服务更新优先显示。
- 服务更新卡片确认后发送显式服务更新命令；完成后 Node 使用新 active release，失败后重启旧 release。

## 自测用例

- 当前服务版本与签名清单一致时不显示服务更新卡片。
- code 版本更高且 dependencies/lock 指纹一致时显示 code-only 更新。
- code 与 dependencies 均更高且指纹匹配时显示 all 更新及合计下载大小。
- 用户点击稍后不下载、不切换 release。
- 用户确认后状态流包含下载、校验、切换、重启；服务代码更新完成后 active release 指向目标版本。
- 下载、签名、空间或解压失败时保留旧 release 并允许重试。
- min APK 更新提示、未知来源授权和 PackageInstaller 流程不回归。

## 兼容性测试

- Android 9/API 28：完整 Offline APK、min APK、code-only 更新。
- full APK 已安装但没有 `active-release.json` 的旧 Runtime：legacy dependencies 兼容路径。
- LAN 不可用时通过 `c.aasc.us` DNS 解析后的 WAN IP 获取清单和服务包。
- update-only APK 没有完整 Offline 安装标记时仍阻止启动。

## 性能测试

- 清单检查在后台线程执行，不阻塞 Activity 主线程。
- 服务包下载和 ZIP 解压在 Node 服务单线程执行器中，不阻塞 UI。
- code-only 更新不下载 dependencies；all 更新只下载清单要求的 code/dependencies 文件。

## 风险评估

- 服务更新期间 Node 短暂停止，需由卡片状态明确提示。
- Activity 退出后仍可能完成服务更新；结果保留在 active release 和日志中，下一次启动继续健康检查。
- 更新包失败时必须避免覆盖当前 release，依赖现有暂存目录和原子指针机制。
- 新增原生 UI 行为需要重新构建并正式发布 min APK；仅发布服务 code 包不能让旧 APK 显示服务更新卡片。
