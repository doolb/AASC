# 控制端 VAD 输入框键盘焦点修复

## 任务描述

修复手机控制端点击 VAD 阈值数字输入框后，键盘弹出期间因设备/语音状态刷新导致输入框自动关闭的问题。

## design 需求

- 控制端仍可实时接收显示端列表、语音输入、会话状态和 VAD 配置回执。
- 正在编辑 VAD 阈值时不得替换当前输入框 DOM，保持输入值和键盘焦点。
- 输入框失焦后再完成延迟的状态卡片刷新，其他设备状态展示不改变。

## spec 设计

- `DeviceList.renderVoiceVadPanel()` 检查 `voiceVadPanel` 内的当前焦点。
- 焦点属于当前显示端的 `data-vad-threshold` 输入框时跳过 `innerHTML` 重建，并记录待刷新标志。
- 面板 `focusout` 且没有继续聚焦 VAD 输入框时，清理标志并执行一次完整刷新。

## 实现结果

- 在 `device-list.js` 增加 VAD 输入框焦点检测和一次性 `focusout` 延迟刷新。
- 输入框聚焦期间仍更新内存中的显示端状态，但不重建 VAD/摄像头卡片 DOM；显示端切换或下线时仍立即完整刷新。
- 使用 `setTimeout(..., 0)` 等待 Android WebView 完成焦点切换后再判断，避免键盘收起过程误判为可刷新。

## 自测用例

1. 当前 VAD 输入框聚焦时调用面板刷新，输入框节点、值和焦点保持不变。
2. 当前没有 VAD 输入框聚焦时调用面板刷新，仍能正常更新卡片 HTML。
3. 输入框失焦后，待刷新状态被清理并完成一次面板更新。
4. 运行 VAD 配置、语音监听和控制端 UI 定向回归测试。

## 兼容性测试

- 桌面浏览器控制端：VAD 输入、显示端切换、底噪检测和录音模式不变。

## 性能测试

- 键盘编辑期间不重复创建 VAD/摄像头 DOM。
- 失焦后最多补做一次完整面板刷新。

## 风险评估

- 焦点保持期间 VAD 卡片的非关键状态可能延迟到失焦后显示；设备列表和服务端状态仍实时更新。
- 若显示端被切换或下线，不能保留旧设备输入框，必须执行完整重绘。
