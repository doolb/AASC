# Chat2API 普通网页手动外部认证

## 任务描述

普通网页控制端支持用户在外部登录后复制 Cookie，按 Provider 专属规则手动添加 Chat2API 账号；不打开供应商登录页，不支持普通网页 OAuth。Android 隔离 WebView 登录能力继续保留。

## design 需求

- 新增普通网页“手动添加外部认证”界面。
- 认证入口沿用 Chat2API：Provider 先选，随后进入统一账号表单；表单同时承载手动 Token 字段和支持 Provider 的完整 Cookie，Android 额外提供当前 Provider 的外部登录按钮，普通网页隐藏。
- 服务端解析 Cookie 并提取 Chat2API Provider 所需字段。
- 复用现有凭据校验和账号持久化，校验失败不保存。
- 对不支持完整 Cookie 认证的 Provider 保留 Token/手动字段入口；Cookie 认证只开放 MiMo、Perplexity、Qwen。

## spec 设计

- `parseCookieHeader` 解析标准 Cookie 字符串。
- `extractManualCredentials` 使用 Provider 专属映射生成现有凭据字段。
- 统一表单根据 Cookie 是否为空自动选择 manual/cookie 输入；保留服务端 `authMethod` 兼容参数，`external` 仍只走 Android WebView。
- `POST /api/chat2api/accounts/manual` 调用手动账号服务。
- 控制端成功后刷新账号列表并清理敏感输入。

## 自测用例

- 解析多个 Cookie、忽略属性段、拒绝空输入。
- MiMo、Perplexity、Qwen 的完整 Cookie 字段提取；GLM、Kimi、Qwen AI、Z.ai 等 Provider 的手动 Token 字段提示。
- 缺少必要字段时不发起 Provider 校验、不保存账号。
- Provider 校验成功后保存并返回脱敏账号。
- Provider 校验失败时不保存账号。
- 普通网页提交走 manual 路由，不打开登录页；Android 原有 start/complete 流程保持不变。

## 性能测试

- Cookie 解析只遍历输入一次，常规 Cookie 字符串处理不产生网络额外请求。
- 手动添加仅增加一次 Provider 校验请求，账号存储复用原流程。

## 风险评估

- Provider Cookie 字段可能变更；映射集中管理，未知字段不自动猜测。
- Cookie 属于敏感凭据；禁止日志输出，前端提交成功后清理输入。
- 真实 Provider 校验依赖外部网络，失败时只报告校验失败，不写入半成品账号。
