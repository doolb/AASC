# PMX 加载进度条适配显示端旋转

## 任务描述

PMX 模型加载时显示的进度条需要适配显示端 0°、90°、180°、270°旋转。四种方向下进度条均须完整可见、不越出屏幕，阶段文字方向遵循现有显示端旋转规则。保留现有加载百分比、失败隐藏和完成后自动隐藏行为。

## Design 需求

- 复用显示端现有旋转角和 DisplayStage 逻辑画布，不增加独立旋转配置或消息。
- 进度条放入独立舞台层，与 MMD Canvas 使用相同的逻辑宽高及整体旋转；角色显隐开关不影响进度提示。
- 进度条锚定旋转后逻辑画布的底边中心，宽度受逻辑画布和安全区约束。
- 阶段文字、轨道和填充随舞台层一起旋转，进度回调继续更新原有 ARIA 百分比和状态。

## Spec 设计

```text
DisplayStage.initialize:
  loadingLayer = displayMmdLoadingLayer

DisplayStage.resize:
  geometry = getRotationGeometry(viewportWidth, viewportHeight, rotation)
  对 mmdLayer、loadingLayer、chatLayer、interactionLayer、arCalibration:
    width/height = geometry.logicalWidth/logicalHeight
    transform = translate(-50%, -50%) rotate(geometry.rotation)

onLoadProgress(progress):
  error -> progress.hidden = true; loadingLayer.ariaHidden = true
  otherwise -> clamp百分比; 显示 progress; 更新aria-valuenow、阶段文字和填充宽度
  percent == 100 -> 1500ms后隐藏并将loadingLayer设为aria-hidden

loading progress layout:
  width = min(440px, logicalWidth - 28px)
  left = 50%; bottom = logical安全区下边距 + 48px
```

## 自测用例

- Chromium 使用 1280×720 与 360×800 视口，分别设置 0°、90°、180°、270°。
- 检查进度条内容整体旋转角、非零包围盒、四边均在视口内。
- 检查 `aria-valuenow`、加载显隐与填充百分比保留。
- 运行已有显示端舞台旋转、聊天/MMD 分层及播报文本旋转回归。

## 兼容性测试

- 确认默认 0°及 180°显示行为、原有加载进度回调和完成隐藏时序不变。
- 确认 90°/270°逻辑宽高交换、安全区映射和 MMD Canvas 旋转不受影响。
- Android Offline WebView 未现场验收；通过浏览器验证后保留设备旋转验收待办。

## 性能测试

- 旋转仅复用 DisplayStage 既有一次布局更新，不增加逐帧任务或轮询。
- 通过四方向页面布局回归检查，无额外绘制层循环或加载请求。

## 风险评估

- 进度条若继续留在未旋转的物理视口层，会出现文字方向与 MMD 画面不一致；因此必须加入共用旋转层。
- 旋转后的安全区若误用物理边，会造成刘海/手势区遮挡；布局继续读取现有安全区映射变量。
- 真实 Android WebView 的安全区和缩放表现需设备验收；代码包未发布前不声称 Offline APK 已更新。
