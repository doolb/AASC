# 任务：唤醒后群聊与 Chat2API 查找工具修复

## 任务描述

修复显示端纯唤醒后普通群聊消息被指令模式过滤的问题，并处理 Chat2API `find` 工具调用依赖 Pi 原生 `fd`、首次执行下载失败的问题。

## Design 需求

- 纯“你好，小爱”只切换到群聊，不创建聊天消息。
- 进入 `activeGroup` 或 `activePrivate` 后，普通文本继续复用正常聊天路径；内置命令仍然优先。
- 显示端顶部状态显示监听状态和当前会话范围，私聊显示目标助手名。
- Chat2API `find` 转换为项目内置 `aasc_find`，使用 Node 文件系统遍历，不依赖外部下载。
- 保持只读权限，不新增 bash/edit/write 工具。

## Spec 设计

- 显示端调用 `processVoiceCommand` 时传递 `conversationActive`，仅 activeGroup/activePrivate 绕过普通文本的 commandMode 过滤。
- 显示端保存 voiceConversation 的 `state/target`，更新状态文案为群聊或私聊目标。
- `find` 别名在 Chat2API Provider 转换边界映射为 `aasc_find`；readonly Pi 启动参数不再启用原生 `find`。

## 自测用例

- 纯唤醒文本只切换 `activeGroup`，不产生 `chatInput`。
- 唤醒后普通群聊文本即使 commandMode 开启也产生 `chatInput`。
- 内置天气/报时等命令仍优先执行。
- 私聊状态显示目标助手名，群聊显示群聊。
- Chat2API `find` 转换为 `aasc_find` 并能够查找 `package.json`，不调用 `fd` 下载。
- Chat2API 旧式 `<|parameter=...>` 和命名参数 CDATA 格式均可转换。

## 兼容性测试

- 保持控制端普通聊天、Pi 历史 `User:`/`Assistant:` 标记、工具权限和旧显示端分支不变。
- 保持 Chat2API `read`、`grep`、`ls` 和网络工具转换行为。

## 性能测试

- 文件查找限制最大结果数和遍历目录，跳过 `node_modules`、`.git`。
- 唤醒后普通聊天不增加额外模型请求，只改变现有语音路由门控。

## 风险评估

- activeGroup 放行普通文本后，误识别的 ASR 可能进入聊天；仍由唤醒状态、ASR 短文本过滤和三分钟会话超时限制。
- 自定义文件遍历与 Pi 原生 `find` 的 glob 细节可能存在差异；优先覆盖常用 basename、路径和 `**` 模式。
