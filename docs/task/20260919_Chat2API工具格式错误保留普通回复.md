# Chat2API 工具格式错误保留普通回复

## 任务描述

修复 Pi Agent 收到上游非法 Chat2API 工具调用时聊天内容变为空的问题。模型可能已经生成了普通回复，随后输出不完整的工具 JSON 或残留协议结束标签；当前转换器报错后直接生成 provider error，导致控制端收到 `success=false` 且 `messageLength=0`。

目标是在不执行非法工具、不暴露协议内容的前提下，保留错误位置之前的安全普通文本返回聊天和 TTS。

## Design 需求

- Chat2API 工具格式错误仍禁止执行工具调用。
- Provider 层从第一个协议异常位置之前提取普通文本。
- 末尾的半截 JSON 工具数组、`invoke`/`tool_calls` 残留标签不进入聊天或 TTS。
- 有安全普通文本时按普通助手回复结束，不伪造工具成功；无安全文本时保持原有失败回报。
- 工具调用解析器继续保持严格校验，容错只放在 Provider 展示回退层。

## Spec 设计

- 新增 `getSafeChat2ApiFallbackText(text)` 伪代码规则。
- `createChat2ApiCompatibleStream()` 捕获转换错误后先尝试安全文本回退。
- 回退消息只包含普通 `text` 内容块，`stopReason=stop`，不保留原始 `toolCall` 内容块。
- 回退路径记录错误摘要，保留原始错误诊断能力。

## 受影响的功能模块和代码

- `src/apps/server/modules/chat/pi-chat2api-tool-converter.js`：提供安全普通文本提取函数。
- `src/apps/server/modules/chat/pi-readonly-tools.mjs`：工具转换失败时回退普通回复。
- `src/apps/server/modules/chat/pi-chat2api-tool-converter.test.js`：覆盖缺少开始标签、残留结束标签和半截 JSON。
- `src/apps/server/modules/chat/pi-readonly-tools.test.js`：覆盖 Provider 源码契约。

## 自测用例

1. 完整合法 Chat2API 工具调用继续生成 `toolCall`。
2. 普通文本加合法协议标签前缀时，格式错误回退只保留普通文本。
3. 缺少 `tool_calls` 开始标签但存在 JSON 工具数组和结束标签时，回退只保留数组前的普通文本。
4. 回退文本不包含 `tool_calls`、`invoke`、JSON 工具数组或其他协议残留。
5. 回退路径不执行任何工具调用。
6. 没有普通文本的格式错误仍返回 provider error。

## 兼容性测试

- 合法旧式 `<|parameter=...>` 和 canonical CDATA 工具调用保持原行为。
- 普通 LLM、Codex Agent 和非 Chat2API Provider 不受影响。
- 只读工具白名单仍由服务端模板权限决定，回退不会扩大权限。

## 性能测试

- 仅在工具协议解析抛错时扫描一次响应字符串。
- 正常文本和合法工具调用不增加额外解析流程。

## 风险评估

- 回退文本可能包含模型尚未完成的承诺语句，但不会伪造工具执行成功；日志仍保留协议错误，便于上游模板修复。
- 任何不确定的工具 JSON 都不执行，安全性优先于自动恢复搜索。
- 没有安全前缀时保留原有失败行为，避免空内容被误当作成功。

## 预计工时

- 约 45 分钟，包括转换器、Provider、单元测试、契约测试和文档同步。
