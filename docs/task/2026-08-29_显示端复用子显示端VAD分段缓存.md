# 显示端复用子显示端 VAD 分段缓存

## 任务描述

浏览器显示端持续监听时复用子显示端已有的 VAD 分段策略，去除语音段前的大段静音，减少无效 ASR 音频，同时保留连续监听的单条音频资源链路。

## design 需求

- VAD 阈值触发前不写入当前 ASR 语音段。
- 保留约 300ms 前置循环缓冲，避免检测延迟导致首字被截断。
- 保留判定语音结束所需的尾部静音。
- 控制端聊天和声纹注册等非分段录音继续使用完整 PCM 缓冲。

## spec 设计

- 共享 `PcmAudioCapture` 增加可选分段模式和前置缓冲。
- 显示端以分段模式启动采集器，VAD 首次越过阈值时调用 `beginSegment()`。
- `takeRawPcmWav()` 只在已有语音段时返回 WAV；分段完成后清空当前段但不关闭 AudioContext。

## 自测用例

1. 分段模式在 VAD 触发前的长静音不进入 WAV。
2. 语音开始前最多保留约 300ms 前置 PCM。
3. 语音段结束后的判停尾静音仍保留在 WAV 中。
4. 普通控制端录音不受分段模式影响。
5. 显示端持续监听仍只复用一个 PCM/VAD 音频上下文。

## 兼容性测试

## 性能测试

- 持续监听期间前置缓冲限制在约 300ms，不随等待时间增长。
- 每次提交后当前语音段清空，不累计历史静音或语音。

## 风险评估

- 前置缓冲过短可能截断首字，使用 300ms 作为兼顾响应和有效音频长度的默认值。
- VAD 阈值过低会把底噪作为语音开始，继续依赖控制端底噪检测和阈值配置。

## 实际完成

- 共享 `PcmAudioCapture` 增加可选分段模式，持续维护不超过约 300ms 的前置循环缓冲。
- 显示端 VAD 首次越过阈值时转入语音段缓存，ASR WAV 不再包含等待期间累积的大段前置静音。
- 分段完成后仍只清空 PCM 段，不重建 AudioContext、麦克风流或 VAD 分析器。
- 控制端聊天、声纹注册等默认录音入口保持完整 PCM 缓存行为。
