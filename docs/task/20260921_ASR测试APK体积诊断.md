# 2026-09-21 ASR 测试 APK 体积诊断

## 任务描述

确认测试 APK 在只保留 base FP32 声纹模型后仍接近 500 MB 的原因，区分模型资源体积与 APK 打包异常。

## design 需求

- 统计 APK 中模型、原生库、DEX 和资源的大小。
- 检查 ZIP 中央目录、条目偏移和异常填充。
- 仅记录诊断结论，本任务不直接修改构建流程。

## spec 设计

- 读取 ZIP 条目的未压缩大小和压缩大小。
- 汇总主要模型和 `.so` 文件。
- 使用 `zipinfo` 检查资源表前的空白区。

## 受影响的功能模块和代码

- `3rd/tts-server/android-asr/app/build.gradle.kts` 的模型资源打包结果。
- `docs/design/android-voiceprint-test-apk.md`。
- `docs/spec/android-voiceprint-test-apk.md`。

## 自测用例

- 检查 APK 文件大小和 SHA-256。
- 使用 `unzip -l`、`zipinfo -l` 和 `zipinfo -v` 检查 APK 内容。
- 核对 APK 可正常安装，既有模型和录音测试不受影响。

## 诊断结果

- APK 文件大小为 `503,520,540 bytes`。
- 有效 ZIP 条目压缩内容约 `280,336,497 bytes`。
- 主要体积来自 SenseVoice ASR、流式 ASR、base FP32 声纹模型和 ONNX/Sherpa 原生库。
- 资源表前存在约 `223 MB` 的全零填充区，属于独立的 APK 打包布局膨胀问题。
- 后续修复需要重新验证 APK 签名、安装和真机录音，不在本次诊断中直接改动构建流程。

## 执行结果

- 重新执行 `npm --prefix 3rd/tts-server run build:android-asr` 后，旧构建产物的全零填充区消失。
- 新 APK 大小 `280663752 bytes`，SHA-256 `76a7c9aa0c09eaf2a4266e7cab88761e89ed44f2b4efb3649a962fb78f26c47c`。
- ZIP 完整性、真机安装和 LAN/WAN HTTP `200` / `Content-Length` 校验通过；本诊断任务完成。

## 风险评估

- 删除模型资源会导致对应 ASR、流式识别或声纹功能不可用。
- 直接重排或重签 APK 可能影响 Android 安装和资源完整性，必须通过构建工具重新生成。
