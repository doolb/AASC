# 任务：统一 Codex 代理配置

## 任务描述

让普通聊天 Codex 和工作 Agent Codex 统一读取 `chat.codexProxy`，避免普通聊天与工作 Agent 的代理配置来源不一致。

## Design 需求

- 配置项统一为 `chat.codexProxy`。
- 普通聊天、工作 Agent、搜索临时 Agent 创建 Codex bridge 时传递该代理。
- 已运行的 Codex bridge 不动态切换，配置修改后新建或重启进程生效。
- 群聊/私聊 threadId 继续按会话隔离，不因代理统一而共享上下文。

## Spec 设计

- `AiRolesService` 创建工作 Agent bridge 时注入 `getCodexProxy()`。
- `AgentBackendClient`/`agent-backend-host` 透传 `options.proxy` 到 `CodexBridge`。
- `CodexRuntimeManager` 继续由服务器使用 `chat.codexProxy` 初始化。
- `CodexBridge` 保留默认代理作为旧调用兼容，但生产服务器统一显式传入配置值。

## 受影响的功能模块和代码

- `src/apps/server/modules/ai-roles/ai-roles-service.js`
- `src/apps/server/modules/ai-roles/codex-bridge.js`
- `src/apps/server/boot/server-app.js`
- 相关 Agent bridge 测试和文档。

## 自测用例

- 工作 Agent 创建 Codex bridge 时收到 `chat.codexProxy`。
- 普通聊天 Codex 继续收到同一代理。
- Codex bridge 的 `HTTPS_PROXY` 与传入代理一致。
- 群聊/私聊 session key 和 thread 隔离测试保持通过。

## 兼容性测试

- Claude 工作 Agent 不受代理配置影响。
- 直接构造 CodexBridge 未传代理时仍使用默认 `http://127.0.0.1:7899`。
- Pi Agent、普通 LLM 和 TTS 路径不改变。

## 性能测试

- 不增加 Codex 请求次数，只增加创建 bridge 时一次配置传递。

## 风险评估

- 代理配置错误会同时影响普通聊天和工作 Agent 的新 Codex 进程。
- 已运行进程保留旧代理，避免运行中切换造成请求中断。
