# Node 子显示端语音唤醒与群聊路由

## 任务描述

`voice-display-node-arch0` 的语音输入在服务器仍显示 `waitingWake` 时也被接受，并落入群聊。使 Node 子显示端与网页显示端共用服务端唤醒状态机；Go/C# 子显示端暂时保留原语音命令兼容路径。

## design 需求

- Node 子显示端等待唤醒时拦截普通语音；既有免唤醒内置命令继续可用。
- 纯助手名、私聊唤醒词及群聊进入词只改变会话状态，不作为聊天文本发送。
- 活跃群聊/私聊、临时窗口、退出和超时使用与网页显示端相同的服务端状态逻辑。
- 新版 Node 握手显式声明 `clientType=node`；继续兼容 ID 以 `voice-display-node-` 开头的已部署客户端。
- 不修改 Go/C# 客户端代码和连接协议；未标记为 Node 的子显示连接保留原兼容分支。
- Node 子显示端重连采用网页显示端的固定 3 秒间隔和持续重试；`error`/`close` 共用清理入口，首次连接暂时失败不退出进程。
- 断线释放麦克风，重连后以服务端确认的 `displayId` 和权威录音能力恢复；正常停止时取消重连。
- 重连继续使用进程启动时生成的稳定本地 `displayId`；服务器确认 ID 单独保存，不能因重连被覆盖或变化。

## spec 设计

```text
Node 建立 /display WebSocket:
    查询参数包含 subDisplay=true、clientType=node、displayId
    旧客户端若 displayId 以 voice-display-node- 开头，也标记为 Node 子显示端

handleDisplayConversationInput(displayId, text):
    如果目标是子显示端且不是 Node:
        沿用旧路径，直接接受输入
    否则:
        使用 display-voice-conversation reducer
        按 displayId 更新状态、提示和会话计时器
        纯唤醒事件只切换状态；input 事件才交给 voiceCommand

Node 收到 voiceConversationState:
    保存服务端状态并记录状态变化

Node WebSocket 断线或连接失败:
    只清理当前 socket，停止麦克风、清除能力确认和旧 displayId
    error 时关闭异常 socket
    通过唯一的 3 秒定时器无限重试；首次连接失败不退出进程
    进程停止时取消重连

Node WebSocket 重连成功:
    等待服务端确认本次 displayId
    重新声明能力并等待 capabilitiesUpdated
    仅按服务端权威 voiceRecording 值恢复麦克风
    后续重连仍使用相同 clientDisplayId
```

对应实现伪代码：`docs/spec/display-voice-conversation.md`。

## 自测用例

1. Node 处于 `waitingWake` 时，普通语音不进入群聊；免唤醒内置命令仍执行。
2. 纯助手名或“你好+助手名”只改变状态并播报，不创建聊天输入。
3. 助手名加内容按现有 temporary/oneShot 配置进入群聊；活跃群聊/私聊使用当前会话路由。
4. 退出和超时后恢复等待唤醒，普通文本再次被拦截。
5. 新版握手 `clientType=node` 和旧版 `voice-display-node-` ID 都进入 Node 状态机路径。
6. Go/C# 未声明 Node 类型时仍走原兼容路径。
7. 服务端不可达时启动 Node，确认进程保持运行并每 3 秒重试；服务恢复后无需手工重启即可连接。
8. 断开后重连，确认 WebSocket URL 中的 `displayId` 不变，服务端显示列表仍是同一个 Node 子显示端。
9. 重连时 `error`/`close` 只安排一个连接尝试，麦克风先释放；服务端返回权威能力后，关闭状态不恢复录音、开启状态仅启动一个采集流。

## 兼容性测试

- 普通网页显示端和 Android 显示端仍使用原 reducer 流程。
- Go/C# 客户端代码和连接协议不变；未标记 Node 的子显示连接保持原有服务端分支。
- Node ASR、声纹过滤、免唤醒命令、TTS 播报和录音能力开关保持原入口。
- 网页显示端仍使用原有 3 秒单飞重连逻辑；Go/C# 客户端代码和协议不变。
- 群聊/私聊聊天会话仍复用项目当前的服务端聊天会话规则，本次不改为按设备隔离。

## 性能测试

- 使用已有内存中的会话 reducer 和每显示端计时器，不新增轮询、ASR 请求或外部调用。
- 新增的握手参数只在连接时读取；Node 仅在状态变化时写一条 TUI 日志。

## 风险评估

- 使用自定义且不带 `voice-display-node-` 前缀的旧 Node ID 时，需要更新 Node 客户端以发送 `clientType=node`。
- Node 客户端本地只展示收到的会话状态，状态迁移和语音放行由服务端负责。
- 自动化测试未运行；目标 Node 的麦克风/真实语音与 TTS 回声场景仍待现场验收。
