# 任务：正式显示端完整离线 APK

## 任务描述

新增正式 Android 显示端完整离线 APK 构建命令，内置当前正式运行所需的 Node.js Runtime、服务器代码、生产依赖和模型；离线 APK 默认连接本机，并提供最上层“控制端”按钮弹出/隐藏控制页面。离线 APK 使用独立文件名和 Android 包名，普通 APK 保持兼容。

## Design 需求

- 设计文档：`docs/design/android-display-offline-apk.md`
- 新 APK：`aasc-display-offline.apk` / `com.aasc.display.offline`
- 模型范围：SenseVoice、streaming Zipformer、正式声纹 base FP32 + pyannote、GTCRN、嵌入式 TTS、RapidOCR、YOLO11n。
- 默认本机地址：`https://127.0.0.1:8081`
- 离线 Node 使用 `main` 角色，不连接远端主服务器。
- 控制页面以同源 WebView 覆盖显示页，按钮保持最上层。

## Spec 设计

- 实现规格：`docs/spec/android-display-offline-apk.md`
- Runtime manifest 增加模型文件和离线模式元数据。
- Gradle 通过 `-PaascOffline=true` 切换独立包名、名称和版本后缀。
- MainActivity、ServerConfig、NodeServerService、NodeServerConfig 增加离线模式分支。

## 自测用例

1. 构建脚本能发现并复制全部离线白名单模型。
2. 缺少模型时命令失败且不输出成功 APK。
3. 普通 APK 的 role、地址和包名不变。
4. 离线 APK 默认加载本机 `/display`，并启动本地 `main` Node。
5. 控制按钮能弹出和隐藏 `/control`，不销毁显示 WebView。
6. Runtime 版本复用路径能发现缺失离线模型并重新安装。

## 完成结果

- 已完成全部代码、文档和测试项。
- 离线 APK 已生成：`src/apps/android-display/app/build/outputs/apk/offline/aasc-display-offline.apk`。
- APK applicationId 为 `com.aasc.display.offline`，versionName 为 `0.1.0-offline`，包内模型 32 个，共 451,266,757 bytes。
- 现场真机安装/启动尚未在本次构建中执行；需要使用目标设备继续确认本机 Node 首次解包、HTTPS 页面、录音和控制端 WebView 交互。

## 兼容性测试

- Android API 26+、arm64-v8a。
- 普通 `npm run build:apk` 和已有 Android JVM 单测。
- 离线包安装后与普通包并存，确认 applicationId 不冲突。
- 本地 HTTPS 证书、WebSocket、麦克风权限和同源控制页。

## 性能测试

- 首次安装包含约 451 MB 模型，记录 APK 大小和首次 Runtime 解压耗时。
- 二次启动走版本复用路径，不重复校验全部模型 SHA-256。
- 控制页显示/隐藏不重建显示页 WebView 或推理状态。

## 风险评估

- APK 体积较大，构建和首次安装耗时明显增加。
- Android AssetManager/aapt 对大体积 assets 的限制需要通过实际 APK 构建确认。
- 本机 Node 监听和 WebView 加载存在启动竞态，需要有限自动重试。
- 离线模式仍不提供需要外部网络或外部 Agent 的能力；页面需保持现有能力提示。
