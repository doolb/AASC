# tts.server 内置 Wine/Linux TTS 服务

## 任务描述

创建一个 `tts.server` server service 内置任务。任务实例内部选择 Wine 或 Linux 引擎并配置 HTTP 端口；由任务系统保存、停止和自动恢复唯一实例。主服务器继续通过通用 TTS URL 调用，本阶段不启用服务器 TTS 回退。

## design 需求

- 只有一个 `tts.server` 内置任务，不拆分 `tts.wine` 和 `tts.linux`。
- `engine` 支持 `wine`、`linux`，默认 `wine`；`port` 保存于实例参数，默认 `3001`。
- 服务绑定 `127.0.0.1`，使用兼容现有客户端的 `/api/tts`、`/api/voices` 和 `/api/tts/status`。
- Wine 直接在 Linux 主机运行 worker，不使用 libvirt Win7；Linux 保留为可选引擎。
- 服务启动成功后动态更新主服务器通用 `serviceUrl`；不直接改变 `tts.serverEnabled`。
- 自动恢复依赖任务索引中唯一的 `running` 实例，重复 server service scope 不并存。

## spec 设计

```text
注册 tts.server:
    target = server
    mode = service
    params = engine(wine|linux), port(1024..65535)

启动实例:
    读取并校验实例参数
    按 engine 选择 tts-wine.js 或 tts-linux.js
    生成本机运行时环境变量
    启动 Node 子进程
    等待 /api/tts/status 返回 200
    更新主服务器通用 serviceUrl
    返回带 stop() 的 service controller

停止实例:
    SIGTERM 子进程
    超时后 SIGKILL
    恢复之前的 serviceUrl
    更新 widget 为已停止
```

## 自测用例

1. `tts.server` 注册为 `server/service` 内置任务，参数包含 `engine` 和 `port`。
2. 默认参数为 `wine` 与 `3001`，非法引擎和非法端口被拒绝。
3. Wine 启动命令使用 `tts-wine.js`、本机 Wine prefix、worker 目录和 `PORT`。
4. Linux 启动命令使用 `tts-linux.js`、Linux binary、共享模型目录、SDK 目录和 `PORT`。
5. HTTP 服务返回 `/api/tts/status` 成功后，通用 TTS URL 更新为 `127.0.0.1:<port>`。
6. 健康检查超时会终止子进程并抛出可诊断错误。
7. `stop()` 可正常终止子进程并恢复原通用 URL。
8. 子进程异常退出不会触发无限重启，widget 能显示失败状态。
9. 任务索引只有一个 `tts.server` running 实例，服务器重启后任务系统可以按原 instanceId 和参数恢复。
10. `tts.serverEnabled` 仍为 `false`，显示端 TTS 失败时不触发服务器回退。

## 兼容性测试

- Wine 引擎在没有 libvirt Win7 的 Linux 主机上启动 HTTP 服务并返回 `/api/tts/status`。
- 主服务器继续使用通用 HTTP TTS 客户端，不引用 Wine worker 内部函数。
- 修改实例端口后，服务和主服务器 URL 使用同一个端口。
- 旧的显示端优先 TTS 路由、服务器 TTS 开关和已有任务服务恢复逻辑不改变。

## 性能测试

- 服务启动健康检查不超过 30 秒，轮询间隔固定且不会创建无界定时器。
- Wine worker 并发、队列和请求回收继续由 `tts-wine.js` 管理。
- 任务停止后不残留 Node、Wine 或 worker 子进程。

## 风险评估

- 端口占用会使实例启动失败，但不阻塞主服务器启动。
- Wine 运行时或模型缺失会使服务任务失败；任务日志保留具体引擎和路径。
- Linux Embedded SDK 可能受 AVX 等 CPU 指令集限制，本阶段仅作为可选引擎，默认不启用。
- `serverEnabled=false` 时即使 Wine 服务健康，也不会改变当前显示端失败后的 TTS 行为。

## 预计工时

约 3-5 小时，包含任务生命周期、真实 Wine 服务验证、实例持久化和文档同步。

- 已新增 `tts.server` server service 内置任务，支持 Wine/Linux 引擎选择和实例端口配置。
- 已创建唯一持久化实例 `tts-wine`，参数为 `engine=wine`、`port=3001`、状态为 `running`；任务系统重启恢复正常。
- 主服务器保持通用 HTTP TTS 客户端，服务实例启动后动态指向 `http://127.0.0.1:3001/api/tts`。
