# External 层第二步迁移任务

## 任务描述

- 目标：将 ASR/TTS/LLM 实现体从 `core/*` 迁入 `src/external/*`。
- 范围：迁移实现体、保留 `core/*` 兼容转发、验证入口可用。

## design 需求

- External 承接外部服务实现体。
- Core 保留兼容层以平滑过渡。

## spec 设计

- 增加 External 第二阶段迁移伪代码。
- 明确 `core/* -> src/external/*` 的导出转发关系。

## 受影响模块与文件

- `src/external/asr/asr-service.js`
- `src/external/tts/tts-service.js`
- `src/external/llm/llm-service.js`
- `core/asr.js`
- `core/tts.js`
- `core/chat.js`
- `src/external/README.md`
- `docs/design/layered-architecture.md`
- `docs/spec/layered-architecture.md`
- `docs/task/2026-04-23_External层第二步迁移.md`
- `changelog.md`
- `docs/todo.md`

## 自测用例

1. 执行 `node --check src/external/asr/asr-service.js` 通过。
2. 执行 `node --check src/external/tts/tts-service.js` 通过。
3. 执行 `node --check src/external/llm/llm-service.js` 通过。
4. 执行 `node -e "require('./core/asr'); require('./core/tts'); require('./core/chat');"` 通过。

## 兼容性测试

1. `server.js` 入口依赖不变（继续使用 `src/external/*`）。
2. 旧代码路径 `core/*` 仍可被引用。

## 性能测试

1. 本次为代码位置迁移，不涉及算法调整，性能影响可忽略。

## 风险评估

- 风险：迁移后相对路径错误导致配置或资源读取失败。
- 缓解：修正路径并执行语法与模块加载自测。
