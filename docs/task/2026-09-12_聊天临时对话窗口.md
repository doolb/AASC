# 聊天临时对话窗口

## 任务描述

为显示端语音聊天增加临时对话模式，调整群聊和私聊关键词，并增加临时窗口、持续对话窗口两个可配置时间。TTS 播放期间暂停窗口计时，播放完成后恢复完整窗口时间，且不受非打断录音策略影响。

## Design 需求

- 任意已配置 AI 角色名进入临时群聊窗口；角色名沿用现有自动匹配列表，不设默认角色名。
- `开始对话` / `结束对话` 控制群聊窗口。
- `你好<角色名>`、`<角色名>你好`进入对应角色私聊；`<角色名>再见`、`再见<角色名>`退出对应私聊。
- 关键词中间允许存在空白、Unicode 标点或符号。
- 增加临时窗口和持续窗口两个全局秒数设置，默认 30 秒和 180 秒。
- TTS 播放期间冻结窗口倒计时，实际播放全部结束后重新按当前窗口类型计时。
- 角色名加额外内容默认进入临时模式，并提供“临时模式/一次性群聊”切换。
- 临时模式只维护一个全局会话；新临时会话替换旧会话，控制端增加临时页签显示当前/最近内容，并支持直接发送到当前临时会话。

## Spec 设计

- 会话状态增加 `windowType`、`timerPaused` 和 `remainingMs` 语义。
- 服务端根据窗口类型选择到期时长，并作为到期时间唯一来源。
- 复用 `voiceTtsPlaybackState` 和 `voiceConversationTtsFinished` 生命周期暂停/恢复会话计时。
- 配置通过已有控制端 WebSocket 消息校验、持久化和广播，不新增 HTTP 配置接口。
- 临时会话使用独立会话键和服务端快照，不污染普通群聊历史。
- 控制端临时页签发送时携带临时会话标识；服务端以当前全局实例为准，避免旧控制端状态写入普通群聊或创建分叉。

## 自测用例

1. 任意已配置角色名进入临时群聊，默认 30 秒到期。
2. `开始对话`、`结束对话`正确控制群聊。
3. 任意角色名的 `你好<角色名>`、`<角色名>你好`、`<角色名>再见`、`再见<角色名>`正确控制私聊。
4. TTS 播放期间剩余秒数保持不变，播放完成后恢复完整窗口。
5. 修改两个窗口设置后，控制端显示服务端规范化值，重连后仍保持。
6. 旧显示端收到不带新字段的状态时仍可正常显示和监听。
7. 角色名加内容在默认临时模式下进入 activeGroup；切换一次性群聊后保持 waitingWake。
8. 新显示端开启临时模式后，旧显示端临时状态被替换；多个控制端临时页签内容一致。
9. 控制端临时页签可直接发送消息；服务端将用户消息和助手回复写入同一全局快照，刷新/重连后仍可显示当前实例内容。

## 兼容性测试

- waitingWake、activeGroup、activePrivate、disabled 状态切换。
- TTS 播放暂停录音与非打断录音两种配置。
- 多句 TTS、播放失败、播放超时和显示端断开。
- Web 显示端、Android WebView 和旧子显示端。

## 性能测试

- 每个显示端最多一个会话计时器和一个倒计时 interval。
- 多句 TTS 不重复创建永久 timer，不因重复状态广播累积监听器。

## 风险评估

- TTS 跨显示端播放时需绑定语音会话来源，避免暂停错误显示端的窗口。
- 旧客户端不理解暂停字段时仍可能继续显示旧倒计时，但服务端到期逻辑保持正确。
- 配置输入必须限制最小/最大值，避免超长 timer 或过短窗口造成误触发。
