## 需求分析与设计

采用 analyze-requirement-level 的 enterprise 模式。用户描述“镜头拉远时，far值没有更新”，输入为既有镜头缩放操作，期望为远裁面同步容纳模型。源码证据：普通取景只在 fitCameraToModel 设置 far；普通缩放只通过 applyCameraView 移动位置；AR 缩放不改投影且定位更新覆盖 far。需求明确，属于相机模块契约 L6，建议下放到 L4 的数据流实现；证据权重为三条强证据，单层一致，置信度 1.00。评审可开发，直接开发风险低；评分为层级清晰度25/25、证据充分度20/20、实现完备度18/20、风险暴露度18/20、L4可落地性15/15，总分96/100。

设计见 docs/design/mmd-ar-test-apk.md；L4 草案见 docs/spec/mmd-ar-test-apk.md。核心为距离/模型边界 → far → 投影深度系数 → 逆投影；AR 构图参数保持。无需增加远端配置或生产依赖。

## 自测与兼容性

1. 普通预览拉远至缩放下限，far 足够容纳模型，深度投影与 far 一致。
2. 拉近和复位恢复合理裁剪，near=1，模型位置/缩放不因修复改变。
3. AR 首锁、连续定位、缓动及失锁缩放保持足够范围；新定位不会覆盖修正。
4. AR 偏心投影的横纵构图系数保持，投影和逆投影乘积为单位矩阵。
5. 相机 VMD 播放、AR 接管和停止恢复保持现有行为。
6. 使用现有 npm 脚本重建独立网页，执行适合本次改动的定向测试。
