# 服务器 TTS 按调用方检查显示端睡眠

## 任务描述

调整 TTS 与显示端睡眠模式的边界：普通聊天、Agent、手动 TTS、提醒和语音指令不受睡眠影响；只有整点报时在服务器向目标显示端下发前按 `checkSleep` 选项检查目标显示端是否处于睡眠/深度睡眠。

## design 需求

- 服务器 TTS 显示端发送接口增加可选 `checkSleep` 参数，默认不检查。
- `checkSleep=true` 时按目标显示端当前 `sleepState` 独立过滤。
- `time.announce` 使用 `checkSleep=true`；其他 TTS 使用默认 `false`。
- `tts.generateTTS()` 保持纯音频生成，不读取显示端状态。
- 显示端不再因睡眠状态暂停或清空通用 TTS 队列。

## spec 设计

- 扩展服务器 `sendToDisplay(displayId, message, options)`。
- 扩展任务引擎 `broadcastToDisplays(message, options)`，定时报时广播传入 `{ checkSleep: true }`。
- 兼容旧报时服务路径，使用同一发送选项。
- 删除显示端 `applySleepState()` 对 TTS 的暂停/恢复调用及通用 TTS 入口睡眠拦截。

## 自测用例

1. `checkSleep=true` 且目标显示端为 sleep/deep 时跳过下发。
2. `checkSleep=false` 或缺省时，即使目标显示端睡眠也正常下发。
3. 多显示端广播逐个检查，睡眠显示端跳过，正常显示端收到。
4. 睡眠期间聊天/Agent/手动/提醒 TTS 继续播放。
5. 睡眠期间整点报时不播放，唤醒后不补播已跳过的报时。

## 兼容性测试

- 普通 LLM、Agent 流式 TTS 协议保持不变。
- 控制端播放不经过显示端睡眠检查。
- 显示端视频和 HTML 睡眠暂停逻辑保持不变。
- 未传 `checkSleep` 的旧调用保持原有下发行为。

## 性能测试

- 睡眠判断仅为每次显示端发送时的一次内存状态读取，不增加 TTS 服务请求。
- 多显示端广播每个目标最多一次状态判断。

## 风险评估

- 显示端状态尚未上报时，`checkSleep=true` 按非睡眠处理，避免误丢报时。
- 服务器重启后运行时 `sleepState` 需要等待显示端重新上报；期间按非睡眠处理。
