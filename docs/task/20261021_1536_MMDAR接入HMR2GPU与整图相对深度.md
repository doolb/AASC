# MMD-AR 接入 HMR2 GPU 与整图相对深度

日期：2026-10-21 15:36。状态：用户已选择“完整接入（推荐）”，实现与本机定向/浏览器验收完成；真实HMR GPU跨域联网及手机性能待用户服务/实机验证。

## 任务描述与需求

将用户现成的[hmr2_gpu_service.py](<E:/ai/ai-depthmap/hmr2_gpu_service.py>)接入独立 MMD-AR 全身 IK 的图片骨骼计算，同时接入“Depth Anything V2 Small · 整图相对深度”。既有 MediaPipe 默认、本地图片/粘贴、实际骨架叠加和相机匹配/恢复保持可用。不重新做 HMR 服务或网页 GB 级 HMR ONNX 移植。

需求与设计见[Human design](../design/mmd-human-interface.md)，候选实现伪代码见[Human spec](../spec/mmd-human-interface.md)。

## 实施前核对事实与接口

- 当前[图片 UI](../../3rd/mmd-ar-test/web-human-pose-ui.mjs)只调[本地客户端](../../3rd/mmd-ar-test/web-human-pose-client.mjs)，默认 MediaPipe 33 点。
- [重定向](../../3rd/mmd-ar-test/web-human-pose-retarget.mjs)、[二维 FK 拟合](../../3rd/mmd-ar-test/web-human-pose-lift.mjs)和[相机拟合](../../3rd/mmd-ar-test/web-human-pose-camera.mjs)依赖现有 MediaPipe 编号空间，不能只换 fetch 接口。
- HMR 实际 `GET /health`、`POST /infer`。JSON 只允许 `image_base64` 和可省略的 `bbox_xyxy`，不是此前候选 `/v1/hmr2/predict`。返回 `hmr2.result/schemaVersion=1`、原生 BODY25 的 `xyz/xy/names/edges`、`rotations24/betas10`、相机/图尺寸/框和耗时；没有关节置信度或 health 版本/limits 字段。
- 框为同一已定向上传图像的像素 xyxy，不是 xywh；省略框使用整图而非检测人物。上传前以同一像素准备 PNG，可避免 EXIF 原图与画布坐标不一致。
- HMR 相机点为 `xyz+cameraTranslation`，投影 X 图右、Y 图下、Z 前方；原生 XYZ 是米制 SMPL 点而非 PMX 局部骨，不能直接复制原 24 旋转到 PMX。
- [自选图深度原型](../../tmp/mmd-pose/depth-eval/hmr2-sam3d/custom-depth.mjs)已有真实浏览器 ORT/WASM 推理，[报告调用](../../tmp/mmd-pose/depth-eval/hmr2-sam3d/report.mjs)把 HMR 与深度分开执行和报错。该原型只返回热图，正式接入需保留浮点值及释放会话。
- [深度取样试验](../../tmp/mmd-pose/depth-eval/rigid-projection/depth-inference.mjs)使用 RGB/ImageNet/NCHW、minimal 尺寸、14 倍数、[1,H,W] 输出，热图按单图 P5/P95、数值大黄/近，小蓝/远。既有 5×5 局部中位数弱排序未有稳定姿态收益，不把颜色/浮点值当米制关节 z。
- 固定模型路线为 Depth Anything V2 Small 量化 ONNX（27,258,801 字节）；资源版本/大小/SHA/配置/许可在接入构建时再次核验。正式模块不得依赖 `tmp` 的根绝对 URL。

## 推荐设计

1. 两条骨骼方式：MediaPipe 本地默认，HMR2 GPU API 可选；HMR 地址输入、测试连接、会话内 Bearer token 和图片上传提示。只将地址保存为本浏览器偏好，不新增 HTTP 配置读写接口。
2. HMR 客户端单飞、AbortController、结构化错误与响应校验；原生数据保存，专用语义适配层把身体关节映射给预览、重定向/FK、相机，不伪造 MediaPipe 33 点或置信度。
3. HMR 原生 3D 方向/身体框架按当前 PMX 固定骨长和共享限位映射，通过既有物理统一提交；不改变用户 PMX 体型，不直接写 SMPL quaternion。
4. 整图深度使用独立按需 Worker/客户端/预后处理及资产清单，针对当前图实际计算，提供来源/耗时/黄近蓝远说明与浮点图数据。失败独立提示，不让深度失败删除有效 HMR 骨架。
5. 另设默认关闭的“相对深度辅助（实验）”：仅弱顺序约束，严格拒绝出画、局部不稳定、小差异及几何冲突；不把可见表面当内部关节真值，不自动左右纠错。关掉后与不加载深度的主路径等价。
6. 换图/方式/API/框/PMX/收起/取消使所有请求、深度及拟合代次失效；用户点击应用后才更改当前目标，失败保留原姿态。相机仍使用实际骨架、所有者/revision/token 与恢复。

## 自测用例与兼容性
