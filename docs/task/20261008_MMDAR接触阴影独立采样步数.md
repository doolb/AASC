# MMD-AR接触阴影独立采样步数与刷新显示（已实现并验证）

任务描述：新增控制接触阴影采样次数的控件。按当前实现，将次数解释为沿主光短射线的粗采样步数。
设计需求：4–64步整数滑块；默认12，旧存储缺字段沿用旧质量12/20/32初始化；即时生效、保存、刷新恢复、灯光复位。SSGI步数及射线数保持质量档控制。
伪代码设计：见`docs/spec/mmd-ar-test-apk.md`中的独立步数与刷新修复段落；设计见`docs/design/mmd-ar-test-apk.md`。

受影响模块和代码：
- `3rd/mmd-ar-test/web-screen-lighting-build.js`：接触阴影分组控件。
- `3rd/mmd-ar-test/web-screen-lighting-panel.mjs`：归一化、整数显示、旧值迁移与存储。
- `3rd/mmd-ar-test/web-screen-lighting.mjs`：独立步数uniform。
- `3rd/mmd-ar-test/web-screen-lighting-shader.mjs`：当前帧追踪接收显式步数，上限64；GI调用保留旧步数。
- `tests/mmd-ar-screen-lighting.test.js`、`tests/mmd-ar-contact-shadow-browser.test.js`：设置与实际GPU行为回归；`tests/mmd-ar-screen-lighting-refresh-browser.test.js`：真实角色加载/刷新、分类点击、步数保存及DPR 1/2回归。
- 对应design/spec/todo/changelog/README、发布状态：实施时同步。

自测用例：缺字段低/中/高迁移、空值/非数值/越界/小数、面板显示、输入保存、刷新与复位、独立接触阴影/SSGI开关组合、4/12/32/64步GPU遮挡/自遮挡/背景。
兼容性：现有WebGL2及浏览器本地存储；不新增HTTP或远端配置接口；不升级依赖。保留工作区中其他任务的改动。
性能：64步开销较32步增大；静态循环有上限，关闭接触阴影不执行相关射线；手机耗时待测。
风险评估：厚度随步数变化，须验证高步数不会引入大面积漏判/自遮挡；不覆盖已有SSGI历史实现。
预计工时：30–60分钟。用户已确认4–64范围、默认值和迁移规则，追加刷新模型不可见及分类样式要求。

需求等级分析（enterprise，自动触发）：主L6参数契约，次L4数据流；证据为新增采样控制、当前质量步数12/20/32、Shader静态32步上限。无需进一步下放，实施可直接以L4变量数据流表达。评分：层级25/25、证据18/20、完备16/20、风险18/20、可落地15/15，总计92/100；置信度0.90。结论：需确认默认值/范围及界面方案后开发。后续候选：按确认方案实施、只同步伪代码、保留方案；不自动调用翻译技能。

追加范围：`web-screen-lighting.mjs`删除离屏pass的全局setViewport污染；面板使用下方正式分类容器与现有展开事件。新增浏览器回归验证保存设置后刷新、实际模型像素、完整画布viewport和分类开合。
