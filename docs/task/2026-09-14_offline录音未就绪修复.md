# offline APK 录音未就绪修复

## 任务描述

修复 offline APK 启动后显示端语音状态为“未就绪”的问题，确保 APK 默认开启显示端录音监听，并继续使用显示端录音、服务端公共 ASR 和显示端原生 ASR 提供端配置。

## Design 需求

- 保持 `asr.serverEnabled=false`、`asr.device=display` 和 `tts.serverEnabled=false`、`tts.device=display`。
- Android Manifest 同时声明 `RECORD_AUDIO` 与 `MODIFY_AUDIO_SETTINGS`。
- `RECORD_AUDIO` 继续由 `MainActivity` 负责运行时授权；授权完成后重载 display WebView。
- `DisplayWebView` 继续只授予 WebView 音频/视频采集资源，不改变网页录音协议。
- 页面只有在 `/api/asr/status` ready、显示端录音能力有效且服务端能力允许时自动进入监听。

## Spec 设计

```text
启动 offline APK:
  加载本地 display 页面
  请求 RECORD_AUDIO 运行时权限
  Manifest 提供 MODIFY_AUDIO_SETTINGS
  WebView 授予 RESOURCE_AUDIO_CAPTURE
  页面 getUserMedia 成功 -> voiceRecording=true
  /api/asr/status ready -> voiceSupported=true
  服务端 capabilitiesUpdated.voiceRecording=true -> 自动 startVoiceRecording()
```

## 自测用例

1. 静态检查 offline APK Manifest 包含 `RECORD_AUDIO` 和 `MODIFY_AUDIO_SETTINGS`。
2. 运行 `node --test tests/android-offline-apk.test.js`。
3. 运行 Android `testDebugUnitTest`。
4. 重新构建 offline APK 并安装到 `192.168.1.6:5555` 的 display 2。
5. 检查 Chromium 日志不再出现 `No audio device will be available for recording` 或 `Unable to select audio device`。
6. 检查 UI 自动化状态从“未就绪”变为“监听中”。
7. 使用测试 WAV 或现场语音验证 ASR HTTP 200 和聊天回复链路。

## 兼容性测试

- Android 9/API 28、arm64-v8a：目标真机 `Samsung SM-N9500`。
- 在线 APK 与普通浏览器显示端不改变录音协议和服务端能力门控。
- 旧服务端配置继续通过 `asr.device=display` 路由；只修复 Android WebView 系统权限。

## 性能测试

- `MODIFY_AUDIO_SETTINGS` 为普通安装权限，不新增运行时弹窗和模型内存开销。
- 录音仍复用既有 `PcmAudioCapture`、VAD 和单条麦克风链路，不增加采样线程。

## 风险评估

- 若设备系统禁用了麦克风或用户拒绝 `RECORD_AUDIO`，页面仍安全显示“未就绪”，不影响 APK 启动。
- Manifest 权限只作用于 APK 音频采集；不改变服务器 ASR/TTS 开关及远端配置契约。

## 预计工时

约 30 分钟，包含修改、定向测试、Gradle 构建和真机回归。

- 实现：在 `AndroidManifest.xml` 增加 `MODIFY_AUDIO_SETTINGS`；新增 offline APK Manifest 权限契约测试；同步更新设计和伪代码文档。
