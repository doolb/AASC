# 群聊私聊搜索转普通聊天

## 任务描述

调整显示端 active 群聊和私聊中的搜索文本：不再进入特殊搜索处理，而是作为原始普通聊天发送给当前会话 Agent。等待唤醒状态的搜索命令保持原行为。

## Design 需求

- activeGroup 和 activePrivate 中包含“搜索”的文本直接进入当前聊天会话。
- active 会话不受 `search=llm` 路由配置影响，不创建独立搜索 session。
- 保留群聊原文和私聊的 target、sessionId、templateTarget 元数据。
- 天气、提醒、播放、静音、报时、录音及自定义指令本次不修改，记录到 `docs/todo.md`。

## Spec 设计

```text
processVoiceCommand(text, displayId, callbacks, internal=false, options):
    获取当前群聊/私聊 session
    如果 internal=false 且 conversationActive=true 且文本包含“搜索”:
        群聊返回 { type: chat, message: 原始文本, mode: group }
        私聊返回 { type: chat, message: 原始文本, mode: private, target, sessionId, templateTarget, systemPrompt }
        不调用 checkCommandRouting、handleSearchCommand 或独立搜索 session
    其他文本继续按现有系统命令和内置指令优先级处理
```

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：增加 active 搜索普通聊天分支。
- `tests/group-chat-templates.test.js`：覆盖 active 群聊和私聊搜索文本及元数据。
- `docs/design/display-voice-conversation.md`：记录 active 搜索路由和未调整指令范围。
- `docs/spec/display-voice-conversation.md`：同步伪代码。
- `docs/todo.md`：记录天气、提醒、播放、静音、报时、录音和自定义指令的后续调整。

## 自测用例

1. active 群聊开启指令模式时，“搜索北京新闻”返回普通群聊消息，保留完整文本。
2. active 私聊时，“搜索北京新闻”返回普通私聊消息，保留当前角色及会话元数据。
3. 等待唤醒状态的搜索命令仍返回原有搜索路由结果。
4. active 状态不调用特殊搜索处理，`search=llm` 配置不改变普通聊天结果。

## 兼容性测试

- 不改变等待唤醒状态的搜索命令、独立搜索 session 和已有搜索服务端处理。
- 不改变天气、提醒、播放、静音、报时、录音及自定义命令。
- 不改变普通群聊/私聊的 Agent 历史和 TTS 路由。

## 性能测试

- active 搜索文本只增加一次会话状态判断，不新增网络请求、搜索请求或 TTS 请求。

## 风险评估

- 使用现有“包含搜索”匹配规则，可能将带有该词的普通句子统一交给聊天 Agent；这是本次 active 会话规则的预期行为。
- 仅在 `conversationActive=true` 且非内部组合命令时生效，避免破坏等待唤醒和内部命令组合流程。

## 预计工时

约 30 分钟，包含路由修改、测试和文档同步。

## 执行结果

- 已完成 active 群聊/私聊搜索文本的普通聊天路由；群聊保留原文，私聊保留角色与会话元数据。
- 等待唤醒状态的搜索命令仍使用原有搜索路由；其他内置和自定义指令未修改。
- 定向测试及语法、差异检查结果见变更日志。
