# 睡眠状态测试时序与语音输入缺省声纹策略修复

## 任务描述

修复显示端睡眠模式集成测试受 10 秒周期检查影响而产生的时序失败，并明确 Windows Node 子显示端语音输入的本地声纹策略：`requireVoiceprint` 缺失、`undefined` 或 `null` 时按 `false` 处理，只有显式配置 `inherit` 才跟随服务器。

## design 需求

- 睡眠测试必须通过真实的 `sleepOverride` 控制路径或等效的手动覆盖状态保持睡眠，不能让周期性 `checkSleepMode()` 在测试期间把状态恢复为 `normal`。
- 本地语音输入声纹策略保持 `inherit` / `false` 两种有效策略。
- 缺失、`undefined` 或 `null` 的 `textInput.requireVoiceprint` 视为 `false`，不要求输入模式 ASR 做声纹匹配。
- 显式 `inherit` 继续读取服务器最新的 `voiceprintConfig.enabled`，不改变服务器全局配置。

## spec 设计

```text
睡眠测试进入强制睡眠:
    发送 control.sleepOverride = sleep
    服务端/显示端设置 manualSleepMode = sleep
    周期 checkSleepMode 保持 sleep，不受 sleepSettings.enabled 影响
    测试点击页面时保持睡眠，不触发媒体播放

归一化 textInput.requireVoiceprint:
    value 缺失、undefined 或 null:
        textInputVoiceprintPolicy = false
    value == false 或字符串 "false":
        textInputVoiceprintPolicy = false
    value == "inherit":
        textInputVoiceprintPolicy = inherit

计算本地输入请求声纹开关:
    如果 policy == inherit:
        requireVoiceprint = serverVoiceprintEnabled
    否则:
        requireVoiceprint = false
```

## 自测用例

1. 睡眠测试使用手动覆盖后，10 秒周期检查不会把状态改为 `normal`。
2. 睡眠期间点击页面，视频保持暂停。
3. 缺少 `textInput.requireVoiceprint` 时按 `false` 处理。
4. 显式 `inherit` 仍跟随服务器声纹开关。
5. 显式 `false` 仍跳过输入模式声纹要求。

## 兼容性测试

- 旧 Node 配置没有 `textInput` 字段时不报错，输入模式默认不要求声纹。
- 已保存的 `inherit` 配置继续有效。
- 已保存的 `false` 配置继续有效。
- 普通显示端、Android 显示端和服务器全局声纹配置不受影响。

## 性能测试

- 不新增定时器；睡眠周期检查仍保持原有 10 秒间隔。
- 缺省策略只在配置归一化时判断，不增加 ASR 计算。
- `false` 策略继续跳过声纹提取和匹配。

## 风险评估

- 缺失配置从原先的服务器跟随改为关闭输入模式声纹，可能放宽旧 Node 的输入模式门控；显式 `inherit` 可恢复旧行为。
- 睡眠测试改用生产控制协议后，对 WebSocket 初始化和控制消息处理有依赖，但能覆盖真实运行路径。
- 当前睡眠测试仍需要本地 8081 服务和 Chromium 环境。
