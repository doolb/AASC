# Sherpa 快速多段支持最多 5 人

## 任务描述

为独立 Android ASR 测试 APK 增加 Sherpa 快速多段流程，支持自动人数或明确的 1–5 人，并针对非混合的连续多人语音减少重复声纹 embedding 推理。

## Design 需求

- 保留 `SHERPA_SINGLE` 和通用 `SHERPA_MULTI`。
- 新增 `SHERPA_MULTI_FAST`，支持 `speakerCount=AUTO|1|2|3|4|5`。
- 明确人数时把人数传入 Sherpa 聚类配置；自动时保持动态聚类。
- 快速流程每个 cluster 只提取一次代表性 embedding；每个时间分段仍单独执行 ASR。
- 人数超过 5、非数字或非法值返回 400。

## Spec 设计

```text
VoiceprintSpeakerCount.parse(value):
  value 缺失、空白或 AUTO -> 0
  value 为 1..5 -> 对应整数
  其他值 -> null

POST /api/voiceprint/test?mode=SHERPA_MULTI_FAST&speakerCount=<AUTO|1..5>:
  解析 speakerCount
  非法 -> HTTP 400
  合法 -> coordinator.test(mode, samples, cpuMode, speakerCount)

VoiceprintTestCoordinator.fastMulti(samples, speakerCount):
  diarize(samples, speakerCount)
  合并相邻 cluster 分段
  每个 cluster 选择持续时间最长的 merged segment 提取一次 embedding 并匹配注册库
  遍历所有分段分别执行 ASR
  返回完整分段、匹配人名、阶段耗时
```

## 自测用例

- `VoiceprintSpeakerCount` 接受 AUTO、1、5，拒绝 0、6、负数、小数和文本。
- HTTP 页面和状态接口包含 `SHERPA_MULTI_FAST`。
- 缺少人数使用 AUTO；明确 1–5 人进入快速流程。
- `speakerCount=6` 和非法字符串返回 HTTP 400。
- 原 `SHERPA_SINGLE`、`SHERPA_MULTI` 接口行为保持可用。

## 兼容性测试

- SM-N9500、Android 9、arm64-v8a。
- 既有 `zh.wav`、`en.wav`、`zh-en.wav` 回归；`zh-en-mix.wav` 保留通用模式兼容，不作为快速模式优化目标。

## 性能测试

- 对 `zh-en.wav` 对比原多段和快速多段的 `diarizationMs`、`embeddingMs`、`asrMs`、`elapsedMs`。
- 记录快速模式按 cluster 提取 embedding 的次数，确认不超过实际输出 cluster 数。

## 风险评估

- 固定错误人数会导致聚类结果偏差，因此网页默认 AUTO，并允许明确选择实际人数。
- 快速流程按 cluster 复用代表 embedding，遇到同一说话人音色变化较大时可能降低匹配稳定性；通用模式保留逐段匹配作为对照。
- Sherpa AAR 的 `numClusters` 明确设置后会绕过阈值聚类，必须在测试结果中显示所选模式。
