# Chat2API 公共工具调用提示去重

## 任务描述

对照原版 Chat2API 的 `ToolCallingEngine`、Provider profile 和工具提示检测逻辑，修复 AASC 仅在 Qwen 适配器中注入工具提示的问题。所有网页 Provider 统一使用 managed tool calling；同一原生会话的续聊请求只发送增量消息，不重复生成 `System` 工具提示。

## Design 需求

- 在 AASC 核心适配层统一处理 Chat2API tools，不在单个 Provider 中重复实现。
- 使用现有 Pi 支持的 `<|CHAT2API|tool_calls>` 标签协议，保持工具白名单和 TTS 隔离行为。
- Provider 请求移除不被网页接口支持的原生 `tools` 与 `tool_choice` 字段。
- 以工具定义指纹记录提示是否已注入；兼容没有指纹的旧原生会话，避免继续追加重复提示。

关联设计：`docs/design/chat2api-global-responses.md`、`docs/design/chat2api-builtin-task.md`。

## Spec 设计

1. 过滤有效 function 工具并生成统一 managed_xml 提示。
2. 扫描当前消息中的已有提示；若不存在，则按 Responses 原生状态决定是否注入。
3. 首轮注入后保存工具定义指纹，后续相同工具集合只删除原生字段，不再次插入提示。
4. 继续由 Pi Chat2API 转换器把模型返回的标签恢复为 Pi `toolCall`。

关联规范：`docs/spec/chat2api-global-responses.md`、`docs/spec/chat2api-builtin-task.md`。

## 自测用例

- 无 tools 的请求保持原样。
- 首轮工具请求生成一条统一 system 提示，并移除 `tools`/`tool_choice`。
- Qwen 和其他网页 Provider 都收到同一 managed_xml 提示逻辑。
- 同一原生会话第二轮使用相同工具集合时不重复注入。
- 当前消息已经包含工具提示时不重复注入。
- 没有工具指纹的旧原生会话不会再次生成重复 System。
- 工具定义变化时生成新的提示指纹。
- 现有 Pi 标签解析和 Chat2API 全量回归保持通过。

- 既有 Qwen 非流式、流式、gzip 和原生会话测试。

## 性能测试

- 工具提示只在请求边界做一次小规模工具定义序列化和指纹计算。
- 后续原生会话不复制完整历史，不增加 Provider 请求正文长度。
- 不新增常驻进程、定时器或外部网络请求。

## 风险评估

- Provider 网页协议仍可能自行改变标签解析方式；现有 Pi 转换器继续作为权限和格式校验边界。
- 旧会话没有工具提示指纹时按已注入处理，可能导致该旧会话首次新增工具不能立即看到新提示；工具集合变化时会重新注入，必要时可通过新建会话恢复。
- 本次不改变 Provider 的认证、原生会话字段、响应解析和 Pi 工具执行逻辑。
