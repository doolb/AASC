## 自测、性能与风险

受影响仅本机新精度结果和文档，见[Human设计](../design/mmd-human-interface.md)/[spec](../spec/mmd-human-interface.md)。42次完整推理（每模式3×7），Half未适配探测另计；加载和首次kernel/权重触达不纳入热时间。热墙时包含网络/LBS/投影与CPU输出拷贝，不含读图/预处理/加载/JSON序列化；GPU事件与墙时不得互换。显存初始化可用约5GiB，按阶段重查，OOM不得回退CPU标GPU通过。

风险包括Half零token和旋转正交误差、GPU/CPU/版本差异、共享GPU负载、SMPL GPU父节点的同步开销、映射加载与直接目标dtype转移口径；不沿用CPU约慢8倍或当小数值差证明姿态真值。预计20～40分钟用于加载/热测/统计/保护/文档，具体性能以原始实测而非预估为准。API/ONNX、PMX质量及正式MediaPipe入口保持原状。

## 追问：FP16为什么慢（2026-10-19，代表块剖析完成）

非侵入加载同原生ViT Block(dim1280/heads16/MLP4x/tokens192)，随机seed权重，5预热+20事件热测，3次CPU+CUDA profiler（各75 GPU kernel事件），原checkpoint和双JSON不覆盖。FP32/FP16块热时间6.497/19.949ms；profile四Linear核每块6.266/19.873ms，占GPU核时间93.9%/96.4%，attention BMM0.112/0.648ms，主要瓶颈确在代表块矩阵核。MLP fc2形状[192,5120]×[5120,1280]核时间2.304→9.107ms。库所选FP16 GEMM/CUTLASS核不同且实测低效，不把存储减半当计算时间减半。

关闭deterministic后6.600/19.923ms仍约3倍，同workspace4096:8保持，不能单归因开关或排除workspace。块无zero-token bridge、SMPL或Half→Float尾，仍复现慢；原全网254.94/695.21ms、尾部5～6ms与其一致，但不是完整训练模型逐层profile。核名中的volta/tensorop不证明设备误识别/物理TensorCore使用，没有SASS证据确定内部指令、调度或仿真根因；NVIDIA原文说明TU116原生支持FP16而非“不支持FP16”。

原35项/75包及完整GPU原始双JSON SHA保持，已保存[慢因报告](../../tmp/mmd-pose/depth-eval/hmr2-sam3d/precision-eval/gpu-20261019-be36e53f/kernel-diagnosis/diagnosis.md)、[kernel与形状](../../tmp/mmd-pose/depth-eval/hmr2-sam3d/precision-eval/gpu-20261019-be36e53f/kernel-diagnosis/analysis.json)及原始traces。仍建议此卡FP32；优化算法/AMP和准确性回归另需用户确认，本轮无生产源码/配置/依赖/服务变更。
