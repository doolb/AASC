# 正式 APK 双录音方式与控制端麦克风选择

## 任务描述

正式 Android 显示端同时支持 WebView `getUserMedia` 和 Native `AudioRecord` 两种录音方式，控制端可以按显示端选择录音方式和输入设备。两种方式统一复用现有 VAD、PCM、声纹、ASR 和语音会话链路。

## Design 需求

- 新增按 `displayId` 持久化的 `voiceCaptureMode` 和 `voiceInputDeviceKey`。
- `webview` 方式使用 WebView `enumerateDevices` 与 `getUserMedia(deviceId)`。
- `native` 方式使用 Android `AudioRecord`、`AudioDeviceInfo` 和蓝牙 SCO。
- 控制端显示设备列表、请求/实际设备和回退状态。
- 录音切换在空闲时立即生效，录音中停止后自动重启；不可用设备回退默认设备。

## Spec 设计

- 服务端新增 `setVoiceCaptureConfig`、`voiceCaptureConfig`、`displayVoiceCaptureConfigChanged`、`requestAudioInputDevices`、`audioInputDevices`、`voiceCaptureStatus` 消息。
- NativeBridge 新增输入设备枚举、Native AudioRecord 启停和状态接口。
- `NativePcmAudioCapture` 接收 Native PCM16 分块，转换为 Float32，复用 JS VAD 与 WAV 编码。
- 现有 `voiceRecordingMode` 继续表示 ASR/单次/实时用途，不被新配置覆盖。

## 自测用例

1. 服务端重启后，显示端恢复 `webview + default` 默认值或已保存的规范化配置。
2. 控制端切换 WebView/Native，服务器广播权威配置，显示端停止旧链路并按新方式启动。
3. WebView 设备存在时使用 `deviceId: exact`；设备消失时回退默认设备并上报原因。
4. Native 设备列表覆盖默认、内置、蓝牙 SCO、USB（以系统实际暴露为准）。
5. Native 录音产生 PCM 分块，现有 VAD 能分段并继续进入 `/api/asr/recognize`。
6. Native 蓝牙 SCO 建链失败、录音启动失败、设备断开和页面销毁均释放资源。
7. 录音切换、TTS 暂停/恢复、全局录音暂停和 WebSocket 重连不残留 MediaStream、AudioRecord 或 SCO。

## 兼容性测试

- 浏览器显示端：无 NativeBridge 时保持 WebView/default 录音。
- Android 9/API 28：内置麦克风、AIMIC-M4 SCO、设备断开回退。
- Android 12+：`BLUETOOTH_CONNECT` 权限和设备枚举。
- Native 16kHz 失败时的兼容采样率与现有 16kHz PCM 编码。

## 性能测试

- Native 录音线程持续 10 分钟无 AudioRecord 读取错误、主线程无持续积压。
- PCM 分块桥接不会无限增长 JS 缓冲；单次/持续/实时录音分别验证内存。
- 切换设备后 2 秒内回报实际路由状态。

## 风险评估

- WebView 是否暴露所有输入设备由 Chromium/系统决定，不能承诺所有设备都可选。
- Android 音频路由可能接受首选设备但实际使用其他设备，必须显示实际 `routedDevice`。
- Native PCM 通过 JavaScript bridge 分块会增加主线程调度开销，需限制分块频率并在释放时丢弃过期回调。
- 蓝牙 SCO 仍受窄带链路限制，切换录音方式不能提升 SCO 物理音质。
