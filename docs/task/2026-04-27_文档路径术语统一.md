# 任务记录：文档路径术语统一

## 任务描述

- 需求来源：在完成目录清理后继续统一文档中的旧路径术语。
- 目标：将核心文档中的路径示例统一到当前目录结构，减少“历史路径与现路径”混用造成的理解成本。

## Design 需求

1. 核心索引文档（rules/ref/design）优先统一为现行路径。
2. 模块文档中高频被引用路径（ASR、子显示端、ViewBind）优先更新。
3. 保留历史任务/changelog 里的旧路径用于回溯，但在当前设计文档明确“现路径规则”。

## Spec 设计

1. 在 `docs/spec/project-structure.md` 增加文档路径统一校验伪代码。
2. 统一 `server.js`、`scripts/asr-stress-test.js`、`voice-display-node/`、`core/viewbind` 等示例到现路径。
3. 同步更新 changelog 与 todo 检查时间，确保文档闭环。

## 自测用例

1. 检查核心文档中的服务端入口示例为 `src/apps/server/boot/server-app.js`。
2. 检查 ASR 压测脚本文档路径为 `src/scripts/asr-stress-test.js`。
3. 检查子显示端文档路径为 `3rd/voice-display/` 与 `3rd/voice-display-node/`。
4. 检查 ViewBind 示例依赖路径为 `src/core/viewbind` 与 `src/core/data-snapshot`。
5. 检查 `docs/spec/project-structure.md` 已包含路径统一校验伪代码。

## 风险评估

1. 风险：部分历史模块文档仍保留旧路径描述，短期内可能继续出现混用。
2. 缓解：以核心索引与常用模块优先统一，后续按模块滚动清理其余文档。
