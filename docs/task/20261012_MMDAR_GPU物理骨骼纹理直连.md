# 2026-10-12：独立MMD-AR GPU物理姿态直连骨骼纹理

## 任务与授权

用户已明确确认“GPU物理姿态直连骨骼纹理，加一个开关控制”，并确认只针对独立MMD-AR测试网页、先不改正式端、不构建/发布APK、不发布外网。现有PMX已经在Three的顶点着色器GPU蒙皮，本任务是可选地跳过GPU XPBD每帧完整物理结果读回，不是新增CPU→GPU蒙皮或顶点缓存。设计：`docs/design/mmd-xpbd-webgl.md`；实现前伪代码：`docs/spec/mmd-xpbd-webgl.md`。

## 受影响模块和代码

- 3rd/mmd-ar-test/web-xpbd-webgl-solver.mjs、web-xpbd-webgl-physics.mjs、web-xpbd-webgl-state.mjs以及新GPU骨骼合成模块：最终状态纹理→层级/刚体骨骼合成→GPU骨骼调色板，原同步readback保留作为诊断/回退。
- 3rd/mmd-ar-test/web-xpbd-webgl-inject.js、web-xpbd-build.js、web-physics-solver.js、build.js、web-panel-groups.js：仅WEB_MODE按源构建注入开关，处理真实后端与UI状态、缓存指纹、模型/动作生命周期。
- 添加或扩展定向自动测试、真实浏览器WebGL2回归；同步docs/usage/mmd-xpbd-webgl.md、自测说明、相关设计/伪代码与changelog。已有正式显示端源代码和APK不改。

## 实施步骤

1. 首先确认GPU/CPU空间变换、受支持骨骼拓扑和当前动作采样/暂停两种锚点来源。检查出错/限额/多刚体顺序时保留同步后端并说明原因。
2. GPU计算最终局部骨骼P/Q/S及世界骨骼调色板，独立RGBA32F render target每骨四vec4，物理常规帧直接使用state.texture，不做完整打包/读回。Three主材质、深度、阴影从同一纹理采样。
3. 动作UI默认关闭，仅xpbd-webgl且有能力/模型时实际激活；诊断中暂同步，拾取等按需同步；开关和动作/模型切换、后台/上下文丢失清理GPU资源并正确恢复或显式重置。
4. 自测通过后执行 `npm run build:web:mmd-ar-test`；不自动发布/安装APK/重启服务器。若实际GPU/数值验收不能通过，不以保留UI伪开关冒充功能完成。

## 自测与兼容性

- 数值：type0/1/2、不同骨骼父子更新顺序、同骨多刚体、bind inverse/offset、根部变化与非单位缩放，GPU位置、法线/阴影与现有CPU读回基准比对。
- 时序：动作播放、暂停/无mixer、预热、首帧隐藏、动画循环、物理旋转门控、重置/T Pose、风吹、切换VMD/模型/后端和编辑模式。
- UI：默认关闭、存储异常、无WebGL2/无Float FBO、XPBD CPU/Ammo不适用、打开骨骼/碰撞体诊断、点击拾取、后端回退原因、开关反复切换/上下文恢复。
- 性能：在普通预览和动作暂停状态 `readbacks` 保持0（初始化或按需同步单列）；诊断下读回增加；相同模型设置下比较CPU总帧时、GPU计时、pass数、显存和中位数/P95。软件GPU不能代表手机实测收益。

## 风险与预计工时

预计1–3个开发日，取决于PMX刚体对同骨骼的多次写回及父子深度。WebGL2不能直接从顶点着色器写纹理，需多阶段RenderTarget合成；RGBA16F可能引入位移和旋转抖动，本轮先用RGBA32F。CPU诊断、精确拾取和布料依赖可能需要临时同步；断上下文无可读最新物理状态时应显式重置。WebGL新pass成本可能大于原readback收益，必须以真实设备结果为准。
