# 聊天设置外部保存保护 profile 协议

## 任务描述

控制端聊天设置点击外部“保存设置”后，服务端会将完整规范化聊天配置写回配置文件。旧 profile 缺少协议字段时会使用全局 Responses 协议补齐，导致多个内部 profile 的协议被统一显示为 `openai-responses`。需要让外部保存只更新全局聊天字段，保护 profile 专用配置。

## Design 需求

- 外部聊天设置保存只处理系统提示词、Agent 后端和兼容的全局聊天字段。
- profile 的 `protocol`、`apiUrl`、`apiKey`、模型和 `activeProfile` 不由外部保存接口修改。
- Chat2API 配置保存接口保持现有职责，不参与聊天 profile 保存。

## Spec 设计

- 控制端构造全局字段 payload，不发送本地缓存中的 `llmProfiles`。
- 服务端通过统一字段筛选函数处理 `/api/chat/config` 入参。
- 服务端将筛选后的字段合并到已有 `config.chat`，保留 profile 列表和当前 profile。
- profile 继续通过 `/api/chat/profiles` 保存，协议值在该流程中保持独立。

## 自测用例

1. 两个 profile 分别为 `openai-completions` 和 `openai-responses`，外部保存全局设置后协议值保持不变。
2. 外部保存 payload 不包含 `llmProfiles`、`activeProfile` 或 profile 协议字段。
3. profile 专用保存仍可更新协议、地址、模型和密钥。
4. Chat2API 配置保存仍只更新 Chat2API 代理配置。

## 兼容性测试

- 旧客户端提交完整聊天配置时，`/api/chat/config` 忽略 profile 字段，不覆盖已有 profile。
- 旧配置缺少 profile 协议时，仍沿用既有启动迁移规则；本任务不猜测旧协议。
- 不改变聊天历史、会话键、Agent 后端和 Responses 请求流程。

## 性能测试

- 外部保存仅增加一次本地字段筛选，不新增网络请求。
- profile 列表不会因外部保存被重复规范化和写盘。

## 风险评估

- 依赖 profile 变更的调用方必须使用 `/api/chat/profiles`；外部保存接口不再兼容通过完整 chat 配置隐式修改 profile。
- 服务端响应仍返回完整权威聊天配置，旧页面可继续展示；新页面只回填全局字段。

## 预计工时

- 约 1 小时：字段筛选、前后端保存链路调整、回归测试和文档同步。
