# 控制端 AI 角色 Agent 后端选择

## 任务描述

控制端聊天设置增加全局 Agent 后端选择，支持 Claude 和 Codex，默认 Codex。工作 AI 角色保持独立上下文；已有运行中的角色不因全局设置变化而被终止，新建或进程退出后重建的角色使用最新设置。控制端 Agent 不进入 poll.js 任务队列，普通 LLM 与 Agent 使用显式消息类型区分。

## design 需求

- `docs/design/ai-roles.md` 增加 Agent 后端选择、Codex app-server 持久会话和代理环境规则。
- 角色记录保存实际后端，避免全局设置改变时错误替换存活进程。
- Codex 子进程使用 `HTTPS_PROXY=http://127.0.0.1:7899`。

## spec 设计

- `AiRolesService` 按角色创建 `ClaudeBridge` 或 `CodexBridge`，统一 `chat/reconnect/stop/isAlive` 接口。
- Codex 通过 JSON-RPC `initialize`、`thread/start`、`turn/start` 保持 thread 上下文。
- `assistantType='agent'` 路由到当前角色；旧 `mode='role'` 继续兼容。
- `/api/chat/config` 返回并保存 `agentBackend`，默认 `codex`。

## 受影响的功能模块和代码

- 服务端配置、AI 角色桥和角色存储
- WebSocket 聊天消息路由
- 控制端聊天设置、角色状态显示和消息协议
- `docs/design/ai-roles.md`、`docs/spec/ai-roles.md`、`docs/todo.md`、`changelog.md`

## 自测用例

- 默认配置返回 `agentBackend=codex`；旧配置缺失字段时兼容回退。
- 控制端保存 Claude/Codex 后端并刷新后仍显示。
- 新角色按当前全局后端创建；运行中的角色切换全局设置后桥实例不变。
- Codex 假 app-server 能完成 initialize、thread/start、turn/start、增量输出和完成回调。
- Codex 子进程收到指定 `HTTPS_PROXY`，不改变服务端其他环境。
- Agent 消息进入角色处理；普通 LLM 消息仍进入原有处理；旧 `mode=role` 可用。
- Codex/Claude 进程退出后，下一次消息采用最新全局后端。

## 兼容性测试

- 旧控制端不发送 `assistantType` 时，`mode=role` 仍按 Agent 处理。
- 旧角色目录没有 backend 字段时，存活的 legacy Claude 进程继续使用 Claude；无存活进程按最新默认 Codex 重建。
- poll.js 与 workgroup 成员流程不修改、不接收控制端 Agent 消息。

## 性能测试

- 同一角色连续消息只启动一个 Agent 子进程。
- 每次消息只发送一个 `turn/start`，不重复初始化 thread。
- 流式增量不通过轮询任务队列转发。

## 风险评估

- Codex app-server 协议可能随 CLI 版本变化，桥接层只依赖稳定的 initialize/thread/start、turn/start 和完成/增量事件，并对未知消息忽略。
- `approvalPolicy=never` 允许 Agent 按现有工作 AI 规则执行任务；服务器重启仍必须通过控制端接口，规则继续注入角色提示词。
- 代理不可用时仅当前 Codex 请求失败，不终止服务器进程；切换 Claude 可恢复新建角色。
