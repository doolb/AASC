# ASR 测试 APK 麦克风选择

## 任务描述

为 `3rd/tts-server/android-asr` 原生 ASR 测试页面增加输入麦克风选择，支持用户选择已连接的蓝牙麦克风，并在设备不可用时回退系统默认输入。

## design 需求

- 使用 Android 输入设备枚举能力展示当前可用的系统默认、蓝牙、USB、有线和内置输入设备。
- 使用 `AudioRecord.setPreferredDevice` 将原生录音路由到选择设备。
- 选择结果持久化；设备断开时回退默认并提示。
- 录音期间锁定选择控件，避免录音过程中修改路由。
- Android 12 及以上按需申请蓝牙连接权限。
- 本次不改变内置 HTTPS 网页的浏览器录音链路。

## spec 设计

- 新增 `AudioInputDevice` 设备描述和类型名称格式化。
- `MainActivity` 负责枚举、刷新、持久化选择、权限回调和控件状态。
- `AudioRecorder.start` 接收可选 `AudioDeviceInfo`，通过 `AudioRecord.Builder` 设置首选输入设备。

## 自测用例

1. 无蓝牙设备时，页面显示系统默认和现有输入设备，默认选择系统默认。
2. 连接蓝牙麦克风并允许蓝牙连接权限后，刷新列表能显示该设备及其输入类型。
3. 选择蓝牙麦克风录音，`AudioRecord` 设置首选设备并能正常生成 PCM。
4. 录音中麦克风选择和刷新按钮不可用，停止录音后恢复。
5. 选中的设备断开后刷新，页面回退系统默认并显示提示。
6. 蓝牙权限被拒绝时，APK 仍可使用系统默认输入。

## 兼容性测试

- Android 9/API 28：验证 `AudioRecord.setPreferredDevice` 和设备列表兼容。
- Android 12/API 31 及以上：验证 `BLUETOOTH_CONNECT` 按需申请。
- 内置麦克风、蓝牙输入、USB/有线输入（设备实际暴露时）分别验证。

## 性能测试

- 设备枚举仅在页面初始化、手动刷新和设备连接变化时执行，不进入录音循环。
- 录音仍使用 16 kHz、单声道、PCM16 和现有后台线程，不能增加 ASR 推理耗时。

## 风险评估

- 不同 Android 厂商可能不暴露蓝牙输入设备，页面需保留系统默认回退并提示，不保证所有蓝牙协议均可被系统路由。
- 设备 ID 可能随重新连接变化，持久化选择仅在 ID 可恢复时生效；不可恢复时明确回退。
- `BLUETOOTH_CONNECT` 被拒绝不应阻断普通录音。
