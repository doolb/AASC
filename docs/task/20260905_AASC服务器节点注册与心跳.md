# AASC 服务器节点注册与心跳

## 任务描述

在固定主服务器入口下，增加服务器节点登记、心跳和统一只读目录，使控制端可以查看当前 AASC 网络中的服务器节点状态。

## Design 需求

- 主服务器使用固定入口 `https://192.168.1.39:8081/`。
- 节点主动调用注册接口，使用 `nodeId`、地址、版本、能力和元数据登记。
- 节点通过心跳保持在线；90 秒无心跳后显示离线。
- 主服务器自身登记为 `main-server`。
- `/api/aasc/servers` 同时兼容现有 `SubServerManager` 配置节点。
- 当前不做自动发现、权限认证、代码下发、媒体索引同步和任务路由。

## Spec 设计

1. `AascServerRegistry` 使用内存 Map 保存节点记录。
2. 注册和心跳只允许更新受控字段，状态由主服务器根据时间计算。
3. 提供：
   - `POST /api/aasc/servers/register`
   - `POST /api/aasc/servers/:nodeId/heartbeat`
   - `GET /api/aasc/servers`
4. `/upload` 服务器页面改用统一目录接口。

## 自测用例

- 注册新节点后返回在线节点快照。
- 同一 `nodeId` 重复注册时更新信息而不产生重复节点。
- 已登记节点心跳后恢复在线并更新时间。
- 超过心跳 TTL 的节点读取目录时变为离线但不被删除。
- 未知节点心跳返回 404；缺少必填字段返回 400。
- 控制端请求 `/api/aasc/servers` 并展示 `nodeId`、地址、能力和状态。

## 兼容性测试

- 保留 `/api/subservers` 原有接口和配置行为。
- 旧子服务器配置可以通过 `/api/aasc/servers` 兼容展示。
- 不改变 `/display`、`/upload` 和现有 WebSocket 路径。

## 性能测试

- 注册表为内存 Map，注册、心跳和单次查询为 O(1)/O(n) 操作。
- 以 1000 个节点执行一次目录查询，确认无不必要的网络请求和文件写入。

## 风险评估

- 当前注册表不持久化，主服务器重启后需要节点重新注册；主服务器自身会在启动时登记。
- 当前没有认证，局域网内能访问接口的客户端可以登记节点；认证按路线放到后续阶段。
- 旧配置节点的状态仍依赖 `SubServerManager` 健康检查，和主动心跳节点的数据来源不同。

## 实际结果

- 已完成内存注册表、主服务器自身登记、注册/心跳/目录接口和控制端列表切换。
- 保留 `/api/subservers`，统一目录兼容展示旧配置节点。
- 定向测试 7/7 通过。
