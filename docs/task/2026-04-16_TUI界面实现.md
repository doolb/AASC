# 任务：服务端和子显示端 TUI 界面实现

## 任务描述

为服务端（server.js）和子显示端（voice-display-node/main.js）实现基于 blessed 的 TUI 界面，替代 console.log 输出，提供结构化的信息面板展示。

## Design 需求

- 服务端 TUI：系统状态面板 + 设备列表表格 + 事件日志
- 子显示端 TUI：连接状态面板 + 录音状态面板 + 事件日志
- 支持 `--no-tui` 参数禁用 TUI，回退到纯日志模式
- 日志分类着色，缓冲区限制防止内存溢出
- 详见 [docs/design/tui.md](../design/tui.md)

## Spec 设计

- ServerTUI 类：管理 blessed 界面，提供 addLog/updateStatus/updateDeviceList API
- SubDisplayTUI 类：管理子显示端界面，提供 addLog/updateConnectionState/updateRecordingState API
- 详见 [docs/spec/tui.md](../spec/tui.md)

## 自测用例

1. 启动服务端，验证 TUI 界面正常显示
2. 连接显示端，验证设备列表实时更新
3. 发送语音命令，验证日志分类着色
4. 使用 `--no-tui` 启动，验证回退到纯日志模式
5. 启动子显示端，验证 TUI 界面正常显示
6. 子显示端连接/断开，验证状态面板更新
7. 子显示端语音识别，验证日志和录音状态更新

## 兼容性测试

- Windows Terminal / PowerShell
- CMD 终端（有限 Unicode 支持）
- Linux 终端
- SSH 远程终端

## 性能测试

- 日志缓冲区 500 行时内存占用
- 设备列表 50+ 设备时刷新性能
- 高频日志（语音识别每秒多次）时界面流畅度

## 风险评估

- blessed 库在某些 Windows 终端（如 CMD）下 Unicode 渲染可能有问题 → 使用 ASCII 回退
- blessed 与 process.exit 冲突 → 需正确处理 screen.destroy
- 日志高频写入导致界面闪烁 → 使用 screen.render() 节流
