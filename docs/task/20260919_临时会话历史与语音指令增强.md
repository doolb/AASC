# 临时会话历史与语音指令增强

## 任务描述

为显示端临时语音会话增加跨会话历史上下文，并将群聊、临时退出和天气播报规则统一到当前需求：

- 临时会话按一次连续对话分组，主动结束或临时窗口超时后完成一组；
- 默认保留最近 10 组已结束会话，模型请求使用当前组和最近 2 组历史，共 3 组；
- 支持 `小爱再见`、`再见小爱` 退出当前角色的临时模式；
- 使用 `进入群聊`、`退出群聊` 作为群聊控制词；
- 未指定日期的天气请求播报今天、明天、后天，明确指定日期时只播报目标日期；
- 临时唤醒提示语本次不调整。

## Design 需求

- 临时会话 ID 作为连续会话组 ID，新的临时唤醒结束旧组但不清理旧组历史；
- 临时历史和上下文组数量通过现有语音会话 WebSocket 配置流程持久化、广播和重连补发；
- `进入群聊` 在等待唤醒状态也能直接进入持续群聊，`退出群聊` 只在 activeGroup 结束群聊；
- 角色名再见在 activePrivate 时结束私聊，在 temporary activeGroup 时结束临时会话组；
- 当前组始终进入 LLM 上下文，默认再拼接最近两组历史组。

## Spec 设计

- `ConversationState` 增加 `temporaryRoleName`，用于校验临时模式角色名再见；
- 新增 `temporary-conversation-history.js`，负责配置归一化、按 sessionId 分组和上下文选择；
- LLM 构造消息支持调用方传入 `historyMessages`，临时模式使用当前组加历史组；
- 服务端按临时历史组数清理过旧临时消息，当前组不被清理；
- 控制端配置增加临时历史会话组数和临时上下文会话组数输入框。

## 自测用例

1. 临时会话连续消息使用同一个 sessionId，并在新临时唤醒后形成上一组历史。
2. 默认上下文为当前组加最近两组，不携带更早会话。
3. 历史组默认保留 10 组，配置值按服务端范围归一化。
4. `小爱再见`、`再见小爱` 在临时模式结束当前组；私聊场景继续结束私聊。
5. `进入群聊` 在等待唤醒时生效，`退出群聊` 在等待唤醒时不生效。
6. `天气`、`北京天气`使用三天播报；明确说今天/明天/后天时只播报目标日期。
7. 临时唤醒提示保持既有内容，不新增短提示随机逻辑。

## 兼容性测试

- 旧控制端收到不含历史组字段的 `voiceConversationConfig` 时继续使用本地默认值。
- 旧显示端忽略新增 `temporaryRoleName` 和配置字段，不影响普通语音流程。
- 子显示端继续使用原有语音命令流程；新群聊词通过系统命令兼容处理。
- 私聊、持续群聊、一次性群聊和等待唤醒状态互不误触发。

## 性能测试

- 临时历史只按 sessionId 分组并截取配置范围，不在每次请求发送全部历史。
- LLM 请求继续受既有 token 预算裁剪，历史组数量增加不会绕过模型输入上限。
- 每个显示端仍只维护一个会话 timer，不增加临时历史定时器。

## 风险评估

- 历史消息来源包含不同 profile/template，需要按临时 sessionId 聚合，避免上下文缺组或串组。
- 语音状态和控制端文本命令存在两套入口，需保持新指令与旧子显示端兼容。
- 天气服务返回日期不足三天时只能播报实际可用数据，不能合成缺失天气。
