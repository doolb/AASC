# PMX 物理计算频率面板设置

## 任务描述

在显示端“灯光”面板开放 PMX 物理步进频率设置。Three.js r160 当前使用 65 Hz 固定步长；需要让用户按模型运行表现调整，并在刷新显示页后保留选择。

## Design 需求

- 面板提供 30–90 Hz、每格 5 Hz 的滑块，默认值为 65 Hz。
- 设置保存至既有显示端浏览器 `localStorage` 灯光对象，不通过 WebSocket 或服务端配置流程。
- 调整时即时设置当前 PMX `MMDPhysics.unitStep = 1 / physicsFps`；创建 PMX helper 时也使用当前值。
- 每帧最多 3 个物理子步的限制保持不变；面板及文档说明这是目标频率，实际步数受渲染帧率及补算上限影响。
- 灯光预设不改变物理频率；“恢复默认”把物理频率恢复为 65 Hz。
- 老版本 localStorage 数据缺少字段时规范化为 65 Hz；VRM 忽略此配置。

## Spec 设计

```text
结构 MmdLightingSettings
  physicsFps = 65

过程 normalizeMmdLighting(input)
  对 physicsFps 限制在 30..90，并按 5 Hz 对齐
  缺少或非法时使用 65
  返回其余灯光字段与 physicsFps

过程 applyPmxPhysicsFrequency(settings, helper)
  如果 helper 对应 physics 存在
    helper.physics.unitStep = 1 / settings.physicsFps
  新建 helper 时用同一个 unitStep 初始化
  maxStepNum 保持 3
```

## 自测用例

1. 无保存值/旧设置缺少频率时显示 65 Hz。
2. 滑块只产生 30–90 Hz、5 Hz 间隔的规范化值，并保存至 localStorage。
3. 修改值时当前 PMX 的 `unitStep` 即时变更，新建动作或模型 helper 沿用当前频率。
4. 选择柔和/明亮灯光预设保留频率；恢复默认后值为 65 Hz。
5. VRM 忽略该值，不改变 SpringBone 更新。
6. 当前物理每帧最多 3 子步的限制不变。

## 兼容性、性能与风险

- 兼容性：Three.js r160 `MMDAnimationHelper.add()` 已支持 `unitStep` 参数；存量设置缺字段时使用原有 65 Hz 默认值。
- 性能：提高 Hz 会按物理固定步长增加 Bullet 子步工作量；最多子步数仍为 3，不增加物理循环或 WASM 实例。
- 风险：渲染帧率较低时实际步进追不上配置目标；不同 PMX 模型对步长敏感度不同，65 Hz 保持为默认值。
