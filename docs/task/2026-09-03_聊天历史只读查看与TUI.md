# 聊天历史只读查看与 TUI

## 任务描述

复用现有聊天只读接口，提供命令行查看聊天历史及私聊 session 名称的能力，并支持可选的终端 TUI 展示。查看命令不新增服务端 API，不发送或修改聊天数据；历史 session 名称另执行一次性原始配置迁移。

## Design 需求

- 默认输出服务端返回的 JSON，方便脚本和 AI 继续解析。
- `--tui` 将聊天历史按时间、角色和消息内容渲染为终端面板。
- `--sessions` 不要求 `target`，获取全部私聊 session，并补充群聊的角色名和 session 名。
- 支持 `--mode`、`--target`、`--session`、`--profile` 和 `--limit` 客户端过滤。
- 同时兼容现代 `role/content` 消息和旧版 `user/assistant` 成对消息。
- 读取失败、JSON 格式错误和参数错误返回 stderr 与非零退出码。
- `--target` 在 `--sessions` 下为可选过滤项；省略时保留全部角色。
- 本次不处理实时 WebSocket 跟随，不增加新的服务器路由；现有 sessions 路由仅扩展缺省 target 的查询分支。

## Spec 设计（伪代码）

```
查看聊天历史(参数):
    解析只读过滤参数和 TUI 参数
    如果未选择 sessions:
        调用现有 GET /api/chat/history
        检查响应是对象且 history 是数组
    如果选择 sessions:
        调用现有 GET /api/chat/sessions，可选传入 target
        调用现有 GET /api/chat/history，仅查找群聊首条用户消息
        检查 sessions 是数组
        按 mode、target、sessionId 过滤
        每项只保留 { target: 角色名或群聊, name: session 名 }
        输出 { status, sessions }
        如果选择 tui:
            只输出角色名和 session 名面板
    否则:
        按 mode、target、sessionId、profileName 在客户端过滤
        保留最近 limit 条消息
        如果选择 tui:
            识别旧版 user/assistant 或现代 role/content 格式
            按终端显示宽度换行
            输出元数据和消息面板
        否则:
            输出 history JSON

服务端全部 session 查询:
    保留 GET /api/chat/sessions?target=TARGET 的原有返回格式
    target 缺省时收集配置和私聊历史中的全部 target
    恢复缺失的 default/session 元数据
    返回扁平的 { mode, target, id, name, createdAt } 列表
```

## 受影响的功能模块和代码

- `scripts/api/chat-history.js`：现有聊天历史和 session HTTP API 的只读 CLI 封装。
- `scripts/api/chat-tui.js`：聊天历史终端格式化器。
- `src/external/llm/llm-service.js`：汇总全部目标的私聊 session 元数据。
- `src/apps/server/boot/server-app.js`：扩展现有 sessions GET 路由的可选 target 行为。
- `tests/chat-history-cli.test.js`：参数、过滤、JSON/TUI 输出和只读边界测试。
- `tests/private-chat-session-recovery.test.js`：全部 session 汇总和服务端路由契约测试。
- `tests/api-cli-contract.test.js`：将聊天历史脚本纳入 API CLI 契约检查。
- `docs/api-usage.md`、`docs/design/api-usage.md`、`docs/spec/api-usage.md`：使用说明、设计和伪代码同步。

## 自测用例

1. `chat-history.js --help` 不发起网络请求。
2. 默认模式调用 `GET /api/chat/history` 并输出 JSON。
3. `--sessions` 不填写 target 时调用现有 sessions GET 接口并只输出角色名、session 名。
4. 过滤参数只影响客户端输出，不调用写接口。
5. `--tui` 正确显示 session 名称；默认模式继续显示现代消息和旧版 user/assistant 消息。
6. 非法参数、错误 JSON 和服务端错误返回非零状态。
7. 带 target 的现有 sessions API 返回格式保持兼容。
8. 执行根目录 `npm test`，记录当前已知 DeX 输入测试边界。

## 兼容性测试

- 复用 `scripts/api/common.js` 的 HTTP、HTTPS、自签名证书和超时约定。
- 保持 `/api/chat/history` 原有 JSON 外壳和字段；不新增服务端路由，现有 sessions 路由的带 target 调用格式不变。
- 终端中文使用显示宽度计算，适配普通文本终端。

## 性能测试

默认模式只读取一次历史；`--sessions` 读取一次 session 列表和一次历史（只提取群聊标题），在内存中过滤和裁剪字段；TUI 不持久化数据、不轮询、不启动常驻进程。

## 风险评估

- 聊天历史可能包含敏感内容，CLI 不写入额外文件，用户需自行保护终端输出。
- 服务端历史字段同时存在新旧格式，格式化器必须兼容两种结构。
- 本次不提供实时跟随；实时展示后续应复用既有 WebSocket，不通过轮询伪造实时接口。
