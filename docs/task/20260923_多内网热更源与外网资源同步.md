# 多内网热更源与外网资源同步

## 任务描述

为 Offline APK 增加家庭和公司两个内网热更地址，并新增脚本把外网服务资源包同步到指定本地热更目录。完整 APK 不参与同步，现有内网/外网发布目标保持不变。

## Design 需求

- 热更源顺序为家庭 `192.168.1.39`、公司 `10.221.70.87`、外网域名回退。
- Android 对域名源继续先解析 IP，再替换 URL 主机访问，不保留 Host。
- Node 构建读取当前清单时也支持两个内网源和公网 IP 回退。
- 发布器的本机目录和外网 SCP 目录不因新增读取源改变。
- 新增同步命令，默认从公网 IP 下载到 `/mnt/aasc-offline`，支持参数或环境变量指定其他本地目录。
- 同步代码、依赖、min APK、数据修复包；排除完整 APK。

## Spec 设计

- Android `OfflineUpdateManager` 使用三组源并保持 DNS/IP 展开与逐源回退。
- `offline-update-package.js` 使用可测试的多源常量读取当前签名清单。
- 新增 `scripts/ops/sync-offline-update.js`，验签、下载、大小/SHA-256 校验、原子清单切换和精确清理。
- `package.json` 新增 `sync:offline-update`。
- 同步 CLI 支持 `--source-url`、`--local-root`，默认值兼容现有目录。

## 自测用例

1. Android 源列表按家庭、公司、外网顺序尝试；前一源不可用时可从下一源读取清单和资源。
2. Node 构建从任一内网源取得当前清单，均能继续构建。
3. 同步命令验签失败、清单组件 SHA-256 错误、同版本 hash 冲突时不替换 `manifest.json`。
4. 同步命令能下载 code/dependencies/min/data-repair，且不下载完整 APK。
5. 同步目标使用 `--local-root` 和环境变量时写入指定目录，默认目录仍为 `/mnt/aasc-offline`。
6. 现有发布器仍只写本机 `--local-root` 和固定外网 SCP 目录，不向第二个内网 IP 自动上传。

## 兼容性测试

- 已安装旧 Offline APK：旧地址仍可用，升级后新增公司地址仅增加回退能力。
- 家庭网络、公司网络、仅公网三种网络环境。
- Linux 本地目录和跨文件系统临时目录。
- 不同步完整 APK，不改变 full APK 发布规则。

## 性能测试

- 清单请求按源顺序连接超时，不改变现有连接/读取超时。
- 同步包使用流式下载和 SHA-256，避免将大文件整体载入内存。
- 不重复下载本地已有且 hash 相同的版本文件。

## 风险评估

- 公司内网目录可能与家庭不同；通过 `--local-root` 或 `AASC_OFFLINE_LOCAL_ROOT` 显式指定，避免误写默认目录。
- 公网域名当前可能返回代理 403；同步默认使用公网 IP，Android 仍保留域名解析逻辑。
- 同版本 hash 不一致时严格中止，避免覆盖已发布资源。
