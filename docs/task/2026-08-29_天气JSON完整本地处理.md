# 2026-08-29 天气 JSON 完整本地处理

## 任务描述

修复天气接口 `lang_zh` 仍返回 `Mist` 等英文描述的问题，并将 wttr.in `format=j1` 返回的完整天气数据在服务端本地归一化，支持系统回复查看当前天气、未来约 3 天预报、逐时天气、天文信息和降雨/紫外线等指标。

## Design 需求

- 继续使用 `https://wttr.in/{city}?format=j1&lang=zh`。
- 服务端不假设 `lang_zh` 一定为中文，按天气编码本地转换天气描述。
- 保留当前城市识别、默认城市回退、请求重试、TTS 和显示端天气响应协议。
- 显示文本包含完整数据；TTS 播报当前天气和逐日概览，避免逐时明细导致播报过长。

## Spec 设计

- 新增天气数据归一化函数，统一数字类型和缺失值。
- 当前数据包含温度、体感温度、湿度、气压、能见度、风向风速、天气编码、云量、降水、紫外线和观测时间。
- 未来最多保留 3 天逐日和逐时数据，并保留日出、日落、月相等天文数据。
- `weatherResult` 消息增加完整 `detailText` 和结构化 `weather`，`text` 保留短 TTS 文案。

## 自测用例

1. `weatherCode=143` 且 `lang_zh=Mist` 时输出“雾”；`weatherCode=149` 且 `lang_zh=Smoky haze` 时输出“霾”。
2. 当前天气完整保留温度、体感、湿度、气压、能见度、风向风速和天气编码。
3. 未来数据最多保留 3 天，每天保留逐日、逐时和天文信息。
4. 逐时数据保留降雨概率、降水量、紫外线、温度、湿度和风速。
5. 缺失字段归一化为 `null`，不生成 `undefined` 文案。
6. 默认城市回退提示和现有 TTS/显示端流程保持有效。

## 兼容性测试

- Node.js CommonJS 模块加载。
- 旧天气 JSON（没有 `lang_zh` 或缺少部分字段）。
- 显示端只使用 `text` 的旧天气消息。
- `weatherResult` 新增字段不影响已有天气音频播放流程。

## 性能测试

- 本地归一化仅遍历最多 3 天逐时数组，不新增网络请求。
- 保持 wttr.in 原有 15 秒超时、最多 3 次请求和 1 秒重试间隔。

## 风险评估

- wttr.in 天气编码来自 WorldWeatherOnline，未知编码只能回退接口原文，不能保证所有描述都能中文化。
- 完整逐时文本较长，显示端需要使用弹窗的完整详情；TTS 只播报摘要以控制时长。
- wttr.in 返回字段是字符串和数组混合结构，归一化函数必须对缺失字段保持容错。
