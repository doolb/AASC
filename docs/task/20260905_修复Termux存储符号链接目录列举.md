# 修复 Termux 存储符号链接目录列举

## 任务描述

Termux 执行 `termux-setup-storage` 后，`~/storage` 目录及其下级目录通常由符号链接指向共享存储。媒体库配置使用 `../` 作为基础路径时，LocalProvider 可以读到链接名称，但控制端无法把链接目录识别为文件夹并继续列举。

本任务修复符号链接目录的类型判断，同时保持断链跳过、路径校验、隐藏文件过滤和普通文件处理行为不变。

## Design 需求

- 对 `LocalProvider.list` 中的目录项同时区分链接自身状态和链接目标状态。
- 使用 `lstat` 判断是否为符号链接，使用 `stat` 获取有效目标的真实目录或文件属性。
- 符号链接目标不存在时继续跳过该项，避免断链影响整个目录列表。
- 不放宽 `_resolvePath` 的路径边界校验，不改变 `../` 的既有路径解析规则。

## Spec 设计

- 先调用 `lstat(itemPath)` 得到链接自身属性。
- 普通文件或目录直接使用该属性；符号链接调用 `stat(itemPath)` 获取目标属性。
- 使用最终的 `stat` 判断 `type`、`mediaType`、`size` 和 `modifiedTime`。
- 对 `stat` 失败的断链项返回空值，并在列表映射后过滤。

## 自测用例

- 创建临时目标目录和 `storage` 目录符号链接。
- 列举根目录时，验证 `storage` 返回 `type=folder` 和 `mediaType=folder`。
- 继续列举 `/storage` 时，验证目标目录中的 `DCIM` 可以返回。
- 保证测试结束后删除临时目录。

## 兼容性测试

- Linux/Termux 使用目录符号链接执行回归测试。
- Windows 测试使用 junction，避免依赖管理员权限。
- 普通文件、普通目录、隐藏文件和断链逻辑沿用现有实现。

## 性能测试

- 每个符号链接目录项增加一次 `stat`，普通文件和普通目录不增加系统调用。
- 列表排序、媒体类型识别和公开 URL 生成逻辑不变，预计对普通媒体库无可感知性能影响。

## 风险评估

- 有效符号链接可能指向媒体库基础目录之外；路径边界仍由 `_resolvePath` 负责，当前改动不改变其校验策略。
- 断链继续被忽略，可能无法在列表中显示已失效链接，但与原有行为一致。
