# Termux 服务器切换 8081 端口

## 任务描述

停止 Android Termux 中原有的 code-server，取消其 runit 自动启动，并将 AASC 试运行服务器从 18081 切换到 8081。保留 code-server 数据，不修改仓库内业务代码。

## Design 需求

- AASC 继续运行在 Termux 的 `~/aasc-server-test` 目录。
- 释放原有 8081 端口给 AASC 使用。
- code-server 服务停止，并通过 runit `down` 标记持久化禁用自动启动。
- 保留旧端口 18081 的释放状态和当前配置备份。
- 保留 HTTPS、静态页面、WebSocket 和服务状态接口。

设计文档：`docs/design/android-termux-server.md`。

## Spec 设计

- 停止 `aasc-server-test` 服务，避免切换期间端口竞争。
- 在 `$PREFIX/var/service/code-server/` 写入 `down` 标记并停止服务。
- 将 `config/config.json` 备份为 `config/config.before-port-8081.json`。
- 将 `server.port` 设置为 `8081`，重新启动 AASC runit 服务。
- 检查 8081 的 `/api/status`、`/upload`、`/display`，并确认 18081 无监听。

实现文档：`docs/spec/android-termux-server.md`。

## 受影响的功能模块和远程文件

- 远程配置：`/data/data/com.termux/files/home/aasc-server-test/config/config.json`。
- 远程配置备份：`/data/data/com.termux/files/home/aasc-server-test/config/config.before-port-8081.json`。
- AASC 服务：`/data/data/com.termux/files/usr/var/service/aasc-server-test/`。
- code-server 服务：`/data/data/com.termux/files/usr/var/service/code-server/down`。
- 本次没有修改仓库内 Node.js 业务代码，也没有删除 code-server 数据。

## 自测用例

| 用例 | 结果 |
|---|---|
| AASC 端口配置为 8081 | 通过，远端配置读取值为 8081 |
| AASC runit 服务运行 | 通过，服务状态为 `run` |
| `/api/status` | 通过，返回 `status=ok` |
| `/upload` | 通过，HTTP 200 |
| `/display` | 通过，HTTP 200 |
| 局域网访问 | 通过，`https://192.168.1.6:8081/display` 返回 HTTP 200 |
| 旧端口释放 | 通过，18081 无监听 |
| code-server 停止 | 通过，服务状态为 `down`，未发现 code-server 进程 |
| code-server 自动启动禁用 | 通过，`down` 标记持久存在 |

## 兼容性测试

- Android 9（API 28）、Samsung SM-N9500、arm64-v8a、Termux 0.118.3。
- HTTPS 局域网访问通过。
- AASC 服务核心链路不依赖 ASR、TTS Wine 和 Puppeteer。

## 性能测试

- 端口切换后 AASC 服务正常启动，状态接口可用。
- 本次未进行媒体大文件上传、WebSocket 长连接和并发压力测试。

## 风险评估

- code-server 被禁用后，如需恢复，需移除 runit `down` 标记并手动启动服务。
- Android 电池优化和设备重启后的 AASC 自动拉起仍未验收。
- 端口 8081 当前仅在局域网 HTTPS 下验证，正式部署仍需节点认证和访问控制。
