# APK 媒体焦点播放状态同步

## 任务描述

修复 Android APK 显示端播放视频/音频时，系统媒体播放器抢占音频焦点导致 WebView 媒体暂停，且控制端服务器仍显示播放中的状态不一致问题。

## Design 需求

详见 `docs/design/android-display.md` 的“外部系统媒体抢占与播放状态一致性”：区分控制端期望播放状态与媒体元素实际状态，监听原生音频焦点并在焦点恢复后重试播放。

## Spec 设计

详见 `docs/spec/android-display.md` 的“媒体播放状态检测”伪代码：显示端监听媒体事件，原生桥转发 `AudioManager` 焦点变化，控制端暂停/睡眠场景禁止自动恢复。

## 自测用例

1. 控制端播放 video，系统媒体播放器抢占焦点后，显示端检测暂停并尝试恢复。
2. 系统媒体停止并释放焦点后，显示端恢复播放并上报 `isPlaying=true`。
3. 控制端手动暂停后启动系统媒体，显示端保持暂停，不自动播放。
4. 睡眠/深度睡眠中媒体暂停不触发恢复。
5. 音频批量播放的自动切换与 `playlistState.paused` 不被焦点检测破坏。
6. 无 APK 原生桥的浏览器显示端保持现有行为。

## 兼容性测试

- Android 7+、WebView 版本差异下验证 AudioFocus 监听。
- Chromium 浏览器显示端不依赖 `NativeDisplay`，回归现有播放控制。

## 性能测试

- 事件监听优先，播放状态检测只在媒体播放期间使用低频兜底定时器。
- 自动恢复采用有限次数/退避，避免系统焦点持续占用时高频调用 `play()`。

## 风险评估

- Android 音频焦点策略由系统和设备 ROM 决定，不能保证与第三方媒体同时输出；实现保证焦点恢复后按控制端期望状态恢复。
- 自动播放策略仍可能被 WebView 播放策略拒绝；此时服务器继续保持控制端期望的播放状态，待焦点恢复或 watchdog 再次尝试，控制端明确暂停仍会立即切换为暂停状态。
