# TUI日志过长截断避免越界

## 任务描述

- 问题：服务端/子显示端 TUI 的事件日志出现超长单行日志时，右侧会越界显示，导致 TUI 列表区域被“撑破”，可读性变差；且当仍有模块使用 console.* 直接输出时，会破坏 blessed 渲染，文本会“串到上面其他面板”
- 目标：保证日志面板内每条日志在可视宽度内展示（必要时截断），且不影响滚动与刷新

## Design 需求

- 日志默认单行展示；原始换行压缩为字面量 `\\n`，避免单事件占多行
- 按日志面板可视宽度对消息做截断，使用 `...` 作为省略标记
- 截断按终端显示宽度估算：中文/全角按 2 列宽
- 清理 ANSI 控制序列/不可见控制字符，并转义 `{}`，避免 blessed 标签解析导致边界溢出
- TUI 模式下必须重定向 console.* 到 TUI 日志，禁止直接写 stdout/stderr

## Spec 伪代码

```
当 addLog(category, message) 被调用:
    timestamp = HH:MM:SS
    tag = `[${category}]`
    prefix = `${timestamp} ${tag}`
    safeMessage = normalizeToSingleLine(message)
    innerWidth = getLogInnerWidth()  // 优先 logBox.iwidth，兜底 screen.width
    maxMessageWidth = innerWidth - displayWidth(prefix) - 2  // 预留右侧安全边距，避免终端自动换行串到其他面板
    fittedMessage = truncateMiddleToDisplayWidth(safeMessage, maxMessageWidth)  // 中间截断，尽量保留尾部信息
    logBox.log(`${prefix} ${fittedMessage}`)  // prefix 保持颜色标签

normalizeToSingleLine(input):
    把换行替换成 " \\n "，tab 替换为 4 空格

stripAnsiSequences(input):
    移除 "\x1b[..." ANSI CSI 控制序列

stripControlChars(input):
    移除不可见控制字符（0x00-0x1F、0x7F-0x9F）

escapeBlessedTags(input):
    将 { 和 } 转义为 \{ 和 \}（避免 tags=true 时被当作 blessed 标签）

displayWidth(str):
    遍历字符，中文/全角按2列，其他按1列

truncateToDisplayWidth(str, maxWidth):
    若 <= maxWidth: 返回原文本
    否则截断到 maxWidth-3 并追加 "..."
```

## 受影响模块

- 服务端 TUI：`core/tui.js`
- 子显示端 TUI：`voice-display-node/tui.js`
- 公共工具：`core/tui-utils.js`（新增）

## 自测用例

1. 在 TUI 模式下打印超长单行日志（中文 + 英文 + JSON）
   - 预期：日志在右侧不越界；显示 `...` 省略
2. 打印包含换行的日志（例如堆栈或多行文本）
   - 预期：在日志面板中仍是一行，换行显示为字面量 `\\n`
3. 调整终端宽度后继续打印日志
   - 预期：截断宽度随面板宽度变化，不出现明显错位

## 兼容性测试

- Linux/macOS 常见终端（等宽字体）
- tmux 场景（iwidth 获取不到时能兜底）

## 性能评估

- 每条日志增加一次字符串遍历（按字符计算宽度/截断），复杂度 O(n)
- 仅在 addLog 时执行，不影响定时刷新频率

## 风险评估

- 宽度估算为近似实现，极少数字符宽度可能与终端实际不一致；但目标是避免明显越界，近似足够
- 极窄终端宽度下可能截断很短（<3 列宽）不显示省略号，属于可接受退化
