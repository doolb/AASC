# 显示端单次录音注册声纹

日期：2026-10-18。状态：代码与定向测试完成，待显示端现场验收。

## 任务描述与需求评审

用户要求在控制端当前选中显示端的“单次录音”结果区，“已收到录音”后增加姓名输入框和“注册为声纹”按钮。已收到的录音直接用于注册，不要求显示端或控制端重新录制。

主等级 L6：控制端录音结果与声纹注册接口之间的输入输出契约；次等级 L5：录音、重播、填写姓名和提交的交互顺序。现有单次录音结果已是 16kHz WAV，注册接口已接收 multipart WAV，因此可下放到 L4 数据流；关键风险是界面重绘丢失姓名、重录后误提交旧录音、重复点击，以及显示端断线。结论：可按既有协议开发，不需要新 WebSocket 或 Android 桥接口。

## Design 与 Spec

控制端为每个显示端只保存最近一次单次录音的 WAV Blob、播放 URL、声纹姓名草稿与注册状态。收到新录音时替换 Blob，保留姓名草稿并清除上次结果；注册调用 `VoiceprintPanel.submitRegistration`，由同一接口刷新权威声纹列表。输入框聚焦时暂停 VAD 卡片重绘。见 `docs/design/display-recording.md`、`docs/design/voiceprint.md` 与对应 spec 伪代码。

## 受影响模块

- `src/apps/web-mediacenter/ui/public/js/device-list.js`：结果卡片、WAV Blob、状态与注册动作。
- `src/apps/web-mediacenter/ui/public/js/voiceprint-panel.js`：复用 multipart 注册和声纹列表刷新。
- `src/apps/web-mediacenter/ui/public/css/upload.css`：输入框与按钮布局。
- `tests/display-recording-voiceprint-registration.test.js`：最近录音、重录替换、空名字、重复提交及失败反馈。

## 自测、兼容与性能

定向测试覆盖单次/实时录音原契约、WAV 编码和新注册入口，24/24 通过；脚本语法与差异检查通过。真实设备需从当前选中显示端录音后填写姓名，验证成功、同名重录、列表刷新与随后识别。实时录音和普通 ASR 不显示该注册入口，服务端现有 8 MiB 单次回传限制和注册提取模式保持。控制端只保留一份最近录音 Blob，新的录音替换旧对象 URL；网络请求仅在点击注册时发生。预计开发与自测约 1 小时，设备验收另计。
