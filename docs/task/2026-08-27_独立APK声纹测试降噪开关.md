# 独立 APK 声纹测试降噪开关

## 任务描述

在 `3rd/tts-server/android-asr` 测试 APK 中增加降噪开关。开关开启时，使用 Sherpa GTCRN 对完整音频降噪一次，并将降噪音频用于声纹注册、单段声纹匹配、普通多段 diarization/声纹匹配、快速多段声纹匹配以及 ASR；流式 ASR 保持不变。

## design 需求

- 网页增加“ASR/声纹降噪”复选框，默认关闭。
- 注册接口和声纹测试接口接收 `denoise=0|1`。
- 开启后使用降噪音频完成全部离线声纹流程，保证注册和匹配使用相同的音频条件。
- 返回 `denoise`、`denoiseMs`，用于测试结果对照。
- 降噪模型加载失败或推理失败时返回明确错误，不静默使用原始音频。

## spec 设计

```text
VoiceprintRequest:
  mode
  speakerCount
  denoise
  audio

处理请求:
  rawSamples = 解码为 16k mono Float32
  if denoise:
    samples = SherpaDenoiseEngine.process(rawSamples)
  else:
    samples = rawSamples
  samples -> diarization / embedding / match / ASR
  返回 denoise 和 denoiseMs
```

## 受影响的功能模块和代码

- `SherpaDenoiseEngine.kt`：封装离线 GTCRN 降噪模型加载、推理和释放。
- `DenoiseModelFiles.kt`、`app/build.gradle.kts`：内置模型资源复制。
- `VoiceprintTestCoordinator.kt`：注册与三种测试模式接收降噪参数。
- `AsrHttpServer.kt`：解析注册/测试请求的 `denoise` 参数。
- `AsrWebPage.kt`：增加开关并透传请求参数。
- `HttpJson.kt`：返回降噪状态和耗时。
- Android JVM 测试：覆盖开关解析、网页契约、结果 JSON 和模型文件契约。

## 自测用例

- 开关关闭时，三个离线模式请求保持原有接口兼容。
- 开关开启时，注册请求和测试请求均透传 `denoise=1`。
- `denoise=0`、`false`、缺失值解析为关闭；`denoise=1`、`true` 解析为开启。
- 非法请求仍返回 400，降噪模型不可用返回明确错误。
- `zh.wav`、`en.wav`、`zh-en.wav`、`zh-en-mix.wav` 分别测试单段、普通多段、快速多段的开关前后结果。

## 兼容性测试

- Android 9、arm64-v8a、SM-N9500 真机。
- 原有 HTTPS 页面、`/api/asr`、`/api/asr/stream` 和声纹接口保持可访问。
- 流式 ASR 不加载或调用降噪流程。

## 性能测试

- 返回并记录 `denoiseMs` 和 `elapsedMs`。
- 对比四个 WAV 在降噪关闭/开启时的 diarization、embedding、ASR 和总耗时。
- 验证完整音频只执行一次降噪，不按每个分段重复运行模型。

## 风险评估

- 降噪模型可能改变声纹特征，需使用相同开关重新注册声纹后再比较。
- 降噪不能分离重叠说话人，`zh-en-mix.wav` 仍可能出现两个分段得到相同混合语音文本。
- GTCRN 模型会增加 APK 资源和内存占用；模型初始化失败必须可观测。

## 预计工时

- 约 1.5 小时：模型资源、流程参数、网页开关、单测、构建和真机对照。

## 实际完成结果

- 已加入 GTCRN 模型资源、Sherpa 离线降噪封装、网页开关、HTTP 参数和结果耗时字段。
- Android JVM 单元测试和 Debug APK 构建通过；APK 已安装到 SM-N9500。
- 真机启动状态显示 Sherpa、GTCRN、流式 ASR、HTTPS 均就绪；`/health` 返回 `modelReady:true`、`streamingReady:true`。
- `zh.wav` 开启降噪后，注册、单段、普通多段、快速多段均成功；四次结果均匹配 `ZH`。
- 降噪耗时分别为注册 `1556ms`、单段 `1536ms`、普通多段 `1542ms`、快速多段 `1615ms`。
