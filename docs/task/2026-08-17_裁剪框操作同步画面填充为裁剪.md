# 控制端裁剪框操作同步画面填充为裁剪

## 任务状态：✅ 已完成

## 设计需求

参考：[design/control.md](../design/control.md)（裁剪预览模块）

## 问题描述

控制端上传页通过裁剪框（拖拽/缩放/重置）设置裁剪区域给显示端时，画面填充模式未同步变为「裁剪」。

## 根因

- 裁剪框**拖拽/缩放/重置路径**（`Crop.onMouseDown` → `onMouseMove` → `sendData()`）只发送 `sendControl('crop', data)`，从不同步 fit 模式：
  - 不更新 `Crop.currentFit`、不高亮控制端「裁剪」按钮、不发 `fit='crop'`
  - 服务端 `crop` 分支只持久化 `crop`，`fit` 保持旧值（如 `contain`）
- 显示端 `case 'crop'` 会强制 `currentFit='crop'`，所以**显示端实时确实裁剪了**，但：
  - 控制端「画面填充」按钮不高亮「裁剪」
  - 服务端持久化 `fit` 不是 `crop` → **显示端刷新/重连后 restoreState 恢复 `fit='contain'`，`applyCrop` 里 `if (currentFit !== 'crop')` 直接跳过 → 裁剪区域视觉丢失**

仅手动输入路径 `applyManualCrop()` 正确调用了 `sendFitMode('crop')`，拖拽路径漏了。

## 修复方案

`crop.js` 的 `sendData()`（裁剪下发统一出口）增加非裁剪模式自动切裁剪：

```
sendData():
    若 currentFit ≠ 'crop' 且 window.Controls 存在:
        Controls.sendFitMode('crop')   # 高亮裁剪按钮 + currentFit='crop' + 下发 fit='crop'（内部已带 crop 数据）
        return                          # 避免重复发 crop
    否则:
        WebSocketManager.sendControl('crop', this.data)
```

- 首次操作裁剪框时 guard 触发一次切为裁剪模式，之后 `currentFit === 'crop'` 走正常 crop 下发（拖拽节流不受影响）
- `recalculateSize` 非裁剪模式早退逻辑不变，切换角度不误发
- 重置裁剪（`Crop.reset`）在非裁剪模式下同样经 guard 切为裁剪模式，保证重置后立即生效

## 自测用例

- 控制端：上传图片 → 拖拽裁剪框 → 「画面填充」按钮自动高亮「裁剪」；缩放手柄、重置裁剪同样生效
- 显示端：收到 `fit='crop'` + `crop` 数据，裁剪生效；刷新/重连后 restoreState 恢复 `fit='crop'`，裁剪区域不丢失
- 回归：不操作裁剪框时切换角度，`recalculateSize` 非裁剪模式仍不发 crop（不误进裁剪）
- 自动化：`node tests/crop-senddata-sync.test.js`（puppeteer：contain→sendData 发 fit+crop、currentFit 变 crop；已 crop 只发 crop；reset 自动切裁剪）；`node tests/rotate-crop-js.test.js` 3 场景回归通过

## 风险评估

- `sendFitMode` 内部已带 crop 数据下发，guard 提前 return 避免重复发送
- 非裁剪模式早退（`recalculateSize`）保持不变，切换角度不误进裁剪
- 无显示端/服务端改动，数据流沿用现有 `fit`/`crop` control 通道
