# 正式 APK 声纹分段后处理与相似度阈值

## 任务描述

将独立 Android ASR 测试 APK 已验证的声纹分段后处理逻辑接入正式 `android-display` APK，并在控制端提供声纹相似度阈值设置，默认值为 `0.3`。

## Design 需求

- 正式 APK 继续使用现有 ERes2Net 512 维声纹模型和 Sherpa 快速多人分割。
- `SHERPA_MULTI` 与 `SHERPA_MULTI_FAST` 使用同一套后处理：短未知段只有在与相邻已知段合并后重新匹配成功时才归属该说话人。
- 单段和多段结果都返回实际 `similarityScore` 与当前 `threshold`。
- 控制端、服务端和正式 APK 通过现有 `voiceprintConfig` 链路传递阈值，默认 `0.3`；已有持久化阈值保持不变。

## Spec 设计

- `VoiceprintEngine.match` 返回说话人、诊断分数和阈值。
- `VoiceprintSegmentPostProcessor.resolve` 负责保护性合并和合并后重新匹配。
- `NativeBridge` 的异步统一 ASR、单段桥和多人桥均消费后处理结果。
- `/api/voiceprint/config` 校验并保存 `(0,1]` 阈值；控制端新增数值输入。

## 自测用例

1. 短未知尾段与前段合并后重新匹配为同一注册说话人，最终只产生一个 ASR 分段。
2. 合并后重新匹配为其他说话人时，不合并且保留未知段。
3. 不同已知说话人之间的短未知段不被强行合并。
4. 单段返回 `speaker`、`similarityScore`、`threshold`；多人每个分段返回分数。
5. 控制端阈值输入默认显示 `0.3`，非法值被服务端拒绝，保存值通过 WebSocket 下发到正式 APK。
6. 未配置旧阈值时使用 `0.3`，已存在的旧阈值不被启动迁移覆盖。

## 兼容性测试

- 无 `NativeDisplay` 的浏览器路径保持现有 ASR 行为。
- 旧 APK/旧桥缺失分数字段时，服务器仍按 `speaker` 字段处理。
- `multiSpeaker=false`、`AUTO` 人数和 `1-5` 人数配置保持兼容。
- Android JVM 单测、Node 契约测试、正式 Debug APK 构建。

## 性能测试

- 快速模式代表 cluster 的一次 embedding 逻辑保留。
- 只有触发保护性合并时额外执行候选区间 embedding；普通分段不增加重复 ASR。
- 真机使用已有测试 WAV 验证完整链路和耗时字段无异常增长。

## 风险评估

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 阈值过低造成陌生人误匹配 | 中 | 默认 0.3 可调，结果保留 score，服务端继续按 speaker 门控 |
| 合并重新提取增加耗时 | 低 | 仅对短未知/相邻同名候选触发，保留 fast representative 路径 |
| 正式 APK 与测试 APK 结果字段不一致 | 中 | 共用同等数据结构，增加 Kotlin/Node 契约测试 |
| 旧配置迁移改变用户行为 | 低 | 只修改缺省回退值，不覆盖已保存阈值 |
