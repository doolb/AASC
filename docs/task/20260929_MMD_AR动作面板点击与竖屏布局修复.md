# 2026-09-29 MMD AR 测试页动作面板点击与竖屏布局修复

## 任务描述

修复 HTTPS MMD-AR 测试网页的“动作”按钮无法打开面板，以及竖屏下面板仍显示在按钮下方的问题。竖屏和横屏都应将灯光、动作/物理、定位面板停靠在按钮列左侧，顶部与按钮列对齐。外网部署不在本任务范围内。

## Design 需求

- 测试构建器替换为专用动作按钮和面板 ID 后，必须为它们绑定测试网页自己的开合事件。
- 动作面板恢复“动作”“物理”两个可折叠分类，分别容纳播放/进度控件与物理开关/参数。
- 开合时同步 `hidden` 与 `aria-expanded`；动作、灯光和定位面板互斥；点击面板内部不关闭，点击外部或 Escape 关闭。
- 横屏与竖屏统一采用按钮列左侧、第一按钮顶部对齐的布局。
- 常规视口下横竖屏的面板宽度保持 320px；只有空间不足以避开按钮列、间距和安全区时才收缩。最大高度按可视高度和上下安全区计算，内容留在面板内滚动。
- 动作面板打开时立即显示 VMD 当前进度和当前/总时长，并每 250ms 更新；暂停时显示停留位置，关闭面板时停止轮询。
- 原有面板内容、透明度共用设置、控件 ID 和本地存储语义保持不变。

## 自测用例

1. 通过真实浏览器点击动作按钮，动作面板打开；再次点击关闭，`aria-expanded` 与 `hidden` 保持一致。
2. 动作、灯光、定位面板切换时始终只有一个可见；面板内点击不关闭，点击外部和 Escape 关闭。
3. 在常规竖屏和横屏视口下，三个面板顶部与按钮列首按钮对齐，面板右边位于按钮列左侧且宽度保持 320px；在窄屏下按可用空间收缩。
4. 模拟有效 VMD 时打开动作面板，进度条与时间显示随运行时间更新；暂停时保留当前时间，关闭后不继续轮询。
5. 面板分类、透明度滑条、本地设置和定位/灯光交互继续可用。
6. `npm run build:web:mmd-ar-test` 成功；MMD AR 面板浏览器回归、JS 语法与 `git diff --check` 通过。

- 检查 pointer/click 事件、面板内滚动与动作按钮无障碍状态。

## 性能测试

- 布局只在窗口、visualViewport 或舞台尺寸变化时通过 requestAnimationFrame 合并计算。
- 点击处理限于三个测试网页面板按钮，不增加每帧工作。

## 风险评估

- 页面端通过不同 ID 重建控件，若事件依赖正式端控件 ID，按钮会无反馈。
- 竖屏可用宽度较小时，面板需优先受左右安全区约束，避免覆盖按钮列或溢出屏幕。
- Chromium 对 `color-mix()` 的 computed style 序列化格式不同，回归测试不应依赖某一种文本格式。
