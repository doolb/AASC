# APK 支持 Android 10 及 11 以上共享存储访问

## 任务描述

扩展 APK 内置 Node.js 子服务器的共享存储能力：Android 10/API 29 及以上通过 SAF 选择并持久化一个目录，由原生网关把该目录映射为 Node 媒体库虚拟根 `/`，继续支持列出、读取、Range 播放、上传、建目录和删除。

## Design 需求

- Android 9/API 28 保持旧版读写权限和 Node `fs` 直接访问共享存储。
- Android 10/API 29 及以上通过 `ACTION_OPEN_DOCUMENT_TREE` 选择目录，持久化读写 URI 授权。
- 不声明或申请 `MANAGE_EXTERNAL_STORAGE`，不把 `content://` URI 直接交给 Node `fs`。
- 原生 SAF 网关仅监听 `127.0.0.1` 并使用随机令牌，Node `AndroidSafProvider` 访问虚拟根 `/`。
- 未选择目录、授权失效或操作失败时不阻塞 WebView、Node 服务或主服务器连接；媒体库返回明确错误。
- 保留现有媒体库 API、Range 播放、路径越界和只读保护。

## Spec 设计

- `SharedStorageAccess` 根据 API 版本区分 API 28 旧权限和 API 29+ SAF tree URI 需求。
- MainActivity 在 API 23..28 使用运行时权限，在 API 29+ 使用文件夹选择器并持久化 URI。
- NodeServerService 启动 `SafMediaServer`，把地址/token 注入 Node 环境。
- Node 新增 `AndroidSafProvider`，将原生目录映射为虚拟 `/`。

## 受影响的功能模块和代码

- Android：`SharedStorageAccess.kt`、`MainActivity.kt`、新增 `SafMediaPath.kt`/`SafMediaServer.kt`、`NodeServerService.kt`、Android 单测和 `documentfile` 依赖。
- Node：`media-library-app-service.js`、`server-app.js`、媒体库契约测试。
- 文档：Android display/embedded-node 的 design/spec、`docs/todo.md`、`changelog.md`。

## 自测用例

1. API 28 返回 READ/WRITE_EXTERNAL_STORAGE；API 29+ 不返回旧版权限。
2. API 29+ 无持久化 URI 时打开 ACTION_OPEN_DOCUMENT_TREE，取消后继续 APK 启动。
3. API 29+ 选择目录后 URI 授权可持久化，Node 媒体库根路径固定为 `/`。
4. SAF 媒体库可列目录、读取元数据、Range 读取、上传、创建目录、删除文件和删除目录。
5. 未选择目录、撤销 URI 或系统拒绝时显示端、Node 服务和主服务器连接不被阻塞，媒体库返回错误。
6. Android 11+ 受保护目录不能被错误宣称为可访问。
7. Node 和原生网关均拒绝 `..`、绝对路径和虚拟根之外的路径。

## 兼容性测试

- Android 9/API 28：旧版读写权限、Node `fs` 和媒体库回归。
- Android 10/API 29：SAF 目录选择、持久化授权和原生网关回归。
- Android 11/API 30 及以上：SAF 目录限制、撤销授权和媒体库回归。
- Node JVM/Android JVM：协议、路径校验和 provider 操作契约测试。

## 性能测试

- 启动时只检查 URI/权限状态，不扫描共享存储。
- 目录按需列出，不递归扫描；文件读取和上传按块流式传输，不使用 Base64 和整文件缓存。
- 视频 Range 请求只打开所需的原生流区间；不把媒体文件复制到主服务器或 APK 私有目录。

## 风险评估

- SAF 性能受 DocumentsProvider 实现影响，大目录和高频随机拖动可能比 Node `fs` 慢；使用懒加载、Range 和流式传输控制开销。
- Android 11+ 仍不能选择内部存储根目录、Download 根目录、`Android/data` 和 `Android/obb` 等受保护位置。
- 部分厂商文件选择器可能不返回可持久化授权，需在真机上验证并明确提示用户重新选择。
- Node 子进程不能直接读取 `content://` URI，原生网关与 token 注入是必要依赖。
