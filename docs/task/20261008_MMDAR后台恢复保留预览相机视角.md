# MMD-AR后台恢复保留预览相机视角

日期：2026-10-08。状态：代码、定向回归与Web构建完成；真实浏览器/GPU画面待设备复验。用户在本地最新web-dist、联动阴影已勾选、普通预览且AR未启动时复现；切回前台后要求保留相机位置/角度和画面布局，不自动居中。

## 任务描述与根因

舞台构建通过`window.resize`、`visualViewport.resize`和`ResizeObserver`调用`DisplayMmd.resize`。共享`display-pmx-runtime.js`的`resize()`设置camera.aspect后，在AR未激活时无条件调用`fitCameraToModel(currentRotationPivot || currentMesh)`。该取景函数将cameraTarget重设为模型包围盒中心、cameraDistance重设为自动适配值、cameraZoomFactor重置为1，因此浏览器后台恢复产生resize时，画面会重新将角色居中。

`fitCameraToModel`本身只修改相机，不写角色根节点的位置/旋转/缩放。用户观察到的画面位置变化由相机重置即可解释；回归测试应确保resize路径也不改角色根变换。如果独立获取到根节点世界变换确有变化，则记录为另一条待查路径，不要通过伪装相机重置来掩盖。

## Design需求

- 仅对独立MMD-AR测试页的生成运行时注入`resize`修正，不改正式display运行时。
- 视窗变化时仍更新renderer尺寸、`camera.aspect`与projection matrix；不执行`fitCameraToModel`，不重置camera position/quaternion、cameraTarget、cameraDistance、cameraZoomFactor，也不改角色根position/quaternion/scale。
- 首次加载/替换模型继续沿用既有显式`fitCameraToModel`，保留初始自动取景。
- 浏览器恢复导致尺寸/DPR变化后，视角和角色屏幕位置继续保持；FOV为垂直FOV，aspect更新负责适配横向视场。
- 阴影联动计算继续锚定CSM相机切片；resize确实改变aspect时切片按新投影更新，但不令模型根或视角重居中。
- 参考用户提供的[Stable CSM文章](https://chillstepp.github.io/2024/07/19/%E9%98%B4%E5%BD%B1%E6%8A%80%E6%9C%AF(2)%E2%80%94%E2%80%94CSM/)：固定切片球半径避免主相机转向时投影范围变化，方向光空间用固定朝向正交包围盒，平移仅通过整ShadowMap texel吸附稳定。当前每盏灯为单切片/单ShadowMap，不扩成多级级联与级间混合。
- 修正阴影控件过时说明，不再称联动模式“按可见区域+0.5”。

## 自测用例

1. 运行时注入输出的`resize`仍设置aspect、调用`camera.updateProjectionMatrix()`，但没有`fitCameraToModel`。
2. 模型加载/替换路径仍明确调用`fitCameraToModel`，初始自动取景不退化。
3. resize函数不写相机位置、角度、cameraTarget/distance/zoom，也不写当前角色根position/rotation/scale。
4. ShadowMap联动开启时，aspect变化可使CSM切片按新主相机投影更新；根变换和相机取景不因后台恢复被重置。
5. 更新阴影面板提示，旧“可见区域+0.5”文字消失，改为CSM切片和无额外0.5。
6. `node --test tests/mmd-ar-camera-motion.test.js tests/mmd-ar-shadow-map-size.test.js`通过；CSM转向时切片球半径与投影宽高保持，texel snapping仍通过；`npm run build:web:mmd-ar-test`成功并检查生成运行时。

## 兼容、性能与风险

- 仅测试页构建注入；共享正式runtime源码与APK不变。
- resize时只更新渲染尺寸/投影，无额外模型遍历或包围盒计算；比原来减少一次自动拟合。
- aspect变化可能改变横向覆盖，这是透视相机正常行为；垂直FOV及相机空间姿态保持。
- 显式“模型初次加载/替换”和手动清理相机VMD仍可调用自动取景，不改变其原有体验。
- 当前环境无配置Chromium，自动化真实GPU画面验收可能跳过，构建和代码注入测试不能替代手机手动前后台验收。
