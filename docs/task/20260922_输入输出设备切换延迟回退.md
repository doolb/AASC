# 输入输出设备切换延迟回退

## 任务描述

修复正式 Android 显示端切换录音设备和声音输出设备时回退过快的问题。设备刚连接、蓝牙 SCO 尚未完成建立或 Android 音频设备列表尚未刷新时，控制器应短暂等待并重新枚举目标设备，重试耗尽后再回退系统默认。同步修复设备 key 使用临时 Android device id 导致重连后无法命中的问题，并兼容历史已保存 key。

## design 需求

- 输入、输出共用 300ms、700ms、1200ms 递增等待重试策略。
- 重试时重新获取 `AudioDeviceInfo`，不复用失效设备句柄。
- 所有重试失败后才启动系统默认路由；状态保留请求 key 并报告回退原因。
- 有地址或产品名的设备生成稳定 key；旧 key 以 `legacyKey` 透传并可被解析。
- API 26–30 的 A2DP/有线输出精确路由限制保持显式 `system_default`，不伪造实际路由。

## spec 设计

- 修改 `AudioInputDevice`、`AudioOutputDevice` 的 stable/legacy key 生成与匹配。
- 修改 `NativeAudioCaptureController.start` 和 `NativeAudioOutputController.apply`，增加枚举、路由、启动失败的递增重试。
- 修改服务端设备规范化和控制端历史 key 匹配，确保旧配置在新列表中仍能选中并迁移到当前 key。
- 更新音频静态契约测试，覆盖延迟重试、stable key、legacyKey 传输和控制端兼容匹配。

## 自测用例

- 目标设备暂未枚举时，输入和输出均按 300/700/1200ms 重新枚举后再决定回退。
- SCO 建立失败时不会立即切到系统默认，重试耗尽后才回退并回报原因。
- 路由成功时 `fallback=false`，失败时 `fallback=true` 且 `requestedDeviceKey` 不丢失。
- 旧版 `native-output:{type}:{name}:id-{id}` 和 `native:{type}:{name}:id-{id}` 能命中当前稳定设备。
- 控制端命中 `legacyKey` 后使用当前 `key`，完全不匹配才显示 default。

## 兼容性测试

- Android API 28：内置麦克风、蓝牙 SCO、系统默认输出。
- Android API 31+：`setCommunicationDevice` 成功与失败回退。
- 浏览器显示端和旧 APK：没有 `legacyKey` 时继续按原有 key 工作。
- 服务端断线重连：保存的旧 key 和当前 stable key 都可恢复。

## 性能测试

- 设备已存在且第一次成功时不产生等待。
- 设备暂不可用时额外阻塞不超过 2.2 秒（不含单次 SCO 自身连接超时）。
- 不创建常驻线程，不增加 PCM 采集线程数量，不改变已启动录音的数据格式。

## 风险评估

- Android API 26–30 仍不能精确指定普通 A2DP/有线媒体输出，只能通过系统默认媒体路由；状态必须继续对控制端透明。
- 同类型、同名称且没有地址的多个设备无法生成真正稳定且可区分的 key，只能使用系统枚举信息和最后的 id 兜底。
- 同步等待会延长一次切换调用时间，但仅在目标设备不可用或路由失败时发生，最多增加 2.2 秒。
