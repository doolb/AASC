# 提醒统一 TTS 路由修复

## 任务描述

修复控制端测试单条提醒接口在 `tts.device=display` 且服务器 TTS 关闭时仍直接访问
`127.0.0.1:3001` 的问题，让普通提醒触发和单条提醒测试统一使用显示端优先、服务端回退的 TTS 路由。

## design 需求

- 提醒模块接收服务端注入的统一 TTS 生成函数。
- 触发提醒和测试提醒均不得直接调用底层 `tts.generateTTS`。
- 显示端 TTS 失败或不可用时，继续由统一路由决定是否回退服务器 TTS。

## spec 设计

```text
服务端启动:
    reminder.init({ generateTTS: generateTtsWithFallback })

提醒需要语音:
    fullContent → reminder.generateTTS(fullContent)
    生成音频 → 发送到目标显示端
```

- 提醒模块不直接调用底层 TTS 服务。
- 服务器入口向提醒模块注入 `generateTtsWithFallback`。
- 运行提醒相关测试和完整测试。

## 兼容性测试

- `tts.device=display` 且显示端在线：使用显示端 TTS。
- 显示端离线或生成失败：由统一路由回退服务端 TTS。
- `tts.device=server`：使用服务端 TTS。
- 弹窗提醒不受影响。

## 风险评估

- 注入依赖改变提醒模块初始化契约；保留底层实现作为兼容默认值。
- 当前 Termux 子服务器离线不在本任务修复范围内。
