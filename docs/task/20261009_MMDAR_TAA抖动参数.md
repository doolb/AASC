日期：2026-10-09。状态：用户确认的两项抖动参数已实现并验证；运动向量继续暂缓。

用户指定[《深入浅出Temporal Antialising》](https://zhuanlan.zhihu.com/p/142922246)，随后两次明确“暂不处理运动向量”，并要求“TAA可不可以开放抖动参数”。浏览器成功读取正文；本轮围绕已有Halton抖动做小范围扩展，运动向量及其他历史滤波优化留待后续。使用brainstorming的bounded路径，结合项目要求先写对应文档，用户回复“是”后开始实施。方案确认依据是用户提供的项目规则“修改代码前必须先将改动方案告知用户……等待用户确认后才能开始写代码”。

## Design需求

- 抗锯齿分类新增抖动强度0–2/步长0.05/默认1与周期4/8/16/32帧/默认8。
- 强度1、周期8保持现有八相位；0仅取消空间偏移，不关闭历史混合。
- 周期代表不同帧的采样位置序列，每帧仍一次场景绘制。
- 参数本地保存、刷新恢复，旧存储补默认，复位恢复1/8；不支持WebGL2时控件禁用。
- 改值清TAA/SSGI历史并重启相位，实际像素和Canvas倍率一致，保留相机/角色状态。
- 本轮不增加运动向量、骨骼/morph缓存、颜色裁剪优化、Catmull–Rom或额外画质模式。

```text
输入 -> 数值规范化 -> 默认/夹取/离散集合校验 -> 发布与保存权威本地值
历史签名 := 既有签名加有效强度/周期；变化 -> 清历史，相位0
样本 := Halton序列[相位对周期取余]乘强度

输出成功 -> 提交历史并推进相位；finally -> 恢复原投影/逆投影/临时相位/目标
后台/尺寸/模型/动作跳转 -> 沿用当前失效；PNG/诊断 -> 沿用当前旁路
```

## 自测、兼容性与性能

- 单位：默认八相位与当前值一致，4/8/16/32全部循环；强度0无偏移、1兼容、2为双倍；非法周期/NaN/无字段回默认。仅改变抖动参数时历史首帧拒绝。
- 相机：透视/正交/AR view offset与奇数/高DPR尺寸，绘制及异常后原矩阵恢复；不移动相机或角色。
- GPU：静态轮廓、透明alpha、颜色拒绝、RGBA8回退保持；实际米娅与静态GLB可见。
- 界面：范围/选择实际生效，保存/刷新/复位，旧值迁移，WebGL2不支持的选择控件禁用，320px面板容纳。
- 联动：接触相位遵从TAA有效周期，SSGI基础投影不被逐帧抖动错误切断；改值/后台正确清历史。
- 性能：记录同条件周期8/32的提交次数与GPU完成耗时；不增加目标数和每帧场景绘制次数，不把桌面软件GPU读数当手机性能。

## 风险与未明确项

- 用户已确认强度0–2与周期4/8/16/32。大幅度可能使画面更软；长周期不保证更好，仍需与累积强度配合。
- 无模型运动向量的动态残影边界继续存在，本轮不声称解决。
- 默认序列数值必须与旧八相位一致，避免默认画质/取景变化；参数签名与临时相位不一致会污染历史，应由回归验证。
- 预计2–3小时，含真实浏览器/GPU和文档；设备性能与系统后台验证另列。
