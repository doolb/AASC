# ASR 内存上传与 VAD 静音时间统一

## 任务描述

取消 `/api/asr/recognize` 的 ASR 临时文件，改为内存 Buffer 传递；统一网页显示端和 `voice-display-node` 的 VAD 阈值配置链路，并将结束语音段所需的静音时间设置为 500ms。

## Design 需求

- 设计文档：`docs/design/asr-memory-upload-vad-unification.md`
- ASR HTTP 上传使用内存 Buffer，标准 WAV 和非 WAV 均不生成 ASR 临时文件。
- 内嵌 ASR、独立 ASR 进程和显示端 ASR 转发均支持 Buffer 输入。
- `vadThreshold` 继续按显示端保存，默认 `0.01`，范围 `0.001..0.2`。
- 新增 `vadSilenceDurationMs`，统一默认 `500ms`；保留最短语音长度 `300ms`。
- 普通 ASR 录音和播放期间的语音检测复用同一组 VAD 参数；既有播放兼容模式保留，避免影响已部署 Node 子显示端。

## Spec 设计

- 实现伪代码：`docs/spec/asr-memory-upload-vad-unification.md`
- 服务器发送完整 `voiceVadConfig`：阈值、静音时间、最短语音时间。
- 网页显示端和 Node 子显示端都动态应用配置。
- 旧客户端忽略新增字段时仍使用已有默认值。

## 自测用例

1. ASR HTTP 上传不生成临时文件，服务器识别直接接收 Buffer。
2. 显示端 ASR 转发直接将 Buffer 转 Base64。
3. 内嵌和独立 ASR 进程都能识别 WAV Buffer。
4. 非 WAV Buffer 通过 ffmpeg 管道转换，不生成转换文件。
5. 网页端收到配置后使用 500ms 静音结束时间。
6. Node 子显示端收到配置后使用 500ms 静音结束时间。
7. VAD 阈值仍按显示端持久化并同步，非法值回退/裁剪规则不变。
8. 声纹注册临时文件仍按原链路清理。

## 兼容性测试

- 旧显示端仅上传 `audio` 时仍可识别。
- 旧 WebSocket `voiceInput` 链路不改变。
- `asr.device=server/display` 两条路径均兼容。
- ASR 内嵌和独立进程模式均兼容。
- Node 子显示端 PvRecorder 和 naudiodon 两种录音器均使用相同 VAD 参数。

## 性能测试

- 44.1KB 短 WAV 不落盘，减少一次文件写入、读取和删除。
- 内存 Buffer 在请求结束后不再被引用；ASR samples 仍按既有 finally 释放。
- 超过 10MB 的 ASR 上传直接返回 413，避免内存无限增长。
- VAD 分段仍复用单条采集链路，不创建额外录音器。

## 风险评估

- 内存上传增加单请求堆内存占用，使用 10MB 上传上限缓解。
- 独立进程 IPC 传 Buffer 会有一次序列化开销，但避免磁盘 I/O；超大音频被拒绝。
- 非 WAV 转换依赖 ffmpeg 标准输入/输出，ffmpeg 不可用时返回明确错误。
- 静音时间从网页 1000ms、Node 300ms 改为 500ms，可能改变分句边界，需要用现场麦克风复核。
