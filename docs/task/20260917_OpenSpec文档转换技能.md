# OpenSpec 文档转换技能任务

## 任务描述

新增一个项目内 AI 技能，将 OpenSpec 的 `proposal.md`、`design.md`、可选的 `specs/**/*.md` 和 `tasks.md` 转换为 AASC 项目的 `docs/design/<模块>.md` 与 `docs/spec/<模块>.md` 格式。

## Design 需求

- 设计文档承接 proposal 的 why/what 与 design 的 how。
- 实现文档承接真实文件映射、接口契约、中文伪代码、测试和实施状态。
- 必须检查当前仓库，不能从相似模块或 OpenSpec 路径凭空推断代码落点。
- 缺少 specs、存在虚假路径或任务未完成时，必须明确记录风险和状态。

## Spec 设计

- 技能入口读取项目规则、OpenSpec 输入和目标模块现状。
- 任务编号逐项映射到 spec 的实现章节、伪代码和回归契约。
- 伪代码不包含可运行 JavaScript；复杂分支使用状态/规则表达。
- 生成后同步 design/spec 索引、task、todo 和 changelog。

## 受影响的功能模块和文件

- `.agents/skills/openspec-to-aasc-docs/SKILL.md`：新增技能。
- `docs/design/openspec-to-aasc-docs.md`：新增设计文档。
- `docs/spec/openspec-to-aasc-docs.md`：新增实现伪代码文档。
- `docs/design.md`、`docs/spec.md`：新增索引项。
- `docs/todo.md`、`changelog.md`：同步任务台账和变更记录。

## 自测用例

1. 完整输入：包含 proposal、design、specs 和 tasks，检查四类内容均被映射。
2. 缺少 specs：检查仍能生成两个目标文档，并记录行为场景缺失风险。
3. 相似模块：输入任务路径指向不存在模块时，检查技能要求搜索真实代码并请求确认，不套用相似文档。
4. 未勾选任务：检查 spec 标记待实现/待验证，不写成已完成。
5. 伪代码检查：检查目标 spec 不含模块导入、类型声明和可运行 JavaScript。

## 兼容性测试

- 兼容项目既有 design/spec 文档的中文标题、表格、伪代码和相对链接风格。
- 兼容只提供 proposal、design、tasks 的 OpenSpec 变更目录。
- 兼容存在多个 capability 的 specs 目录，按 capability 保留行为边界。
- 不修改现有业务代码和工作区中与本任务无关的改动。

## 性能测试

- 使用 `rg --files` 和 `rg` 进行目标文档及真实代码定位，避免无目的扫描全部构建产物、日志和模型。
- 文档转换不引入运行时依赖、构建步骤或服务端请求。

## 风险评估

- OpenSpec 自定义 schema 可能改变字段名称；技能按语义读取，并在无法识别时保留原文和待确认项。
- 项目模块可能存在同名文档；写入前必须完成唯一模块识别。
- 源任务勾选状态不等于项目实现状态；必须以代码和测试证据为准。
- spec 可能在实现前生成；必须显式区分目标方案与当前已实现行为。

## 预计工时

1–2 小时，包括技能编写、项目文档同步、基线场景验证和静态检查。

## 完成结果

- ✅ 已新增技能及其 design/spec 文档。
- ✅ 已同步项目 design/spec 索引和 changelog。
- ✅ 本任务无新增未完成待办，不在 todo 中保留已完成条目。
