# Offline 发布过时资源自动清理

## 任务描述

当 Offline full APK、min APK、服务代码包或生产依赖包产生新版本时，发布器需要同时维护局域网和外网发布目录，删除不再使用的旧版本资源，避免发布目录持续膨胀。清理必须严格受限，不能误删日志、模型、配置、任务、results、非版本文件或符号链接。

## Design 需求

- 服务签名清单中的 `code`、`dependencies`、`apkMin` 相对路径是权威保留版本。
- 完整 Offline APK 不写入服务签名清单，使用 `apk/aasc-display-offline-v<versionCode>.apk` 的精确版本名；完整包发布时保留本次版本。
- 局域网 `/mnt/aasc-offline` 和外网 `~/a/aasc-offline` 分开执行相同清理规则。
- 只匹配 `code-v<数字>.zip`、`dependencies-v<数字>.zip`、`aasc-display-offline-min-v<数字>.apk`、`aasc-display-offline-v<数字>.apk`，只删除普通文件。
- 发布顺序必须是校验、上传、原子清单切换、验证、清理；清理失败为可重试错误，不回滚有效发布。

## Spec 设计（伪代码）

```text
publishOfflineUpdate(mode):
    verify signed manifest and selected artifacts
    publish selected versioned artifacts to LAN and WAN
    atomically replace manifest.json on each target
    verify manifest and component hashes
    cleanup exact stale code/dependencies/min artifacts

publishOfflineFullApk(apk, buildManifest):
    require allserver and not updateOnly
    publish apk/aasc-display-offline-v<versionCode>.apk to LAN and WAN
    verify file hash and HTTP HEAD content length
    cleanup exact stale full APK artifacts
```

## 受影响的功能模块和代码

- `scripts/ops/publish-offline-update.js`：服务/min 发布后的双站点清理、完整 APK 发布模式、CLI 参数和清理失败报告。
- `package.json`：新增 `publish:offline-apk:full` npm 入口。
- `tests/offline-update-publish.test.js`：普通文件、符号链接、非版本文件、清单保留项及 full APK 清理回归。
- `docs/design/android-offline-hot-update.md`：发布资源保留策略。
- `docs/spec/android-offline-hot-update.md`：清理及完整 APK 发布伪代码。
- `CLAUDE.md`、`AGENTS.md`：记录供 Claude/Codex/AI 复用的 Offline 打包、发布和清理规则。
- `docs/todo.md`、`changelog.md`：任务状态与结果。

## 自测用例

1. `all` 发布保留清单引用的 code/dependencies，并删除同目录旧数字版本。
2. `apk-min` 发布保留清单引用的 min APK，并删除旧 min APK。
3. full APK 发布上传到两个目标，保留当前 versionCode，删除旧 full APK。
4. 日志、模型、配置、任务、results、临时文件、普通文件和符号链接均保持不变。
5. 同名同 hash 发布幂等；同名不同 hash 拒绝覆盖。
6. 清理失败时 manifest 和已验证新包保持可用，返回可重试错误。

## 兼容性测试

- Node.js `node:test` 临时目录测试。
- 远端发布命令通过 `/bin/sh -c`，兼容 fish 登录 shell。
- LAN/WAN HTTP 目录均使用当前 manifest 和 versioned artifact 布局。
- 不改变 Android 端清单验签、服务更新和模型缓存逻辑。

## 性能测试

- 清理只扫描 `code`、`dependencies`、`apk` 三个一级目录的目录项，不读取模型内容。
- 新包 hash 校验仍按文件大小和 SHA-256 执行；full APK HTTP 验证使用 HEAD，避免再次下载近 1GB 文件。

## 风险评估

- 误删风险：通过固定目录、固定数字版本名、普通文件检查和符号链接跳过降低风险。
- 目标不一致：LAN/WAN 独立完成，任一目标失败不覆盖另一目标状态。
- 清理异常：清理为 best-effort，保留旧文件并记录错误，可重复发布/清理。
- 完整 APK 不在服务清单中：通过 build manifest 的 `allserver`、`updateOnly` 和 versionCode 校验避免误发布 min APK。
