# 独立 MMD-AR：FSR2斜边滤波方向修正

日期：2026-10-09。状态：方向估算、真实WebGL多角度回归与网页构建完成；Android WebView/手机实测仍待设备。

## 问题与目标

上一轮在FSR2全分辨率present中加入FXAA风格滤波。用户实际观察：水平和垂直边缘改善，对角边缘反而加重。用户已试过FSR2比例1.0，因此本任务不再提高默认比例或改变缩放比例设计；只修正FSR2滤波的方向估算，普通TAA保持不变。

## 设计与契约

依据：`docs/design/mmd-ar-test-apk.md`“FSR2斜边滤波方向修正”节；`docs/spec/mmd-ar-test-apk.md`“FSR2斜边方向估算修正”伪代码。

- 当前方向来自四角亮度差；其在部分45°斜边采样分布下可能互相抵消或方向偏离。
- 在FSR2最终present现有3×3邻域增加N/S/E/W luma，使用`gx=luma(E)-luma(W)`、`gy=luma(S)-luma(N)`估算法线，再旋转90°得到边缘切线；四角与中心继续用于contrast range/阈值。
- 保留已有沿切线双候选样本、局部亮度约束、方向跨度限幅与预乘RGBA处理；不增加target/历史/速度数据、不修改TAA。

## 受影响文件与顺序

3. 扩展`tests/mmd-ar-temporal-aa-browser.test.js`，加入水平/45°/垂直边缘及比例0.5/1.0对照。
4. 运行TAA与FSR2真实GLSL夹具、模式/模型/alpha/导出回归及`npm run build:web:mmd-ar-test`。
5. 完成后更新usage/README/self-test/changelog并从todo移除实现项；设备动态画面/帧时仍留作待验收。

## 自测与兼容性

- 每种角度分别在滤波开/关下运行相同jitter帧序列，记录部分覆盖像素、alpha RMS帧差、平坦中心颜色、GL错误。
- 对角边缘必须改善；水平/垂直结果相对上一版不得明显回退。
- 比例0.5与1.0都验证，证明效果不是靠升高内部比例。
- TAA fixture维持原颜色、alpha、背景揭露结果；PNG/透明通道、模型AO/接触/SSGI保持。

## 性能与风险

新增四个方向探针采样仅在FSR2全分辨率present运行，不增加显存目标但会略增纹理读取。方向估算与亚像素覆盖的静态夹具结果不能等同真实动画；阈值/方向错误可能再次软化或放大斜线锯齿，无运动矢量仍限制移动内容时间稳定性。SwiftShader不能代替手机实测。

预计实施1–3小时；不构建APK、不发布外网、不修改正式显示runtime。
