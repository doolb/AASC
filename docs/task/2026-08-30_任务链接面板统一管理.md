# 任务链接面板统一管理

## 任务描述

任务控制面板已有“链接到...”弹窗，但只能选择目标实例，不能查看当前来源实例已链接的显示端，也不能解除链接。本任务统一改造该现有弹窗，并让一个来源任务实例可以明确管理多个目标显示端。

## Design 需求

- 一个来源实例可链接多个 `render-display` 目标实例。
- 查询链接时过滤来源或目标已不存在的历史记录，并去重。
- 现有弹窗同时展示已链接目标和可新增目标。
- 已链接目标显示目标任务、实例、目标显示端和状态，并支持解除。

## Spec 设计

- `TaskManager.linkTasks()` 对相同来源/目标组合幂等。
- `TaskManager.getTaskLinks()` 返回规范化有效链接数组。
- `task:list:result.payload.links` 返回链接数组。
- TaskPanel 复用 `_linkInstance()` 管理查看、添加和解除，收到变更事件后刷新列表。

## 自测用例

- 同一来源重复链接同一目标不会产生重复记录。
- 查询结果包含多个有效目标，并包含目标 displayId 和状态。
- 来源或目标实例不存在时不返回失效链接。
- 弹窗读取 `payload.links`，展示已链接目标和新增目标。
- 点击解除发送 `task:unlink`，点击选择发送 `task:link`。
- 解除某一个目标时只携带该目标实例 ID，不影响同一来源的其他目标。
- 解除后仍运行的目标从已链接列表移到当前弹窗的添加目标列表；目标已停止时只移除，不加入候选。

## 兼容性测试

- 旧版没有 `links` 字段的 `task:list` 响应仍按空链接处理。
- 旧 `.task-links.json` 数组格式继续可读取。
- 现有 `task:link`、`task:unlink` 和任务链数据转发协议保持兼容。

## 性能测试

- 链接查询仅在任务列表刷新时读取任务索引，不参与高频 progress 转发。
- 面板候选目标按实例 ID 去重，避免重复 DOM 节点。

## 风险评估

- 历史链接可能指向已清理实例，因此查询层必须过滤，不能让面板操作失效目标。
- 解除请求缺少目标实例 ID 时由服务端拒绝，避免误触发来源级别的全部解除。
- 控制端旧版本不读取 `links` 字段时不影响任务执行。
