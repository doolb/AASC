# 任务：任务 widget 刷新日志降噪

## 任务描述

运行中任务面板会周期性发送 `widgetRefresh`，服务端同时打印控制端收发和 `task:widget_update` 广播日志，导致日志重复刷屏。保持消息和任务刷新行为不变，仅静默高频刷新日志。

## Design 需求

- `widgetRefresh` 收发过程不输出普通 `[WS]` 操作日志。
- `task:widget_update` 高频广播不输出普通 `[WS]` 操作日志。
- `updateConfig` 等人工 widget 操作、任务错误和其他业务日志继续保留。

## Spec 设计

```text
收到 task:widget_action:
    如果 payload.action == 'widgetRefresh':
        执行任务刷新，不写普通 WS 日志
    否则:
        按既有流程写操作日志并执行

广播 task:widget_update:
    正常发送给控制端
    不写普通 WS 日志
```

## 自测用例

1. 运行中任务连续刷新时不出现 `task:widget_action` 的 `widgetRefresh` 日志。
2. 运行中任务连续推送 `task:widget_update` 时不出现普通 WS 广播日志。
3. `updateConfig` 等人工操作仍有收发日志。
4. widget 数据仍正常推送到控制端。

## 兼容性测试

- Chat2API 服务 widget 刷新和账户管理按钮。

## 性能测试

- 高频刷新不再构造和写入对应普通 WS 日志，消息发送频率和任务处理开销保持不变。

## 风险评估

- 仅改变日志输出，不改变 WebSocket 协议、任务状态和 widget 数据。
- 若需要诊断刷新链路，可通过控制端数据或任务专用日志定位。
