# APK 子服务器媒体就绪后的正常流程重播

## 任务描述

修复 APK 显示端在子服务器媒体播放开始时，WebView 已恢复但 APK 内置 Node.js 子服务器尚未完成 AASC 注册，导致媒体直连地址暂时不可用的问题。主服务器在子服务器注册完成或注册地址变化后，主动重新发送原有正常播放消息；显示端不增加节点状态和重播协议处理。

## Design 需求

- 子服务器注册成功后，主服务器检查所有在线显示端当前播放状态。
- 子服务器心跳上报的 `node.url` 变化时，主服务器重新处理该节点的播放状态，以适配 IP 变化。
- 单媒体沿用 `url`/`base64` 消息，播放列表沿用 `playlistStart` 消息，并保留已有播放进度和循环状态。
- 只重播来源属于当前节点的媒体，不影响其他子服务器和主服务器媒体。
- 主服务器按最新节点地址重写直连 URL，保留同源远程代理 URL。
- 兼容旧状态：没有来源字段时，使用主服务器代理路径或旧/新节点 URL 识别媒体来源。
- 显示端继续连接主服务器，`display.html` 不需要修改。

## Spec 设计

```text
控制端发送远程媒体
    → 在单媒体和播放列表项中写入 sourceNodeId/sourceLibraryId/sourcePath
    → 同时保留 directUrl 和主服务器 proxyUrl

主服务器收到 node.register
    → 保存旧节点地址
    → 更新节点注册信息
    → 遍历 displayClients 的 currentMedia/currentPlaylist
    → 选出属于当前 nodeId 的播放状态
    → 按最新 node.url 重写直连地址
    → 使用既有 url/base64/playlistStart 消息发送

主服务器收到 node.heartbeat
    → 更新节点 heartbeat 和 url
    → 仅当 url 变化时执行上述重播

显示端收到消息
    → 继续使用已有 showMedia/handlePlaylistStart 流程
    → 不识别节点就绪事件，不处理新消息类型
```

## 受影响的功能模块和代码

- `src/framework/aasc/media-replay.js`：新增纯函数，识别来源、重写节点地址并生成正常播放消息。
- `src/framework/aasc/node-connector.js`：注册和每次心跳上报最新可访问地址。
- `src/apps/server/boot/server-app.js`：保存来源元数据；在节点注册或地址变化时遍历显示端并重发普通媒体消息。
- `src/apps/web-mediacenter/ui/public/js/media-library.js`：控制端播放消息增加来源节点元数据。
- `tests/aasc-media-playback-replay.test.js`：新增单媒体、播放列表、旧代理地址和节点隔离测试。
- `tests/aasc-node-connector.test.js`：验证注册与心跳上报动态地址。
- `tests/aasc-server-registry.test.js`：验证主服务器重播接入契约。
- `docs/design/*.md`、`docs/spec/*.md`：同步设计和伪代码。

## 自测用例

1. APK 节点尚未注册时，显示端已有该节点媒体播放状态；节点注册后收到原有 `url` 或 `playlistStart` 消息。
2. 节点心跳地址从旧 IP 变为新 IP 后，正在播放该节点媒体的所有显示端收到新地址；代理 URL 保持不变。
3. 正在播放其他节点媒体的显示端不收到本次重播。
4. 播放列表的当前索引、播放时间、播放状态、循环配置和每项来源信息保持正确。
5. 旧版没有来源字段但使用主服务器代理路径的播放状态仍能识别并重播。
6. 显示端不需要新增 `mediaReplay` 消息处理。

## 兼容性测试

- Node.js 现有 CommonJS 服务代码和当前运行版本兼容。
- 保持 `url`、`base64`、`playlistStart` 消息结构，旧显示端可按原流程处理。
- 保留主服务器代理地址，直连不可用时仍可回退。
- 显示端固定连接主服务器的架构不变。

## 性能测试

- 重播仅遍历内存中的显示端状态，不主动扫描子服务器文件，也不发起额外 HTTP 探测。
- 无匹配播放状态时不发送消息；匹配后每个显示端每次节点事件最多发送一条正常媒体消息。
- 定向测试覆盖 3 个测试文件，避免引入全量测试中的既有不相关失败。

## 风险评估

- 节点注册事件可能在已有媒体播放状态下触发一次重复播放，这是为保证子服务器就绪后的恢复而设计的行为。
- 旧状态缺少来源元数据时只能依赖代理路径或 URL origin 推断；新播放会写入来源标识，后续识别更稳定。
- 子服务器地址配置为固定 `aasc.advertisedUrl` 时，心跳仍遵守该显式配置，不会擅自改写为本机地址。
