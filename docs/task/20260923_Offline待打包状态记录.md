# Offline 待打包状态记录

## 任务描述

使用同一个受 Git 管理的状态文件，记录当前是否还需要生成 Offline min APK、服务代码包和生产依赖包。代码修改后把受影响的状态设为 `true` 并上传；出包机成功生成对应产物后改回 `false` 并上传。

## Design 需求

- 单一状态文件为 `release/offline-release-status.json`，三个字段缺省状态均为 `false`。
- 服务端/网页热更新代码影响 `servicePackage`；Android 原生或 min APK 内资源影响 `minApk`；生产依赖集合变化影响 `dependenciesPackage`。
- 只更新实际受影响的字段；“待打包”与“已经打包/发布”语义分开。
- 打包只在持有离线签名密钥的出包机执行。失败或产物不包含最新代码时，状态保留为 `true`。

## Spec 设计

- 代码修改后按文件范围识别产物，把对应 JSON 字段设为 `true`，随代码变更上传 Git。
- 出包机读取状态并生成对应产物；成功后把对应字段设回 `false` 并上传 Git。
- 依赖未变化时不要求重建依赖包；Android 原生代码未变化时不要求 min APK。

## 受影响的功能模块和代码

- `release/offline-release-status.json`
- `AGENTS.md`、`docs/rules.md`
- `docs/design/android-offline-hot-update.md`、`docs/spec/android-offline-hot-update.md`
- 本任务及本次声纹 TTS 输入任务文档

## 自测用例

1. 状态文件包含三个布尔字段，未受影响字段保持 `false`。
2. 服务端/网页代码变化只把 `servicePackage` 设为 `true`。
3. Android 原生/min APK 资源变化把 `minApk` 设为 `true`。
4. 生产依赖变化把 `dependenciesPackage` 设为 `true`。
5. 出包机成功生成对应产物后，只将对应字段改为 `false`；失败时不清除待打包状态。

## 风险评估

- 状态误设为 `false` 会漏包；因此必须在出包机确认产物包含最新代码后再清除状态。
- 当前工作机没有签名密钥，不执行 APK/发布包构建。

## 兼容性测试

- 现有更新器仍按签名 manifest 和组件版本工作；该状态文件只跟踪待构建项，不改变运行时更新协议。
- 未修改的依赖版本继续沿用当前发布值。

## 性能测试

- 状态文件仅在代码变更和成功出包时读写，不进入运行时服务请求路径。

## 预计工时

- 约 15 分钟，含规则、状态文件和相关任务文档更新。

## 执行结果

- 本次声纹开关的实时产物状态只记录在 `release/offline-release-status.json`，不在任务文档重复维护状态值。
- 本轮未构建发布包；对应产物由持有签名密钥的出包机生成后再清除状态。
