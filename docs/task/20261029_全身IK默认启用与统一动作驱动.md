# 全身IK默认启用与统一动作驱动

## 授权、目标与需求分析

用户确认推荐方案：正式显示端默认启用全身IK，新增动作由SubAI直接规划IK目标，预设与旧MPL/VMD转换后统一求解；表情/口型保留Morph，旧库保留。此前默认启用会被误当作手动接管，因此必须拆分引擎状态与活动手动目标。

主L6、次L5/L7，邻层混合，建议下放L4，直接开发风险中，置信度0.90。证据为默认启用、全部身体动作走IK、新生成格式已确认三项强证据。评分24/25、20/20、19/20、19/20、14/15，总96/100，结论可开发。已有声明为Human/IK/mixer/动作生成和候选库；新增定义为求解器/接管状态、有界目标轨迹与格式标记；流程为模型就绪→默认引擎→动作转目标→约束求解→完成/保存或取消。

## 实现文件与行为

- 新增 `mmd-ik-plan.mjs`：生成、存储、端侧共用格式；format=ik-targets/version=1，0.2～15秒，2～48帧，目标通道一致，首尾归零；模型局部位移按身高归一，每轴<=0.5，旋转每轴<=90度，smoothstep峰值速度受限，源码<=16KiB，真实部位/Morph校验。
- 新增 `mmd-human-ik-targets.mjs`：旧动画语义身体姿态转世界目标，新IK通道叠加；末端目标释放上游肩肘/髋膝硬牵引，保留其他明确目标。沿用现有physics关节/碰撞/力矩和骨长保护。
- `mmd-human-interface.mjs`、`mmd-human-ik.mjs`、`mmd-human-mixer.mjs`、`mmd-human-model.mjs`：默认异步初始化，换模型/隐藏/退出隔离迟到结果；无手动目标时自动动作可用，On/Hold/Comply接管，Off/重置恢复；引擎关闭/失败保持最后身体姿态，Morph继续；IK轨道不直接写骨骼，外部TTS时钟、零强度、停止按统一混合器处理。
- `mmd-human-ik-ui.mjs`：默认后台求解不显示彩色控制点，打开IK面板进入编辑后才显示；收起面板保留原拖点行为，停止拖动不会销毁引擎。
- `motion-model-service.js`、`motion-coordinator.js`、`mmd-chat-actions.mjs`：新模型只输出IK目标JSON，CSV及独立模型设置不变；上报真实ikTargets；20秒准备/一次修复/取消保留。真实可见舞台低FPS复现旧固定回执余量误取消，播放回执调整为最少30秒、时长×10+10秒、最多1小时，不改变准备预算或主动停止语义。
- `mmd-human-storage.mjs`、`mmd-human-ui.mjs`：source保存规范化JSON并标记format；旧schema1/2、MPL与VMD版本继续读取；候选预览/采用保留IK参数，旧MPL候选不重复缩放参数；不批量迁移或改默认版本。
- npm现有 `test:mmd-production:ik` 增加目标/真实物理测试并串行运行；修改既有SubAI和真实PMX浏览器用例，补实际手腕移动、舞台可见与候选格式验证。

## 自测、兼容、性能与边界

基础回归：MMD生产227通过/1既有跳过。新目标/生命周期7/7；IK界面8/8；SubAI完整专项串行18/18（单元16及浏览器2）通过。真实PMX/Worker/Ammo：默认引擎不屏蔽自动动作、旧MPL零生成、新目标实际抬手（关闭基础动画及生理/注视以隔离）、完整完成后保存、采用才切版本、真实鼠标拖点/手动优先/重置和关闭。补真实舞台显隐后发现并修复播放确认超时，非只验证离屏骨架。已查看最终截图 `/tmp/aasc-unified-ik-final.png`，角色可见且默认编辑点隐藏。

本机Node真实PMX在30/60fps步长下多轮求解均为有限姿态，手腕实际抬高超过2厘米，释放后回归；781项自有原生分配在采样期间固定，dispose归零。单独一轮平均11.41/3.63ms（另一轮12.15/3.80ms），与软件浏览器并行时17.26/6.36ms，包含预热及负载差异，不能作为Android实时帧率承诺。Chromium软件渲染可见舞台约1fps，回执预算需容纳其慢时间轴；两个真实浏览器并行时曾使30秒测试等待超时，最终串行复验，不能把争用失败忽略为通过。测试降低画布倍率，仍保留真实角色和物理，不以低分辨率截图评价细节美观。

目标覆盖头/胸/骨盆/手/肘/膝/脚，不新增指趾独立控制点；动态服饰仍是原PMX物理。旧动作受限位/碰撞影响可能改变观感，复杂姿态和其他PMX需用户实际预览。未联调真实Provider、未发送聊天到当前用户会话、未操作手机。独立3rd实验页保持原行为。
