# 游戏规则按当前棋局注入

## 任务描述

把五子棋专属规则从冗长 GM 回执压缩为单一规则定义；查询时只返回该游戏规则，开局后的下一轮在 `NowGame` 下附该规则。保留通用 Game 标签、玩家语音由 AI 代发命令、GM 权威确认的统一交互方式。

## 需求与等级

- L6：游戏专属规则的提示词输入/GM 输出契约；L5：未开局、查询、开局及后续回合的状态流程。下放至 L4：权威快照 → 判定当前游戏 → 查游戏规则定义 → 组装 `NowGame`；规则查询 → 按游戏名返回同一规则定义。
- 规则查询不能把游戏改成当前活动游戏；无棋局和已结束时不常驻五子棋规则。开局后提示词变化可能使 Responses 重建上游会话，此行为已由用户接受。

## Design 与 Spec

- `docs/design/game-gomoku.md` 记录统一 AI 命令交互、按当前游戏注入规则与 Responses 会话边界。
- `docs/spec/game-gomoku.md` 先描述查询、开局和下一轮的伪代码，以及 GM 与 `System:` 规则去重。

## 受影响代码

- `src/apps/server/modules/game/game-chat-bridge.js`：精简五子棋专属规则，GM 查询和活动棋局提示共用该规则；不根据用户话术识别游戏或替 AI 落子。
- `tests/game-gomoku.test.js`：验证普通聊天无游戏规则、查询只返回短规则、开局后下一轮规则位于 `NowGame` 下、语音 H3 仍由 AI 发 User 标签。
- 对应 design/spec/task/todo/changelog 与 Offline 服务包状态。

## 自测、兼容和风险

- 先运行五子棋定向测试，再用隔离显示端、临时棋局和项目现有 Responses 协议模拟开局与一轮落子，避免污染当前对话。
- 普通 Game 标签格式、GM 回执和显示端棋盘协议不变；风险在于规则过短导致模型遗漏尺寸或落子约束，需观察真实 Responses 输出。预计工时约 45 分钟。
- 定向测试 `node --test tests/game-gomoku.test.js` 24/24 通过；覆盖规则查询时 `NowGame:无` 不变、开局后下一轮注入规则、非法落子后查询和口头宣称不能伪造成功、合法重试可完成 H3/H4、其他命令不能替代被拒落子、部分开局只报部分完成，以及 AI 回合只用自然语言自称落子时聊天和 TTS 均不接收虚构棋步。
- 隔离真实模型测试使用项目 `llm-responses-client.js` 的 Responses 请求及 `previous_response_id` 续接：目录→规则→开局成功，开局后的新会话看到 `NowGame:五子棋` 和短规则；H3 回合模型仍把两条标签隔着叙述输出，桥接层拒绝且棋盘未改变，续接时豆包返回 `doubao_risk_control`。未触碰当前显示端和 AASC 聊天历史，真实落子与播报仍待验收。
