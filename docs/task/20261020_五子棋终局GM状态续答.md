# 五子棋终局 GM 状态续答

日期：2026-10-20

## 任务描述

模拟 User 胜和 AI 胜后，GM 棋盘已给出正确胜负，但模型在终局落子的同条回复里仍可能说“接下来该你”。用户要求胜负发生后再把 GM 状态回送模型，并明确要求保留终局落子回复里已有的自然语言。

## Design 需求与 Spec 设计

见 `docs/design/game-gomoku.md` 与 `docs/spec/game-gomoku.md`。终局落子成功时暂存其自然语言，从权威棋局读取一次 `GM,状态`，连同 `GM,落子` 送回模型，等待后续终局答复。最终展示和朗读原叙述与后续答复，协议行只进入游戏提示。若终局落子刚好出现在第七次模型回复，额外允许一次状态续答。

## 受影响功能模块与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：终局 GM 状态续接及回复合并。
- `tests/game-gomoku.test.js`：User 胜、AI 胜及第七次回复终局边界。
- 五子棋 design/spec/usage、todo、changelog 与 Offline 服务包状态。

## 自测、兼容性与性能

运行 `npm run test:game-chat`；分别校验 User 胜与 AI 胜的模型下一次输入同时含 GM 落子和状态、棋盘结果不变、两段叙述进入聊天和 TTS。另测试第七次模型回复才产生终局时仍有一次续答。普通落子、新旧协议格式以及离线模拟入口继续由原定向测试覆盖。终局比旧流程多一次模型请求和一次只读状态查询，可能增加终局答复耗时。

## 风险与预计工时

原叙述可能与后续权威状态相矛盾；这是用户明确要求保留原文的结果。模型看见权威状态后仍可能产生不准确的文字，需在真实模型和显示端验收。预计约一小时。

## 执行结果

`npm run test:game-chat` 36/36 通过，`git diff --check` 通过。使用临时棋局和临时“小爱”聊天运行目录，经本机 Qwen `aasc-qwen-flash` 分别复测两盘终局：用户 E2 连五得到 `User胜`、版本 10，AI E9 连五得到 `AI胜`、版本 11。两盘各调用模型两次，终局后的模型输入同时包含 `GM,落子` 与 `GM,状态`，最终回复保留原叙述并追加终局答复。测试后删除临时目录，未连接真实显示端。AI 胜补充文字误称“四子连珠”，权威棋盘和 GM 胜负正确；真实显示端及 TTS 仍待验收。
