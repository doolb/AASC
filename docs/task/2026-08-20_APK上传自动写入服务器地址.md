# APK 上传自动写入服务器地址

## 任务描述

卸载 APK 后重新安装会清除 `SharedPreferences` 中的 `server_url`，导致 APK 启动后停留在配置页。要求 `upload:apk` 安装 APK 后自动将 `https://192.168.1.39:8081` 写入 APK 配置并启动显示端；允许通过环境变量覆盖地址。

## design 需求

- `apk-deploy.js` 安装后启动 `MainActivity`，通过 Intent extra `server_url` 传递服务器地址。
- `MainActivity` 在冷启动和 `singleTask` 新 Intent 两种路径接收地址，保存并连接。
- 无 Intent 地址时保持原有已保存地址和手动输入行为。

## spec 设计（伪代码）

```
serverUrl = AASC_DISPLAY_SERVER_URL 非空 ? AASC_DISPLAY_SERVER_URL : "https://192.168.1.39:8081"
安装 APK
启动 MainActivity，传入 extra server_url=serverUrl
MainActivity:
    读取 Intent extra 与 SharedPreferences.server_url
    Intent 地址优先
    地址非空 → 写入输入框 → connect()
connect():
    保存 server_url
    加载 serverUrl + "/display"
```

## 自测用例

1. 默认地址：部署脚本无环境变量时传入 `https://192.168.1.39:8081`。
2. 自定义地址：`AASC_DISPLAY_SERVER_URL=https://example:8081` 时传入自定义地址。
3. APK 冷启动收到 Intent 地址后保存并加载 `/display`。
4. APK 已运行时收到 `singleTask` 新 Intent 地址后更新并重新连接。
5. 无 Intent 地址时，已保存地址仍自动连接；无保存地址时仍显示配置页。

## 兼容性测试

- Android 7+，保留现有 `singleTask` 启动模式。
- `adb install -r` 保留已有配置；卸载重装后由 Intent 恢复配置。
- 未连接 adb 设备时上传流程仍只上传服务器文件，不中断构建。

## 性能测试

- 配置注入只增加一次 Intent 启动调用，不增加 WebView 页面加载以外的网络请求。

## 风险评估

- 服务器地址变更：通过 `AASC_DISPLAY_SERVER_URL` 覆盖，避免固定地址无法部署。
- APK 正在运行：必须处理 `onNewIntent`，否则 `singleTask` 不会重新执行 `onCreate`。
- 地址参数安全：使用 adb 参数数组传递，不拼接 shell 命令。
