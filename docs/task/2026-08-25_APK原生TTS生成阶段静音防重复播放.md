# APK 原生 TTS 生成阶段静音防重复播放

## 任务描述

- 问题：APK 本地生成 TTS 时手机先播放一次，服务器收到生成结果后又通过 `playAudio` 播放一次，用户听到两遍。
- 根因：Embedded Speech SDK 的 `SpeechSynthesizer(config)` 默认调用默认扬声器输出；当前代码同时读取 `SpeechSynthesisResult.getAudioData()` 回传服务器，形成生成播放与服务器播放两条路径。
- 目标：APK 原生 TTS 只生成并回传 WAV，服务器负责统一播放，每段语音只播放一次。

## Design 需求

- `TtsEngine` 的合成器显式传入空 `AudioConfig`，禁止默认扬声器输出。
- 声线探测同样不绑定默认扬声器。
- 保留 `ttsExecutor` 单线程后台执行与 60 秒超时机制。

## Spec 设计

```text
load:
  probeVoice(config, null AudioConfig)
  synthesizer = SpeechSynthesizer(config, null AudioConfig)
synthesize:
  在 ttsExecutor 单线程执行 SpeakText
  返回 getAudioData，不调用任何播放 API
server:
  收到 ttsResult 后下发一次 tts action=playAudio
```

## 兼容性测试

- Android 9 / API 28 / arm64-v8a display2。
- 保留旧 APK 的同步 `ttsSynthesize` 兼容入口。
- 服务端生成设备切换为 server 时不受影响。

## 性能测试

- 合成仍使用单线程执行器串行执行，不新增并发任务。
- 音频数据仍通过 `getAudioData()` 回传，格式保持 24kHz/16bit/单声道 WAV。

## 风险评估

- 空 `AudioConfig` 依赖 Embedded Speech SDK 的公开重载；已通过本地 AAR 字节码确认该重载会向 native 层传入空音频句柄。
- 若静音配置导致 SDK 不返回音频数据，需改用 `PullAudioOutputStream` 接收音频，但当前先采用 SDK 支持的空输出配置。
