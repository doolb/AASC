# 豆包签名刷新聊天状态提示

## 需求与范围

用户请求豆包重新获取签名时给出提示。用户已确认方案：实际获取/重新获取、更新后发送/重试、失败在对应请求显示临时状态，两端可见；缓存复用不提示，不写历史或朗读。

## 评审与设计

enterprise默认，明确性通过。主L5过程可见性，次L6请求状态契约；签名获取在上游请求发送前，因此不能等流返回才提示。置信度0.68；评分24/25、20/20、19/20、19/20、15/15，共97。可开发，中风险，建议下放L4拆为缓存判定→状态→prepare→状态→原请求；文档先行见doubao-web design/spec。用户已确认，先更新L4伪代码再实现。

## 预计文件

豆包适配器、Chat2API core/Responses/proxy、chat-model-tier-service、llm-service、game-chat-stream、server-app、websocket.js/display-stage.js及两端聊天UI；优先复用现有传输与样式。补针对性测试和self-test，servicePackage受影响，无新增APK、依赖或任务包要求。

## 验收、兼容、性能与风险

prepare等待期间能先收到安全状态；缓存不提示、一次补发、失败取消/清空收尾、请求隔离、旧客户端忽略未知事件。覆盖本地与HTTP Responses及双端DOM，状态不进入TTS和模型输出重发判据。每次实际准备少量事件，无额外上游请求；HTTP准备前发SSE须保留response.failed原始错误，不断流。预计1小时；实现与回归已完成，servicePackage保持true等待服务包更新。
