# PMX 角色 AO 环境遮蔽

## 任务描述

为显示端当前使用的 PMX 角色加入屏幕空间环境遮蔽，增强衣袖、发丝和躯干等邻近表面的接触暗部；在右上角“灯光”面板提供默认开启的开关，先用于内网显示端验证。

## Design 需求

- 只作用于 PMX 渲染，VRM 显示逻辑保持现状。
- AO 随动作和角色旋转逐帧更新；开关即时生效，不重新加载模型或 VMD。
- 保持透明画布的 alpha，不能在角色外出现实色背景或黑色边框。
- 旧浏览器灯光设置缺少 AO 字段时默认开启；开关随现有 localStorage 保存，亮度预设保留当前 AO 状态，恢复默认重新开启。
- 限制 AO 分辨率和采样数，图形设备不支持 WebGL2 时保留直接渲染。

## 需求等级评审

- 评审结论：可开发；主等级 L6（显示端渲染功能与设置契约），次等级 L4（逐帧渲染步骤），置信度约 0.9，直接开发风险中等。
- 层级清晰度 23/25、证据充分度 18/20、实现完备度 17/20、风险暴露度 18/20、L4 可落地性 14/15，总分 90/100。
- 下放判定：建议下放到 L4。证据为“PMX 角色 AO”“默认开启”“灯光面板开关”“先在内网显示端测试”；拆解为设置规范化、透明色彩目标、深度采样、RGB 合成、回退和释放五段操作。
- 信息断点已通过方案确认明确：范围为当前 PMX，VRM 暂不接入；默认开启且可切换；目标显示设备的性能与画质仍需现场验收。

## Spec 设计

见 `docs/spec/mmd-pmx-vmd-local.md` 第 12 节。核心流程为：

```text
设置 AO 开关 → PMX runtime 更新环境遮蔽状态
每帧 PMX 原场景 → 透明色彩目标和深度纹理
深度重建与邻近采样 → 半分辨率 AO 目标
深度边缘过滤 → 仅调暗已有 RGB 并保留 alpha → 显示画布
AO 关闭或 WebGL2 不可用 → 直接渲染 PMX 场景
```

## 自测用例

1. 默认/旧设置 AO 为开启，点击开关即时关闭并保存，亮度预设保留选择，恢复默认重新开启。
2. 浏览器 WebGL 场景中，AO 开启后相邻几何表面变暗；关闭后颜色恢复。
3. AO 开关前后透明背景和 PMX 画面 alpha 一致；真实米娅 PMX 有可见遮蔽像素。
4. 不支持 WebGL2 时保留直接渲染；隐藏、模型切换和销毁时不继续占用渲染循环或泄漏目标。
5. 目标 Android WebView 上观察发丝/裙摆边缘、动作旋转和开关前后帧率。

## 兼容性测试与性能

- 使用项目固定的 Three.js r160，无新增第三方依赖或外网脚本。
- AO 最多使用绘制缓冲区一半尺寸，且不超过 1280×720；每个 AO 像素固定采样 12 次深度。开关关闭时不执行 AO 通道。
- 六份 AO/MMD/显示端定向测试共 64/64 通过；本机 Chrome 对真实本地米娅 PMX 的透明度与遮蔽做了像素验证。已用运行中的本地服务 `https://127.0.0.1:8081/display` 打开真实显示页，PMX 模型成功加载，灯光面板 AO 默认开启，点击关闭/开启时面板与 `DisplayMmd` 状态同步，页面没有 JavaScript 异常。最终 `npm test` 为 900/955 通过、55 项失败，失败项集中在当前 Windows 环境、Offline 打包/发布、旋转文本等非 AO 用例。目标 Android WebView 仍需现场观察。

## 风险评估

- 透明 PMX 材质的发丝与裙摆可能在特定姿态出现遮蔽边缘伪影；需现场按自测表检查。
- 高 DPI/低性能 GPU 可能因额外场景通道和深度采样降低帧率；面板开关可即时停用。
- AO 需要 WebGL2 深度纹理能力；不满足时使用直接渲染。
