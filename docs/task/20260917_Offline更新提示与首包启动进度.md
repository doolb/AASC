# Offline 更新提示与首包启动进度

## 任务描述

Offline APK 发现新 min APK 时先由用户确认下载，下载期间显示浮动进度，校验完成后自动提交系统安装；完整 Offline APK 首次启动时显示 Runtime、服务源码、Node 依赖和配置迁移的详细阶段进度。

## design 需求

- 在 `docs/design/android-offline-hot-update.md` 增加手动确认下载、浮动进度和首包阶段进度约定。
- 保留 Android PackageInstaller 的系统确认，不实现静默安装。

## spec 设计

- `OfflineUpdateManager` 提供下载/校验/模型物化回调，`MainActivity` 通过浮动卡片展示阶段和字节百分比。
- `NodeRuntimeInstaller` 以 manifest 文件大小累计 Runtime、源码、依赖和元数据复制进度，`NodeServerService` 广播阶段状态。
- 安装结果通过应用内广播回传，失败保留当前版本并允许重试。

## 受影响的功能模块和代码

- 更新管理：`OfflineUpdateManager.kt`、`OfflineApkInstallReceiver.kt`。
- 首包安装：`NodeRuntimeInstaller.kt`、`NodeServerService.kt`。
- UI：`MainActivity.kt`、`activity_main.xml`、`strings.xml`。
- 测试与文档：Android JVM 测试、静态契约测试、design/spec/todo/changelog。

## 自测用例

- 发现新 min APK 时仅显示提示，未点击下载不产生 `.part` 文件。
- 点击下载后进度按已接收字节递增，完成后自动进入系统安装流程。
- LAN 失败回退 WAN、hash/签名失败、安装失败均显示错误并保留当前版本。
- 首包启动阶段依次显示 Runtime、源码、Node 依赖和配置元数据进度；快速复用 Runtime 不显示虚假解压进度。
- PackageInstaller 成功、待用户确认、失败广播都能更新浮动卡片。

## 兼容性测试

- Android API 28 Debug/JVM 测试。
- Android 8+ 未知来源授权流程和 Android 12+ PendingIntent 行为。
- 普通 APK 不显示 Offline 更新进度 UI。

## 性能测试

- 下载回调节流，避免每个网络块触发 UI 重绘。
- 进度计算使用 Long，支持大于 2 GiB 的 Runtime 文件总量。
- UI 更新运行在主线程，文件复制和网络读取不阻塞主线程。

## 风险评估

- 标准 Android 设备仍可能要求用户确认安装，无法保证完全静默更新。
- Activity 被系统回收时仅保留已下载的校验文件，回到前台后恢复提示，不重复覆盖有效缓存。
- 首包进度是文件复制进度，不代表底层闪存落盘或 Node 服务已健康；服务健康仍由现有检查决定。
