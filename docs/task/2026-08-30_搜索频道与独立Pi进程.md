# 任务：搜索频道与独立 Pi 进程

## 任务描述

修复控制端搜索历史没有可见刷新、搜索请求进入群聊以及搜索开始提示 TTS 未播报的问题。搜索通过 LLM/Pi Agent 时使用独立临时 Pi 进程，避免继承群聊上下文。

## Design 需求

- 新增控制端独立搜索频道，展示搜索状态和历史。
- 搜索命令开始时先发送搜索频道状态并播报 `正在搜索${内容}`。
- 搜索不写入群聊历史，不发送普通聊天流式消息。
- 每次 Pi 搜索只使用当前请求，完成后回收独立 Pi 进程。

## Spec 设计

- 新增 `searchChannel` WebSocket 消息，包含 requestId、query、status、result/error 和 timestamp。
- `searchHistory` 到达时刷新搜索频道；服务端历史文件协议保持兼容。
- Pi Runtime 增加一次性会话调用或等价的临时会话回收能力。
- system 搜索继续使用现有搜索实现；llm 搜索改为独立 Agent 搜索流程。

## 自测用例

1. 控制端连接后能显示已有搜索历史。
2. 收到 `searchHistory` 后不刷新页面即可显示新记录。
3. 搜索开始先收到 `searchChannel(start)`，再开始搜索处理并触发 TTS。
4. system 搜索不产生群聊历史。
5. llm/Pi 搜索不产生群聊历史，且新建独立 Pi 进程。
6. Pi 搜索结束后 Runtime 会话数恢复，连续搜索不会无限积累进程。
7. Pi 搜索失败、超时仍发送搜索频道错误并回收进程。

## 性能测试

- 连续执行 10 次串行搜索，确认临时 Pi 进程不会累积。
- 观察服务器 RSS 与 Pi 子进程 RSS，记录峰值和完成后的回落情况。

## 风险评估

- 风险：Pi 搜索响应慢，临时进程创建会增加启动开销；通过复用现有启动参数和请求超时控制。
- 风险：旧控制端不认识 `searchChannel`；新消息只增加展示能力，不改变既有搜索协议。
- 风险：历史刷新与搜索频道同时更新；使用 requestId 和统一历史消息避免重复项。
