# 任务：更新控制端系统指令帮助内容

## 任务描述

补齐控制端“系统指令帮助”弹窗中的会话控制和其他系统命令说明，使页面内容覆盖当前语音会话状态机已经支持的实际指令。

## Design 需求

- 保留服务端动态返回的“内置功能命令（无需唤醒）”列表。
- 在动态列表后增加完整的会话与模式命令说明。
- 展示开始/结束对话、助手名临时唤醒、私聊唤醒与退出、进入群聊模式等当前支持的会话指令。
- 保留私聊和系统记录等其他系统命令说明。
- 不修改语音命令解析、WebSocket 消息和会话状态机。

## Spec 设计

```text
打开系统指令帮助弹窗:
    渲染服务端返回的 builtinVoiceCommands
    渲染“会话与模式命令”静态区域:
        开始对话、结束对话、助手名临时唤醒
        你好/助手名你好、助手名再见/再见助手名
        进入群聊模式、退出私聊
    渲染“其他系统命令”静态区域:
        私聊助手名、系统记录内容
    不改变任何命令执行和消息协议
```

## 自测用例

1. 系统指令帮助仍显示动态内置命令容器。
2. 弹窗显示“开始对话”和“结束对话”。
3. 弹窗显示助手名临时唤醒、私聊唤醒和私聊结束示例。
4. 弹窗显示“进入群聊模式”“退出私聊”“私聊{助手名字}”和“系统记录{内容}”。
5. 动态内置命令列表、WebSocket 加载流程和原有语音命令测试保持通过。

## 兼容性测试

- 不修改 `getBuiltinVoiceCommands` 返回结构。
- 不修改 `builtinVoiceCommands`、`showHelp` 等 WebSocket 消息类型。
- 不修改语音会话状态迁移、TTS 播报和自定义指令配置。
- 保留旧控制端未理解新增页面文案时的服务端兼容性。

## 性能测试

- 仅增加静态 HTML 文案，不新增网络请求、轮询或持久化数据。
- 动态命令仍由现有 WebSocket 初始化和重连流程加载。

## 风险评估

- 静态帮助文案可能再次落后于会话状态机；本次仅补齐已在当前代码和设计中确认的命令，不改变解析实现。
- 长命令示例在窄屏弹窗中可能换行，但不影响功能。
