# 控制端裁剪框计算加详细打印并修复刷新Bug

## 任务描述
给控制端裁剪框计算加上详细 console.log 打印，方便跟踪计算过程；同时解决页面刷新后裁剪框显示不对的问题。

## 根因分析
- 刷新后接收 `displayState` → `showPreview(url, type, callback)` → 图片已缓存时
  `onload` 事件和 `complete` 检查两条路径都会触发回调
- 第一次回调 `setData(savedCrop)` 恢复保存的裁剪数据（正常）
- 第二次回调因 `_onReadyCallback === null` 走入 `recalculateSize(false)` 分支，
  覆盖了 `this.data` 为居中对齐的全尺寸值
- 导致裁剪框在任何非全尺寸的保存状态下，刷新后都复位到全尺寸

## 改动内容

### 1. Bug 修复：`showPreview()` 双回调冲突

- 新增 `_callbackExecuted` 标志位
- 新增 `executeCallback()` 包装函数，内部检查标志位确保只执行一次
- `_retryShowPreview()` 同样加标志位检查，防止重试覆盖
- 第 264 行 `this.previewVideo.src = url` 触发的 `onloadedmetadata` 和 `readyState >= 1`
  两条路径、第 278 行 `src` 触发的 `onload` 和 `complete` 路径全部统一走 `executeCallback()`

### 2. 详细日志

| 函数 | 日志内容 |
|------|----------|
| `showPreview()` | 触发路径（`onload`/`complete`/`readyState`）、`_callbackExecuted` 状态 |
| `updateBox()` | `rotation`、`mediaRect`、`containerRect`、`offsetX/Y` 计算来源、百分比转像素每一步 |
| `recalculateSize()` | `displayCanvasSize`、`aspectRatio` vs `mediaAspect` 比较、选 `width=100` 还是 `height=100` 分支、计算结果 |
| `setData()` | 被设置的 crop 数据 |
| `setRotation()` | 旋转角度 |
| `onMouseMove()` | 拖拽：`dx/dy`、`cropStart→data` 变化；缩放：`handle` 旋转映射、delta 选择、边界修正、最终值 |
| `reset()` | `mediaRect`、`aspectRatio` 比较、计算结果 |
| `_retryShowPreview()` | 重试次数、`mediaRect`、`callbackExecuted` 状态 |

## 自测用例

1. 打开控制端，在显示端当前有裁剪数据（非全尺寸）时刷新控制端页面
   - 预期：裁剪框显示和刷新前一致（不应复位到全尺寸）
2. 控制台查看 `[Crop] showPreview: callback 已执行过，跳过` 出现（仅第二次触发时）
   - 预期：`[Crop] showPreview: 执行回调（恢复裁剪数据）` 出现且仅一次
3. 操作裁剪框后查看控制台日志链
   - 预期：`[Crop] updateBox` 打印 offset、百分比、像素值完整链路
