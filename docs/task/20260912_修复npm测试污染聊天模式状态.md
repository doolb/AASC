# 修复 npm 测试污染聊天模式状态

## 任务描述

修复 `npm test` 执行聊天会话模式测试时，将临时的私聊“小爱”状态写入真实用户配置，导致服务器重启后自动进入私聊的问题。测试应只验证内存状态，并在测试结束后恢复测试开始时的会话状态。

## Design 需求

- 聊天服务的会话、模式和私聊 session 切换仍支持生产环境默认持久化。
- 单元测试调用这些接口时可显式关闭持久化。
- 测试之间恢复原始内存会话，不能遗留私聊目标或临时 session ID。
- 不改变服务器真实控制端、显示端和语音模式切换流程。

关联设计：`docs/design/chat-history-persistence.md`。

## Spec 设计

- `setSession(session, metadata)`、`setMode(mode, target, metadata)` 和 `switchSession(target, sessionId, metadata)` 统一识别 `metadata.persist === false`。
- `persist=false` 时仍执行内存状态变更、Pi 会话重置和模式审计日志，但跳过 `saveSession()`。
- 测试使用 `source: test`、`persist: false`，并在每个测试结束时恢复原始会话。

关联实现伪代码：`docs/spec/chat-history-persistence.md` 的“会话状态保存策略”。

## 受影响的功能模块和代码

- `src/external/llm/llm-service.js`：会话状态持久化开关。
- `tests/llm-agent-mode.test.js`：模式切换测试的非持久化调用和状态恢复回归。
- `docs/design/chat-history-persistence.md`：测试会话状态隔离设计。
- `docs/spec/chat-history-persistence.md`：会话保存策略伪代码。
- `docs/todo.md`、`changelog.md`：任务状态和变更记录。

## 自测用例

1. 测试前为群聊，运行模式切换测试后仍为群聊。
2. 测试前为私聊“小爱”，运行模式切换测试后仍为私聊“小爱”。
3. `persist=false` 的 `setSession`、`setMode`、`switchSession` 不修改用户会话文件。
4. 生产默认调用仍写入会话文件。
5. `npm test` 全量执行，确认新增回归测试通过。

## 兼容性测试

- 既有控制端手动、文本、语音切换保持默认持久化。
- 服务端显示端语音同步仍可写入权威聊天状态。
- 未传 metadata 或未传 `persist` 的旧调用保持兼容。

## 性能测试

- 非持久化测试调用不产生磁盘写入，减少测试期间的同步文件操作。
- 生产路径仍只执行原有一次 `saveSession()`，无额外持久化开销。

## 风险评估

- 风险：错误地把 `persist=false` 传入生产调用会导致状态不落盘。
- 控制：仅测试代码使用该标志；默认值保持持久化；增加生产默认行为回归断言。
