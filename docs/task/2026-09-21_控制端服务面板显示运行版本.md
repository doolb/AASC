# 控制端服务面板显示运行版本

## 任务描述

外网真机需要确认服务热更新是否成功，因此在控制端服务器面板显示 APK、服务代码、依赖包和显示端版本，优先处理版本确认，再发布新的服务代码包。

## Design 需求

- 版本来源优先使用 `updates/active-release.json`，没有热更新时回退 APK 内置 `offline-update-client.json`。
- 节点注册 metadata 和 `/api/status` 均返回统一的 `versions` 对象。
- 控制端服务器面板显示当前节点摘要以及每个节点的详细版本。
- 只发布服务代码包，不重打完整 APK、min APK、依赖包和模型。

详见：[runtime-version-display.md](../design/runtime-version-display.md)。

## Spec 设计

- 新增运行版本读取模块，统一处理文件读取、回退和版本格式化。
- AASC 节点目录和状态接口复用该模块。
- 控制端使用 HTML 文本转义后的固定字段渲染版本信息，并兼容旧节点。

详见：[runtime-version-display.md](../spec/runtime-version-display.md)。

## 自测用例

- active release 优先级测试。
- 无 active release 时内置基线回退测试。
- 控制端服务器列表版本字段和摘要区域测试。
- Node.js 语法检查与 `git diff --check`。

## 兼容性测试

- 旧节点没有 `metadata.versions` 时仍显示旧 `server.version`。
- 非 Offline 服务使用 `package.json` 版本作为服务基线。
- 不改变已有服务器列表接口字段和 APK 原生更新流程。

## 性能测试

- 版本文件只在服务注册和状态请求时读取，文件很小，不引入常驻扫描。
- 控制端仅在服务器列表刷新时更新摘要，不增加轮询频率。

## 风险评估

- 显示端版本沿用现有代码指纹语义，不代表显示端业务版本号；已在 design 文档中说明。
- active release 文件损坏时安全回退到 APK 基线或 `unknown`，不阻断服务启动。
- 本任务不修改依赖包，因此不会解决旧 APK 内置 `_vendor` 被资源打包器过滤的问题；该问题需要单独重打原生 APK 处理。
