# 控制端语音聊天实时顺序修复

## 任务描述

显示端语音输入进入临时聊天时，控制端实时列表偶尔将助手回复显示在用户输入之前；刷新后服务端历史顺序正常。本任务让实时完成态直接使用服务端最终消息快照，消除流式 DOM 与最终历史的顺序差异。

## Design 需求

- 普通群聊和私聊成功回包后，以回包中的服务端历史重绘控制端聊天列表。
- 临时对话成功回包携带完整会话快照；控制端用该快照更新状态并重绘。
- 临时助手快照保留正文、思考内容和语音文本，历史播放与思考入口继续可用。
- `requestId` 校验、流式 chunk 展示、失败处理和显示端语音路由保持原有协议。

## Spec 设计

```text
服务端临时回复完成:
    写入助手消息及 reasoning/speech
    snapshot = 当前临时会话快照
    chatResponse 携带 snapshot

控制端收到成功 chatResponse:
    校验 requestId
    更新普通历史或临时会话快照
    按当前会话数据重新渲染完整消息列表
```

## 受影响模块与代码

- `src/apps/server/boot/server-app.js`：临时消息快照保留 reasoning/speech，临时成功回包附最终快照。
- `src/apps/web-mediacenter/ui/public/js/chat.js`：成功回包应用最终临时快照，并按服务端历史/快照重绘。
- `docs/design/chat-system.md`、`docs/spec/chat-system.md`、`docs/todo.md`、`docs/self-test.md`、`changelog.md`：同步设计、伪代码、任务状态、验收步骤和变更记录。

## 自测用例

1. 显示端语音输入一条消息，控制端实时流式期间显示用户输入和助手回复；回复完成后顺序为用户在前、助手在后。
2. 刷新控制端，消息顺序和实时完成态一致。
3. 临时会话回复完成后，控制端按临时快照渲染；助手思考内容和语音文本仍可供原有入口使用。
4. 普通群聊、私聊、失败回包及非语音控制端聊天行为保持不变。

## 兼容性测试

- 旧控制端忽略 chatResponse 新增的临时快照字段时，既有 temporaryConversation 广播仍提供会话内容。
- 普通群聊/私聊回包结构不变；Go/C# 客户端及 Node 子显示端协议不变。

## 性能测试

- 成功临时回复多携带一次当前会话快照；其大小与既有临时会话广播同级，不新增请求或轮询。
- 完成态重绘只执行一次列表模板渲染，不增加 LLM、ASR 或 TTS 工作。

## 风险评估

- 若回包快照更新与页面当前查看的历史临时组冲突，控制端仍按现有历史只读选择规则显示；实时完成态只更新当前会话状态。
- 最终重绘需沿用服务端历史中保存的 speech/reasoning 字段，避免丢失播放和思考功能。
