# 全身IK参考图片相机视角匹配

状态：已实现并完成桌面验证，代码已准备提交；手机/更多图片验收另记todo。

## 任务与边界

用户追加希望“有一个按钮可以定位到图片里的相机角度”。与实际骨架对照任务联合：参考图显示真实角色骨架，用户在3D拖点，增加「匹配图片视角（估计）」与「恢复匹配前视角」。相机拟合以当前实际角色姿态为条件，只改相机，不暗中应用姿态或改变人体目标。

对应`docs/design/mmd-human-interface.md`及`docs/spec/mmd-human-interface.md`顶部追加段。首版固定当前透视FOV，通过可信3D/2D关节对应估计视角和取景，显示重投影误差；不承诺单图恢复真实物理相机，二次元比例/遮挡/错误关键点和角色姿态差异都可能影响估计。用户应先让角色姿态大致接近图片，再匹配相机并继续手调。

## 代码依据

- `display-pmx-runtime.js`现有相机默认透视28°，普通视角每帧按cameraViewState/cameraTarget/distance更新，存在相机VMD与AR控制。
- 独立`web-editor-build.js`/`web-editor-bridge.mjs`已有编辑器相机覆盖；直接写camera对象会被普通/编辑器控制覆盖，单纯复用编辑器覆盖又会阻断后续普通旋转，需要统一适配当前相机控制源。
- 图片现有33点2D坐标/质量与PMX语义骨架可构造关节对应。已有ONNX world是估计值，不能把它直接当真实相机外参；肩髋等对应也要按真实模型语义核查。

## 需求等级分析（enterprise）

主L6（相机拟合输入输出/误差/失败契约），次L5（按钮/恢复/相机仲裁），不新增服务拓扑。强证据分别为用户明确相机角度按钮、既有图片关键点与实际骨架输入、真实运行时多源相机覆盖；主层6/总9×邻层一致性0.90=0.60。结论可开发但直接风险中，建议下放L4，坐标/代次/失败与恢复必须先写伪代码。

评分：层级清晰24/25、证据20/20、方案完备17/20、风险19/20、L4落地14/15，总94/100，仅评价方案。断点是模型姿态与相机误差混淆、未知内参及多源覆盖；分别以冻结骨架/可靠性与误差门槛、固定FOV假设、显式运行时桥接解决。

L4已有声明为实际3D点/图片2D点/相机状态；新增定义为对应集合、候选相机、误差、恢复快照和有界求解；操作为验证→冻结→拟合→再校验→原子应用→叠加/3D手调→按需恢复。详见spec。

## 自测与兼容性

- 合成已知3D与相机投影：水平/俯仰/画面倾斜/取景可近似恢复；不同图片宽高与主画布比例保持正确。
- 离群/低可信/缺点/退化/错误候选/姿态差异过大时可靠性提示，失败相机/骨骼/目标完全不变。
- 连续帧不弹回，手动旋转/缩放接续正常；多次匹配/恢复、图片候选/模型/相机代次变化、关闭取消、AR/外部相机接管保护。
- 真PMX与真实ONNX图片浏览器验证误差变化及骨架叠加，保留粘贴/无人/取消回归；Android/iOS实际设备另验，不把合成已知视角测试等同二次元真实相机验收。

## 性能、风险与工时

拟合仅点击触发，候选数量与迭代有上限并可取消，不重复ONNX；需按实际桌面耗时决定分片/Worker，不能长时间阻塞拖动与绘制。与叠加一起预计3～5小时实现和桌面回归，手机另验。固定FOV和当前人体比例是明确假设；相机拟合误差下降不代表姿态或真实机位正确。

参考：[OpenCV PnP文档](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)（3D/2D对应与内参、重投影误差、多解/鲁棒估计）；[MediaPipe Pose说明](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)（图像与估计3D点输出）。本项目固定OpenCV Zoo ONNX并非直接接入最新Tasks API，引用仅说明数学及输出类别。

前期方案已获用户确认，按spec先行和测试先行完成实现，执行结果见下节；未修改模型/依赖/Offline状态，未发布。

独立只读方案核查未发现需另问用户的阻塞点；已采纳两项补充：应用前比较实际骨架变化，最终有效内点仍检查数量/身体分布与误差。阈值由实现者结合已知相机测试确定，不新增用户设置。
