# MMD-AR 主相机视野与阴影相机联合拟合

日期：2026-10-08。状态：代码、定向单测、Web构建与用户视觉验收完成；当前环境的自动浏览器测试因缺少Chromium跳过。

后续修正：用户反馈首版联动仍以角色为中心；当前联动已改为CSM式主相机前向视锥切片，详见 `docs/task/20261008_MMDAR主相机CSM切片拟合.md`。

## 任务描述

显示相机缩放、旋转时，ShadowMap 阴影相机当前仍按完整角色包围范围拟合。将主相机可见范围、角色投影、阴影接收平面和方向光阴影相机统一考虑，按当前可见投影区域在 ShadowMap 中的占比动态拟合阴影相机。

## Design 需求

- 面向独立 MMD-AR 测试页，覆盖米娅 PMX 与静态西施 GLB；不修改正式 `/display` VRM/PMX 运行时。
- 按主相机当前视锥与角色/接收面范围求可见投影区域，分别转换到主光、补光的光源相机空间。
- 保留当前 `cameraScale` 手动倍率、ShadowMap 分辨率设置、阴影像素网格对齐和原始拟合回退；联合拟合的自动视野高度再乘既有0.5基准，默认倍率仍1。
- 相机、灯光、模型等变化时拟合；静止帧不重复完整遍历模型。

## 自测用例

1. 默认1x时联合拟合视野高度按targetOccupancy=0.78后再乘0.5；检查主/补光ShadowMap预览及角色阴影边缘，确认范围变小后的实际视觉无不可接受裁切（用户已确认效果正常）。
2. 拉近/拉远、转动主相机时，主光/补光分别按自身光线方向重拟合；边缘留量避免影子突然裁切。
3. 联合拟合计算范围按 `targetOccupancy=0.78` 后再乘既有0.5自动基准；`cameraScale=1`保持默认，0.5/2倍率相对新基准不累乘，阴影相机范围与投影占比符合当前确认效果。
4. 换入静态西施GLB及米娅PMX、移动/缩放角色、调整灯光方向后更新有效；不可见/退化范围回退原包围盒算法。
5. 静止时不重复计算包围范围；同一渲染帧多次相机事件合并为一次拟合。
6. `node --test tests/mmd-ar-shadow-map-size.test.js`：12/12通过，含默认cameraScale=1时的0.5联合拟合基准断言；浏览器自动化1项因Windows环境缺少配置的 `/usr/bin/chromium` 跳过。
7. `npm run build:web:mmd-ar-test`：本地GLB缺失时经公网回退成功构建；用户检查追加0.5后的视觉效果并确认正常。

## 兼容、性能与风险

- 正交阴影相机每盏灯分别按光空间范围拟合；保留当前shadow map像素对齐，减少投影范围/中心变化引发的闪动。
- 遮挡体在视锥外但其投影落入可见接收面的情况需要纳入caster footprint与安全边距，否则可能裁去屏外物体投来的阴影。
- PMX动作中的变形包围范围需采用保守边界；不承诺每个姿势均最紧拟合。静止时复用缓存，避免每帧扫描高顶点角色。
- 追加0.5会进一步收紧投影覆盖；用户已检查默认效果并确认正常，其他角色姿势/灯光/相机组合仍可通过cameraScale调节，需留意极端角度的阴影裁切。
- 本任务仅更新独立测试网页，不打包、发布或重启服务。
