# 五子棋 System 目录与普通对话

## 任务描述

按用户提供的完整 System 文本调整游戏提示，支持 `GameUser` 帮玩家查目录，并修复已有棋局时模型只输出自然语言却被再次要求判断原话的问题。五子棋规则补充自然语言行列到坐标的示例。

## Design 需求

`GameUser` 和 `GameAI` 均可调用目录列表，规则查询仍由 `GameAI` 发起；GM 是权威回执角色，不可由模型伪造。模型没有游戏调用行时，这次回复就是普通聊天，保留同一会话历史与原棋局，不自动补发游戏请求。口语“第三行第三列”应引导 AI 写用户落子 `C3`。

## Spec 设计

见 `docs/spec/game-gomoku.md`。System 在原有 raw 消息的 `System:` 正文中按用户文本排列目录示例；解析器接受两种目录角色；无调用行进入正常聊天输出路径，已有 GM 拒绝操作的纠错校验继续保留。

## 受影响功能与代码

- `src/apps/server/modules/game/game-chat-bridge.js`：替换通用游戏提示，增加坐标换算规则，删除无指令重判和轮次驱动的伪 GM 续问。
- `src/apps/server/modules/game/gomoku-game-service.js`：目录列表接受 `GameUser`。
- `tests/game-gomoku.test.js`：测试目录角色、原文提示、无调用普通聊天、伪造 GM、自然语言行列示例和抢跑后的无调用回复。
- `docs/design/game-gomoku.md`、`docs/spec/game-gomoku.md`、`docs/usage/game-gomoku.md`：同步协议与行为。

## 自测用例

1. GameUser/GameAI 的目录查询得到同一权威目录，GM 角色目录仍被拒绝。
2. 已有棋局中用户说“下第三”，AI 只给出自然语言时仅调用模型一次，聊天正常展示并保留历史，棋局不变。
3. AI 伪造 `Game:五子棋,GM,落子,5eb1,3,3` 时返回格式错误；后续普通问题不出现“重新判断原话”提示。
4. GM 确认用户落子后，AI 若只给普通话语，不合成 GM 错误，也不擅自改棋盘。
5. 原有胜负、查看快照、尺寸和落子协议继续通过。

## 兼容性测试

保留完整 `Game:`、活动棋局简写与旧尖括号外形；不接受旧 `User`/`AI` 角色或模型伪造 GM。`npm run test:game-chat` 覆盖入口与桥接。

## 性能测试

无调用行少一次或多次模型续问，不增加棋局持久化和网络请求；目录查询复用原有白名单与回执。

## 风险评估

模型若没有调用行却用自然语言声称落子成功，普通聊天路径不会自动代其执行棋步；GM 已拒绝操作时仍保留原有纠错限制。真实模型对口语坐标和 System 指令的遵守程度需现场验收。
