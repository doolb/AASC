# TTS 开始生成回执与 3 秒确认

## 任务描述

显示端收到 `ttsGenerate` 后先回报已接受生成任务。服务端 3 秒内未收到 `ttsGenerating` 就判定显示端未接收或已离线，立即回退服务器；收到开始回执后继续等待最终音频，整体生成超时保持 60 秒。

## design 需求

- 新增 `ttsGenerating{requestId}` 中间回包。
- `ttsResult` 必须在 `ttsGenerating` 之后才有效。
- 开始回执等待 3 秒；最终 TTS 生成等待 60 秒。
- 显示端 WebSocket 在等待期间断开时立即失败并回退。

## spec 设计

```text
server:
  send ttsGenerate
  startAckTimer = 3s
  receive ttsGenerating → clear startAckTimer, mark started=true
  receive ttsResult before started → reject
  receive ttsResult after started → resolve/reject
  total timer = 60s

display:
  async bridge accepted=true → send ttsGenerating
  bridge rejected/exception → send ttsResult{error}
  synthesis complete → send ttsResult{audioData/error}
```

## 自测用例

- 收到 `ttsGenerating` 后允许最终 `ttsResult` 成功。
- 3 秒未收到开始回执时回退服务器。
- 未开始就收到 `ttsResult` 时判定失败。
- 显示端断开时立即回退。
- 相关 Node 测试、语法检查和 `git diff --check` 通过。

## 风险评估

- 旧 APK 若仍被错误标记为 `ttsGeneration=true`，同步兼容路径也会先发送开始回执；正常能力上报为 false 的旧 APK 不会被选中。
- 开始回执只表示任务已接受，不代表模型合成已完成；最终结果仍受 60 秒总超时限制。
