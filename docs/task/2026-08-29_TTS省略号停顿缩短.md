# TTS 省略号停顿缩短

## 任务描述

将 `......` 和 `……` 作为 TTS 句子边界，使 `你好......世界` 生成 `你好`、`世界` 两句，并避免在单个音频内部产生过长停顿。

## design 需求

- 保留界面原始文本。
- 连续英文句点或中文省略号参与 TTS 分句，作为句间边界。
- 相邻的仅标点分句只保留第一个，删除后续仅标点分句，避免 `？`、`！` 等独立标点重复进入 TTS 队列。
- 每个分句的合成输入将省略号边界压缩为一个英文句点。
- 覆盖显示端离线 TTS、服务端 TTS 及 fallback。

## spec 设计

- 新增纯文本 `normalizeTtsPauseText(text)`。
- `generateTtsWithFallback()` 在所有设备路由前调用该函数。
- 单个英文句点保持不变。

## 自测用例

1. `你好......世界` 分为 `你好......`、`世界` 两句。
2. `你好……世界` 分为 `你好……`、`世界` 两句。
3. `1.2` 和普通英文句号保持原有规则。
4. TTS 统一路由使用处理后的文本，显示消息仍保留原文。
5. 实际 TTS 服务分别生成两句音频。
6. `喵呜……？！ （耳朵瞬间变得通红` 分为 `喵呜……`、`？`、`（耳朵瞬间变得通红`，连续仅标点分句只保留第一个。

## 兼容性测试

- 普通句子和小数点不被误拆。
- 不影响非字符串输入的既有错误处理。
- 显示端离线生成和服务端 fallback 使用同一处理规则。

## 性能测试

- 仅增加一次分句结果扫描和字符串替换，不增加音频处理和等待步骤。

## 风险评估

- 英文句点的实际停顿由具体音色和 TTS 引擎决定，0.2 秒不是跨引擎的硬保证。
- 仅替换连续句点，避免误伤小数点或普通英文句号。
