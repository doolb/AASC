# 语音对话确认模式

## 任务描述

为唤醒后的普通语音增加全局三档确认模式，避免错误 ASR 在用户确认前进入聊天和 Pi 历史；确认文本使用原显示端天气同款弹窗显示，并继续走通用 TTS 路由。

## Design 需求

- 全局模式：关闭、手动确认、自动确认。
- 手动确认等待 30 秒；确认才发送，取消、拒绝或超时丢弃。
- 自动确认在所有实际 TTS 播放目标完成后等待 7 秒；用户取消或拒绝才丢弃，否则自动发送。
- TTS 生成或播放失败不立即提交；自动模式仍显示原文并开启 7 秒取消窗口，手动模式继续等待明确确认。
- 确认倒计时显示在唤醒倒计时后面，倒计时文字带背景。

## Spec 设计

```text
普通语音 -> 保存原文 -> 弹窗 + 通用 TTS -> 待确认
手动模式: 30秒内确认 -> 正常聊天；否则丢弃
自动模式: TTS完成后7秒内取消 -> 丢弃；否则正常聊天
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：全局配置 WebSocket、待确认拦截和确认后聊天提交。
- `src/apps/server/modules/voice/conversation-confirmation.js`：确认模式和待确认状态逻辑。
- `src/apps/web-mediacenter/modules/voice/voice-command-app-service.js`：三档模式语音命令和内置命令列表。
- `src/apps/web-mediacenter/ui/public/display.html`：天气弹窗、确认倒计时和 TTS 完成回执。
- `src/apps/web-mediacenter/ui/public/css/display.css`：倒计时背景和确认提示样式。
- `src/apps/web-mediacenter/ui/public/js/voiceprint-panel.js`、`websocket.js`：声纹页面内的全局设置与状态同步。

## 自测用例

1. 关闭模式下普通语音仍立即进入正常聊天。
2. 手动模式下确认前不产生 `chatInput`、Pi 请求或聊天历史，确认后只提交一次原始文本。
3. 手动模式 30 秒超时、取消和拒绝均不提交。
4. 自动模式在 TTS 完成后 7 秒内取消不提交，窗口结束后只提交一次。
5. TTS 失败时天气弹窗仍显示，待确认状态按模式继续，不自动误提交。
6. 确认倒计时位于唤醒倒计时之后且有背景，旋转布局不换行。
7. 三档模式可由控制端设置并持久化，也可由免唤醒语音命令切换。

## 兼容性测试

- 未升级的显示端忽略新确认消息时，服务端仍不在确认前调用聊天；控制端旧页面不影响服务端配置。
- 现有提醒、播放选择和内置命令确认流程继续独立运行。
- 服务器重启后从持久化配置恢复模式，内存中的待确认内容安全丢弃。

## 性能测试

- 每个待确认记录最多一个超时计时器，完成后立即清理。
- 显示端确认倒计时复用单个 interval，不创建新的录音链路。
- 不增加 Pi 进程数量，确认前不启动 Pi 请求。

## 风险评估

- 自动模式存在误提交风险，因此只允许“取消/拒绝”阻止，并将窗口固定为 7 秒。
- TTS 失败时只能依靠弹窗和语音取消，必须确保弹窗先于 TTS 异步生成发送。
- 多显示端同时输入时按来源 `displayId` 保存待确认，避免确认串台。

## 预计工时

约 2～3 小时，包含测试、文档同步和回归验证。

- ✅ 已完成普通语音确认前拦截，确认后复用正常聊天/Pi 路径；取消和超时不会写入历史。

- ✅ 已将声纹页面主要设置统一为大卡片布局。
- ✅ 已清理旧提醒确认弹窗中的 5 秒自动确认错误提示，并同步修正规格说明。
- ✅ 已通过确认状态机、语音路由、TTS、Pi、显示端 UI 和旋转布局相关回归测试。
