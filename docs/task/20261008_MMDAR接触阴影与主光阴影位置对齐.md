# MMD-AR接触阴影与主光阴影位置对齐

## 任务描述

用户反馈接触阴影的位置与主光源阴影有偏差。用户已确认修正方案：接触阴影沿用主光现有`bias/normalBias`接收面偏置，并改进接触阴影alpha的几何引导上采样；SSGI RGB与其他设置保持不变。

## Design需求

- 主光阴影有效时，从DirectionalLight shadow读取`normalBias`及正交阴影相机范围换算`bias`。
- 将等效偏置用于接触射线起点，保留屏幕像素量化保护偏置。
- 上采样只对接触阴影alpha选择几何权重最高的同表面样本；SSGI RGB仍按现有双边权重平均。
- 不增加配置、不修改正式显示端、不增大目标分辨率和射线步数。

## Spec设计

见`docs/spec/mmd-ar-test-apk.md`的“接触阴影对齐主光阴影偏置与边界”。

## 自测与兼容性

- 检查主光阴影启用时bias换算、关闭时偏置归零、接触阴影参数及SSGI路径保持。
- 检查上采样只改变接触阴影alpha，SSGI RGB依旧采用原几何权重平均。
- `npm run build:web:mmd-ar-test`构建本地网页；本任务不增加或执行自动测试。
- 目标浏览器同视角对照接触阴影/主光shadow map边缘；无主光阴影、阴影来源切换、不同模型及相机距离确认。

## 性能与风险

- 不新增纹理、采样循环或分辨率，渲染开销预期基本不变。
- 深度重建几何法线可能不同于材质平滑法线，透明/屏外表面仍有屏幕空间限制；Alpha选样可能令低分辨率边缘略显阶梯。
- 浏览器同视角及设备GPU观感待用户现场验收。

## 执行结果

实现完成：`web-screen-lighting.mjs`为接触射线增加主光`normalBias`及按正交阴影相机深度范围换算的`bias`；主光shadow map未启用或非正交相机时两项置0。`web-screen-lighting-shader.mjs`只对接触alpha选择几何权重最高的效果样本，SSGI RGB仍使用原双边加权平均。`npm run build:web:mmd-ar-test`成功，本地`web-dist`已更新。

未运行自动测试；尚未在目标浏览器同视角确认阴影边界差异，未发布外网。验收重点：主光阴影开启/关闭、bias调节、不同距离及平滑法线位置；若几何法线近似产生残余偏差，再按现场画面决定是否需要法线缓冲或提高接触阴影分辨率。
