# 任务：ASR 压测脚本

## 任务描述

补充一个可直接对服务端 `/api/asr/recognize` 发起并发请求的压测脚本，用于复现和验证服务端语音识别 RSS 上涨问题是否已修复。

## Design 需求

### 压测能力
- 支持指定服务端 URL、音频文件、总请求数、并发数和超时
- 支持统计成功、忽略、429 忙碌、失败数量
- 支持周期性输出当前进程的 RSS / Heap / External / ArrayBuffers
- 没有现成音频文件时自动生成一个可用的 WAV 样本，降低使用门槛

## Spec 设计

### `scripts/asr-stress-test.js`
- 解析命令行参数
- 自动生成或读取测试音频
- 手动构造 multipart/form-data 请求体
- 使用 `http` / `https` 发起请求
- 通过 worker 池控制并发
- 汇总耗时、延迟和内存指标

## 自测用例

1. 执行 `node scripts/asr-stress-test.js --total 5 --concurrency 2`
2. 确认脚本自动生成测试 WAV 文件
3. 在服务端启动时执行压测，确认能输出 success / ignored / busy429 / failed 统计
4. 并发数调高后确认能观察到 429 忙碌返回
5. 观察日志输出中的 RSS / ArrayBuffers 是否进入平台期

## 兼容性测试

- Windows PowerShell
- HTTP 和 HTTPS 服务端地址
- 未提供音频文件与提供自定义音频文件两种模式

## 性能测试

- 默认 50 次请求、5 并发作为基础验证
- 高并发模式用于验证队列保护是否生效

## 风险评估

- 低风险：脚本独立运行，不影响线上逻辑
- 低风险：自动生成音频仅写入临时测试文件
- 中风险：压测时会放大服务端负载，应避免在生产高峰期执行
