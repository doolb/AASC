# Offline 本机模型入口下移与边缘收起

## 任务描述

修复 Offline APK 显示页左上角“本机模型”入口覆盖 FPS 的问题，并使入口支持像原生控制端按钮一样收起到屏幕边缘。入口还需避开 Android 原生控制端按钮的左上占用区。

## 需求等级

- 主等级：L6，定义入口状态和按钮交互契约。
- 次等级：L5，定义显示位置、安全区和遮挡边界。
- 评审结论：可开发；影响限于 Offline 显示页交互，风险低。

## Design 需求

1. 本机模型入口位于 FPS 下方，并与 Android 原生左上控制端按钮纵向分离；原生收起把手高度为 72 dp，网页入口纵向起点至少为 84 CSS px。
2. Offline 原生模型能力存在时，入口初始为贴左边缘的收起把手；没有能力时继续隐藏入口。
3. 点击把手展开主按钮和收起按钮；主按钮保留现有 `NativeDisplay.offlineShowModels()` 行为；收起按钮恢复边缘把手。
4. 入口继续按显示舞台旋转映射、安全区和软键盘内缩布局；不改变模型状态查询、下载、加载或 APK 原生逻辑。
5. 网页显示资源按服务代码包交付，标记 `servicePackage=true`；不标记 `minApk`。

## Spec 伪代码

见 `docs/spec/android-display-offline-apk.md` 的“本机模型入口位置与边缘收起”。

```text
如果 Offline 原生模型能力存在
  显示入口容器并初始化为收起状态
  点击边缘把手 → 展开主按钮和收起按钮
  点击主按钮 → 调用现有本机模型列表原生桥
  点击收起按钮 → 恢复边缘把手
否则
  隐藏整个入口容器

入口纵向位置 := max(84 CSS px, 安全区顶部 + 键盘顶部内缩 + 间距)
入口与 FPS 及原生控制端左上按钮保持分离
```

## 自测用例

1. Offline 原生桥可用且模型列表非空时，初始显示左边缘把手；点击后显示主按钮和收起控件。
2. 点击主按钮调用原有模型列表桥；点击收起控件恢复边缘把手；展开状态的 ARIA 属性与实际控件一致。
3. 没有 Offline 模型能力时整个入口隐藏；其他显示端按钮和模型准备流程不变。
4. FPS、控制端把手和模型入口不重叠；考虑安全区、键盘内缩和舞台旋转映射。

## 兼容性与性能

- 仅复用现有 Offline 原生桥和网页样式；不新增网络接口、原生方法或持久化状态。
- 控件状态只在点击时切换，不创建定时器、动画循环或逐帧计算。
- 不需要重建 min APK；新网页资源通过服务代码包更新。

## 风险评估与预计工时

- 风险：Android 原生按钮处于 WebView 上层；若 CSS 坐标或安全区映射错误，仍可能出现遮挡。通过明确预留 72 dp 原生区域并让网页入口至少从 84 CSS px 开始规避。
- 风险：浏览器 `hidden` 默认样式可能被布局规则覆盖；显式定义入口各状态的隐藏样式并由自测诊断状态。
- 预计工时：实现与文档 1 小时，设备验收另计。
