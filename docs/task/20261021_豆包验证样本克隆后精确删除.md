# 豆包验证样本克隆后精确删除

## 任务描述

用户要求“克隆完把创建的临时聊天删了”。本项加入Android登录样本克隆修复，清理仅针对当前捕获尝试成功新建并被同次SSE确认的官网会话；先前uncertain旧会话清理仍保持仅记录。

## 需求与设计

见`docs/design/chat2api-doubao-web.md`对应段。明确性检查通过；主等级L6（单ID与来源/结果契约），次等级L5（克隆→清理→完成/重试），三项证据为用户明确清理要求、官网实际请求、真实成功回执。按enterprise默认模式评审可开发，建议下放L4，以捕获尝试、新ID和清理状态串联。用户已通过“直连和兼容都修复下”确认合并实施；源码接入、定向测试及真机验证已完成。

## 当前官网证据

- 精确核对上轮“早”测试会话只有一条用户消息及一条回复后，由官网菜单删除，页面回空白聊天且原链接消失。
- 新测试样本先用CDP在内存确认新会话请求、非空完整SSE与ACK ID，再经官网UI删除；只删除同次ID，HTTP200/status_code0/OK。
- 实际路径`/im/conversation/batch_del_user_conv`，POST；报文cmd4171，内层单项conversation_id、delete_all=false、conversation_type3，外层独立sequence_id、channel2、version1。
- 官网头为`application/json; encoding=utf-8`与`agw-js-conv: str`。普通JSON头返回712012002；按实测头对同一已删除样本重试，仍HTTP200/status_code0，确认精确重试可用。
- 所有操作使用当前Android已登录WebView，没有搜索网络文档或打印Cookie/CSRF/签名。未向当前AASC对话写入测试消息。

## 风险与预计工时

风险是误用当前页面ID或宽泛批量删除，以及把HTTP200错误体当成功；用同次ACK、单ID和status_code三重约束。官网协议变化时保留资料并提示，不猜测删除目标。预计实现及定向测试约1小时，出包和真机回归约1小时。用户已明确合并运行时恢复，执行记录见联合修复任务。
