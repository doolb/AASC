# 当前实际角色姿态投影到图片并微调

状态：已实现并完成桌面验证，代码已准备提交；手机验收另记todo。

追加关联：用户继续要求一键定位到参考图片的相机角度，方案见`docs/task/20261015_MMDAR图片相机视角匹配.md`。相机匹配成功后固定对照视角，继续在3D微调；先前只读方案核查仅覆盖叠加，不包含新增相机求解与仲裁。

## 需求与待确认

用户希望“投放当前实际人物pose到图片上，让我可以微调实际pose，去还原图片”，已明确选择“参考图只显示实际骨架，在3D场景里拖控制点调整”。继续限定全身IK图片姿态面板，不提供图片关节拖动或半透明人物渲染。

## 已确认的代码依据

- `web-human-ik.mjs`输出`target`与`achieved`，`screen`来自控制点标记，不是实际骨骼的图片投影。
- `web-human-interface.mjs`已有目标设置、IK状态与模型代次，但需增加图片投影/编辑的受控接口。
- `web-human-pose-ui.mjs`已有本地图片与ONNX参考点；`web-human-ik-ui.mjs`管理开关/收起和500ms状态同步，实际骨架叠加需独立受控刷新。

## design/spec实施方案

对应`docs/design/mmd-human-interface.md`与`docs/spec/mmd-human-interface.md`顶部。使用求解后真实骨骼绘制，参考与实际分色；开启时捕获当前视角，图片平移/等比缩放独立固定，显式按钮可重取投影。图片不改骨骼目标，3D控制点仍按原规则求解；限位/碰撞可能使实际点与目标不同。叠加可在IK关闭或未识别图片时使用。具体控件及刷新频率是拟定实现选择，尚待用户确认。

## 验证、风险与预计工时

- 自测：实际骨骼/目标点区分，投影宽高比、真实PMX姿态变化，固定相机与对齐、显示不写目标、缺失点，模型token及可见性/销毁，既有粘贴/识别/应用回归。
- 兼容性：桌面鼠标与手机Pointer Events触控，透视/正交与舞台旋转，不复用主画布像素当图片像素；手机实机另外验收。
- 性能：原图底图缓存，只在可见编辑时受控刷新，不重复执行ONNX或在每帧复制整张原图；收起/销毁停止刷新。
- 风险：二维不能唯一还原前后关系；全局图片对齐不能替代姿态调整；物理解算未达目标时必须保留真实反馈，不能通过重拟合掩盖误差。
- 实际骨架对照预计1～2小时实现与本地回归；手机实物另验，不增加模型下载或ONNX推理次数。
