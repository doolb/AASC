# 服务代码包 v34 发布

## 任务描述

在 Offline min APK v34 发布后，重新生成当前服务代码包并发布到家庭内网和外网。依赖 lock 指纹未变化时继续复用 dependencies v6，不构建完整 APK。

## Design 需求

- 服务代码版本从 v33 升级到 v34。
- 服务依赖保持 v6，必须校验 `requiredDependencyVersion` 和 `lockSha256` 一致。
- 清单中的 min APK 保持 v34，不能因使用旧构建清单回退到 min v33。
- 发布目标为本机 `/mnt/aasc-offline` 和外网 `as@120.79.245.103:~/a/aasc-offline`。

## Spec 设计

- 读取当前已发布清单，使用 `code-only` 生成 `code/code-v34.zip`。
- 生成服务清单时保留当前 `dependencies-v6` 和 `apkMin-v34` 组件。
- 发布顺序为本地/远端资源校验、版本文件上传、原子替换 manifest、LAN/WAN 验证和严格版本清理。

## 受影响的功能模块和代码

- `scripts/ops/offline-update-package.js`
- `scripts/ops/publish-offline-update.js`
- `release/offline-update/output-publish-v34/` 构建输出
- Offline 服务更新清单和发布目录

## 自测用例

1. code 包 version 为 34，依赖版本为 6，lock 指纹与 dependencies v6 一致。
2. code ZIP 可正常读取，文件大小和 SHA-256 与签名清单一致。
3. min 组件仍为 versionCode 34。
4. 内网和外网 manifest 均切换到 code v34，HTTP 资源校验通过。
5. 旧 code 版本按严格数字版本规则清理，dependencies v6 和 min v34 保留。

## 兼容性测试

- 复用现有 dependencies v6，不触发依赖更新。
- 不构建、不替换完整 Offline APK。
- 保留 min APK v34 与 code v34 的清单兼容关系。

## 性能测试

- 代码包使用现有流式 SHA-256 校验。
- 发布验证会读取依赖和 APK 资源，确保两端清单与资源一致。

## 风险评估

- 若使用旧清单生成服务包，可能把 min 组件回退到 v33；本次使用发布后的当前清单生成并验证为 min v34。
- 远端网络校验耗时较长，但发布器在清单切换前完成资源校验。

## 预计工时

约 20 分钟，包括服务代码归档、签名清单生成、内外网发布和完整性验证。
