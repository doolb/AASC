# 私聊角色与 session 名称只读查看

## 任务描述

在已有聊天历史 CLI/TUI 基础上增加 `--sessions` 参数：不填写 `target` 时查看全部私聊 session，并补充群聊条目，显示角色名和基于聊天记录生成的 session 名。私聊名称只对原始配置执行一次迁移；查看命令不得新增服务端 API 路径，也不提供发送、删除、切换或修改操作。

## Design 需求

- 扩展现有 `GET /api/chat/sessions`：带 target 时保持原返回；省略 target 时返回所有目标的扁平 session 列表。
- 复用现有 `GET /api/chat/history` 识别群聊，不把聊天消息放入 session 输出。
- CLI 输出 `{ status, sessions: [{ target, name }] }`，其中 target 为私聊角色名、name 为 session 名。
- 一次性将技术 session 名替换为对应 session 的首条用户消息标题，并写回原始 session 配置。
- `--target` 在 `--sessions` 下保持可选，填写时只过滤 session 列表。
- `--sessions --tui` 只显示角色名和 session 名，不显示聊天记录、ID 或时间。

## Spec 设计（伪代码）

```
chat-history.js --sessions:
    读取 GET /api/chat/sessions，可选传入 target
    读取 GET /api/chat/history，仅查找 mode=group 的首条用户消息
    有群聊历史时追加 { target: 群聊, name: 首条用户消息 }
    按 mode、target、sessionId 过滤 sessions
    每项只保留 { target: 角色名, name: session 名 }
    输出 { status, sessions }
    如果选择 tui:
        只显示角色名和 session 名

GET /api/chat/sessions:
    如果有 target:
        返回指定目标的原有 session 数组
    否则:
        收集会话配置和私聊历史中的全部 target
        恢复每个 target 缺失的 session 元数据
        返回带 target 的扁平 session 数组

一次性原始数据迁移:
    按 target/sessionId 扫描私聊历史
    将 qwen-import-* 等技术名称替换为最早用户消息的短标题
    把新增或重命名的 session 写回 chat-session.json
```

## 自测用例

1. `chat-history.js --sessions` 不要求 `--target`。
2. `--sessions` 只输出全部 session 的角色名和 session 名，不输出聊天记录、ID、createdAt。
3. `--sessions --target 小爱` 只输出小爱相关 session。
4. `--sessions --tui` 只显示角色名和 session 名面板。
5. 带 target 的原有 `/api/chat/sessions` 返回格式不变。
6. 脚本只调用 GET，不调用 POST、PUT、DELETE。

## 兼容性测试

- 不增加 HTTP 路由；现有 `/api/chat/sessions?target=TARGET` 保持数组返回格式。
- 旧版 `user/assistant` 和现代 `role/content` 历史继续兼容。
- 不要求 target 的新分支仅返回私聊 session；群聊 default 仍由 history 记录表达。

## 性能测试

- `--sessions` 固定一次 GET 请求，在客户端内存中完成过滤和名称裁剪。
- 不轮询、不启动常驻进程、不写入额外文件。

## 风险评估

- session 名称和角色名可能包含用户敏感信息，CLI 和 TUI 不落盘但终端输出需由用户自行保护。
- 没有聊天记录且没有持久化元数据的目标无法凭空发现；有配置或历史的目标均会被汇总。
- session 元数据可能缺少角色名时，target 参数可为带 target 的旧接口返回补回角色名；没有来源时显示“未知角色”。
