# http 媒体库获取文件大小 + 批量播放视频 seek

## 任务状态：✅ 已完成

## 设计需求

参考：[design/media-library.md](../design/media-library.md)（http 媒体库获取文件大小 + 批量播放视频 seek）

## 问题描述

1. **控制端媒体库不显示 http 库文件大小**：HttpProvider 的 list/getFile 不返回 size（fancy-index 目录列表只有人类可读大小如 `531M`，无法精确还原字节），界面显示 0
2. **批量播放视频无法 seek**：库代理端点 Range 解析依赖 `getFile().size`，http 库 size 未知时恒回落 200 全量，播放器拖动进度条会重新全量下载

## 根因

- HttpProvider 未实现 HEAD 请求获取精确大小
- MediaLibraryManager 缺 getFile(libraryId, filePath) 委托方法 → proxy 端点调 `mediaLibraryManager.getFile` 抛错被 `catch(e){}` 静默吞掉，range 恒 null

## spec 设计

参考：[spec/media-library.md](../spec/media-library.md)（HttpProvider list/getFile/_fetchHead + manager.getFile 委托）

```
_fetchHead(url):
    HTTP HEAD(url, {超时: requestTimeout})
    非 200 / 失败 / 超时 → null
    返回 { size: Content-Length, modifiedTime: Last-Modified }

getFile(filePath):
    sizeInfo = _fetchHead(_buildUrl(filePath) 去尾斜杠)
    返回 { name, path, type, mediaType, size: sizeInfo?.size||0, modifiedTime: sizeInfo?.modifiedTime||null, url }

_fetchList(dirPath):
    items = _parseHtml(html, dirPath)
    对 mediaType ∈ [image,video,gif,html] 的 file 项并发 HEAD（小并发池 6）补 size/modifiedTime
    单文件失败回落 0，不阻塞列表浏览

MediaLibraryManager.getFile(libraryId, filePath):
    获取 library → provider.getFile(filePath)
```

## 自测用例

1. mnt 库 list 返回真实 size：60 文件 56 个有值（0.36s 并发 HEAD），文件夹不 HEAD
2. getFile 返回 size + modifiedTime（本地 mock 服务器断言精确字节与日期）
3. 库代理 Range 端到端：`Range: bytes=0-99` → 206 + Content-Range `bytes 0-99/43690`
4. 播放列表 buildFromLibrary(mnt) → 60 项全部同源代理 URL
5. HEAD 失败（文件删除）回落 size=0 不抛错
6. `node --test tests/media-library-app-service.test.js` → 11 全绿

## 兼容性测试

- http 库 GET/HEAD 均走同一 Apache，HEAD 返回 200 正常
- 不可达库（192.168.1.101）：HEAD 超时回落 0，列表浏览不阻塞（8s 超时保证）

## 性能测试

- 小并发池（6）限制 HEAD 并发，60 文件 0.36s 完成
- 库代理 Range 206 分段返回，seek 不再全量下载

## 风险评估

- HEAD 失败回落 0：仅影响大小显示与 Range 解析（回退全量 200），不影响播放
- 修复 manager.getFile 后，本地/SMB 库代理 Range 也受益（此前同样静默回落）
- 低：仅新增委托方法 + 补 size 字段，不改播放链路
