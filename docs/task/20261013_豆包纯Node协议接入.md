# 豆包纯Node协议接入

- 需求：使用当前授权账号，参考doubao2api及其它Chat2API网页Provider，实现Node独立收发。
- 授权：2026-10-13用户扩大限制，允许推进真实诊断；账号秘密只留内存，不操作主服务器或无关页面。
- design：docs/design/chat2api-doubao-web.md；spec：docs/spec/chat2api-doubao-web.md。
- 完成证据：去签名及Node自行构造新会话验证成功；正式Provider工厂和CoreAdapter在断CDP后，流式/非流式均实际回复OK并正常结束。只在内存初始化凭据，不使用网页fetch或签名。
- 步骤：对比协议→去签名诊断→自行构造请求/新会话验证→说明最终文件方案→先同步spec→实现→模拟和真实验收。
- 实际模块：新增doubao-node-protocol及测试；修改doubao-chat-adapter、core-adapter、data-store、load-balancer、secret。复用Runtime已有工厂，无需修改启动器。
- 独立审查：两项重要问题先RED再GREEN修复（公开profile泄漏、混合账号轮询）；旧Provider参数调用契约保持。格式校验/导入、token优先级、跳转拒绝与取消等新增8项通过。
- 验证：Chat2API 181/184，同3项既有Windows chmod失败；Ogg/WASM21/21，旧TTS19/19。真实验收不代替think/expert/长期令牌/多账号/设备验证。
- 发布：servicePackage=true，dependenciesPackage/minApk保持既有值；未构建或重启主服务，真实账号包未写入。
- 自测：协议字段/凭据校验、错误脱敏、禁止重定向、取消/超时/容量、流式与非流式、旧Provider回归。
- 兼容性：Windows Node验证；Android/Linux不自动宣称通过；保持WAV/TTS和网页模式已有行为。
- 性能：沿用120秒和8MiB上限；不新增无限队列或周期后台诊断。
- 风险：动态协议、账号风控和令牌有效期；浏览器生成签名的Node重放不等于独立Node。
- 预计工时：随协议验证结果调整；不得把模拟通过或HTTP200等同于成功回复。
