# 聊天助手工作 AI 角色成员选择

## 任务描述

聊天列表自动展示 `ai-roles` 已保存角色；点击“+”打开只读列表选择窗口，扫描 `workgroup/members` 的成员目录并选择成员创建工作 AI 角色，不允许手动输入角色名。

## Design 需求

- 复用现有 `roleList` 作为已保存角色/在线状态来源。
- 新增只读 `roleCatalog` 消息扫描 `workgroup/members` 直接子目录。
- 候选展示成员目录名、`role.md` 中的 `primary`/`secondary`、`role.md` 和 `history.md` 是否存在。
- 选择后以成员目录名作为 `ai-role` 名称，重复候选标记为已添加且不可重复创建。
- 弹窗只渲染成员候选列表，不提供角色名称输入框或手动添加按钮。
- 弹窗标题、成员名、状态文字、背景、边框和按钮使用控制端主题变量，确保浅色主题下文字清晰可读。
- 不向控制端发送角色文件正文、历史正文和绝对路径。

## Spec 设计

- `roleCatalog` 请求返回 `{ type, members }`。
- `AiRolesService.memberCatalog()` 只返回候选元数据。
- `roleAdd` 继续负责名称校验、角色目录创建和 `roleList` 广播。
- 成员来源角色在提示词/历史读取时优先使用对应成员目录的 `role.md`/`history.md`，保留既有 `workgroup/roles/<name>.md` 和 `control-<name>` 兼容路径。

## 自测用例

1. `workgroup/members` 不存在或不可读时，`roleCatalog` 返回空数组，不影响已有 `roleList`。
2. 成员目录包含 `role.md` 时，正确解析 `primary` 和逗号分隔的 `secondary`。
3. 成员目录缺少 role/history 文件时，仍返回候选并标记文件不存在。
4. WebSocket `roleCatalog` 返回候选元数据，扫描异常返回 `roleError`。
5. 聊天初始化显示已保存 `ai-roles`，点击“+”打开弹窗并请求候选；已添加候选不可重复选择。
6. 选择候选后复用 `roleAdd`，成功广播 `roleList` 并显示新角色页签。
7. 弹窗不包含手动输入框、手动添加按钮或对应前端方法，只能从候选列表选择。
8. 浅色主题下，弹窗文字、成员行和按钮与背景保持可读对比度；`control-mainfornt` 的历史记录状态显示为“有历史记录”。

## 兼容性测试

- 保持既有 `roleList`、`roleAdd`、`roleDelete`、`roleHistory` 协议不变。
- 保持无 `workgroup/members`、空 `role.md`、旧 `ai-roles` 目录的兼容行为。
- 运行 Node.js 现有角色测试和控制端静态契约测试。

## 性能测试

- 成员目录仅扫描一层，不读取历史正文；目录数为常规工作组规模时应同步完成。
- `roleList` 广播不携带成员目录内容，避免聊天状态刷新变大。

## 风险评估

- 成员目录名可能与聊天模板或已有 ai-role 重名；前端显示冲突状态，服务端继续执行最终校验。
- `role.md` 字段格式可能不完整；解析失败按空字段处理，不阻断候选列表。
- 工作组成员目录是运行态与历史混合目录；只读扫描，不修改或删除其中任何文件。
