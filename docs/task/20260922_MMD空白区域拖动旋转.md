# MMD 空白区域拖动旋转角色

## 任务描述

为显示端 `displayMmdCanvas` 增加空白区域拖动旋转。按下时使用现有 Raycaster 判断：命中角色时继续执行既有轻点互动；未命中角色时，水平拖动旋转当前 PMX 或 VRM 角色。

## Design 需求

- 角色命中判定必须发生在按下时，防止从角色拖向空白区域时误触发旋转。
- 旋转仅改变本地模型 Y 轴朝向，不写入远端配置、不发送 WebSocket 消息。
- 聊天层打开、MMD 隐藏、模型未加载时不响应拖动。
- 使用 Pointer Capture 覆盖拖出 Canvas 的结束场景；取消、松开和模型切换后不得残留拖动状态。
- Canvas 降级占位保留现有点击反馈，不模拟 3D 旋转。

## Spec 设计

```text
pointerdown 计算 Raycaster 命中
命中角色 -> 记录点击候选
空白 -> 记录 pointerId 和坐标，捕获 pointer
pointermove 的空白 pointer -> 计算 deltaX，调用当前 runtime 旋转 Y 轴
pointerup/cancel -> 释放 pointer，完成阴影范围刷新，清理状态
角色点击候选的位移小于阈值 -> 发布既有 mmd.interaction
```

## 自测用例

1. 空白区域按下并水平拖动时调用 PMX/VRM 的模型旋转入口。
2. 命中角色后的轻点仍发布 `mmd.interaction`。
3. 命中角色后拖动不进入空白旋转。
4. `pointerup` 和 `pointercancel` 都释放拖动状态。
5. 聊天层打开、MMD 隐藏或模型未加载时不旋转。

## 兼容性测试

- PMX 和 VRM runtime 使用一致的 `rotateModelBy`/`finishModelRotation` 接口。
- 触摸、鼠标和触控笔均沿用 Pointer Event。
- 运行时降级为 Canvas 占位时不抛错，既有轻点反馈保持可用。

## 性能测试

- 每次 `pointermove` 只应用一次水平角度增量；阴影范围仅在拖动结束时刷新。
- 不创建额外 WebSocket、网络请求、模型副本或动画循环。

## 风险评估

- 低风险：改动局限于现有 Canvas 交互和两个本地 runtime。
- 需防止 Pointer Capture 未释放导致后续点击失效，因此所有结束路径统一清理。
