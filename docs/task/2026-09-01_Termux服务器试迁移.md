# Termux 服务器试迁移

## 任务描述

将当前 AASC Node.js 服务器复制到 Android 9 arm64 设备的 Termux 环境中进行可运行性验证，并以 Termux runit 服务方式保持运行。试运行不停止设备已有的 code-server，不实现 ASR、TTS Wine 和 Puppeteer 能力。

## Design 需求

- Android 设备作为独立 AASC 服务器节点。
- 使用 Termux 提供 Node.js、npm 和进程管理环境。
- 使用独立目录和 18081 端口，避免占用现有 8081。
- 保留 HTTPS、HTTP 静态页面、WebSocket 和媒体资源主链路。
- 记录 Android 不兼容模块，不因可选模块失败阻止核心服务启动。

设计文档：`docs/design/android-termux-server.md`。

## Spec 设计

- 源码、配置和资源同步到 `~/aasc-server-test`。
- 使用 Termux npm 安装依赖，跳过安装脚本和 Puppeteer 浏览器下载。
- 使用 `$PREFIX/var/service/aasc-server-test/run` 启动服务。
- 日志写入 `~/.local/state/aasc-server-test/log`。
- 使用 `/api/status`、`/upload` 和 `/display` 进行验证。

实现文档：`docs/spec/android-termux-server.md`。

## 受影响功能模块和代码

- 运行时：`src/apps/server/boot/server-launcher.js`、`src/apps/server/boot/server-app.js`。
- 服务依赖：`package.json`、`package-lock.json`。
- 运行资源：`config/`、`res/`、`src/apps/web-mediacenter/`。
- 远程部署目录：`/data/data/com.termux/files/home/aasc-server-test/`。
- Termux 服务目录：`/data/data/com.termux/files/usr/var/service/aasc-server-test/`。
- 本次没有修改仓库内业务代码；远端只生成试运行配置备份和 runit 服务文件。

## 兼容性测试

- Android 版本：9（API 28）。
- 设备：Samsung SM-N9500。
- ABI：arm64-v8a。
- Termux：0.118.3。
- 网络：局域网 HTTPS 访问通过。
- 现有 8081 code-server：未停止、未修改。

## 性能测试

- 启动后服务 RSS 日志约 102MB，作为初步观测值。
- `/api/status` 连续运行期间可正常返回，未观察到服务重启。
- 本次未进行媒体大文件上传、WebSocket 长连接、并发显示端和长时间功耗测试。

## 风险评估

- Android 电池优化可能在后台终止 Termux 或 runit；需要 Termux:Boot、Wake Lock 和系统电池白名单验收。
- Android 9 设备与部分原生 Node 模块、Puppeteer 浏览器和 Linux 工具存在兼容性风险。
- 当前测试目录复制了配置和证书，正式多节点部署必须增加节点认证和密钥隔离。
- 当前端口为临时 18081，正式部署需要节点端口自动配置和主服务器发现/注册。
