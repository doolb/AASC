# 控制端选择显示端声音输出设备

## 任务描述

在正式 Android 显示端增加声音输出设备枚举与路由选择，控制端通过 AASC WebSocket 远程配置并显示实际路由和回退状态；显示端重启后恢复服务端保存的设备 key。

## design 需求

- 正式 APK 输出设备由 Android `AudioManager.GET_DEVICES_OUTPUTS` 枚举。
- 控制端选择按 `displayId` 持久化，复用现有远端配置链路，不增加 HTTP 配置接口。
- Android 12+ 尝试 `setCommunicationDevice`；API 26–30 采用扬声器/听筒、蓝牙 SCO 或系统默认媒体路由，并明确报告限制。
- 设备断开时保留请求 key，实际路由回退系统默认。

对应设计：`docs/design/android-display.md`、`docs/design/websocket.md`。

## spec 设计

- 新增 `AudioOutputDevice.kt` 和 `NativeAudioOutputController.kt`。
- NativeBridge 新增设备列表、设置设备和状态查询方法。
- 服务端新增 `audioOutputDeviceKey`、`setAudioOutputConfig`、`audioOutputConfig`、`requestAudioOutputDevices`、`audioOutputDevices`、`audioOutputStatus`。
- 控制端在现有语音/VAD 设置卡中提供输出设备选择和刷新按钮。

对应伪代码：`docs/spec/android-display.md`、`docs/spec/websocket.md`。

## 自测用例

1. 静态契约检查确认服务端、控制端、显示端和 NativeBridge 消息名称一致。
2. 无输出设备或仅系统默认时，控制端仍显示“系统默认”，不抛异常。
3. 选择原生输出设备后，服务端保存 `audioOutputDeviceKey`，控制端收到权威配置和状态。
4. 服务器/显示端重连后重新下发配置并调用原生路由。
5. 设备断开后状态包含 `fallback=true` 或 `routingMode=system_default`，不伪造实际设备。
6. 录音使用 SCO 时，停止录音不会释放仍由输出配置占用的 SCO owner。

## 兼容性测试

- Android API 28：验证内置扬声器、系统默认、AIMIC-M4 SCO/蓝牙设备的列表与回退状态。
- Android API 31+：验证可用通信设备的 `setCommunicationDevice` 成功与不可用设备回退。
- 浏览器显示端：无 NativeBridge 时保持默认输出并不影响原有媒体播放。
- 旧版显示端：忽略新增 WebSocket 消息，不影响录音和媒体播放。

## 性能测试

- 设备枚举只在能力声明、控制端刷新和重连时执行，不进入音频 PCM 循环。
- 输出配置不创建额外 `AudioRecord`，路由切换不复制模型、不增加 ASR/TTS 线程。
- 控制端状态按已有显示端列表刷新，不缓存音频数据。

## 风险评估

- Android API 26–30 缺少面向 WebView 媒体流的通用输出设备 API，A2DP/有线设备可能只能走系统默认媒体路由；通过状态字段明确降级。
- `setCommunicationDevice` 主要面向通信音频，部分 ROM/WebView 可能不影响普通媒体流；失败时恢复系统默认。
- 蓝牙 SCO 同时用于输入和输出，使用 owner 计数避免一方停止时误释放另一方链路。
