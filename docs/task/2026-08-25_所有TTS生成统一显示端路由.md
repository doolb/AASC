# 所有 TTS 生成统一显示端路由

## 任务描述

当配置 `tts.device=display` 时，所有服务端发起的 TTS 生成都优先交给在线且具备 `ttsGeneration` 能力的显示端；显示端不可用、模型未就绪、生成失败或超时后回退服务器 TTS。生成完成后的音频播放目标和原有路由保持不变。

## design 需求

- 统一入口为 `generateTtsWithFallback(text, voice, speed)`。
- API、聊天、Agent、文本媒体、语音指令、提醒、整点报时等入口不得直接调用底层 `tts.generateTTS`。
- `tts.generateTTS` 只允许出现在统一 fallback 函数的最终服务器分支。
- 内置任务通过 TaskManager 注入统一 TTS 函数，避免任务模块直接依赖底层服务。

## spec 设计

```text
任一服务端 TTS 请求:
  text → generateTtsWithFallback
  tts.device == display 且存在 ttsGeneration 显示端:
    ttsGenerate → 显示端异步合成 → WAV 写入服务器 → 返回音频路径
    失败/离线/超时 → tts.generateTTS 服务端回退
  tts.device == server 或无可用显示端:
    tts.generateTTS 服务端生成

TaskManager:
  setGenerateTts(generateTtsWithFallback)
  内置任务上下文提供 generateTTS
  time.announce 使用 context.generateTTS
```

## 受影响功能与代码

- `src/apps/server/boot/server-app.js`
  - 替换系统帮助、指令模式、提醒、部分语音指令等直接 TTS 调用。
  - 向 TaskManager 注入统一生成函数。
- `src/apps/server/modules/task-engine/task-manager.js`
  - 增加统一 TTS 函数注入，并传入内置任务上下文。
- `src/apps/server/modules/task-engine/builtin-tasks/time-announce.js`
  - 改用上下文注入的 TTS 路由。
- `docs/design/android-native-tts.md`、`docs/spec/android-native-tts.md`
- `tests/tts-display-routing.test.js`

## 自测用例

- server-app 只保留 fallback 内部的底层 `tts.generateTTS` 调用。
- 系统帮助、指令模式、提醒和语音指令均使用 `generateTtsWithFallback`。
- 整点报时通过 TaskManager 注入的 `generateTTS` 生成。
- Node 语法检查和相关 TTS/显示端回归测试通过。

## 兼容性测试

- `tts.device=display` 且显示端在线：所有入口优先显示端生成。
- 显示端离线/失败/超时：所有入口自动回退服务器。
- `tts.device=server`：所有入口直接服务器生成。
- 音频仍按原有控制端、源显示端或目标显示端路由播放。

## 风险评估

- 所有入口统一使用显示端后，显示端生成请求并发量会增加；原生 TTS 单线程执行器会串行排队。
- 整点报时、提醒等后台任务也可能触发显示端模型生成，显示端离线时依赖服务端回退。
- 本次不改变播放目标选择，不会把生成设备强制变成播放设备。

## 预计工时

约 1 小时（入口收敛、任务注入、回归与文档同步）。
