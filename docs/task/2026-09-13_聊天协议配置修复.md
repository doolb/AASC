# 聊天协议配置修复

## 任务描述

修复控制端聊天设置只编辑系统提示词和 Agent 后端、无法配置当前 `openai-responses` 请求地址的问题。用户将 Chat Completions 地址配置为局域网地址时，聊天仍然读取旧的 `responsesBaseUrl`，导致 Android APK 将 `127.0.0.1` 错误解析为设备自身地址并连接失败。

## Design 需求

- 在聊天设置中增加调用协议、Responses Base URL 和 Responses API Key。
- 明确 profile 的 `apiUrl` 只用于 `openai-completions` 的 Chat Completions 请求。
- 保持现有 `/api/chat/config` 远端配置流程，由服务端返回权威配置。
- 当前主服务和 offline APK 的 Responses Base URL 均设置为 `http://127.0.0.1:8081/v1`，协议保持 `openai-responses`；offline APK 内置 Node 服务的无配置回退值也必须保持一致。

关联设计：`docs/design/chat-system.md`。

## Spec 设计

- 前端加载/显示/保存 `protocol`、`responsesBaseUrl`、`responsesApiKey`。
- `openai-responses` 请求使用 `responsesBaseUrl + /responses`。
- `openai-completions` 请求继续使用当前 profile 的 `apiUrl`。
- Responses 地址为空时阻止保存；服务端回包覆盖本地配置。

关联实现文档：`docs/spec/chat-system.md`。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/js/chat.js`：聊天配置状态及读写。
- `src/apps/web-mediacenter/ui/public/upload.html`：聊天设置表单和字段说明。
- `config/config.json`：当前部署的 Responses 网关地址。
- `src/apps/server/modules/config/config-app-service.js`、`src/external/llm/llm-service.js`、`src/apps/server/boot/server-app.js`、`src/apps/server/modules/task-engine/builtin-tasks/llm-chat.js`：主服务及 offline APK 内置 Node 服务的默认 Responses 地址。
- `tests/chat-config-transport.test.js`：配置界面、部署配置及 offline APK 默认值回归测试。

## 自测用例

1. 打开控制端“助手 → 聊天设置”，确认协议、Responses Base URL、Responses API Key 字段可见。
2. 选择 `openai-responses` 保存 `http://127.0.0.1:8081/v1`，刷新设置后值保持不变。
3. 选择 `openai-completions`，确认 profile 的 Chat Completions API URL 仍独立可编辑，Responses 字段隐藏。
4. 使用 Responses 协议发起聊天，确认请求目标为 `http://127.0.0.1:8081/v1/responses`。

## 兼容性测试

- 保持旧配置只有 `apiUrl` 时，仍可选择 `openai-completions` 使用原有 profile。
- 缺少新字段时，前端回退到 `openai-responses` 和本地默认地址。
- offline APK 缺少持久化聊天配置时，内置 Node 服务的 Responses 默认地址为 `http://127.0.0.1:8081/v1`。
- 不改变聊天历史、profile 切换、Pi Agent 和 Chat Completions 请求结构。

## 性能测试

- 配置表单仅增加字段读取和一次已有配置请求，不增加聊天请求次数。
- 无额外常驻定时器、模型加载或网络探测。

## 风险评估

- Responses 地址指向的设备必须可被控制端/服务端访问；配置错误时请求仍会按现有错误处理失败。
- `config/config.json` 只调整当前部署的 `responsesBaseUrl`，不覆盖用户已有 profile、API Key 或其他运行配置。
