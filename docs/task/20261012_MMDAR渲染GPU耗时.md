# MMD-AR 渲染 GPU 耗时

- 日期：2026-10-12
- 状态：已完成开发、自测与本地WEB构建；未发布，真机验收待处理。用户“是”确认两端共享后实施。
- 任务描述：在 MMD-AR 现有 CPU 绘制提交耗时旁显示 GPU 绘制耗时，保持 FPS 与物理统计，不把 CPU/GPU 相加为总帧耗时。

## design 需求

对应 `docs/design/mmd-ar-production-offline.md` 的“渲染 GPU 耗时”小节。独立页复用正式性能模块与 PMX runtime，用户已确认独立及正式 PMX/VRM 共享实现。GPU 范围为主角色 renderer 本次绘制、阴影与后处理，排除物理计算、AR 识别和浏览器合成。

## spec 设计

对应 `docs/spec/mmd-ar-production-offline.md` 的实现伪代码。GPU timer 独立模块负责 WebGL1/2 查询适配、固定容量队列、结果异步回收和生命周期失效。沿用实际帧采样，不增加 RAF、finish 或同步读回。有效结果每项只汇总一次，GPU 独立样本计数；不支持、等待、disjoint 和上下文丢失分别回显明确状态。已有活动时间查询时跳过，不嵌套或结束其他模块查询。

## 自测用例

1. WebGL2查询延后可用：不读未就绪结果，纳秒转换毫秒准确，每项只汇总一次。
2. WebGL1扩展适配：创建、开始、结束、轮询、删除接口正确，无扩展明确不支持。
3. 固定容量队列与外部活动query：饱和跳过，不嵌套、不结束其他模块查询；后续可恢复采样。
4. 多结果/跨统计窗口：只按有效GPU样本均值，不重复旧值，无结果窗口不记零。
5. disjoint/查询异常/上下文丢失与恢复：失效旧结果，重新检查能力，诊断失败不阻断原绘制。
6. 隐藏、后台、模型切换、销毁：清理自身query与统计，迟到结果不串模型，监听正确释放。
7. PMX原物理和动画不进入GPU渲染区间；CPU数值与FPS原口径不变，finally可靠结束查询。
8. UI同时显示CPU/GPU毫秒，不支持/等待正确；窄屏不溢出，FPS原位置/指针行为保持。
9. 独立构建新模块存在、导入指纹一致、已有ShadowMap注入锚点保留，无重复定义。

## 兼容性测试

- WebGL1/2支持与缺失扩展；真实桌面浏览器有效query或明确能力状态。
- Android WebView/手机驱动可能屏蔽扩展，不伪造GPU值；有效性和设备性能需真机验收。
- 独立MMD-AR与正式PMX/VRM，共用统计、不共享用户配置；保留原阴影/AO/SSGI/TAA/FSR2及物理后端。

## 性能测试

- 核对无新增绘制/RAF/GPU同步等待、队列容量有界、query完成及时释放。
- 对支持设备比较开关渲染效果的有效GPU窗口值，软件GPU只验证流程，不代表手机速度。
- 低帧率与GPU结果延迟时回显可变慢，保持无结果占位，不承诺实时精确到当前帧。

## 风险评估

- 扩展不可用：显示不支持，CPU/FPS照常。
- query与GPU物理共用上下文：检查外部活动查询，仅测绘制段，不增加物理总GPU查询。
- 模型/后台重置后的迟到结果：统一释放与代次失效，不复用旧数据。
- 独立导入缓存或文本注入冲突：补齐依赖指纹并构建验证，保持原诊断锚点。
- 已有超长runtime不整体重写：核心新增独立GPU模块，入口仅少量接入。
