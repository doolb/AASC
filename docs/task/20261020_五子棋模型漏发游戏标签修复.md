# 五子棋模型漏发游戏标签修复

- 任务描述：真实 `raw` 对话里，模型对“我们来玩五子棋”“H3”“B3”只回复“轮到你落子”，没有输出 Game 标签，导致棋盘不随语音推进。
- 需求判级：主等级 L5（游戏调用流程），次等级 L6（模型输出与 GM 校验契约）；已有现场输入、输出、权威快照及上一版有效提示，结论可开发。风险是模型输出并非确定性协议，须保留服务端权威校验和失败时原棋盘。
- design 需求：保留当前 `raw` 单条 user 消息格式及按需目录/规则设计；补回上一版有效的“标签位于开头、语音用户落子由 AI 代发 User、等待 GM 确认”约束；已有棋局漏发标签时只请模型重新判断一次，服务端不替 AI 开局或落子。
- spec 设计：首轮有活动棋局时缓冲模型普通回复；无标签且轮到 User 则携原始用户话语续问一次；续问给出合法标签后按原桥接流程校验、执行并展示，仍无标签则保持首答和棋盘；普通无棋局聊天保持流式。
- 影响模块和代码：`src/apps/server/modules/game/game-chat-bridge.js`、`tests/game-gomoku.test.js`；不改 `llm-service.js` 的角色消息格式、游戏权威状态文件或显示端 UI。
- 自测用例：原已有棋局收到 `H3`，模型先漏标签再查询目录/规则并发 User、AI 落子，首答不进入聊天或 TTS；已有棋局普通天气聊天即使续问仍无标签，也只显示首答且不改棋盘；无棋局普通聊天继续流式。
- 兼容性测试：运行五子棋定向测试，并用当前豆包模型的隔离 Responses 会话分别验证“我们来玩五子棋”和已恢复棋局的 `B3`，不写用户现有聊天历史或真实棋盘。
- 性能测试：无活动棋局维持一次请求和流式输出；活动棋局首答漏标签时最多增加一次模型请求。目录、规则和合法操作仍受现有回合上限约束。
- 风险评估：模型可能第二次仍漏标签，服务端保留权威棋盘，不伪造成功；活动棋局普通聊天会增加一次模型调用和首字延迟，待真实使用观察。
- 预计工时：约 1 小时。
- 状态：源码与定向测试完成，待服务代码包发布及实际语音回归。
