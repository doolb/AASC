# 控制端入口统一为 control

## 任务描述

将控制端 HTTP 页面入口从 `/upload` 统一为 `/control`，与已有的控制端 WebSocket `/control` 使用同一业务路径；保留 `/upload` 和 `/` 的兼容重定向，内部 `upload.html` 文件名不变。

## Design 需求

- `GET /control` 返回现有控制端页面。
- `WS /control` 保持现有控制端实时通信协议。
- `GET /upload` 重定向到 `/control`。
- `GET /` 重定向到 `/control`。
- 网页服务器列表的节点连接和手动地址连接统一跳转到目标 `/control`。
- 不重命名 `upload.html`、`upload.js` 和 `upload.css`。

## Spec 设计

```text
浏览器访问 /control
    → 服务端返回 upload.html
    → 页面脚本连接 wss://当前主机/control
    → 控制端继续使用原有消息协议

浏览器访问 /upload 或 /
    → 返回重定向 /control
```

## 受影响的功能模块和代码

- `src/apps/server/boot/server-app.js`：新增 `/control` 页面路由，调整根路径和旧 `/upload` 兼容跳转，更新启动日志。
- `src/apps/web-mediacenter/ui/public/js/server-list.js`：手动地址和节点连接跳转 `/control`。
- `tests/server-api-contract.test.js`：增加控制端页面和兼容入口契约。
- `tests/server-list-ui.test.js`：更新手动连接目标断言。
- `docs/design/control.md`、`docs/spec/upload.md`、`docs/usage.md` 及 AASC/Termux 路由文档。

## 自测用例

- `/control` 页面路由存在并返回现有 `upload.html`。
- `/upload` 和 `/` 都重定向到 `/control`。
- `/control` WebSocket 路径继续存在且控制端脚本仍连接该路径。
- 服务器列表在线节点连接和手动输入地址跳转到 `/control`。

## 兼容性测试

- 保留所有 `/upload-file` 和 `/api/*` HTTP 接口，不与控制页面路径混淆。
- 保留 `upload.html` 及其相对 CSS/JS 资源引用。
- 不改变 `/display`、`/server` 和 `/runtime-bridge` 路由。

## 性能测试

- 页面路由只执行一次重定向或静态文件发送，不新增长连接和后台任务。

## 风险评估

- 外部旧书签会收到一次重定向；不删除 `/upload`，因此旧入口仍可用。
- 依赖硬编码 `/upload` 的外部调用仍能打开页面，但后续应统一迁移到 `/control`。
