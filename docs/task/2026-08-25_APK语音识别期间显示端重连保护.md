# APK 语音识别期间显示端重连保护

## 任务描述

排查 APK 原生 ASR/TTS 同步调用期间显示端 WebSocket 不断重连的问题，并修复显示页因多个重连定时器或过期 socket 回调造成的重连风暴。

## Design 需求

- 同一显示页面最多保留一个待执行的 WebSocket 重连定时器。
- 同一页面最多创建一个处于 CONNECTING/OPEN 状态的显示端 WebSocket。
- 旧 WebSocket 的延迟事件不能修改当前连接状态或再次安排重连。
- 页面进入 `pagehide` 后停止重连并关闭当前连接。
- 不改变服务端同 `displayId` 接管旧连接的既有语义。

## Spec 设计

- 在 `docs/spec/websocket.md` 增加显示端重连状态和事件伪代码。
- `display.html` 使用 socket 对象身份校验隔离旧事件。
- `display.html` 统一通过单飞调度函数创建重连定时器。

## 受影响的功能模块和代码

- `src/apps/web-mediacenter/ui/public/display.html`：显示端 WebSocket 生命周期。
- `tests/display-websocket-reconnect.test.js`：重连单飞和页面销毁回归断言。
- `docs/design/display.md`、`docs/spec/websocket.md`：设计和伪代码同步。

## 自测用例

1. 重连过程中再次收到旧 socket 的 `close`，不产生第二个定时器。
2. 旧 socket 的 `message/open/error/close` 事件不影响新 socket。
3. 页面 `pagehide` 后不再创建 WebSocket。
4. 连接正常打开后不触发重连定时器。
5. 运行显示端相关 Node 回归测试和 `node --check`。

## 兼容性测试

- 普通浏览器 display.html。
- Android WebView APK 显示端。
- 服务端同 `displayId` 重连接管逻辑保持不变。

## 性能测试

- 正常消息路径只增加 socket 身份判断。
- 重连路径最多保留一个 3 秒定时器，不增加持续轮询。

## 风险评估

- 页面被冻结后恢复可能只保留断开状态；后续由 `pageshow` 或下一次页面初始化重新建立连接。
- `pagehide` 关闭连接会触发一次 `close`，但页面活跃标记可阻止无意义重连。
