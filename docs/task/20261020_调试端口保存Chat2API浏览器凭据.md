# 调试端口保存 Chat2API 浏览器凭据

## 任务描述与设计需求

用户要求用浏览器 debug port 保存正式账号凭据；只指定 `doubao` 或 `qwen`，默认端口 9222，不手填账号 ID。需与 Android 外部登录复用相同 Provider 资料和服务端保存路径，避免泄露凭据。

设计见 `docs/design/chat2api-doubao-web.md`，伪代码见 `docs/spec/chat2api-doubao-web.md`。

## 受影响模块与实现

- `scripts/ops/save-chat2api-browser-credentials.js`：参数、CDP连接、固定来源 Cookie/资料捕获、账号自动选择和现有管理接口调用。
- `package.json`：增加 npm 入口；不增加生产依赖。
- 定向测试：模拟 CDP 与 Chat2API 管理接口，核对默认值、Provider 映射、同名 Cookie、原账号复用、多个账号拒绝、日志脱敏。
- 文档：design、spec、task、todo、usage、changelog。既有服务代码包待出包状态保持 true。

## 自测、兼容与性能

- 运行脚本定向测试及 `npm run check:chat2api`。
- 当前 Vivaldi 的已登录豆包页尝试保存唯一正式账号，再通过 Responses 单次发送自然短句；记录实际 HTTP/SSE 结果。
- CDP 只连本机；采集与保存均为一次操作，无后台轮询。旧账号 ID 不变化，多个同 Provider 账号不自动选其中一个。

完成结果：脚本定向 5/5、Chat2API 293/293 通过；正式服务重启后，使用已登录 Vivaldi 的 9223 端口更新原 `doubaochat-d56259056231` 账号，快照分别含 `www` 30 项及 `accounts` 24 项，原 Node profile 保留。正式 Responses 流式“早”返回 HTTP 200 但最终事件为 `response.failed`，公开错误码 `doubao_upstream_failed`；没有把 HTTP 200 视作模型成功。千问保存分支仅完成模拟测试，未在未登录网页上操作正式账号。

## 风险评估与预计工时

- 浏览器官网可能变更 Cookie 或 localStorage 结构，缺字段时明确失败；不会猜测替代凭据。
- 千问 ticket 无稳定公开身份字段，单账号时按用户指定 Provider 覆盖该账号；多账号时停止。
- 真正上游风控不由凭据保存操作保证消失。预计 2 小时。
