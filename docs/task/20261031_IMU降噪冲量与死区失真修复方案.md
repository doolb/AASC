## 复现一：多帧降噪改变加速度冲量

独立解析位置：动作源时间1..2秒、p=0.3*sin(π*(t-1))^4米，其他时刻p=0；其解析二阶导数作为x轴加速度。动作起止位置/速度/加速度均归零，峰值位移30cm。无旋转、无噪声、无零偏、无磁场、无静稳/快停/死区/低通，含重力y输入固定9.80665；当前产品引擎接收真实瞬时配对字段，不向估计器注入位置真值。

50Hz关闭降噪，结束速度约-7.4e-17m/s、位置约-2.5e-16m。开启当前300ms多帧降噪，在同一输出源时刻4.7秒时留下速度0.164210910m/s、位置0.525474913m；zeroCorrections=0。说明处理本身改变了原始输入的冲量；并非传感器或姿态真值不准才出现。

25/50/100Hz×动作时长0.8/1.0/1.2/1.6秒也有不同大小残差。源码imu-denoiser.mjs对每个中心独立选择边界/缩窗与二阶拟合，再独立积分，局部拟合保多项式不等于整段信号保冲量或保一阶时间矩。例50Hz/1秒在中部幅度发生非一致改变，正负加速度积分失衡。原82项只含阶跃/孤立脉冲等，漏掉这种平滑往返下的守恒检查。

数据closed-translation-probe.json；脚本/tmp/aasc-imu-wave-probe.mjs。该结果是已知真实闭合的合成运动，不是169点手机轨迹的真实误差量。

## 复现二：对整段运动加速度使用硬死区也改变冲量

同一个50Hz/1秒往返，关闭降噪和低通，只开1.33m/s²硬死区，结束速度-0.099062342m/s、位置-0.346718198m（源time5秒）。死区0和0.08时该特定算例接近浮点零。阈值不对称地去掉不同加速/减速瓣的部分面积，因此只修降噪仍会留下这一类缺陷。

这是可证明的截断失真；不表示所有小加速度都是真实运动，也不把此结果与降噪残差相加或声称等于本轮手机漂移。报告hard-deadzone-impulse-probe.json。

## 数学原型与结果

只在/tmp脚本内替换局部实例的输出计算，不改仓库源文件。对同源世界加速度的分段线性输入建立一次/二次/三次积分V/P/J，在中心前后固定80ms源时间窗口计算：

```text
平滑加速度 := (V(t+R)-V(t-R))/(2R)
位置原函数修正C := (J(t+R)-J(t-R))/(2R)-P(t)
速度原函数修正D := (P(t+R)-P(t-R))/(2R)-V(t)
输出速度增量 := 原输入区间冲量 + D(当前)-D(前一)
输出位置增量 := 已有速度*dt + 原输入区间加权冲量 + C(当前)-C(前一)-D(前一)*dt
```

对25/50/100Hz×四动作时长×有/无15%时间抖动，共24组，数学候选相对相同离散输入的基线积分，结束位置/速度差最大约2.96e-15m/9.80e-16m/s。抖动输入自身的采样误差仍存在，原型没有凭空知道真实终点。只验证x轴无噪声/无低通/无死区、不含生命周期的积分原理，不能称产品修复或实机验收。

## 已确认的具体产品方案

1. 新增`3rd/imu-six-axis-test/imu-conservative-denoise.mjs`。使用固定源时间对称平滑及区间冲量/一阶时间矩更新速度、位置，不直接积分逐点独立拟合值。默认半窗先取80ms且受现有延迟限制；确认为孤立真实短脉冲时拆出该分量直通、其余分量平滑，分别保持积分量，避免把脉冲摊开或用变化权重重新制造偏差。对规则/不规则采样和区间/瞬时契约分别建立正确的输入原函数。
2. 修改`imu-denoiser.mjs`：加速度支路改接新模块，保留原姿态平滑、固定300ms输出语义、快停及原静稳；缓存仍有界。低通在源输入侧以一致区间模型处理，验证其冲量和时间矩，不能在平滑后再用不匹配的点积分破坏守恒。
3. 修改`imu-engine.mjs`、`imu-preintegration.mjs`：APK瞬时路径的运动积分使用硬截断前的加速度及一致低通区间积分；1.33等已学阈值继续用于显示/噪声诊断，真实静稳仍由已有静稳/快停处理。旧输入/模拟器的原死区语义保留兼容。原始与延迟支路均回传实际积分信号，不能把显示用归零值冒充积分输入。
4. 修改`server.mjs`静态路由/可选诊断白名单，新增可选`integrationAcceleration`同源三轴字段；修改`app.mjs`、`index.html`明确区分显示用死区后值和实际世界积分用值。复用原WS和profile参数，不增加HTTP配置或APK字段，不需重装APK。
5. 更新专项与文档：在原82项之外加入24组合往返与单向不归原点/匀速/持续加速、脉冲幅度和积分、恒定偏置保留、静置噪声/真实慢动作、暂停/缺口/参数/校准/快停后再动、旧协议/真实浏览器。先验守恒及输入完整性，再看手机效果；静态噪声因移除积分硬死区是否变差必须单独验收。

## 设计、执行、自测与风险

设计/实现伪代码对应imu-six-axis-test文档首节。确认后先细化三轴、源时间边界、低通模型、脉冲分解、首次输出与保持段的L4伪代码，再写产品；测试通过后备份现场、更新独立8769并核对HTTP/大小/SHA-256，提交代码/文档。开发完成从todo删除，只留设备验收。预计实现、回归、边界核对约半天到一天，手机窗口另计。

风险：守恒只说明处理不额外改变相同输入的积分，不自动消除真实输入零偏/温漂/姿态误差；移除原生积分硬死区可能暴露静置噪声，须用原静稳保持及噪声测试验证，不能靠无条件速度衰减掩盖；脉冲识别和流边界不能制造或丢弃冲量；浮点原函数需局部重基准避免长会话消减误差；不能把不同代次源时间混在一起。新模块沿用512帧上限，保持计算/内存有界并测实际耗时，不以Node性能推算手机。

需求分析沿用enterprise，主L6（降噪/积分信号契约），次L5（分解→源时间平滑→区间积分→保持/恢复），建议下放L4。三条强证据为无噪声闭合运动的降噪残速、孤立硬死区残速、24组合数学原型；模块与流程邻层混合，主权重6/总8×0.9=0.675。评分23/25+19/20+13/20+18/20+14/15=87。结论“需补充产品边界”：输入需区分显示/积分信号，不补会继续错读；异常需覆盖保持/断流/长会话，不补可能边界失真；验收需补噪声/真实脉冲/物理参考，不补不能宣称已解决手机漂移。后续技能不自动追加，等待本具体方案确认。
