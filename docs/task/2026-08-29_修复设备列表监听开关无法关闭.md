# 修复设备列表监听开关无法关闭

## 任务描述

设备列表中的“🎙️监听”复选框可以显示，但点击后没有关闭效果；控制端的语音识别设备和语音生成设备选项需要移动到声纹面板。

## Design 需求

- 监听开关绑定 `change` 事件。
- 关闭时通过现有 `updateCapability(display.id, 'voiceRecording', false)` 发送服务端。
- 识别设备和生成设备控件移动到 `panel-voiceprint`，保留原 DOM id、接口和状态同步。
- 不修改服务端 WebSocket 能力协议，不影响设备条目点击选择。

## Spec 设计

```text
renderVoiceControl(display):
    创建监听 checkbox
    checkbox.onchange:
        停止事件冒泡
        updateCapability(display.id, 'voiceRecording', checkbox.checked)

panel-voiceprint:
    包含 asrDeviceServerBtn/asrDeviceDisplayBtn
    包含 ttsDeviceServerBtn/ttsDeviceDisplayBtn
```

## 受影响模块和代码

- `src/apps/web-mediacenter/ui/public/js/device-list.js`
- `src/apps/web-mediacenter/ui/public/upload.html`
- `tests/display-voice-listening.test.js`
- `tests/ui-theme.test.js`

## 自测用例

1. 检查监听复选框注册 `change` 事件。
2. 检查事件使用 `event.target.checked` 调用 `updateCapability`。
3. 检查两个设备选项只存在于声纹面板。
4. 执行显示端监听、声纹面板和 UI 回归测试。

## 兼容性与风险

- 继续使用原有 `updateCapabilities` 消息和服务端持久化逻辑。
- 事件停止冒泡，避免点击监听开关同时触发设备条目选择。

## 实现结果

- `device-list.js` 为监听复选框绑定 `change` 事件，调用现有 `updateCapability` 发送 `voiceRecording`，并阻止事件冒泡。
- `upload.html` 已将语音识别设备、语音生成设备选项移动到 `panel-voiceprint`，原 DOM id 和 `tts.js` 配置接口保持不变。
- 验证：显示端监听、显示列表状态、声纹选项和 UI 回归 26/26 通过；脚本语法检查和 `git diff --check` 通过。
