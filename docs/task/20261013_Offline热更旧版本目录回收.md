# Offline 热更旧版本目录回收

日期：2026-10-13。状态：已完成，min APK待出包。

## 任务描述

Offline APK服务代码或生产依赖热更新会在`files/aasc-server/updates`生成逐版目录。健康提交后`active-release.json`清除回滚指针，但旧目录未删除，设备用量持续增加。清理仅限旧代码和依赖目录，保护当前运行版本和用户数据。

## Design需求

见`docs/design/android-offline-hot-update.md`的“Offline 热更旧版本目录回收”。更新切换后保留回滚副本；候选API健康并确认release后，以active指针为准删除旧代码/依赖版本。对历史累积版本，在后续服务启动健康时清理。绝不在pending health、失败或进程代次变化期间清理。

## Spec伪代码

见`docs/spec/android-offline-hot-update.md`的“Offline 热更旧版本目录回收”。严格匹配直属版本目录，活动版本保留；符号链接及包含链接的树跳过，更新目录外资源不触碰。

## 自测用例

健康提交后旧code/dependencies目录移除，活动版本保留；当前release目录不存在时不误删。`pendingHealth=true`时保持候选和previous目录；启动失败仍能恢复previous；健康后的历史残留版本目录可重试回收。普通非版本文件、非严格命名目录、active/failed指针、data-repair、APK、模型/配置/任务/结果不变。版本目录自身或子树含符号链接时跳过且链接目标保持。个别删除失败不影响运行或其他候选，后续健康启动可重试。

## 兼容性、性能与风险

只在Offline本地Node服务已有健康HTTP检查成功后执行；普通浏览器、非Offline服务与APK PackageInstaller流程不变。只读扫描最多遍历两个版本目录直属列表。删除发生在健康确认后，退出或空间/权限异常时保留失败目录，不回滚健康版本。将来切换指针格式时未通过有效active版本校验则整体跳过清理。
