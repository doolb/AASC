# 纯文本分页 TTS 播放

## 任务描述

新增 `.txt/.md` 纯文本媒体播放。显示端负责按屏幕尺寸分页、按现有规则分句，每个分句请求服务器 TTS；当前页播放完成后自动下一页。纯文本媒体加入现有批量播放，控制端提供文本页级和批量级播放控制。

## Design 需求

详见 `docs/design/text-media.md`：

- txt 原文显示，md 安全 Markdown 渲染。
- 显示端分页与分句，服务端逐句合成。
- 单文档支持播放、暂停、上一页、下一页、停止。
- 批量模式支持 text 项，文档结束后切换下一项。
- 控制端增加类似 HTML 模式的文本模式设置面板，支持字体大小、行间距和页边距；默认浅黄色背景、深灰色文字。
- 旧 playbackId 的 TTS 回包必须失效，避免快速翻页串音。

## Spec 设计

详见 `docs/spec/text-media.md`，包含媒体类型、文本播放器、单句 TTS 协议、批量状态、控制动作和资源清理伪代码。

## 受影响的功能模块和代码

- 媒体库类型识别、文本格式识别和文件列表展示
- 普通上传、临时上传、临时批量上传
- PlaylistManager 媒体过滤与列表项格式字段
- 服务端显示端 WebSocket 单句 TTS 处理
- 显示端文本渲染、分页、分句、TTS 队列和批量切项
- 控制端文本页按钮、批量双层进度和浮动控制
- 显示端状态持久化与重连恢复

## 自测用例

1. `.txt` 和 `.md` 被识别为 `text`，格式字段分别为 `plain` 和 `markdown`。
2. txt 保留换行，md 标题、列表、代码块、表格可安全显示，原始 HTML 不执行；文本页使用浅黄色背景和深灰色文字。
3. 长文本按实际显示区域分页，显示页码，旋转/resize 后能重新分页。
4. 显示端每个分句单独发送 `textSentenceTts`，服务端按顺序生成并回传 `playAudio`。
5. 当前页所有分句播放完成后自动进入下一页，最后一页完成后停止。
6. 上一页/下一页会清除旧音频和旧回包，快速操作不串页、不串音。
7. 暂停/继续保持当前句和当前页；停止清除 TTS 但保留当前页。
8. 媒体库 URL、普通临时 base64、临时批量 base64 均能播放文本。
9. 批量播放混合 image/video/audio/html/text 时，文本项按文档结束切换下一项，批量暂停/恢复/上一个/下一个/停止均正常。
10. 控制端显示“文档 N / 总数 · 第 X / Y 页”，切换显示端时不会残留旧状态。
11. 控制端打开“文本模式”面板可调整字体大小、行间距和页边距，应用后显示端立即重新分页。
12. 显示端刷新/重连恢复文本样式、当前列表项、页码和暂停状态，语音从当前页重新开始。
13. 图片、GIF、视频、音频、HTML、普通 TTS 和睡眠模式相关测试保持通过。

## 兼容性测试

- Chromium 浏览器与 Android WebView 验证 UTF-8 文本、Markdown 渲染和 TTS 音频播放。
- 横屏、竖屏、90/180/270 度旋转和窗口 resize 验证分页尺寸。
- 本地媒体库、HTTP 媒体库代理、普通临时上传和临时批量上传分别验证。
- 没有语音播放能力时文本仍可翻页显示，不能阻塞 UI。

## 性能测试

- 分页只在文档加载、resize、旋转和字体尺寸变化时重新测量。
- 单句 TTS 请求严格串行，避免一次性生成整页音频占用服务端资源。
- 翻页/切项/停止清理音频事件监听、计时器和过期请求状态。
- 批量临时数据沿用现有 WebSocket 总量限制，不额外复制文本内容。

## 风险评估

- 不同 WebView 字体度量可能导致分页边界差异；以显示端实际测量结果为准。
- 浅黄色背景和深灰色文字需要在不同亮度的显示设备上验证可读性；首版固定为 `#FFF4B8` / `#333333`。
- 文本样式改变会触发重新分页；需要防止应用设置时重复启动 TTS 或丢失当前页。
- 现有分句规则抽取后需同时覆盖服务端和浏览器运行环境，避免规则漂移。
- TTS 服务慢或失败会延长页面播放时间；单句失败跳过，避免整篇卡死。
- 快速翻页可能存在已发出的 TTS 请求无法中止；通过 playbackId 丢弃过期音频，后续可增加服务端取消机制。
- 临时批量文本和既有媒体共用 base64 总量上限。
