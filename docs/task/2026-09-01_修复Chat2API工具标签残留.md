# 任务：修复 Chat2API 工具标签残留

## 任务描述

修复 Pi Agent 使用 canonical Chat2API XML 工具调用格式时，解析器因固定使用旧式 `</function>` 标签长度推进游标，导致 `|invoke></|CHAT2API|tool_calls>` 残留到助手回复、控制端聊天和 TTS 的问题。

## Design 需求

- 参考 `/mnt/Chat2API` v1.4.0 的 `managedXmlProtocol`，按完整 `tool_calls` 区块匹配和清理协议文本。
- 兼容旧式 `<|parameter=...>` 与 canonical 命名参数 CDATA 格式。
- canonical `</|CHAT2API|invoke>` 和旧式 `</function>` 必须分别按实际标签长度消费。
- 残留或未识别的 Chat2API 协议标签不得作为普通助手文本输出。

## Spec 设计

```text
parseChat2ApiToolCalls(text, allowedTools):
    查找并完整匹配 tool_calls 区块
    在区块中解析 invoke、旧式参数或命名参数 CDATA
    选择实际匹配到的 invoke 结束标签并消费其完整长度
    校验工具白名单、参数唯一性、标签闭合和区块内未识别文本
    返回标准 calls 和删除完整协议区块后的 remainingText
    remainingText 仍含 Chat2API 标签时返回 malformedProtocol
```

## 自测用例

- canonical 命名参数 CDATA 格式解析后 `remainingText` 为空。
- 旧式 `</function>` 格式继续正常解析。
- canonical 格式后带普通文本时只保留普通文本。
- 同一响应包含多个 canonical/旧式调用时不残留协议标签。
- 未闭合区块、重复参数、未知工具和未识别协议文本继续报错。

## 兼容性测试

- 不改变只读工具白名单和 `find -> aasc_find` 映射。
- 不改变 Pi 原生 ToolCall 输出结构、工具调用 ID 生成方式和 TTS 隔离。
- 不修改 `/mnt/Chat2API` 上游仓库及 Chat2API Provider 请求逻辑。

## 性能测试

- 解析器继续只处理当前 AssistantMessage 文本，不保存额外历史副本。
- 结束标签定位和区块清理保持单次线性扫描级别。

## 风险评估

- 旧实现兼容两套结束标签，游标逻辑修改可能影响多调用响应；通过旧式、canonical 和多调用测试覆盖。
- 模型输出不完整协议时会被拒绝，不再泄漏标签；这可能让异常响应显式失败，但能避免污染对话历史和 TTS。
