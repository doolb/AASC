# 2026-09-20 正式 APK 蓝牙 SCO 录音接入

## 任务描述

将正式 Android 显示端接入标准 Bluetooth SCO，使 AIMIC-M4 等经典蓝牙免提麦克风可以作为 WebView 语音录音的系统输入。只接入单路系统音频，不引入思必驰厂商 SDK 或第二个 AudioRecord。

## design 需求

- 在网页 `getUserMedia()` 前建立并等待 SCO。
- 使用 NativeBridge 调用 `BluetoothScoController`，录音停止和 Activity 销毁时释放并恢复音频模式。
- Android 12+ 申请 `BLUETOOTH_CONNECT`，旧版本沿用标准 SCO 权限/接口。
- 无 SCO 设备、权限不足、超时或浏览器环境时回退系统默认 `getUserMedia()`，不影响非 APK 页面。

对应设计文档：`docs/design/android-display.md` 的“正式 APK AIMIC-M4 蓝牙 SCO 单路录音”。

## spec 设计

- `BluetoothScoController.startForVoice()` 枚举 `TYPE_BLUETOOTH_SCO`，设置通信模式，等待 `ACTION_SCO_AUDIO_STATE_UPDATED` 的 CONNECTED 状态并返回 JSON 结果。
- `NativeBridge` 提供开始/停止 JavaScript 接口，并在 Activity 销毁时释放控制器。
- `display.html` 的普通 ASR 和控制端临时录音在创建 MediaStream 前调用开始接口，在统一释放函数中调用停止接口。

对应实现伪代码：`docs/spec/android-display.md` 的“正式 APK 蓝牙 SCO 单路录音伪代码”。

## 自测用例

1. 静态检查正式 APK 声明 SCO 所需权限，NativeBridge 暴露开始/停止接口，网页在两个录音入口前建立 SCO。
2. 无原生桥的浏览器页面不调用 SCO，原有 `getUserMedia()` 行为不变。
3. SCO 启动成功后再创建 WebView MediaStream；录音结束可释放 SCO。
4. 无 SCO 输入、连接超时、权限异常时记录错误、恢复 AudioManager 状态并回退默认麦克风。
5. Android JVM 单测、Node 定向静态测试和 Gradle APK 编译通过。

## 兼容性测试

- Android 9/API 28：SM-N9500 + AIMIC-M4，检查 `TYPE_BLUETOOTH_SCO` 输入与持续 PCM。
- Android 12+：检查 `BLUETOOTH_CONNECT` 运行时授权和拒绝后的降级。
- 无蓝牙设备、A2DP-only 设备、页面刷新、TTS 暂停/恢复、控制端临时录音。

## 性能测试

- SCO 建立等待不超过 8 秒，等待期间不创建额外录音线程或 AudioRecord。
- 连续开始/停止录音 10 次，广播接收器、音频模式和 WebView MediaStream 无泄漏。
- 录音期间保持单路输入，不增加服务端请求或 PCM 编码频率。

## 风险评估

- 不同 Android ROM 对经典蓝牙 SCO 路由支持不一致；只能依据系统暴露的 `TYPE_BLUETOOTH_SCO` 输入判断，不保证 A2DP-only 设备可录音。
- Android 12+ 蓝牙运行时权限被拒绝时无法枚举设备，必须保留明确错误和系统默认麦克风降级边界。
- SCO 为窄带语音链路，音质/采样率受系统蓝牙栈限制，不能通过网页参数强制提升为宽带。
