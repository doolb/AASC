日期：2026-10-18

## 任务描述与设计需求

语音“我们来玩五子棋。”进入临时会话后，Responses 流式请求报告 `socket hang up`。要求在尚未输出正文时自动恢复一次，同时避免部分正文重复播放或控制端出现双份回复。需求主等级 L5（失败恢复规则），次等级 L6（SSE 结束契约和会话引用），实现下放 L4；风险为断连时无法知道上游是否已经生成完成，所以以本地可见输出为重试边界。

## Spec 设计与影响代码

先更新 `docs/spec/chat-system.md`。`src/external/llm/llm-responses-client.js` 识别 `response.completed` / `[DONE]` 完成标记，未正常完成即结束时返回固定中断码；`src/external/llm/llm-service.js` 只针对连接中断或旧引用失效执行一次恢复。无正文时清除旧引用，用完整历史新建上游会话；有正文时清除引用并报错，不重发本轮。`llm-responses-client.test.js` 与 `llm-service-responses-transport-recovery.test.js` 覆盖客户端和临时会话；原豆包引用失效回归保持。

## 自测、兼容性与性能

本地模拟建连前 socket hang up、没有终止标记的 SSE、完成事件后关闭、临时会话无正文重试、部分正文中断不重发以及下一轮完整历史新建会话。定向与聊天回归测试 16/16、`npm run check:chat2api` 284/284 通过；语法与差异检查通过。重试最多一次、退避 300 毫秒，不改变正常请求路径；真实语音和远端代理需现场验收。
