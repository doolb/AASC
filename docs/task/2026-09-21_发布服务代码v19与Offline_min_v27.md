# 任务：发布服务代码 v19 与 Offline min v27

## 任务描述

发布版本路径诊断代码，并同步更新 Offline update-only min APK；不重新生成完整 Offline APK，不改变 dependencies v4。

## Design 需求

- 服务代码递增到 v19，携带 `codePath`、`dependenciesPath` 和 `dependencySource` 版本诊断字段。
- min APK 递增到 versionCode 27、versionName `0.2.25-offline-min`。
- 清单最终引用 code v19、dependencies v4、apkMin v27。
- LAN `/mnt/aasc-offline` 和 WAN `~/a/aasc-offline` 独立发布并精确清理旧 min 文件。

## Spec 设计

- 使用 `npm run build:offline-update -- --mode=code-only --code-version=19` 生成代码包。
- 使用固定 MNN checkout `build/third_party/MNN` 和 revision `d407447ed56c4121a11ccbd266dc184ca1ead0c2` 构建 `allserver-min`。
- 使用 `package:offline-apk:min` 生成签名 min 清单，再使用 `publish:offline-apk:min` 原子发布。

## 受影响的功能模块和代码

- `release/apkbuild/allserver-min/app.json`
- `tests/apk-build-profile.test.js`
- `release/offline-update/output/code/code-v19.zip`
- `release/offline-update/output/apk/aasc-display-offline-min-v27.apk`
- `docs/design/android-offline-hot-update.md`
- `docs/spec/android-offline-hot-update.md`

## 自测用例

1. 代码包签名清单验证通过，lock 指纹继续匹配 dependencies v4。
2. min APK build manifest 与实际 APK SHA-256 一致。
3. min APK 签名证书和模型兼容指纹验证通过。
4. 相关 Node 发布测试 32/32 通过。
5. LAN/WAN 清单返回 code 19、dependencies 4、apkMin 27。
6. 两站点只保留当前 min v27，日志、模型、配置和 results 不受影响。

## 兼容性测试

- 旧 full Offline APK 可以通过 min APK v27 原位更新。
- code v19 不要求重新下载 dependencies v4。
- 完整 Offline APK 保持现有版本，不写入服务更新清单。

## 性能测试

- 本次 min APK 构建使用固定 MNN checkout；不增加模型和生产依赖。
- 发布校验对清单组件进行流式 SHA-256 检查。

## 风险评估

- 中风险：min APK 属于原生更新，安装仍依赖 Android 系统确认；需保持签名证书和 versionCode 递增。
- 低风险：服务依赖 lock 指纹未变化，沿用 dependencies v4。
