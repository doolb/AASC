# 任务：显示端分布式能力

## 任务描述

实现显示端分布式能力系统，让每个显示端可以声明自身的能力（capabilities），服务端根据能力进行智能路由。

## Design 需求

参考 [docs/design/display-capability.md](../design/display-capability.md)

核心需求：
1. 显示端能力声明：每个显示端连接时声明自身能力（语音播放、语音录音、语音识别、媒体渲染、文本显示）
2. 能力路由：TTS 只发送给有播放能力的显示端，录音只开启有录音能力的显示端，媒体只发送给有渲染能力的显示端
3. 控制端 UI：显示端列表展示能力图标，支持手动编辑能力标记
4. 子显示端自动声明：voice-display 连接时自动声明为纯语音能力

## 自测用例

### 1. 显示端能力声明
- [ ] 普通显示端连接后自动检测并声明能力
- [ ] 子显示端连接后自动声明 SUB_DISPLAY_CAPABILITIES
- [ ] 旧版显示端不发送 capabilities 时使用默认值

### 2. TTS 路由
- [ ] broadcastAll 模式下，TTS 只发送给 voicePlayback=true 的显示端
- [ ] 指定显示端播放时，检查该显示端是否有 voicePlayback 能力
- [ ] 标记显示端A无 voicePlayback，TTS 不发送给A

### 3. 媒体路由
- [ ] 媒体播放只发送给 mediaRendering=true 的显示端
- [ ] 子显示端不收到媒体渲染指令

### 4. 控制端 UI
- [ ] 显示端列表展示能力图标
- [ ] 有能力的显示端图标亮色，无能力的灰色
- [ ] 点击能力编辑可修改显示端能力
- [ ] 修改能力后服务端和显示端同步更新

### 5. 语音录音路由
- [ ] 语音录音只开启有 voiceRecording 能力的显示端
- [ ] 标记显示端B无 voiceRecording，不开启B录音

## 兼容性测试

- [ ] 旧版显示端（不发送 capabilities）正常工作，使用默认能力
- [ ] 旧版控制端不显示能力图标，不影响基本功能
- [ ] voiceSupported/voiceListening 字段继续工作
- [ ] 子显示端（Go/Node.js/C#）连接正常

## 性能测试

- [ ] 能力检测不阻塞显示端初始化
- [ ] 能力路由过滤不影响消息发送性能
- [ ] 多显示端（10+）广播时能力过滤正常

## 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 能力检测失败导致误判 | 中 | 检测失败时默认为 true，确保功能不丢失 |
| 控制端手动修改能力后显示端行为不一致 | 低 | 发送 capabilitiesUpdated 通知显示端 |
| 子显示端未发送 capabilities 消息 | 低 | 服务端通过 subDisplay=true 参数自动设置 |
