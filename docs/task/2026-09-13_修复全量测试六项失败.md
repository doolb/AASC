# 修复全量测试六项失败

## 任务描述

修复全量 `npm test` 中 6 项失败，区分真实运行时缺陷、过时测试契约和受本地模型缓存影响的非确定性测试，保留既有 Android DeX 多屏触摸/滚轮的 JS 回退策略。

## Design 需求

- ASR 结果日志契约应匹配当前规范化消息变量 `logData`。
- 服务端发送的初始化 `llm.status` 只用于状态同步，显示端不得将其当作普通媒体触发临时激活。
- DeX 多屏控制模式下，键盘和文本继续通过原生桥，触摸和滚轮继续使用显示端 JS 合成事件。
- LLM ModelScope 清单测试必须隔离真实本地模型缓存，保持远端清单的 `ready=false` 断言稳定。
- Windows 语音显示端配置显式持久化 `textInput.requireVoiceprint = "inherit"`。

## Spec 设计

1. 更新 ASR、显示睡眠、Android LLM、Windows 语音输入和显示端控制相关 design/spec 文档。
2. 调整静态测试以验证当前实现契约，而不是已废弃的变量名或输入路径。
3. 为远端 LLM 清单测试复制清单到临时目录，不读取 `res/models/llm` 下的真实缓存文件。
4. 在显示端 WebSocket 消息分支中消费 `llm.status` 后直接返回，不调用媒体显示和临时激活逻辑。

## 自测用例

- 定向执行 6 个原失败测试；显示端桥场景另执行无桥回归。
- 执行 `npm test`，确认全量 693 项测试无失败。
- 执行相关 JavaScript `node --check`。
- 使用 Puppeteer 验证显示端初始 `llm.status` 不产生 60 秒临时激活；睡眠模式集成测试全绿。

## 兼容性测试

- 保留 Android 10/11+ SAF 文件访问和 APK 专属外部目录实现不变。
- 保留 Android DeX 多屏触摸/滚轮 JS 回退；原生桥仅处理键盘和文本输入。
- 保留已有 LLM 清单、远端下载和模型缓存运行逻辑，仅隔离测试数据。

## 性能测试

- `llm.status` 增加一个常量时间的状态分支，不增加网络请求或定时器；睡眠模式测试实测通过。
- 测试临时目录只复制清单文件，不复制模型大文件，不影响生产模型缓存。

## 风险评估

- 若显示端把 `llm.status` 误入媒体兜底分支，会导致页面错误进入临时激活并影响睡眠模式；新增分支可隔离该风险。
- 修改 DeX 测试断言不改变输入实现；若未来提供目标显示原生注入，需要同步更新设计、实现和测试契约。
