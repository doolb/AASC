# 豆包完整请求参数导入

## 任务描述

账号导入保存官网成功聊天请求的受限参数模板，使 Node 使用新用户消息创建会话。用户确认手动官网发送样本，覆盖调试端口和 Android 外部登录；基础代码与离线测试已完成，真实账号长期可用性待验收。

## Design 需求

- 复用现有豆包账号、Cookie 快照、设备资料和 Responses 原生会话状态。
- 请求模板只接受同账号、固定官网来源的成功请求；保留与账号及环境有关的字段，不保存样本聊天文字或旧会话 ID。
- 每轮替换新消息并生成本地会话 ID、消息 ID、时间等动态值；由豆包 ACK 返回上游会话 ID。
- 对 `a_bogus`、追踪头等逐次字段建立采集或更新策略，不能将一次成功样本长期当作有效凭据。
- 将同账号网页完整聊天结果标为“网页聊天已验证”；Node 实际聊天完整成功后才标“Node 聊天已验证”。不在导入时自动发额外测试消息；保留现有会话列表验证为独立状态。

## 受影响功能模块与代码

- 调试端口导入：`scripts/ops/save-chat2api-browser-credentials.js` 及定向测试。
- 账号校验与存储：`chat2api-doubao-chat-adapter.js`、`chat2api-data-store.js`、外部网页会话刷新服务及测试。
- Node 构造与传输：`chat2api-doubao-node-protocol.js`、文字适配器及 Responses 测试。
- 若覆盖 Android：`Chat2ApiAuthWebView.kt`、`Chat2ApiLoginActivity.kt` 与捕获测试；当前 WebView 拦截器不提供 POST 正文。
- Android 可增加仅豆包官网生效的文档起始 `fetch`/XHR 观察脚本和专用桥接；需先核对本项目缺少的 AndroidX WebKit 依赖及真机脚本时序。ADB 调试协议用于验证，不作为用户导入前提。
- 文档：豆包 design/spec、todo、changelog、使用说明；服务代码变更标记 `servicePackage=true`，Android 原生变更标记 `minApk=true`。

## 自测用例

- 样本来源、账号指纹、大小、字段白名单与敏感信息输出检查。
- 新消息与新会话 ID 替换、ACK 权威会话保存、正常续聊、取消及失效字段处理。
- 隔离账号、导入更新冲突、旧账号兼容；用真实 Responses 流验收首轮和续聊终态。
- HTTP200、仅 ACK、空正文、业务错误、凭据版本变化都不能误标聊天能力已验证。

## 兼容性与性能

保留旧账号读取；不得使无请求模板的其他 Provider 变化。捕获与请求仍受现有大小、时间和队列上限约束。Node HTTP/2 与 Android WebView 行为分别验证。

## 风险与预计工时

逐次签名或追踪字段可能随时间失效；单次原样重发成功不足以证明长期有效。Android WebView 当前不能直接从 `shouldInterceptRequest` 读取 POST 正文。确认范围后预计 1–2 天实现与离线测试，真实账号稳定性需单独观察。
