# 两端聊天上下文占用与历史计数

## 任务描述与确认

用户确认两端输入框上方显示本地输入预算估算及对话计数，并纠正计数来源为聊天管理。改动文件与方案已告知，收到“是”后实施。功能源码完成，服务包及设备验收待进行。

## 需求分析与design

- 主等级L6：数字结构、范围与WS契约；次等级L5：查询、正式发送、清空和重连流程。复用现有AASC连接，不引入新的架构或配置。
- 下放判定：建议下放到L4；依据是同源预算、模式差异和迟到消息隔离需要明确步骤。已有声明：buildMessages、历史裁剪、现有聊天范围和WS；新增定义：contextUsage数字快照与请求编号；流程：组装→统计→按范围回传→仅更新当前请求。
- 使用现有历史上限与管理单位，不更改容量或Chat2API状态。百分比采用既有文本估算，保留≈；独立角色Agent不代算。
- design：`docs/design/chat-system.md`、`docs/design/display-chat-mmd.md`。

## 性能、风险和工时

统计在已有组装器复用最终裁剪结果；只在历史/会话/请求节点查询，不逐字或轮询，查询不调用模型。额外计算随本次保留历史线性增长，数字快照不含提示词、音频或图片内容。真实模型窗口和远端续接内存不可由此统计，界面和usage明确本地估算。预计工时1～2小时。
