# 背景光晕中心范围与横屏时间避让

## 任务描述

修正显示端背景光晕调参语义：增加可配置中心颜色，将“中心亮度”改为“中心亮度范围”，该范围定义中心色保持完整的空间区域，不作为 alpha/透明度。提高默认中心色亮度，并保留中心色向外围渐变的扩散参数。修复横屏时右上交互按钮与时间重叠，竖屏保留现有时间位置和按钮列顶部间距。

## Design 需求

- 全局共享配置为 `{ color, centerRange, spread }`，默认值 `#8FA8D5`、10%、58%。
- 中心范围取值 0–20%，扩散范围取值 25–90%；中心颜色在中心范围内完全不变，之后向中间色及 `#101116` 过渡。
- 使用原有 AASC WebSocket 远端配置、权威广播与 `config.set` 持久化流程，不增加 HTTP 接口。
- 光晕保持在媒体元素下方，睡眠遮罩仍为纯黑，媒体像素和播放尺寸不变。
- 横屏时只在实际物理包围盒相交时水平移动时间，按钮侧留 12px；竖屏不改变时间角落与按钮顶部留白。

## Spec 伪代码

```text
配置默认 = { color: '#8FA8D5', centerRange: 10, spread: 58 }
收到控制端配置:
    校验 color 为 #RRGGBB，centerRange/spread 为有限数值
    规范化颜色大小写与数值范围
    config.set('ui.displayBackgroundGlow', normalized)
    广播权威 normalized 到控制端和在线显示端

用户调色/滑块:
    预览只更新 CSS 中心色、纯色中心范围、扩散位置和混合色
    提交 { color, centerRange, spread } 到既有 WebSocket 配置消息

显示端渲染:
    径向渐变 = centerColor 0..centerRange，middleColor spread，#101116 100%
    媒体元素仍在渐变上层，睡眠遮罩保持纯黑

每次旋转文本包围盒校正:
    若逻辑方向不是 landscape，结束
    读取时间和按钮列物理包围盒
    若不相交，不移动
    若相交，沿屏幕水平方向移动时间，使其越过按钮列并留 12px
```

## 自测用例

- 缺失配置返回 `#8FA8D5/10/58`；越界数值被夹取；合法颜色规范化；无效颜色和非数值请求被拒绝。
- WebSocket 更新发送 `{ color, centerRange, spread }` 并保持原有服务端持久化/权威广播。
- 中心范围变动更新完整中心色终点 CSS 值而不写入 alpha；颜色变动实时更新设置预览和显示端色阶。
- 媒体容器渐变使用中心色、纯色中心范围、中间色和外围色；睡眠遮罩保持纯黑。
- 横屏中时间与按钮列相交时向外移动并保留 12px；不相交时不移动；竖屏总是返回零位移。
- 执行定向测试和 `npm test`。

## 兼容性测试

- 旧存量 brightness 配置读取时忽略该字段，补齐中心颜色/范围默认值并保留合法扩散范围。
- 新 WebSocket 消息沿用原消息 type 和配置路径；断线/重连使用默认值及服务端权威值。
- 0°/90°/180°/270°覆盖实际包围盒避让；竖屏状态不得触发水平偏移。
- 不改现有状态栏按 displayId 配置、显示导航方向切换、媒体层级和睡眠行为。

## 性能测试

- 排版回调只进行两个 `getBoundingClientRect()` 读取和一次必要的 x 偏移；没有重绘循环或定时轮询。
- 光晕仅更新 CSS 自定义属性，不创建 Canvas、不变更媒体元素尺寸。

## 风险评估

- 显示端完全不透明的黑色媒体像素仍会覆盖底层光晕；光晕只在媒体透明或未覆盖区域可见，符合背景层定义。
- 旧配置的 brightness 语义与新 centerRange 不兼容，按默认中心范围迁移，避免误把透明度继续影响渐变。
- 旋转后的交互按钮包围盒可能改变方向；避让以物理屏幕测量为准，并在四个旋转角度测试。
