# AASC 子服务器主动连接架构

## 任务描述

将 AASC 服务器节点从主服务器主动 HTTP 请求模式调整为子服务器主动连接主服务器模式。主服务器通过 `wss://192.168.1.39:8081/server` 接收节点连接，并通过该连接处理注册、心跳、远程索引、服务任务和热更新命令。

## Design 需求

- 主服务器入口固定为 `https://192.168.1.39:8081/`。
- WebSocket `/server` 作为子服务器主动连接入口；HTTP `/server` 和 `/server/package` 继续作为代码下发接口。
- 子服务器启动后主动连接主服务器，连接断开后指数退避重连。
- 子服务器继续使用启动器进程和服务进程两个进程，不创建第三个常驻服务进程。
- 暂不实现权限认证、自动发现、最近节点选择和媒体文件同步。
- 网页手动输入服务器地址继续保留，但不用于控制端登记子服务器。

## Spec 设计

实现 `AascNodeConnector` 客户端和主服务器 `/server` 节点接收端：

```text
子服务器服务进程启动
    → 读取 aasc.role=subserver、mainServerUrl、nodeId
    → 连接 wss://主服务器/server
    → 发送 node.register
    → 接收 node.registered
    → 周期发送 node.heartbeat
    → 主服务器通过 node.request 下发白名单操作
    → 断开后按指数退避重连
```

```text
主服务器接收 node.register
    → 校验 nodeId、url、版本和能力
    → 注册 nodeId 与当前连接
    → 关闭同 nodeId 的旧连接
    → 回复 node.registered
    → 连接关闭时标记节点 offline
```

远程媒体索引通过连接请求，实际媒体播放继续使用所属节点的 `ownerUrl`。显式服务节点任务通过连接转发；显示端优先任务行为不变。

## 受影响的功能模块和代码

- `src/framework/aasc/node-connector.js`：新增子服务器主动 WebSocket 客户端。
- `src/framework/aasc/server-registry.js`：保存节点连接状态，支持连接接管、断开和请求投递。
- `src/framework/aasc/media-index-service.js`：远程索引改为连接 RPC。
- `src/apps/server/modules/config/config-app-service.js`：新增主/子服务器角色和 AASC 连接配置。
- `src/apps/server/boot/server-app.js`：增加 `/server` WebSocket 节点入口、子服务器客户端启动和命令处理。
- `src/apps/server/modules/task-engine/task-manager.js`：明确服务节点任务的连接转发边界。
- `scripts/termux/aasc-server-bootstrap.cjs`：复用主动主服务器地址执行清单、代码包下载和热更新结果回传。
- `src/apps/web-mediacenter/ui/public/js/server-list.js`：只展示主动连接节点，保留网页手动地址跳转。
- `tests/aasc-node-connector.test.js`、`tests/aasc-server-registry.test.js`、`tests/server-api-contract.test.js` 及媒体/任务相关测试。
- `docs/design/aasc.md`、`docs/spec/aasc.md`、`docs/design/android-termux-server.md`、`docs/spec/android-termux-server.md`、`docs/todo.md`、`changelog.md`。

## 自测用例

- 子服务器客户端发送注册消息并接收注册确认。
- 注册消息缺少 `nodeId` 或地址时被拒绝。
- 同一 `nodeId` 新连接接管旧连接，列表不产生重复节点。
- 心跳更新节点状态，断开连接后节点立即或按超时规则离线。
- 连接失败按最小/最大退避时间重连，成功后退避恢复初始值。
- 主服务器请求远程媒体索引时通过 WebSocket 返回结果，单节点超时不影响其他来源。
- `server.update` 被接受后使用现有 Bootstrap，服务恢复后重新注册当前版本。
- `/server` HTTP 清单、`/display`、`/control` 和网页手动地址连接不受影响。
- 旧 `/api/subservers` 可访问，但不再作为 AASC 节点主动连接来源。

## 兼容性测试

- Node.js 服务端继续使用 `ws`，不新增第三方依赖。
- 主服务器自签名 HTTPS 证书和 Termux 证书不被覆盖。
- 主服务器角色默认保持 `main`，现有主服务器无需配置子节点即可启动。
- Termux 仍由 `server-launcher.js` 拉起 `server-app.js`，Bootstrap 不常驻。
- 网页手动输入 HTTP/HTTPS 地址仍跳转到目标 `/upload`。

## 性能测试

- 每个节点只保留一个 WebSocket 连接和一个心跳定时器。
- 节点连接请求按 `requestId` 管理，超时请求及时清理，不阻塞心跳。
- 重连退避不产生高频连接风暴。
- 远程媒体索引请求只访问在线节点，并限制单节点超时。

## 风险评估

- 当前无权限认证，局域网内客户端仍可能伪造节点；按原计划后续增加。
- 服务进程更新时 WebSocket 会短暂断开，必须依赖 Bootstrap 回滚和重新注册。
- 主服务器重启后节点目录为临时状态，依赖子服务器自动重连恢复。
- 子服务器的 `advertisedUrl` 仍要求显示端能直接访问；本次不实现媒体反向代理。

## 预计工时

约 5 小时，包含协议模块、主/子角色接入、媒体索引迁移、文档和定向测试。
