# 控制端增加服务端 ASR/TTS 功能开关

## 任务描述

在控制端声纹面板增加服务端语音识别、服务端语音生成两个独立开关。关闭后不启用对应服务器功能；如果当前设备选择服务端则自动切换显示端，没有可用显示端时直接返回不可用。

## Design 需求

- 开关默认开启，兼容已有 `asr.device`、`tts.device` 配置。
- 保存到 `asr.serverEnabled`、`tts.serverEnabled`。
- 服务端按钮随开关禁用；当前选择服务端而关闭开关时自动切换到显示端。
- ASR/TTS 请求均必须经过服务端开关门禁，关闭后不得调用对应服务器引擎或 TTS 回退。

## Spec 设计

```text
GET /api/config/serverVoice:
    返回 { asrEnabled, ttsEnabled, asrDevice, ttsDevice }

POST /api/config/serverVoice:
    校验可提供字段为 boolean
    保存 serverEnabled
    关闭开关且设备为 server -> 设备改为 display
    广播开关状态和设备状态

VoiceprintPanel:
    加载两个 checkbox
    checkbox change -> POST serverVoice
    server device button disabled = !serverEnabled

ASR:
    启动时 serverEnabled 为 true -> 初始化服务端 ASR
    请求设备为 server 且 serverEnabled 为 false -> 503
    请求设备为 display -> 仅转发到显示端，无显示端时 503

TTS:
    设备为 display -> 尝试显示端
    服务端 TTS 关闭 -> 显示端失败/离线时直接报错，不调用 server TTS
    设备为 server 且 serverEnabled 为 false -> 503
```

## 自测用例

1. 页面显示两个开关，加载并保存状态。
2. 关闭 ASR/TTS 后对应服务端按钮禁用，当前服务端设备自动切换显示端。
3. 服务端 ASR 关闭时请求不调用 `asr.recognize`。
4. 服务端 TTS 关闭时请求不调用 `tts.generateTTS`，显示端失败不回退。
5. 开关重新开启后服务端功能恢复。

## 兼容性、性能与风险

- 缺失旧配置按开启处理，不改变既有部署行为。
- 显示端路由协议保持不变，只增加服务端的配置门禁。
- 关闭 ASR 时避免启动本地服务器模型；关闭 TTS 时不发起服务器 TTS 网络请求。
- 关闭后若没有显示端能力，相关语音请求会明确失败，调用方需显示错误提示。

## 实现结果

- `config-app-service.js` 为 ASR/TTS 增加默认开启的 `serverEnabled` 配置。
- `server-app.js` 增加 `/api/config/serverVoice` 配置接口；关闭服务端功能时自动把对应设备改为显示端，并在 ASR/TTS 入口增加门禁。
- `upload.html` 和 `voiceprint-panel.js` 增加两个独立开关；`tts.js` 禁用对应服务端设备按钮，WebSocket 支持跨控制端同步。
- 服务端 ASR 关闭时不在启动阶段初始化；服务端 TTS 关闭时显示端失败不再回退服务器 TTS。
- 验证：新增开关测试 3/3 通过，相关 ASR/TTS、显示端和 UI 回归测试通过。
