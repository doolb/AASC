# 睡眠立即切换优先级与侧栏滚动条样式

## 任务状态：✅ 已完成

## 任务描述

修复显示端临时激活 60 秒期间立即睡眠/深度睡眠/恢复正常指令不生效的问题，并隐藏控制端左侧导航滚动条的视觉样式，同时保留导航滚动能力。

## Design 需求

参考：design/display.md（睡眠模式优先级与下发媒体、控制端左侧导航样式）。

- sleepOverride('sleep'|'deep'|'normal') 优先于已有临时激活窗口。
- 立即指令执行时清除 activationUntil，避免旧激活窗口继续拦截。
- checkSleepMode() 先判断 manualSleepMode，再判断 activationUntil，最后执行时段判定。
- 左侧导航保留 overflow-y: auto，仅隐藏 Firefox、旧 Edge、WebKit/Chromium 的滚动条视觉元素。

## Spec 设计

参考：spec/display-sleep-mode.md、spec/sidebar.md。

    checkSleepMode:
        若 manualSleepMode 为 sleep/deep:
            target = manualSleepMode
        否则若当前时间早于 activationUntil:
            target = active
        否则按睡眠设置和本地时段计算 target

    handleControl(sleepOverride):
        activationUntil = 0
        manualSleepMode = sleep/deep 或 null
        checkSleepMode()

## 兼容性测试

- 临时激活仍高于自动时段判定。
- 下发媒体/临时激活仍会取消已有手动覆盖。
- 左侧入口数量少时视觉布局不变，数量多时仍可滚动访问。
- 触摸、触控板和鼠标滚轮滚动不依赖可见滚动条。

## 性能测试

- 睡眠修复仅增加一次时间戳清零和一次条件顺序调整。
- 滚动条隐藏仅使用 CSS，不增加 JavaScript 监听器或布局轮询。

## 风险评估

- 低：状态修改限定在显式 sleepOverride 指令，自动时段和临时激活入口保持独立。
- 隐藏滚动条后用户仍可通过滚轮、触控板、触摸和键盘访问导航；不支持这些输入的环境可能缺少视觉滚动提示。
