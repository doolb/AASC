# 文本媒体 TTS 动态选择全部设备

## 任务描述

文本媒体播放时，源显示器没有声音播放能力或当前能力发生变化时，TTS 不能继续固定使用媒体开始时的旧目标。每次实际句子播放请求需要重新检查当前在线且启用语音播放的显示端，并允许从未被媒体选中的显示端中选择；下一句预取必须继续使用当前句目标，避免远程预取无法自动播放。

## Design 需求

- 保留文本媒体的分页、逐句 TTS、远程回执和单句预取协议。
- 媒体开始时的 route 仅作为初始、兼容和恢复信息，不作为后续每句 TTS 的永久目标。
- 每个非预取句子请求重新检查全部在线 `voicePlayback=true` 显示端。
- 源显示端可播放时优先源端，否则按稳定顺序选择其他可用设备。
- 预取句沿用当前句实际目标；如果该目标已失效则取消预取，实际下一句开始时再重新评估设备。
- 无可用目标时返回可定位错误，不阻塞后续文本句子。

## Spec 设计

```text
每个 textSentenceTts 请求:
    获取当前播放上下文
    读取全部在线且启用 voicePlayback 的显示端
    如果请求是预取:
        当前句实际目标仍可用时沿用该目标
        否则选择源端或全部设备中的第一个可用目标
    如果请求是实际播放:
        优先源端，否则按稳定顺序选择全部设备中的第一个可用目标
        把本句实际目标写入 pendingRemoteSentences
    本地目标发送 textPlayback
    远程目标发送 textPlaybackRemote
    远程完成回执按本句登记的目标校验
```

## 自测用例

1. 源端不可播，未选中的在线语音设备可以接收远程 TTS。
2. 第一条句子使用设备 A，设备 A 下线或关闭能力后，下一条实际句子使用设备 B。
3. 当前句使用设备 A 时，预取句仍发送到设备 A。
4. 当前句目标失效时取消预取，不把预取缓存改投设备 B；实际下一句重新选择设备。
5. 所有设备均不可用时，返回带页码和句子序号定位的错误。
6. 现有文本分页、远程回执、取消、超时和预取回归不受影响。

## 兼容性测试

- 旧客户端无 route 时继续使用源端兼容路径。
- 浏览器显示端、Android APK 显示端和远程语音显示端均沿用现有消息协议。
- 未选中的设备只参与语音目标选择，不参与文本画面播放。

## 性能测试

- 每个句子请求在进入队列和音频发送前各读取一次当前显示端能力列表，不增加 TTS 生成次数。
- 预取请求不重复切换当前远程目标，保持现有单槽预取上限。

## 风险评估

- 设备在句子生成和实际播放之间断连时仍可能播放失败；现有远程超时和失败回执负责跳过该句。
- 若设备能力在连续句之间变化，语音可能在不同设备间切换，这是本需求的预期行为。
