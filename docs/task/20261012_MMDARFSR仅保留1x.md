# 正式与独立MMD-AR的FSR仅保留1×

日期：2026-10-12。状态：源码实施完成，待设备画质验收。用户反馈其他倍率效果不好，要求独立MMD-AR与正式显示端都只保留1×。

## 任务描述与需求分析

移除两端面板中的FSR输出重建倍率控件。本地保存值、旧预设或其它输入中的0.25/0.5/2/4仍统一归一到1；默认值继续为1。保留内部设置字段及现有渲染/时域接口，避免破坏既有尺寸和历史逻辑。

需求等级为L6配置契约，次级为L4尺寸数据流。范围明确：正式和独立两个MMD-AR界面；不改变FSR内部比例、画质算法、场景渲染次数、TAA、PNG旁路、远端配置流程或默认灯光预设。风险是外部预设中的非1值会被强制恢复为1，这是当前“仅保留1×”规则的预期结果。

## Design需求

- 正式端与独立端面板均不显示FSR输出重建倍率控件，原有内部场景渲染比例继续独立生效。
- 内部重建倍率固定为1；保存状态及灯光预设携带其它值时，归一化成1并在现有流程中持久化。
- FSR开启时输出大小等于基础Canvas尺寸；TAA、关闭抗锯齿、WebGL2不可用及PNG/诊断旁路沿用旧行为。
- 不删除 `fsr2ReconstructionScale` 字段，不重写Shader/resize/历史契约，不新增远端配置接口。
- 正式网页更新标记 `servicePackage=true`；若状态已为true则保持。min APK和生产依赖状态按现值保留，不在本任务发布/出包。

## Spec伪代码

```text
正式与独立FSR倍率控件 → 不渲染
正式与独立fsr2ReconstructionScale ← 1
旧存储/预设/远端残留中的其它倍率 → 归一为1
BaseSize ← CSS尺寸×自动DPR×canvasScale
FSR有效 → SceneSize ← BaseSize×fsr2Scale；PresentSize ← BaseSize×1
非FSR/不支持WebGL2 → PresentSize ← BaseSize
Canvas/历史目标变化 → 沿用既有resize和历史清理
PNG或诊断请求 → 使用请求尺寸并在完成后恢复预览状态
```

## 自测用例

1. 两端默认和字符串/数值1均归一为1；0.25/0.5/2/4及其它非法值均归一为1。
2. FSR下两端输出严格等于基础Canvas尺寸；场景输入仍只由内部比例控制。
3. 历史输出目标与Canvas一致，重绘/模式变化后历史仍按原逻辑清理。
4. 普通TAA、抗锯齿关闭及WebGL不支持仍旁路重建倍率；PNG请求尺寸不变。
5. 执行 `node --test tests/mmd-fsr-reconstruction.test.js`、两端定向Shader回归与 `npm run build:web:mmd-ar-test`；执行 `git diff --check`。

## 兼容性测试

- 旧 localStorage、灯光预设、历史调用方继续读取同一字段，但非1值统一迁移为1。
- 远端配置协议、默认预设、PNG尺寸恢复、正式与独立隔离存储键保持。
- 正式服务端网页改变会使服务包待构建；独立网页生成资源通过既有构建入口更新。未获发布要求前不发布。

## 性能测试

输出乘数固定为1后，重建输出和历史颜色缓冲不会再因该字段增大或缩小；场景成本继续由Canvas倍率与内部比例决定。用目标尺寸断言验证输入/输出面积一致于既有约定，不对GPU总帧时作线性推断。

## 风险评估

- 非1档位被归一化会改变此前保存的设置，但这是用户明确要求；保留原字段可让旧代码/存储继续解析。
- 多档菜单移除后，尺寸仍可通过Canvas倍率和内部比例调节；本次不修改这两个控制。
- 不改重建Shader，不声称改善或修复某一模型的细节质量；实际设备需确认1×观感及原性能。

预计工时：1小时。实施及验证结果完成后补记于本任务。

## 实施与验证结果

- 两端面板移除FSR输出重建倍率控件及专属说明；设置归一器仍固定输出1，旧值及预设残留自动回退。FSR内部比例、算法、TAA、PNG旁路及渲染接口未改。
- `node --test tests/mmd-fsr-reconstruction.test.js`：8/8通过；`node --test tests/display-mmd-render-production.test.js`：2/2通过，覆盖正式面板无重建倍率控件、真实PMX渲染、旧值归一、刷新/复位与历史缓冲生命周期。
- Chromium SwiftShader下正式和独立真实GPU Shader定向测试各1/1通过，覆盖10个角度，GL错误为0；独立端生成页已核对不包含重建倍率控件。
- `npm run build:web:mmd-ar-test`、所有改动JS文件的 `node --check` 及 `git diff --check` 通过。构建包含既有Vite大chunk提示。
- 独立端轻量浏览器页面回归1/1通过，验证控件不存在且旧存储中的2会归一为1。真实模型长流程未能完成：浏览器页面有API，但模型未到 `modelReady`，并出现 `ERR_INSUFFICIENT_RESOURCES`；因此真实模型组合/PNG/刷新复位端到端验收仍待设备或资源充足环境。
- `release/offline-release-status.json` 的 `minApk`、`servicePackage`、`dependenciesPackage` 原值均为 `true`，按项目规则保留；本次没有出APK或发布服务/网页。
- 实际设备上的1×画质、发丝/动画拖影、GPU帧时和显存仍列入 `docs/todo.md` 待验收。
