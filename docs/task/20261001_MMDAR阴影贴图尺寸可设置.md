# MMD AR阴影贴图尺寸可设置

## 任务与授权

用户询问当前阴影贴图大小并要求可设置。已核对源代码及独立生成网页均为1024×1024，用户回复“可以”，并追加ShadowMap列表预览以观察角色占比；尺寸与预览实现已获授权。

## Design需求与Spec设计

灯光主光分组新增统一尺寸下拉选择512/1024/2048/4096，主光与补光共用此数值，默认1024。即时生效、本地保存、刷新/换模型恢复、灯光恢复默认。设备上限自动降档，界面回显实际尺寸。尺寸变化时释放并清空旧阴影贴图，结束时释放仍持有资源，不逐帧重建。参见design/spec的同名章节，spec使用伪代码。

## 自测、兼容与性能

规范化允许档位、缺失/非法值；设备上限降档与回显；重复设置不重建；实际map尺寸、主光及补光独立/沿用模式；旧map/mapPass释放；连续切换及退出GPU资源回收；保存/刷新/坏存储/恢复默认；换模型及关闭阴影后再开启。仅验证受影响范围，未授权重新打包APK。各尺寸比较真实阴影边缘，手机帧耗时待现场检查；2048/4096像素数分别为1024的4/16倍。

## 风险与预计工时

高档位GPU内存与渲染开销增加，较大贴图不能保证消除由bias或阴影相机范围导致的条纹；防止切换泄漏与不支持档位。预计实现、网页构建和验证约30–45分钟，手机验收另计。默认保持1024。

主L4（参数归一/贴图属性更新/条件释放，各强证据3），次L5（保存/刷新恢复，中证据2），邻层一致性0.90，置信度9/11×0.90≈0.736；程序能力L4，无需下放。用现有runtime声明串联设置、设备能力、释放与重建流程，不引入远端协议。评分：清晰24/25、证据18/20、完备18/20、风险19/20、落地14/15，总93/100；候选可开发，具体方案按AGENTS仍待确认。后续翻译/伪代码同步技能不自动调用。
