# Auto-Brain 分层与命名优化任务

## 任务描述

- 目标：将“条件反射层/小脑/大脑”示例抽象为更通俗、可工程落地的分层命名。
- 范围：新增独立 Auto-Brain 设计与实现文档，并与 AASC 解耦，AASC 仅保留消息总线定位。

## design 需求

- 增加 Auto-Brain 场景下的分层定义。
- 明确与 AASC 的协作边界（AASC 只做消息总线）。
- 明确 AASC 支持多个 Auto-Brain 运行时并行运行。
- 明确 LLM 仅输出策略草案，不能直接执行。
- 明确策略发布需经 Guard 校验，支持灰度与回滚。

## spec 设计

- 增加模块职责伪代码。
- 增加 Auto-Brain 流水线伪代码，避免大段 if-else。
- 增加原型注册扩展点伪代码。
- 增加关键数据契约与失败回滚伪代码。
- 增加多运行时主题隔离与注册机制伪代码。

## 自测用例

1. 检查 `auto-brain` 设计文档中是否包含 Input/Fast Decision/Action/Tuning/Planning/Guard/Monitor 分层。
2. 检查实现文档是否仅使用伪代码描述，不包含可直接运行的函数实现。
3. 检查文档中是否明确 LLM 不直控执行。
4. 执行 `node -e "require('./auto-brain/src')"`，确保骨架模块可正常加载。
5. 执行多运行时冒烟测试，确认同一总线上可注册多个 runtimeId。
6. 执行跨设备冒烟测试，确认 `targetDeviceId` 可把 runtime 消息转发到其他设备总线。
7. 执行 `node --check server.js`，确认运行时桥接分支语法正确。

## 兼容性测试

1. AASC 文档中不再混入 Auto-Brain 分层内容。
2. Auto-Brain 文档独立维护，保留与 AASC 的协作边界说明。

## 性能测试

1. 本次主要为消息总线扩展，需关注 `messagesByRuntime` 统计开销。

## 风险评估

- 风险：AASC 与 Auto-Brain 的职责边界被误用。
- 缓解：在 design/spec 索引与正文中明确“总线”和“决策架构”分工。
- 风险：多个运行时共享总线时主题误配导致串话。
- 缓解：强制使用 `autobrain.{runtimeId}.{channel}` 命名规则并通过 API 生成主题。
- 风险：设备传输层未注册导致跨设备消息丢失。
- 缓解：发送前检查 `deviceTransports`，对缺失传输通道打印告警并暴露统计。
