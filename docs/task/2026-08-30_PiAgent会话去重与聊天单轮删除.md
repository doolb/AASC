# Pi Agent 会话去重与聊天单轮删除

## 任务描述

修复 Pi Agent 同时使用 Pi 内存上下文和应用历史导致的 prompt 递归；控制端聊天页增加删除任意中间单轮对话的功能。

## design 需求

- 同一个 Pi 聊天会话首次初始化时使用必要历史，后续只发送当前用户消息。
- 群聊、不同私聊 session、不同 profile/template 的 Pi 上下文必须隔离。
- 删除任意一轮时删除用户消息和紧随其后的助手回复，不影响其他轮次。
- 删除后重置对应 Pi 内存会话，下一次请求从剩余历史重新初始化。

## spec 设计

- Pi Runtime 增加 conversationKey、continuationPrompt 和会话初始化状态。
- llm-service 为 Pi 首次请求构造完整 prompt，后续请求传 continuationPrompt。
- 服务端新增单轮删除接口；历史服务按消息 ID 定位，并调用 Pi Runtime 重置对应会话。
- 控制端在用户消息气泡上显示“删除本轮”，成功后刷新当前历史。

## 自测用例

- 连续两次 Pi 请求的第二次只发送当前用户消息，不重复历史。
- 群聊和不同私聊 session 不共享 Pi 上下文。
- 删除最后一轮、中间一轮和唯一一轮，分别只删除对应用户/助手消息。
- 删除无助手回复的用户消息只删除用户消息。
- 删除后下一次 Pi 请求重新从剩余历史初始化。
- 控制端删除按钮能定位消息 ID，成功后更新列表。

## 兼容性测试

- 普通 LLM 仍按原有 `contextCount` 拼接应用历史。
- Pi Chat2API 工具转换和工具循环不变。
- 旧历史消息和默认群聊继续可显示；没有消息 ID 的异常请求返回失败。

## 性能测试

- Pi 会话建立后每轮不再复制完整历史 prompt，降低请求体和模型上下文增长。
- 删除操作只修改命中的历史会话，不扫描后写入无关会话。

## 风险评估

- Pi 进程重启会丢失内存上下文，下一轮需要重新初始化；这是删除和配置隔离的必要代价。
- 若历史中存在旧式 `{user, assistant}` 记录，删除按单条记录整体处理，保持兼容。
