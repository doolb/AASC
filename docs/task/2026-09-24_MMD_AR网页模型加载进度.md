# MMD AR 网页模型加载百分比

## 任务描述

在已发布的 HTTPS 测试页显示 PMX 模型加载的阶段、百分比与进度条，不改变独立 APK 或正式显示端现有 UI。

## Design 需求

- PMX、纹理、VMD 与初始化均应反映在进度中，100% 只能在模型可显示后出现。
- 无资源长度时不编造字节进度；加载失败保留原错误提示。
- 进度条只在 HTTPS 测试页出现，不遮挡灯光/定位交互。

## Spec 设计

- `docs/spec/mmd-ar-test-apk.md` 的“HTTPS 网页模型加载进度”定义回调、阶段权重、代次隔离和界面状态伪代码。

## 影响模块与代码

- `src/apps/web-mediacenter/ui/public/js/display-pmx-runtime.js` 接入 MMDLoader 和 LoadingManager 进度事件，并输出可选进度回调。
- `src/apps/web-mediacenter/ui/public/js/display-mmd.js` 接收可选回调，仅 ready 后发出 100%。
- `3rd/mmd-ar-test/build.js` 仅为网页测试页生成进度层和回调绑定；APK 不变。
- 同步 design/spec/todo/changelog/README/usage/self-test。

## 自测、兼容性与性能

1. `npm run build:web:mmd-ar-test` 成功，静态资源路径仍指向 `/mnt/mmd-ar/`。
2. 浏览器记录进度，确认单调不倒退、模型就绪前不显示 100%，最终显示 100% 后隐藏。
3. 检查宽/窄屏灯光和定位面板可点击，进度层不阻止触摸。
4. 加载失败显示错误；现有 APK 与正式显示端不传回调，原状态文字不变。
5. 资源大小不增加模型副本；只增加很小的 JS/HTML/CSS，性能耗时记录以实际浏览器为准。

## 风险评估与预计工时

- LoadingManager 的资源总数可能动态变化；阶段百分比需保持单调，说明其不是精确总字节比例。
- 浏览器缓存可能导致下载事件缺失；阶段转换仍需继续前进，完成只由模型 ready 决定。
- 预计 1–2 小时，含构建、浏览器回归与 HTTPS 覆盖发布。

## 执行结果

- HTTPS 测试页已覆盖发布；外网脚本 SHA-256 与本地一致，旧网页目录保留为可恢复备份。
- Chromium 实际 HTTPS 请求中 PMX 进度连续到 70%，其后纹理/VMD/初始化推进到 100%；模型 ready 后短暂展示并自动隐藏，未发现资源/页面错误。
- 定向测试 50/50 通过，`git diff --check` 通过。手机现场视觉与相机 AR 验收仍待执行。
