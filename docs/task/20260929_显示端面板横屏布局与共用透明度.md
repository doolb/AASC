# 2026-09-29 显示端面板横屏布局与共用透明度

## 任务描述

修正显示端横屏时灯光、动作/物理、定位面板出现在按钮列下方、占用过多竖向空间的问题。把三个面板放到右侧按钮列左边并对齐顶部；给每个面板顶部增加共用的不透明度滑条。MMD-AR HTTPS 测试网页同步采用相同布局和透明度行为。

## Design 需求

- 横屏下所有面板共享位于右侧按钮列左侧的同一锚点，并与按钮列顶部对齐。
- 面板宽高受逻辑舞台尺寸和安全区约束，内容较长时面板内部滚动；竖屏继续使用已有纵向布局。
- 三个面板各自显示同一不透明度滑条，任一滑条调整后同步影响三面板背景；默认 96%，范围 0%–100%，保存到 localStorage。
- 只调整背景表面不透明度，保持文字、输入控件和滑条清晰。
- MMD-AR HTTPS 测试网页包含相同功能，测试网页仍通过现有 npm 脚本构建。

## 自测用例

1. 横屏依次打开灯光、动作/物理、定位面板，三者都位于按钮列左边且顶部对齐。
2. 短屏横屏下每个面板均可内部滚动，最后一个控件和关闭/切换按钮可达。
3. 竖屏下三个面板仍按原布局显示。
4. 调整任一面板的不透明度，三面板背景及其他面板滑条读数同步；文字和控件保持不透明。
5. 刷新后恢复不透明度；localStorage 不可用时页面仍可滑动调节。
6. MMD-AR HTTPS 测试网页构建产物包含相同行为，APK 资源清单不因网页构建变化。

## 兼容性测试

- 检查 `currentRotation` 为 0/90/180/270 时逻辑方向判定、映射安全区和面板可视区域。
- 检查 Android WebView 旧版缺少 `100dvh` 或 CSS 环境安全区时仍通过既有 resize/Inserts 值保持面板可见。
- 检查正式显示端及 HTTPS 测试页的灯光、动作、定位开合互斥和面板内部点击行为不变。

## 性能测试

- 面板尺寸只在既有 resize 链更新；滑条更新 CSS 自定义属性，不触发 MMD Canvas 重建或渲染器尺寸变化。
- 滑动过程中不创建定时器、不读取模型资源；仅更新 DOM 样式和本地设置。

## 风险评估

- 旋转后的逻辑宽高与设备物理方向不同，使用物理 viewport 计算可能导致横屏规则判断错误；实现需复用舞台几何。
- 只调整外层背景可能看不出透明变化；分类卡片及标题背景也要共用透明度变量，同时避免降低文字/表单控件清晰度。
- localStorage 可能被浏览器策略禁用；失败时回退默认值并保持当前页面交互可用。
