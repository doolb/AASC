# 显示器播报文本旋转与字号适配

## 任务描述

修复显示端播报文本没有跟随 90°/270°显示器旋转适配的问题，并将播报文本字号增加 50%。播报文本使用 `#voiceTextDisplay`，同时覆盖 TTS 播报、语音识别结果和语音状态提示。

## design 需求

- 90°/270°时播报文本使用竖排布局并保持正确阅读方向。
- 0°/180°保持水平布局，180°文字翻转 180°。
- 桌面端字号 `24px → 36px`，移动端字号 `18px → 27px`。
- 放大字号后保留旋转场景的最大宽度约束。

## spec 设计

- 在 `applyRotation()` 中统一清理 `voiceTextDisplay` 的旧变换、定位和文字方向样式。
- 90°设置 `writingMode=vertical-rl`、`textOrientation=mixed`；270°在此基础上设置 `transform=rotate(180deg)`。
- 在 `display.css` 中调整 `#voiceTextDisplay` 的桌面端和移动端字号。

## 受影响的功能模块和代码

- 显示端旋转：`src/apps/web-mediacenter/ui/public/display.html`
- 显示端播报文本样式：`src/apps/web-mediacenter/ui/public/css/display.css`
- 旋转回归测试：`tests/display-broadcast-text-rotation.test.js`

## 自测用例

- 静态检查 0°/90°/180°/270°均有明确的播报文本定位和方向规则。
- 检查桌面端字号为 36px、移动端字号为 27px。
- 运行 `node --test tests/display-broadcast-text-rotation.test.js`。
- 运行相关显示端/文本媒体测试，确认 TTS、ASR 和文本媒体不回归。
- 实测聚焦回归 3/3、相关静态与逻辑回归 37/37、显示端集成回归 9/9 通过。

## 兼容性测试

- Chromium/WebView 支持 `writing-mode: vertical-rl` 的显示端。
- 旧显示端不涉及协议变化，只加载新的页面样式和旋转逻辑。

## 性能测试

- 仅修改 CSS 和旋转时的内联样式，不增加定时器、网络请求或媒体处理开销。

## 风险评估

- 风险低：TTS 和 ASR 共用同一文字节点，旋转规则会同时影响两类提示，但两者应保持一致的阅读方向。
- 需要避免 CSS 淡入动画的 `transform` 覆盖旋转内联样式；回归测试需覆盖可见状态的方向配置。
