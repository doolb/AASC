# TTS 语速按 Provider 分别配置

## 任务描述

调整已完成的声纹面板语音参数入口：语速（−10 至 10）继续按 TTS Provider 分别配置；全局音量（0 至 100）仍只保留一个入口。Provider 不接受原生语速参数时，不显示语速输入、不提交语速值。用户确认豆包网页朗读按上游原生能力判定，因此隐藏语速；其 WAV 后处理只应用全局音量。

## Design 需求

- 每个支持语速的 Provider 设置卡显示自己的默认语速，值互不覆盖。
- 全局音量仍在同一声纹面板入口配置，应用于全部业务与 Provider。
- 每种 TTS 能力显式声明 `supportsSpeed`；不支持的方式隐藏语速控件，服务端剔除历史无效字段。`doubao-chat` 固定上游参数，声明不支持。
- 单次请求显式语速覆盖当前 Provider 默认；显式音量覆盖全局音量。
- 豆包网页朗读继续使用固定上游音频参数，生成 WAV 后只应用全局音量；按上游原生参数判断不支持语速，隐藏输入且丢弃历史值。
- 复用现有 WebSocket 权威配置、广播、重连与双存储回滚流程。

## Spec 设计

- `ttsProviderConfig.providers[id].defaultSpeed` 作为 Provider 默认语速；仅对声明支持语速的 Provider 有效，限制 -10..10。
- `ttsProviderConfig.defaultVolume` 及 `config.tts.sharedParameters.defaultVolume` 保持共享音量，限制 0..100。
- 当前能力矩阵：system、qwen-chat、qwen-api、doubao-api 支持语速输入；doubao-chat 上游固定速度，不显示语速输入。
- 旧配置若含共享 `defaultSpeed`，用作仍缺少 Provider 专属语速值的支持 Provider 迁移值；已有 Provider 专属值优先。system 再回退 `config.tts.defaultSpeed`，最后回退 0。
- 配置广播只输出支持语速 Provider 的语速，不输出不支持方式的历史语速，不将音量写入 Provider 配置。

## 自测用例

1. 声纹面板只有一个全局音量输入；各支持 Provider 的语速输入位于自己的 Provider 设置卡，范围和默认值正确；豆包网页无语速输入。
2. 不支持语速时不渲染输入、不提交字段，服务端快照不输出其历史语速。
3. 多 Provider 分别保存/广播/重连后语速互不覆盖；共享音量仍对全部 Provider 生效。
4. 旧共享语速正确迁移到缺少 Provider 值的支持 Provider；Provider 既有值保留，system 兼容旧配置回退。
5. 请求显式语速/音量优先；省略时分别使用所选 Provider 默认语速和共享音量。
6. 豆包网页朗读仍向上游发送固定速度和音量，WAV 后处理只应用共享音量。
7. 任一配置存储失败时保持双存储回滚、旧权威值回传及凭证脱敏。

## 性能测试

- 不新增依赖、HTTP 接口或网络往返；WebSocket 配置快照只增加少量数值字段。
- WAV 后处理继续复用既有实现，无新增音频复制或额外变速步骤。

## 风险评估

- Provider 能力声明与实际适配器不一致会造成错误显示；新增/修改 Provider 时必须同步能力元数据及覆盖测试。
- 旧版本只保存了一组共享语速，无法还原用户更早的每 Provider 差异；迁移把此共享值复制到所有缺少 Provider 值的支持方式，允许之后分别调整。
- 豆包网页朗读不接收语速设置；WAV 音量处理沿用既有逻辑。
