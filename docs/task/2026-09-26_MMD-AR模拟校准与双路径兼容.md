# MMD AR 模拟校准与双路径兼容

- 日期：2026-09-26
- 范围：`3rd/mmd-ar-test/` HTTPS 测试网页的构建产物、模拟视频源和校准流程；正式显示端及独立 APK 的行为保持不变。
- 问题：直接访问内网 `http://192.168.1.39/mnt/AASC/3rd/mmd-ar-test/web-dist/` 时，页面引用固定 `/mnt/mmd-ar/js/...`，内网返回 404，`window.DisplayMmd.init` 不存在。模拟模式点“拍照校准”仍调用实体摄像头。

## Design 需求

同一份 `web-dist` 同时支持外网 `/mnt/mmd-ar/` 和内网深层路径，无需 Apache 别名。模拟模式的校准预览应与当前透视后的画布一致；拍照固定当前帧，之后沿用现有四角选区、命名和 IndexedDB 保存。校准和 A-Frame 定位不同时持有模拟流，失败、取消、切换或页面离开都释放轨道和绘制定时器。真实相机模式不变。

## Spec 与伪代码

见 `docs/spec/mmd-ar-test-apk.md` 的“无实体摄像头的透视模拟输入”。主要流程：页面目录 → 相对静态资源路径；模拟图片 → 透视画布 → 校准视频 → 当前帧截图 → 原选区/保存；停止校准流 → 透视画布 → A-Frame 定位。

## 影响模块

- `3rd/mmd-ar-test/build.js`：资源根改为页面相对路径，APK 构建分支不变。
- `3rd/mmd-ar-test/display-mmd-ar-benchmark.js`：动态导入的 MindAR Compiler 按当前脚本地址寻找同级 `vendor`，兼容深层挂载和旧 APK 路由。
- `src/apps/web-mediacenter/ui/public/js/display-mmd-ar.js`：仅在测试页显式模式下向校准取流流程注入模拟视频，状态与释放逻辑沿用同一生命周期。
- `tests/mmd-ar-sim-camera.test.js`：深层路径加载、无实体摄像头校准拍照/保存、流释放和后续 MindAR 回归。

## 自测、兼容与风险

1. `npm run build:web:mmd-ar-test` 成功；内网和外网式路径的页面、JS、CSS、MindAR 官方图、MMD 清单及模型 URL 都在当前目录解析。

3. 取消、保存、切换或停止后视频轨道和模拟绘制定时器结束；校准后可再次启动 A-Frame 目标识别。
4. 真实相机模式及正式显示端不注入模拟取流；原网页定位、面板分类、灯光与显示端 AR 回归通过。
5. 风险：相对路径需与所有动态导入、MMD 清单和纹理解析一致；HTTP 内网为非安全上下文，需实际浏览器验证画布流可用。
