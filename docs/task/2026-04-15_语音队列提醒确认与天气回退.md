# 2026-04-15 语音队列提醒确认与天气回退

## 任务描述

完成 `docs/todo.md` 第10行到27行相关事项：语音输入排队、提醒确认增强、录音开关指令、提醒模板、天气城市回退、无效语音过滤与 AASC capabilities 路由修复。

## Design 需求

- 同一显示端的语音输入必须串行执行，避免多条语音并发处理。
- 提醒确认必须播报 24 小时制时间，并在创建成功后追加成功语音提示。
- 新增“开启录音 / 关闭录音 / 开始录音 / 停止录音”指令。
- 提醒内容支持模板、前缀、后缀拼接。
- 天气查询增加城市白名单和默认城市回退。
- AASC 需要能正确处理 `capabilities` 消息。

## Spec 设计（伪代码）

```text
voiceCommand.enqueueVoiceInput(text, displayId):
    获取 displayId 对应的 Promise 队列
    将当前任务挂到上一个任务之后执行
    执行完成后清理空队列

voiceCommand.handleReminderCommand(text, displayId):
    解析时间
    通过模板拼接提醒内容
    生成“相对时间 + 24小时制时间”的确认文本
    创建待确认记录（30秒过期）
    不再自动确认

voiceCommand.executeReminderConfirmation(id, confirmed):
    如果已确认过，则忽略
    如果 confirmed:
        添加提醒
        播报“提醒添加成功”
    否则:
        播报“已取消”

voiceCommand.handleWeatherCommand(text):
    清洗标点
    在城市列表中匹配城市
    未匹配则回退到默认城市
    查询 wttr.in

DisplayRenderAgent.updateCapabilities(params):
    将 capabilities 写回显示端状态
    广播 displayList
```

## 自测用例

- 同一显示端连续发送两条 voiceInput，应按顺序处理。
- 说“提醒我十分钟后喝水”，确认语音里应包含 24 小时制时间。
- 对同一个 confirmationId 连续确认两次，只添加一条提醒。
- 说“关闭录音”后，显示端 recorder 进入 pause；说“开启录音”后恢复。
- 说“天气。”或无效城市时，应回退到默认城市天气。
- 显示端发送 `capabilities` 消息，不再出现 “No handler found for type: capabilities”。

## 兼容性测试

- AASC 路由兼容旧的 `voiceInput` 与 `commandAck` 处理链路。
- Node 子显示端保持现有播放暂停录音逻辑，仅增加录音总开关。

## 性能测试

- 语音排队基于 Promise 链，不引入额外轮询。
- 天气城市匹配使用小规模内存数组，不影响响应时间。

## 风险评估

- 如果某条语音命令长时间阻塞，会拖慢同显示端后续语音执行。
- 录音控制依赖 recorder.pause/resume，若 recorder 未初始化需安全跳过。
