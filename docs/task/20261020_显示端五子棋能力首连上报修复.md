# 显示端五子棋能力首连上报修复

日期：2026-10-20

## 任务描述

当前显示端问游戏目录时收到 `Game:目录,GM,列表,无`，随后规则查询被告知“不支持五子棋”。ADB 检查发现游戏模块已声明五子棋，但显示页及服务端当前 `capabilities.games` 均为空。单次重新上报后，服务端目录恢复五子棋。

## Design 需求与 Spec 设计

见 `docs/design/game-gomoku.md` 与 `docs/spec/game-gomoku.md`。显示端在 WebSocket 开始前同步注册游戏模块；首次基础能力上报从模块读取 `games`，异步完整检测继续读取同一来源。服务端的游戏白名单与不支持游戏的拒绝逻辑保持现有规则。

## 受影响模块与代码

- `src/apps/web-mediacenter/ui/public/display.html`：调整游戏脚本执行顺序，补全首次基础能力字段。
- `tests/display-game-browser.test.js`：约束脚本顺序与首连声明；原浏览器用例覆盖棋盘行为。
- 五子棋 design/spec/task/todo/changelog 与 `release/offline-release-status.json`。

## 自测用例、兼容性测试与性能测试

运行显示端游戏浏览器测试及 `npm run test:game-chat`。核对首个 `capabilities` 消息已有五子棋、服务端目录会列出五子棋；旧显示端缺失模块时保持空列表。同步加载的脚本约 13 KiB，只在显示页启动时执行，需在真机刷新后再次核对启动和重连时的能力值。

## 风险评估与预计工时

游戏脚本加载失败会阻塞页面解析直至浏览器报错，游戏能力仍为空；服务端不会误宣告支持。预计约一小时。当前设备的运行时能力已临时恢复；源码需部署后验证刷新与重连。

`display-game.js` 现于内联 WebSocket 脚本之前同步加载，`baseCaps.games` 首次即使用模块声明。`node --test tests/display-game-browser.test.js` 2/2 通过，`npm run test:game-chat` 41/41 通过，`git diff --check` 通过。ADB 现场确认运行时重发后服务端 `displayList` 从 `games: []` 变为 `['五子棋']`；源码修复的页面刷新与重连效果留待服务包部署后现场复测。`servicePackage=true` 待构建。
