# 聊天隐藏 think 与私聊清空修复

## 任务描述

聊天回复中会泄漏 `<character_set>`、`<role_settings>` 等内部提示词以及 `</think>` 前的思考内容；同时控制端在私聊页点击“清空”没有可见反馈。需要隐藏聊天内部思考输出，并修复私聊清空的范围参数和错误提示。

本任务明确不处理 MNN `.mmap` 文件预生成。

## Design 需求

- 统一清洗普通 LLM 聊天的流式、非流式输出。
- 支持完整 think 标签和孤立结束标签的模型输出。
- 清洗结果用于 `chatChunk`、`chatResponse`、历史和 TTS。
- 私聊清空必须限定当前 `target + sessionId`，失败时明确提示。

## Spec 设计

- 新增 `docs/spec/chat-output-filter.md` 中的 `stripThinkBlocks` 和 `ThinkOutputFilter` 伪代码。
- 更新 `Chat.clearHistory()`，对私聊范围和 HTTP/业务响应做显式处理。

## 自测用例

1. 成对 `<think>` 标签被完整移除。
2. 只有 `</think>` 时，结束标记前的 XML/提示词前缀不出现在结果中。
3. think 标签被拆分到多个流式 chunk 时，chunk 和最终结果均只保留正文。
4. 没有 think 标签的普通文本保持流式输出。
5. 私聊清空请求包含当前助手和会话 ID。
6. 私聊清空 HTTP 错误或服务端业务错误显示失败原因。

## 兼容性测试

- Responses 非流式和流式协议。
- Chat Completions 流式协议。
- 普通群聊、私聊和 Agent profile。
- 没有 think 标签的旧模型输出。
- 私聊默认会话和自定义会话。

## 性能测试

- 过滤器只保存当前请求的文本，不读取或复制模型文件。
- 每个 delta 只做一次累计文本扫描，控制内存增长与回复长度线性相关。
- 私聊清空不扩大删除范围，不增加 LLM 请求。

## 风险评估

- 误把正文中的 `</think>` 当作隐式结束标记；仅在 AASC 聊天展示链路清洗，不影响 Chat2API 对外 reasoning 字段。
- 流式响应初始结构化前缀需要短暂缓存；响应结束时强制冲刷，避免普通短回复丢失。
- 服务端返回错误时前端不再静默，可能暴露参数错误，但便于定位当前私聊会话状态。
