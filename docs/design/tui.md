# TUI 界面设计文档

## 需求描述

服务端和子显示端当前使用 `console.log` 输出运行状态信息，缺乏结构化展示。需要使用 `blessed` 库实现 TUI（终端用户界面），提供全面的信息面板。

### 服务端面板说明

| 面板 | 位置 | 内容 |
|------|------|------|
| 标题栏 | 顶部 | 服务器名称、地址、协议 |
| 系统状态 | 左上 | 运行时间、内存、CPU、协议、静音状态、设备计数 |
| 设备列表 | 右上 | 显示端/控制端表格（ID、IP、类型、能力） |
| 事件日志 | 底部 | 连接/断开、语音输入、TTS播报、提醒触发、设备事件 |

### 系统状态字段

- 运行时间：格式化显示（Xd Xh Xm Xs）
- 内存：RSS / HeapUsed / HeapTotal
- 协议：HTTP / HTTPS
- 静音状态：是/否
- 显示端数量
- 控制端数量

### 设备列表字段

| 字段 | 说明 |
|------|------|
| ID | 显示端/控制端标识 |
| IP | 客户端IP地址 |
| 类型 | 显示端/子显示端/控制端 |
| 能力 | 媒体渲染/语音播放/语音录音/语音识别/文本显示 |

## 技术选型

- **blessed**：成熟的 Node.js TUI 框架，支持窗口、表格、文本框等丰富组件

## 设计原则

1. TUI 模块独立，不侵入业务逻辑
2. 通过事件回调方式接入，原有 console.log 保留为备选
3. 支持 `--no-tui` 参数禁用 TUI，回退到纯日志模式
4. 日志缓冲区限制最大行数，防止内存溢出
5. 设备列表定时刷新，不依赖事件驱动
6. TUI 模式下重定向 `console.*` 到 TUI 日志，禁止直接写 stdout/stderr，避免破坏 blessed 渲染
