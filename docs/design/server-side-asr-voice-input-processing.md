# 服务端统一处理显示端 ASR 与声纹结果

## 需求背景

显示端上传录音后，原流程由显示端解析 `/api/asr/recognize` 响应，再通过 WebSocket 回传 `voiceInput`。当响应包含多个声纹分段时，显示端和服务端各自处理，容易造成同一说话人的文字被拆成多条、未识别声纹的文字不回显，以及命令处理链路不一致。

## 设计目标

1. 显示端只负责上传 WAV，并携带自身 `displayId` 和录音时间区间。
2. 服务端成为 ASR/声纹结果的唯一业务处理入口，负责相邻同一说话人分段合并、跨显示端去重、控制端回显、声纹门控和唤醒/命令处理。
3. 声纹未识别的分段仍返回原文字、`speaker: null`、相似度分数和阈值，并回显到原显示端，但不得触发唤醒、对话或命令。
4. 保留旧版显示端主动发送 `voiceInput` 的 WebSocket 处理，保证 APK 或浏览器未更新时仍可工作。
5. 控制端直接上传的聊天录音不携带 `displayId`，继续走控制端自己的响应处理，不被当作显示端语音命令。
6. 服务端收到显示端 `asrResult` 时，默认打印完整 ASR/声纹诊断信息；控制端声纹面板提供全局开关，关闭后仅打印摘要信息。

## 分段规则

- 只合并响应中相邻且 `speaker` 相同、非空的分段。
- `speaker: null` 是未识别声纹边界，不与任何相邻分段合并。
- 合并后的文本按原顺序直接拼接，保留起止时间、说话人、分数列表和阈值。
- 服务端按合并后的每个分组调用一次语音输入处理，因此同一人形成一句，不同人切成不同句。
- 未识别分组只广播和回显诊断信息，不进入语音会话门控。

## 数据流

```text
显示端 WAV + displayId + 时间区间
              │
              ▼
      /api/asr/recognize
              │
              ▼
     ASR/声纹显示端结果
              │
              ▼
     服务端分段合并与归一化
       ┌──────┴────────┐
       ▼               ▼
  控制端 voiceInput   原显示端 HTTP 回显
       │
       ▼
 去重 → 未匹配门控 → 唤醒/命令
```

## 兼容与边界

- `displayId` 只用于确认上传来源和路由命令，不能通过 IP 推断来源。
- 没有 `displayId` 的旧请求仍返回识别结果，但服务端不代替旧显示端发送 `voiceInput`。
- 原有 `voiceInput` WebSocket 消息继续兼容，并复用同一套服务端处理函数。
- 本次不更换 ASR 或声纹模型，不改变相似度算法和阈值含义。
- 详细日志开关只影响服务端 `asrResult` 日志内容，不影响 ASR 结果、声纹匹配、分段合并、命令门控或控制端 `voiceInput` 回显。
- 详细日志包含识别文字、分段文字、说话人、相似度、阈值、时间区间、聚类 ID 和错误信息，不记录音频原始数据。

## ASR 结果日志

- 配置项：`voiceprint.asrResultDetailLog`，默认值为 `true`。
- 控制端在声纹识别设置卡片中显示“打印 ASR/声纹详细日志”开关。
- 开关关闭时保留请求 ID、ASR 总文字和错误摘要；开关开启时额外打印顶层及每个分段的声纹字段。
