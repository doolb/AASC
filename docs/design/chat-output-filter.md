# 聊天输出过滤与私聊清空交互设计

## 需求

1. 聊天界面不显示模型输出中的 `<think>...</think>`、`<thinking>...</thinking>` 思考块。
2. 兼容模型只返回孤立 `</think>` 的情况：将结束标记之前的内部提示词/思考内容视为隐藏内容，只展示结束标记之后的正文。
3. 流式输出、非流式输出、聊天历史和 TTS 使用同一份清洗后的正文，避免控制端、语音和历史记录出现不一致。
4. 私聊点击“清空”时必须携带当前助手和私聊会话 ID；服务端拒绝时控制端要显示实际错误，不得静默无响应。

## 设计原则

- 清洗在聊天服务层完成，避免只在某一个页面隐藏而把泄漏内容继续写入历史或送入 TTS。
- 流式过滤器按累计原始文本维护状态，支持标签跨 chunk 分割；在检测到思考结束前暂存可能的结构化前缀。
- 正常回复没有思考标记时保持流式输出；响应结束时再冲刷过滤器中尚未确定的短文本。
- 清空私聊只作用于 `mode=private + target + sessionId` 对应范围，不扩大为该助手的全部会话。
- 清空请求的网络错误、HTTP 错误和业务错误都通过 Toast 告知控制端。

## 兼容边界

- 不修改 Chat2API 对外协议中的 `reasoning_content`，只清洗 AASC 内部聊天展示链路。
- 不处理 MNN `.mmap` 预生成，也不改变模型文件打包策略。
- 没有思考标签的普通文本原样返回，仅保留必要的首尾空白清理。
