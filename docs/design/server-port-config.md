# 控制端服务器端口设置设计

## 普通 APK 与 Offline APK 共存（2026-10-14）

SM-N9500 上两个 APK 原来均使用8081。普通 APK 已通过现有 WebSocket 配置消息持久化为8071并完成托管服务重启；现场新端口HTTPS 200与权威配置确认通过。用户进一步确认修复冷启动将端口重置为8081的问题，并更新普通 APK。

普通 APK 启动时保留已有合法数值整数端口，缺省/非法端口回退8081。Offline APK 保留现有8081与本机WebView首装地址约定。本机健康检查根据实际配置生成URL，避免探测另一APK的端口；损坏配置不猜测成功。主服务器地址仍使用原配置，8071仅是本机服务监听端口。此项不新增HTTP配置接口，端口设置和权威广播继续复用已有流程。

源码与自动验证已完成：Android232/232、profile/端口契约16/16。普通withserver v2/0.1.1已用相同签名覆盖SM-N9500普通v1；完全停止重开后8071 HTTPS /api/status与权威广播通过，主服务器目录记录`APK-SM-N9500`在线、URL为`https://192.168.1.6:8071`，稳定nodeId与主地址均保持。Offline仅核对原配置8081，本次未启动或安装该包。

## 需求

在控制端设置面板最下方的“服务端”卡片增加服务器监听端口设置，便于查看和修改当前服务端端口。

## 行为约束

- 端口输入为 1–65535 的整数；默认和缺省配置为 8081。
- 设置通过 AASC WebSocket 消息提交，服务端校验并由 `config.set('server.port', port)` 持久化；不新增 HTTP 配置接口。
- 服务端向所有控制端和在线显示端广播规范化权威端口；两类客户端连接初始化时收到当前端口。
- 端口未变化时不重启；端口变化保存成功后调用现有托管服务重启流程。
- 已进入托管重启流程时拒绝新的端口修改，避免等待跳转的页面和最终监听端口不一致。
- 已连接控制端和显示端保留页面路径、查询和 hash，等待新端口可访问后跳转；非法输入或保存失败时回传当前权威端口，不重启。
- 服务启动仍从持久化 `server.port` 读取监听端口；配置断线时显示端使用当前页面来源，不新增依赖。

## 验收

验证 1、65535 边界、非整数/越界拒绝、权威广播和控制端/显示端初始化补发；确认同端口保存不重启，变更端口触发托管重启并让所有在线页面转向新端口。
