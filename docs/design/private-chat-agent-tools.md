# 私聊聊天 Agent 系统工具设计

## 设计状态

本文档记录后续讨论方案，当前只保存设计，不实现代码和工具接口。

## 背景与目标

当前私聊语音需要在语音命令层判断特殊控制词。后续私聊使用聊天 Agent 时，希望普通文本统一交给当前 Agent，由 Agent 在确实需要时调用受限的服务端系统工具。

目标是让自然语言理解由 Agent 负责，让状态修改和敏感操作仍由服务器负责校验和执行，避免继续在语音命令服务中增加大量文本匹配分支。

## 适用范围

第一阶段只针对显示端处于 `activePrivate` 的私聊语音输入：

- 原始识别文本完整交给当前私聊 Agent。
- 当前私聊角色、`sessionId`、历史和后端会话保持不变。
- 群聊、等待唤醒状态和现有搜索独立 session 暂不因本设计改变。
- 工具调用能力需要同时兼容 Pi 和 Codex；不能只为某一个 Agent 后端实现。

## 核心原则

### Agent 负责意图识别，服务器负责执行

Agent 只能从服务器提供的工具清单中选择工具并提交结构化参数。服务器不根据 Agent 返回的自然语言猜测是否执行控制操作，也不允许 Agent 直接修改配置、会话对象或密码。

### 工具白名单按会话下发

`activePrivate` 只向当前聊天 Agent 暴露本阶段允许的系统工具。工具清单由服务器根据会话模式、当前显示端和权限策略生成，前端不能传入任意工具名。

### 修复模式保持本地安全边界

Agent 可以调用“请求进入修复模式”工具，但该工具只启动服务器现有的密码等待流程。密码比较、超时、确认、角色绑定和 TTS 抑制仍由服务器本地完成，Agent 不能直接激活修复模式，也不能读取密码。

## 第一阶段工具候选

| 工具 | 参数 | 服务端行为 | 是否结束当前聊天请求 |
|------|------|------------|----------------------|
| `endVoiceConversation` | 无 | 结束当前显示端语音对话，回到等待唤醒 | 是 |
| `exitPrivateChat` | 无 | 退出当前私聊并切换到群聊激活状态 | 是 |
| `switchPrivateAssistant` | `assistantName` | 校验助手存在后切换当前私聊对象；保留或重建会话的规则另行确认 | 是 |
| `requestRepairMode` | 无 | 启动修复模式密码输入流程，不直接进入修复模式 | 是 |
| `mute` | 无 | 按现有显示端/全局静音语义执行静音 | 否，是否需要回复待确认 |
| `announceTime` | 无 | 使用现有时间解析和报时服务播报当前时间 | 否，是否需要回复待确认 |

本阶段不默认把搜索、天气、提醒、播放等能力加入该工具白名单。它们仍作为普通聊天文本交给 Agent，后续分别讨论是否设计为 Agent 工具。

## 会话流程

```text
显示端处于 activePrivate:
    收到原始语音文本
    不在语音层按天气、搜索、提醒、播放等普通功能分流
    获取当前私聊 Agent 后端和 session 元数据
    根据权限策略生成第一阶段系统工具清单
    将原始文本、当前私聊历史和工具清单发送给 Agent

Agent 返回普通文本:
    按正常私聊回复、历史保存和 TTS 流程处理

Agent 返回系统工具调用:
    服务器校验工具名属于当前 activePrivate 白名单
    校验工具参数、当前 displayId、私聊 target 和会话状态
    调用对应的服务端控制模块
    将结构化执行结果返回 Agent，或对终止型工具结束当前请求

requestRepairMode:
    只启动本地密码等待状态
    密码输入不发送给 Agent、不写入历史、不写入普通日志
    密码正确后才进入修复模式，并绑定配置中的工作 Agent 角色
```

## Pi/Codex 统一适配

服务端定义与后端无关的工具描述和工具调用结果格式：

- 工具名称、描述、JSON 参数 schema 和副作用类型由服务端注册表维护。
- Pi 适配器将注册表转换为 Pi 可用的工具声明，并归一化工具调用事件。
- Codex 适配器使用同一注册表和同一服务端执行器，不把控制能力复制到 Codex bridge 内部。
- 工具执行结果只返回必要的成功、失败、状态变化和用户可读摘要，不返回密码、内部配置或完整敏感上下文。
- 后端不支持工具调用时，不能通过解析普通文本伪造成功执行；应返回明确的不支持结果，或暂时使用旧的本地命令兼容路径。

## 状态与并发约束

- `endVoiceConversation`、`exitPrivateChat` 和 `switchPrivateAssistant` 执行前再次确认会话仍属于发起该请求的显示端。
- 状态切换必须在服务器串行化，避免 Agent 回复已经开始后又切换私聊对象。
- 终止型工具执行成功后，丢弃当前请求剩余的普通回复，避免切换状态后继续播报旧 Agent 内容。
- `switchPrivateAssistant` 的历史归属、旧 Agent session 回收和新助手初始上下文是否立即生效，待后续讨论确定。
- 工具调用失败只返回失败结果，不应伪装成控制成功；必要时由 Agent 向用户说明失败原因。

## 确认与安全策略待讨论

以下内容暂不在本文档中拍板：

1. 是否所有工具调用都需要语音确认，还是仅修复模式沿用“预览后确认”，静音和报时直接执行。
2. “静音”是否同时包含取消静音、恢复音量，以及作用范围是当前显示端还是全局。
3. 切换私聊助手后是否复用目标助手当前 `sessionId`，还是创建新的私聊会话。
4. Agent 工具失败后的重试次数、TTS 提示和控制端事件格式。
5. Codex/Pi 均接入后，工具权限是否按 Agent profile、助手角色或私聊状态进一步拆分。

## 分阶段实施建议

1. 先确定工具名称、参数、返回值和确认策略，不改变现有命令行为。
2. 建立服务端工具注册表和统一执行器，先用单元测试验证权限、会话绑定和状态切换。
3. 在 Pi 和 Codex 适配器中接入统一工具调用协议。
4. 仅将 `activePrivate` 切换为“原文交给 Agent + 受限工具”，保留等待唤醒兼容路径。
5. 验证普通聊天、工具调用、修复模式密码保护、TTS 抑制和 Agent session 连续性后，再讨论群聊及更多内置能力。
