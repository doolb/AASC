# MindAR Basic 独立 HTTPS 测试页设计

状态：官方 Basic 示例、自定义目标矩形裁剪编辑器及控制面板折叠已发布到独立外网目录；保留官方卡片和 Softmind 模型。IMU 姿态防抖与失锁补偿现仅在本地代码，尚未发布；Chromium 模拟摄像头和真实 MindAR Compiler 的本地/线上端到端测试通过，摄像头识别及 IMU 轴向/观感待真机现场验证。

## 目标

将 MindAR 官方 `basic.html` 示例作为独立静态页面发布到 `https://c.aasc.us/mnt/mind-basic/`，便于在与 MMD AR 测试页隔离的路径中验证 MindAR 自带示例目标、相机启动和目标锚定模型显示。

## 范围

- 保留官方示例的 A-Frame 场景、MindAR 图片目标、卡片平面和 Softmind 动画模型。
- A-Frame、MindAR runtime、`.mind` 目标、卡片贴图及 glTF 模型固定引用官方 HTTPS/CDN 资源。
- 页面只为适配手机视口增加基础全屏样式，并显示 Softmind 作者与 CC BY 4.0 署名。
- 新页面与 `mmd-ar` 使用不同 URL/localStorage origin，不修改 MMD AR 页、正式显示端、APK 或服务器功能。
- 保留官方卡片目标，同时提供自定义定位图流程：用户主动申请摄像头并拍摄完整帧；照片编辑器默认显示居中、四边各内缩 10% 的矩形裁剪框，用户可移动选框，并拖动四角/四边调整任意可用尺寸，选区始终轴对齐且保持矩形。
- 拍摄后显示完整照片，在照片上叠加蓝色可交互矩形裁剪框；每次移动/缩放只更新叠加框，不显示单独的裁剪结果缩略图。确认后将完整原图与矩形选区保存到本地 IndexedDB。开始定位时按矩形从原图裁切，调用 MindAR Compiler 编译并显示进度，再交给 MindAR 1.2.5 A-Frame system；目标锚点保留参考平面，Softmind 模型位于独立场景舞台并按视觉/IMU 融合结果更新姿态。
- `mind-basic-geometry.js` 提供矩形边界校验、选框移动/缩放、像素裁剪范围计算及旧版四角记录转外接矩形；独立测试覆盖默认 10% 裁剪框、边界限制、任意矩形调整与旧记录兼容，不引入 MMD AR 页面依赖。
- MindAR Basic 控制面板默认展开；用户可收起内容并通过紧凑按钮恢复，ARIA 展开状态同步。
- 增加可选 IMU 实验，不改变摄像头原始视频：用户主动授权设备运动传感器后，可单独启用虚拟场景姿态防抖和定位图短暂丢失时的位移补偿，也可同时启用。定位图可见时以 MindAR 的视觉位姿校正 IMU 预测；丢失时仅在有限时长内积分陀螺仪与无重力加速度，超时隐藏模型；重新识别后重置速度并重新锚定。传感器数据不支持或权限拒绝时，原有 MindAR 定位照常运行。
- IMU 仅作为独立测试页的短时辅助，不能替代视觉定位或宣称达到 ARCore 精度；陀螺仪偏置、设备坐标系差异和加速度双积分漂移均通过状态面板暴露，位置推算设置时长与位移上限。
- 自定义原照片和矩形选区仅留在当前浏览器 origin，不上传服务器；编译结果按每次启动重新生成。可选择/删除自定义目标，官方目标只读。
- 校准摄像头与 MindAR 跟踪摄像头按顺序使用，避免同时打开两个摄像头流；取消、切换、停止和页面离开均释放摄像头及临时 object URL，并移除 MindAR 1.2.5 重启时添加的 resize listener。

## 验收

- `https://c.aasc.us/mnt/mind-basic/` 返回页面，浏览器可读取固定版本的核心脚本和示例资源。
- 页面显示官方 MindAR 卡片识别结果和跟随目标锚定的动画 Softmind 模型；手机摄像头权限只由浏览器在页面运行时处理。
- 默认官方目标与用户自定义目标可切换；完整帧拍摄后默认出现 10% 内缩的蓝色叠加裁剪框，移动和缩放时保持轴对齐矩形且不得超出图片；重拍、命名保存、刷新恢复、编译进度、定位/停止和删除均可使用。
- 控制面板首次加载默认展开；收起后仅保留紧凑展开入口，点击后恢复完整面板。
- IMU 实验默认关闭，首次启用只在用户点击后申请权限；姿态防抖与丢失位移补偿可分别开关或同时运行。目标可见期间渲染模型姿态由视觉观测持续校正；目标丢失时模型只按有限时长和有限位移继续移动，超时后隐藏；重新识别后回到 MindAR 位姿并清除旧速度，关闭实验后行为回到原始 MindAR 跟踪。
- 页面展示传感器可用性、陀螺仪角速度、线性加速度、IMU 推算姿态/位移、当前跟踪状态和丢失时长；无 HTTPS、权限被拒绝、传感器字段为空或页面进入后台时有明确状态，且不得阻止摄像头和普通 MindAR 使用。
- 自定义目标编译结果可被 MindAR 识别；Softmind 模型随自定义目标锚定，切回官方目标后原示例仍正常。
- Chromium 模拟摄像头端到端验证完整帧拍摄、默认框、选框移动/缩放、矩形裁剪、IndexedDB 保存、真实 MindAR Compiler 编译、Blob `.mind` 切换、`arReady`、停止清理和面板折叠；手机浏览器摄像头首锁待现场验证。
- 外网目录独立于 `/mnt/mmd-ar/`，更新不覆盖 MMD AR 资源。

## 风险

页面运行依赖 A-Frame、MindAR 与模型/CDN 可访问；网络或第三方 CDN 故障时页面无法完整加载。MindAR 1.2.5 的 A-Frame system 需要在每次开始时读取新的 `imageTargetSrc`，因此先停止旧 system、替换为编译结果的临时 Blob URL，再重启；必须验证停止/销毁与 Blob URL 生命周期，不能只在运行中的场景上修改属性。自定义目标的 IndexedDB 数据随浏览器站点数据清理而删除。资源版本固定，并保留独立站点路径，避免影响现有 MMD AR 测试页。

IMU 防抖与位移补偿依赖浏览器向网页暴露的设备运动字段，不同浏览器可能返回不同坐标约定或不提供无重力加速度；视觉锚点和 IMU 时间戳并非硬件同步。滤波会在抑制抖动与响应延迟之间折中；加速度双积分误差会快速累积，因此只作为短时演示，必须设置失锁时间/位移上限、在重新识别时重锚，并允许随时关闭。该功能只调整虚拟场景，不稳定摄像头视频本身。
