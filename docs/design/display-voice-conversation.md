# 显示端语音唤醒与监听控制设计

## 概述

显示端持续执行 ASR 时，增加唤醒状态和每个显示端独立的监听开关。关闭声纹识别只取消说话人匹配，不影响 ASR、唤醒词和对话；关闭显示端语音监听才会停止采集和语音处理。

## 需求

1. 显示端语音监听由控制端按显示端独立开关控制，关闭后不主动采集任何语音。
2. 显示端默认处于等待唤醒状态；等待状态仍可执行 ASR，但普通文本不进入命令处理。
3. 支持 `你好小爱`、`小爱你好` 等唤醒词，以及 `{助手}开始对话` 进入指定助手私聊。
4. 私聊状态下支持 `{其他助手}开始对话` 切换目标；`结束对话` 回到等待唤醒，`退出私聊` 回到群聊激活状态。
5. 有效对话结束后，必须等待当前回复的全部 TTS 队列实际播放结束，再重新计时 3 分钟。
6. 3 分钟内没有有效对话输入时，显示端回到等待唤醒。
7. 关闭声纹识别时，普通 ASR 结果不携带 speaker，按普通语音命令处理，不要求注册声纹。
8. 显示端处于 `waitingWake` 时，现有内置功能指令可直接执行；执行后仍保持等待唤醒，普通聊天、自定义命令和对话控制词仍需唤醒词。

## 状态模型

```text
disabled       监听开关关闭，不采集、不处理、不自动恢复
waitingWake    监听开启但等待唤醒；内置功能指令可执行，普通聊天和自定义命令仍需唤醒词
activeGroup    已唤醒，群聊命令可处理
activePrivate  已唤醒，普通文本发送到当前私聊助手
waitingTts     等待 LLM/TTS 完成，录音暂停
```

声纹开关独立于上述状态；声纹关闭不改变状态迁移，只改变 ASR 结果是否包含 speaker。

## 兼容原则

- 复用现有 `voiceRecording` 控制能力作为显示端监听开关，避免新增一套重复的物理录音能力。
- 复用现有 TTS 队列和 `audio ended/error` 回调，队列为空后才启动 3 分钟计时。
- 旧显示端未理解新增消息时，服务端仍可通过现有 `capabilitiesUpdated` 停止录音；普通 ASR 协议保持兼容。

## 控制端监听状态与最近识别文本

控制端不再要求用户进入能力设置弹窗才能看到监听控制。显示端列表的每个条目直接展示：

- `监听开关`：复用 `capabilities.voiceRecording`，可直接启用或停用目标显示端监听；
- `监听状态`：根据 `voiceSupported`、`voiceListening` 和对话状态显示“监听中”“等待唤醒”“已关闭”或“不可用”；
- `最近识别`：显示该显示端最近一次 `voiceInput` 的文本，并标记实时 partial 或最终 final 结果；包括声纹未匹配但已完成 ASR 的文字。

最近识别文本只保存在当前控制端页面内，每个显示端只保留最新一条，用于观察本次语音回传，不改变语音命令处理和唤醒状态机。声纹未匹配的文字可以回传展示，但不能进入命令处理链路。

## 控制端内置命令列表

控制端“系统指令帮助”弹窗通过 WebSocket 获取服务端内置功能命令清单，展示每条命令的示例、功能说明和“无需唤醒”标记。清单由语音命令服务统一提供，避免控制端静态文案与实际命令解析规则不一致；普通聊天、自定义命令和会话控制词不列入免唤醒内置功能清单。

## 系统指令语音帮助

用户说“系统”或“系统。”时，显示端无需唤醒词即可触发系统帮助。服务端根据当前内置命令注册表、自定义语音指令和会话控制指令动态生成完整播报文本，并通过通用 TTS 路由发送到在线语音播放显示端；控制端同时打开系统指令帮助弹窗。新增或修改指令后无需再维护一份固定的帮助播报文案。

## 显示端语音输入 TTS 通用路由

显示端语音输入的 TTS 生成和播放必须与通用 TTS 流程一致：

1. 显示端的 `displayId` 只作为命令执行、媒体控制和结果弹窗的来源标识，不能自动成为 TTS 播放目标。
2. TTS 生成统一调用服务端 `generateTtsWithFallback()`，遵循 `tts.device`、显示端 TTS 生成能力和服务器 TTS 开关配置。
3. 音频生成完成后，按当前在线且启用 `voicePlayback` 能力的显示端列表发送 `type: 'tts' / action: 'playAudio'`；多个显示端都可以播放同一段音频。
4. 唤醒提示、内置功能响应、提醒确认、天气/搜索/播放响应和语音触发的普通对话均使用该路由。
5. “停止播报”同样按通用语音播放目标广播停止消息；控制端发起的定向语音命令继续使用控制端指定的目标显示端。
6. `voiceCommand` 消息只保留触发显示端需要的弹窗或选择信息，不携带音频 URL，避免同一段 TTS 在触发端重复播放。

天气响应在上述通用路由上额外携带完整本地归一化结果：`text` 是适合 TTS 的当前天气和逐日摘要，`detailText` 是显示端弹窗使用的完整当前/逐日/逐时/天文数据，`weather` 是结构化天气对象。旧客户端只读取 `text` 时仍可正常播报。

天气详情使用 `.voice-response-popup` 临时弹窗展示，显示时长按去除空白后的可见字符数计算为每 3 个字符 1 秒，且不少于 30 秒；该弹窗与 TTS 音频生命周期独立，不改变 `#mediaText` 文本媒体和其他响应弹窗的生命周期。

## 显示端 VAD 阈值与底噪检测

1. 控制端“显示控制”页提供独立的监听 VAD / 底噪检测卡片，只针对当前选中的显示端提供 VAD RMS 阈值输入，默认 `0.01`，服务端按 `displayId` 持久化。
2. 服务端通过 WebSocket 将显示端自己的 VAD 阈值下发；显示端运行 VAD 时实时读取该值，不再使用固定常量。
3. 控制端可请求目标显示端进行约 3 秒静音采样；采样只计算麦克风 RMS，不上传 ASR、不触发语音命令、不播放 TTS。
4. 显示端返回采样数、平均 RMS、峰值 RMS、P95 RMS 和建议阈值，独立卡片展示结果并允许将建议值填入阈值输入框后保存。
5. 底噪检测期间暂停 VAD 的语音段结束判定，但不停止麦克风采集；检测完成后恢复正常监听。

## 显示端 VAD 分段与前置静音

浏览器显示端复用子显示端的分段录音策略：持续监听只维持一条采集链路，VAD 检测到语音前不把音频写入待识别语音段。为避免首字音素被 VAD 检测延迟截断，采集器仅保留约 300ms 的循环前置缓冲；检测到语音开始时将该短缓冲并入当前语音段。检测到语音结束后保留用于判停的尾部静音并提交 WAV，下一段继续复用原有 AudioContext。

## 持续监听采集资源生命周期

1. 连续监听期间复用同一个 `micStream`、PCM `AudioContext` 和 VAD `AnalyserNode`，语音分段只清空当前 PCM 缓冲，不重复申请麦克风或创建音频图。
2. ASR 返回 `ignored` 后，自动重启前必须释放旧的麦克风轨道、PCM 采集器和 VAD 分析器；不能只修改 `isListening` 后直接再次调用 `getUserMedia()`。
3. 关闭监听、页面离开、冷却和异常路径统一调用幂等资源清理函数，确保旧的 `AudioContext`、媒体轨道和动画检测循环不再持有引用。
4. 单次语音识别请求持有的 WAV Blob 只存活到请求完成，不因持续监听重启累积未释放的采集链路。

## 未启用声纹识别时的跨显示端 TTS 录音暂停

1. 当任一显示端开始播报 TTS，服务端向所有正在录音的显示端广播播报状态；未启用声纹识别的录音端暂停 PCM/VAD，避免另一台显示端的扬声器回声进入 ASR。
2. 每个独立 TTS 会话携带播放 ID 和播放目标 ID；服务端按目标分别维护播报状态，所有目标完成后才结束对应状态，避免多台播报设备先后结束时误恢复。
3. 播放目标在音频实际播放完成、失败或停止后回报播放 ID，服务端广播结束状态；旧显示端不回报时由服务端超时清理，避免录音端永久暂停。
4. 暂停只清理当前未完成的语音段和前置缓冲，不停止麦克风轨道、不关闭 `AudioContext`，以复用既有采集链路并避免 Chromium 内存持续增长。
5. 多条独立连续 TTS 使用不同播放 ID；同一重复播报组复用一个播放 ID，并携带重复总数。服务端只有收到该组全部完成次数后才广播结束；录音端维护活动播放 ID 集合，只有集合为空才恢复，并在恢复时重置 VAD 段状态。
6. 声纹识别已启用的录音端忽略跨显示端暂停状态，保持当前声纹过滤和语音打断能力。

## ASR 结果回传与命令处理分离

- 显示端完成 ASR 后，服务端先向控制端广播所有有效识别文字，保证控制端可以观察监听期间的实际识别结果。
- 启用声纹识别且 `speaker === null` 时，只阻断唤醒/对话/命令处理，不阻断控制端的文字回传。
- 控制端收到多条结果时仍按显示端覆盖保存，仅显示最新一条，不在列表中无限累积历史。

## ASR 能力异步状态回传

- 显示端 WebSocket 建立时可以先发送初始语音状态，但不能把初始 `voiceSupported=false` 作为最终状态。
- `checkAsrStatus()`、原生 ASR 模型就绪回调和完整能力探测完成后，必须重新回传 `voiceStatus` 及 `capabilities.voiceRecognition`。
- 控制端以异步回传的最新状态为准，避免 ASR 服务已经就绪时仍显示“不可用”。

## ASR 统一服务端识别链路

- 录音显示端只负责采集原始 PCM/WAV 和执行 VAD 分段，所有语音段统一提交服务端 `/api/asr/recognize`。
- 服务端公共接口根据 ASR 设备配置执行本机 ASR，或按显示端连接顺序转发到第一个 `voiceRecognition=true` 的显示端。
- 选择“显示端”时不按 IP、设备名或固定设备优先；连接顺序变化后，候选提供端也随之变化。
- 录音显示端不直接调用自己的 ASR；只有被服务器选中的 Android ASR 提供端处理 `asrAudio` 并回传 `asrResult`。
- 服务端统一负责普通 ASR、声纹匹配/分段、降噪和识别结果返回，录音显示端只处理公共接口的 `text`、`speaker`、`segments` 和错误结果。

## 2026-08-29 控制端监听开关与全局降噪

1. 控制端显示端条目的监听开关必须在创建时绑定 `change` 事件，复用 `updateCapability` 发送 `voiceRecording`；点击后立即显示“发送中”，收到服务端 `displayList` 回传后显示最终状态；WebSocket 未连接时显示发送失败，不得静默吞掉操作。
2. 删除控制端独立的“显示端 ASR 处理”区域和语言选择。正式显示端 ASR 固定使用中文提示，控制端不再提供语言切换入口。
3. 降噪开关移动到声纹面板，但配置语义为全局 ASR 降噪：普通 ASR、单段声纹和快速多段声纹共用同一个开关。
4. 声纹配置接口返回并广播全局降噪状态；显示端收到配置后同时更新普通 ASR 和声纹处理所使用的降噪状态。
5. 语音识别设备和语音生成设备选项统一放入声纹面板，保留原有 DOM id、配置接口和状态同步逻辑。

## 2026-08-29 服务端 ASR/TTS 功能开关

1. 控制端声纹面板增加“启用服务器语音识别”和“启用服务器语音生成”两个独立开关，默认开启以兼容既有配置。
2. 关闭服务器 ASR/TTS 后，对应的服务端设备选项置灰；如果当前选择服务端，自动切换到显示端。
3. 显示端没有对应能力时，服务端请求直接返回不可用，不回退到已经关闭的服务器 ASR/TTS。
4. 服务端开关状态持久化到 `asr.serverEnabled`、`tts.serverEnabled`，并通过统一配置接口同步控制端；显示端只接收实际设备路由配置。
5. 服务器启动时仅在对应开关开启时初始化服务端 ASR；服务端 TTS 在关闭时禁止所有服务端生成入口。
