# 显示端语音唤醒与监听控制设计

## 概述

显示端持续执行 ASR 时，增加唤醒状态和每个显示端独立的监听开关。关闭声纹识别只取消说话人匹配，不影响 ASR、唤醒词和对话；关闭显示端语音监听才会停止采集和语音处理。

## 临时与持续对话窗口

语音聊天增加三种入口语义，并由服务端统一维护显示端会话状态：

1. 任意已配置 AI 角色名：进入临时群聊窗口，默认 30 秒；窗口到期后回到等待唤醒。角色名沿用现有自动匹配列表，不引入默认角色名，也不在会话解析器中写死。
2. `开始对话` / `结束对话`：进入或结束群聊窗口，默认保留原有 3 分钟窗口。
3. `你好<角色名>`、`<角色名>你好`：进入对应 AI 角色私聊；`<角色名>再见`、`再见<角色名>`：结束对应私聊；私聊默认使用 3 分钟窗口。关键词中间允许存在空白、标点或符号。

临时窗口和持续对话窗口分别提供全局秒数设置，服务端通过现有控制端 WebSocket 配置消息校验、持久化并广播权威值，显示端不直接保存配置。

角色名加额外内容的处理方式由同一份服务端配置控制：默认进入临时群聊窗口，也可以切换为兼容旧行为的一次性群聊输入。临时聊天只保留一个全局会话实例，任一显示端重新用角色名开启临时模式都会替换旧实例并同步所有控制端；控制端的“临时”页签展示这一个当前/最近临时会话，并允许控制端直接输入消息，消息仍写入同一个全局实例，不建立按显示端或按控制端分叉的历史。

TTS 播放期间不消耗当前对话窗口：服务端暂停会话到期定时器，显示端冻结当前剩余时间；同一显示端所有相关 TTS 播放完成（或播放超时）后，重新按对应窗口完整计时。该规则与是否暂停录音、是否允许语音打断相互独立。

## 需求

1. 显示端语音监听由控制端按显示端独立开关控制，关闭后不主动采集任何语音。
2. 显示端默认处于等待唤醒状态；等待状态仍可执行 ASR，但普通文本不进入命令处理。
3. 支持任意已配置 AI 角色名进入临时群聊，`开始对话` 进入持续群聊，窗口时长分别可配置，默认 30 秒和 3 分钟。
4. 角色名加额外内容默认启动临时群聊；控制端可以在“临时模式/一次性群聊”之间切换。一次性群聊保持等待唤醒，不启动临时窗口。
5. 支持配置中所有角色名的 `你好<角色名>`、`<角色名>你好` 私聊唤醒，以及 `<角色名>再见`、`再见<角色名>` 退出私聊；关键词中间允许有空白、标点或符号。
6. 有效对话结束后，必须等待当前回复的全部 TTS 队列实际播放结束，再重新按当前窗口类型计时。
7. 窗口到期后显示端回到等待唤醒；TTS 播放期间暂停窗口消耗，播放完成后恢复完整窗口。
8. 关闭声纹识别时，普通 ASR 结果不携带 speaker，按普通语音命令处理，不要求注册声纹。
9. 显示端处于 `waitingWake` 时，现有内置功能指令和已配置的自定义命令可直接执行；执行后仍保持等待唤醒，普通聊天和对话控制词仍需唤醒词。
10. 等待唤醒状态下的确认/取消免唤醒指令只接受规范化后的完整短指令，不能因为普通语音文本包含“拒绝”或“取消”就误放行。
11. 显示端语音进入群聊后，使用聊天系统当前全部角色模板，用户原始语音文本完整保留；角色名只作为群聊输入的唤醒/接受标识。
12. 等待唤醒时，纯“你好+助手名”或“助手名+你好”必须优先识别为指定助手私聊唤醒；纯任意已配置角色名进入临时群聊；包含额外内容时按当前配置进入临时模式或一次性群聊。
13. 临时模式服务端只维护一个全局会话 ID 和消息快照；新的临时唤醒清除旧临时上下文并替换所有显示端的临时状态，控制端临时页签展示该全局快照，并支持直接发送消息到当前临时会话。
14. Pi Agent 详细生命周期日志默认不注入服务器日志，Pi 真正错误仍保留错误回报和可测试的显式 logger。
15. 显示端进入 `activeGroup` 或 `activePrivate` 后，普通语音不受全局指令模式过滤；当前先将包含“搜索”的文本按普通聊天发送，搜索路由配置不再影响 active 会话。天气、提醒、播放、静音、报时、录音和其他自定义指令暂时继续按现有命令优先级处理，后续再逐项调整。
16. 显示端顶部语音状态显示当前会话范围：群聊显示“群聊”，私聊显示“私聊：助手名”；纯唤醒文本仍只切换状态，不产生聊天消息。
17. 天气和普通语音详情弹窗复用显示端已有的安全 Markdown 渲染器，支持结构化文本展示；TTS 继续使用原始纯文本。
18. Pi Agent 的聊天会话按模式隔离：群聊共用一个 Pi 会话，私聊按助手角色和当前私聊会话独立；切换群聊、私聊角色或私聊会话时回收旧模式会话，下一次输入创建干净的 Pi 进程，但不删除应用层已保存的对应历史。
19. 语音进入命令处理前记录会话门控结果，必须按返回状态对象中的 `state.state` 判断活跃会话，便于定位 ASR 已回传但未进入聊天的问题。
20. 显示端唤醒状态的第一行保持状态和柱状图布局，第二行只显示剩余时间 `MM:SS`；倒计时使用服务端下发的会话到期时间，过期后隐藏。
21. 媒体文件名自动播报统一走服务器 TTS 路由；服务器为播放分配跨端播放状态，非声纹监听设备在其他设备播报文件名时也暂停录音，播报完成后恢复。
22. 修复模式工作 Agent 的回复 TTS 复用通用语音播放目标，按每句播放时动态选择当前可用的显示端；修复模式只放行该 TTS，不改变普通 TTS 的全局抑制规则。

## 状态模型

```text
disabled       监听开关关闭，不采集、不处理、不自动恢复
waitingWake    监听开启但等待唤醒；内置功能指令和已配置自定义命令可执行，普通聊天和会话控制词仍需唤醒词
activeGroup    已唤醒，群聊命令可处理
activePrivate  已唤醒，普通文本发送到当前私聊助手
waitingTts     等待 LLM/TTS 完成，录音暂停
```

声纹开关独立于上述状态；声纹关闭不改变状态迁移，只改变 ASR 结果是否包含 speaker。

## 兼容原则

- 复用现有 `voiceRecording` 控制能力作为显示端监听开关，避免新增一套重复的物理录音能力。
- 复用现有 TTS 队列和 `audio ended/error` 回调，队列为空后才恢复当前窗口类型的完整计时。
- 旧显示端未理解新增消息时，服务端仍可通过现有 `capabilitiesUpdated` 停止录音；普通 ASR 协议保持兼容。

## 控制端监听状态与最近识别文本

控制端不再要求用户进入能力设置弹窗才能看到监听控制。显示端列表的每个条目直接展示：

- `监听开关`：复用 `capabilities.voiceRecording`，可直接启用或停用目标显示端监听；
- `监听状态`：根据 `voiceSupported`、`voiceListening` 和对话状态显示“监听中”“等待唤醒”“已关闭”或“不可用”；
- `最近识别`：显示该显示端最近一次 `voiceInput` 的文本，并标记实时 partial 或最终 final 结果；包括声纹未匹配但已完成 ASR 的文字。

最近识别文本只保存在当前控制端页面内，每个显示端只保留最新一条，用于观察本次语音回传，不改变语音命令处理和唤醒状态机。声纹未匹配的文字可以回传展示，但不能进入命令处理链路。

## 控制端内置命令列表

控制端“系统指令帮助”弹窗通过 WebSocket 获取服务端内置功能命令清单，展示每条命令的示例、功能说明和“无需唤醒”标记。清单由语音命令服务统一提供，避免控制端静态文案与实际命令解析规则不一致；普通聊天、自定义命令和会话控制词不列入免唤醒内置功能清单。

## 系统指令语音帮助

用户说“系统”或“系统。”时，显示端无需唤醒词即可触发系统帮助。服务端根据当前内置命令注册表、自定义语音指令和会话控制指令动态生成完整播报文本，并通过来源显示端优先、在线语音播放能力兜底的单目标 TTS 路由播报；控制端同时打开系统指令帮助弹窗。新增或修改指令后无需再维护一份固定的帮助播报文案。

用户说“帮助静音”或“静音帮助”时，服务端提取“静音”为帮助主题，只播报静音、全部静音、取消静音和恢复音量等相关说明，不执行静音命令；帮助主题也支持其他内置命令和已配置的自定义关键词。未知主题返回未找到相关帮助的提示。

系统帮助播报按现有句子边界切分后串行生成和播放，每句完成后才生成下一句，避免一次请求生成超长音频、降低单次 TTS 失败影响范围，并保持帮助指令的原始顺序。分句消息携带同一个 TTS 批次标识，最后一句携带批次结束标记；显示端只有整个批次的最后一句真正播放完成后才结束语音会话，不能因为句子生成间隔导致中途误判完成。控制端帮助弹窗仍一次显示完整文本，不随 TTS 分句拆分；指定主题时，完整文本替换为主题匹配结果。

系统帮助的完整响应文本先下发到目标显示端，立即打开帮助弹窗；TTS 分句生成在后台继续执行，不能让弹窗等待音频生成完成后才出现。

## 显示端语音输入 TTS 单目标动态路由

显示端语音输入的 TTS 生成和播放必须与通用 TTS 流程一致：

1. 显示端的 `displayId` 作为命令执行、媒体控制和结果弹窗的来源标识，同时作为 TTS 播放目标的首选标识；来源端没有语音播放能力时不得强制回放到来源端。
2. TTS 生成统一调用服务端 `generateTtsWithFallback()`，遵循 `tts.device`、显示端 TTS 生成能力和服务器 TTS 开关配置。
3. 音频生成完成后，按当前在线且启用 `voicePlayback` 能力的显示端动态选择一个目标；来源端可用时优先来源端，否则按稳定顺序选择第一个可用显示端。
4. 唤醒提示、内置功能响应、提醒确认、天气/搜索/播放响应和语音触发的普通对话均使用该路由。
5. 每个 TTS 句子重新读取在线能力；来源端在连续句子之间失效时，后续句子切换到备用目标。无可用目标时跳过当前音频并记录可诊断日志。
6. “停止播报”只停止当前语音会话实际选中的目标；控制端发起的定向语音命令优先使用控制端指定目标，指定目标不可用时按同样规则兜底。
7. `voiceCommand` 消息只保留触发显示端需要的弹窗或选择信息，不携带音频 URL，避免同一段 TTS 在触发端重复播放。

天气响应在上述通用路由上额外携带完整本地归一化结果：`text` 是适合 TTS 的当前天气和逐日摘要，`detailText` 是显示端弹窗使用的完整当前/逐日/今日逐时/天文数据，`weather` 是结构化天气对象。旧客户端只读取 `text` 时仍可正常播报。

天气详情和普通语音对话回复统一使用 `.voice-response-popup` 临时弹窗展示，显示时长按去除空白后的可见字符数计算为每 3 个字符 1 秒，限制在 5～90 秒；该弹窗与 TTS 音频生命周期独立，不改变 `#mediaText` 文本媒体和其他响应弹窗的生命周期。

## 显示端 VAD 阈值与底噪检测

1. 控制端“显示控制”页提供独立的监听 VAD / 底噪检测卡片，只针对当前选中的显示端提供 VAD RMS 阈值输入，默认 `0.01`，服务端按 `displayId` 持久化。
2. 服务端通过 WebSocket 将显示端自己的 VAD 阈值下发；显示端运行 VAD 时实时读取该值，不再使用固定常量。
3. 控制端可请求目标显示端进行约 3 秒静音采样；采样只计算麦克风 RMS，不上传 ASR、不触发语音命令、不播放 TTS。
4. 显示端返回采样数、平均 RMS、峰值 RMS、P95 RMS 和建议阈值，独立卡片展示结果并允许将建议值填入阈值输入框后保存。
5. 底噪检测期间暂停 VAD 的语音段结束判定，但不停止麦克风采集；检测完成后恢复正常监听。

## 显示端 VAD 分段与前置静音

浏览器显示端复用子显示端的分段录音策略：持续监听只维持一条采集链路，VAD 检测到语音前不把音频写入待识别语音段。为避免首字音素被 VAD 检测延迟截断，采集器仅保留约 300ms 的循环前置缓冲；检测到语音开始时将该短缓冲并入当前语音段。检测到语音结束后保留用于判停的尾部静音并提交 WAV，下一段继续复用原有 AudioContext。

## 持续监听采集资源生命周期

1. 连续监听期间复用同一个 `micStream`、PCM `AudioContext` 和 VAD `AnalyserNode`，语音分段只清空当前 PCM 缓冲，不重复申请麦克风或创建音频图。
2. ASR 返回 `ignored` 后，自动重启前必须释放旧的麦克风轨道、PCM 采集器和 VAD 分析器；不能只修改 `isListening` 后直接再次调用 `getUserMedia()`。
3. 关闭监听、页面离开、冷却和异常路径统一调用幂等资源清理函数，确保旧的 `AudioContext`、媒体轨道和动画检测循环不再持有引用。
4. 单次语音识别请求持有的 WAV Blob 只存活到请求完成，不因持续监听重启累积未释放的采集链路。

## 未启用声纹识别时的跨显示端 TTS 录音暂停

1. 当任一显示端开始播报 TTS，服务端向所有正在录音的显示端广播播报状态；未启用声纹识别的录音端暂停 PCM/VAD，避免另一台显示端的扬声器回声进入 ASR。
2. 每个独立 TTS 会话携带播放 ID 和播放目标 ID；服务端按目标分别维护播报状态，所有目标完成后才结束对应状态，避免多台播报设备先后结束时误恢复。
3. 播放目标在音频实际播放完成、失败或停止后回报播放 ID，服务端广播结束状态；旧显示端不回报时由服务端超时清理，避免录音端永久暂停。
4. 暂停只清理当前未完成的语音段和前置缓冲，不停止麦克风轨道、不关闭 `AudioContext`，以复用既有采集链路并避免 Chromium 内存持续增长。
5. 多条独立连续 TTS 使用不同播放 ID；同一重复播报组复用一个播放 ID，并携带重复总数。服务端只有收到该组全部完成次数后才广播结束；录音端维护活动播放 ID 集合，只有集合为空才恢复，并在恢复时重置 VAD 段状态。
6. 声纹识别已启用的录音端忽略跨显示端暂停状态，保持当前声纹过滤和语音打断能力。

## ASR 结果回传与命令处理分离

- 显示端完成 ASR 后，服务端先向控制端广播所有有效识别文字，保证控制端可以观察监听期间的实际识别结果。
- 启用声纹识别且 `speaker === null` 时，只阻断唤醒/对话/命令处理，不阻断控制端的文字回传。
- 控制端收到多条结果时仍按显示端覆盖保存，仅显示最新一条，不在列表中无限累积历史。

## ASR 能力异步状态回传

- 显示端 WebSocket 建立时可以先发送初始语音状态，但不能把初始 `voiceSupported=false` 作为最终状态。
- `checkAsrStatus()`、原生 ASR 模型就绪回调和完整能力探测完成后，必须重新回传 `voiceStatus` 及 `capabilities.voiceRecognition`。
- 控制端以异步回传的最新状态为准，避免 ASR 服务已经就绪时仍显示“不可用”。

## ASR 统一服务端识别链路

- 录音显示端只负责采集原始 PCM/WAV 和执行 VAD 分段，所有语音段统一提交服务端 `/api/asr/recognize`。
- 服务端公共接口根据 ASR 设备配置执行本机 ASR，或按显示端连接顺序转发到第一个 `voiceRecognition=true` 的显示端。
- 选择“显示端”时不按 IP、设备名或固定设备优先；连接顺序变化后，候选提供端也随之变化。
- 录音显示端不直接调用自己的 ASR；只有被服务器选中的 Android ASR 提供端处理 `asrAudio` 并回传 `asrResult`。
- 服务端统一负责普通 ASR、声纹匹配/分段、降噪和识别结果返回，录音显示端只处理公共接口的 `text`、`speaker`、`segments` 和错误结果。

## 服务器重启后的显示端监听恢复

1. 显示端 WebSocket 每次重新建立后都重新检查服务端 ASR 状态，不能只依赖页面首次加载时的一次检查。
2. 服务器重启期间 ASR 暂未就绪时，显示端按固定间隔重试；ASR 恢复后重新上报 `voiceStatus` 和能力，并自动恢复原本开启的监听。
3. WebSocket `error` 事件不能只记录日志；应释放异常连接并进入与 `close` 相同的单飞重连流程。
4. 用户通过控制端关闭的 `voiceRecording` 能力必须继续保持关闭，ASR 重试不得绕过服务端能力开关。
5. 重连和 ASR 重试使用可清理的单一计时器，页面离开时取消，避免旧连接或旧请求回调启动录音。

## 显示端语音状态、旋转布局与音频监视图

1. 显示端语音状态固定显示三种用户可理解的状态：`未就绪`、`监听中`、`暂停监听`；浏览器不支持语音、监听被关闭或尚未启动时显示“未就绪”。
2. 未启用声纹识别时，远程 TTS 播放期间沿用现有录音暂停标记，状态显示“暂停监听”；TTS 完成并恢复采集后回到“监听中”。声纹识别开启而允许打断播报时不强制显示暂停。
3. 语音状态标签和音频频谱监视图使用与媒体、时间和媒体名相同的 `currentRotation` 四向布局；90/270 度不能只改变位置，还要对监视图本身应用同角度旋转，并以对应屏幕角为变换原点。
4. 音频监视图持续使用单个 `requestAnimationFrame` 循环。监听中复用已有 `AnalyserNode` 和可复用的频谱数组，等待、暂停或没有有效频谱时显示低幅动态占位柱，避免每帧创建数组和静态空白。
5. 状态文字变化、TTS 暂停/恢复、窗口尺寸变化和角度变化不得创建新的录音链路；只刷新显示状态、布局和监视图绘制。

## 显示端语音修复模式

1. 显示端说“进入修复模式”后，服务端只在该显示端等待下一条语音密码；密码使用配置中的共用明文字符串比较，密码输入不得进入普通聊天、聊天历史、工作 Agent 或日志。
2. 修复模式配置为 `repairMode.password` 和 `repairMode.role`。密码为空时修复模式不可进入；角色从 `aiRoles` 当前角色列表校验，支持多个角色，不能写死为某个角色。
3. 修复模式只允许显示端进入和操作。进入后每一条非退出语音都先发送预览并等待“确认/是/好的”或“取消/拒绝”；确认后调用现有 `AiRolesService` 的工作 Agent 路径，使用配置角色处理原始请求。
4. 修复模式下“退出修复模式”优先于待确认请求，清理密码/确认状态并恢复普通语音处理；显示端断开、关闭录音或会话超时也执行同样清理。
5. 进入修复模式时向所有语音播放显示端发送停止消息，并抑制普通聊天、搜索、提醒、媒体和普通工作 Agent 的后续 TTS；修复模式自己的提示和工作 Agent 回复允许播报。退出后恢复普通 TTS。

## 全局语音对话确认模式

1. 对话确认设置为全局三档模式：`off` 关闭确认、`manual` 手动确认、`auto` 自动确认，默认使用 `off` 兼容现有行为。
2. `manual` 模式下，唤醒后的普通语音先保留原始 ASR 文本，不调用聊天或 Pi；服务端通过通用 TTS 路由播报原文，同时立即向来源显示端发送天气同款详情弹窗，等待用户说“确认/是/好的”或“取消/拒绝”。
3. `manual` 模式待确认有效期为 30 秒；超时、取消或拒绝都直接丢弃原文，不进入聊天历史。内置指令、唤醒词、退出指令和确认/取消指令不进入该流程。
4. `auto` 模式仍先播报并显示原文；所有实际 TTS 播放目标完成确认提示播放后才开启 7 秒取消窗口，期间说“取消/拒绝”则丢弃，否则将原始文本发送到正常聊天路径。TTS 生成或播放失败时不立即提交，仍保留弹窗并开启同样的 7 秒取消窗口。
5. 控制端在声纹管理页面的“声纹识别设置”卡片内提供全局模式选择；语音命令支持“开启对话确认”（`manual`）、“关闭对话确认”（`off`）和“开启自动确认”（`auto`），这些模式控制命令无需唤醒词。
6. 显示端第二行在唤醒退出倒计时后追加确认倒计时，两个时间均使用带背景的独立文本块；确认完成、取消、超时或监听关闭时清理确认倒计时和详情弹窗。
7. 声纹管理页面的注册、声纹列表、声纹识别设置、语音设备、服务器语音功能和语音对话确认统一使用独立的大卡片样式；语音对话确认仍归属于声纹管理页面，但不嵌入其他设置项。
8. 确认倒计时使用独立高对比提示色块；深色主题使用白字深红背景，浅色主题使用深红字浅红背景，避免黄色文字在浅色背景上不可读。
## 显示端语音普通对话走正常聊天路径

1. 显示端语音经过等待唤醒、助手名匹配和内置指令判断后，未被内置指令消费的普通文本必须调用现有聊天服务端路径，不再另建一套语音专用 LLM 请求。
2. 服务端接受普通语音文本后，先向控制端发送带 `requestId` 的 `chatInput` 事件；控制端复用普通聊天的用户气泡和流式助手气泡，用户无需等待 LLM 首个 chunk 才看到自己的输入。
3. `chatInput` 只用于控制端展示，不触发控制端再次发送 `chatMessage`，一次语音输入只能产生一次聊天请求。
4. 普通语音聊天保留原始识别文本、聊天模式、历史和全部角色模板规则；内置指令、确认、唤醒提示和会话控制仍使用语音命令路径。
5. 语音普通对话的回复必须回传到产生输入的显示端：`voiceCommand` 的 `response` 携带完整 `detailText`，显示端用该字段展示完整对话内容，不依赖其他显示端的聊天 UI。
6. 该语音请求的 TTS 使用来源显示端优先、在线 `voicePlayback` 能力兜底的单目标动态路由；来源显示端只接收完整 `detailText` 弹窗，不因语音来源自动改变视频媒体。

## ASR/声纹识别耗时回传

正式显示端完成一次原生语音识别后，`asrResult` 必须携带模型处理耗时，单位为毫秒。`asrElapsedMs` 表示 ASR 模型识别耗时，`voiceprintElapsedMs` 表示声纹分段、特征提取和匹配耗时；未执行对应能力时使用 `null`。

耗时使用 Android 单调时钟测量，只覆盖模型处理阶段，不包含 VAD、PCM 解码、网络上传、服务端转发和播放。多人声纹模式返回整段请求的累计 ASR/声纹耗时，保留现有分段时间区间不变。网页显示端透传字段，服务端 `asrResult` 详细/简要日志均保留字段，旧端缺少字段时继续兼容。

## Active 群聊/私聊搜索路由

1. `activeGroup` 或 `activePrivate` 收到包含“搜索”的普通语音文本时，保留完整原始文本，直接进入当前群聊/私聊 Agent 会话。
2. 上述 active 会话不执行搜索关键词提取、`checkCommandRouting`、本地搜索处理或独立搜索 session；`search` 配置为 `llm` 也不改变该行为。
3. 等待唤醒状态仍沿用现有搜索命令和独立搜索路由，避免改变免唤醒功能。
4. 当前只调整搜索；天气、提醒、播放、静音、报时、录音和自定义指令仍保持现有命令优先级，后续改动记录在 `docs/todo.md`。

## 临时会话角色选择与单角色提示词
