# 个人 Agent 第一阶段

独立子工程负责角色、人设、任务委派、权限检查和模型适配接口。游戏识别、导航与设备执行继续由 AASC-HIE 管理，通过显式注入的适配器连接；不移动绑定导航循环的 HIE 角色运行时。主角色和专用角色分别授予可调用能力，所有调用先检查权限。内部动作命令默认只接受完整方括号包裹的 CSV 格式；解析接口可显式关闭此限制。第一阶段使用模拟模型和工具验证，不连接真实电脑、网页或模型服务。

后续工作：按需接入真实本地能力、网页、Codex/Claude 与持久记忆，并按实际环境验证权限边界；Responses 模型适配已实现，真实浏览器端到端验收待完成。

## 终端聊天界面

默认终端入口使用 Node.js readline 接收人的自然语言，显示 AI 文本、状态和本地调用结果；旧解析工具以独立开发命令保留。方括号 CSV 是模型提出本地调用的内部格式，不要求人输入，也不会把人输入的方括号直接执行。宿主模型以 `respond` 返回文本或明确携带命令的对象，Agent 校验所有命令并只允许宿主配置的角色，再执行既有权限检查并将结果交回模型；每次聊天的模型调用次数有限，默认不允许模型调用任何角色。终端通过 /role 查看角色、/role 名称 切换聊天角色，并将角色名称和人设传给模型；/role --default 恢复未选角色。聊天角色不改变可调用角色或工具权限，角色上下文由模型适配器管理。界面保持可注入，演示只本地回显，真实模型、HIE 与模型的跨轮会话由宿主提供。长任务暂不支持界面取消或流式输出。

## 真实模型与正式角色配置

独立 Agent 默认读取自身本地配置，模型走已配置的 OpenAI Responses 兼容地址；示例指向本机 Gemini2API，密钥只放不提交的本地配置。按拆分设计提供主助手及游戏专用角色，由配置承载人设、授权能力和模型可调用角色；不把 HIE 中绑定环境的运行时迁入 Agent。默认只启用模型聊天，不依赖 HIE；HIE 或其他本地能力由宿主按需注入并显式授权，未接入的能力不能执行。聊天按所选角色分别维护 Responses 续接 ID，切换角色不共享上下文；进程退出后不宣称持久化。真实命令必须由模型的结构化 commands 字段明确提出并经过角色及能力授权；模型纯文本中的方括号不直接执行。配置错误、网络错误和不可续接均显式返回，避免伪造执行结果。

终端 `/new` 显式重置当前角色的本地续接点，并不删除 Gemini 网页记录；会话异常不自动重发以免丢失上下文。未选择角色时使用配置的默认主助手，`/role --default` 恢复它。
