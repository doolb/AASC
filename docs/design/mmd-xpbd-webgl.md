# MMD刚体XPBD WebGL2后端设计（测试版已实现）

## 需求与范围

用户提出将XPBD改为WebGL版本，使用ping-pong贴图计算。现有XPBD为PMX刚体六轴约束求解，JS子步执行积分、关节/接触位置修正、锁轴投影、速度回算、摩擦/反弹和限位速度修正，帧末回写Three骨骼。

已确认第一阶段在独立mmd-ar测试版增加XPBD（WebGL2）选项，保留CPU XPBD与Ammo作兼容回退和对照；本阶段处理刚体XPBD，不迁移TMP14顶点布料，不直接改变正式版。默认求解器保持现值，旧偏好可恢复。

## 计算与数据

复用显示端WebGLRenderer上下文；探测WebGL2、EXT_color_buffer_float、RGBA32F帧缓冲完整性、纹理大小。位置、四元数、线/角速度、前姿态、约束lambda以明确布局的RGBA32F贴图存储，索引在独立Float32纹理中精确表示；Nearest、不生成mipmap、不进行颜色空间转换或混合。每个pass只采样读集合并写另一集合，完成后交换，不读写同一纹理。

每帧上传两端动画骨骼锚点；每子步GPU插值，应用重力、阻尼、相对气流风与预测姿态，求解关节/碰撞、锁轴终态投影、回算速度及速度约束。type0跟随锚点；type2保持锚点位置、允许动态旋转；直接全锁绑定保持CPU定义、不向动态子链传播。重置/T-pose及动作切换时两套状态与前姿态一起初始化并清零速度/lambda。

共享刚体不能被多个约束同时无序写入：静态关节拓扑在CPU加载时图着色，同色不共享可写刚体，按色分pass；约束结果先写自己的槽，再由刚体pass收集修正。接触采用GPU逐对检测与按刚体邻接收集的并行迭代，每对内部按有效质量求解，跨对以有效接触对数倒数松弛；不依赖浮点原子操作或浮点加法混合。保持XPBD柔度alpha/h²和lambda语义，不能用简单位置平均冒充XPBD；并行次序/float32产生数值差异，不承诺与CPU逐帧完全相同。

加载时CPU根据碰撞组、静态类型和排除规则建立保守允许对表，GPU每子步进行AABB及球/盒/胶囊精确接触检测。接触槽按形状算法上界预分配，超出纹理/内存预算显式回退，不静默漏碰撞。允许对数量最坏O(N²)，首版需记录实际对数与显存预算；不在CPU每子步读回生成碰撞对。

帧末将刚体位置/四元数打包到一个结果目标，只集中同步读回一次，复用当前骨骼回写；保持当前帧动作和物理一致。每子步不readPixels。首版不采用可能跨帧延迟的异步姿态读回，不迁移整条骨骼层级和蒙皮；GPU计时扩展可用时统计GPU耗时，始终记录CPU墙钟耗时与同步读回等待。子步诊断不能偷偷恢复逐子步读回，GPU模式明确标记为帧末采样，累计碰撞可在GPU保留标记后按需读回。

## 兼容与异常

无能力/不支持模型容量时切回CPU XPBD并显示实际后端及原因；初始化成功才提交新后端，失败释放新资源并保留原实例。WebGL context lost事件中暂停并销毁自有旧GL句柄，保留CPU姿态；上下文恢复后重新探测并从已保留姿态重建，不能宣称共享上下文丢失时仍可正常渲染。销毁/换模型/换动作清理所有RenderTarget、材质及自有buffer，不能销毁共用renderer。

## 验收与性能

验证静止悬挂、六轴锁定/非零锁值、type0/1/2、质量/惯量与碰撞过滤、球盒胶囊所有形状对、摩擦/反弹、强风及经纬度、模型旋转缩放、动作锚点插值、T-pose初始化清零、失败回滚和上下文恢复。CPU对照按约束误差/有限状态/接触穿透与能量变化评估，不要求位级相同；重点复测左右蝴蝶结6_1等小物件。模型/动作切换至少50次，无GPU资源持续增长。

相同模型/动作/风/子步3、10、45、180和30/60FPS下测CPU总帧时间、GPU计时（扩展可用才记录）、readPixels等待、pass数、显存与整体画面帧率，报告中位数及P95。数百刚体与大量pass/readback时可能更慢，未实测前不宣称加速；目标手机实测另列。

## 当前实现边界

状态为每刚体6个vec4（位置/四元数/线速度/角速度/前位置/前四元数）；关节结果11个vec4；每允许对8个接触槽，每槽3个vec4。每子步1轮，关节lambda从零开始；接触lambda保留到该子步速度摩擦阶段。允许对32768、刚体4096、颜色128、纹理总预算64MiB；超过明确回退CPU。模型初始化仅建拓扑及上传，子步无CPU碰撞扫描。

球盒胶囊解析接触、盒SAT/裁面、胶囊平贴双点支撑、锁轴投影、风及锚点插值均在shader内执行。未实现GPU空间哈希，保守对检测仍可能昂贵；多pass和读回可能抵消并行收益。本机SwiftShader结果不能代表手机硬件性能，真机小物件抖动、碰撞观感与性能仍待现场验收。

## GPU 物理姿态直连骨骼纹理（2026-10-12，用户已确认）

现有PMX `SkinnedMesh` 已在顶点Shader通过 Three 骨骼矩阵纹理完成蒙皮。新增的不是CPU→GPU蒙皮，也不缓存逐顶点位置，而是可选地将 GPU XPBD 的最终刚体纹理直接合成 GPU 骨骼矩阵纹理，跳过普通预览每帧完整 GPU→CPU 刚体/触点同步读取。仅独立测试网页、仅WebGL2 XPBD适用，动作面板提供默认关闭的「GPU物理直连骨骼」开关；不切换求解器、不影响Ammo、CPU XPBD或正式端、APK。用户请求与实际后端、回退原因分别显示。

CPU 保留 VMD/高级动作混合、IK、Grant，并按帧提供局部骨骼P/Q/S；WebGL物理继续使用原RGBA32F状态/求解pass。新骨合成pass复现原物理回写类型/绑定偏移、骨骼父子空间和最终世界矩阵到逆绑定矩阵的转换，按每骨四vec4列输出Three兼容调色板；主材质、阴影和深度一致读取。Three Skeleton每帧自动更新原骨纹理，直连采用每模型独立纹理绑定，不能以数据纹理的CPU更新覆盖GPU RenderTarget，更不得全局修改Three原型。首版维持RGBA32F作为对照基线，half需另行精度验证。

动作有效时以本帧完成IK/Grant后的CPU动画骨骼计算物理锚点；暂停、没有mixer或预热时必须保留GPU上一帧最终局部姿态，并在当前模型根变换下推导锚点，避免使用陈旧CPU骨树。GPU按刚体顺序保留type1位置+旋转、type2仅旋转和同骨多刚体行为；不能保证等价的拓扑/资源超限时明确回退原同步路径。常规帧不读整批刚体；骨骼/刚体诊断等需要CPU姿态时暂回同步，精确拾取或关直连仅按需读取。切模式需保持连续姿态/速度，无法读取的上下文丢失情况显式重置而非假装无损恢复。

验收以浏览器真实GPU对照，覆盖type0/1/2、父子/多刚体、非单位缩放、暂停/初始门控/旋转、动画/表情、开关/诊断/编辑/拾取、换模型/动作、阴影与GPU资源及上下文恢复。测常规/暂停完整读回数为零、诊断读回准确，并报告额外合成pass、总体帧耗和手机实测；无真实测量前不声称提速。实现细节和伪代码见 `docs/spec/mmd-xpbd-webgl.md`；仅修改测试网页源码与构建适配，现有正式发布状态不变。

### 本地实现与验收边界（2026-10-12）

已实现独立RGBA32F骨骼调色板、GPU锚点/局部姿态缓存、Three蒙皮纹理绑定和默认关闭开关。每骨至多一个写入刚体、父刚体先于子刚体、骨骼无缩放、层级最多64且骨数最多1024；同骨多刚体和逆序明确走同步兼容。type1写位置/旋转，type2只写旋转，支持现有模型根缩放。主/深度/阴影沿用Skeleton骨纹理接口，尚未做硬件上的逐像素阴影对照。

默认手部防穿模保持开启，明确提示其CPU依赖并阻止实际直连；用户手动关闭后生效。诊断UI与API都立即同步且诊断期间维持兼容；编辑read/face按需同步，rest重置物理；精确网格拾取入口按需同步。暂停根跟随先在正确物理根恢复CPU局部骨姿态，再交原暂停契约跟随/清速度；同步退出会失效GPU局部姿态缓存，恢复时重新种子，避免陈旧父骨锚点。

真实PMX已验证开关/连续播放与暂停/诊断/编辑/T Pose/上下文恢复/两轮后端重建/关开物理/VMD重载。小骨架覆盖type0/1/2、模型缩放、旋转门控与兼容恢复；50次GPU实例循环验证资源回到基线。手机驱动/复杂动画表情、精确点击与阴影观感、真实PMX模型/VMD50次混合切换以及中位数/P95性能尚未验收，保留待办，不宣称全仓通过或提速。

### 拖动移动/旋转后衣料飞散（2026-10-12，独立场景验收完成）

用户提供截图并确认通过鼠标/触摸拖动，表现为瞬间拉长或飞散。本地真实米娅PMX鼠标右键平移120px/-40px、左键旋转-150px/+50px复现跨屏三角；关闭直连但保留同一WebGL2求解器仍复现，最大刚体坐标由约19增到2760/27102。该缺陷不能用“GPU骨骼矩阵与同一GPU状态的CPU回写接近”排除，因为两者可同样消费已发散物理状态。

定位到接触速度修正：法线从A指向B，正间距表示已分离；旧实现将正间距/h作为强制正向目标，并允许负法向修正，接触点被关节推开后仍可能制造或反向拉回速度。已修正测试端WebGL2接触shader，使用允许闭合的负间距/h下界与只推不拉的法向修正；接触点超出容差后停止旧lambda摩擦，仍接触时保留现有预算及直连零读回。CPU XPBD的同类表达仅记录，不在本轮范围；正式端、APK及发布不变。

进一步定位到拾取/诊断同步后重新直连的端点缓存缺口：刚体已读回，但type0/type2 CPU目标仍停在进入直连前。已在既有单次同步中更新目标位置及前端点；type0旋转也跟随最终姿态，type2动态旋转规则保留，不增加读回或重置运行姿态。

接触八项和小骨架连续同步恢复回归已先失败后通过；type0/type2端点及type0旋转缓存、50次资源循环通过。真实PMX验收新增真正蒙皮顶点范围、刚体位置/速度界限、输入枢轴变化、60Hz真实页面物理更新及mixer推进断言，3/45子步完整32段独立矩阵与最新生命周期均通过；另补45子步纯直连不重置的播放/暂停八段累计拖动也通过，真实直连截图裙摆正常。各独立配置分别重置起始姿态，配置内四种操作连续执行；3子步跨配置累计同步对照复跑仍发散，尚需定位，最终轮30项29通过/1累计失败，不能推断所有累计切换稳定。详见`docs/task/20261012_MMDAR拖动布料飞散修复.md`。
