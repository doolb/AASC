# 显示端摄像头拍照、实时预览与 AI 图片聊天设计

## 需求范围

- 控制端在当前选中显示端的声音卡片下方显示摄像头卡片。
- 每个显示端同一时刻只选择一个摄像头；摄像头列表由显示端通过 WebSocket 返回，控制端提供切换。
- 支持单次拍照和实时视频预览。实时视频只用于监控预览，不保存、不进入聊天、不发送给 AI。
- 单次拍照可以由控制端加入聊天输入的图片附件，并随下一条普通 LLM 消息发送。
- 浏览器显示端和 Android WebView 显示端复用 `display.html`；Windows `voice-display-node` 声明暂不支持摄像头。

## 交互设计

1. 控制端选择一个显示端后，摄像头卡片显示能力状态、摄像头选择框、刷新按钮、拍照按钮和实时预览按钮。
2. 显示端上线且控制端首次渲染摄像头卡片时自动刷新设备列表；显示端按浏览器权限策略申请摄像头权限，并返回可用摄像头列表。自动刷新只读取设备，不自动开启预览。
3. 切换摄像头时先停止当前视频轨道，再按所选 `deviceId` 重新打开；不并行打开多个摄像头。
4. 实时预览采用低分辨率 JPEG 定时帧，只发送给发起控制端的控制 UI；控制端断线或点击停止后，显示端停止轨道和定时器。
5. 单次拍照优先使用视频轨道的 `ImageCapture.takePhoto()` 获取原生照片；不支持时再等待多个稳定视频帧并使用 Canvas 生成 JPEG，超时则释放轨道并返回错误，避免 Android WebView 读取黑帧。
6. 单次拍照完成后，控制端显示图片缩略图，点击“发送给 AI”后加入聊天输入区；图片可在发送前移除。
7. 显示端在刷新设备、拍照、实时预览、停止和错误状态期间显示摄像头状态提示，不改变媒体显示区和语音状态。
8. 控制端收到 LLM 状态更新时只刷新 LLM 模型面板，不重绘包含摄像头列表的声音卡片，避免摄像头下拉列表在展开过程中被自动收起。

## 一致性和边界

- 服务端只负责鉴权目标显示端、转发请求和回传消息，不保存实时视频帧。
- 每条请求包含 `requestId`，结果必须带回同一 ID；过期/未知请求返回错误并由前端恢复空闲状态。
- 服务端限制单张图片和实时帧的 Base64 大小；超过限制直接丢弃并回传错误，避免 WebSocket 内存持续增长。
- 显示端重连后不自动恢复摄像头流，控制端需要重新发起刷新或预览。
- AI 图片消息保留图片数据用于当前模型请求；聊天历史只保留图片 MIME 元数据，当前消息由控制端即时渲染，避免把大段 Base64 持久化到历史文件；Agent 角色链路暂不接受图片并返回明确提示。

## 多摄像头策略

- 一次只采集一个摄像头。
- 移动设备优先选择 `environment` 后置摄像头，桌面设备选择第一个可用摄像头。
- 设备标签在浏览器授权前可能为空，控制端显示“摄像头 1/2...”作为回退名称。
