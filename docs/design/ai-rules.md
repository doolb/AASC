# AI 执行规则设计

## 功能需求

工作 AI 修改项目代码后，如果需要让服务器加载新代码，只能通过控制端提供的重启/重载接口或控制端操作完成，不得直接控制服务器进程。

## AI 任务系统通用能力规则

用户任务是由项目维护者自行管理的代码隔离单元，不按第三方插件处理。任务可以自主管理自己的控制端展示、交互逻辑和 URL 路由；任务系统负责提供统一的运行上下文、消息转发和生命周期清理，不引入控制端页面/动作白名单层。

- 任务声明必须明确执行目标、执行模式和参数；不同任务的参数、默认值和配置可以互相独立。
- 内置任务与用户任务遵循同一任务描述和上下文契约；后续可将稳定的内置任务实现迁移到 `res/tasks/<taskName>/`，只要保留入口、元数据和上下文能力，控制端不需要改任务专用逻辑。
- 控制端展示优先复用任务元数据：`sidebar` 声明侧边栏归属，`widget` 声明任务卡片/实例/侧边栏中的展示和交互，`control.actions` 声明任务页面或弹窗，`configButton` 仅作为旧任务专属配置入口兼容字段。
- `widget.html` 和 `widget.script` 属于任务自管理的控制端 UI 资源，由任务自行维护 HTML、JavaScript、事件和状态更新逻辑。
- 任务服务可以使用通用上下文完成进度上报、Widget 更新、Widget 动作、任务间关联和 URL 路由注册；任务停止、异常、显示端断开或服务销毁时必须由任务引擎统一清理。
- URL 路由必须通过 `context.registerRoute()` 注册到 AASC 当前服务端口（暂定 `8081`），不得由显示端任务自行监听新的 TCP 端口；显示端请求通过已有 WebSocket 转发。
- 服务端负责校验任务实例归属、转发 `type` 消息、保存实例状态和清理资源；任务负责自己的业务处理和前端 UI 资源，不绕过任务上下文直接控制服务器进程。

## 规则边界

- 适用对象：工作 AI、workgroup 子 agent、控制端 AI 角色。
- 允许操作：修改代码、更新文档、运行测试和静态检查；通过控制端接口发起服务器重启/重载。
- 禁止操作：直接查找或操作服务器 PID，发送终止信号，执行 `kill`、`pkill`、`killall`，以及直接启动、停止或重启 `server-app.js`。
- 用户手动启动的服务器属于用户管理范围，AI 不得终止、替换或接管。
- 控制端接口不可用时，AI 应报告阻塞原因并交由用户处理。

## 任务台账与变更日志规则

- `docs/todo.md` 是未完成任务台账，只保留 `⏳待处理`、`⏳可选任务` 和 `🔄进行中` 条目。
- 任务完成后，从 `docs/todo.md` 删除对应条目，不再使用 `✅已完成` 作为待办状态长期保留。
- 完成记录写入 `changelog.md`，至少包含完成日期、任务摘要、主要改动和验证结果。
- 如果 `changelog.md` 已有同一变更记录，应补充或合并原记录，避免重复追加。
- 可选任务在真正实施前保持 `⏳可选任务`，取消时应明确标记取消原因或移除并保留必要的决策记录。

## 设计原则

1. 规则写入项目级 AI 规则文件，保证不同工作角色使用同一约束。
2. 工作组 main 角色额外携带该规则，避免拆分任务时遗漏重启边界。
3. 任务状态和变更归档分离，避免待办清单与版本变更记录混用。
4. 本次只增加行为规则，不改变服务器生命周期实现；技术层命令拦截另行立项。
