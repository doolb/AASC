# AI 执行规则设计

## 功能需求

工作 AI 修改项目代码后，如果需要让服务器加载新代码，只能通过控制端提供的重启/重载接口或控制端操作完成，不得直接控制服务器进程。

## 规则边界

- 适用对象：工作 AI、workgroup 子 agent、控制端 AI 角色。
- 允许操作：修改代码、更新文档、运行测试和静态检查；通过控制端接口发起服务器重启/重载。
- 禁止操作：直接查找或操作服务器 PID，发送终止信号，执行 `kill`、`pkill`、`killall`，以及直接启动、停止或重启 `server-app.js`。
- 用户手动启动的服务器属于用户管理范围，AI 不得终止、替换或接管。
- 控制端接口不可用时，AI 应报告阻塞原因并交由用户处理。

## 任务台账与变更日志规则

- `docs/todo.md` 是未完成任务台账，只保留 `⏳待处理`、`⏳可选任务` 和 `🔄进行中` 条目。
- 任务完成后，从 `docs/todo.md` 删除对应条目，不再使用 `✅已完成` 作为待办状态长期保留。
- 完成记录写入 `changelog.md`，至少包含完成日期、任务摘要、主要改动和验证结果。
- 如果 `changelog.md` 已有同一变更记录，应补充或合并原记录，避免重复追加。
- 可选任务在真正实施前保持 `⏳可选任务`，取消时应明确标记取消原因或移除并保留必要的决策记录。

## 设计原则

1. 规则写入项目级 AI 规则文件，保证不同工作角色使用同一约束。
2. 工作组 main 角色额外携带该规则，避免拆分任务时遗漏重启边界。
3. 任务状态和变更归档分离，避免待办清单与版本变更记录混用。
4. 本次只增加行为规则，不改变服务器生命周期实现；技术层命令拦截另行立项。
