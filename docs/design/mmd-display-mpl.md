# 正式显示端 MPL 动作与表情

## 需求

2026-10-10 用户要求将 MPL 也接入正式端。接在本轮已迁移的通用表情控制后，网页消费已生成的MPL，不调用LLM；本轮不自动接入TTS口型。

## 方案

- 正式「动作 → MPL 动作」提供代码输入、编译播放、取消编译/停止恢复原动作、动作＋表情/纯表情示例和VMD下载。
- 正式与独立网页共享mmd-mpl-ui/worker/morphs模块及固定MMD-MPL 0.3.6编译器；编译器本地同源部署，附带上游GPL-3.0许可证及来源/哈希清单，点击播放才加载WASM。
- 移除MPL对独立编辑器mesh接口的依赖：runtime/DisplayMmd提供只读MPL模型快照，含模型token、骨骼原名、Morph元数据与真实可用状态，不暴露mesh。
- 编译与播放仍沿用现有资源注册表、VMD加载、动作恢复、异步模型/动作保护和大小/超时限制；手动表情覆盖优先。
- 同步迁移循环不重置物理的已确认方案，正式默认/本地/MPL共用helper，显式换模型/换动作初始化保持现有流程。
- 独立构建按共享模块实际内容添加依赖指纹，不重复注入MPL UI；无需新增npm生产依赖。服务源码和本地静态WASM资源由代码包覆盖，servicePackage=true。

已实现正式面板、只读模型快照、共享MPL三模块与编译器资源、独立构建依赖指纹及共用循环物理连续性。prepare:mmd-mpl及web-dist构建成功，12源文件语法、正式/生成各7模块语法、MPL依赖与指纹、两端各3项固定资源大小/SHA-256和差异空白检查通过。未新增或运行自动/浏览器测试；servicePackage=true，未提交/发布正式服务包，实际设备验收待安排。
