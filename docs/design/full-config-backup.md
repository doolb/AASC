# 全量配置与聊天数据 ZIP 备份

状态：已实现，定向自测与 Android 编译通过；发布时重出代码和依赖包。

## 需求与范围

控制端新增“导出全量配置”“导入全量配置”，同时保留现有 aasc-user JSON 导入导出入口。ZIP 包含当前服务实例的全局配置目录和用户配置目录；用户目录中的群聊、私聊、会话选择、角色历史、模板、提醒及 Chat2API 账号/模型映射等持久化数据一并收录。账号凭证和 API Key 作为配置内容保留。

普通模式按 release-runtime-context 解析 config 与 aasc-user；Offline/release 模式解析 release/config 与 release/userconfig。备份不携带源机器的绝对路径，导入映射到目标实例的实际目录。模型、媒体原文件、任务结果、日志、PID、锁、缓存、历史备份与临时文件不属于本需求范围。

## ZIP 格式

- `manifest.json`：格式标识、版本、创建时间、文件相对路径、所属配置范围、大小与 SHA-256。
- `config/**`：全局持久化配置原文件。
- `userconfig/**`：用户持久化配置和聊天数据原文件。
- 文件名使用 `aasc-full-config-<日期时间>.zip`，原文件直接压缩，不使用 Base64 包装。
- 采用纯 Node ZIP 生成能力，在 Android Node 环境不调用系统 zip；直接生产依赖 yazl 提供流式写入，ZIP 读取复用 yauzl。

## 导出与恢复流程

导出先完成必要的聊天延迟保存，再建立文件快照；复核文件清单与文件状态，遇到并发修改时重试或明确失败，不返回无法校验的包。响应为 application/zip 下载，缓存关闭，日志只记录数量和结果。

导入先上传 ZIP 并校验，显示全局/用户文件数量、聊天数据范围与覆盖数量。默认按文件合并：同路径覆盖，目标端额外文件保留。另提供明确选择的完整替换模式：仅删除受管持久化范围内未在备份出现的文件。

确认导入后保存在固定暂存目录，先返回成功及“服务器正在重启”，再自动触发现有托管重启流程。响应结束/连接关闭处理幂等，只重启一次；校验失败或取消不重启，非托管启动模式在接受导入前明确拒绝自动恢复。恢复在新进程启动、配置模块加载前执行，避免旧配置缓存、延迟聊天保存和在途回复覆盖恢复数据。应用前生成独立回滚备份；写入使用临时文件和原子替换，记录事务状态，失败恢复原文件。重连后显示该次应用结果并刷新配置。若导入更改服务地址/端口且当前地址无法连接，提示按导入后的地址重新连接。

## 浏览器与 Offline APK

浏览器使用普通下载与 ZIP 文件选择。APK 导入复用已修复的 WebView 文件选择器；NativeControl 已有16MiB小文件保存能力，全量 ZIP 在该桥使用流式保存入口直接写入系统Download。原生端只接受当前控制页服务来源的备份下载，复用现有证书校验，保存完成/取消/失败均返回页面，不增加通用存储权限。修改 Chat2ApiNativeBridge、MainActivity，并复用 ModelDownloader 连接能力。

## Android路径别名与Download导出修复（2026-10-13，已实现，API28 Download与启动复测通过）

ADB安装full v38后复现内置v69启动失败，安装v70后同样失败并触发回滚。Android系统`/data/user/0 -> /data/data`被工作目录父级链接检查拒绝。受信任项目根先解析为真实目录，默认备份工作目录与配置范围据此派生；根内部的工作目录/配置文件链接仍拒绝。

用户已确认最终ZIP直接保存到系统Download；上传、解包与恢复事务仍在服务内部。Android复用现有同来源流式下载与100MiB约束，API29+使用MediaStore pending文件，旧系统使用Download独占新文件，失败只清理本次新文件，完成回传文件名与保存位置。

用户要求启动和应用更新错误可见。Native收集有界、脱敏的实际错误摘要；失败/回滚显示原因与保留版本，直到重试或健康启动。更新成功必须等待实际候选服务版本/路径通过健康检查，不能在文件切换后提前提示成功。
