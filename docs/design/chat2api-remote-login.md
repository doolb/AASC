# Chat2API远程交互登录

状态：已实现；2026-10-22用户最终确认登录与豆包运行共用浏览器。本节替代此前独立登录进程和空白页保活方案。

## 需求

普通控制端远程显示服务器网页登录画面，支持点击、拖动、滚动、英文键盘及文字输入栏，复用10种Provider登录声明及OAuth保存。全服务最多一个登录会话。Android显示端暂不接入，Android原有原生登录入口不变。

## 共享浏览器与页面角色

登录与豆包运行共用同rootDir的浏览器租约、固定本机debug port（默认9224）和统一持久profile。新安装使用`browser-profiles/shared`；现有受管豆包目录通过`shared-browser-profile.json`登记并原地沿用，不搬动运行数据。切换账号不切换profile。

登录通过默认Context创建唯一登录tab，各网站按域名保留自己的Cookie/localStorage，不向其他Provider套用豆包Cookie。关闭登录只关tab，不清空网站设置。`remote-login-page.json`记录端点与targetId，运行页整理排除登记登录页；重启后恢复该角色，重新打开登录只回收对应旧tab。

登录期间固定宿主账号；豆包登录与豆包运行请求互斥，避免共享网站身份变化。其他Provider登录允许运行页继续使用原账号，保留原身份校验。

## 重连与退出

启动前探测127.0.0.1调试端口。已有实例通过CDP命令行核对实际user-data-dir，兼容旧实例时读取chrome://version的profile路径；只有匹配受管profile才接管，其他实例拒绝。服务器被强制退出后重启可连接存活浏览器；不会声称恢复原WS登录会话，控制端须重新打开登录。新登录只回收remote-login-page.json中端点与targetId均匹配的遗留登录tab，不扫描删除其他标签。

新启动实例在专用Preferences关闭Vivaldi退出/关闭窗口确认。已运行实例先校验归属，再调用Vivaldi内置prefs API更新相同设置；不更改用户日常profile。正常服务器退出先结束登录，再停止全部共享浏览器桥；固定profile保留供重启使用。

## 会话与传输

WS协议绑定拥有者连接、实例、Provider、账号、随机会话ID及输入序号。其他控制端得到占用提示。同拥有者切换先确认；输入在通用日志记录前分流，不记录文字/密码。截图1024×720、JPEG65、最大2MiB；帧率默认10，可设整数1～30；服务端按截图开始时间缓存，客户端等待回包与解码后扣除已耗时再调度，队列最多64项。有效期不超过OAuth期限。完成经现有OAuth校验及锁内账号版本比较保存，只回送结果。

## 验证边界

定向测试使用隔离profile和本地网页，覆盖中文输入栏、拖动、截图、标签隔离、PID/WS端点重连、错误profile拒绝、账号保存冲突及会话回收。模拟CDP断连代表连接丢失，不把它描述为已杀死正式服务器进程。官网各Provider真实认证、验证码及中文输入法直接输入仍需分别验收。只影响servicePackage，无APK改动。

## 控制端设置与显示

帧率走AASC WS配置注册、config.set持久化和权威广播。保存期间保持用户输入，只有匹配requestId的回执才结束保存；10秒无回执提示超时，断线默认10。设置值是采集频率上限，实际速度取决于截图、网络和解码耗时。

显示方式默认“适应”，完整显示截图并留边；“铺满”等比裁剪填充。面板限制在视口内，坐标根据比例和居中偏移换算，留白点击忽略、拖动释放限幅。模式仅影响当前控制端窗口。
