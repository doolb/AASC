# Chat2API远程交互登录

状态：已实现；2026-10-22用户最终确认登录与豆包运行共用浏览器。本节替代此前独立登录进程和空白页保活方案。

## 需求

普通控制端远程显示服务器网页登录画面，支持点击、拖动、滚动、英文键盘及文字输入栏，复用10种Provider登录声明及OAuth保存。全服务最多一个登录会话。Android显示端暂不接入，Android原有原生登录入口不变。

## 共享浏览器与页面角色

登录通过同rootDir的doubao-browser-port租约借用豆包launcher。沿用固定的`browser-profiles/doubao/<账号SHA256前24位>`及任务浏览器/debugPort配置（默认vivaldi、9224）；不启动独立登录进程，不创建空白保活页。

当前运行账号优先；重启后从私有active-browser.json及已有豆包账号集合匹配实际profile，空账号初次启动采用external-login稳定标识。此记录只存账号ID/端口/程序名，不存Cookie或聊天。账号变更由原launcher管理；登录打开期间固定宿主账号，拒绝切换宿主，防止运行请求关闭登录浏览器。

登录每轮创建独立BrowserContext和标签，防止登录其他Provider/账号时污染运行Cookie。豆包运行页使用默认Context，现有旧页整理仅处理默认Context；不复用、不导航或删除登录Context。登录弹窗只接管登录页opener。关闭、完成、断线或到期回收登录Context及pin；其他运行标签保留。最后标签关闭时允许浏览器退出，下次自动启动；不再保证进程永远存活。

## 重连与退出

启动前探测127.0.0.1调试端口。已有实例通过CDP命令行核对实际user-data-dir，兼容旧实例时读取chrome://version的profile路径；只有匹配受管profile才接管，其他实例拒绝。服务器被强制退出后重启可连接存活浏览器；不会声称恢复原WS登录会话，控制端须重新打开登录。新登录只回收remote-login-context.json中端点与Context ID均匹配的遗留登录环境，不扫描删除其他标签。

新启动实例在专用Preferences关闭Vivaldi退出/关闭窗口确认。已运行实例先校验归属，再调用Vivaldi内置prefs API更新相同设置；不更改用户日常profile。正常服务器退出先结束登录，再停止全部共享浏览器桥；固定profile保留供重启使用。

## 会话与传输

WS协议绑定拥有者连接、实例、Provider、账号、随机会话ID及输入序号。其他控制端得到占用提示。同拥有者切换先确认；输入在通用日志记录前分流，不记录文字/密码。截图1024×720、JPEG65、最大2MiB；客户端解码后约300ms请求下一帧，服务端250ms缓存，队列最多64项。有效期不超过OAuth期限。完成经现有OAuth校验及锁内账号版本比较保存，只回送结果。

## 验证边界

定向测试使用隔离profile和本地网页，覆盖中文输入栏、拖动、截图、标签隔离、PID/WS端点重连、错误profile拒绝、账号保存冲突及会话回收。模拟CDP断连代表连接丢失，不把它描述为已杀死正式服务器进程。官网各Provider真实认证、验证码及中文输入法直接输入仍需分别验收。只影响servicePackage，无APK改动。
