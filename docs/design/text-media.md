# 纯文本分页 TTS 播放设计文档

## 需求概述

新增 `.txt` 与 `.md` 纯文本媒体类型。显示端按当前屏幕可用区域分页展示文档，并在显示端按现有分句规则拆分当前页；每个分句单独请求服务端 TTS。当前页的所有分句播放完成后自动进入下一页。纯文本媒体同时纳入现有批量播放模式，批量项结束后切换到下一个文档。

## 已确认的行为

| 场景 | 规则 |
|------|------|
| `.txt` | 按原始纯文本显示，保留换行，不执行 HTML |
| `.md` | 使用现有安全 Markdown 渲染器显示，原始 HTML 转义，危险链接不执行 |
| 分句 | 显示端按与服务端现有实现一致的分句规则拆分当前页 |
| TTS | 显示端逐句请求服务器，服务器每次只合成一个分句并返回音频 |
| 自动播放 | 当前页所有分句播放结束后自动进入下一页；最后一页结束后结束当前文档 |
| 单文档控制 | 播放、暂停、上一页、下一页、停止 |
| 批量控制 | 沿用现有播放/暂停、上一个、下一个、停止；文本项内部继续执行分页和逐句 TTS |
| 停止语义 | 停止语音和自动推进，保留当前文档与当前页；再次播放从当前页继续 |
| 手动翻页 | 取消当前句和剩余句队列，切换页面后重新请求新页 TTS |
| 最后一页 | 语音结束后停止当前文档；批量模式下切换到下一个列表项 |
| 文本样式 | 控制端通过“文本模式”面板设置，默认浅黄色背景、深灰色文字、自动字体、标准行距和标准页边距 |

## 方案架构

采用“显示端分页与分句、服务端单句合成”的职责划分：

```text
控制端选择 txt/md
    → mediaType=text + format=plain/markdown
    → 服务端转发单媒体或 playlistStart
    → 显示端读取 URL/base64 文本
    → Markdown 安全渲染或纯文本渲染
    → 按屏幕尺寸生成 page[]
    → 当前页按既有分句规则生成 sentence[]
    → 每个 sentence 请求服务端 textSentenceTts
    → 服务端调用 tts.generateTTS(sentence)
    → 显示端串行播放音频
    → 当前页完成后 nextPage；文档完成后 playlistNext
```

分页必须在显示端完成，因为不同显示端的 viewport、旋转角度、字体和 WebView 尺寸可能不同。分句也放在显示端完成，服务端只处理单句合成，避免服务端重新解析整页文本以及停止/翻页时产生整页的无效 TTS 任务。

## 分页设计

- 文本播放器使用独立的 `#mediaText` 容器，不复用 HTML iframe 滚动。
- `.md` 先渲染为安全 HTML，`.txt` 使用 `textContent`/等宽文本样式渲染。
- 文本页默认使用浅黄色背景 `#FFF4B8` 和深灰色正文 `#333333`；代码块、引用区域使用同色系稍深底色，链接使用深蓝色。
- 背景与文字颜色属于文本播放器专用样式，不改变图片、视频、音频和 HTML 媒体的既有样式。
- 使用与 `#mediaText` 已完成旋转布局后相同宽高的隐藏测量容器，按块元素高度贪心组页，旋转坐标只在显示层交换一次。
- Markdown 缺少空行时仍按可量测行/渲染子节点分页；单个长段、列表或代码行超过一页时按量测文本片段继续拆分，不能发生裁切。
- 页面尺寸变化或旋转后重新分页，保留当前页首段的文本锚点并将页码限制在新页数范围内。
- 页面进度上报包含文档索引、页索引、页总数和播放状态，控制端显示“文档 N / 总数 · 第 X / Y 页”。

## 分句与 TTS 设计

- 现有服务端 `chat.splitIntoSentences()` 的规则提取为可在浏览器执行的共享规则模块，服务端和显示端共用同一规则定义。
- 显示端对当前页的可读文本分句；Markdown 的标题、列表符号、代码围栏等格式标记不进入 TTS 文本。
- 显示端只发送单句：`textSentenceTts { playbackId, pageIndex, sentenceIndex, text }`。
- 服务端串行调用 `tts.generateTTS(text)`，返回带 `playbackId/pageIndex/sentenceIndex` 的 `tts/playAudio`。
- 显示端只接受当前 `playbackId`、当前页和当前句序号的回包；暂停发生在回包前、停止、翻页和切换批量项都会使旧 playbackId 失效，恢复播放时以新 ID 重发当前句。
- 单句合成失败只跳过该句并继续当前页；全部句子处理完成后仍发送页面完成事件。

## 批量播放设计

- `PlaylistManager.MEDIA_TYPES` 增加 `text`。
- 播放列表项增加 `format` 字段，媒体库项携带 URL，临时项携带 base64、文件名、MIME 和格式。
- 文本项不使用图片/视频的 interval 计时器；其自然结束条件是最后一页最后一句播放结束。
- `playlistProgress` 增加 `pageIndex/pageTotal/textIndex/textTotal` 等轻量进度字段。
- 批量暂停暂停文本 TTS 和自动翻页，恢复后从当前句继续；批量 next/prev 取消当前文本状态并切换项。
- 批量循环开启时，最后一个文本项结束后回到第一个列表项；关闭时发送 finished。
- 文本批量重连恢复当前列表项、页码和暂停状态；页码优先读取专用 `currentTextProgress`，兼容旧的 `currentMediaProgress`；语音从当前页的第一句重新生成，避免持久化音频文件状态。

### Task 5 已实现的混合列表衔接

- 显示端在文本项开始前清理上一轮文本句子并调用 `TextMediaPlayer.attachPlaylist({ listId, index, total })`；仅其最后一页完成回调才调用既有 `playlistNext()`。
- `playlistControl` 的 pause、resume、prev、next、jump、stop 继续沿用原协议；文本项分别暂停/恢复或失效旧句子，避免迟到的 TTS 回包推进新项。
- `playlistProgress` 除原媒体时间字段外，携带 `pageIndex/pageTotal/sentenceIndex/sentenceTotal/format`；服务端只持久化非临时列表的标量进度。
- 临时 base64 列表仅保留文件名、媒体类型、尺寸和文本格式的展示元数据，绝不写入可恢复状态。

## 控制端设计

- 媒体库文件列表识别 `.txt/.md` 并使用文本占位缩略图。
- 单文件发送、普通上传、临时上传和临时批量上传均携带 `mediaType=text` 与 `format`。
- 媒体播放控制区域增加“文本模式”按钮，交互方式与现有“HTML 模式”一致。
- “文本模式”面板提供字体大小、行间距和页边距设置；主题默认固定为浅黄色背景 `#FFF4B8` 与深灰色文字 `#333333`。
- 设置通过 `control` 消息发送到当前显示端并持久化；显示端收到后立即应用样式并重新分页，当前页按内容位置尽量保持。
- 媒体播放控制区域显示文本专用按钮：播放/暂停、上一页、下一页、停止及页码状态。
- 主控制面板和浮动控制面板都提供“文本模式”入口；浮动入口调用主面板复用的文本样式弹窗与发送逻辑，保证两处发送相同的 `textStyle` 字段和默认主题。
- 浮动控制面板继续复用文本播放动作，批量播放面板继续显示列表级上一个/下一个。
- 收到 `textProgress` 或带文本进度的 `playlistProgress` 后，只更新当前选中显示端的文本状态。

## 错误与边界

| 场景 | 处理 |
|------|------|
| 文件为空 | 显示空文档提示，不发起 TTS |
| 非 UTF-8 字节 | `TextDecoder` 使用替换字符继续显示，记录解析告警 |
| Markdown 原始 HTML | 由现有渲染器转义，不执行脚本 |
| TTS 服务失败 | 显示端跳过当前句，服务端记录错误；不阻塞后续句/页 |
| TTS 回包过期 | playbackId、文档索引、页索引和句索引校验失败则丢弃 |
| 快速连续翻页 | 递增 playbackId，清空音频队列和请求状态，只保留最后一次操作 |
| 显示端无语音能力 | 文本仍可翻页显示，控制端提示 TTS 不可用 |
| 文档批量临时数据过大 | 沿用现有临时批量 WebSocket 总量限制 |

## 受影响模块

| 模块 | 设计变化 |
|------|----------|
| 媒体类型 | `.txt/.md` 识别为 `text`，并记录 plain/markdown 格式 |
| 显示端 | 新增文本容器、分页器、分句器、单句 TTS 队列和文本播放状态 |
| 服务端 | 新增单句 TTS WebSocket 处理与过期请求隔离 |
| 批量播放 | 接纳 text 项，按文档自然结束切换并回传双层进度 |
| 控制端 | 新增文本页控制和批量文本进度显示 |
| 持久化 | 保存文本样式、当前文本列表、文档索引、页索引和暂停状态，不保存音频内容 |

## 非目标

- 不把 Markdown 转换为服务器端 HTML 文件。
- 不执行 Markdown 中的脚本、原始 HTML 或自动下载外部资源。
- 不新增独立的 TTS 服务配置；沿用现有服务器 TTS 配置、超时和错误处理。
- 不改变图片、GIF、视频、音频和 HTML 媒体既有播放语义。
