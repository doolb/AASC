# Windows 子显示端语音转文字输入设计

## 概述

Node.js 子显示端在 Windows 上增加系统级语音转文字输入能力。用户通过全局快捷键 `Ctrl+Alt+Space` 或语音命令“开始输入”进入输入模式，随后识别出的普通语音文本通过 Windows 前台窗口输入，而不是写入子显示端自身的 TUI；“返回”删除最近一次完整语音输入，“发送”向当前窗口发送 Enter，“结束输入”退出输入模式。

## 实现状态

本功能已落地到 Node.js 子显示端：Windows 输入注入器和全局快捷键由独立模块封装，ASR 请求携带本地输入上下文，服务端在激活词和 active 输入模式下旁路原有语音命令/聊天处理链路；“结束输入”及开始/结束状态提示也已接入，提示期间暂停录音。状态提示已与全局 TTS 录音门控隔离，避免提示完成后残留远程播放状态而导致录音无法恢复。SendInput 的原生结构尺寸和 PowerShell 输出编码已修复，并保留 Win32 错误码。非 Windows 平台和未携带本地输入标记的旧客户端继续使用原有行为。

## 需求

1. 本期仅支持 Windows，非 Windows 环境不注册快捷键、不调用系统注入，并保持现有语音识别与语音命令功能。
2. Node 子显示端启动后默认处于普通语音处理状态，不自动向其他窗口注入文字。
3. 全局快捷键 `Ctrl+Alt+Space` 切换 Windows 语音文字输入模式；快捷键不要求 Node TUI 获得焦点。
4. 识别到完整且规范化文本“开始输入”时进入 Windows 语音文字输入模式，不能把该激活词发送到服务器聊天或命令处理链路。
5. 输入模式下，普通最终 ASR 文本注入识别结果产生时的 Windows 前台窗口；一次 ASR 分段作为一次可返回的语音输入记录。
6. 输入模式下的完整短指令“返回”删除最近一次语音输入记录；没有可返回记录时不发送删除按键。
7. 输入模式下的完整短指令“发送”向最近一次注入的同一前台窗口发送 Enter，成功后清空记录并退出输入模式。
8. 输入模式下的完整短指令“结束输入”退出输入模式，不注入目标窗口，并播放结束提示。
9. 开始/结束输入均播放明确提示；提示播放开始前暂停录音，提示播放完成或失败后才恢复录音，避免把提示音识别为用户语音。
10. 输入模式下的普通文本不进入服务器语音会话、聊天、内置命令和控制端 `voiceInput` 回显链路；服务器只返回 ASR 结果给子显示端。
11. 文本注入使用 Unicode 剪贴板配合 Ctrl+V，注入完成后尽力恢复原有文本剪贴板，避免中文被逐字符编码破坏。
12. 返回、发送和普通注入均串行执行；当目标前台窗口已经变化时，返回和发送必须拒绝执行并保留输入状态，避免误操作新窗口。
13. Windows 输入注入不可用、PowerShell/Win32 调用失败或剪贴板被占用时，记录可诊断错误，不影响子显示端录音、ASR 和 WebSocket 重连。

## 设计边界

- 本期目标是 `src/apps/voice-display-node` Node 子显示端，不改 Android APK、Go 子显示端和 C# 子显示端。
- 本期不新增控制端配置页面，不新增 HTTP 配置读写接口；快捷键作为 Node 子显示端本地固定默认行为记录。
- 不使用子显示端 TUI 底部输入栏承载语音文本；现有 TUI 手工输入和 Enter 发送能力保留。
- ASR 仍使用现有 `/api/asr/recognize`，仅增加可选的本地 Windows 文本输入请求标记，普通客户端兼容旧协议。

## 组件与数据流

```text
Windows 全局快捷键 / ASR 结果“开始输入”
                    ↓
          Node 子显示端 textInputMode
                    ↓
        暂停录音并请求开始/结束提示
                    ↓
        ASR 请求携带 localTextInputMode
                    ↓
              主服务器 ASR
          ┌─────────┴─────────┐
          │                   │
    普通语音命令链路       本地输入旁路
    （模式关闭）            （模式开启）
                              ↓
                 Windows 前台窗口快照
                              ↓
                    Unicode 粘贴注入
                              ↓
                  返回记录栈 / 发送 Enter
```

### Windows 输入注入器

新增独立模块封装 Windows 平台能力：

- 检测 `process.platform === 'win32'`；其他平台返回明确的不可用结果。
- 通过隐藏 PowerShell 子进程调用 Win32 `GetForegroundWindow`、Unicode 剪贴板、`SendInput`。
- C# Win32 结构完整匹配原生 `INPUT` 联合体布局，包含最大成员以使 x86/x64 的 `cbSize` 正确。
- 将文字、目标窗口句柄和操作类型编码传给 PowerShell，避免命令行转义破坏中文或特殊字符。
- 强制 PowerShell 标准输出使用 UTF-8，并记录 `SendInput` 的 Win32 错误码，避免中文异常乱码且便于诊断。
- 维护串行 Promise 队列，保证“设置剪贴板 → 粘贴/按键 → 恢复剪贴板”不与下一次操作交叉。
- 返回目标窗口标识和操作结果，调用方据此执行焦点一致性校验。

### Node 子显示端输入状态

```text
textInputMode:
    inactive      普通 ASR 结果由服务器处理
    active        普通 ASR 结果进入 Windows 输入注入器

textInputHistory:
    按识别顺序保存本次输入模式注入的文本和目标窗口标识

textInputAnnouncement:
    requestId: 当前开始/结束提示请求标识
    state: pending | playing | waiting-queue | finished | failed
    播放完成只由来源 Node 本地音频队列确认，不参与全局 TTS 播放状态门控
```

状态只保存在当前 Node 进程内，断线、重启或输入模式结束后清空。

### 服务端 ASR 旁路

- 子显示端所有 ASR 请求标记 `textInputClient=true`，输入模式开启时再标记 `localTextInputMode=active`。
- 服务端识别到精确激活词“开始输入”且请求来自 `textInputClient` 时，返回 `localTextInputAction=activate`，不进入 `processDisplayVoiceInput`。
- `localTextInputMode=active` 时，服务端返回 ASR 文字和分段，但不广播控制端、不执行声纹门控后的聊天/命令处理。
- 非 Node 子显示端不带标记，继续走原有服务端统一语音处理逻辑。
- Node 通过专用 WebSocket 消息请求当前子显示端播放“已开始输入”或“已结束输入”；服务端复用现有 TTS 生成/下发路由，不增加独立 HTTP 配置接口。
- Node 在发送提示请求前暂停录音，并在带有请求标识的本地 TTS 播放队列空闲或错误回执后恢复录音。
- 状态提示不创建 `voiceTtsPlaybackId`，不广播 `voiceTtsPlaybackState`，避免其他显示端的播放状态阻塞来源 Node 恢复录音。
- 服务端将 `textInputAnnouncement` 注册为子显示端可上行消息，只向请求来源显示端下发带请求标识的提示音。

## 异常与安全

- 输入注入失败只影响当前文本，保留后续输入模式；日志包含操作类型和错误摘要，不记录剪贴板原文。
- 获取不到前台窗口或前台窗口句柄变化时，拒绝返回/发送并提示“目标窗口已变化”，不向未知窗口发按键。
- 激活词、返回、发送仅接受去除首尾空白后的完整短文本，不匹配包含额外业务内容的句子。
- PowerShell 子进程设置超时并在结束时清理；Node 停止时终止未完成的注入任务。
- TTS 生成或下发失败时，服务端回传提示错误，Node 清除等待状态并恢复录音；不能因为提示失败永久阻塞录音。

## 兼容性

- 普通网页显示端、Android 显示端、Go/C# 子显示端和旧版 Node 子显示端不带本地输入标记时行为不变。
- 主服务器 ASR 响应保留 `status`、`text`、`segments`、`processedByServer` 等现有字段，仅按请求增加可选本地输入动作字段。
- Windows 剪贴板不支持或目标窗口拒绝粘贴时记录失败；不降级为逐字符模拟，以避免中文和特殊字符损坏。

## 验收标准

1. Windows 下在记事本、浏览器地址栏和普通文本编辑器中，快捷键激活后可注入中文完整文本。
2. 说“开始输入”可激活，且该词不会出现在目标窗口、聊天记录或控制端语音命令中。
3. 激活时听到“已开始输入”后才能继续录音；说“结束输入”听到结束提示后恢复普通录音。
4. 连续说两段文本后说“返回”，只删除第二段；再说“发送”，目标窗口收到 Enter 且输入模式结束。
5. 切换到另一个窗口后执行返回/发送，不误操作新窗口并保留状态。
6. PowerShell 失败、剪贴板占用、服务端断线时 Node 进程仍可继续运行或按现有重连规则恢复。
