# 子服务器管理 设计文档

## 需求描述

主服务器需要支持将显示端请求分发到多个子服务器，实现负载均衡和分布式部署。

## 功能需求

1. 子服务器注册与管理
   - 添加/删除子服务器
   - 子服务器配置（URL、名称、最大显示端数、优先级）
   - 配置持久化

2. 健康检查
   - 定时检查子服务器健康状态
   - 记录延迟和可用性
   - 不健康的子服务器自动排除

3. 负载均衡
   - 基于优先级和负载选择最佳子服务器
   - 支持显示端注册/注销计数

4. 消息转发
   - 通过子服务器向显示端发送消息
   - 支持所有消息类型（TTS、控制、媒体等）

```
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐    │ │
│  │  │ SubServer│ │ SubServer│ │ SubServer│    │ │
│  │  │   #1     │ │   #2     │ │   #3     │    │ │
│  │  └──────────┘ └──────────┘ └──────────┘    │ │
│  └─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
        │                │                │
        ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│  子服务器 #1  │ │  子服务器 #2  │ │  子服务器 #3  │

```

## 负载均衡策略

1. 过滤不可用服务器（disabled 或 unhealthy）
2. 按优先级降序排序
3. 按负载率（currentDisplays/maxDisplays）升序排序
4. 选择负载率最低的服务器

## API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/subservers | 获取所有子服务器列表 |
| POST | /api/subservers | 添加子服务器 |
| DELETE | /api/subservers/:id | 删除子服务器 |
| GET | /api/subservers/health | 检查所有子服务器健康状态 |

## 配置格式

```json
{
  "subServers": {
    "servers": [
      {
        "id": "sub1",
        "url": "http://192.168.1.100:3001",
        "name": "子服务器1",
        "maxDisplays": 10,
        "priority": 0,
        "enabled": true
      }
    ],
    "healthCheckPeriod": 30000
  }
}
```

## 控制端服务器列表（第一阶段）

控制端在现有 `/control` 管理页面中增加“服务器”只读页面，用于查看主服务器当前登记的全部服务器节点。第一阶段不新增服务器增删改操作，不实现自动发现、最近服务器选择、权限认证或故障转移。

页面通过 `GET /api/aasc/servers` 获取主服务器和主动 WebSocket 注册节点快照。用户可以手动刷新列表，页面展示节点身份、地址、在线状态、版本/能力元数据以及连接状态；旧 `/api/subservers` 仅保留给兼容调用。

服务器代码下发入口 `/server` 与本页面无关，后续由独立的服务器 Bootstrap/代码分发功能使用；本页面只负责观察当前服务器列表。

## 子服务器使用边界

子服务器是可选的服务型执行节点。普通媒体任务、显示控制、截图、录音、ASR、TTS、OCR 和 YOLO 等任务，优先由具备能力的显示端处理，不要求经过子服务器。

以下场景才需要使用子服务器：

- 依赖子服务器本地媒体库、NAS、数据库或持久化资源；
- 依赖 Node.js、Puppeteer、后台脚本或显示端不具备的运行环境；
- 需要在显示端离线后继续运行；
- 需要独立的资源隔离、网络出口、聚合或多显示端网关。

因此，`SubServerManager` 的负载均衡只适用于实际选择了服务型节点的任务，不应成为所有显示端任务的必经路径。

## 主动连接架构迁移

AASC 正式节点不再由主服务器通过 `SubServerManager` 主动 HTTP 连接。子服务器启动后主动连接主服务器 `wss://<主服务器>/server`，并通过长连接完成节点注册、心跳、远程请求和服务命令。

`SubServerManager` 与 `/api/subservers` 暂时保留给旧配置和兼容调用，但不再作为 `/api/aasc/servers` 的实际在线来源，也不再由主服务器对这些地址执行 AASC 健康检查。节点列表以主动 WebSocket 连接为准，节点 `url` 仅作为显示端和网页访问地址。
