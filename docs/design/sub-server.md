# 子服务器管理 设计文档

## 需求描述

主服务器需要支持将显示端请求分发到多个子服务器，实现负载均衡和分布式部署。

## 功能需求

1. 子服务器注册与管理
   - 添加/删除子服务器
   - 子服务器配置（URL、名称、最大显示端数、优先级）
   - 配置持久化

2. 健康检查
   - 定时检查子服务器健康状态
   - 记录延迟和可用性
   - 不健康的子服务器自动排除

3. 负载均衡
   - 基于优先级和负载选择最佳子服务器
   - 支持显示端注册/注销计数

4. 消息转发
   - 通过子服务器向显示端发送消息
   - 支持所有消息类型（TTS、控制、媒体等）

## 架构设计

```
┌─────────────────────────────────────────────────┐
│              主服务器 (server.js)                  │
│  ┌─────────────────────────────────────────────┐ │
│  │         SubServerManager                     │ │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐    │ │
│  │  │ SubServer│ │ SubServer│ │ SubServer│    │ │
│  │  │   #1     │ │   #2     │ │   #3     │    │ │
│  │  └──────────┘ └──────────┘ └──────────┘    │ │
│  └─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
        │                │                │
        ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│  子服务器 #1  │ │  子服务器 #2  │ │  子服务器 #3  │
│  (Node.js)   │ │  (Node.js)   │ │  (Node.js)   │
│  显示端 A,B  │ │  显示端 C,D  │ │  显示端 E    │
└──────────────┘ └──────────────┘ └──────────────┘
```

## 负载均衡策略

1. 过滤不可用服务器（disabled 或 unhealthy）
2. 按优先级降序排序
3. 按负载率（currentDisplays/maxDisplays）升序排序
4. 选择负载率最低的服务器

## API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/subservers | 获取所有子服务器列表 |
| POST | /api/subservers | 添加子服务器 |
| DELETE | /api/subservers/:id | 删除子服务器 |
| GET | /api/subservers/health | 检查所有子服务器健康状态 |

## 配置格式

```json
{
  "subServers": {
    "servers": [
      {
        "id": "sub1",
        "url": "http://192.168.1.100:3001",
        "name": "子服务器1",
        "maxDisplays": 10,
        "priority": 0,
        "enabled": true
      }
    ],
    "healthCheckPeriod": 30000
  }
}
```
