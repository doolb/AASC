# 五子棋游戏协议与本地显示

游戏在现有聊天里使用位置参数标签 `<Game:游戏名,操作者,操作[,操作参数...]>`。首版支持五子棋，标签是内部调用格式，不提供独立 MCP 服务。`操作者`表示棋子所属方；语音中的用户落子由 AI 发出 `User` 标签，显示端点击则直接由服务端执行。GM 把权威结果交给 AI，AI 自行叙述；标签不显示、不朗读。

有目标显示端的聊天都会附加游戏工具指令，覆盖标签语法、棋规、参与方、GM 回执和用户确认边界。是否调用开局指令完全由 AI 根据用户意思决定，服务端不从“五子棋”等关键词推断或代发开局。用户不需要手动输入协议说明。

服务端按显示端 ID 保存一局权威棋盘。默认 15×15，可选 9、11、13；用户黑子先行，五子及以上获胜，无禁手。坐标含 I 列，从左上角 A1 起。普通回合只下发落子增量、版本、下一手和结果。首次打开、断线或增量缺口恢复，以及改尺寸重置时才下发完整棋盘。

显示端在现有页面全屏显示棋盘，点击交点直接提交并立即等待权威确认。点击成功后 GM 增量进入当前 AI 对话，AI 知道用户下在哪里。游戏关闭显示不删除棋盘；语音窗口计时沿用现有流程。中途改变尺寸先提议，再经用户确认，清空棋盘并沿用游戏 ID。已有棋局不能通过再次开局绕过尺寸确认；进行中的同尺寸重开需要用户明确提出，省略尺寸时沿用当前尺寸。

实现中模型以游戏标签开头的回复先由服务端截留，完成校验后只向用户展示 AI 的自然语言回复。没有标签时按普通聊天流式送出，不以用户话术强制补发游戏操作；意外夹在普通回复中的游戏标签会被过滤，且不会在已输出的普通回复后执行。服务端通过现有 WebSocket JSON 外壳传送 Game 标签和增量字段；“不使用 JSON”适用于游戏调用标签及其位置参数。首次接入某聊天上下文时给 AI 一次快照，连续回合以增量推进。显示端点按产生的自然语言输入会进入现有聊天历史，GM 标签不进入用户可见历史。

源码已实现，待 Offline 服务代码包出包和 Android 现场验收。

当前显示端演示通过本机控制 WebSocket 选择在线显示端。服务端向其发送带 `demo` 标记的临时快照与黑白各一步增量，显示端沿用真实棋盘 UI，但禁用演示棋盘点按。脚本断开或显式结束时恢复当下权威棋盘；原来没有棋局则关闭演示层。真实棋局若在演示期间更新，会立即中止演示并恢复最新快照。演示不调用 AI、不发送 `chatInput`，不写聊天历史和棋局文件；控制消息只接受本机连接。
