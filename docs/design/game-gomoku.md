# 五子棋游戏协议与本地显示

## GameUser / GameAI 角色与当前游戏简写（2026-10-20）

游戏协议中的操作者统一命名为 `GameUser` 与 `GameAI`，避免与普通聊天的 `User:`、`AI:` 文本混淆。完整调用如 `Game:五子棋,GameUser,落子,A9`；当前显示端有进行中的权威棋局时，也可独立一行写 `GameUser:落子,A9` 或 `GameAI:落子,F5`，服务端从棋局快照补上游戏名。无活动棋局、终局或普通句子中的同样文本不作为简写调用。旧 `User`、`AI` 游戏操作者不再接受；尖括号外形仍可读，但其中也必须使用新角色名。

简写与完整调用共用 GM 的坐标、轮次、版本和胜负校验。GM 快照、落子、状态回执中的落子方、下一手和胜方也使用 `GameUser`、`GameAI`、`GameUser胜`、`GameAI胜`。模型在同一回复预写用户和 AI 两步时，仍只先执行用户一步并等待 GM。棋盘持久化与显示端 WebSocket 的 `actor`、`turn`、`result` 保留内部 `User`/`AI` 值，现有棋盘 UI 无需迁移。协议提示的 `kind`、摘要和完整调用行显示新名称；聊天正文与朗读会剥离合法简写行。

## 独立聊天游戏调用入口（2026-10-20）

提供可 `require()` 的 `createGameChatSession`，由调用方传入隔离棋局文件、显示端 ID 和异步目标 AI 回调，或传入现有聊天服务及选定角色。入口复用正式聊天使用的 `runGameAwareChat` 与五子棋权威服务，按发生顺序回传模型请求、AI/GM 协议、棋盘更新和最终聊天；目标 AI 可依据每次实际 GM 回执继续作答。真实聊天模式根据角色名读取现有模板并按 private 会话传入 `chatStream`，由原聊天服务生成 `System:` 和历史，不由演练入口手工拼接。每轮用户原话和 GM 校验后的最终助手正文通过原聊天服务保存在同一私聊会话；GM 行作为协议元数据，不混入普通历史。`NowGame` 变化可重建上游 Responses 会话，下一轮仍能读取本地历史。交互式 `npm run demo:game-chat` 以 JSON 行收发模拟模式内容，默认棋局写在临时目录，显式指定 `--state-file` 才跨进程保留。游戏桥在模型整次回复完成并经 GM 校验后才输出叙述。两种模式都不连接真实显示端；真实 chat 模式会连接模型并写入其配置的私聊历史。子代理演练已依次完成目录、规则、9 路开局、User C3、AI E5，权威快照版本为 3 且轮到 User，最终聊天只包含自然语言。

随后以 `192.168.1.39` 的 Chat2API qwenchat 模型接入同一入口：手工构造 `System:` 的首试只作为非正式诊断，曾出现错误调用和 HTTP 403 `RGV587_ERROR::SM`。改用现有 `llm-service.chatStream` 和“小爱”角色的 private 会话后，旧提示下模型曾输出 `Game:五子棋,AI,列表`、叙述后才放协议行，故 9 路棋盘未开局；另一轮空回复触发了“游戏操作已处理”的误导性兜底。替换为目录与规则独立示例、依赖 GM 时等待回执、每次附自然语言的新提示后，隔离会话的真实 Qwen 已按目录→规则→开局建立 9 路棋盘，另一次完整回合中 User C3 和 AI H8 均获 GM 确认，棋盘版本 3，但最终文字误称“报错好几次”。进一步修复中间独立行与历史保存、避免角色设定重复后，再次隔离复测得到目录→规则→9 路开局、User C3→AI E5，棋盘版本 3，四条私聊历史按用户/助手顺序保存，最终叙述与权威回执一致。旧提示下空回复的误导性兜底及真实显示端体验仍待验收。

同一真实 Qwen 路径还完成两盘独立终局：用户胜盘在 9 路棋盘以 C5–G5 连五，权威版本 10；AI 胜盘以 E5–E9 连五，权威版本 11。AI 胜盘终局后的模型文字仍误称轮到用户，显示终局聊天叙述需要与权威胜负状态再次核对；棋盘胜负本身由 GM 正确判定。

终局落子获得 GM 确认后，聊天桥始终把该次落子回执与另取的权威 `GM,状态` 一起交回模型，再等一条终局答复。User 胜、AI 胜和平局使用同一路径。落子那条回复已经写出的自然语言按用户要求保留，终局答复接在其后，二者一起进入聊天历史、显示和朗读；GM 行仍只作协议提示。即使原叙述提前说错回合，也不由桥接层改写或丢弃。普通非终局落子仍按既有快速结束规则处理。

终局已无“下一手”，所以终局 GM 落子行只写游戏短编号、版本、落子方和坐标，胜负由紧随其后的 GM 状态行提供。例如 `Game:五子棋,GM,落子,344a,10,GameUser,E2` 与 `Game:五子棋,GM,状态,344a,10,9,GameUser胜`。进行中的 GM 落子与状态仍带下一手及“进行中”。内部棋局和显示端增量保持原有 turn/result 字段，避免改变棋盘同步；灰色状态摘要显示最终结果。

## 无尖括号协议行（2026-10-20）

游戏调用首选独立纯文本行 `Game:游戏名,操作者,操作[,操作参数...]`，例如 `Game:五子棋,GameAI,落子,G3`。AI 提示、目录、规则、落子等新调用与 GM 回执统一使用此格式；字段仍以英文逗号分隔。提示要求模型从回复开头给出调用，但解析器也接受叙述中间的独立 `Game:` 行；普通行内文字中的 `Game:` 不触发游戏操作。尖括号 `<Game:...>` 外形仍可解析，包括正文中出现的单条调用，但其中的操作者也须是新角色名；这些调用都经同一权威棋局校验，并从用户正文和朗读中剥离。新调用及其回执保存在 `gameTrace`，旧历史提示仍可在界面查看。

游戏在现有聊天里使用位置参数协议行 `Game:游戏名,操作者,操作[,操作参数...]`。首版支持五子棋，协议行是内部调用格式，不提供独立 MCP 服务。`操作者`表示棋子所属方；语音中的用户落子由 AI 发出 `GameUser` 协议行，显示端点击则直接由服务端执行。GM 把权威结果交给 AI，AI 自行叙述；协议行不显示、不朗读。raw 聊天组装检测角色设定是否已作为 `System:` 的完整末尾块，避免再次生成相同的普通聊天 `User:` 设定。

显示端通过现有能力消息声明可显示的游戏名；当前五子棋显示端声明“五子棋”，旧端未声明时目录为空。带目标显示端的聊天在现有 `raw` 用户消息的 `System:` 标记后，先放简短的协议行格式与调用依赖规则，再逐行放目录、按需规则查询示例，最后接当前游戏提示和原角色设定；不另发 `system` 角色消息。AI 首次需要游戏时单独查询 `Game:目录,GameAI,列表`，等 GM 返回支持列表，再用 `Game:五子棋,GameAI,规则` 按需读取操作和棋规；已有规则的上下文可直接操作。协议行必须以英文逗号分隔，回复开头最多八条，每条独占一行；某条调用需要 GM 确认或查询数据时，本次回复不再输出其他调用行，等回执后再决定下一步；每次回复另起行附自然语言。用户语音报坐标由 AI 代发 `GameUser` 协议行，只有 GM 确认后才能说落子完成；模型应等这条 GM 回执再选择 AI 棋步。是否查询和开局完全由 AI 根据用户意思决定，服务端不从“五子棋”等关键词推断或代发开局。普通聊天不重复携带完整五子棋规则。桥接层继续兼容尖括号外形和最多八条调用的解析，但不再接受旧游戏角色名。

用户在 A9 落子而希望 AI 继续 E7 时，真实模型曾在同一回复预写两条落子调用，又在只收到 User A9 的 GM 回执后宣称 E7 也成功。游戏桥已有“User 与 AI 同批预写只执行 User，等 GM 后重新决定 AI 棋步”的权威保护；本次按用户给出的完整 `System:` 原文补入“需要状态确认的 User/AI 游戏操作是原子操作，等待该调用行回复，不能再发其他调用行”，以减少模型抢跑。提示仍写回复开头最多八条，解析器仍支持八条，避免改变已有多调用兼容行为。模型自然语言是否守约仍须真实模型验收。

隔离 Qwen 在同一句 A9 输入中遵守了 User→GM→AI 的顺序，却把已有白棋的 E5 当成候选落点，被 GM 判为“位置已占用”。五子棋专属规则现在解释 GM 快照各字段和棋盘编码：末尾按 `/` 从上到下分行，每行从左到右对应列，`.` 空位、`X` 用户黑棋、`O` AI 白棋。规则还要求落子前按行列查看目标是否为 `.`；该说明同时用于按需规则查询和正在进行的 `NowGame` 提示。GM 仍负责最终校验，不能依赖模型自行解析保证棋步有效。

加入规则后，用相同棋盘和同句 A9 原话在隔离 Qwen 复测：模型先让 GM 确认 User A9，再选空格 F5 作为 AI 落点，GM 接受，最终叙述与棋局一致。这是单次样本，真实显示端仍需现场观察。

AASC 每轮聊天还会在上述目录提示后写入一行 `NowGame:五子棋` 或 `NowGame:无`，来源是目标显示端的服务端权威棋局：只有结果仍为“进行中”才算当前游戏，手动隐藏棋盘不改变此状态。该行与游戏规则共处于现有 `raw` 的 `System:` 正文，进入新一轮时重新计算；同一轮中目录、规则及开局的 GM 回执继续通过游戏桥接层发给模型。直接调用 Chat2API 的网页会话没有目标显示端与游戏桥接层，不会自动执行 Game 协议行或产生 GM 回执。2026-10-20 09:56 保存的 Chat2API 独立会话曾输出旧格式 `<Game:目录,AI,列表>`；它现在可在 AASC 游戏桥接层按旧规则解析，独立 Chat2API 会话本身仍不具备游戏桥接能力。

游戏协议面向统一的 AI 命令交互：玩家的语音先进入聊天，AI 依据通用协议行语法发 `User` 或 `AI` 命令，服务端只执行、校验并返回 GM 结果。查询游戏规则时，GM 只提供所查询游戏的专属操作和玩法，不重复常驻 `System:` 中的协议行通则。权威五子棋开局后，下一轮 `NowGame:五子棋` 下附同一份精简五子棋规则；查询规则本身不改变 `NowGame`。没有进行中的游戏时不携带游戏专属规则，避免以后游戏种类增加时每轮常驻所有规则。开局导致 Responses 上游新建会话可以接受，AASC 会话和本地历史继续保留。

模型可能把两条合法协议行隔着自然语言输出。桥接层现在按出现顺序解析，不因中间有叙述而报“协议行格式无效”；它逐条交 GM 验证，并在全部成功后保留叙述。若同一回复包含 User 落子和预写的 AI 落子，只执行到 User 落子，丢弃后续预写协议行及该回复的叙述，把 GM 增量交回模型重新选择 AI 棋步。真实无效坐标、错误轮次等由 GM 返回具体错误并停止后续协议行。此前隔离 Responses 复测中的交错协议行曾被旧格式门槛整批拒绝，随后豆包触发安全验证；新规则的真实账号验证仍待进行。

若权威回合已轮到 AI，但模型仅用自然语言声称已落子，桥接层不暂存这些未经 GM 确认的句子；有限续问后仍无合法落子协议行时，聊天和 TTS 只收到“AI 落子尚未得到 GM 确认”的提示，真实棋盘保持 AI 回合。

2026-10-20 使用真实豆包模型、临时显示端 ID 和临时棋局文件模拟开局及一轮落子：下一轮提示由 `NowGame:无` 变为 `NowGame:五子棋`，用户 H3 经 GM 确认后模型落 H4，棋盘版本为 3。模拟器以单条 raw 用户文本重放本地临时对话，没有接入 AASC WebSocket 或真实显示端。开局阶段模型曾跳过目录、误用“列表”及伪造 GM 协议行；桥接层拒绝非法协议行并回送错误，模型随后成功开局。真实 AASC 会话仍需验收模型遵守目录顺序及播报只陈述已确认结果。

开局时若模型在协议行后已给出自然语言，服务端成功建立棋局后直接完成该轮；GM 开局快照发显示端并记入灰色协议提示，不再为这条快照额外调用模型。已有棋局首次进入新的模型上下文时仍会补一份权威快照。普通落子若轮到 AI，GM 增量会作为下一次模型输入，AI 落子后再合并本轮叙述。

服务端按显示端 ID 保存一局权威棋盘。默认 15×15，可选 9、11、13；用户黑子先行，五子及以上获胜，无禁手。坐标含 I 列，从左上角 A1 起。普通回合只下发落子增量、版本、下一手和结果。首次打开、断线或增量缺口恢复，以及改尺寸重置时才下发完整棋盘。

已创建棋局的显示状态也随棋局保存。显示端连接时自动收到权威快照；页面初始化还会主动补拉。真实棋盘同时遵从当前 AI 对话状态：仅在 `activeGroup` 或 `activePrivate` 中按已保存的 `visible` 值显示；退出对话、超时、等待唤醒或监听关闭时隐藏棋盘和恢复入口，不删除棋局。再次进入活动对话时恢复原棋盘，手动“关闭”写入的 `visible=false` 仍有效。演示画面可在未进入对话时独立显示，结束后恢复真实棋局并重新应用对话状态。

显示端在现有页面全屏显示棋盘，点击交点直接提交并立即等待权威确认。点击成功后 GM 增量进入当前 AI 对话，AI 知道用户下在哪里。游戏关闭显示不删除棋盘；语音窗口计时沿用现有流程。中途改变尺寸先提议，再经用户确认，清空棋盘并沿用游戏 ID。已有棋局不能通过再次开局绕过尺寸确认；进行中的同尺寸重开需要用户明确提出，省略尺寸时沿用当前尺寸。

用户、AI 和演示的每次权威落子增量只让新棋子播放短暂落下回弹；完整快照直接静态展示已有棋子，避免重连或恢复时整盘重播。系统请求减少动态效果时静态显示。

实现中有目标显示端的模型回复先由服务端完整缓冲，随后识别回复中任意位置的独立游戏协议行；完成校验后只向用户展示 AI 的安全自然语言。多协议行允许夹叙述；服务端逐条按当前版本执行并逐条记录 GM，任一条失败则停止后续协议行，将已成功的回执与失败回执交还模型，丢弃本批次预写叙述，已成功的棋步保留。全部成功且还需续接时也把本批每条 GM 回执一并交回模型。有目标显示端的普通聊天同样等本次模型输出完成后显示，减少误播未经 GM 确认的叙述；无目标显示端时保持原聊天流式路径。已有活动棋局的首答若漏发协议行，只向同一模型续问一次，让它依据用户原话判断是否需要调用，服务端不识别游戏关键词或代发操作。续问仍无协议行时保留首答和原棋盘。服务端通过现有 WebSocket JSON 外壳传送 Game 协议行和增量字段；“不使用 JSON”适用于游戏调用协议行及其位置参数。首次接入某聊天上下文时给 AI 一次快照，连续回合以增量推进。显示端点按产生的自然语言输入会进入现有聊天历史，GM 协议行不进入用户可见历史。

成功执行的协议行后若有自然语言，桥接层会保留到最终回复；若还轮到 AI，则继续收集下一步叙述。失败操作后的预先宣称不展示。普通操作已轮到用户且已有完整叙述时直接完成；终局落子则额外回送 GM 落子与状态，保留原叙述并追加模型依据终局状态给出的答复。后续必要的模型续接只发送简短 GM 回执，不附加长篇“根据权威结果继续”提示。GM 回执使用四位游戏短编号，服务端状态和显示端版本匹配仍使用完整唯一 ID。

实际游戏的每条调用和对应 GM 回执作为独立 `gameTrace` 元数据保存，在控制端和显示端聊天中逐条以灰色小字摘要显示；悬停可看原始协议行。普通单轮最多七次模型回复，终局状态确认最多再加一次；每次至多八条协议行，控制端历史和界面保留前 128 条协议提示，足以覆盖本轮上限。它们不进入助手正文、后续模型上下文或 TTS。临时演示不写这些提示。棋盘外层背景透明，木色棋盘保持原样。

标题栏借鉴 TTS 字幕的半透明深色渐变和背景模糊，覆盖标题、回合状态与关闭按钮，并保持白字阴影；棋盘和其他透明区域不加遮罩。即使设备不支持模糊，渐变仍提供可读背景。

显示端左下角把“游戏”入口放在“聊天”入口正上方，点击后向上展开当前显示端支持的游戏列表。列表与显示端上报的游戏能力使用同一数据源，首版仅有五子棋。活动 AI 对话中存在进行中的权威棋局时，入口显示“五子棋”；退出对话、棋局结束或仅有演示时显示“游戏”。原来固定左下角的五子棋重开按钮移除，避免挡住聊天。列表可恢复当前对话中手动隐藏的棋盘；尚未开局时提示通过聊天让 AI 开局，点击列表不会绕过 AI 发起游戏。打开聊天或退出对话时收起列表。

源码已实现，待 Offline 服务代码包出包和 Android 现场验收。

当前显示端演示通过本机控制 WebSocket 选择在线显示端。服务端向其发送带 `demo` 标记的临时快照与逐步落子增量，默认连续演示用户胜、AI 胜各一局；每步延迟、首局结果停留时长和单独胜方均可配置。两局使用不同临时游戏 ID，胜局完成后保留结果画面；显示端沿用真实棋盘 UI，但禁用演示棋盘点按。脚本断开或显式结束时恢复当下权威棋盘；原来没有棋局则关闭演示层。真实棋局若在演示期间更新，会立即中止演示并恢复最新快照。演示不调用 AI、不发送 `chatInput`，不写聊天历史和棋局文件；控制消息只接受本机连接。

显示端棋盘交点保持透明网格；全局浅色主题的通用按钮渐变色不作用于交点，棋盘维持木色。Note8 的横屏显示已通过临时演示截图核对。
