# 五子棋游戏协议与本地显示

游戏在现有聊天里使用位置参数标签 `<Game:游戏名,操作者,操作[,操作参数...]>`。首版支持五子棋，标签是内部调用格式，不提供独立 MCP 服务。`操作者`表示棋子所属方；语音中的用户落子由 AI 发出 `User` 标签，显示端点击则直接由服务端执行。GM 把权威结果交给 AI，AI 自行叙述；标签不显示、不朗读。

游戏相关对话会自动附加专用系统指令，覆盖标签语法、棋规、参与方、GM 回执和用户确认边界。用户不需要手动输入协议说明。

服务端按显示端 ID 保存一局权威棋盘。默认 15×15，可选 9、11、13；用户黑子先行，五子及以上获胜，无禁手。坐标含 I 列，从左上角 A1 起。普通回合只下发落子增量、版本、下一手和结果。首次打开、断线或增量缺口恢复，以及改尺寸重置时才下发完整棋盘。

显示端在现有页面全屏显示棋盘，点击交点直接提交并立即等待权威确认。点击成功后 GM 增量进入当前 AI 对话，AI 知道用户下在哪里。游戏关闭显示不删除棋盘；语音窗口计时沿用现有流程。中途改变尺寸先提议，再经用户确认，清空棋盘并沿用游戏 ID。

实现中模型发出的标签会先由服务端截留，完成校验后只向用户展示 AI 的自然语言回复。服务端通过现有 WebSocket JSON 外壳传送 Game 标签和增量字段；“不使用 JSON”适用于游戏调用标签及其位置参数。首次接入某聊天上下文时给 AI 一次快照，连续回合以增量推进。显示端点按产生的自然语言输入会进入现有聊天历史，GM 标签不进入用户可见历史。

源码已实现，待 Offline 服务代码包出包和 Android 现场验收。
