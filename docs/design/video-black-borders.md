# 视频黑边检测与有效画面填充

## 需求与范围（2026-10-24，源码完成，待部署）

网页、Android WebView 和 Node/mpv 显示端检测视频文件内部的黑边。有效矩形参与适应、铺满、高度、宽度和动态填充；适应模式仍完整展示有效画面，屏幕与内容比例不同产生的留白不视为文件黑边。手动裁剪按原视频坐标与有效矩形求交，不覆盖保存的参数。

控制端画面填充区域增加“自动去黑边”，默认开启。复用按显示端保存的 control 消息、服务端权威状态广播与 restoreState；旧配置缺字段默认 true。检测矩形只属于当前视频，不持久化、不修改文件。

## 检测和生命周期

每秒最多一次低分辨率取样，四边向内检查近黑连续行列；内部亮像素不足、全黑、过暗、有效区域过小时忽略。连续四个不同播放位置的有效样本稳定后才应用，保留边界余量。无黑边样本同样参与确认，以恢复完整画面。暂停/睡眠不持续采样；换源、清空、退出立即清理，异步结果按代次丢弃。

网页以 canvas 小图读取 video。跨域源先尝试匿名 CORS，不支持时先重试相同直连 URL 普通播放，再沿用原代理备用逻辑；无法读像素时保留播放。Node 用专用 mpv Lua 桥获取 screenshot-raw video，将缩小的亮度样本经现有 JSON IPC 交给共享 JS 检测器，不新开进程或网络服务。Lua 不可用/取样失败仅停当前检测。

Node 通过原生缩放/平移适配有效矩形；动态模式在有效画面的适应/铺满之间变化。取样排除 ASS、字幕和屏幕留白。

重新开启当前跨域视频检测时，重试同一直接来源并恢复播放位置/暂停状态。服务端以独立配置处理器校验布尔值、严格持久化后下发，并广播 `autoBlackBordersConfig`；保存失败回传旧权威值。Node 独立包显式包含共享 JS，Lua 桥随应用源码打包。

## 验收与发布

共享检测器覆盖各方向黑边、无边、全黑/暗场、稳定切换与代次隔离；浏览器真实视频覆盖填充/旋转、切源、CORS 直连降级；Node 覆盖 IPC 样本、几何、动态和清理，并以隔离真实 mpv 核查截图方向。仅 servicePackage、voiceDisplayNodePackage 待构建。

已完成真实浏览器画布留白像素检查、mpv Lua→IPC→JS取样和旋转/暂停验证。Android设备、Windows mpv及高分辨率设备帧耗时仍待部署验收。JS检测器192×108运行1000次平均约0.398ms；该数字不含浏览器/原生完整视频帧读回及Lua缩小开销。
