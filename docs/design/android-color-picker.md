# Android 颜色选择器设计

## 需求

Android 控制端和显示端的所有颜色入口使用参照现有 PC 浏览器的选色界面，包括色域、色相条、当前颜色和 HEX 输入。PC 浏览器继续使用当前原生颜色选择器。范围为显示端背景光晕、MMD 灯光七处颜色入口，以及控制端背景光晕入口。

## 设计

Android 页面加载后统一增强现有 `input[type=color]`。保留原控件的 ID、值和业务监听器，只把原生触发器替换为色块按钮；一份共享弹层负责 HSV 色域、色相和 HEX 输入。颜色变化仍派发 `input` 用于即时预览；确认派发 `change` 用于保存；取消恢复原色并派发 `input`。外部权威配置依旧写入原控件，重新打开时读取最新值。

选色面板覆盖页面其他设置层，在小屏和横屏均保持可见，支持触摸、鼠标、键盘、Escape、取消和确认。按钮显示当前颜色，HEX 输入拒绝非法值。组件只改变前端交互，背景光晕与 MMD 配置协议和默认值不变；随服务网页代码包热更新，无需重新构建 APK。

Android WebView 的原生 `range` 轨道可能盖住输入元素的背景，因此色相彩虹渐变同时绘制在 `::-webkit-slider-runnable-track` 上。输入元素背景仍作为不支持该伪元素时的回退。

## 验收

1. PC 的所有颜色输入仍为原生控件，原交互不变。
2. Android 显示端八处、控制端一处颜色入口均显示统一选色面板。
3. 色域拖动和色相调整即时预览；确认保存；取消回退且不保存。
4. HEX 合法值可输入和确认，非法值无法确认；窄屏下不遮挡操作按钮。
5. Android 色相轨道呈彩虹渐变，拖动时颜色预览连续变化。
