# 语音修复模式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在显示端通过中文语音密码进入修复模式，所有修复请求确认后交给可配置的工作 Agent，并暂停普通 TTS。

**Architecture:** 使用独立的纯状态机管理 inactive、awaitingPassword、active 和 pendingConfirmation；服务端只在显示端输入链路拦截修复会话，成功确认后复用 `AiRolesService` 的多角色工作 Agent 路径。普通 TTS 由统一下发出口抑制，修复提示和工作 Agent 回复使用显式放行标记。

**Tech Stack:** Node.js CommonJS、WebSocket、现有语音命令服务、`AiRolesService`、Node test runner。

**Spec:** `docs/spec/display-voice-conversation.md`

## Global Constraints

- 使用 `const/let`、`async/await` 和 `try-catch`。
- 密码按项目确认要求使用明文配置比较，但不得写入日志、聊天历史或 Agent 内容。
- 修复模式只接受显示端入口；工作 Agent 角色从 `config.repairMode.role` 读取并校验多角色列表。
- 普通 TTS 在修复模式期间停止发送；修复模式提示和回复允许播报。
- 完成后同步 `todo.md`、design、spec、task 和 `changelog.md`。
