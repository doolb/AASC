# 控制端任务面板重新设计

## 概述

对 upload.html 侧边栏中的「远程任务」面板进行全面 UI 重新设计，保持现有后端接口和消息协议不变，仅改造前端视图层。

## 设计原则

1. 保持 800px 面板内所有操作可完成，不依赖弹窗
2. 任务列表、新建任务、运行监控三个核心视图通过标签切换
3. 编辑、结果查看等子视图通过面包屑导航栈管理
4. 与现有 upload.html 深色主题风格一致

## 整体布局

面板分为两个层次：

**一级：标签栏（固定在面板顶部）**
- 📋 任务列表（默认）
- ➕ 新建任务
- 🔄 运行中

**二级：导航栈（覆盖当前标签内容）**
- 任务列表 > 编辑任务
- 任务列表 > 查看结果
- 运行中 > 任务详情

每个子视图顶部有面包屑返回上一级。

## 标签一：任务列表

### 分组展示

任务分为两组，每组有分组标题：

```
🛠️ 内置任务（只读）
  ┌─ 任务卡片 ─────────────────────┐
  │ 🔷 图片缩放  id: image.resize  │
  │ 执行于: 服务端 Node.js         │
  │ [运行] [查看参数]              │
  └────────────────────────────────┘
```

```
📦 用户任务
  ┌─ 任务卡片 ─────────────────────┐
  │ ⚡ my-task           运行中 🔄  │ ← 状态徽标
  │ 📄 task.js + 2 文件            │
  │ ████████████░░░░ 60%          │ ← 进度条（仅运行中）  
  │ 上次: 2026-05-14 10:30        │
  │ [详情] [编辑] [删除] [结果]    │ ← 操作按钮
  └────────────────────────────────┘
```

### 卡片设计

| 元素 | 说明 |
|------|------|
| 图标 | 运行中 🔄 / 已完成 ✅ / 失败 ❌ / 已停止 ⏹ / 排队中 ⏳ |
| 任务名 | 粗体，溢出省略 |
| 文件数 | 入口文件 + 附属文件数量 |
| 状态 | 文字 + 颜色（蓝/绿/红/橙） |
| 进度条 | 仅运行中显示，宽度 60px，渐变蓝色 |
| 时间 | 上次执行时间 |
| 运行中 | 卡片边框脉冲动画 |

### 内置任务

- 只读，无编辑/删除按钮
- 有「运行」按钮和「查看参数」按钮
- 点击运行直接提交执行（使用默认参数或弹出参数表单）

### 交互

- 顶部搜索框：按名称实时筛选
- 排序：运行中 > 最近执行 > 创建时间
- 空状态：引导创建第一个任务

### 动态表单（内置任务）

当任务类型切换到"内置功能"时：
- 隐藏入口文件、执行目标、文件上传
- 显示内置任务选择下拉和动态参数表单（根据选中任务渲染对应参数输入）
- 执行固定在服务端

### 设备选择器

- 目标选择「显示端」或「子显示端」时展开设备选择器区块
- 通过 WebSocket 请求 `device:list` 获取在线设备列表
- 每个设备项：名称、在线状态指示器（绿/灰）、支持能力标签（WebGL/WebGPU）
- 默认选中「自动选择」，由后台按能力和负载匹配

## 标签三：运行监控

### 视图结构

```

┌─ 活跃任务 ──────────────────────────┐
│                                      │
│  ┌─ my-job ────── 运行 00:03:23 ──┐ │
│  │  阶段: processing               │ │
│  │  ████████████░░░░░░ 60%        │ │
│  │  执行于: 显示端-客厅            │ │
│  │  ┌ 日志 ───────────────────┐   │ │
│  │  │ HH:MM:SS [流] 消息...   │   │ │
│  │  └─────────────────────────┘   │ │
│  │  [⏹ 停止] [📋 详情]           │ │
│  └────────────────────────────────┘ │
│                                      │
│  ┌─ data-analyze ── 排队中 ───────┐ │
│  │  📤 等待分配资源...             │ │
│  │  [取消]                         │ │
│  └────────────────────────────────┘ │
│                                      │
├──────────────────────────────────────┤
│  📋 最近完成                          │
│                                      │
│  ┌─ ✅ batch 12s  [📂 查看结果] ──┐ │
│  └────────────────────────────────┘ │
│  ┌─ ❌ render 3s   [📂 查看结果] ──┐ │
│  └────────────────────────────────┘ │
└──────────────────────────────────────┘
```

### 设计要点

| 元素 | 说明 |
|------|------|
| 活跃任务 | 置顶显示，每个独立卡片 |
| 排队中 | 显示"等待中"状态，可取消 |
| 日志窗口 | 每个运行中任务拥有独立的可折叠日志框，自动滚动 |
| 计时器 | 从启动开始实时递增显示 |
| 进度条 | 根据 task:progress 事件实时更新 |
| 最近完成 | 已完成/失败任务折叠在下部，带查看结果入口 |
| 迁移按钮 | 运行中任务卡片增加「迁移到...」操作，弹出设备选择器，执行停止→重启流程 |

### 任务迁移流程

1. 用户点击运行中任务的「迁移到...」
2. 弹出设备选择器（相同 UI 组件）
3. 确认后发送 `task:stop` → 等待停止完成
4. 发送 `task:submit`（复用原有 taskName + params，target 更新为目标设备）
5. 新实例自动出现在运行监控中，旧实例标记为 stopped
6. 迁移过程在日志中标注「系统: 任务已迁移到 显示端-客厅」

### 文件替换

- 每个现有文件右侧有「替换」按钮，点击弹出文件选择器
- 拖拽新文件自动添加到文件列表
- 文件左侧有删除图标，点击后标记为待删除（延迟到保存时执行）
- 保存时发送更新请求到服务端（需要新增或复用 API）

### 删除任务

- 点击「删除任务」弹出确认对话框
- 确认后发送删除请求，删除任务目录及所有执行结果
- 删除成功后返回任务列表

| 操作 | 行为 |
|------|------|

| 预览图片 | 在面板内显示缩略图/大图 |

### 空状态

- 没有执行历史时显示：「暂无执行记录，提交任务后将在此显示结果」
- 运行中的任务在结果视图显示当前进度而不是结果

## 消息协议扩展

当前协议基础上需要新增/复用的消息：

### 新增：任务列表查询

```javascript
// 请求
{ type: "task:list", payload: { filter: "user" } }  // "all" | "user" | "builtin"

// 响应
{
  type: "task:list:result",
  payload: {
    tasks: [
      {
        taskName: "my-task",
        taskType: "user",
        builtinId: null,
        entryFile: "task.js",
        files: [{ name: "task.js", size: 1234 }, ...],
        refs: {},
        target: "server",
        env: "auto",
        mode: "one-shot",
        instances: [
          { instanceId: "a1b2c3", status: "running", stage: "processing",
            progress: 60, timestamp: 1712345678000, target: "display-客厅" },
          { instanceId: "d4e5f6", status: "completed", success: true, timestamp: 1712345670000 }
        ],
        lastResult: { success: true, timestamp: 1712345678000 }
      }
    ]
  }
}
```

### 新增：任务删除

```javascript
{ type: "task:delete", payload: { taskName: "my-task" } }
// 响应
{ type: "task:deleted", payload: { taskName: "my-task", success: true } }
```

### 新增：任务更新

```javascript
{
  type: "task:update",
  payload: {
    taskName: "my-task",
    entryFile: "task.js",
    target: "display",
    displayId: "客厅-device",
    env: "webgl",
    mode: "one-shot",
    params: { width: 800 },
    files: [
      { name: "task.js", data: "<base64>", action: "replace" },
      { name: "data.json", action: "delete" }
    ]
  }
}
```

### 复用：设备列表

```javascript
// 已有消息用于填充设备选择器
{ type: "device:list" }
```

## 组件复用

使用现有前端基础设施：
- WebSocketManager 用于实时消息
- 现有 task-panel.js 中的实例管理逻辑可复用
- 现有深色主题 CSS 变量

## 待办：服务端接口

以下接口需要服务端新增支持：

1. `task:list` / `task:list:result` — 获取任务列表及其实例概要
2. `task:update` — 更新任务配置和文件
3. `task:delete` / `task:deleted` — 删除任务及其结果
4. `device:list` — 获取在线设备列表（已有或需新增）
