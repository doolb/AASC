# 豆包Chat音色与显示端回复播放

本轮保存修复、控制端入口及语速滑条已在ADB设备的本地服务候选v100验证；其它运行实例需加载包含本次修复的服务包。无需重建min APK，本轮尚未正式发布LAN/WAN。

控制端右下角工具组点击「音色」浮钮，或在显示端点击灯光按钮上方的「音色」，先选择TTS方式，再选择该方式的音色。豆包网页朗读提供官网当时实际显示的94项音色，女声32项、男声62项，角色与口音已合并，可搜索名称、标签或style_id。目录来源及获取步骤见[官网音色获取](../ref/doubao-web-voice-fetch.md)。

面板中的「性别、年龄、口音」是三个并排下拉框，可组合筛选并与搜索同时使用；每项显示符合其它条件的数量。「未标注」表示该方式目录没有对应属性。点击「清除筛选」恢复完整列表，不改变已选音色。

顶部显示当前已保存的音色；列表中对应项采用激活按钮样式（主题强调渐变、白字、边框和✓），其余采用普通按钮样式（中性背景、普通文字和边框），不显示勾选。保存中或失败时保留原音色，收到服务器成功回显后才更新。每次打开面板都会清空搜索/筛选，自动将列表滚动到当前音色；也可点击顶部当前音色再次定位。没有对应目录项时显示原ID，系统原生沿用默认音色。

每个音色右侧的「试听」会在当前操作的控制端或显示端朗读一条随机短句，不改变已选音色。首次试听需要在线合成并下载 WAV；同一音色再次点击「重播」时直接播放该页面内存中的 WAV。每个面板最多缓存 30 份，超过后淘汰最久未使用的音频；关闭再打开面板仍可重播，刷新页面后缓存清空。模型、语速或总音量变化后会重新合成。合成或播放失败时面板下方显示原因，可再次点击重试。

横屏或键盘使可用高度较小时，列表保留操作空间，面板内部可滚动；自动定位仍确保当前音色可见，不滚动整个显示页面。

较宽的横屏中，面板展开为两列：左侧当前音色、TTS方式、搜索和三个筛选下拉，右侧音色列表；竖屏和较窄屏幕保持单列。左右区域可分别滚动。

选择修改的是「声纹 → 语音服务与音色」中同一份全局AI/Agent默认配置，控制端和显示端同步。每种方式记住自己的音色：例如豆包选桂乡甜妞，切到Qwen选择其它音色，再切回豆包会恢复桂乡甜妞。模板显式设置仍优先；继承默认的模板跟随快选。正在生成或播放的分句批次沿用开始时配置，新选择作用于下一批。

点击已完成AI/Agent回复或历史消息上的🔊可重播，优先使用回复的speech，否则正文，不朗读思考。点击⏹停止；原输入和模板上下文用于选择相应TTS，播放目标为当前显示端。失败时检查声纹页服务是否启用，以及Chat2API对应账号是否可用。各TTS方式默认可用；选择音色不会添加或启用Chat2API账号。

其它方式沿用其已有音色目录；千问网页当前只有已知单项，系统原生沿用原生音色。静态目录可读不代表账号可合成，94项逐一真实听感和Android实机播放仍待验收。

开发调用可使用只读接口`GET /v1/audio/voices?model=doubao-chat`，携带代理现有Bearer或X-API-Key。返回`{object:"list",model:"doubao-chat",data:[...]}`，每项包含`id`、`style_id`、`name`、`gender`、`tags`。生成时将`style_id`作为`POST /v1/audio/speech`的`voice`。独立JSON位于`src/apps/server/modules/chat2api/doubao-chat-voices.json`，只含female/male分组和name/style_id/tags。显示端使用主服务WebSocket查询目录及保存选择。


## 快捷语速

面板显示当前方式的「语速」滑条，范围-10～10，0为正常。拖动时预览数值，松手后保存，另一端和声纹设置页同步显示服务器确认值。各方式分别记忆语速，新值对下一次语音批次生效，当前正在播放的批次保持原设置。

仅上游原生支持语速的方式显示滑条；豆包网页朗读及不支持rate的Qwen3模型隐藏。Qwen-Audio、国内千问网页、豆包API和系统原生按各自能力使用已有语速参数，不增加本地音频变速。保存失败时显示原因并恢复服务器原值。

控制端面板从工具组左侧展开，音色浮钮位于录音暂停、自测和齿轮上方；点击关闭、面板外部或Escape可收起。面板选择仍是全局AI/Agent默认，角色显式语音设置优先。

### 豆包Chat表情处理（2026-10-15源码已修复，待服务包发布）

AASC通过豆包Chat朗读时，会在最终合成前过滤emoji；正文中的文字、数字和标点保留，只有表情或装饰标点的分句直接跳过并继续后面的正文。原聊天内容及已识别的显示端表情/动作不改。自动AI/Agent播报与点击回复喇叭的手动重播均经过该Provider过滤。

例如“喵呜～主人好呀！✨”正常朗读文字，独立的✨不再发送上游；句尾🐱💻⚡同样不生成无正文音频。账号、网络或上游合成本身发生的真实失败仍会报告，不自动改用其他服务。此说明针对AASC的doubao-chat Provider，直接调用Chat2API语音接口沿用原输入契约。

### 长句多个Ogg流接收（2026-10-15源码已验证，待本轮服务包发布）

豆包同一长句返回多个完整Ogg流时，接收层会逐流严格校验、解码并合并为一个WAV；无需把长句手动拆短。纯表情过滤继续生效。用户示例整段的8段正文已通过真实账号合成，末句“喵～”成功，尚不代表在当前设备实际播放完毕。

## 上游生成并发（2026-10-16，源码完成待服务更新）

控制端语音设置的豆包网页区域新增每账号上游生成并发，默认3，可设1～8；聊天和同资料目录代理共用额度，分句按原序播放。保存与服务器回显见[语音配置](tts-providers.md)。当前尚未出包发布，真实官网三路与设备听感仍待验收。
