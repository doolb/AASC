# 五子棋

在当前显示端的对话中说“我们来玩五子棋”，AI 会根据你的意思调用开局指令，显示端出现全屏棋盘。服务端只在收到 AI 的指令后创建棋局。默认 15×15；也可说“用 9、11 或 13 路棋盘开始”。用户执黑先行，五子及以上获胜。

AI 会按需查询当前显示端的游戏目录和五子棋规则。控制端与显示端聊天中的灰色小字会显示查询、落子和 GM 确认的简短提示；控制端临时角色会话完成后也会保留这些提示，完整协议可悬停查看，游戏编号显示四位。提示不会朗读。棋盘外层透明，木色棋盘保留。

私聊里让 AI 查看棋局时，显示端会显示当前权威棋盘；如果此前手动隐藏，查看、落子等棋盘操作会恢复显示。只有“退出显示”操作会主动隐藏棋盘；退出对话后仍按对话状态暂时隐藏，再次进入活动对话时恢复。

当前游戏调用使用独立的纯文本行，例如 `Game:五子棋,GameAI,落子,G3`，不带尖括号。服务端仍兼容活动棋局中独立一行的旧简写 `GameUser:落子,A9` 或 `GameAI:落子,F5`，但模型提示只引导完整 `Game:` 行。独立调用行可出现在自然语言之间，普通句子中的示例不会触发操作。旧的 `<Game:...>` 外形仍可识别，但角色必须使用 `GameUser` 或 `GameAI`；旧 `User`/`AI` 游戏角色不再接受。普通聊天不需要输入协议行。

模型首次需要游戏时先发 `Game:目录,GameAI,列表`，收到 GM 的列表后才按需发 `Game:五子棋,GameAI,规则`。需要 GM 确认或数据的调用会等回执后再决定下一条；每次回复另起行附自然语言，确认前不会宣称操作成功。

需要状态确认的 User 或 AI 游戏操作按原子步骤处理：用户报坐标后先等 GM 确认该棋步；若结果仍在进行且轮到 AI，AI 再决定自己的落点。模型若在同条回复抢先写出双方落子，服务端只执行 User 棋步，并把 GM 回执交回模型重新决定 AI 棋步。

GM 快照末尾是棋盘编码，`/` 把棋盘从上到下分成各行，每行从左到右对应 A、B、C 等列，第一行是数字 1；`.` 为空位，`X` 为用户黑棋，`O` 为 AI 白棋（字母 O）。例如第 5 行的 `....O....` 表示 E5 已被 AI 占用。AI 会收到这段规则，仍以 GM 的落子校验为准。

胜负或平局落子确认后，系统会把 GM 的落子回执和最终状态再交给 AI，等它补充一条终局答复。落子回复中原有的话会保留并排在补充答复前；灰色 GM 提示不会朗读。

终局的落子回执到坐标结束，例如 `Game:五子棋,GM,落子,344a,10,GameUser,E2`；下一行状态给出最终胜负，例如 `Game:五子棋,GM,状态,344a,10,9,GameUser胜`。终局已没有下一手；进行中的回执仍会写明 `GameUser` 或 `GameAI` 下一手。显示端棋盘内部数据继续使用原有 `User`/`AI` 值。

说“下在 H8”或“我下 A一”，AI 会代用户调用游戏协议。也可以直接点击棋盘交点：棋盘确认后，AI 会收到这步并选择白子的下一手。坐标从左上角 A1 开始，列字母包含 I。

每次落子经服务端确认后，新棋子会短暂落下回弹；重连恢复已有棋盘时不重播。设备启用“减少动态效果”后，棋子直接显示。

真实棋盘只在当前显示端 AI 对话活动期间展示；退出对话、超时或关闭监听后自动隐藏，重新进入对话时恢复原棋局。左下角“游戏”按钮位于“聊天”按钮上方，点击可查看当前显示端支持的游戏；有正在进行的五子棋对局时按钮显示“五子棋”。点击棋盘上的“关闭”会在活动对话中继续隐藏棋盘，不删除棋局；打开游戏列表并点击“五子棋”可恢复。没有棋局时，列表会提示在聊天中请 AI 开局，不会自行发起游戏。断线重连后按当前对话状态恢复。中途调整棋盘尺寸时，AI 先提出新尺寸，用户明确确认后清盘并沿用原棋局 ID。

当前是项目内的位置参数游戏协议，不是独立的标准 MCP 服务。服务代码包待构建，Android 真机体验待验收。

在当前在线显示端看连续演示：先确认显示端已加载包含五子棋 UI 的新版服务代码，再在服务端机器运行 `npm run demo:gomoku-ui`。只有一个在线主显示端时自动选择；多个显示端时运行 `npm run demo:gomoku-ui -- --display-id=显示端ID`。默认 15 路，逐步间隔 900 毫秒，用户胜后停留 2 秒，再开始 AI 胜的一局；最终棋盘保留到按 Ctrl+C，退出时恢复原棋盘。可加 `--size=9`、`--delay-ms=350`、`--result-pause-ms=1200`、`--winner=user` 或 `--winner=ai`；自动退出可加 `--duration=12000`。脚本按本机证书自动选择 `ws` 或 `wss`，默认端口 8081；端口不同可设置 `AASC_GOMOKU_SERVER_URL`。演示不发送测试聊天消息，不调用 AI，也不修改实际棋局。

## 独立 JS 演练入口

运行 `npm run demo:game-chat` 后，命令行按一行一个 JSON 对象交互。先输入 `{"type":"user","content":"我们来玩五子棋，开一盘 9 路的"}`；每收到 `modelRequest`，把其中 `input` 和 `systemPrompt` 交给目标 AI，再输入 `{"type":"modelReply","sequence":1,"message":"Game:目录,GameAI,列表"}`，其中 `sequence` 必须对应当前请求。入口会逐次输出 `gameProtocol`、`gameUpdate`、`chatComplete` 和 `chatResult`；若 AI 需要等 GM 回执，会再次输出 `modelRequest`。同一进程可继续输入下一条 `user`。默认棋局仅保存在进程使用的临时目录；需要跨进程复用演练状态时可加 `-- --state-file=/tmp/aasc-gomoku-demo.json`。

JS 调用方可从 `src/apps/server/modules/game/game-chat-session.js` 引入 `createGameChatSession({ filePath, displayId, onModelRequest, onEvent })`；`onModelRequest({ input, systemPrompt, sequence })` 可异步返回 AI 回复字符串，`await session.sendUser(用户文本)` 返回最终 `result`、本轮 `events` 和权威 `snapshot`。这个回调模式接收完整 AI 回复并复用正式游戏桥接逻辑，不连接真实显示端或模型账号。

调用真实聊天模型时，传入现有 `chat` 服务和 `roleName`，例如 `createGameChatSession({ filePath, displayId, chat, roleName: '小爱' })`。角色名必须能从当前聊天模板找到；入口按正式 private 会话保存两轮间的用户与助手历史，模型请求由 `chat.chatStream` 生成和发送，不需要调用方自己拼接 `System:`。这个模式会写入传入聊天服务配置的私聊历史；隔离测试需同时使用临时聊天运行目录和临时棋局文件。带目标显示端的聊天会等本次模型回复完成并校验游戏调用后展示叙述。
