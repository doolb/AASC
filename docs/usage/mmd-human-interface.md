# 独立 MMD-AR Human 生理与后天行为

当前在本地生成的3rd/mmd-ar-test/web-dist提供，尚未发布外网。动作库与生理设置打开「动作 → Human 生理与后天行为」；全身IK使用右侧独立「全身 IK」按钮。

## 操作

### PMX 身体物理与 PBD 姿态

点击右侧「全身 IK」打开专用面板，然后点「启用全身 IK」。当前页面暂时只开放「身体物理（VaM式）」，自动准备人体物理；PBD实现保留，但页面选项暂时屏蔽。最多显示头、双腕、双膝、双踝、骨盆、胸部和双肘共11点，缺骨骼时减少控制点并显示原因。加载失败会明确提示，不自动回退PBD。

#### 从图片应用姿态

所有入口都在「全身 IK → 图片姿态」，其他面板与ASR网页没有新增入口。

1. 加载PMX模型，展开「图片姿态」，选择清晰的单人全身JPG、PNG或WebP；文件上限20MiB，像素上限约1600万，推理前自动缩小到最长边1600像素。
2. 点击「识别姿态」。浏览器在本机Worker中运行人物检测与姿态ONNX，首次按需加载运行时/模型；图片不会上传。支持的浏览器会缓存模型，同源本地网页可访问时不需要外网推理服务。
3. 查看原图上的关键点预览；有多个结果时，可用「人物候选」切换，切换只改变预览。绿色线与黄色点表示过阈值的点，红色空心点和文字列出低可信身体部位；出画面的点只显示文字提示。躯干关键点不完整时不能应用。可信度不代表坐标准确，二次元坐姿和遮挡的手腕/腿部仍需检查，单张图的深度也只是估计。
4. 点击「应用姿态」，自动启用身体物理并按当前PMX骨长生成可用控制点，原有角度限制继续生效；随后仍可拖点微调。点击「重置控制点」恢复当前原动作。
5. 「取消识别」或收起面板会取消待完成的识别/应用，保留已有控制目标；关闭页面释放Worker与图片资源。识别后切换模型会使结果失效，需要重新识别。

本版使用ONNX Runtime Web的WASM单线程兼容路径，模型与运行时从本地网页同源加载，不使用CDN；WebGPU尚未接入。仅支持静态图片，未接入视频、手指动作或表情。检测去重后最多估计3个候选，按肩髋完整性及身体关键点质量辅助选择默认结果；多人图片仍建议先裁剪，肩和髋均需可见才能建立身体方向。已验证所提供坐姿图默认选回女孩，但不能保证所有二次元图片的关键点准确。

模型来源是OpenCV Zoo的MediaPipe人物检测+Pose ONNX（33个人体点及估计3D），模型合计17,547,397 bytes，另有约13MB的ORT WASM。维护者运行`npm run build:web:mmd-ar-test`会校验/准备模型及配套运行时，模型缓存位于`3rd/mmd-ar-test/model-cache/pose-onnx/`，不提交模型二进制。手机耗时与其他模型的姿态精度待实际设备验收。

控制点默认屏幕直径32px，可用「控制点大小」调节20–48px；镜头拉远仍保持屏幕大小，鼠标/手指命中直径至少44px。相邻点重叠时选离触点中心最近的点。

拖动彩色点设置位置目标；选择具体控制点后，位置和旋转可以分别设为On（牵引）、Hold（保持且不可修改）、Off（放开）、Comply（受力让步）。旋转设为On后用X/Y/Z输入目标世界角度。牵引强度默认0.85，强度同时提高目标响应和最大力/力矩预算；Hold的保持更强，Comply更柔和。可降低强度获得软牵引，阻尼用于减小摆动；人体重力默认关闭，可按需要勾选开启。骨盆默认保持原动画位置和朝向，拖骨盆点可平移整个身体；开启「骨盆自由」允许身体受力移动与转动，骨盆旋转目标可控制转向。保持目标后关节会逐渐稳定，PMX骨长固定。

Off取消该点对应的牵引，标记跟随实际骨骼，身体关节阻尼会让残余运动逐渐衰减；位置与旋转状态相互独立。人体物理启用时，即使控制点全Off，惯性及主动开启的重力仍继续；「重置控制点」清除所有牵引并从当前原动作重新对齐，「关闭全身IK」释放人体模拟并恢复动作。点击「收起」、外部或Escape只收起面板并保留目标；点击角色/灯光/动作/定位会切换面板。镜头空白拖动/双指/滚轮与原IK手势相同。人体模拟由全身IK开关控制，服饰的物理开关和计算后端仍单独管理；原手部防穿模开关在PBD模式生效，身体物理模式使用人体代理碰撞。

当前为独立本地网页的首阶段实现；人体碰撞是简化胶囊/球体，地面以启用时脚踝高度估计。衣服/头发接受身体姿态，暂没有衣物向身体反向施力、皮肤软体或精确皮肤网格碰撞。PMX角度限制优先，目标未到达时可能由骨长可达范围、限位、碰撞或牵引强度造成；过远目标不会持续拉伸骨段。设置仅保留在本次页面会话，不保证与VaM逐帧相同，手机观感/性能待验收。

在「身体物理（VaM式）→ 分部位阻尼系数」中调节各部位，范围0.2～2.5，左右共用；全局阻尼默认1，和部位系数相乘。系数越大，运动耗散越强，同时目标响应更缓。默认根据身体支撑/活动分工设置差异，并通过真实米娅PMX逐部位牵引、保持和释放检查；这些是简化人体代理的工程预设，不是人体实测常数。

| 部位 | 默认系数 | 设置键 |
|------|----------|--------|
| 骨盆 | 1.40 | pelvis |
| 躯干（上半身、胸） | 1.30 | torso |
| 颈 | 1.15 | neck |
| 头 | 1.10 | head |
| 肩带、上臂 | 1.05 | shoulder |
| 肘、前臂 | 0.95 | elbow |
| 腕、手 | 0.85 | wrist |
| 髋、大腿 | 1.20 | hip |
| 膝、小腿 | 1.10 | knee |
| 踝、脚 | 1.15 | ankle |

修改一个部位会保留其他部位的调整；「恢复部位默认」恢复上表全部值，保留全局阻尼和牵引/重力设置。部位系数同时影响目标牵引、自然姿态、放开后的关节耗散及刚体速度衰减；自然姿态先应用原有保护，再乘部位系数，因此小于1的值也生效。质量/有效惯量由现有物理驱动处理。切换PBD时设置保留但不参与PBD求解，刷新页面恢复默认。

脚本可调用Human接口 `setInteractiveIKMode('physics'|'pbd')`（异步）、`setInteractiveMarkerDiameter(sizePx)`（20–48px）、`setInteractiveBodySettings({strength,damping,dampingMultipliers,gravity,freePelvis})`、`setInteractiveTargetState(key,positionState,rotationState)` 与 `setInteractiveTarget(key,worldPosition,worldQuaternion)`。例如 `setInteractiveBodySettings({dampingMultipliers:{wrist:0.7,torso:1.4}})` 只改腕与躯干；数值必须为有限数字，非法值回退对应部位默认值，未知键忽略。位置为3个有限数值，旋转为4个有效四元数分量，不填写的目标使用null。状态与控制点通过 `getInteractiveIKState()` 获取，PBD只支持位置目标。

格式边界（2026-10-11核对）：VRM可定义Expression表情、人形骨骼及SpringBone摆动，但当前Human模型适配读取PMX的MMD骨骼/Morph元数据；不能将这里的VMD、MPL和刚体功能直接视为VRM支持。VRM动作可使用VRMA，VMD需要骨骼重定向、坐标/初始姿态和表情映射；SpringBone用于头发/衣物摆动及碰撞，不自动继承PMX刚体和关节。共享VRM运行时每帧调用VRM更新并支持简单happy表情，未接入PMX的VMD或Ammo/XPBD刚体链路。参见[VRMA规范](https://vrm.dev/en/vrma/)及[SpringBone规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_springBone-1.0/README.md)。

1. 加载PMX，等待动作库就绪。呼吸、自然眨眼默认开启，生理强度0.35，可关闭或调整。自然眨眼避开显式眼部动作。
2. 在「模型能力与人工映射」查看缺失项，按当前模型名称手动匹配骨骼/呼吸/闭眼表情。五元音映射仍在「口型」分类。
3. 填行为名称，选择VMD并「登记VMD」；不选文件时登记当前基础VMD。选择控制部位可限制行为轨道，可指定已保存的组合表情名称。
4. 选已登记行为和版本，点「播放行为」预览。登记了“点头”等同名行为后，高级按钮及明确回复标记优先使用该版本。
5. 在「MPL覆写 / 叠加原动作」输入代码，或从MPL分类复制；选择部位、混合方式、开始秒数、时长和强度。「修正当前基础动作」直接叠到当前VMD。
6. 选动作库行为后，「保存行为的新版本」将修正附加到当前默认版本。旧版本保留，选择旧版后「切换默认版本」可恢复旧定义；下一次播放使用它。
7. 「组合表情」用JSON权重保存组合，例如 {"开心":0.7,"害羞":0.3}；也可用当前PMX原始名称。保存后可预览，或通过 [表情:友好] 调用。
8. 「条件反射」登记事件与行为/表情的关联；发送事件可预览。默认touch.head→害羞、stimulus.surprise→惊讶，支持阈值、冷却与删除。事件来源由调用方提供。
9. 动作库按PMX骨骼/Morph签名存当前浏览器IndexedDB；「导出动作库」同时备份VMD及定义。「导入」替换当前模型库，不自动修改其他模型库。保存失败时页面显示原因，可导出备份。

原VMD持续播放，修正结束回归本帧原姿态。MPL覆写只影响指定轨道，原文件保留；加法是相对绑定姿态叠加。默认禁止根移动，root/all遮罩或bone:原名可显式启用。动态刚体骨骼继续由物理控制。

表情、动作、口型可同时播放。相同轨道按优先级混合：生理→高级/回复→反射→手动MPL；手动表情最后覆盖，嘴型由口型播放器控制。动作面板的停止按钮只停止自身动作层。

## 待机、服务器动作与防穿模

独立网页默认循环待机，使用用户给定MPL：双臂bend forward 35°、双肘10°、双腕-10°，不含turn，8秒循环；跳舞需要在「动作 → 高级动作」手动选择。时长留空时，服务器VMD按原速原长播放，当前跳舞15.2秒；填时长才调整速度，次数按完整周期重复。强度/次数留空采用来源默认值。停止或自然结束后回到基础待机，同名登记行为仍优先。

「动作 → 物理 → 手部防穿模」默认开启，使用物理现有刚体检测并用手臂IK避让；开关保存到当前浏览器，刷新或切换模型/物理后端会恢复。接触时承接当前避让姿态并过滤目标，短暂断续不立即回拉；当前避让姿态没有穿透时，会按600ms限速尝试回到原动作；遇到碰撞就停在安全位置，继续检查。原动作稳定无接触和关闭后按600ms预算平滑释放。此待机原始姿态手部贴近裙面，建议保持手部防穿模开启。需要模型提供可靠手臂链和对应刚体；刚体未覆盖的衣服细节及不可达动作仍可能出现穿模。

点击高级动作会播放，并将待机或内置动作的可用源码填入MPL编辑器；每个动作只有一个按钮，不自动展开编辑器、滚动或抢焦点。需要编辑时手动展开「MPL 低级动作」，可修改并点「编译并播放」预览，或下载MPL/编译后的VMD。当前只编辑、预览和下载，不提供保存高级动作入口。跳舞只有VMD，显示暂无MPL源码；服务器以后可在条目中提供同源mmd目录`mplUrl`。当前模型同名本地MPL优先；本地VMD或多层修正提示从Human动作库查看，不冒充另一份源码。

后续服务器动作：将VMD放在站点的`mmd/`目录，在`mmd-actions.json`的actions数组新增唯一id/name、type=`vmd`、相对url，刷新页面即可显示并用`[动作:名称]`调用。例：`{ "id": "greet", "name": "问候", "type": "vmd", "url": "./mmd/motions/greet.vmd" }`。项目维护时修改`3rd/mmd-ar-test/server-actions.json`并运行`npm run build:web:mmd-ar-test`；发布时一起同步目录JSON与VMD。无需每个动作修改源码，清单与文件当前仅在本地构建提供。

## 高级动作与动作库保存格式

内置点头、摇头、歪头、鞠躬、挥手是源码中的MPL文本模板；播放时根据名称、时长、强度和次数生成MPL，编译为VMD数据再采样，不会仅因点击播放就自动登记到动作库。同名已登记行为优先于内置模板。

登记动作库按PMX签名保存在当前浏览器IndexedDB：动作名称、版本、默认版本、遮罩、参数和MPL修正等为结构化定义；MPL行为保存原始source文本，VMD行为保存ArrayBuffer并通过assetId引用。导出为 `mmd-human-<模型签名>.json`，VMD二进制编码为Base64内嵌；MPL面板另可下载编译后的 `mpl-motion.vmd`。

## 头部与眼球注视

「Human 生理与后天行为 → 头部与眼球注视」中分别开启头部/眼球跟随；新配置默认两者开启，注视强度0.7。默认看向当前相机。轻触或点击画面后暂时看向该位置，默认3秒后平滑返回相机；拖动角色/相机不切换目标。「返回相机」可提前结束临时目标。

修改后点「保存注视设置」，按当前PMX签名保存。可调水平/垂直附加角、头部/眼球缓动及停留时间。附加角是在当前基础动作之上计算，头部默认45°/25°、眼球20°/15°；缓动默认200ms/60ms。标准PMX正面为+Z，正面相反的模型可选-Z。状态区显示实际头部/眼球绑定和不能自动驱动的原因，人工绑定在「模型能力与人工映射」。

注视不影响口型/眨眼/表情。显式Human头部或眼球动作按权重优先。头部开始动作或被新动作接管时，从当前显示姿态用600ms融合到实时动作与剩余跟随；淡出或停止时，同样用600ms平滑回归相机/点击目标。短动作提前结束会承接当前姿态开始恢复。普通头部跟随仍使用设置的缓动时长。换模型、进入编辑、后台或隐藏显示清除临时点击目标。非标准旋转继承关系、动态眼球骨骼会跳过；共有眼仅支持已识别的比例1非局部旋转grant。

## 页面接口

PMX和动作库就绪后使用window.MmdArHumanInterface，current取得当前模型的实际HumanInterfaceElement实例。

~~~js
const human = window.MmdArHumanInterface;
human.capabilities();
await human.physiology.set({ breathing: true, blinking: true, strength: 0.35 });
await human.gaze.set({ head: true, eyes: true, holdSeconds: 3 });
human.gaze.point(0.5, 0.2); // 画面归一化坐标[-1,1]，Y向上
human.gaze.reset(); // 平滑返回相机
await human.learn.register({
    actionId: '招手', vmd: file, mask: ['rightArm'], expression: '友好'
});
await human.learn.revise('招手', {
    source: mplSource, mode: 'additive', mask: ['head'], start: 0, strength: 0.6
});
await human.perform({ action: '招手', expression: '友好', owner: 'ai', count: 1 });
await human.mpl.play(mplSource, { owner: 'correction', mode: 'override', mask: ['head'] });
const mouth = await human.mouth.play('你好，很高兴见到你。');
human.mouth.stop(mouth.sequence);
await human.reflex.emit({ type: 'touch.head', strength: 0.8 });
human.stop('correction');
human.getState();
~~~

组合需先用learn.expression('友好', {开心:0.7,害羞:0.3})保存。learn.list列出行为和版本，learn.selectVersion(actionId,versionId)选择默认版本；learn.reflex保存规则，learn.removeReflex删除；learn.export返回JSON Blob，learn.import(file)导入。

同owner新请求替换旧请求，不同owner按部位并行。stop(owner)释放该owner的身体/表情贡献，口型用sequence单独停止。切换基础VMD/模型、编辑、后台、隐藏显示或离页取消旧自动层；迟到编译结果不写入新角色。

## 范围和限制

学习由人工登记、关联及版本修正组成。标准骨骼/MPL语义可自动匹配，非标准骨骼可配置；原始VMD按真实骨骼名匹配，绑定轴/比例不同需要专用动作，不提供任意模型自动重定向。

每行为16版本/8修正层，总64行为/128版本；单VMD16MiB、库VMD合计64MiB。MPL最多64KiB，编译30秒超时。独立口型仍为文字估算、无声播放。

已完成构建和静态检查，实际多模型、物理连续性、版本切换及手机性能待设备验收。使用说明不表示已完成浏览器播放测试。

## Emoji高级动作与自动MPL（2026-10-11）

高级动作增加爱心/比心、亲亲、猫爪、猫咪撒娇、拥抱、思考、嘘、晚安、庆祝、闪亮、赞同、加油、合十、敬礼、摊手、拒绝，以及开心/悲伤/生气/惊讶/害羞/眨眼/平静入口，共28类内置动作。按钮显示Emoji和中文名；心形/猫咪家族、常用手势和肤色/性别变体也可在AI回复中识别。🐾是猫爪，❤️/🫶是比心，🐱/🐈‍⬛/🦊是撒娇，😽/😘是亲亲；猫咪喜怒惊哭沿用对应情绪。天气、设备、国旗和未知组合保留文字。

点击高级动作会播放，并自动将可用的完整MPL替换到低级编辑器；时长/强度/次数用于内置模板生成。内置和服务器动作均只保留动作按钮；填入时保持编辑器折叠状态、当前位置与焦点，需要编辑时手动展开「MPL 低级动作」。只编辑、预览和下载，暂不保存。快速换动作、修改编辑内容、停止、换模型或后台，迟到源码不会覆盖新内容。AI回复队列播放不逐段改编辑器。跳舞等纯VMD正常播放并提示暂无MPL，保留现有文本；本地/服务器MPL保留原始源码，已有播放层参数不会被改写到资源文件。
