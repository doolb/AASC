# MMD测试版刚体XPBD WebGL2

重新构建或刷新 `3rd/mmd-ar-test/web-dist/`，在动作面板的“布料计算”中选择 **XPBD（WebGL2）**。这是PMX刚体/骨骼物理的GPU后端；保留原Ammo、CPU XPBD及其独立选择。

GPU版用浮点贴图ping-pong执行预测、锚点插值、六轴约束、球/盒/胶囊接触、摩擦、反弹和风。默认每帧结束同步读回一次最终刚体状态以更新骨骼；开启下述直连后，正常预览与动作暂停帧直接使用GPU骨骼纹理。现有本地模型/VMD切换继续使用T-pose、清空速度、下一帧播放的流程。

切换后原“纠错基准”显示为“每帧子步数”：3表示每帧3个子步，**不是3Hz**。物理Hz不参与XPBD步进。默认子步为45，已有手动值保留；3子步累计拖动/模式切换仍观察到飞散，不能将降低到3视为已验证的稳定设置。提高子步会线性增加绘制pass和同步等待。

状态栏显示帧物理耗时、读回耗时、pass数；支持GPU计时扩展才显示GPU毫秒。无WebGL2/可渲染浮点纹理、容量超限或数值错误时回退CPU XPBD并显示原因。默认仍保留当前求解器；不会自动将所有模型换成GPU。

当前属于实验后端：保守碰撞对、较多pass及同步读回可能使它比CPU更慢。本机软件GPU下默认米娅也明显更慢，不能据此宣称硬件加速。手机实际稳定性及耗时仍待测试，可随时切回XPBD（CPU）或Ammo。

构建：`npm run build:web:mmd-ar-test`。定向自测与重型浏览器串行命令见下文；需本机Chromium（可通过CHROMIUM_PATH指定浏览器）和构建后的默认模型。面板回归另用 `node --test tests/mmd-ar-web-panel-groups.test.js`。

## GPU物理直连骨骼纹理（独立网页）

在「动作 → 物理」勾选「GPU 物理直连骨骼纹理」，默认关闭，选择保存在本浏览器。它只适用于 **XPBD（WebGL2）**，不会自动切换求解器；Ammo、CPU XPBD和未运行物理时状态行会说明不适用或等待。无有效浮点FBO、超出预算、同骨多刚体、先写子骨后写父骨、骨骼缩放或额外骨根父节点时明确回退/同步，不丢弃刚体来强行直连。

**手部防穿模默认开启，需要CPU刚体姿态。** 即使请求直连，状态行也会显示「同步兼容 · 手部防穿模需要CPU刚体，请先关闭其开关」。如需体验直连，手动关闭同组「手部防穿模」；重新开启时自动同步兼容。不会为了直连自动关闭防穿模。

生效时状态行显示「GPU直连生效 · 本帧完整读回 0」及累计按需/兼容读回。动作播放和暂停都继续GPU物理合成骨骼纹理，计数在普通帧保持不变。骨骼/刚体诊断开启期间恢复每帧同步；关闭诊断后自动恢复直连。精确拾取、编辑读取/固定视角和关闭直连时按需同步一次；T Pose及动作重载会重置物理和纹理。上下文丢失先解绑旧纹理，恢复时从本地骨姿态重建并清零速度，不保证丢失前GPU姿态无损续接。

此轮仅完成本地网页实现与浏览器验收，未发布网页或构建APK。SwiftShader证明WebGL2执行/读回与生命周期流程，手机GPU帧耗、阴影观感和P95仍待验收；直连增加合成pass，不承诺提速。

## “读回耗时”的含义

当前刚体GPU后端在所有物理pass提交后，对`readRenderTargetPixels`调用前后计时。该值包含等待GPU完成此前命令、同步及实际数据传输；显示5ms不能直接认定为拷贝数据花了5ms。它已包含在帧物理总耗时中，不应再次相加。GPU计时来自异步查询，可能对应较早帧，不能与当前读回耗时简单相减。

同步兼容模式每帧读回6项刚体状态和所有允许碰撞对的累计标记；以183刚体/11540允许对计算，含纹理填充约199KiB。标记即使未打开碰撞诊断仍会读回。直连普通帧跳过这整批状态与标记打包/读取，CPU碰撞信息只在显式同步后有效。另一独立的“顶点布料 GPU（WebGL2）”使用GPU纹理渲染顶点，不能与这里的刚体骨骼回写路径混淆。

参考：[MDN WebGL最佳实践中的同步读回说明](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。读回计时口径保持，直连模式改变的是普通帧是否进行整批物理读取。
