# 聊天视频生成与播放

控制端和显示端的“模型”面板新增“生视频模型”，选择已登录Provider及具体模型后沿既有配置流程同步。该选择用于SubAI生视频，主AI原生生成继续沿用主模型。主聊天、生图选择分别保留。

可以自然地说“帮我生成一段橘猫眨眼的视频”。主AI可输出如下调用，提示词含逗号需用双引号，内部双引号写两次；参考图使用当前聊天的图片ID：

```text
SubAI,生视频,"窗台上的橘猫轻轻眨眼，尾巴慢慢摆动"
```

聊天立即显示生成中卡片，后台完成并保存后在同一位置显示可播放视频；一轮多视频全部保存。主AI直接生成的视频不需要该标签，视频与文字共用主回复。播放器有控制条，支持内联播放，刷新和历史恢复仍使用本地文件。

取消停止本地查询/下载，清空和删除聊天后迟到结果不会重新插入。官网已接收的生成是否取消、是否返还额度由官网决定；服务重启只查询已知任务，不自动再生成。独立任务API为POST `/v1/video/generations`和GET `/v1/video/generations/{id}`，沿用Chat2API API Key；POST返回202和任务ID，随后查询状态。model值可从`/v1/models`的video能力条目读取。

当前目录提供豆包/清影官网默认模式，以及Qwen HappyHorse1.0、Wan2.6、Wan2.7。参数使用当前接入的默认模式，是否有生成权限、积分和可用画幅以官网实际返回为准。当前Node接入的Qwen旧聊天入口曾返回积分不足；当前浏览器千问创作的HappyHorse 1.1已生成作品并通过Node下载/视频格式检查，新创作入口的创建/查询尚未接入Node，不能将旧入口错误视为HappyHorse不可用；豆包和GLM已生成并完成下载/桌面双端播放。

“支持上传视频”仍默认关闭，实际视频输入入口尚未接入，不影响生成视频输出。此改动只需更新服务代码包并刷新网页，尚未构建部署；Android更新后的实际播放待验收。
