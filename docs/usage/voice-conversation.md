# 显示端语音三种会话状态使用说明

本文说明显示端语音会话当前的三种主要状态：`waitingWake` 等待唤醒、`activeGroup` 群聊、`activePrivate` 私聊。

`disabled`（监听关闭）和 `waitingTts`（等待语音播放或处理）属于设备运行状态，不属于本文的三种聊天会话状态。

## 一、三种状态总览

| 状态 | 页面显示 | 普通语音是否处理 | 主要用途 |
|------|----------|------------------|----------|
| `waitingWake` | 监听中 · 等待唤醒 | 需要唤醒词；免唤醒功能指令例外 | 安静等待，不让普通对话误触发 |
| `activeGroup` | 监听中 · 群聊 | 直接作为群聊输入处理 | 与全部聊天角色共同对话 |
| `activePrivate` | 监听中 · 私聊：助手名 | 直接发送给当前私聊助手 | 与指定助手连续对话 |

## 二、共同处理规则

### 1. 监听和识别

- 监听关闭时，语音输入直接丢弃，状态为 `disabled`。
- 监听重新开启后回到 `waitingWake`，不会自动恢复原来的群聊或私聊。
- 语音识别文字会先回传控制端用于观察。
- 启用声纹识别但没有匹配到说话人时，文字可以显示，但不会执行唤醒、聊天或指令。

### 2. TTS 和超时

- 普通聊天回复沿用正常聊天历史、流式响应和通用 TTS 播放目标。
- active 状态的有效输入会刷新会话计时。
- 连续约 3 分钟没有有效输入后回到 `waitingWake`。
- 当前回复的 TTS 队列实际播放完成后，才重新开始会话计时。

### 3. 指令模式

`commandMode` 是语音指令模式开关，对应语音配置中的 `voiceCommand.commandMode`，可以说“打开指令模式”或“关闭指令模式”切换。两个切换指令始终可用，不受当前会话状态和开关本身影响。

| 会话状态 | `commandMode` 对普通文本的影响 | 内置指令 |
|----------|-------------------------------|----------|
| `waitingWake` | 会话门控本身会拦截未唤醒的普通文本；打开或关闭指令模式都不会让普通文本直接进入聊天 | 免唤醒内置功能继续执行 |
| `activeGroup` | 不过滤普通文本，直接进入群聊处理 | 当前仍按原优先级处理；“搜索”例外转普通聊天 |
| `activePrivate` | 不过滤普通文本，直接进入当前私聊处理 | 当前仍按原优先级处理；“搜索”例外转普通聊天 |

因此，打开指令模式并不等于“所有语音都只能执行命令”：在 active 群聊和私聊中，普通语音仍会发送给聊天；在等待唤醒时，普通语音仍需要唤醒词。当前 `commandMode` 对现代显示端三状态流程没有实际控制作用，暂作为历史兼容配置保留。

## 三、`waitingWake`：等待唤醒

这是显示端监听开启后的默认状态。除免唤醒功能外，普通语音不会发送给聊天 Agent，也不会写入普通聊天历史。

### 1. 处理顺序

1. 识别纯唤醒词或私聊唤醒词。
2. 识别带助手名且包含额外内容的群聊输入。
3. 识别免唤醒内置功能或已配置的自定义指令。
4. 以上都不匹配时丢弃普通文本。

### 2. 唤醒进入群聊

以下类型会进入 `activeGroup`：

- `你好小爱`
- `小爱你好`
- `小爱，介绍一下今天的安排`

纯唤醒词只切换状态，不把唤醒词本身发送给聊天。带有额外内容时，会保留完整原始文本发送到群聊，不会删除助手名前缀。

所以“`小爱，介绍一下今天的安排`”会先从 `waitingWake` 进入 `activeGroup`，随后把完整句子作为第一条群聊消息发送；它不是只识别“小爱”后停在等待唤醒状态。

进入群聊后，普通聊天使用当前聊天系统的全部角色模板，不固定为被提到的某一个角色。

### 3. 唤醒进入私聊

使用“助手名 + 开始对话”的形式进入指定助手私聊，例如：

- `小爱开始对话`
- `妲己开始对话`

进入后状态变为 `activePrivate`，当前助手名作为私聊对象。

### 4. 免唤醒功能

当前 `waitingWake` 可以直接执行已注册的内置功能和已配置的自定义指令，例如：

- 系统帮助、主题帮助，例如 `系统`、`帮助静音`、`静音帮助`
- 报时，例如 `现在几点`
- 提醒、天气、搜索、播放
- 静音、取消静音、停止播报
- 开启或关闭录音、指令模式
- 完整匹配的确认/取消词，例如 `确认`、`是`、`好的`、`取消`、`拒绝`

“结束对话”“退出私聊”属于会话控制词，在等待唤醒状态下不会单独唤醒聊天。

## 四、`activeGroup`：群聊

进入群聊后，显示端的普通语音被视为当前群聊的一条消息。

### 1. 普通聊天

- 普通文本直接发送到群聊 Agent。
- 保留完整 ASR 原文。
- 使用群聊模式和全部角色模板。
- 不会因为 `commandMode=true` 而静默丢弃普通文本。

例如：

```text
用户：你们觉得周末去哪里比较好？
处理：作为普通群聊消息发送给当前群聊 Agent
```

### 2. 带助手名的文本

群聊中提到助手名时，仍保留完整原始文本：

```text
用户：小爱，帮我总结一下刚才的内容
处理：完整原文进入群聊，不删除“小爱”前缀
```

### 3. 搜索文本

当前 active 群聊中的搜索按普通聊天处理：

```text
用户：搜索北京新闻
处理：原文作为群聊消息发送给当前群聊 Agent
```

此时不会执行搜索关键词提取、独立搜索 session 或 `search=llm` 特殊路由。

### 4. 其他内置指令

除“搜索”外，天气、提醒、播放、静音、报时、录音、停止播报、系统帮助和自定义指令当前仍按原有命令优先级处理。例如 active 群聊说“北京天气”，目前仍可能进入天气处理，而不是普通聊天。

### 5. 会话控制

- `结束对话`：回到 `waitingWake`，下一次普通聊天需要重新唤醒。
- `私聊 + 助手名`：切换到该助手的 `activePrivate` 私聊。
- `进入修复模式`：进入现有的本地修复模式密码流程，不直接发送给普通聊天 Agent。

## 五、`activePrivate`：私聊

进入私聊后，普通语音发送给当前指定助手，并携带当前私聊对象和会话 ID。

### 1. 普通聊天

- 使用当前 `target` 指定的助手模板。
- 保留 `sessionId`，不同私聊对象或会话不会混用历史。
- 普通回复继续进入私聊历史、控制端聊天显示和通用 TTS。

例如：

```text
当前状态：activePrivate，小爱
用户：帮我安排一下明天的工作
处理：发送给小爱当前私聊 Agent
```

### 2. 搜索文本

当前 active 私聊中的搜索也按普通聊天处理：

```text
用户：搜索北京新闻
处理：完整原文发送给当前私聊 Agent
```

它不会进入独立搜索频道、独立搜索 session，也不会因为搜索路由配置为 `llm` 而改变。

### 3. 当前仍保留的特殊命令

当前 active 私聊仍会优先处理已存在的系统命令和自定义命令，包括天气、提醒、播放、静音、报时、录音、停止播报、系统帮助和自定义指令。

私聊相关控制包括：

- `结束对话`：回到 `waitingWake`。
- `退出私聊`：切换为 `activeGroup`。
- `私聊 + 助手名`：校验助手后切换私聊对象。
- `进入修复模式`：启动本地密码验证流程。

例如当前说“天气北京”，仍可能直接执行天气查询。后续计划是把部分控制能力设计为聊天 Agent 可调用的受限系统工具，设计记录见 [私聊聊天 Agent 系统工具设计](../design/private-chat-agent-tools.md)。该工具方案目前尚未实现。

## 六、三种状态切换示例

```text
waitingWake
    ├─ “你好小爱” -> activeGroup
    ├─ “小爱开始对话” -> activePrivate(小爱)
    ├─ “搜索北京新闻” -> 执行免唤醒搜索，仍留在 waitingWake
    └─ “今天天气怎么样” -> 普通文本被忽略

activeGroup
    ├─ 普通文本 -> 当前群聊 Agent
    ├─ “搜索北京新闻” -> 当前群聊 Agent（原文）
    ├─ “私聊妲己” -> activePrivate(妲己)
    └─ “结束对话” -> waitingWake

activePrivate(小爱)
    ├─ 普通文本 -> 小爱当前私聊 Agent
    ├─ “搜索北京新闻” -> 小爱当前私聊 Agent（原文）
    ├─ “私聊妲己” -> activePrivate(妲己)
    ├─ “退出私聊” -> activeGroup
    └─ “结束对话” -> waitingWake
```

注意：等待唤醒状态的搜索仍是免唤醒特殊功能；只有 active 群聊和 active 私聊中的搜索才作为普通聊天发送。

## 七、当前规则与后续设计的区别

当前代码仍由服务端语音命令层优先处理大部分内置指令。`commandMode` 当前未参与现代显示端三状态的实际门控，只保留配置和旧调用路径兼容；后续再决定删除或重新定义。后续的“私聊 Agent 系统工具”方案会让聊天 Agent 通过服务端白名单工具调用结束对话、退出私聊、切换助手、请求修复模式、静音和报时，但必须先完成工具协议、确认策略和 Pi/Codex 适配，不能把设计文档当成已实现功能。

## 八、Windows 子显示端语音转文字输入

Node.js 子显示端在 Windows 上支持系统级语音输入，不会把文字写入子显示端 TUI 输入栏。

- 按 `Ctrl+Alt+Space` 可切换语音输入模式。
- 说“开始输入”可进入语音输入模式。
- 输入模式下，普通识别文字会注入当前 Windows 前台窗口。
- 说“返回”删除最近一次完整语音输入。
- 说“发送”向目标窗口发送 Enter，并退出语音输入模式。
- 说“结束输入”退出语音输入模式；开始和结束时会先播报状态提示，提示播放完成后才恢复录音。
- 返回或发送时如果前台窗口已经变化，系统会拒绝操作，避免误操作其他窗口。

该功能当前仅支持 Windows；普通语音会话、Android 显示端和其他子显示端行为不变。
