## 无效棋盘点击飘字与不补执行（2026-10-21）

```text
已有声明 := canPlay门控、棋步pending锁、恢复requestId、原旋转游戏层、服务端当前请求Map
新增定义 := 单个飘字节点 + 一个1500毫秒隐藏计时器；落子阻止原因表
校验点击 → 依次检查连接、对话、棋局、演示、可见性、结果、同步、处理中、回合、空位 → 返回首个阻止原因或允许

按下时无效的指针手势 → 标记该指针编号，仅用于阻止本次click；即使松手前刚好解锁也不落子；下一次新按下重新校验，不保存坐标
click → 再校验；受阻仅显示原因并返回；允许时立即设置pending再发送；发送失败提示断线并释放本次锁

权威gameError → 当前匹配请求的拒绝也显示飘字；旧请求回包忽略，原同步与解锁规则保持
收到可落子状态、棋盘隐藏或退出对话 → 清除过期飘字和计时器；旋转与游戏层一致
无效点击 → 不创建消息、不写上下文、不存坐标、不排队；解锁、回合切回用户及重连后仍不补执行
验证 := 真鼠标/触屏点击disabled交点有原因、连点单节点、计时隐藏、四向旋转边界、服务端解锁后棋局/AI请求不新增
```

## 棋盘点击状态与请求生命周期（2026-10-21）

```text

点击 → 再次检查可点击条件 → 先保存唯一请求编号、棋局编号和版本并禁用所有格 → 发送 gameMove；发送失败立即解除本次锁
普通快照、增量、显隐和尺寸事件 → 只更新权威棋盘，不解除棋步锁；同局旧版本快照或重复增量忽略
gameError → 仅对应 requestId 能解除本次锁；版本过期或棋局变化须先同步；无关错误不能解锁
服务端 gameMove → 校验连接身份、该显示端无处理中棋步、棋局编号和版本 → 由权威服务校验轮次及空位 → 成功后保存请求锁，发送 gameMoveResult(processing)，只启动一次现有 AI 聊天

AI 聊天完成或失败 → finally 删除该请求锁 → 给当前连接回 gameMoveResult(complete)；显示端只接受匹配请求的完成回包，之后仍检查权威轮次、结果与空位
恢复或重连 → 保持禁用并发送带独立 requestId 的 gameRecover → 服务端返回 gameRecoverResult { requestId, snapshot, pendingRequestId } → 仅匹配本次恢复的回包可恢复棋盘和处理中请求；没有棋局时明确返回空快照
普通快照不能结束同步；恢复期间忽略旧恢复回包；断线禁止点击，重连再次核对服务端处理中请求

```

```text
真实棋盘展示条件 := 棋局 visible=true 且对话状态为 activeGroup 或 activePrivate；等待唤醒、监听关闭、未知状态时棋盘和恢复入口均隐藏，棋局数据仍保留
收到 voiceConversationState → 更新棋盘展示条件，但继续将事件交给语音模块处理；退出/道别/超时/监听关闭时立即隐藏；重新进入活动对话时按原棋局 visible 值恢复
显示端本地语音倒计时到期 → 本地语音状态改为 waitingWake → 经 DisplayStage.handleServerMessage 发布同一 voiceConversationState 给游戏层 → 立即隐藏真实棋盘与游戏菜单；之后服务端权威状态消息仍可再次覆盖本地状态并恢复棋盘
演示棋盘不受对话状态门控；演示结束 → 恢复当前真实棋局快照，并按当前对话状态决定是否显示；点击“关闭” → gameView(false) 持久化 visible=false，新对话也不会自动展开该棋局
AI 代 GameUser 落子 → 模型依据用户自然语言填写坐标，用户原话不必逐字包含坐标；GM 仍校验棋局存在、当前回合、坐标范围、空位和版本，不因模型推断坐标而跳过权威规则；显示端点击通过受信任连接身份直达服务端，不接受客户端自行指定操作者
当前显示端演示脚本 → 连接本机控制 WebSocket → 读取在线 displayList → 唯一主显示端自动选中，多个显示端时要求显式 displayId → 发送本机专用 gameDemoStart
服务端演示会话 → 校验请求来自本机、目标显示端在线、棋盘尺寸与逐步延迟/结果停留时长/胜方参数有效 → 向该显示端发临时棋盘快照
演示脚本默认依次模拟 User 胜、AI 胜两局；每局按合法预设落子交替发送单步增量，逐步等待设定延迟；第五子写入胜负结果后保持该棋盘一段时间，再用新游戏ID发下一局空棋盘快照
演示脚本可只选 User 胜或 AI 胜；不调用真实模型，不写入权威棋局或聊天历史；最终获胜棋盘一直保留到脚本停止
演示结束、脚本断开或真实棋局更新 → 取消演示定时器 → 恢复目标显示端当下权威棋盘；若原无棋局，则发 gameDemoEnd 关闭演示层
```

## 2026-10-23 已确认实现：清空生命周期

```text
棋局归属 := 规范化mode/target/sessionId，保存在game.chatScope；无归属的旧棋局只接受明确displayId清理

清空入口 := 共用history-clear服务先校验聊天/目标参数，再game.clearForChat，最后原chat.clearHistory
目标匹配 := 有displayIds只清这些显示端；无displayIds只清有明确所属范围的棋局；不全局删除旧棋局
持久清除 := 批量移除匹配棋局 → 原子保存；失败回滚内存并报错，历史不先删除
完成 := 失效匹配在途租约 → gameCleared(gameId)事件 → 显示端清理棋盘/棋步锁/恢复入口
迟到响应 := 游戏桥使用租约signal过滤输出；模型返回后先检查signal，已清空不执行标签、不保存答复
恢复 := 旧gameId已清除时不接收其迟到快照；重启从文件读不到已清棋局，NowGame为无
临时清空 := 复用同一服务，优先服务端临时会话displayId；没有该信息才使用消息目标
```
