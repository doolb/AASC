# 五子棋游戏协议实现伪代码

```text
独立会话入口 → 接收临时棋局文件路径、显示端 ID、真实聊天服务或目标 AI 回调及事件回调 → 创建权威五子棋服务；真实聊天服务直接复用其 chatStream 与会话配置，回调模式只用于离线模拟 → 调用现有 runGameAwareChat，不另写协议解析或棋局规则
入口收到用户文本 → 读取该显示端权威快照 → 向目标 AI 回调传入本次模型输入与完整系统提示 → 把 AI 原文交给现有游戏桥 → 按原有校验流程产生目录/规则/棋局 GM 回执、聊天输出和棋盘快照
真实聊天模式选定角色名 → 从已有聊天服务的角色模板读取角色设定，按正式 private 会话填入 templateTarget、target、固定 sessionId、历史选项；每轮先以同一会话键通过聊天服务保存用户消息，再把桥接层叠加游戏提示后的原始 input 与 options 交给已有 chat.chatStream，最终只保存已由 GM 校验的助手正文；GM 行不写入普通聊天历史；入口不自行拼接 System:、角色消息或历史
raw 聊天组装 → 若指定角色模板内容已作为 System: 的完整末尾块出现，则不再生成重复的 User:角色模板行；下一轮 NowGame 改变引发上游会话重建时，仍从同一 private 会话历史恢复先前用户和助手正文
目标 AI 回调模式 → 每次续接只收到游戏桥实际发出的输入并返回完整回复；入口不伪造流式片段；两种模式都按发生顺序输出 modelRequest、gameProtocol、gameUpdate、chatChunk、chatSentence、chatComplete 或 chatError；一轮返回最终聊天、事件列表和权威快照
交互式 JSON 行脚本 → 用户发送带 type 的 user 消息 → 脚本发出 modelRequest 并等待带 type 的 modelReply → 可能反复往返 GM 直到本轮 chatResult → 使用临时文件隔离默认演练棋局；显式 state-file 可复用演练棋局
回调模拟模式不连接生产聊天账号、WebSocket 或真实显示端；传入真实 chat 服务时按原有聊天会话连接模型并保存所选角色的私聊历史，调用方需自行隔离测试运行数据；两种模式都不修改实际用户棋局，应用聊天入口继续沿用同一个 runGameAwareChat
首选协议行 := Game:游戏名,操作者,操作[,操作参数...]；不用尖括号，回复中任意位置的独立 Game: 行可作为新格式调用；同一行内普通叙述含 Game: 时仍按正文处理
兼容旧调用 := <Game:游戏名,操作者,操作[,操作参数...]>；沿用旧解析和批量执行规则，旧单条调用仍可出现在正文中
解析调用 → 两种格式均只接受五子棋、User/AI、已定义操作和对应数量的位置参数；拒绝中文逗号、多余字段和未知值；普通正文中的无尖括号 Game: 不触发操作
输出与回执 → 新提示引导 AI 使用无尖括号协议行；GM 状态/错误/快照及新 gameTrace 原文使用新格式；旧模型输出经同一权威流程执行；自然语言不包含协议调用
流式过滤 → 新 Game: 或旧 <Game: 前缀未完整时先缓冲；两种调用都从用户正文和 TTS 过滤；普通行内 Game: 保留为文字且不执行
用户语音 → 沿用现有聊天入口 → AI 生成独立 Game 协议行与另行自然语言，协议行前后均可有叙述 → 服务端收到完整回复后逐条截留并执行 → 必要时将 GM 结果送回 AI → 只把已确认操作对应的自然语言交给用户
显示端连接时声明 games 能力列表；服务端只认可实际已实现的游戏名，旧显示端缺少声明时列表为空
有目标显示端的聊天在现有 raw 对话文本的 System: 标记后，依次放用户指定的游戏调用格式、回复开头最多八条及原子等待规则、目录与按需规则查询示例、当前游戏提示、原角色设定；提示原文保留最多八条、每行独占、每次回复附自然语言，解析兼容回复中间的独立调用行；字段只用英文逗号；语音坐标由 AI 发 User 落子行，GM 确认后 AI 才选择自己的落子；未获 GM 成功回执不得声称落子成功
模型准备输出调用行 → 如果该调用行需要等待确认或者数据，以及 User 或 AI 操作游戏需要等待状态确认，则将其视为原子操作 → 等该调用行的 GM 回复，本次不能再发其他调用行；解析器仍兼容既有至多八条批量及旧尖括号格式，不能因模型抢跑改变权威棋局
用户报坐标 → 模型先发 User 落子行并等待 GM → 回执显示 User 落子成功、下一手 AI 且棋局进行中后，模型再决定并发 AI 落子行；若模型抢跑预写 AI 行，桥接层只执行 User 行并回送其 GM 回执，预写 AI 行不生效
目录提示 → 首次需要本地游戏先独立发送 Game:目录,AI,列表 → 等 GM 目录结果 → 再按需发送 Game:游戏名,AI,规则 → 等 GM 规则结果后按规则操作；模型入口保持现有 raw 的单条 user 消息格式，不另发 system 角色消息；不把全部游戏规则预先拼进每轮提示，也不根据用户文本关键词替模型开局或落子
每轮 AASC 聊天开始 → 从目标显示端的权威棋局快照读取结果；若正在进行中，将 `NowGame:五子棋` 接在目录提示后，否则写入 `NowGame:无`；该行属于原 raw `System:` 正文，不创建真实 system 角色消息
当前棋局结果为进行中 → 在 `NowGame:五子棋` 下一行附 `五子棋规则:<仅五子棋操作与棋规>`；无棋局或已结束 → 只写 `NowGame:无`，普通聊天不带五子棋规则
AI 查询 `Game:五子棋,AI,规则` → GM 仅回送五子棋专属操作、坐标、先后手、胜负、尺寸约束和快照解码方式，不重复 System 已有的通用协议语法、语音代发与 GM 权威约束；本轮 System/NowGame 不因查询而变化
五子棋快照规则 → 说明 `GM,快照` 后依次为短编号、版本、尺寸、下一手、结果、棋盘编码 → 编码由 `/` 自上而下分行，每行从左到右对应 A、B、C 等列，第一行对应数字 1；`.` 是空位、`X` 是用户黑棋、`O` 是 AI 白棋且为字母 O → AI 选择落点前按尺寸与行列检查该格是否为 `.`，已占用时另选空格，最终仍由 GM 校验
开局成功后的下一轮 AASC 聊天 → 重新读取进行中的权威棋局 → `NowGame:五子棋` 附同一份游戏专属规则；该提示变更允许 Responses 重建上游会话，原 AASC 会话和历史仍保留
一轮内目录/规则/开局后的 GM 回执仍由游戏桥接层续送模型；NowGame 只在下一次 AASC 聊天入口重新计算，不替代同轮 GM 状态，也不让独立 Chat2API 直连接口自行执行游戏
临时真实模型模拟 → 创建独立 displayId 与临时棋局文件 → 每次模型请求以 raw System/历史/User 正文送本机 Chat2API → 使用真实游戏桥执行 Game 协议行并回送 GM → 开局后下一条用户 H3 的 NowGame 为五子棋 → GM 确认 User H3 → AI H4 → 棋盘版本 3、轮到 User；该模拟是旧版实测，后续按新协议重测
模型输出非法协议行（如错误的列表游戏名或 GM 操作者）→ 桥接层回送调用行格式错误，不执行操作，也不向用户输出该批次预写的叙述；模型后续合法开局或落子再按权威状态处理
目录请求 → GM 返回当前目标显示端支持的游戏名；规则请求 → 仅对目录中有的游戏返回对应规则；其余普通聊天不读取详细规则
本地模拟的开局调用链 → 用户原话 → AI 查询目录 → GM 列表 → AI 查询五子棋规则 → GM 按需规则 → AI 开局及自然语言 → GM 开局快照写入 gameTrace 和显示端；开局回复已有叙述时本轮直接结束，不再把该快照回送模型
本地模拟的落子调用链 → 用户 H3 → AI 代 User 落子 H3 及叙述 → GM 第2手增量作为下一次模型输入 → AI 落子 H4 及叙述 → GM 第3手增量写入 gameTrace → 合并两段叙述给界面和 TTS
终局落子调用链 → GM 确认 User 或 AI 的落子并将权威结果改为 User胜、AI胜或平局 → 暂存该次回复中已经写出的自然语言 → 读取同一棋局的 GM 状态 → 把 GM 落子回执与 GM 状态行一并送回模型 → 等模型依据最终状态再答一次 → 按原顺序合并两段自然语言供聊天、历史和 TTS 展示；两条 GM 行只进入协议提示，不混入正文
终局续接上限 → 普通回合最多七次模型回复；若第七次刚产生终局落子，额外允许一次模型回复接收终局状态；终局状态确认不改变权威棋盘，也不让模型自行宣告新的落子成功
批量落子调用链 → 模型输出 User 落子 H3，且同一回复提前预写 AI 落子 H4 → 先只执行 User 落子并丢弃该回复未确认的后续协议行与叙述 → GM 第2手增量回送模型 → 模型重新决定并输出 AI 落子 → GM 第3手增量确认后才展示相应叙述
批量协议校验 → 最多八条；新 Game: 行可在回复开头或叙述之间，但每条必须独占一行；旧 <Game:...> 继续兼容正文内调用；两种格式都使用英文逗号且满足位置参数语法，失败时给出格式错误
批量协议行执行 → 按出现顺序逐条交给 GM 验证并记录结果；普通可连续操作全部成功才展示本批叙述；遇到 User 落子后还有预写 AI 落子时以该 GM 回执为确认点，当前回复只执行到 User 落子，下一次模型调用决定 AI 棋步
被拒绝的批次包含开局、落子或其他状态变更命令 → 标记本轮存在未确认操作，丢弃此前暂存的叙述 → GM 错误要求模型改用合法协议行；若后续只查询状态，则先回送权威 GM 状态并继续等模型纠正，不转述查询旁的落子宣称
未确认操作集合尚有条目而模型只输出自然语言或达到续接上限 → 比较棋局版本与本轮初始版本，向用户给出“棋盘未变化”或“部分操作未完成”的权威提示；仅同类状态变更命令经 GM 确认后清除对应条目，查询或其他操作不能替代确认
开局已获 GM 确认但之前同批次被拒绝的落子仍未确认 → 本轮直接给出部分完成提示，不继续让模型用旧用户原话补造棋步
棋局轮到 AI 而模型只输出自然语言 → 不暂存其中可能虚构的落子叙述，有限续问 AI 落子协议行；仍未取得 GM 确认时只返回“AI 落子尚未确认”的权威提示
批量执行中途失败 → 停止剩余协议行，之前已确认的操作保留 → 将本批次已成功的 GM 与失败 GM 按序回送模型纠正 → 丢弃该批次模型预写的自然语言，不播报未经确认的结果
批量执行全部成功且还需续接 → 将本批次每条 GM 按顺序一起回送模型，目录与规则连续查询不能丢失前一条回执
有目标显示端的模型输出 → 暂存完整本次回复，再识别任意位置的独立 Game 行并交给权威 GM → 校验结束后一次性展示安全叙述；普通聊天虽需等待本次生成完成，但不按关键词补发开局请求；无目标显示端时继续使用原聊天流式路径
初始已有活动棋局的首轮普通文本先缓冲 → 若无 Game 协议行且仍轮到 User，向同一模型最多续问一次，提供原始用户输入并沿用已有的首答与权威回合上下文，要求模型自行判断是否需要游戏协议行；若仍无协议行则输出首轮自然语言，服务端不得代下棋或显示虚假的落子成功
显示端点击 → 以连接绑定的 displayId 提交坐标和当前版本 → 服务端执行用户落子 → 同步 Game 增量给显示端 → 控制端/显示端聊天显示“棋盘点击 坐标” → 把 GM 增量送入当前 AI 聊天入口 → AI 决定下一手
显示端浅色主题 → 通用按钮强调色规则排除棋盘交点 → 交点保持透明背景，木色棋盘和网格可见；关闭/重开等真实按钮仍受主题控制
显示端左下角入口 → 将“游戏”按钮置于“聊天”按钮正上方，同一列布局；旧棋盘左下角独立重开按钮移除，避免覆盖聊天入口
点击“游戏”按钮 → 展开/收起游戏列表浮层，列表来自显示端声明的游戏能力；首版只有五子棋，不因点击列表自动创建棋局
游戏列表中的五子棋 → 当前对话有已保存棋局且棋盘手动隐藏时，发送带权威版本的 gameView 恢复显示；棋盘已显示时保持当前状态；没有棋局时提示用户在聊天中请 AI 开局
入口名称 → 仅当前 AI 对话活动、且已有进行中的真实棋局时显示“五子棋”，否则显示“游戏”；演示棋盘不计为当前执行的游戏；退出对话时列表关闭
棋盘关闭 → 保留权威棋局与 visible=false，游戏列表仍能恢复；语音对话结束后按钮回到“游戏”，重新进入活动对话后按权威状态显示游戏名
用户/AI 落子 → 检查对局存在、轮次、范围、空格、版本 → 更新棋盘和版本 → 检查横竖斜连续五子 → 原子保存权威状态 → 发送单步增量
显示端收到有效 gameDelta 且目标格原为空 → 更新该格棋子 → 若未启用减少动态效果，仅给这颗新棋子播放约 300 毫秒的落下回弹 → 动画结束清理临时状态；真实对局与演示共用，快照恢复和棋盘重建不触发动画
开局 → 无旧局时默认15路，支持9/11/13路 → 用户执黑先行 → 生成游戏ID与版本 → 保存 → 发送完整快照并显示棋盘
已有棋局再次开局 → 未指定尺寸时沿用原尺寸；尺寸不同则拒绝并要求先提议与用户确认；进行中的同尺寸重开须用户明确说重新开始；已结束棋局可直接同尺寸新开
提议尺寸 → 保存待确认尺寸但不更改棋盘；确认尺寸 → 验证同一尺寸与用户确认 → 保留游戏ID、清空棋盘、版本递增 → 保存并发送新快照
退出显示 → 只隐藏棋盘；恢复显示或显示端重连 → 从按显示端ID保存的状态发送一次快照
进行中落子 GM 回执 := Game:五子棋,GM,落子,4位游戏短编号,版本,操作者,坐标,下一手,进行中
终局落子 GM 回执 := Game:五子棋,GM,落子,4位游戏短编号,版本,操作者,坐标；终局没有下一手，胜负只由随后 GM 状态给出
进行中只读 GM 状态 := Game:五子棋,GM,状态,4位游戏短编号,版本,尺寸,下一手,进行中
终局只读 GM 状态 := Game:五子棋,GM,状态,4位游戏短编号,版本,尺寸,User胜或AI胜或平局；终局不输出下一手字段
服务端内部与显示端增量仍使用完整唯一游戏ID；终局显示端增量的 result 字段仍给出胜负，内部 turn 保留现有兼容状态，模型只以 GM 状态判断结果
显示端 Game 协议行 := 与同次 GM 协议行位置参数一致，只把操作者字段 GM 换为 Game；现有 WebSocket 消息外壳仍按项目规则包含 type
恢复快照 GM 状态 := Game:五子棋,GM,快照,游戏ID,版本,尺寸,下一手,结果,棋盘编码
棋盘编码 := 每行N格的 . / X / O，行之间用 / 分隔；`/` 从上到下分行，每行从左到右按 A 到当前棋盘末列排列，首行对应 1；`.` 空格、`X` 用户黑棋、`O` AI 白棋；只在恢复或重置时传送
GM 对模型的内部续接输入只传简短权威回执协议行，不附加“根据权威结果继续……”等长提示；游戏系统规则已说明如何根据 GM 回执继续
过期版本或增量缺口 → 请求权威快照；非法 AI 落子 → 最多再请求两次，仍失败则保留 AI 回合并提示
有目标显示端的游戏聊天整次模型回复先缓冲，服务端完成独立 Game 行校验后再把纯叙述送往聊天历史、控制端/显示端和 TTS；无目标显示端的聊天保持原流式路径
每条模型回包中的自然语言仅在整批操作成功后保留；若下一步仍轮到 AI，积累到本轮最终回复；操作失败或同回复提前预写 AI 落子时丢弃该批可能不准确的叙述；普通成功操作后已轮到 User 且有自然语言时直接完成回复；终局落子例外，保留原叙述并再发 GM 落子与 GM 状态给模型续答
实际游戏的 AI/User 调用行及 GM 回执 → 在本轮收集为 gameTrace，生成简短中文摘要并保留完整协议行供悬停查看 → 用 chatGameProtocol 实时事件发给控制端与目标显示端 → 随助手消息作为非模型上下文字段保存；两端聊天在回复旁渲染灰色小字提示，历史重载仍可见；不参与朗读，也不追加到模型正文
单次模型回复至多八条协议行，整个聊天桥接通常至多七次模型回复，终局状态确认最多再加一次 → 控制端实时显示本轮每条调用及 GM 提示，历史保存与渲染至多 128 条，覆盖本轮理论上限及初次快照
点击棋盘产生的 GM 增量、聊天首轮需要恢复时的 GM 快照也进入 gameTrace；演示棋局不走聊天路径，不生成 gameTrace
五子棋棋盘外层背景透明，仅棋盘自身保持木色与可读阴影；棋盘点按仍由游戏层接管
五子棋标题栏 → 用独立半透明深色纵向渐变与轻微背景模糊托住标题、回合状态和关闭按钮 → 保留白字阴影；棋盘外层仍透明，背景模糊不可用时渐变继续保证文字对比
AI 首次接入某显示端棋局、服务器重启或聊天上下文改变 → 先给一次 GM 快照；正常连续回合只给 GM 增量；版本过期时快照恢复
显示端启动或重连 → 服务端按 displayId 读取持久化棋局并发送 gameSnapshot，同时发送 voiceConversationState；页面初始化发送 gameRecover 补拉权威快照 → 显示端舞台缓存最新对话状态供游戏层初始化读取
真实棋盘展示条件 := 棋局 visible=true 且对话状态为 activeGroup 或 activePrivate；等待唤醒、监听关闭、未知状态时棋盘和恢复入口均隐藏，棋局数据仍保留
收到 voiceConversationState → 更新棋盘展示条件，但继续将事件交给语音模块处理；退出/道别/超时/监听关闭时立即隐藏；重新进入活动对话时按原棋局 visible 值恢复
演示棋盘不受对话状态门控；演示结束 → 恢复当前真实棋局快照，并按当前对话状态决定是否显示；点击“关闭” → gameView(false) 持久化 visible=false，新对话也不会自动展开该棋局
AI 代 User 落子 → 原始用户文本必须明确包含该坐标（A一视作A1）；显示端点击通过受信任连接身份直达服务端，不接受客户端自行指定操作者
当前显示端演示脚本 → 连接本机控制 WebSocket → 读取在线 displayList → 唯一主显示端自动选中，多个显示端时要求显式 displayId → 发送本机专用 gameDemoStart
服务端演示会话 → 校验请求来自本机、目标显示端在线、棋盘尺寸与逐步延迟/结果停留时长/胜方参数有效 → 向该显示端发临时棋盘快照
演示脚本默认依次模拟 User 胜、AI 胜两局；每局按合法预设落子交替发送单步增量，逐步等待设定延迟；第五子写入胜负结果后保持该棋盘一段时间，再用新游戏ID发下一局空棋盘快照
演示脚本可只选 User 胜或 AI 胜；不调用真实模型，不写入权威棋局或聊天历史；最终获胜棋盘一直保留到脚本停止
演示结束、脚本断开或真实棋局更新 → 取消演示定时器 → 恢复目标显示端当下权威棋盘；若原无棋局，则发 gameDemoEnd 关闭演示层
```
