# 控制端媒体循环区间伪代码

状态：2026-10-23 单轨双手柄已实现，本地专项自测通过；服务与Node独立包待构建部署，设备验收另行记录。

## 已有声明

```text
控制卡片 := upload.html 中的媒体播放区域
控制发送 := WebSocketManager.sendControl
显示状态 := 服务端按显示端保存的播放状态
播放进度 := videoProgress 或 audioProgress 的 currentTime 与 duration
播放器 := 网页 video/audio 或 Node 常驻 mpv
```

## 新增定义

```text
媒体循环区间 := { enabled, startPercent, endPercent }
当前媒体标识 := mediaLoopToken，服务端随机生成并随显示状态持久化
默认区间 := 关闭，开始为零，结束为百分之百
编辑控件 := 循环开关，一条滑条上的开始和结束两个手柄，只读起止时间
最小间距 := 媒体总长度的千分之一
生效范围 := 当前显示端当前媒体；新媒体和播放列表项切换时清除区间
```

## 操作流程

```text
当前显示端进度 → 有限媒体时长 → 启用区间控件，百分比乘时长显示分秒
同一可见轨道上的两个原生range手柄 → 浏览器鼠标/触屏或方向键移动 → 钳制不交叉与最小间距
拖动 → 本地预览与区间高亮，不发远端消息
释放或完成键盘调整 → 区间与当前媒体标识 → type为control且action为mediaLoop的WebSocket消息
服务端媒体标识不匹配 → 拒绝迟到拖动，广播当前权威区间与错误
服务端验证显示端当前为音视频且已有有限时长 → 规范化百分比与开关
规范化区间 → 既有配置持久化流程 → 广播权威状态 → 控制端回填与显示端应用
配置保存失败 → 保留原权威值，广播错误，不向播放器下发
权威广播 := type为mediaLoopState，携带显示端、区间、媒体标识与时长
网页播放器 := 公共模块绑定持久timeupdate/play/ended监听，不覆盖页面既有进度上报
普通URL或临时Base64音视频 → 共用持久timeupdate、loadedmetadata与durationchange上报监听
当前音视频且WebSocket已连接且时长有限且大于零 → 发送audioProgress或videoProgress
刚加载或暂停的媒体 → 元数据加载即发送有限时长 → 控制端无需等待播放即可启用双手柄
隐藏的旧媒体、尚未加载完或非有限时长 → 不发送可编辑的时长，保留禁用回退
Node播放器 := 百分比乘有限时长 → 原生ab-loop-a/ab-loop-b与无限计数；关闭和新媒体加载解除旧AB点
启用区间且播放到结束点 → 当前播放器跳回开始点 → 保留播放或暂停状态
启用区间且位于播放列表 → 优先循环当前媒体，暂不自动推进列表
关闭区间 → 恢复原有单媒体循环或播放列表推进
网页媒体加载或Node加载新媒体 → 清除播放器旧区间
服务端当前媒体或播放列表项身份变化 → 清除旧区间与过期时长 → 广播默认区间
连接初始化或重连 → 当前媒体的权威区间 → 加载媒体后恢复显示与播放边界
未收到配置 → 默认关闭；未知时长或直播 → 禁用区间编辑
```

## 待验证

```text
拖动与键盘、交叉与重叠端点、非法消息 → 控制端和服务端最终值一致
音频与视频 → 结束点回跳，暂停不被唤醒
多显示端与多控制端 → 按显示端隔离，权威值一致
媒体切换与列表推进 → 不继承旧媒体区间，不破坏关闭时原逻辑
刷新与重连 → 当前媒体匹配时恢复，默认关闭可回退
网页/APK显示页与Node mpv → 相同行为契约，设备实测单独记录
```
