# OpenSpec 文档转换技能实现规范（伪代码）

## 技能入口与输入

```text
调用 OpenSpec 文档转换技能：
  读取输入目录中的 proposal.md
  读取输入目录中的 design.md（存在时）
  读取输入目录中的 specs/**/*.md（存在时）
  读取输入目录中的 tasks.md
  读取项目根目录规则、package.json、design/spec 索引和目标模块文档
```

## 输入职责解析伪代码

```text
解析 proposal.md：
  提取 why 作为需求背景
  提取 what changes 作为功能需求、范围和影响
  提取明确的非目标并保留原边界

解析 design.md：
  提取 context 作为现状和约束
  提取 goals/non-goals 作为设计目标和排除项
  提取 decisions 作为架构、接口、数据流和兼容性决策
  提取 risks/trade-offs/open questions 作为风险与待确认项

解析 specs/**/*.md：
  按 capability 文件拆分行为需求
  保留 ADDED、MODIFIED、REMOVED 分类
  将 requirement/scenario 转换为项目验收条件和回归契约
  如果目录不存在：记录“缺少独立行为场景”，继续使用 proposal 和 design

解析 tasks.md：
  保留任务组、任务编号、顺序和勾选状态
  提取每项任务声明的文件、模块、接口和测试关键词
```

## 目标模块识别伪代码

```text
从输入标题、能力名称和任务文件路径生成候选模块名
在 docs/design、docs/spec 和真实源码中搜索候选模块

如果只有一个已有模块匹配：
  复用该模块 slug 并计划增量更新
否则如果没有已有模块但任务路径明确指向一个模块：
  使用规范化后的新 slug
否则：
  列出候选模块、冲突路径和需要用户确认的选择
  暂停写入目标文档

对每个 tasks 文件路径：
  检查普通文件或目录是否真实存在
  检查导出标识、消息类型、配置键和测试入口是否真实存在
  不存在的落点标记为“待实现/待确认”，不得改写为已存在
```

## design 文档生成伪代码

```text
创建或读取 docs/design/<模块>.md
写入概述和需求背景
合并 proposal 的功能需求、范围、目标和非目标
合并 design 的现状、约束、设计原则、架构、数据流、决策和风险
加入 specs 的行为边界和验收标准
加入真实文件清单与尚未实现的目标落点
保留未解决问题，并为每项问题标记影响范围
```

## spec 文档生成伪代码

```text
创建或读取 docs/spec/<模块>.md
写入模块职责和真实文件映射
按任务组建立实现章节

对每个任务：
  写入任务编号和原始勾选状态
  绑定已核实的真实文件或标记待实现路径
  描述输入、输出、状态和消息契约
  用中文动作语句写入数据流伪代码
  将对应 specs 场景写入回归契约
  将对应 tasks 测试项写入自测方案
  只有代码检查或测试结果支持时才写“已实现”

伪代码检查：
  删除类型声明、模块导入、可直接执行的函数体和语言专属语法
  将复杂条件改成提前返回、状态表或规则表
  保留异常、兼容旧输入、空值和失败分支
```

## 索引与任务记录同步伪代码

```text
如果新增 design 文档：
  在 docs/design.md 功能模块表增加模块、链接和说明
如果新增 spec 文档：
  在 docs/spec.md 功能模块表增加模块、链接和说明

创建 docs/task/<时间>_<简要描述>.md：
  写入任务描述、design 需求、spec 设计、受影响模块、自测、兼容性、性能、风险和预计工时

任务完成后：
  从 docs/todo.md 删除已完成条目
  在 changelog.md 写入完成日期、文件、转换规则和验证结果
```

## 转换结果回归契约

```text
输入存在 proposal、design、tasks：
  输出 design 和 spec
  每个任务编号均可追溯到 spec 章节

输入缺少 specs：
  仍输出 design 和 spec
  输出中明确记录行为场景缺失风险

输入含相似模块或虚假路径：
  不套用相似文档
  不创建虚假文件映射
  请求确认或标记待实现

输入任务未勾选：
  输出为待实现/待验证
  不宣称代码已完成
```
